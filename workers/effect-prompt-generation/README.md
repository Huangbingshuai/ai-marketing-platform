# Effect Prompt Generation Worker

效果类第 3 节点“Prompt 生成”的独立 Python 3.12 Worker。Worker 从 RabbitMQ 只接收运行标识，通过 NestJS 内部 API 领取不可变输入快照，持久化分片和安全进度，并返回当前批次结果。它不直连数据库，也不在日志中记录 Prompt、提炼正文或模型原始输出。

## 统一卖点输入与完整追溯（2026-09-10）

API 在读取边界归一化已确认提炼工作副本。当前每条 `sellingPoints` 一对一映射为 `SELLING_POINT`，不重新拆分受众、痛点或场景；Worker 仅对已经领取的旧任务保留缺省字段折叠。最多 100 条卖点加 5 项产品基础，共 105 项事实；单项最多 1000 字，只去空白和完全相同内容，不做关键词排除、大小写折叠或 500 字截断。

视觉策略目标按最多 24 项或 12,000 字分片，模型始终能读取完整事实目录。输出范围、稳定 ID、完整性和哈希由 Worker 确定性验证；相同 Run 的成功策略分片可从既有阶段检查点恢复，新批次从头生成。分片增加的是容量保护，不是新的业务节点或事实分类规则。

详情分别展示收到的卖点、方向使用的卖点、最终实际体现和仅作上下文保留的卖点。最终绑定完整保存 AI 返回且经结构验证的有效事实，不再截取前 5 条；样例数量限制仅影响展示。规划使用不等于正文已实现，背景保留也不等于事实被丢弃。详细边界与自动验收见 [统一卖点同步方案](../../docs/workflows/effect/plans/效果类Prompt-统一卖点同步实施方案.md)。

## 当前视觉策略流程

### 事件差异化与有效补充恢复（2026-09-10）

空间和方向模板以“主体关系—关键事件—可见结果—商品价值”组织差异，独立卖点数量不等于独立素材数量。同一方向的素材不是替代机位：单条生成输入携带该方向既有兄弟路线的精简摘要，失败拆分成单条时也保留比较依据；不传整批方向表，不新增模型输出字段。全批 AI 复核读取路线的实际关系、动作及结束状态，不能只凭摘要或细分标签判定不同。多样性补充同时读取已生成拥挤样例的真实动作和结果，不只看六维标签。

补充方向仍先请求 2～4 个、最多两次结构恢复；恢复耗尽后，结构有效的部分继续走既有 AI 复核，不再因一个无效方向整体丢弃。复核失败或取消不会发布未审核方向。通过全批复核的新事件不再被分配器按拥挤上位族二次过滤。实际候选数以通过复核的路线容量为限，不能循环复用少数路线凑满可选补充池；这不改变最终批次数量目标。正常生成调用轮次、MMR 权重和阈值不变，Worker 不增加任何语义或商品关键词判断。

自动回归已通过，真实重复度与速度改善仍需同配置付费测试验证，见 [实施记录](../../docs/workflows/effect/plans/效果类Prompt-事件差异化与部分补充恢复优化.md)。

### 单一英雄事件与紧凑拍摄指令（2026-09-09）

Prompt 候选继续使用现有模型路由，不更换生成、方向规划或质量评估模型。生成端现在先确定一个“单一英雄事件”，再围绕同一事件生成六维、创意主线和结构化拍摄计划：4～8 秒通常使用 1 个节拍，9～15 秒通常使用 1～2 个连续节拍，后续节拍只能推进同一动作，不能再引入第二项独立任务。

当同一画面已经包含多人、工具、流体、柔性物体、大量相似小物体或复杂运镜时，模型必须主动减少其他高风险因素；多人画面只保留一名主要操作者。开口容器不通过翻转展示内部状态，零售包装不充当多人共享的操作容器，也不要求视频模型保证“完全、始终、绝不滴落”等随机物理结果。这些关系由 AI 在生成时设计，Worker 仍只校验结构、稳定 ID、来源、数量和哈希，不判断动作、场景或物理语义。

执行路线和 `creativeUsage` 中的具体拍法是 AI 建议，不具备已确认产品事实的权威性。生成模型必须在保留营销意图的前提下重设计有风险的拍法：成组画面只完成一个主要对象的一次局部操作，其余结果在首帧已有；接触动作、主体运动与相机运动明确分工，不同步双转；浓稠、黏附、柔软等属性不能自行推导拉丝、回弹或精确成型。复合多用途由不同方向共同表达，不要求一条素材做完全部用法。既有方向 AI 复核和局部执行修订沿用这些原则，不新增模型调用、输出字段或 Worker 语义门禁，也不把所有素材统一成固定镜头。

结构化 `shotPlan` 仍完整保存所有字段；供应商 Prompt 编译器只把重复标题压缩为紧凑的概览和逐秒镜头，不删除首帧状态、核心动作、镜头、焦点、运动来源、可见结果、同步声或结束画面，也不会自行补写商品语义。

实现边界与验证记录见 [视频画面稳定性源头优化](../../docs/workflows/effect/plans/效果类Prompt-视频画面稳定性源头优化实施方案.md)。

三类具体风险的后续修正与逐轮实测见 [三类画面执行风险源头修正](../../docs/workflows/effect/plans/效果类Prompt-三类画面执行风险源头修正.md)。主生成指令已压缩，并用通用拍法示意说明占用手、遮挡面、高低机位和固定/移动关系；`factApplications.value` 与 AI 视觉建议的证据地位明确分开。自动测试只验证指令和结构契约，不能代替浏览器最终正文审查，更不代表未经渲染的实际视频已无故障。

### 视觉事件差异与镜头局部修订（2026-09-08）

方向规划继续由 AI 完成，不使用商品动作词库。每条执行路线新增简短 `eventOutline`，全批视觉复核现在读取每条路线的事件摘要，而不再只看方向标题和分类标签；原有分批关系复核读取完整路线。AI 比较起始关系、关键事件、可见结果与商品价值，指出仅换机位或背景的近似路线，同动作但不同需求/结果仍可保留。不增加固定动作配额或 Worker 语义门禁。

新 `shotPlan.beats` 分开描述 `framing`（景别/角度）、`camera`（相机位置/运动）、`focus`（焦点）和 `motionSource`（主体运动来源）。后两项允许 null；历史记录缺省时正文编译保持原样。字段内容与物理因果由 AI 设计和判断，Worker 只分配时间、排版并校验结构，不替物体猜测动力来源。

原有评估调用可返回最多 3 条有节拍位置的执行诊断。无硬问题的 AI 候选才可追加一次局部字段修订与一次独立复核，每条最多 2 次额外模型调用；不进行无限修订，也不触碰人工正文。复核须没有新的硬问题、执行问题已消失、原已实现事实未丢失，且可执行性和加权质量分不下降，否则保留原稿与软提醒。先给其他待评估候选预留调用空间，再原子预留本次修订/复核的两次调用额度，不扩大现有总调用上限。

尝试标记在模型调用前保存；修订后的候选和对应评估保存在同一条分类分片的 `executionRepair` 内，API 样例只投影已经采用的新正文与评分，不公开内部检查点。任务中断恢复会校验原稿哈希、ID、事实、时长权重和未修改字段；已经开始的局部修订不会重复调用。新动作补充只允许在原有空间和已确认事实内提案，并额外经过现有 AI 关系复核及全批重叠复核；不修改原创意版图或补造产品能力。

为新增短字段和诊断预留输出空间，4 条 15 秒候选的计划输出预算为 8000 Token（仍不超过现有 8192 上限）；评估在 6144 Token 上限下普通短候选通常每批 3 条，较长输入仍可能进一步拆分。这是传输预算，不是正文最少字数或质量门槛。2026-09-08 的 100 条 × 15 秒真实对照已验证结构恢复和精确数量链路，但最新一轮仍出现 23 条动作过密软提醒，不能把结构稳定等同于镜头执行质量达标。

实现与验收记录见 [视觉事件与镜头执行修复](../../docs/workflows/effect/plans/效果类Prompt-视觉事件差异与镜头执行修复.md)。

### 营销表达与镜头推进

当前方向模板在既有 `creativeDirection` 中引导 AI 说明观众关注点、已确认产品价值及承载它的可见事件；补充方向沿用相同原则。拍摄模型仍在一次调用中生成创意主线、六维和 `shotPlan`，编译器只分配时间和排版。镜头可通过注意力转移、细节揭示和人物选择推进信息，同一连续事件可合理切镜，也可一镜到底；不强制每条具有痛点、反转或购买号召。

少量跨品类示例只示范表达方式，不作为当前商品事实或批次固定脚本。新素材依靠首帧关系、连续产品动作、镜头揭示和结束状态表达价值，人物只做使用、选择、递交、观察或非语言反应；内部 `shotPlan` 不再提供台词或总览音乐字段，只允许与画面同步的自然环境声和产品动作 Foley。人物口播、旁白、歌词、字幕文案和可辨识说话口型由 AI 评估器判为不适合作为当前素材，Worker 不做关键词或语义判断。配乐、统一口播及字幕留给后续混剪/成片。

详见 [实施记录](../../docs/workflows/effect/plans/效果类Prompt-营销表达与镜头推进优化实施方案.md)。

### 事实与创意链路

新任务固定使用当前八节点拓扑。Worker 先把已提交营销洞察中的产品基础与统一卖点，以及该洞察实际消费的资料包内全部可用产品主图和细节图，交给独立多模态 AI 策略调用（大量事实时分片），编译为“产品身份锚点、可直接呈现、可通过动作呈现、仅作商业背景、仅适合文字表达、禁止视觉证明”六种角色；Worker 再校验事实引用、结构和完整覆盖；是否涉及禁止推导由 AI 判断。图片只帮助模型认识商品真实外形、结构、细节和可操作部位，不是新的事实来源，不能从包装文字、背景或道具推导卖点。图片不会继续传入创意方向、候选生成或评分请求，后续节点只消费已经验证的简短视觉策略。每次用户重新批量生成都会重新调用模型编译策略，不复用其他 Run 的结果；只有同一 Run 因网络、租约或 Worker 故障重试时，才恢复本任务已经验证的检查点。检查点同时绑定营销洞察内容与图片 SHA-256，命中时不重新下载图片。策略不会写入公开 Prompt 结果，也不会按候选数量重复调用。

视觉策略使用规划节点的独立输出预算与超时，不与单批候选生成共享 4096 Token 上限。策略正文保持短语化，既保留跨品类判断，又避免整份事实卡在结构化 JSON 尾部被截断；Ark 返回 `incomplete_details.reason=length` 时按明确输出截断处理，不再显示旧“营销关系规划”文案或无意义重试。

随后先由 AI 根据可用事实、事实视觉策略、共用提示词和视觉风格基调规划产品专属创意空间；第二次紧凑 AI 调用再把每项必用业务事实唯一分配给一个自然相容空间；最后由创意导演按通过复核的版图动态规划 8～32 个创意方向。方向数同时受目标 Prompt 数和必用业务事实数影响，目标 50 条默认规划 20 个方向，目标 100 条默认规划 32 个方向。空间和事实的业务关系都由模型判断；同一自然主题可以承载较多事实，Worker 按每方向最多 4 项事实计算该空间需要的方向槽位，只检查事实覆盖、空间 ID、数量、结构和总容量。Worker 不维护“厨房、切片”等商品关键词，也不把遗漏事实随机塞进某个空间。

方向规划完成后，原有分片 AI 继续复核事实关系、版图和主动作；另一次轻量 AI 会读取全批方向摘要，检查跨分片方向渲染后是否仍会得到相同的主要场景、人物关系、产品主动作和构图。Worker 只验证复核返回的稳定方向 ID 和结构。场景、动作或正文向量过于集中时，多样性补充先由 AI 规划 2～4 个新方向并完成全批重叠复核，再生成补充候选，不再直接复用拥挤旧方向。

向量 MMR 通常使用 `70%` 质量和 `30%` 多样性；候选池正文近重复率超过 50% 时，当轮自动调整为 `60% / 40%`。这仍是软排序，不会因为一般相似删掉候选或破坏精确数量。

历史受控真实 Ark 复验曾在旧容量口径下形成 6 个真实创意空间、13 个方向并覆盖 37/37 项强制业务事实。当前容量策略已升级为 50 条默认 20 个方向、100 条默认 32 个方向，并增加全批 AI 视觉重叠复核；历史数据只证明当时的事实分配链路有效，不代表当前版本最终 Prompt 的质量结论。

风格基调只转译为光线、色彩、材质、镜头质感和情绪底色，不能反向虚构场景、人物或商品事实。方向事实数量由 AI 按自然关系决定，不设每方向最低事实密度。每项统一卖点保留为可追溯事实；适合无口播画面承载的卖点是整批规划的覆盖目标，遗漏作为覆盖提醒，不以缺少固定数量或固定字段搭配判定方向无效。仅作背景、仅适合文字和禁止视觉证明的事实仍保留给规划理解商品，但不强制获得画面证明；营销目标不是产品事实。每条创意完整继承所属方向的事实组合和 `productSnapshot`，模型仍在一次创意调用中同时生成：

```text
完整创意主线 + 六维信息 + 最终干净正文
```

六维为叙事、场景、人物、产品关联点、镜头和情绪。六项必须属于同一个创意，正文必须真实体现它们。生成模型不按钩子、产品展示、效果、结尾转化四类用途分组；独立评估模型在正文完成后负责质量评分、事实证据核验以及多用途分类。

Prompt 条目不再包含独立的次级素材标签。Worker 只输出评估得到的推荐用途与兼容用途，避免把同一分类再复制为一套可编辑标签。

视觉策略、连贯创意和独立评估分别使用无编号的稳定模板标识。生成角色保持厂商无关，一次调用直接产出可供后续渲染的完整素材 Prompt；镜头、光线和情绪必须服务本条产品动作，不得给不同候选机械套用统一的“电影级、商业广告、高级质感、暖色调、浅景深、缓慢推进”等正向前缀。已有语义和视觉签名只是软避重参考，不能迫使模型使用与产品无关的场景。抽象配方、成分、工艺、认证和背书只能作为商业背景，不能被写成肉眼已经证明的纹理、光泽、纯度或功效。

独立评估模型会同时接收候选声明的完整计划事实组合，并复用同一份视觉策略检查抽象事实是否被错误包装成视觉证明。评估模型逐项判断事实是完整实现、部分实现还是未实现，并对可用绑定返回 `EXACT` 或 `SEMANTIC_FULL`；`evidenceText` 和 `evidenceSource` 只是可选诊断信息，不是 Worker 的文字匹配依据。Worker 只白名单校验事实 ID、枚举、数量和结构，再机械采用评估模型的支持等级，不搜索正文证据、不比较摘录与事实含义，也不重新判断事实是否实现。包装规格能否证明配方、普通厨房能否证明传统工艺，以及商品无关、事实捏造和不可执行画面等结论均由评估模型负责；方向中的次要事实未完整实现只降低择优顺序，不会让数量恢复流程直接失去候选。

Worker 不再把事实拆成主事实、辅助事实、视觉任务和产品锚点等竞争角色。批次方向模型直接使用整张已确认业务事实表，先为每个方向形成自然的事实关系，再把该关系作为不可拆分的任务简报交给生成模型；产品名称、品类、规格和外观仍由 `productSnapshot` 提供真实性边界，不能冒充卖点、痛点、受众或场景。Worker 只统计实际规划与实现的事实 ID，不因方向遗漏而机械触发密度重规划，也不会自行把事实补挂到无关方向。

批量生成采用以下规则：

- 首轮候选数为用户目标数量的 `140%`（向上取整），例如目标 50 条时先生成 70 条；需要数量或多样性补充时，候选总数最多为目标数量的 `180%`。
- 创意与分类分片都按实际预算动态规划。分类同时检查输入体量、精简结构化输出体量和 4～15 秒目标时长；异常长正文自动单条执行，多条结构异常时仍只拆分当前分片。评估请求中的事实和视觉策略按分片去重发送，模型不再重复输出可由候选结构确定性派生的事实 ID 列表及内部签名。
- 创意与分类调用共用 `PROMPT_MAX_CONCURRENCY` 滑动并发门限；一个分片完成后立即补入下一个，但分类节点仍等待本轮全部创意分片完成后再启动。
- 评估模型可以结合干净正文、创意主线、场景、人物和产品关联点判断事实是否实现。Worker 只移除不属于当前候选计划或当前可信上下文的未知事实 ID；对于合法事实，是否支持、支持到什么程度完全采用评估模型返回的结构化等级，不因缺少摘录、原词未出现或字符不相似而删除绑定。评估模型确认后只剩产品名或规格时，该候选不能进入最终结果。
- 每条统一卖点都是可用事实，仅 AI 视觉策略确认可由无口播画面承载的事实进入覆盖目标。初始候选会优先让每项事实获得多个生成机会；最终选择后仍有遗漏时，Worker 会按缺失事实单独生成覆盖候选，再参与同一质量评估和择优，不会用产品名称冒充已覆盖。
- 最终结果恢复 `insightCoverage`：直接呈现的事实使用 `PRIMARY/EVIDENCE`，用于人物、场景、动作或商业语境的事实使用 `CONTEXT`。必用事实仍缺失时保留足量草稿并标记 `NEEDS_REVIEW`，不伪造事实绑定。
- 当前连贯创意简报使用方向模型给出的 `factApplications`，每项包含原始事实和该事实在当前创意中的具体用途。每方向不设置业务事实最低数量，不强迫稀疏商品重复事实。`productSnapshot` 保存产品名称、品类、规格和视觉特征，只用于保持身份与实物边界。
- 完全相同的正文，或完全相同的创意主线与六维组合，才算硬重复。
- 新任务只为 Prompt 正文生成向量。候选池正文近重复率不超过 50% 时按 `70%` 独立质量分和 `30%` 相对已选集合的新颖度逐条选择；超过 50% 时当轮调整为 `60% / 40%`。同一语义连通组尚有组外候选可用时优先选组外代表；全部语义组均已覆盖后才允许组内补齐，并按组内负载施加递增软惩罚。新颖度内部继续综合正文向量与业务语义簇，语义簇同时观察六维分类、具体产品动作和真实场景原子。
- 全量生成将人工保留项作为固定相似度参照；单条重新生成将目标条目和当前批次其他 Prompt 一起作为固定参照。新请求直接重做创意方向、六维和正文，并按用户选择的新时长生成；旧正文和旧六维不进入生成模型上下文。参照项不参与淘汰和数量统计。
- 一般相似只影响排序，不会机械删除候选。评估节点以正文余弦相似度不低于 `0.82` 建立连通重复组，每组按 `组内数量 - 1` 计算重复条目；达到或超过 `15%` 时额外生成一次最多目标数 `40%` 的多样性候选，并把高风险组的语义、场景与动作作为避重上下文。最终保护会从未选候选中逐条替换重复项，同时保持数量与必用事实覆盖；仍不理想时保存准确数量的 `NEEDS_REVIEW` 草稿并提示用户继续优化，但只要数量、结构、事实安全和评估状态满足要求，用户仍可主动完成校验并提交工作副本。
- 首轮不足时按实时缺口执行受候选总上限约束的定向补充，并在达到用户数量后立即停止；候选达到目标数 `180%` 后仍不足则保存为待检查结果，不能继续付费重试或伪装成合格批次。
- `ITEM_EVALUATE` 只重新评估用户新增或修改后的原正文，不生成替代正文；评估时读取当前全部可信事实。用户未填写创意主线和六维时，模型才从正文补齐这些结构；用户已完整填写时，模型只校验正文、创意结构与事实是否一致，Worker 保留用户结构，不用推导结果覆盖。两种情况都会重新分析事实绑定、推荐用途和兼容用途。API 在完成时按稳定 ID 合并回原批次；无硬问题为 `VERIFIED`，事实编造、产品无关或正文破损等硬问题为 `NEEDS_REVISION`，且保留安全问题代码供页面提示。

共用提示词继续作为批次级权威数据：创意生成时作为约束上下文传给模型但不自动写入每条正文；后续 Seedance 请求编译时再由第 4 节点追加。时长、画幅和分辨率仍是结构化渲染参数，不依赖正文表达。

API 只向 Worker 下发当前拓扑。不兼容的历史任务在认领时会被安全终止，不会进入模型调用或被套用当前图继续执行；旧数据库记录只作为不可见审计数据保留。

## Provider 与运行隔离

### 补充方向局部恢复与评分一致性（2026-09-08）

补充规划读取旧方向的字段摘要，保留全部 AI 编写的视觉事件、场景关系、产品动作与结束状态，不重复发送旧方向的事实应用长说明；当前可信事实、视觉策略和合法空间/动作/事实组合仍完整传入。首次分配稳定补充方向 ID；数量缺失或来源引用出错时，只请求未通过的方向，已通过的对象不改写。完成后仍由 AI 做全批视觉重叠复核；AI 只要求修改部分方向时也只重取那些方向。结构恢复最多两次、语义修订最多一次，总循环最多四轮，不延长候选补充上限，不添加规则创意兜底。

评分模型建议只返回最多三个其他兼容用途，解析器同时兼容包含主用途的四项列表，最终仍通过枚举去重合并主用途。结构异常日志增加最多八项 Schema 字段路径与错误码，未知字段名匿名化，不记录正文、输入值或异常消息。生成/评分模型增加跨镜位置、朝向、持握与状态衔接指导；可执行性和无信息长停留只由 AI 给软提醒与评分，Worker 不做语义或关键词判断。

实现及验证边界见 [修复记录](../../docs/workflows/effect/plans/效果类Prompt-补充方向局部恢复与评分一致性修复.md)。Mock 回归通过不代表真实重复度、耗时或镜头质量已达到目标，仍需独立真实验收。

生产默认 Provider 是 Ark；缺少 `ARK_API_KEY` 时启动失败，不会静默降级 Mock。Mock 只允许使用以 `.test` 结尾或 `test.` 开头的 RabbitMQ 队列，防止测试 Worker 消费生产任务。完成回写包含 `executionMode=ARK|MOCK`，API 可拒绝非测试运行的 Mock 结果。

Ark Responses API 在解析 JSON 前检查 `status` 与 `incomplete_details`。输出长度截断会返回 `AI_OUTPUT_TRUNCATED`，未完成响应不会被当作合法 JSON。创意评估的三条合并分片若格式异常或被截断，Worker 会只把该分片拆成单条重新评估；单条仍异常才终止任务。网络、超时、限流和 5xx 的业务重试继续统一由 API 任务层负责。

事实视觉策略、产品创意空间、事实主承载分配和创意方向在模型请求内使用 `F1/F2...` 短事实别名，返回后再机械恢复为权威事实 ID。创意空间 JSON 格式损坏时只局部重取，不占用业务语义修订预算；事实分配缺失、重复、未知引用或整批方向容量不足时，只重取紧凑的事实分配，不重写整套空间。同一空间不再受固定 8 项事实上限约束，Worker 会按事实负载增加方向槽位。只有独立 AI 认为事实与空间语义不自然时，才重新规划产品创意空间。Worker不修改场景语义，也不自行决定事实应去哪个空间。

队列信封只携带当前任务标识，不携带 Prompt 代码版本。Ark 偶尔会把被截断的 JSON 标成 `completed`；候选生成的事实编号会先转换为每条任务私有的 `F1/F2...`，模型返回后再映射回权威事实 ID，避免同一次请求中的多条任务串用事实。新候选必须在结构中完整保留本条 `factApplications` 的事实引用；引用越界、计划事实 ID 缺失或结构破损时只隔离该候选。产品身份是否充分、计划事实是否真正进入创意，以及各项事实是否语义完整，全部由独立评估模型判断；Worker 不要求逐字证据，也不检查证据在正文中的字符位置。批量生成分片连续两次无有效候选时会跳过该分片并交给现有数量补充流程，不降低事实安全门槛，也不再让单条异常拖垮整批。

向量服务使用独立 Provider 和 HTTP 客户端，不复用生成模型。`trigram` 保持字符基线；`shadow` 计算正文向量 MMR 但仍保存字符基线结果；`vector` 才由正文向量 MMR 接管。火山向量模型或 Endpoint 必须显式配置，不能回退到 `ARK_MODEL`。当前账号使用 `doubao-embedding-vision-251215`，通过官方 `/embeddings/multimodal` 端点发送纯文本。该端点每次最多接收一个 `text`，Worker 会自动把每批限制为单条并使用独立并发门限；不会误发到文本 `/embeddings` 端点。`shadow` 下向量故障会在阶段详情留下告警并继续旧算法，`vector` 下则重试或失败，禁止静默降级。

向量正文会去除共用提示词、时长、画幅和固定合规尾段，并把批内共同产品名与品类规范成占位符。原始向量只保存在 Worker 进程内的有界内容缓存中，补充轮次和人工单条评估只向量化新增或变化正文，不写数据库或日志。数据库阶段元数据只保存正文哈希和重复关系边，用于删除条目后的可信重算，不保存正文或向量。

向量进入选择前会转换为 NumPy `float32` 矩阵、按行归一化，并用一次矩阵点积得到全部候选与固定参照的余弦相似度。MMR 选择期间只增量维护每个候选的最大风险，不再重复遍历高维向量。`shadow` 阶段记录字符基线与正文 MMR 的近重复数、平均质量、六维覆盖、选集重合率、矩阵耗时和条件补充判断，这些指标只用于决定是否切换 `vector`，不会改变影子模式的权威结果。

## 本地验证

创意空间和方向只规划观看意图、事实关系与主要事件，具体持握、工具次序、机位和运动交给正文模型统一设计。正文沿首帧状态→动作→终态表达每段真实观察关系，不靠固定商品词库或硬动作规则。

生成内部先保存结构化草稿，再由同一生成模型执行一次聚焦修订（`creative_execution.system.prompt.txt`）。该调用只接收事实、视觉边界、时长、共用约束和草稿，不接收上游执行路线、creativeUsage 或拍法 instruction。AI 返回 KEEP 时原条目原样保留；REPAIR 时只返回冲突路径、简短原因与最小文本字段替换，不再整条重写。可同步确实受影响的主线、六维与 shotPlan 字段，不能改事实、稳定编号、节拍数量/顺序/权重。内部 Schema 和安全路径替换位于 `execution_refinement.py`，不改变公共结果。Worker 只核验 ID、数量、允许路径、重复路径和结果结构并排版，不解释原因或判断任何动作、镜头、材料语义，也不添加字符匹配门禁。

这是原生成内修订调用的替换，不新增调用轮数；使用现有并发和 Run 调用上限，无效结构仍有有界恢复。修订失败保留当前 Run 未完成分片中的草稿，只重试修订，不当作成功候选；新 Run 不复用。人工 `ITEM_EVALUATE` 仍只评估、不重写正文，独立质量评分模型与模板不变。Mock 只验证协议和编排，真实质量、重复度与速度须另行浏览器验收。

关系复核开始前会把已验证的空间/方向写入本 Run 的阶段检查点，并逐批保存合法审查结果。失败后只恢复同一 Run、同一输入与模板哈希、同一审查轮次的完成分片；被修改的方向或下一轮语义修订重新复核。检查点仍经 API 当前项目、有效租约与 attempt token 校验，不向公开详情展示内部审查 JSON。新建批次始终从头生成。

排查超时查看安全日志的 `step`、`batch_size`、`input_chars`、`timeout_seconds`、`latency_ms`、`attempts` 与 `exception_type`。`estimated_input_units` 只表示拆批容量估算，不作为计费 Token；日志不含 Prompt 正文、原始响应或凭证。
