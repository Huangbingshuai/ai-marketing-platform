# Effect Prompt Generation Worker

效果类第 3 节点“Prompt 生成”的独立 Python 3.12 Worker。Worker 从 RabbitMQ 只接收运行标识，通过 NestJS 内部 API 领取不可变输入快照，持久化分片和安全进度，并返回当前批次结果。它不直连数据库，也不在日志中记录 Prompt、提炼正文或模型原始输出。

## 当前视觉策略流程

新任务固定使用当前八节点拓扑。Worker 先把已提交营销洞察中的可用事实交给一次独立 AI 调用，编译为“产品身份锚点、可直接呈现、可通过动作呈现、仅作商业背景、仅适合文字表达、禁止视觉证明”六种角色；Worker 再校验事实引用、完整覆盖和禁止推导。每次用户重新批量生成都会重新调用模型编译策略，不复用其他 Run 的结果；只有同一 Run 因网络、租约或 Worker 故障重试时，才恢复本任务已经验证的检查点。策略不会写入公开 Prompt 结果，也不会按候选数量重复调用。

视觉策略使用规划节点的独立输出预算与超时，不与单批候选生成共享 4096 Token 上限。策略正文保持短语化，既保留跨品类判断，又避免整份事实卡在结构化 JSON 尾部被截断；Ark 返回 `incomplete_details.reason=length` 时按明确输出截断处理，不再显示旧“营销关系规划”文案或无意义重试。

随后先由 AI 根据可用事实、事实视觉策略、共用提示词和视觉风格基调规划产品专属创意空间；第二次紧凑 AI 调用再把每项必用业务事实唯一分配给一个自然相容空间；最后由创意导演按通过复核的版图动态规划 8～24 个创意方向。方向数同时受目标 Prompt 数和必用业务事实数影响，目标 50 条默认规划 20 个方向，使每个方向平均只承担 2～3 条候选。空间和事实的业务关系都由模型判断；同一自然主题可以承载较多事实，Worker 按每方向最多 4 项事实计算该空间需要的方向槽位，只检查事实覆盖、空间 ID、数量、结构和总容量。Worker 不维护“厨房、切片”等商品关键词，也不把遗漏事实随机塞进某个空间。

方向规划完成后，原有分片 AI 继续复核事实关系、版图和主动作；另一次轻量 AI 会读取全批方向摘要，检查跨分片方向渲染后是否仍会得到相同的主要场景、人物关系、产品主动作和构图。Worker 只验证复核返回的稳定方向 ID 和结构。场景、动作或正文向量过于集中时，多样性补充先由 AI 规划 2～4 个新方向并完成全批重叠复核，再生成补充候选，不再直接复用拥挤旧方向。

向量 MMR 通常使用 `70%` 质量和 `30%` 多样性；候选池正文近重复率超过 50% 时，当轮自动调整为 `60% / 40%`。这仍是软排序，不会因为一般相似删掉候选或破坏精确数量。

历史受控真实 Ark 复验曾在旧容量口径下形成 6 个真实创意空间、13 个方向并覆盖 37/37 项强制业务事实。当前容量策略已升级为 50 条默认 20 个方向、100 条默认 24 个方向，并增加全批 AI 视觉重叠复核；历史数据只证明当时的事实分配链路有效，不代表当前版本最终 Prompt 的质量结论。

风格基调只转译为光线、色彩、材质、镜头质感和情绪底色，不能反向虚构场景、人物或商品事实。方向事实数量按本批信息密度自适应：富信息商品每方向使用 2～4 项彼此有关联的业务事实，中等信息商品至少 1 项，稀疏信息商品只要求把有限业务事实分散到不同方向，剩余方向使用已确认产品基础事实保持关联；所有卖点、痛点、受众、决策动机、营销目标和已确认场景仍必须在整批方向中获得合理用途。每条创意完整继承所属方向的事实组合和 `productSnapshot`，模型仍在一次创意调用中同时生成：

```text
完整创意主线 + 六维信息 + 最终干净正文
```

六维为叙事、场景、人物、产品关联点、镜头和情绪。六项必须属于同一个创意，正文必须真实体现它们。生成模型不按钩子、产品展示、效果、结尾转化四类用途分组；独立评估模型在正文完成后负责质量评分、事实证据核验以及多用途分类。

Prompt 条目不再包含独立的次级素材标签。Worker 只输出评估得到的推荐用途与兼容用途，避免把同一分类再复制为一套可编辑标签。

视觉策略、连贯创意和独立评估分别使用无编号的稳定模板标识。生成角色保持厂商无关，一次调用直接产出可供后续渲染的完整素材 Prompt；镜头、光线和情绪必须服务本条产品动作，不得给不同候选机械套用统一的“电影级、商业广告、高级质感、暖色调、浅景深、缓慢推进”等正向前缀。已有语义和视觉签名只是软避重参考，不能迫使模型使用与产品无关的场景。抽象配方、成分、工艺、认证和背书只能作为商业背景，不能被写成肉眼已经证明的纹理、光泽、纯度或功效。

独立评估模型会同时接收候选声明的完整计划事实组合，并复用同一份视觉策略检查抽象事实是否被错误包装成视觉证明。生成模型必须为每项计划事实返回一段来自正文、创意主线或六维字段的逐字证据；Worker 只验证事实引用和证据位置，评估模型再逐项判断它是完整实现、部分实现还是未实现。只有语义完整且证据真实存在的事实才能形成绑定。包装规格不能证明配方，普通厨房不能证明传统工艺。商品无关、事实捏造和不可执行画面仍是硬问题；方向中的次要事实未完整实现只降低择优顺序，不会让数量恢复流程直接失去候选。

Worker 不再把事实拆成主事实、辅助事实、视觉任务和产品锚点等竞争角色。批次方向模型直接使用整张已确认业务事实表，先为每个方向形成自然的事实关系，再把该关系作为不可拆分的任务简报交给生成模型；产品名称、品类、规格和外观仍由 `productSnapshot` 提供真实性边界，不能冒充卖点、痛点、受众或场景。首轮方向遗漏业务事实时，Worker 只把缺失清单和旧计划交回模型进行一次完整重规划，不会自行把事实补挂到无关方向。

批量生成采用以下规则：

- 首轮候选数为用户目标数量的 `140%`（向上取整），例如目标 50 条时先生成 70 条；需要数量或多样性补充时，候选总数最多为目标数量的 `180%`。
- 创意与分类分片都按实际预算动态规划。分类同时检查输入体量、精简结构化输出体量和目标时长：25～30 秒普通候选每组最多 2 条，异常长正文自动单条执行；多条结构异常时仍只拆分当前分片。评估请求中的事实和视觉策略按分片去重发送，模型不再重复输出可由候选结构确定性派生的事实 ID 列表及内部签名。
- 创意与分类调用共用 `PROMPT_MAX_CONCURRENCY` 滑动并发门限；一个分片完成后立即补入下一个，但分类节点仍等待本轮全部创意分片完成后再启动。
- 评估证据可来自干净正文，也可来自对应的创意主线、场景、人物和产品关联点字段。未知事实、缺失摘录或“摘录与事实不相符”的绑定会被删除；删除后只剩产品名或规格时，该候选不能进入最终结果。
- 核心及次要卖点、核心痛点、目标受众和三类已确认场景均是批次必用事实。初始候选会优先让每项事实获得多个生成机会；最终选择后仍有遗漏时，Worker 会按缺失事实单独生成覆盖候选，再参与同一质量评估和择优，不会用产品名称冒充已覆盖。
- 最终结果恢复 `insightCoverage`：直接呈现的事实使用 `PRIMARY/EVIDENCE`，用于人物、场景、动作或商业语境的事实使用 `CONTEXT`。必用事实仍缺失时保留足量草稿并标记 `NEEDS_REVIEW`，不伪造事实绑定。
- 当前连贯创意简报使用方向模型给出的 `factApplications`，每项包含原始事实和该事实在当前创意中的具体用途。每方向的业务事实下限由整批事实密度决定，不再用固定“至少两项”强迫稀疏商品重复事实。`productSnapshot` 保存产品名称、品类、规格和视觉特征，只用于保持身份与实物边界。
- 完全相同的正文，或完全相同的创意主线与六维组合，才算硬重复。
- 新任务只为 Prompt 正文生成向量，按 `55%` 独立质量分和 `45%` 相对已选集合的新颖度逐条选择。同一语义连通组尚有组外候选可用时优先选组外代表；全部语义组均已覆盖后才允许组内补齐，并按组内负载施加递增软惩罚。新颖度内部继续综合正文向量与业务语义簇，语义簇同时观察六维分类、具体产品动作和真实场景原子。
- 全量生成将人工保留项作为固定相似度参照；单条重新生成将目标条目和当前批次其他 Prompt 一起作为固定参照。新请求直接重做创意方向、六维和正文，并按用户选择的新时长生成；旧正文和旧六维不进入生成模型上下文。参照项不参与淘汰和数量统计。
- 一般相似只影响排序，不会机械删除候选。评估节点以正文余弦相似度不低于 `0.82` 建立连通重复组，每组按 `组内数量 - 1` 计算重复条目；整批 `重复条目数 / 最终数量` 必须严格低于 `15%`。达到或超过 `15%` 时额外生成一次最多目标数 `40%` 的多样性候选，并把高风险组的语义、场景与动作作为避重上下文。最终保护会从未选候选中逐条替换重复项，同时保持数量与必用事实覆盖；仍不合格才保存准确数量的 `NEEDS_REVIEW` 草稿，不能提交工作副本。
- 首轮不足时按实时缺口执行受候选总上限约束的定向补充，并在达到用户数量后立即停止；候选达到目标数 `180%` 后仍不足则保存为待检查结果，不能继续付费重试或伪装成合格批次。
- `ITEM_EVALUATE` 只重新评估用户新增或修改后的原正文，不生成替代正文；评估时读取当前全部可信事实。用户未填写创意主线和六维时，模型才从正文补齐这些结构；用户已完整填写时，模型只校验正文、创意结构与事实是否一致，Worker 保留用户结构，不用推导结果覆盖。两种情况都会重新分析事实绑定、推荐用途和兼容用途。API 在完成时按稳定 ID 合并回原批次；无硬问题为 `VERIFIED`，事实编造、产品无关或正文破损等硬问题为 `NEEDS_REVISION`，且保留安全问题代码供页面提示。

共用提示词继续作为批次级权威数据：创意生成时作为约束上下文传给模型但不自动写入每条正文；后续 Seedance 请求编译时再由第 4 节点追加。时长、画幅和分辨率仍是结构化渲染参数，不依赖正文表达。

API 只向 Worker 下发当前拓扑。不兼容的历史任务在认领时会被安全终止，不会进入模型调用或被套用当前图继续执行；旧数据库记录只作为不可见审计数据保留。

## Provider 与运行隔离

生产默认 Provider 是 Ark；缺少 `ARK_API_KEY` 时启动失败，不会静默降级 Mock。Mock 只允许使用以 `.test` 结尾或 `test.` 开头的 RabbitMQ 队列，防止测试 Worker 消费生产任务。完成回写包含 `executionMode=ARK|MOCK`，API 可拒绝非测试运行的 Mock 结果。

Ark Responses API 在解析 JSON 前检查 `status` 与 `incomplete_details`。输出长度截断会返回 `AI_OUTPUT_TRUNCATED`，未完成响应不会被当作合法 JSON。创意评估的三条合并分片若格式异常或被截断，Worker 会只把该分片拆成单条重新评估；单条仍异常才终止任务。网络、超时、限流和 5xx 的业务重试继续统一由 API 任务层负责。

事实视觉策略、产品创意空间、事实主承载分配和创意方向在模型请求内使用 `F1/F2...` 短事实别名，返回后再机械恢复为权威事实 ID。创意空间 JSON 格式损坏时只局部重取，不占用业务语义修订预算；事实分配缺失、重复、未知引用或整批方向容量不足时，只重取紧凑的事实分配，不重写整套空间。同一空间不再受固定 8 项事实上限约束，Worker 会按事实负载增加方向槽位。只有独立 AI 认为事实与空间语义不自然时，才重新规划产品创意空间。Worker不修改场景语义，也不自行决定事实应去哪个空间。

队列信封只携带当前任务标识，不携带 Prompt 代码版本。Ark 偶尔会把被截断的 JSON 标成 `completed`；候选生成的事实编号会先转换为每条任务私有的 `F1/F2...`，模型返回后再映射回权威事实 ID，避免同一次请求中的多条任务串用事实。新候选必须完整返回本条 `factApplications` 的全部事实，并为每项事实给出确实存在于正文、创意主线或六维字段中的逐字证据；引用越界、遗漏计划事实或证据位置不存在时只隔离该候选。产品身份是否充分和各项事实是否语义完整由独立评估模型判断。批量生成分片连续两次无有效候选时会跳过该分片并交给现有数量补充流程，不降低事实安全门槛，也不再让单条异常拖垮整批。

向量服务使用独立 Provider 和 HTTP 客户端，不复用生成模型。`trigram` 保持字符基线；`shadow` 计算正文向量 MMR 但仍保存字符基线结果；`vector` 才由正文向量 MMR 接管。火山向量模型或 Endpoint 必须显式配置，不能回退到 `ARK_MODEL`。当前账号使用 `doubao-embedding-vision-251215`，通过官方 `/embeddings/multimodal` 端点发送纯文本。该端点每次最多接收一个 `text`，Worker 会自动把每批限制为单条并使用独立并发门限；不会误发到文本 `/embeddings` 端点。`shadow` 下向量故障会在阶段详情留下告警并继续旧算法，`vector` 下则重试或失败，禁止静默降级。

向量正文会去除共用提示词、时长、画幅和固定合规尾段，并把批内共同产品名与品类规范成占位符。原始向量只保存在 Worker 进程内的有界内容缓存中，补充轮次和人工单条评估只向量化新增或变化正文，不写数据库或日志。数据库阶段元数据只保存正文哈希和重复关系边，用于删除条目后的可信重算，不保存正文或向量。

向量进入选择前会转换为 NumPy `float32` 矩阵、按行归一化，并用一次矩阵点积得到全部候选与固定参照的余弦相似度。MMR 选择期间只增量维护每个候选的最大风险，不再重复遍历高维向量。`shadow` 阶段记录字符基线与正文 MMR 的近重复数、平均质量、六维覆盖、选集重合率、矩阵耗时和条件补充判断，这些指标只用于决定是否切换 `vector`，不会改变影子模式的权威结果。

## 环境变量

必填：

- `INTERNAL_API_BASE_URL`
- `EFFECT_PROMPT_WORKER_TOKEN`
- `RABBITMQ_URL`
- `ARK_API_KEY`（`PROMPT_AI_PROVIDER=ark` 时）

常用可选项：

- `EFFECT_PROMPT_QUEUE`，默认 `effect.prompt-generation.requested`
- `PROMPT_AI_PROVIDER`，默认 `ark`
- `ARK_BASE_URL`、`ARK_MODEL`
- `ARK_PROMPT_CANDIDATE_MODEL`：当前连贯创意生成模型；未配置时回退到 `ARK_PROMPT_MODEL`，再回退到 `ARK_MODEL`
- `ARK_PROMPT_FRAGMENT_STRATEGY_MODEL`：批次创意方向规划模型；未配置时跟随候选模型
- `ARK_PROMPT_EVALUATION_MODEL`：当前独立质量评估与用途分类模型；未配置时跟随候选模型
- `ARK_PROMPT_STRATEGY_MAX_OUTPUT_TOKENS`：事实视觉策略、产品创意版图、方向规划与批次方向复核的共享输出额度，默认 `8192`；Ark 会把隐藏推理和结构化正文共同计入该额度
- `ARK_PROMPT_CANDIDATE_MAX_OUTPUT_TOKENS`，默认 `8192`；Worker 会按时长和该上限自动缩小分片，不会让多条长镜头方案挤满一次响应
- `ARK_PROMPT_EVALUATION_MAX_OUTPUT_TOKENS`，默认 `6144`；Worker 会按候选正文体量动态分片
- `PROMPT_EVALUATION_INPUT_TOKEN_BUDGET`，默认 `12000`；只用于 Worker 在调用前规划评估分片，不会修改供应商模型上下文上限
- `ARK_PROMPT_CANDIDATE_TIMEOUT_SECONDS`，默认 `120`
- `ARK_PROMPT_EVALUATION_TIMEOUT_SECONDS`，默认 `120`
- `ARK_PROMPT_PROVIDER_MAX_ATTEMPTS`，默认 `1`
- `PROMPT_SIMILARITY_MODE`：当前固定为 `vector`
- `ARK_PROMPT_EMBEDDING_MODEL`：火山向量 Model ID 或 Endpoint ID；当前使用 `doubao-embedding-vision-251215`；`shadow/vector` 且使用 Ark 时必填
- `ARK_PROMPT_EMBEDDING_API_MODE`：`multimodal|text`，默认 `multimodal`；251215 必须使用 `multimodal`
- `ARK_PROMPT_EMBEDDING_TIMEOUT_SECONDS`，默认 `30`
- `ARK_PROMPT_EMBEDDING_MAX_ATTEMPTS`，默认 `3`
- `PROMPT_EMBEDDING_BATCH_SIZE`，默认 `64`，最大 `256`；多模态端点会按官方上限自动收窄为 `1`
- `PROMPT_EMBEDDING_MAX_CONCURRENCY`，默认 `8`，使用独立并发门限
- `PROMPT_MAX_CONCURRENCY`，默认 `4`，范围 `1..8`
- `PROMPT_SHARD_SIZE`，默认 `8`；实际候选请求会按时长与 Token 安全容量收窄为最多 4 条
- `PROMPT_MAX_AI_CALLS_PER_RUN`，默认 `256`，仅作为异常循环保险丝
- `INTERNAL_API_TIMEOUT_SECONDS`、`ARK_TIMEOUT_SECONDS`、`LOG_LEVEL`

旧策略、关系、坐标和蓝图配置不参与当前 Run，也不能用于恢复旧任务。
