# Worker 通用规则

适用于 `workers/**`。具体 Worker 可用更深层 `AGENTS.md` 补充规则。

## 边界

- 每个 Worker 只处理所属工作流/节点的异步任务，不承载 Web 状态或 API 权限逻辑。
- Worker 从共享契约解析任务，通过 API/队列写回结果，不直接依赖其他 Worker 的内部代码。
- 外部模型通过 Provider/Adapter 封装，业务图和模型供应商协议分离。

## 执行语义

- 同一个 `taskId` 重放必须幂等；写回时携带任务版本，旧执行不得覆盖新任务。
- 明确区分可重试错误、业务阻断、永久失败和部分成功。
- 长步骤定期上报进度并检查取消状态；超时、重试次数和退避策略必须可配置。
- LangGraph 只用于确实需要分支、重试、检查点或人工介入的流程；简单线性调用不要为用框架而用框架。
- Graph State 保持最小，只保存路由和跨节点必需数据；大文件放对象存储，业务实体放数据库。

## Provider 与安全

- 模型、端点和凭证由配置注入；缺失真实配置时 fail fast。
- Mock 仅在明确的测试/演示开关下启用，日志必须标明 Mock。
- 不记录完整 Prompt、上传资料、响应原文或密钥；需要排障时记录脱敏摘要、哈希和供应商请求 ID。

## 验证

- 覆盖契约解析、幂等、重试、取消、超时、部分失败、Provider 异常和旧任务回写。
- 对模型输出做结构校验和业务校验，不能假定供应商永远返回合法 JSON。
