# 效果类 Prompt 生成子工作流节点通俗说明

> 当前状态：已完成
> 适用范围：效果类工作流第 3 个业务节点“Prompt 生成”
> 最后更新时间：2026-08-27

## 1. 这份文档讲的是什么

效果类工作流对用户展示的业务流程固定为：

```text
资料导入 → AI 信息提炼 → Prompt 生成 → 视频渲染 → 模板混剪 → 成片输出
```

本说明讲的是第 3 步“Prompt 生成”内部如何工作。页面里看到的“输入快照”“全局事实分配”“六类营销规划”“质量门禁”等，是系统为了生成和检查 Prompt 而设置的内部处理环节，不是额外增加的业务步骤，也不要求用户逐个操作。

当前 V10 的核心顺序是：`提炼信息应用映射 → 共用提示词编译 → 全局事实分配 → 六类营销组合 → 六类坐标规划 → 组合级蓝图生成 → 全批次正交校验 → 六类 Prompt 生成`。可以把它理解成“先决定每类素材讲哪些已确认事实，再为六类分别准备产品专属拍摄选项，最后为每一个素材位置生成一张完整蓝图”。

可以把整个子工作流理解成一家“短视频素材策划工厂”：

- AI 信息提炼节点交来一份经过确认的产品资料；
- Prompt 生成节点先把资料分类，再规划每条素材要表达什么；
- 六条生产线分别生成六类素材片段 Prompt；
- 最后经过整理、查重、检查和补齐，得到数量准确、职责清楚的一批 Prompt。

这里生成的每条 Prompt 只对应一个可独立渲染的短视频素材片段，不是一条完整广告，也不是最终成片脚本。后续“视频渲染”会将一条 Prompt 渲染成一个素材片段，“模板混剪”再把多个片段组合成完整视频。

### 1.1 V10 最容易混淆的四层对象

V10 不再把“事实为什么放在一起”和“具体怎么拍”混在一个模型输出中。四层对象的区别如下：

| 层级 | 数量由谁决定 | 它回答什么 | 它不回答什么 |
| --- | --- | --- | --- |
| 营销组合 | 程序按每类目标数计算组合数，模型填充事实关系 | 这一组素材应该围绕哪些已确认事实 | 不生成场景、人物、动作、镜头或情绪 |
| 六维坐标计划 | 每个片段类型恰好 1 份，共 6 份 | 这个产品在本类素材中有哪些协调、可拍的叙事/场景/人物/卖点/镜头/情绪候选 | 不是只给一个固定六元组，也不等于最终蓝图 |
| 组合级蓝图 | 每个营销组合按配额获得若干张，总数等于 Prompt 目标数 | 某一个具体素材位置到底怎么拍：选哪套完整六维、首帧、动作弧、结束状态 | 不写最终自然语言 Prompt |
| 最终 Prompt | 一张合格蓝图严格生成一条 | 把蓝图改写为可直接提交视频模型的单镜头自然语言描述 | 不改变蓝图的类型、事实、六维、时长或位置 |

这里没有“一个组合固定生成几张蓝图”的全局常数。组合数和蓝图数由用户设置的每类目标数量共同决定：

```text
每类营销组合数 = min(4, max(1, ceil(该类目标数 / 3)))
每类蓝图总数 = 该类目标 Prompt 数
每个组合的蓝图数 = 把该类目标数尽量平均分给本类组合后的配额
```

默认 50 条配置会得到：

| 类型 | 目标 Prompt | 营销组合数 | 各组合蓝图配额 |
| --- | ---: | ---: | --- |
| 钩子 | 10 | 4 | 3、3、2、2 |
| 痛点 | 8 | 3 | 3、3、2 |
| 产品展示 | 12 | 4 | 3、3、3、3 |
| 卖点讲解 | 10 | 4 | 3、3、2、2 |
| 结尾转化 | 6 | 2 | 3、3 |
| 片尾品牌 | 4 | 2 | 2、2 |

因此默认批次共有 19 个营销组合、50 张首轮蓝图和 50 条首轮 Prompt。营销组合不是 Prompt；一个组合会根据配额生成 2～3 张不同蓝图。

### 1.2 六类营销组合模型到底输入、输出什么

全局事实分配先把已经校验的事实白名单分给六类。然后六个营销组合分支并行调用低成本模型，每个分支只处理一种片段类型。以“卖点讲解 10 条”为例，程序先算出本类需要 4 个组合，然后给模型的安全化输入可以表示为：

```json
{
  "fragmentType": "SELLING_POINT_EXPLANATION",
  "bundleTarget": 4,
  "mandatoryFactIds": ["F04", "F07", "F08"],
  "candidateFacts": [
    {"factId": "F04", "field": "PRODUCT_NAME", "value": "广式腊肠"},
    {"factId": "F05", "field": "VISUAL_FEATURES", "value": "肥瘦相间的真实切面"},
    {"factId": "F06", "field": "CORE_SPECIFICATION", "value": "真空袋装"},
    {"factId": "F07", "field": "CORE_SELLING_POINT", "value": "三七肥瘦比例"},
    {"factId": "F08", "field": "CORE_SELLING_POINT", "value": "广府糖酒腌制工艺"}
  ]
}
```

模型只能输出事实关系：

```json
{
  "fragmentType": "SELLING_POINT_EXPLANATION",
  "bundles": [
    {
      "bundleId": "SELLING_POINT_EXPLANATION-R1",
      "fragmentType": "SELLING_POINT_EXPLANATION",
      "primaryFactId": "F07",
      "factIds": ["F07", "F05", "F04"],
      "creativeIntent": "用真实切面细节承接比例卖点"
    },
    {
      "bundleId": "SELLING_POINT_EXPLANATION-R2",
      "fragmentType": "SELLING_POINT_EXPLANATION",
      "primaryFactId": "F08",
      "factIds": ["F08", "F05", "F04"],
      "creativeIntent": "用真实产品细节承接不可见工艺信息"
    }
  ]
}
```

示例只省略了另外两个组合。注意这里没有“年夜饭厨房”“成年女性双手”“低位推进”或“暖色治愈”。营销组合模型只回答事实之间是否适合共同服务于同一种片段职责。Worker 会拒绝未知事实、跨职责事实、重复事实、组合数不符和必须事实漏配。

### 1.3 六类坐标规划为什么是 6 次调用，而不是 50 次

营销组合合并通过后，系统按片段类型再并行调用 6 次坐标规划模型。每次调用会同时看到本类型全部营销组合，所以它能为不同组合准备可复用但有适用范围的候选。

例如卖点讲解坐标规划模型的输入重点是：

```json
{
  "fragmentType": "SELLING_POINT_EXPLANATION",
  "targetCount": 10,
  "relationshipBundles": [
    {"bundleId": "R1", "primaryFactId": "F07", "factIds": ["F07", "F05", "F04"]},
    {"bundleId": "R2", "primaryFactId": "F08", "factIds": ["F08", "F05", "F04"]},
    {"bundleId": "R3", "primaryFactId": "F05", "factIds": ["F05", "F06", "F04"]},
    {"bundleId": "R4", "primaryFactId": "F04", "factIds": ["F04", "F06"]}
  ],
  "confirmedProductFacts": "只包含信息卡中与本类型兼容的事实",
  "fragmentDuty": "只提供一个真实产品细节或安全使用动作，不伪造工艺过程"
}
```

输出不是一个固定坐标，而是一份六轴候选计划。下面只截取少量候选说明结构：

```json
{
  "fragmentType": "SELLING_POINT_EXPLANATION",
  "narratives": [
    {"coordinateId": "N1", "value": "从完整外观收束到一个真实切面细节", "compatibleBundleIds": ["R1", "R2", "R3"], "sourceFactIds": ["F05"]},
    {"coordinateId": "N2", "value": "以一次安全操作建立产品细节关系", "compatibleBundleIds": ["R1", "R3", "R4"], "sourceFactIds": ["F04"]}
  ],
  "scenes": [
    {"coordinateId": "S1", "value": "年节家庭厨房蒸笼旁的木质案板", "compatibleBundleIds": ["R1", "R2"], "sourceFactIds": ["F04"]},
    {"coordinateId": "S2", "value": "暖色餐桌一角的素色餐盘旁", "compatibleBundleIds": ["R1", "R3", "R4"], "sourceFactIds": ["F04"]}
  ],
  "personas": [
    {"coordinateId": "P1", "value": "只出现成年人的双手和木筷", "compatibleBundleIds": ["R1", "R2", "R3"], "sourceFactIds": []}
  ],
  "sellingPoints": [],
  "cameras": [],
  "emotions": []
}
```

实际严格输出要求六个数组全部非空，并且每一轴都覆盖本类型所有营销组合。`sourceFactIds` 说明该候选依据了哪些已确认事实；像“只出现成年人的双手”这种拍摄执行方案可以没有产品事实来源，但不得借此创造新产品信息。Worker 会重新计算候选文本的规范签名，模型伪造不同 ID 但给出同义内容不能制造虚假差异。

### 1.4 蓝图配额和蓝图模型怎样执行

以卖点讲解的 `3、3、2、2` 配额为例，程序会创建 10 个冻结任务。每个任务固定：片段类型、所属组合、主要事实、允许事实集合、时长、稳定位置和标签。任务本身还没有六维选择和动作方案。

一个任务的输入可表示为：

```json
{
  "slotId": "r0-b0027",
  "fragmentType": "SELLING_POINT_EXPLANATION",
  "bundleId": "R1",
  "primaryFactId": "F07",
  "factIds": ["F07", "F05", "F04"],
  "targetDurationSeconds": 5,
  "coordinatePlan": "上一步整份卖点讲解六维坐标计划"
}
```

蓝图模型必须从 `compatibleBundleIds` 包含 `R1` 的候选中，选择一套协调的完整六维，并写出首帧、一个连续动作弧和结束状态：

```json
{
  "slotId": "r0-b0027",
  "fragmentType": "SELLING_POINT_EXPLANATION",
  "bundleId": "R1",
  "primaryFactId": "F07",
  "usedFactIds": ["F07", "F05", "F04"],
  "narrativeCoordinateId": "N1",
  "sceneCoordinateId": "S1",
  "personaCoordinateId": "P1",
  "sellingPointCoordinateId": "SP1",
  "cameraCoordinateId": "C2",
  "emotionCoordinateId": "E1",
  "openingState": "首帧切开的腊肠片平放在蒸笼旁的木质案板中央",
  "actionArc": "木筷夹起一片腊肠，缓慢转动切面朝向镜头后停住",
  "endingState": "切面稳定清楚，背景蒸汽保持轻微虚化"
}
```

模型不能自己发明坐标，也不能改变类型、组合、主要事实、时长或位置。`usedFactIds` 必须包含主要事实，最多再使用两个直接相关的辅助事实；同一组合有多张任务时会轮动覆盖尚未表达的必需事实，但不会为了覆盖把四五个事实塞进一个五秒片段。

默认 50 个任务按“同一种片段类型不能混片”的规则切成 9 个蓝图分片：`钩子 8+2、痛点 8、产品展示 8+4、卖点讲解 8+2、转化 6、片尾 4`。9 个分片通过 LangGraph `Send` 并行调用，最大并发为 6。正常首轮随后还会形成相同数量的 9 个 Prompt 分片。

### 1.5 如何在优先保证数量的前提下拉开六维差异

六份坐标计划只是提供候选，不能单独保证 50 张蓝图互不相似。所有蓝图汇合后，Worker 使用六个坐标的规范文本签名，对全批次进行统一比较：

```text
叙事、场景、人物、卖点、镜头、情绪
```

片段类型本身不算差异。默认 50 张需要比较 `50 × 49 ÷ 2 = 1225` 对，既包括同一组合内，也包括同类型不同组合之间，还包括钩子与产品展示等跨类型比较。这个比较现在用于“优先选谁”和形成质量告警，不再把“任意一对少于三个维度不同”当作逐条硬删除条件。原因很直接：用户要求 50 条时，系统第一责任是交付 50 条和准确的六类数量，不能为了追求理论上的零相似只留下十几条。

选择合格蓝图时的优先级固定为：

```text
先补足总数、六类数量和每个营销组合的配额
→ 再覆盖必须事实
→ 再让新蓝图与已选集合的最小距离尽可能大
→ 最后按稳定任务顺序决定并列项
```

六维相同但首帧、连续动作或结束状态不同的两张蓝图可以同时保留，它们会被标记为相似但不算完全重复。只有六维和实际拍摄内容都相同，或出现事实越界、虚构证据、职责冲突、无法执行等硬问题时才会剔除。如果某个组合因此原本需要 3 张却只剩 1 张，缺口为 2，补齐轮才会回到同一片段类型、同一营销组合生成 `ceil(2 × 1.25) = 3` 张新蓝图候选。

Prompt 层也采用同一口径：语义重复率和画面重合率按完整批次计算，而不是发现一对相似就删一条。50 条中允许存在少量相似对，只要整批不超过用户设置的上限；即使最终超过上限，也会优先保留 50 条并标记为“需要复核”，不会再用 18 条短批次冒充生成完成。

### 1.6 V10 正常调用量和模型分层

默认 50 条、首轮无缺口时：

| 阶段 | 调用数 | 默认模型 | 原因 |
| --- | ---: | --- | --- |
| 六类营销组合 | 6 | Doubao Seed 2.0 Lite | 只做事实关系，输出小 |
| 六类坐标计划 | 6 | Doubao Seed 2.0 Lite | 一类一次，避免为 50 条逐条规划坐标 |
| 组合级蓝图 | 9 | Doubao Seed 2.0 Lite | 每片最多 8 张，负责选择协调坐标与动作方案 |
| 最终 Prompt | 9 | Doubao Seed 2.1 Turbo | 把冻结蓝图写成高质量自然语言 |
| 合计 | 30 | 分层使用 | 最大并发 6，不增加第三次模型审查 |

这就是为什么系统不是“为每条 Prompt 单独调用一次坐标模型”：坐标规划只有 6 次，一份坐标计划服务本类型所有组合；真正逐条不同的是蓝图任务，但蓝图以每片最多 8 张批量生成，所以默认只需 9 次蓝图调用。

> 本节是当前 V10 权威说明。下文若出现“V9 完整母版”“程序确定性补充场景人物动作”或“片段蓝图编排直接从固定池拼坐标”等表述，仅用于保留历史演进背景，不再代表当前执行逻辑。

## 2. 用“广式腊肠”贯穿举例

为了便于理解，下文统一使用“广式腊肠”举例。下面的内容只是帮助理解流程的示例，不代表系统会凭空认定这些事实；真正生成时只能使用上游信息卡中已经确认的内容。

假设 AI 信息提炼节点已经确认：

- 产品：广式腊肠；
- 目标受众：年节家庭聚餐的备餐人群；
- 核心痛点：准备团圆餐时菜品多、时间紧，希望快速增加一道有节日氛围的菜；
- 核心卖点：广府糖酒腌制工艺、三七肥瘦比例、切面油润；
- 使用场景：年夜饭厨房、家人团聚餐桌；
- 购买动机：备餐方便、适合家庭分享；
- 营销目标：让用户产生进一步了解或购买的意愿；
- 禁用元素：不能宣传疾病治疗效果，不能编造折扣、销量或认证。

用户在 Prompt 节点设置共 50 条：

| 片段类型     |  数量 | 单条时长 |
| ------------ | ----: | -------: |
| 钩子片段     | 10 条 |     5 秒 |
| 痛点片段     |  8 条 |     5 秒 |
| 产品展示片段 | 12 条 |     5 秒 |
| 卖点讲解片段 | 10 条 |     5 秒 |
| 结尾转化片段 |  6 条 |     5 秒 |
| 片尾品牌片段 |  4 条 |     5 秒 |

系统成功保存的新批次必须正好是 50 条，并且六类数量分别符合上表。不能用“其他类型多生成几条”来抵消某一类型的缺口。

### 2.1 一个完整批次到底是怎样跑完的

下面不再只举一句 Prompt，而是完整模拟一次“广式腊肠”批次从已提交信息卡进入系统，到 50 条素材 Prompt 保存成功的全过程。示例中的名称、数据和画面仅用于解释系统行为，不代表数据库中的真实项目，也不允许模型把示例中未被上游确认的内容当成产品事实。

#### 第一步：系统收到的不是一句产品名，而是一份已确认信息卡

本次任务读取的是 AI 信息提炼节点已经“完成校验”的工作副本。为了便于阅读，可以把它理解为下面这份业务资料：

| 信息类别 | 本次已确认内容 | 对 Prompt 生成的影响 |
| --- | --- | --- |
| 产品身份 | 真空袋装广式腊肠，食品类 | 产品展示和片尾可以出现袋装产品，但不能自行改变品类 |
| 可见外观 | 腊肠呈红褐色，切开后可见肥瘦相间的真实切面 | 可以用于产品展示或卖点讲解的画面依据 |
| 核心卖点 A | 三七肥瘦比例 | 可以绑定到切面细节，但画面只能展示切面，不能声称镜头已经科学证明比例 |
| 核心卖点 B | 广府糖酒腌制工艺 | 没有生产过程图片或视频，因此不能生成腌制车间、工厂或工人操作，只能把卖点保留为结构化绑定，并拍真实产品细节 |
| 次要卖点 | 适合切片蒸制和家庭分享 | 可以设计夹起、摆盘等安全使用动作，但不能虚构具体蒸制时间 |
| 目标受众 | 年节家庭聚餐的备餐人群 | 用于规划场景和人物，不会把整段受众画像复制进画面 Prompt |
| 核心痛点 | 同时准备多道菜，案板和餐盘拥挤，备餐节奏紧张 | 适合钩子或痛点片段，不应在同一片段内立即由产品解决 |
| 使用场景 | 年夜饭厨房、家人团聚餐桌 | 可以进入画面，但单条素材只能选一个具体场景 |
| 营销目标 | 引导用户进一步了解产品 | 由结尾转化素材提供干净留白，具体 CTA 在后续混剪添加 |
| 视觉基线 | 写实、暖色、具有年节烟火感 | 转译为木桌、暖色窗光、柔和蒸汽等可见条件，而不是在正文里只写“高级感” |
| 强制禁用 | 医疗或保健功效、未经确认的折扣/价格/销量/认证、虚构生产过程 | 作为全批约束；任何候选一旦出现这些内容会被门禁剔除 |
| 未确认信息 | 具体价格、销量排名、生产认证编号、精确蒸制时间 | 不得进入事实应用表，也不得出现在最终正文 |

这里有一个非常重要的区别：

- “三七肥瘦比例”是上游确认的卖点事实；
- “镜头中能看见肥瘦相间的切面”是允许使用的视觉证据；
- “镜头证明了精确比例”则是系统不允许得出的结论。

系统会保留这个边界，避免模型为了“讲清卖点”而把可见细节夸大成检测结论。

#### 第二步：用户设置的是一个素材池，不是一条 50 镜头的视频

用户本次选择：

```text
钩子 10 条 × 5 秒
痛点 8 条 × 5 秒
产品展示 12 条 × 5 秒
卖点讲解 10 条 × 5 秒
结尾转化 6 条 × 5 秒
片尾品牌 4 条 × 5 秒
语义重复度上限 15%
画面重合度上限 20%
```

这表示系统要生产 50 个可独立渲染的素材片段方案。它不表示一条成片有 250 秒，也不表示系统现在就决定最终成片会使用哪 50 条。后续模板混剪可能从素材池里选择“1 条钩子 + 1 条痛点 + 1 条产品展示 + 1 条卖点讲解 + 1 条转化 + 1 条片尾”组成一条成片，也可能根据模板只使用其中部分类型。

#### 第三步：输入快照实际锁定了什么

任务启动后，“输入快照”会锁定下面这些内容：

```text
产品：广式腊肠
上游信息卡：本次启动时已经完成校验的版本
目标总数：50
六类配额：10 / 8 / 12 / 10 / 6 / 4
六类时长：全部 5 秒
质量阈值：语义 15%，视觉 20%
操作类型：全批生成
需要保留的人工条目：0
共用强制禁用：医疗功效、虚构价格销量认证、虚构生产过程
```

假设任务执行期间，用户回到信息提炼页面，把“适合家庭分享”改成“适合独自食用”，但没有点击“完成校验”，本次任务仍然使用启动时的已提交内容，不会在生成到第 30 条时突然换成另一套事实。

#### 第四步：提炼信息应用映射怎样决定“谁能用什么”

系统不会把所有事实一股脑塞给每条 Prompt，而是先形成一张应用映射表。下面是本例中一部分映射结果：

| 已确认事实 | 事实状态 | 适合的片段类型 | 不允许的用法 |
| --- | --- | --- | --- |
| 年节备餐空间拥挤 | 可用，痛点优先 | 钩子、痛点 | 产品展示片段里长篇讲痛点；同条立即解决问题 |
| 红褐色外观 | 可用，可见属性 | 产品展示、卖点讲解、片尾品牌 | 夸成“零添加”“天然健康” |
| 肥瘦相间切面 | 可用，可见属性 | 产品展示、卖点讲解 | 仅凭画面断言检测数值 |
| 三七肥瘦比例 | 核心卖点，必须覆盖 | 卖点讲解优先，产品展示可辅助 | 在钩子或痛点中强行出现；伪造实验检测 |
| 广府糖酒腌制工艺 | 核心卖点，必须覆盖；当前只能文字绑定 | 卖点讲解 | 虚构工厂、酒液注入、配方实验或消费者“演示工艺” |
| 家庭分享 | 可用，购买动机 | 结尾转化、部分场景规划 | 生成未经确认的人数、身份或宴席规模 |
| 价格待确认 | 排除 | 无 | 任何价格、折扣、限时促销 |

因此，一条产品展示 Prompt 可能只使用“产品身份 + 红褐色外观”，不会因为系统还知道受众、痛点、工艺和购买动机，就把这些信息全写进同一个五秒画面。

#### 第五步：共用提示词编译怎样保持正文干净

本批次编译出的共用约束可以用通俗语言概括为：

> 保持写实食品质感；不得生成医疗或保健功效，不得编造价格、折扣、销量和认证，不得虚构工厂、实验室、生产过程或精确可读包装文字；素材画面不烧录字幕、口播、二维码或促销贴纸。

这段内容会在生成和后续视频任务中统一应用，但不会机械复制到每一条卡片正文末尾。否则 50 条 Prompt 都会重复同一段禁用说明，既影响阅读，也挤占真正有用的画面描述。

#### 第六步：先全局分配事实，再生成六类营销组合（V10）

> 本小节后面的 R1～R6 表格是历史 V9“完整母版”示意。V10 中相同表格必须拆成三步理解：营销组合只保留事实关系；六类坐标计划再提供产品专属拍摄候选；组合级蓝图最后选择完整六维并生成首帧、动作弧和结束状态。当前输入输出以第 1.2～1.5 节为准。

Worker 先决定每条核心事实主要由哪一类片段负责，避免六个分支抢同一条信息或遗漏重要信息；随后六个 AI 分支并行规划，每个分支只看自己允许使用的事实。以下是本例中六组代表性母版：

| 关系编号 | 片段职责 | 人物或主体 | 问题/动机 | 场景 | 可使用事实 | 画面方向 |
| --- | --- | --- | --- | --- | --- | --- |
| R1 | 钩子 | 只出现成年人的手和被遮挡的蒸笼 | 想知道蒸汽后是什么 | 年节厨房 | 食品品类、年节场景 | 蒸笼盖掀开一条缝，在完全揭晓前停住 |
| R2 | 痛点 | 一名正在备餐的成年人 | 案板被多种食材占满 | 年夜饭厨房 | 备餐空间拥挤 | 手端餐盘寻找落点，最后仍无处放置 |
| R3 | 产品展示 | 袋装腊肠作为唯一主角 | 快速识别产品 | 暖色木桌 | 产品身份、红褐色外观 | 手将包装缓慢转正，结束为清楚英雄构图 |
| R4 | 卖点讲解 | 腊肠切面作为唯一主角 | 看清产品细节 | 蒸笼旁的木质案板 | 肥瘦相间切面、三七肥瘦比例绑定 | 筷子夹起一片并轻转切面，但不声称检测结论 |
| R5 | 结尾转化 | 产品和年节餐桌 | 为后续行动提示留位置 | 团聚餐桌一角 | 家庭分享、营销目标 | 手将产品放稳后退出，右侧形成自然留白 |
| R6 | 片尾品牌 | 稳定产品静物 | 安静结束 | 简洁暖色桌面 | 产品身份、视觉基线 | 画面轻微收焦后完全静止 |

不合理的关系会在这个阶段被排除。例如，“户外跑步的人因为工作文件太多而拿起广式腊肠”虽然在场景、人物、动作上看起来很不一样，但和上游事实没有可靠关系，系统不会为了追求差异而制造这种组合。

#### 第七步：组合级蓝图如何把事实关系与坐标计划变成可生成任务

> 下方单张蓝图内容仍可作为结果示例，但它不再由程序从固定池确定性拼装，而是蓝图模型从所属类型的产品专属坐标计划中整体选择；程序只冻结任务、分配配额并校验结果。

关系 R4 还不是最终 Prompt。系统会把它编排成一个冻结蓝图，明确模型只能在这个边界里写画面：

```text
蓝图位置：卖点讲解类的第 3 个位置
片段类型：卖点讲解
目标时长：5 秒
主要主体：一片已经切开的广式腊肠
具体场景：年节厨房内、蒸笼旁的木质案板
首帧：切片平放在案板上，筷子从画面上方接近
主要动作弧：筷子夹起切片 → 缓慢转动切面朝向镜头 → 停住
主景别：近景
机位：桌面高度
主要运镜：轻微平稳靠近
光线与材质：暖色侧光、真实油润纹理、少量自然蒸汽
结束状态：切面稳定清楚，背景仍为厨房环境
主要事实：肥瘦相间的真实切面
卖点绑定：三七肥瘦比例
辅助事实：产品为广式腊肠
禁止：工厂、实验室、比例检测动画、字幕、口播、第二个动作、镜头切换
```

冻结的意思是：候选模型可以把这些内容写得自然，但不能擅自把人物换成厨师、把厨房换成实验室、把动作换成切割加摆盘，也不能把卖点改成“销量第一”。

#### 第八步：条件路由将 50 个蓝图送入六条不同生产线

本轮蓝图被按片段类型确定性分组：

```text
钩子分支：10 个位置，拆成 8 + 2 两个分片
痛点分支：8 个位置，拆成 8 一个分片
产品展示分支：12 个位置，拆成 8 + 4 两个分片
卖点讲解分支：10 个位置，拆成 8 + 2 两个分片
结尾转化分支：6 个位置，拆成 6 一个分片
片尾品牌分支：4 个位置，拆成 4 一个分片
```

每个分片只包含一种片段类型，因此钩子生成规则不会误用到片尾品牌上。分片可以并行，但最终结果仍按稳定类型顺序和类型内位置排序。

#### 第九步：六个分支会生成怎样的正文

下面各展示一条达到目标的候选。时长、画幅、片段类型和卖点绑定都保存在结构化字段里，所以正文只描述视频模型真正需要生成的画面。

**1. 钩子片段候选**

> 年节厨房的暖色蒸汽从竹蒸笼边缘缓慢溢出，一只成年人的手将木盖掀开一道窄缝，里面红褐色食物只露出模糊局部。桌面高度近景迅速靠近后停住，焦点落在盖沿与蒸汽交界处，动作结束时木盖仍遮住大部分主体，悬念没有揭晓。

为什么合格：只有“掀开一道缝”一个连续动作；结尾没有揭晓完整产品，也没有解释卖点或出现购买引导。

**2. 痛点片段候选**

> 年夜饭厨房的案板旁堆着待处理的食材和空餐盘，一名穿素色围裙的成年人双手端着刚整理好的圆盘，尝试在台面寻找一次落点后无奈停住。俯拍中近景保持固定，暖色顶光照出拥挤的操作区，结束时餐盘仍悬在手中，问题没有被解决。

为什么合格：只呈现“没有落盘空间”这一项问题；产品没有出现，更没有在同一条里解决痛点。

**3. 产品展示片段候选**

> 真空袋装广式腊肠从首帧起完整放在暖色木桌中央，一只手扶住包装边缘，将略微侧斜的产品缓慢转正后离开画面。正面近景做轻微水平移动，柔和窗光表现袋内红褐色产品的真实轮廓，结束停在包装完整、主体清楚的稳定构图。

为什么合格：产品首帧建立主体，只发生一次“转正”动作；没有切开、蒸制、试吃或满意反应，不会与卖点和效果素材混在一起。

**4. 卖点讲解片段候选**

> 蒸笼旁的木质案板上放着一片已经切开的广式腊肠，木筷从画面上方夹起切片，缓慢转动至切面朝向镜头后停住。桌面高度近景平稳靠近，焦点持续落在肥瘦相间的真实纹理上，暖色侧光勾出自然油润感，背景保持轻微虚化。

为什么合格：它为“切面细节”提供了真实画面，也可以承载“三七肥瘦比例”的后续字幕，但正文没有声称镜头完成了比例检测，更没有虚构生产工艺。

**5. 结尾转化片段候选**

> 暖色年节餐桌的左侧摆着竹蒸笼和一只素色餐盘，一只成年人的手将袋装广式腊肠平稳放到餐盘旁，轻轻扶正后退出画面。正面中近景缓慢靠近并停止，产品保持清楚，右侧简洁墙面与桌面形成无遮挡留白，画面在稳定构图上结束。

为什么合格：它只形成收束画面和安全留白，不直接生成“立即购买”、价格、二维码或按钮；这些内容由后续混剪决定是否叠加。

**6. 片尾品牌片段候选**

> 简洁暖色桌面上，袋装广式腊肠与一只竹蒸笼安静摆放，背景灯笼形成柔和虚化光点。固定近景从轻微虚焦缓慢恢复到产品轮廓清楚，桌面反光逐渐稳定，画面随后保持静止，中央上方留出干净区域供后续品牌信息使用。

为什么合格：没有新剧情和新卖点，主体几乎不动，只用一次收焦形成可以持续停留的片尾画面。

#### 第十步：结构标准化如何保存“一条真实条目”

以卖点讲解候选为例，标准化后的条目可以通俗地表示为：

```text
编号：本类型内的稳定位置，最终保存时统一编号
片段类型：卖点讲解
目标时长：5 秒
正文：蒸笼旁的木质案板上放着一片已经切开的广式腊肠……
叙事结构：细节观察型
场景：年节厨房的蒸笼与木质案板
人物：无完整人物，仅成年人的手和木筷
卖点侧重：三七肥瘦比例
镜头语言：桌面高度近景，平稳靠近
情绪基调：温暖、真实、克制
提炼来源：产品身份、切面可见特征、三七肥瘦比例
素材标签：食品切面、筷子夹取、暖色厨房
```

正文和元数据各司其职：视频模型得到的是自然画面描述；后续混剪和检索使用片段类型、时长、卖点和素材标签；质量检查使用六维和事实绑定。系统不会把“叙事结构=细节观察型、卖点侧重=……”这些字段重新拼回正文。

#### 第十一步：一个候选是怎样被门禁淘汰的

假设卖点分支还生成了下面这条内容：

> 视频生成方案：先展示消费者在厨房拿起广式腊肠，随后切换到传统工厂，工人演示广府糖酒腌制工艺，最后产品包装出现并配上“百年工艺、立即购买”的字幕和欢快背景音乐。

这条不会被“稍微改写后继续使用”，而会直接被执行门禁剔除，原因包括：

| 命中原因 | 具体问题 |
| --- | --- |
| 策划元话语 | 正文出现“视频生成方案”，它不是可拍画面 |
| 完整时间线 | 使用“先……随后……最后……”组织多个阶段，不是一个五秒单镜头素材 |
| 镜头/场景冲突 | 厨房切换到工厂，包含多个场景和剪辑动作 |
| 不可拍证据 | 上游没有生产过程素材，却虚构工人演示腌制工艺 |
| 烧录文字 | 要求生成可读字幕“百年工艺、立即购买” |
| 音频越界 | 要求完整背景音乐，降低后续混剪复用性 |
| 未确认事实 | “百年工艺”没有来源支持 |
| 片段职责冲突 | 卖点讲解同时承担产品展示、生产证明和转化 CTA |

系统会记录“卖点讲解缺 1 条”，然后按原来的卖点和片段类型重新生成一个安全候选，而不是通过删几个词把这条多场景广告强行洗成合格内容。

再看一个更隐蔽的错误：

> 首帧是真空袋装腊肠，手将包装放到蒸笼里，镜头靠近时包装瞬间变成已经切好的热腾腾腊肠，最后切片自动排列成花形。

它虽然没有元话语，却会因为“包装瞬间变成成品”和“切片自动排列”产生不必要的物理断裂。系统会命中物理连续性问题并剔除，不会把这种无法稳定生成的变化交给视频渲染节点。

#### 第十二步：语义去重和视觉重合不是一回事

第一轮标准化后，假设得到 56 条有效候选，多出的 6 条用于给去重留余量。系统两两比较，共有：

```text
56 条候选
两两组合数 = 56 × 55 ÷ 2 = 1540 对
```

下面两条可能命中语义重复：

- A：筷子夹起腊肠切片，缓慢把切面转向镜头；
- B：木筷提起一片腊肠，使肥瘦相间的一面朝向摄影机。

两条换了词，但主体、动作和表达目的基本相同。

下面两条则可能文字目的不同，却命中视觉重合：

- C：为了展示切面油润，在木案板上用筷子夹起切片，低机位靠近，暖色侧光；
- D：为了承载三七肥瘦比例，在木案板上用筷子夹起切片，低机位靠近，暖色侧光。

C 和 D 的卖点不同，但拍出来的场景、主体、动作、机位、运镜和光线几乎相同。系统会保留其中综合价值更高的一条，另一条进入剔除清单。

假设本轮结果如下：

```text
执行门禁剔除：3 条
语义重复剔除：2 条
视觉重合剔除：2 条
剩余可用：49 条
当前缺口：卖点讲解 1 条
当前核心卖点覆盖：三七肥瘦比例已覆盖；广府糖酒腌制工艺仍缺安全承载条目
```

#### 第十三步：定向补齐如何只补缺少的那一格

系统不会重做另外 49 条，而是生成一张新的补齐蓝图：

```text
缺少类型：卖点讲解
缺少数量：1
优先覆盖卖点：广府糖酒腌制工艺
证据边界：没有过程素材，只允许真实产品细节；卖点留在元数据供后续文案使用
需要避开的已有画面：木案板 + 筷子夹切片 + 低机位靠近 + 暖色侧光
新画面方向：蒸笼内整段产品 + 蒸汽散开 + 固定俯拍 + 柔和顶光
```

补齐分支生成：

> 打开的竹蒸笼内整齐放着两段广式腊肠，薄薄蒸汽沿竹篾缓慢散开，一只手用木夹轻轻转动其中一段，让表面真实色泽朝向上方后停住。固定俯拍近景保持稳定，柔和暖光落在产品与竹篾纹理上，蒸汽逐渐变淡，结束时主体仍清楚完整。

这条没有虚构糖酒腌制过程，只提供一段可以在后续混剪中配合该卖点字幕使用的干净产品细节素材。同时它避开了已有的“切片 + 筷子 + 低机位推近”画面组合。

补齐条目仍然要重新经过结构标准化、执行门禁、语义去重、视觉重合和覆盖校验。只有它与现有 49 条一起通过，系统才会得到最终 50 条。

#### 第十四步：质量门禁最终看见的不是一句“通过”，而是一套结论

本次最终检查可以得到如下结果：

| 检查项 | 目标 | 实际结果 | 结论 |
| --- | ---: | ---: | --- |
| Prompt 总数 | 50 | 50 | 通过 |
| 钩子片段 | 10 | 10 | 通过 |
| 痛点片段 | 8 | 8 | 通过 |
| 产品展示片段 | 12 | 12 | 通过 |
| 卖点讲解片段 | 10 | 10 | 通过 |
| 结尾转化片段 | 6 | 6 | 通过 |
| 片尾品牌片段 | 4 | 4 | 通过 |
| 每条时长 | 按所属类型为 5 秒 | 全部匹配 | 通过 |
| 核心卖点覆盖 | 两个核心卖点至少各有安全承载 | 均已覆盖 | 通过 |
| 单条职责 | 不跨片段职责 | 无越界条目 | 通过 |
| 单一动作和运镜 | 每条最多一个主要动作弧、一种主运镜 | 全部满足 | 通过 |
| 语义重复度 | 不高于 15% | 示例假设为 6.4% | 通过 |
| 画面重合度 | 不高于 20% | 示例假设为 9.1% | 通过 |
| 未确认事实 | 0 条 | 0 条 | 通过 |
| 烧录文字/口播/BGM | 0 条 | 0 条 | 通过 |

这里的 6.4% 和 9.1% 只是为了说明页面如何展示指标，不是对真实项目的检测结果。

#### 第十五步：结果保存以后，视频渲染和混剪到底拿到什么

结果保存会得到一个由 50 个条目组成的批次。每个条目至少包含：

```text
稳定条目标识
稳定编号和列表位置
片段类型
目标时长
可直接用于视频生成的正文
六维元数据
素材次级标签
实际使用的提炼事实绑定
人工编辑状态
```

批次层另外保存：

```text
六类数量配置
画幅、分辨率等渲染配置
全批共用提示词
质量指标和覆盖结论
来源信息卡快照
```

用户点击“完成校验”后，视频渲染节点会按照“一条 Prompt → 一个素材片段”创建任务。例如：

```text
钩子 P001 → 渲染为钩子素材 H001
痛点 P011 → 渲染为痛点素材 PA001
产品展示 P019 → 渲染为产品素材 PD001
卖点讲解 P031 → 渲染为卖点素材 SP001
结尾转化 P041 → 渲染为转化素材 CTA001
片尾品牌 P047 → 渲染为片尾素材 O001
```

到了模板混剪节点，某一条成片工程才可能这样选材：

```text
模板钩子位 ← H001
模板痛点位 ← PA001
模板产品位 ← PD001
模板卖点位 ← SP001
模板转化位 ← CTA001
模板片尾位 ← O001
```

因此，Prompt 节点中的“差异化”不是要在正文里写“这条和别条不同”，而是让素材池中真实存在不同的场景、动作、机位、构图和片段职责，方便后续混剪有足够多的可靠素材可选。

## 4. 第一阶段：把输入准备清楚

### 4.1 输入快照

**通俗理解：** 开工前先把本次要用的资料和设置“装箱封存”，避免生成到一半时输入悄悄变化。

**输入：**

- AI 信息提炼节点已经完成校验的信息卡；
- 用户设置的六类片段数量和各自时长；
- 当前共用提示词；
- 人工保留的 Prompt（例如单条重生成时需要保留的其他条目）；
- 本次操作类型，例如批量生成或单条重新生成。

**处理：**

- 锁定本次实际使用的上游内容；
- 检查输入版本和生成规则是否兼容；
- 恢复同一任务中已经成功生成的分片，避免重复劳动。

**输出：** 一份本次任务专用、后续节点都按它执行的稳定输入。

**广式腊肠例子：** 系统锁定“当前已确认的广式腊肠信息卡 + 50 条配额 + 每类 5 秒”。即使用户此时回到上游编辑页面但还没有完成校验，本次任务也不会读到那份未确认修改。

### 4.2 提炼信息应用映射

**通俗理解：** 给信息卡中的每条信息贴上“必须用”“有位置就用”“不能用”的标签，并说明它适合放在哪类片段里。

**输入：** 输入快照中的产品素材制作信息卡。

**处理：**

- 为每条可用事实建立稳定编号，方便后续准确引用；
- 把事实分为强制应用、自适应应用和排除项；
- 限定每条事实可以由哪些片段类型承载；
- 排除“待确认”“未知”“需核实”等不确定内容；
- 防止价格、认证、销量、功效等敏感信息被模型自行补造。

**输出：** 一张“提炼事实应用表”。它只负责整理事实，不直接生成 Prompt。

**广式腊肠例子：**

- “三七肥瘦比例”可以交给产品展示或卖点讲解片段；
- “年节备餐时间紧”可以交给钩子或痛点片段；
- “适合家庭分享”可以参与结尾转化片段；
- “价格待确认”会被排除，不能进入本批 Prompt。

### 4.3 共用提示词编译

**通俗理解：** 把整批 Prompt 都要遵守的共同要求整理成一段统一说明，避免在 50 条正文里重复维护。

**输入：**

- 上游确认的禁用元素；
- 用户补充的批次共用要求。

**处理：**

- 将共同要求合并为一段共用提示词；
- 生成 Prompt 时把它作为约束交给模型，要求遵守但尽量不要在每条正文里复述；
- 保存为批次级内容，而不是复制进每条 Prompt 正文。

**输出：** 一段整批共同使用的共用提示词。

**广式腊肠例子：** 共用提示词可以包含“不得宣传治疗或保健功效，不得编造折扣、销量和认证；保持写实食品质感”等要求。每条卡片仍只展示自己的干净画面描述。后续创建视频任务时，系统再把同一份共用提示词追加一次。

## 5. 历史 V9 第二阶段说明（已被 V10 第 1.1～1.6 节取代）

> 本章保留 V9 的详细推导，便于理解为什么要升级 V10，不再作为当前实现依据。当前营销组合不含场景、人物、动作、镜头和情绪；当前蓝图也不由程序从固定白名单拼装。

### 5.1 历史 V9：全局事实分配与六类 AI 营销规划

**通俗理解：** 提炼信息应用映射先回答“每条事实允许进入哪些片段类型”；全局事实分配再回答“哪一类主要负责这条核心事实”；最后六类 AI 营销规划分别回答“本类片段里，哪些事实放在一起、在什么场景、由谁做什么、镜头怎么拍才合理”。

它不是把同类型 Prompt 合并，也不是把钩子、痛点、产品展示等六种片段拼成一条广告。每一套关系只属于一种片段类型，可以被该类型的多条 Prompt 重复选用。

可以把它理解成六位同时工作的“专门导演”：

```text
钩子导演：只设计悬念
痛点导演：只设计尚未解决的问题
产品展示导演：只设计产品英雄画面
卖点讲解导演：只设计有安全证据的卖点表达
结尾转化导演：只设计行动留白
片尾品牌导演：只设计稳定收尾
```

每位导演会产出 1～4 个完整母版。母版里的场景、人物、动作、镜头、情绪和结束状态绑定在一起，后续只能做有限细节变化，不会跨母版拆开重组。

#### 5.1.1 这个节点为什么需要模型

确定性应用映射只知道单条事实的允许范围，例如：

```text
“年节家庭备餐人群”允许进入：钩子、痛点、结尾转化
“备餐空间拥挤”允许进入：钩子、痛点
“年夜饭厨房”允许进入：钩子、痛点、产品展示
```

但是它不知道下面三个事实是否真的应该放在同一套关系中：

```text
年节家庭备餐人群
+ 备餐空间拥挤
+ 年夜饭厨房
```

策略模型负责判断事实之间的业务相关性，避免系统只做随机笛卡尔积，产生“每条事实都是真的，但放在一起没有逻辑”的组合。

#### 5.1.2 模型实际收到什么

模型不直接读取完整信息卡，也不会收到图片、文件正文、最终 Prompt 或内部存储信息。Worker 只传入：

- 本批目标 Prompt 数量，用于判断关系丰富度；
- 已完成安全分类的可用事实；
- 每条事实允许进入的片段类型；
- 批次约束，只用于判断安全边界，不能被模型作为输出事实。

#### 5.1.4 每种片段有多少套关系，每套有多少事实

当前数量规则分为三层：

| 层级 | 当前规则 | 含义 |
| --- | --- | --- |
| 每种片段类型的关系套数 | 1～4 套 | 例如 10 条钩子可以共用 2～4 套钩子关系 |
| 一套关系中的候选事实数 | 1～8 个 | 关系是可复用事实池，不代表所有事实都要写进同一条素材 |
| 一条 Prompt 实际表达的事实数 | 1～3 个 | 防止几秒素材承担过多业务信息 |

六种片段的模型关系总数最多 24 套。用户设置 50 条 Prompt，并不意味着模型输出 50 套营销关系。

例如 10 条钩子有三套关系：

```text
H1：F01 家庭备餐人群 + F02 空间拥挤 + F03 年夜饭厨房
H2：F01 家庭备餐人群 + F09 备餐方便动机 + F11 家庭年货采购
H3：F02 空间拥挤 + F09 备餐方便动机 + F03 年夜饭厨房
```

片段蓝图编排会在钩子关系池中轮动选择：

```text
钩子 1 → H1
钩子 2 → H2
钩子 3 → H3
钩子 4 → H1
钩子 5 → H2
钩子 6 → H3
钩子 7 → H1
钩子 8 → H2
钩子 9 → H3
钩子 10 → H1
```

重复使用 H1 不代表生成相同 Prompt。后续蓝图会为它们分配不同的叙事开场、人物方案、镜头和情绪，并继续接受六维距离和双重去重检查。

#### 5.1.5 一套关系的事实是否全部进入单条 Prompt

不一定。一套关系可以有 1～8 个候选事实，但单条素材最多选 3 个。

如果关系只有三个事实，例如 H1，三个事实会全部进入该条素材的绑定：

```text
主要事实：备餐空间拥挤
人物上下文：年节家庭备餐人群
场景上下文：年夜饭厨房
```

如果产品展示关系有六个事实，Worker 会按片段类型的事实优先级和当前未覆盖事实进行轮动：

```text
产品展示 1：产品名称 + 可见外观 + 核心规格
产品展示 2：产品名称 + 使用场景 + 产品品类
产品展示 3：产品名称 + 可见外观 + 一个职责兼容的核心卖点
```

因此，“一套关系包含几个事实”和“一条 Prompt 实际表达几个事实”是两个不同概念。

#### 5.1.6 Worker怎样限制和修正模型输出

模型只是提出关系组合，Worker 才是最终裁判。每一套模型关系都要依次通过：

```text
factId 是否真实存在于当前输入
        ↓
同一套关系是否重复引用 factId
        ↓
每条事实是否允许进入指定 fragmentType
        ↓
六种片段类型是否都有至少一套关系
        ↓
所有 REQUIRED 事实是否至少进入一套兼容关系
```

下面是一套会被丢弃的模型输出：

```json
{
  "bundleId": "invalid-pain-selling-point",
  "fragmentType": "PAIN",
  "factIds": ["F02", "F07"]
}
```

F02“备餐空间拥挤”允许进入痛点，但 F07“三七肥瘦比例”不允许进入痛点。这套关系不会通过验证，也不会被送到后续蓝图。

如果模型遗漏了片尾品牌关系，或者没有覆盖某个必须利用的事实，Worker 会使用确定性规则补充安全关系。最终关系池可能是：

```text
模型输出：15 套
校验淘汰：2 套
模型有效：13 套
Worker 为缺失类型和必用事实补齐：3 套
最终关系池：16 套
```

因此，最终保存的关系不保证全部由模型直接选择；它由“模型提出 + Worker 校验 + Worker 必要补齐”共同形成。

#### 5.1.7 这个节点明确不做什么

营销关系规划节点不负责：

- 把六种片段组合成一条成片；
- 为 50 条 Prompt 分别写 50 套关系；
- 生成六维组合；
- 选择一条素材最终使用的 1～3 个事实；
- 设计可见动作和镜头；
- 编写最终视频 Prompt。

它的准确职责可以概括为：

> 在每一种片段类型内部，从确定性白名单中挑选逻辑相关的事实，形成少量可复用关系套餐；Worker 对套餐进行校验和补齐，再交给片段蓝图编排使用。

> 这一节点只让模型生成精简关系骨架。页面最近更新时间仍在变化时，表示任务仍在工作，不代表模型正在逐条生成 50 个 Prompt。

### 5.2 历史 V9：片段蓝图编排

**通俗理解：** 营销关系规划决定“讲哪件事”，片段蓝图编排进一步决定“这一条具体怎么拍”。

**输入：**

- 营销关系束；
- 六类数量缺口；
- 每类片段时长；
- 已有 Prompt 和待补的事实。

**处理：** 为每个待生成位置分配：

- 片段类型；
- 主要事实和辅助事实；
- 场景与单一人物；
- 开始画面；
- 一个主要可见动作；
- 一种主要镜头行为；
- 光线和情绪；
- 结束画面；
- 对应片段时长。

**输出：** 一批可以直接交给六类生成分支的“片段蓝图”。

**广式腊肠例子：** 某条卖点讲解蓝图可能是：“年节厨房；筷子夹起一片腊肠切面并缓慢转向镜头；桌面低机位近景；暖色侧光；结束时切面清楚并在右侧留出空间；绑定‘三七肥瘦比例’事实。”

### 5.3 片段类型条件路由

**通俗理解：** 像快递分拣中心，把不同类别的蓝图送到对应生产线。

**输入：** 已编排好的片段蓝图。

**处理：**

- 钩子蓝图送到钩子生成分支；
- 痛点蓝图送到痛点生成分支；
- 其余四类按同样方式分发；
- 某一轮没有缺口的类型不再重复生成。

**输出：** 六类生成任务分片。

**广式腊肠例子：** 如果去重后只缺 2 条痛点片段和 1 条片尾品牌片段，补齐时只会启动这两个分支，不会把六类全部重做一遍。

## 6. 第三阶段：六类 Prompt 分别生成什么

六类生成分支可以并行执行，但每一类都有固定职责。它们的共同输入是该类型的片段蓝图、已确认的产品信息和批次共用提示词；共同输出是候选 Prompt。

### 6.1 钩子 Prompt 生成

**作用：** 在最短时间内制造“接下来会发生什么”的兴趣。

**主要使用：** 目标受众、核心痛点、购买动机和场景。

**必须做到：** 只把动作推进到答案揭晓之前，结尾仍保留悬念。

**不能越界：** 不讲完整解决方案，不解释卖点，不出现购买引导。

**广式腊肠例子：** “蒸汽刚散开，筷子夹住一片食物并在切面转向镜头前停住；桌面低机位近景迅速靠近后停止，暖色侧光只露出局部纹理，主体仍被手部遮住。”

### 6.2 痛点 Prompt 生成

**作用：** 让观众看见一个真实存在的不便或问题。

**主要使用：** 核心痛点、目标受众、使用场景或购买场景。

**必须做到：** 人物只尝试解决一次，遇到阻碍后停下，问题仍然存在。

**不能越界：** 不得在同一条中拿出产品完成解决，不做满意结果和前后对比。

**广式腊肠例子：** “年夜饭厨房案板被多种食材和器皿占满，成年人端着餐盘寻找一次落点后停住；俯拍近景保持固定，结束时备餐空间仍然拥挤。”

### 6.3 产品展示 Prompt 生成

**作用：** 让观众快速、清楚地看见产品是什么、外观如何。

**主要使用：** 产品名称、品类、规格、视觉特征和使用场景。

**必须做到：** 首帧产品清楚完整，只做一次扶正、取出、摆放、打开或缓慢转动，最后形成稳定的产品主视觉。

**不能越界：** 不同时演示效果、讲解卖点、展示满意反应或引导购买。

**广式腊肠例子：** “广式腊肠完整放在木质案板中央，一只手将略微倾斜的产品扶正后退出；正面近景轻微横移，暖色窗光表现真实色泽，结束停在清楚的三分之二角度。”

### 6.4 卖点讲解 Prompt 生成

**作用：** 用真实可见的细节或安全动作，为一个卖点提供画面依据。

**主要使用：** 核心或次要卖点、决策动机，以及已经确认的背书。

**必须做到：** 一条只服务一个主要卖点；只展示来源允许、镜头能够观察到的证据。

**不能越界：** 不能为了证明工艺或品质，凭空生成工厂、实验室、检测设备、专家或消费者证明；抽象口感和香味也不能伪装成确定的视觉结果。

**广式腊肠例子：** 对“三七肥瘦比例”，可以表现“筷子夹起一片真实切面并转向镜头”；对“广府糖酒腌制工艺”，如果上游没有生产过程素材，只能拍真实产品细节，不能虚构腌制车间来证明。

### 6.5 结尾转化 Prompt 生成

**作用：** 为后续添加购买文案或行动提示准备一个清楚、自然的收束画面。

**主要使用：** 营销目标、购买场景、决策动机和可确认价格。

**必须做到：** 产品稳定可辨，一侧或下方有自然、无遮挡的安全留白。

**不能越界：** Prompt 中不直接生成价格贴纸、折扣、库存、销量、二维码、购买按钮或促销文案。

**广式腊肠例子：** “人物把广式腊肠包装平稳放到年节餐桌中央后手部退出；正面中近景缓慢靠近后停止，暖色轮廓光稳定，右侧墙面形成自然留白。”

### 6.6 片尾品牌 Prompt 生成

**作用：** 生成可以稳定停留的结束画面，方便后续叠加品牌信息。

**主要使用：** 产品身份、视觉特征、视觉基线和情绪场景。

**必须做到：** 从安静的产品静物开始，只做一次很小的动作或收焦，最后稳定定格。

**不能越界：** 不重新演示使用，不讲新卖点，不引导购买，不开启新剧情。

**广式腊肠例子：** “广式腊肠置于简洁餐桌中央，一只手轻微扶正后离开；固定近景缓慢收焦，暖色背景光恢复稳定，结束画面保持清楚静止。”

### 6.7 六类片段的区别速查

| 类型     | 它要回答的问题                 | 结束时应是什么状态           |
| -------- | ------------------------------ | ---------------------------- |
| 钩子     | “接下来会发生什么？”           | 答案尚未揭晓                 |
| 痛点     | “用户遇到了什么麻烦？”         | 问题仍未解决                 |
| 产品展示 | “这是什么产品？”               | 产品完整、清楚、好识别       |
| 卖点讲解 | “这个卖点有什么真实画面依据？” | 允许的证据清楚可见           |
| 结尾转化 | “后续行动提示放在哪里？”       | 产品稳定，并有自然留白       |
| 片尾品牌 | “视频如何安静结束？”           | 产品身份稳定、画面可持续停留 |

## 7. 第四阶段：整理、查重和检查

### 7.1 结构标准化

**通俗理解：** 六条生产线交来的内容格式可能有细微差异，这一步把它们整理成统一规格。

**输入：** 六类候选 Prompt。

**处理：**

- 过滤缺少必要结构或违反执行规则的候选；
- 统一稳定 ID、编号、片段类型、时长、素材标签、六维信息和事实绑定；
- 确保正文描述的是一个场景、一个主要动作和一种主要镜头行为。

**输出：** 格式一致、可以参与后续检查的 Prompt 列表。

**广式腊肠例子：** 把一条候选整理成“片段类型=卖点讲解、时长=5 秒、来源=核心卖点、正文=干净画面描述”等结构。时长作为独立字段保存，不需要在正文里写“5 秒视频”。

### 7.2 语义去重

**通俗理解：** 检查多条 Prompt 是否只是在换词，其实讲的是同一件事。

**输入：** 标准化后的全部 Prompt。

**处理：** 两两比较内容含义，找出语义过于接近的候选。

**输出：** 语义重复清单和重复率。

**广式腊肠例子：**

- A：“筷子夹起腊肠切面转向镜头”；
- B：“用筷子夹住一片腊肠并把切面朝向镜头”。

虽然用词不同，但核心画面几乎一样，可能被判为语义重复。

### 7.3 视觉重合校验

**通俗理解：** 有些 Prompt 文字讲的不是同一件事，但拍出来可能仍然长得几乎一样，这一步专门检查这种情况。

**输入：** 标准化后的全部 Prompt。

**处理：** 比较场景、人物、景别、机位、动作、光线和结束构图的组合是否过度重合。

**输出：** 视觉结构重合清单和重合率。

**广式腊肠例子：** 一条讲“切面油润”，另一条讲“三七肥瘦比例”，文字含义不同；但如果两条都是“木案板、筷子夹切片、低机位近景、暖侧光、右侧留白”，最终视频会非常相似，因此仍可能被判为视觉重合。

### 7.4 提炼信息覆盖校验

**通俗理解：** 回头核对上游辛苦提炼出的重要信息，是不是真的被合适的 Prompt 使用了。

**输入：**

- 去重后实际准备保留的 Prompt；
- 提炼事实应用表；
- 六类目标数量。

**处理：**

- 统计必须利用、已经利用、仍然缺失和暂未编排的事实；
- 检查事实是否放在职责正确的片段中；
- 检查每个场景组是否至少有代表场景被使用；
- 检查共用约束是否已经应用；
- 确认不确定价格、背书和功效没有被当成真实事实使用。

**输出：** 提炼信息覆盖报告，以及需要优先补齐的事实编号。

**广式腊肠例子：** 50 条中如果“切面油润”和“广府糖酒腌制工艺”都被合理使用，但“三七肥瘦比例”一条也没有，这一步会明确指出缺少该核心卖点，而不是只给一个模糊的“不合格”。

### 7.5 质量门禁

**通俗理解：** 这是整批 Prompt 的总验收员，决定能否保存，还是要回去补货。

**输入：**

- 去重结果；
- 提炼信息覆盖报告；
- 用户设置的总数和六类配额；
- 每条 Prompt 的职责与执行检查结果。

**处理：** 综合检查：

- 总数量是否准确；
- 每一类数量是否准确；
- 重要提炼事实是否正确覆盖；
- 片段是否越过自己的职责；
- 动作和镜头是否能够实际执行；
- 重复和重合是否在允许范围内。

**输出：** “通过”或“需要补齐/人工复核”的判断，以及具体原因。

**广式腊肠例子：** 即使总数已经有 50 条，但实际为“钩子 11 条、痛点 7 条”，仍不能通过，因为用户设置的是“钩子 10 条、痛点 8 条”。

## 8. 第五阶段：缺什么补什么，再保存结果

### 8.1 定向补齐

**通俗理解：** 不是整批推倒重来，而是拿着缺货清单，只补缺少的类型和事实。

**输入：**

- 各片段类型缺少的数量；
- 尚未覆盖的核心事实；
- 这些事实允许出现的片段类型；
- 已有 Prompt 的语义和视觉特征。

**处理：**

- 重新编排缺少部分的蓝图；
- 只路由到有缺口的生成分支；
- 优先使用尚未覆盖的核心事实；
- 避开已有内容的表达、动作和构图；
- 模型定向补齐最多进行三轮；
- 三轮后仍有数量缺口时，使用已经校验过的关系束和蓝图生成安全兜底变体；兜底内容仍要经过同样的检查，不能绕过质量门禁。

**输出：** 新一轮候选 Prompt，随后重新进入标准化、去重、覆盖校验和质量门禁。

**广式腊肠例子：** 当前只有 7 条痛点片段，并且“三七肥瘦比例”尚未使用。系统会根据职责分别补 1 条痛点片段，并在适合的产品展示或卖点讲解片段缺口中优先安排“三七肥瘦比例”，不会把这个卖点硬塞进痛点片段。

如果安全补齐后仍不能满足数量和六类配额，任务会明确失败，并保留上一份有效结果；系统不会保存一份短缺批次去覆盖原结果。

### 8.2 结果保存

**通俗理解：** 把通过检查的整批 Prompt 保存为当前节点的最新生成结果。

**输入：** 通过精确数量检查和质量门禁的 Prompt、共用提示词、渲染参数和质量指标。

**处理：**

- 按稳定顺序重新编号；
- 保存每条干净正文、片段类型、结构化时长、素材标签、六维信息和提炼事实绑定；
- 保存批次级共用提示词、画幅和分辨率等独立配置；
- 记录模型生成数量和安全兜底数量。

**输出：** Prompt 节点中的最新批次结果。

**广式腊肠例子：** 保存正好 50 条广式腊肠素材 Prompt。每条正文只描述画面、动作、镜头、光线和结束状态；时长、画幅、分辨率作为独立字段保存，共用提示词只在批次层保存一次。

需要特别区分两个动作：

1. **生成成功：** 结果已经保存在 Prompt 节点中，可以查看和编辑；
2. **用户点击“完成校验”：** 当前结果才正式提交为可供“视频渲染”节点读取的 Prompt 工作副本。

因此，刚生成完成但还没有点击“完成校验”时，下游资产不会提前使用这份新结果。这是为了防止未检查的 Prompt 污染后续渲染。

## 9. 正文、独立参数和共用提示词如何分工

| 内容                                         | 保存位置                 | 每条卡片是否重复展示 | 什么时候使用                                       |
| -------------------------------------------- | ------------------------ | -------------------- | -------------------------------------------------- |
| 场景、主体、动作、镜头、光线、情绪、结束状态 | 每条 Prompt 正文         | 是                   | 生成素材片段画面                                   |
| 片段时长                                     | 每条 Prompt 的结构化字段 | 只显示时长标签       | 创建视频任务时作为独立参数传递                     |
| 画幅、分辨率                                 | 批次渲染配置             | 不在每条正文重复     | 创建视频任务时作为独立参数传递                     |
| 禁用元素和其他共同要求                       | 批次共用提示词           | 全批只维护一份       | 生成 Prompt 时作为约束；创建视频任务时统一追加一次 |
| 提炼来源                                     | 每条 Prompt 的事实绑定   | 显示精简来源标签     | 覆盖检查、编辑校验和后续追溯                       |

这样设计的目的，是让用户看到的 Prompt 正文保持干净，同时确保真正生成视频时不会漏掉时长、画幅、分辨率和共同要求。

## 10. 用户常见操作会怎样影响流程

### 单条重新生成

- 尽量保留原条目的片段类型、营销关系和事实绑定；
- 只改写表达、动作、镜头或构图；
- 不会把整批 50 条全部重新生成。

### 人工修改正文

- 保留原有事实绑定并标记为人工编辑；
- 修改后重新计算质量和覆盖情况；
- 不会因为编辑正文而把批次级时长或画幅写入正文。

### 修改片段类型或六维信息

- 重新检查原事实是否还适合新的片段类型；
- 不兼容的事实绑定会被移除；
- 覆盖统计随之重新计算。

### 人工新增

- 系统会尝试把正文和上游事实做确定性匹配；
- 匹配不到时仍可作为人工 Prompt 保存，但不会假装它已经覆盖某个核心事实。

### 删除

- 总数和六类配额会立即变化；
- 如果删掉的是某个核心事实唯一的承载条目，该事实会重新变成“待补”；
- 在数量和覆盖恢复之前，完成校验会被阻止。

## 11. 如何看懂运行状态

| 状态            | 通俗解释                                                     | 用户是否需要处理                   |
| --------------- | ------------------------------------------------------------ | ---------------------------------- |
| 等待中          | 任务已创建，正在等 Worker 接单                               | 通常不需要                         |
| 执行中          | 当前节点正在计算或调用生成服务                               | 最近更新时间持续变化时不需要       |
| 已完成          | 当前内部节点已经产出结果                                     | 不需要                             |
| 部分完成/需关注 | 当前轮发现数量、覆盖或质量缺口                               | 系统通常会自动进入定向补齐         |
| 自动重新排队    | 上一次请求超时或 Worker 租约过期，系统正在进行下一次业务尝试 | 等待下一次尝试即可                 |
| 失败            | 达到尝试上限，或输入和质量条件始终无法满足                   | 根据页面原因修改设置后重新批量生成 |

页面显示“第 1/3 次尝试”表示整个任务的业务尝试次数，不是已经生成了三批结果。V10 的六类营销组合、六类坐标计划、蓝图分片和 Prompt 分片均可并行执行；营销组合与坐标保存阶段检查点，蓝图和 Prompt 分别保存自己的分片。后续任务级重试只重做缺失层级或失败分支。判断是否仍在工作，应优先看“最近更新时间”是否继续刷新。若 Ark 明确返回输出截断，任务会直接停止，不再重复同一个超长请求。

## 12. 最容易混淆的几个问题

### 为什么不能直接拿提炼结果随机组合？

因为“受众、痛点、场景、卖点”之间原本有业务关系。随机组合虽然看起来变化很多，却容易出现“场景和痛点无关、卖点不能解决当前问题”的内容。营销关系规划先把关系连通，再在关系内部变化动作和镜头，质量会更稳定。

### 为什么已经生成很多条，还要做覆盖校验？

数量多不代表上游信息被充分利用。50 条 Prompt 可能反复讲同一个卖点，却漏掉另一个核心卖点。覆盖校验检查的是“重要信息有没有被正确使用”，质量门禁再检查“整批是否可以交付”。

### 为什么语义去重和视觉重合校验要分开？

两条文字可以表达不同卖点，但最终拍出来仍可能是同一个构图；也可能构图不同，却用不同说法重复同一个意思。因此必须分别检查“说得像不像”和“拍出来像不像”。

### 为什么设置 50 条就必须正好得到 50 条？

六类片段将被后续模板混剪按槽位使用。少一类或少几条，会直接减少后续可组合素材；多出的类型也不能代替缺少的类型。因此成功批次必须同时满足总数和每类配额。

### 为什么正文没有写“5 秒、9:16、1080p”和禁用元素？

这些不是画面内容，而是生成视频时使用的结构化参数或批次共同约束。把它们反复写进每条正文会让 Prompt 冗长、干扰阅读。系统会在创建视频任务时分别传递参数，并把共用提示词统一追加一次。

### 为什么 Prompt 生成成功后，下游资产还没有马上更新？

生成成功只是得到可编辑结果。用户还可能修改、删除或单条重生成。只有点击“完成校验”后，这一批结果才成为下游可以稳定读取的工作副本。

## 13. 一句话总结每个节点

| 节点                 | 一句话说明                                     |
| -------------------- | ---------------------------------------------- |
| 输入快照             | 锁定这次任务究竟使用哪份资料和设置             |
| 提炼信息应用映射     | 给每条上游信息标明是否可用、必须用和适合放哪里 |
| 共用提示词编译       | 把全批共同要求整理成一段统一提示词             |
| 全局事实分配         | 决定每条核心事实主要由哪类片段负责             |
| 营销组合条件路由     | 同时启动六类事实关系规划                       |
| 六类营销组合         | 每类只组合主要事实、辅助事实和创意意图         |
| 营销组合合并校验     | 检查六类组合数量、事实兼容性和必须事实覆盖     |
| 六维坐标条件路由     | 同时为六类生成产品专属坐标计划                 |
| 六类坐标规划         | 为本类准备六轴候选及其适用营销组合             |
| 坐标计划合并校验     | 检查六份计划是否覆盖六维和全部所属组合         |
| 蓝图配额分配         | 把每类目标数准确分配到本类营销组合             |
| 蓝图类型条件路由     | 把同类型蓝图任务分成每片最多 8 张并行生成      |
| 六类蓝图生成         | 为每个素材位置选择完整六维并生成首帧、动作和结尾 |
| 全批次蓝图正交校验   | 对全部蓝图做类型内、组合间和跨类型六维比较     |
| Prompt 条件路由      | 把合格蓝图送到对应的六类 Prompt 生产线         |
| 钩子 Prompt 生成     | 制造悬念，但不揭晓答案                         |
| 痛点 Prompt 生成     | 展示问题，但不在同条中解决                     |
| 产品展示 Prompt 生成 | 清楚展示产品身份和外观                         |
| 卖点讲解 Prompt 生成 | 用真实可见证据承载一个卖点                     |
| 结尾转化 Prompt 生成 | 为后续行动提示准备产品与自然留白               |
| 片尾品牌 Prompt 生成 | 形成稳定、安静的产品结束画面                   |
| 结构标准化           | 把所有候选整理为同一套可检查格式               |
| 语义去重             | 找出换了说法但意思重复的内容                   |
| 视觉重合校验         | 找出文字不同但拍出来太像的内容                 |
| 提炼信息覆盖校验     | 检查上游重要信息是否真的被正确使用             |
| 质量门禁             | 综合决定整批是通过还是需要补齐                 |
| 定向补齐             | 只补缺少的类型、数量和事实                     |
| 结果保存             | 保存数量准确、质量达标的最新 Prompt 批次       |
