# 正式前端与冻结原型映射

## 使用原则

- `references/prototypes` 是视觉、布局和交互基线，不是生产运行时依赖。
- 开发正式页面前必须先找到对应原型、检查目标状态和关键交互，再检查正式工程已有组件。
- 要求“与原型一致”时，优先保持信息架构、间距、尺寸、颜色、控件位置、文案层级和交互顺序。
- 只有在明确需求、可访问性、响应式或真实接口状态需要时才偏离；偏离必须说明原因。
- 不复制原型的内联脚本、全局 Mock 状态、Data URL 大资源或真实网络请求。

## 原型对应关系

| 正式区域                         | 参考原型                                               |
| -------------------------------- | ------------------------------------------------------ |
| 效果类工作流                     | `references/prototypes/effect/` 下的效果类冻结原型     |
| 定制类工作流                     | `references/prototypes/customized/` 下的定制类冻结原型 |
| 裂变类·爆款复刻                  | `references/prototypes/fission/` 下爆款复刻对应页面    |
| 裂变类·数字人口播                | `references/prototypes/fission/` 下数字人口播对应页面  |
| 裂变类·局部元素替换              | `references/prototypes/fission/` 下局部替换对应页面    |
| 项目与资产、流程与版本、批量导出 | 整合原型中的全局公共组件                               |

若目录实际文件名与表格不同，以 `references/prototypes` 中最新冻结清单为准；无法判断时先报告候选文件，不凭名称猜测。

## 验收清单

1. 对比默认、空、加载、错误、完成和弹窗状态。
2. 对比页面宽度、主卡边界、左右栏比例、固定/滚动区域和按钮位置。
3. 验证路由或节点切换不会残留上一模块组件。
4. 验证真实 API 字段不会迫使 UI 退化为与原型无关的通用表单。
5. 用浏览器截图记录明显偏差，并在交付说明中列出有意偏离项。
