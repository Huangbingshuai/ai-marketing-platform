# 火山服务器运营测试部署

## 检查结果与范围

目标服务器 101.96.224.33：CentOS Stream 9，4 核，约 16GB 内存；检查时可用约 8.5GB，根盘剩余约 40GB。已有 Docker 29.5.2、Compose 5.1.4 和多个生产/预览应用，80、443 已占用。适合受限并发的运营测试，不据此宣称百条级生产容量。

部署完整 Web/API、独立 PostgreSQL/Redis/RabbitMQ 和现有已实现的 Worker。使用独立 Compose 项目与 `/opt/ai-marketing-platform`，外部测试端口 18080；数据库、消息队列、API 不发布宿主机端口。保持既有容器、数据和入口不变。创建空白测试数据库，不搬运本机历史项目和待执行任务。

## 配置和发布

- 包含本机已验证但未提交的登录变更，打包 Git 跟踪源文件与本次新增文件；不包含开发缓存、历史截图、node_modules、明文凭据。
- 当前供应商配置经 SFTP 写入服务器专用权限为 0600 的环境文件；数据库密码、消息队列密码、Worker Token 为部署独立随机值。密码哈希保留单账号登录；不在日志或仓库记录密钥。
- 使用当前私有 TOS 桶；新的空数据库生成独立 UUID，不导入旧对象引用。付费任务只由运营登录后主动发起，部署验收不发起模型生成。
- API 生产构建，Nginx 同源代理。IP 临时测试使用 HTTP，Cookie 明确关闭 Secure；获得域名与证书后切换 HTTPS 并启用 Secure。
- Worker 并发降低为 1，最终合成并发为 1，图像/文档解析线程受限；容器设置内存/CPU 限额与日志轮转。模型下载和镜像构建顺序执行，保留磁盘余量。
- 迁移在新数据库执行。启动后验证匿名业务拒绝、正确/错误登录、会话刷新、退出撤销、项目读写、文件上传读取、Worker Token、队列消费者和外部存储读取连接。

## 回滚与验证边界

新部署失败只停止本 Compose 项目；保留其数据卷与环境文件以便修复，不清理其他项目。后续发布在迁移前备份本项目数据库，保留旧镜像与静态资源。云安全组不属于 SSH 防火墙，须从外部实际访问测试端口确认。

当前无法使用 Context7 工具，部署语法核对 [Docker Compose 官方文档](https://docs.docker.com/compose/) 和 [Nginx 反向代理文档](https://docs.nginx.com/nginx/admin-guide/web-server/reverse-proxy)。具体运行结果另行记录，不把构建或启动等同于付费任务通过。
