# 各工作流当前项目独立绑定

用户确认效果类与定制类需要同时各自运行一个项目。统一 Project Context 保存按工作流分组的绑定，不为页面建立第二套项目、资产或任务状态。

- 修复切换时将原项目写入目标工作流的问题。先保存当前草稿，成功后展示目标绑定；目标为空则展示未绑定状态。切换不调用暂停接口，不创建任务。
- 从资产库进入及新建项目先切换至目标工作流，仅替换该工作流的绑定；明确退出仅清除当前工作流。
- 刷新分别校验各类绑定，清除已删除或失效的项目。旧全局存储只在没有任何分组绑定时迁移到最初可见的工作流，成功读取列表后移除旧键。
- 资产库按所浏览工作流展示当前项目和进行中状态，所有工作流已绑定项目均不可删除。
- 不改变 API、Worker、WorkingArtifact、业务 revision 或数据库结构，不改变既有项目的资料归属。

验证：反复切换两个不同项目、未绑定目标、刷新、单侧退出、失效绑定、保存失败和保存期间状态变化，以及资产库进入/新建接线；运行相关单测、Web 类型检查、构建与浏览器验证。无需付费生成。

## 实施验证（2026-10-10）

- 项目及资产筛选相关 9 个测试文件、62 项测试通过；Web 类型检查、生产构建及 `git diff --check` 通过。
- 浏览器实测效果类绑定“广式腊肠”、定制类绑定“语义精炼过程验收-拾温咖啡杯-20261010”。反复切换、刷新、跨类资产库进入及定制类退出后，效果类绑定始终保持；未绑定的裂变类显示空项目。
- 资产库两类列表分别显示各自项目为“进行中”，均不显示删除按钮。1920、1440 和 390 宽度均可切换，未出现页面横向溢出。
- 未新建付费任务，未重启 API 或 Worker。上述验证证明导航与绑定隔离，不作为双流程付费任务同时执行的性能结论。
