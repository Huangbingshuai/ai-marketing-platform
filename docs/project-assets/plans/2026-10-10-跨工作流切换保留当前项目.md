# 跨工作流切换保留当前项目

## 范围

同一个 Project 可同时拥有效果类和定制类 Run。导航切换不是退出项目，不暂停或取消另一类任务。复用统一 ProjectContext 和现有按项目、workflow、space 隔离的 Run、草稿、工作副本；不复制资料、不生成付费任务、不改业务 revision。

## 实施

- 切换前按原规则保存当前节点草稿，失败留在原工作流。
- 不以 workflowSpaces（已有内容索引）作为项目绑定资格；切换、项目列表重读及刷新均保留合法当前项目。
- 全局当前项目优先于旧的分工作流记忆，防止刷新跳到其他项目。旧记忆仅在没有全局绑定时兼容恢复。
- 从资产库进入同一项目的另一工作流只保存、不退出；进入不同项目仍走明确退出边界。
- 后端现有 active Run 按 projectId + workflow + workflowSpace 唯一；不增加项目归属或额外 Run 状态。

## 验证

覆盖首次进入另一流程、往返切换、保存失败、列表重读、刷新、旧工作流记忆、同项目资产库进入及不同项目退出。检查两类独立 Run 恢复，不触发 pause/cancel 或付费生成。执行相关 Web 单测、类型检查、构建及 diff 检查；浏览器检查宽屏与窄屏。

## 实施与验证结果（2026-10-10）

- 工作流导航复用保存边界，保留统一项目绑定；同项目资产库跨流程进入不再调用退出逻辑。刷新与项目列表重读不再按已有工作流内容过滤项目，统一绑定优先于旧流程记忆。
- `pnpm --filter @ai-marketing/web exec vitest run src/platform/project --maxWorkers=1`：7 个文件、42 项通过，包含往返切换、保存失败、异步保存、无项目、删除状态恢复及资产库入口。
- `pnpm --filter @ai-marketing/web typecheck`、`pnpm --filter @ai-marketing/web build`、`git -c core.safecrlf=false diff --check`：通过；构建保留大 chunk 提醒。
- 浏览器使用“广式腊肠”验证效果类 → 定制类 → 刷新 → 效果类，项目不退出，效果类原混剪节点及两个模板恢复；1920、1440、390 宽度切换正常。定制类未填资料仍可保持项目绑定。[刷新后的定制类项目截图](../evidence/browser/2026-10-10-same-project-customized-1440.png)。
- 未启动模型或付费生成，未修改后端隔离契约；两类真实长任务同时执行未做付费端到端验证。导航路径不调用暂停/取消，后台任务继续由各自 Run 管理。
