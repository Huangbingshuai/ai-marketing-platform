# 项目异步删除

用户调整要求：删除可能耗时，改为后台异步执行；当前项目禁止删除。前一版数据库删除和第一批文件删除发生在请求内，本次将其移到持久化后台队列。

- `DELETE` 只做作用域/当前上下文校验、活动任务检查、项目冻结和持久化排队，返回 202，明确 `deleted: false`，不等待数据库批量删除或对象存储。重复提交返回同一项目任务状态。
- 复用独立 `ProjectDeletionCleanup` 队列，增加数据库/文件阶段、状态、错误及最小列表快照；项目增加删除标记。后台通过租约执行，进程重启恢复，数据库阶段有限自动重试，失败可人工重试；文件阶段保留原有持久化重试。完成删除队列及列表快照。
- 列表展示服务端删除状态，包括项目行已经删除而文件尚未清理的阶段；刷新可恢复。当前项目的按钮禁用并说明先退出；统一项目页在确认前后校验，服务端校验请求携带的当前项目上下文。当前上下文是浏览器会话信息，不冒充服务端权限模型。
- 删除中项目不能进入、浏览或修改。复用项目服务、上下文恢复及公共项目路由保护；内部 Worker 接口保留既有租约防护。活动生成/上传任务仍拒绝，后台删除前再次校验活动状态，防止迟到的新任务与删除并发。
- 增量迁移只新增列，兼容已有文件清理队列。保留已有共享文件隔离逻辑、全关联删除事务及旧 token 防回写。不改变业务流程或执行付费任务。
- 验收：请求在后台任务未完成时立即返回、当前项目拦截、重复提交、刷新恢复、两阶段状态、失败重试、进程恢复/租约互斥、跨项目隔离、完整数据/本地文件删除、列表轮询与卸载清理、1920/1440/390 布局。执行相关测试、类型/构建、真实隔离事务与 HTTP 验证、格式/diff 检查。
