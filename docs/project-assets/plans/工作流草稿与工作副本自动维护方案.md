# 工作流草稿与工作副本自动维护方案

## 1. 结论与范围

本方案以 `WorkflowRun`、`WorkflowNodeState` 和 `WorkingArtifact` 分离工作流编辑状态、最新工作产物与正式项目资产。节点不再提供“保存到项目资产库”或“保存草稿”按钮；普通退出、刷新和切换项目只保存草稿，后台任务继续运行，不创建 `ProjectAsset`。

本次接通效果类资料包导入和 AI 信息提炼节点。未来“完成工作流并归档”才可以把有效工作副本物化为正式项目资产，该能力不在本次范围。Prompt、渲染、混剪、最终归档、跨项目发布以及定制类和裂变类节点均未新增实现。

前端业务结构与视觉继续参考冻结原型 `D:\1Code\ai-marketing-platform\references\prototypes\effect\effect-workflow.html` 的资料包导入、AI 信息提炼、节点导航和轻量状态反馈区域。本次按最新业务规则移除原型中的节点级手动入库条，不改动蓝白页面结构和后续步骤布局。

## 2. 数据职责

- `WorkflowRun`：一次项目内的工作流执行，当前按 `projectId + workflow + workflowSpace + ACTIVE` 维护一个活动运行。
- `WorkflowNodeState`：保存节点表单和人工编辑，按 `projectId + workflowRunId + nodeId` 唯一；包含规范化内容哈希、revision 和保存时间。
- `WorkingArtifact`：保存节点最新文件或结构化结果，按 `projectId + workflowRunId + nodeId + artifactKey` 唯一；覆盖更新时保留原 ID，不关联 `AssetVersion`。
- `ProjectAsset`：仅代表已经正式归档的项目资产。本次所有草稿、上传和生成请求均不会创建或修改它。

资料导入节点使用 `SOURCE_IMPORT`；AI 信息提炼节点使用 `INFORMATION_EXTRACTION`。素材 artifactKey 为 `material:{materialId}`，提炼结果为 `product:{productId}:result`。

## 3. 自动保存与并发规则

- 文本和配置停止输入 1 秒后防抖保存。
- 输入框失焦、切换产品、切换节点、退出项目和切换项目前立即 flush。
- flush 失败时阻止对应的显式导航并保留待重试内容。
- 前端保存已确认的规范化 JSON 快照，相同内容不发请求。
- 后端对递归键排序后的 JSON 计算 SHA-256；相同内容返回 `unchanged=true`，不更新 revision。
- 后端同时对迁移前的旧哈希重新计算当前 state，确保迁移数据第一次原样保存也不会误增 revision。
- 内容变化但 `expectedRevision` 过期时返回 `409 CONFLICT`。
- 页面存在未保存内容时注册离开提醒，并使用 keepalive 做 best-effort 保存；首次持久化不依赖浏览器退出事件。

信息提炼任务开始前先 flush 编辑。生成或重新生成成功后只覆盖对应 `WorkingArtifact`，并把新生成结果设为节点编辑基线；生成失败保留旧工作副本和旧草稿。退出项目不取消任务，迟到的成功结果仍可更新其原 workflowRun。

## 4. 文件与 MinIO

工作文件写入可读目录：

`projects/{项目名__短ID}/{workflow}/01-working/{产品名__短ID}/{资料分类}/{原文件名__对象ID}.{ext}`

正式资产仍使用 `02-assets`，清单临时对象使用 `03-manifest`。本次不会把 `01-working` 自动复制到 `02-assets`。

上传与重传采用两阶段交换：

1. 将新对象流式写入 MinIO 并校验大小、签名和可读性。
2. READY 资料记录与对应 `WorkingArtifact` 在同一数据库事务提交。
3. 提交成功后删除被替换的旧对象；删除失败进入持久清理任务。
4. 新对象写入、可读性校验、revision 或事务失败时只删除新对象，旧资料记录和旧工作副本保持可读。

历史 multipart 文件名在公共文件层恢复 UTF-8，并用于工作副本列表、缩略图替代文本和 Content-Disposition。Word 继续以原始二进制流返回，下载响应包含正确 MIME 与 RFC 5987 UTF-8 文件名，不进行文本转码。

## 5. HTTP 接口

- `GET/PUT /projects/:projectId/workflow-runs/:workflowRunId/nodes/:nodeId/state`
- `GET /projects/:projectId/working-artifacts`
- `GET /projects/:projectId/working-artifacts/:artifactId/content`
- `GET /projects/:projectId/workflow-runs/active/overview?workflow=...&space=...`

效果类工作区响应提供稳定 `workflowRunId`。现有上传、生成和重新生成 HTTP 契约保持不变，但内部只维护工作态。旧效果类 publish 路由、DTO、前端客户端、发布状态、文件 hold 和 `lastPublish` 已删除。

所有读取和写入均同时校验 `projectId` 与 workflowRun/实体归属。工作副本列表只返回活动运行的数据，内容接口对其他项目返回 404。

## 6. 前端展示

- 资料导入节点删除手动入库区域、弹窗和发布状态，只保留“正在保存 / 已自动保存”。
- 信息提炼节点删除“保存草稿”，保留“正在保存 / 已自动保存 / 工作副本已更新 / 尚未归档”。
- “当前项目资产”只读请求 `WorkingArtifact`，显示真实图片缩略图、文档封面或结构化摘要，并统一标记“工作中 / 尚未归档”。
- 当前项目视图不提供手工上传、删除、版本时间线、归档或跨项目引用操作。
- “项目资产库”和跨项目选择器继续只请求正式 `ProjectAsset`，工作副本 ID 与正式资产 ID 不重合。
- 普通“退出项目”只 flush 草稿并解除本地当前项目绑定，不调用任何同步或归档接口。

## 7. 迁移与回滚

迁移 `20260822140000_create_workflow_working_state`：

- 为每个现有效果类工作区创建活动 WorkflowRun，并关联稳定 `workflowRunId`。

- 将 READY 素材映射为文件 WorkingArtifact，沿用仍有效的 MinIO 工作对象。
- 将已完成提炼结果映射为结构化 WorkingArtifact。
- 删除已应用的旧 publish 表和 `lastPublish` 字段；不修改历史迁移文件。
- 保留所有既有 ProjectAsset、AssetVersion 和 MinIO 正式对象。

回滚应用版本时必须同时回滚数据库迁移；由于旧 publish 数据已删除，回滚前应先备份 PostgreSQL。本迁移不删除素材对象，工作文件和正式对象均可从备份或原 storageKey 恢复。

## 9. 项目与资产聚合视图

“项目与资产”继续复用现有抽屉外壳，不新建第二套页面。当前项目详情按职责分为五块：

- 项目资料与状态：展示真实项目信息、工作流/空间、当前已保存节点、进度和最后保存时间。
- 工作流草稿：读取活动 `WorkflowRun` 下的 `WorkflowNodeState`，显示节点 revision 和保存状态；只有已持久化的节点可返回继续编辑。
- 工作区产物：读取活动运行的 `WorkingArtifact`，显示来源节点、对应节点 revision，以及按节点保存时间与产物更新时间计算出的“最新/待更新”状态。
- 已归档资产：继续读取正式 `ProjectAsset` 和 `AssetVersion`，不将 WorkingArtifact 转换或伪装成正式资产。
- 全局发布资产：当前尚无 `GlobalAsset` 模型和发布接口，固定展示明确的未实现空状态，不使用前端假数据。

聚合读取请求都携带当前 `projectId`、`workflow` 和 `space`。项目切换时终止旧请求并清空展示状态，避免旧项目的异步响应回填到新项目。该视图不新增归档、发布、上传、版本创建或节点级手动入库操作；退出项目仍只刷新草稿并解除绑定。
