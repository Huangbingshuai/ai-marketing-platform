# 项目删除提交不阻塞资产库 · 2026-10-10

## 原因与修复

后端 DELETE 原本已经只持久化排队，数据库、存储文件和缓存清理由后台执行。本次问题发生在前端：统一 deletionBusy 被合并到资产库 entryBusy，提交请求未返回时，切换、关闭、新建和所有项目行一起禁用。

改为按项目 ID 维护提交中状态，仅该项目禁止进入与重复删除，其他项目可以独立提交。资产库关闭后请求继续，重开仍显示本地提交状态；收到成功响应后才转为服务端排队状态。失败只释放该项目并显示带名称的错误，其他请求继续。

删除确认仍使用共用确认弹窗，当前绑定项目仍无删除入口，确认前后及进入项目时仍校验保护。删除响应后的列表刷新不清空列表、不退出其他项目详情、不重开资产库、不移动焦点；后台删除状态触发的项目上下文刷新也不再设置整页加载状态。

## 验证边界

本次仅修改前端交互，不改变数据库删除事务、活动任务保护或文件清理机制，没有重新进行真实 TOS 删除、大型项目吞吐或付费生成测试。隔离资产详情的工作副本接口使用最小夹具，出现过夹具缺少 overview 结构的提示；迟到响应验收检查的是详情选择保持，不以该提示宣称工作副本加载通过。后台服务端删除能力的历史证据见[异步删除记录](2026-10-08-async-project-deletion.md)。
