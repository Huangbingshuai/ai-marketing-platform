# 效果类工作流指南

固定流程：`资料导入 → AI 信息提炼 → Prompt 生成 → 视频渲染 → 模板混剪 → 成片输出`

## 业务目标

面向效果广告批量生产：先形成可复用的产品资料与营销洞察，再批量生成碎片化视频素材，自动搭建多条剪辑工程，最后统一输出成片。

## 节点关系

| 节点        | 作用                                                   | 直接上游               | 主要工作副本             | 直接下游      |
| ----------- | ------------------------------------------------------ | ---------------------- | ------------------------ | ------------- |
| 资料导入    | 按产品导入图片、视频、文档和表单，并确认全局视频配置   | 项目资料               | 产品资料包、全局视频配置 | AI 信息提炼   |
| AI 信息提炼 | 从资料中提炼事实、营销洞察、卖点、受众、禁用项与证据   | 已确认产品资料包       | 营销洞察                 | Prompt 生成   |
| Prompt 生成 | 批量生成差异化的片段级视频 Prompt                      | 营销洞察、全局视频配置 | 素材片段 Prompt 批次     | 视频渲染      |
| 视频渲染    | 固定一条 Prompt 渲染一个素材片段，形成片段池           | Prompt 批次            | 渲染素材片段集合         | 模板混剪      |
| 模板混剪    | 按模板槽位、标签、时长和去重规则生成多条独立时间轴工程 | 素材片段池、混剪模板   | 混剪模板、时间轴工程     | 成片输出      |
| 成片输出    | 对选中的时间轴工程执行最终合成与导出                   | 时间轴工程             | 最终成片、交付清单       | 项目归档/交付 |

## 不可混淆的语义

- Prompt 节点的每条 Prompt 只描述一个可用于混剪的素材片段，不描述一条完整成片。
- Prompt 批量生成先由 AI 规划产品专属创意版图，再按版图为 8～16 个创意方向规划多事实使用方案，并由独立 AI 复核方向实际实现的版图与主动作。富信息商品每个方向使用 2～4 项彼此有关联的业务事实，并说明它们如何共同进入人物、场景、需求、动作或产品表达；整批必须覆盖卖点、痛点、受众、决策动机、营销目标和已确认场景。生成后的事实实现、画面证明、场景、动作和用途语义只由 AI 评估器判断；Worker 只能校验来源、稳定 ID、事实 ID、枚举、数量、结构、revision 与哈希，不得核对证据原文位置，不得用商品关键词、字符包含、字符相似度或自由文本规则再次解释语义，也不能在方向生成后随机补挂遗漏事实。
- 单条生成任务完整继承所属方向的事实组合。产品名称、品类、规格和外观由商品快照提供真实性边界，不能替代业务事实覆盖；事实语义是否真正实现由独立评估模型逐项判断。
- 视频渲染节点产出碎片化素材池，不负责把多个镜头合成成片。
- 模板混剪先生成可人工精修的时间轴数据，不应在“智能填充”时立即渲染视频。
- 成片输出才负责最终视频渲染、选择、分页、批量导出与交付清单。

## 资料导入

- 支持单产品导入和多品类批量导入；文件以稳定 ID 独立维护，界面分组不等于工作副本粒度。
- 上传成功可进入当前节点草稿；格式和完整性校验通过后，用户点击确认才提交产品资料包 revision。
- 删除后又添加完全相同文件，如果最终规范化内容指纹未变，确认时 revision 不增加。
- 全局视频配置是独立工作副本。确认后再次修改并提交，自己的 revision 增加，并使消费该配置的下游待更新。

## AI 信息提炼

- 结果必须区分事实、推断、营销建议、来源证据和警告。
- 文档、表单和电商资料中的非空内容属于用户事实，页面不重复展示“用户事实”标签；图片识别只补充可见信息，并逐项显示轻量的图片识别来源说明，不得覆盖价格或挤掉用户清单项。
- 符合产品信息表格式的资料文档应确定性映射为用户事实，避免为字段搬运调用长耗时模型；只有无法可靠识别的非结构化文档才允许使用文档 AI 兜底。
- 图片分支可基于明确画面证据保守补充卖点、痛点、受众、决策动因、营销目标和场景建议；建议进入对应字段的剩余容量并标注来源，不得覆盖用户事实。核心外观特征只在用户资料缺失时由识图补齐。
- 用户事实列表保留最多 20 项公共编辑安全边界，不因语义重复、字段疑似不合理或超过推荐数量而自动删除、改写、排序或迁移。核心卖点 3 项、次要卖点 6 项，核心痛点、决策动因和三类场景各 5 项，只是 AI 图片建议的可用容量；用户事实占满后不再向该字段加入图片建议。
- 语义模型只对用户事实生成非阻断提示，并对 AI 图片建议执行去重、迁移和择优。用户事实提示只能在同一业务层内比较：核心与次要卖点同属卖点层，核心痛点与决策动因同属用户层，使用、购买与情绪场景同属场景层；三个业务层之间不得跨层关联或迁移。关系判断采用商品无关的可替换性和有效差异测试：只有互相替换不会损失营销信息时才提示重复，同主题但目的、场合、时间、人群、动作、对象或关注点不同的内容必须分别保留。用户提供的产品名称、品类、规格和核心外观特征作为只读参照，仅用于防止图片建议重复占位，不得生成提示或被模型修改。图片建议先与权威事实比较，再在整批建议内统一去重；同一中心可见属性不得因换词或附加评价形成两条卖点。Worker 只校验事实 ID、字段数量、结构、来源权限和容量，不得使用字符相似、关键词、修饰语、文本包含或业务规则参与语义判断。模型返回局部结构问题时，Worker 只安全忽略无效决定并保留其余有效决定；用户事实提示不阻断信息卡确认。Provider 整体失败时保留全部用户事实，未经整理的图片建议不进入最终信息卡。
- 时长、画幅、分辨率、渠道、禁用元素和视觉风格只消费资料导入节点的有效配置，资料包和信息卡不能维护第二份配置。
- 用户修改提炼结果后确认，提交营销洞察工作副本；不修改则不得产生空 revision。
- 原始资料变更只让已存在且消费旧 revision 的下游待更新；尚未生成的下游不存在待更新副本。

## 下游依赖规则

每个下游保存实际消费的上游 `artifactId + revision`。例如 Prompt 批次同时绑定营销洞察和全局视频配置的具体 revision；二者任意一项确认产生新 revision，Prompt 批次才标记待更新。
