# 效果类工作流指南

固定流程：`资料导入 → 信息提炼 → 素材 Prompt → 片段渲染 → 模板混剪 → 成片输出`

以上为统一页面显示名称，节点 ID、任务类型、提交边界及业务数据保持原有定义。

## 业务目标

面向效果广告批量生产：先形成可复用的产品资料与营销洞察，再批量生成碎片化视频素材，自动搭建多条剪辑工程，最后统一输出成片。

## 节点关系

| 节点        | 作用                                                   | 直接上游             | 主要工作副本         | 直接下游      |
| ----------- | ------------------------------------------------------ | -------------------- | -------------------- | ------------- |
| 资料导入    | 按产品导入图片、视频、文档和电商链接                   | 项目资料             | 产品资料包           | 信息提炼      |
| 信息提炼    | 从资料中提炼产品基础信息和统一卖点事实                 | 已确认产品资料包     | 营销洞察             | 素材 Prompt   |
| 素材 Prompt | 配置创意参数并批量生成差异化的片段级视频 Prompt        | 营销洞察             | 素材片段 Prompt 批次 | 片段渲染      |
| 片段渲染    | 配置技术参数并将一条 Prompt 渲染为一个素材片段         | Prompt 批次          | 渲染素材片段集合     | 模板混剪      |
| 模板混剪    | 按模板槽位、标签、时长和去重规则生成多条独立时间轴工程 | 素材片段池、混剪模板 | 混剪模板、时间轴工程 | 成片输出      |
| 成片输出    | 对选中的时间轴工程执行最终合成与导出                   | 时间轴工程           | 最终成片、交付清单   | 项目归档/交付 |

## 不可混淆的语义

- Prompt 节点的每条 Prompt 只描述一个可用于混剪的素材片段，不描述一条完整成片。新生成素材不包含人物口播、旁白、逐字台词、歌词、字幕文案或可辨识说话口型，静音时仍需看懂产品动作和素材价值；只保留与画面同步的环境声和产品动作 Foley，配乐、统一口播和字幕交给后续混剪/成片处理。
- Prompt 条目只保留钩子、产品展示、效果、结尾转化四类主用途与兼容用途作为分类信息，不再生成、编辑、搜索、导出或向下游传递独立的次级素材标签。四类用途只在批量创意生成完成后分类，不得进入生成任务、成为数量配额或独立生成分支；人工新增或编辑时，主用途与“还适合”的兼容用途均由用户明确选择并保持权威。`效果片段` 表示产品解决需求后的结果、卖点表现或使用价值，不得把未经确认的配方、工艺或功效当成可视证明。
- Prompt 批量生成：批量生成由 AI 根据已确认卖点直接安排精确数量的素材任务，不再调用空间、方向、路线规划及重复关系复核。默认一条独立可呈现卖点对应一条素材；新任务的第一项事实是唯一主卖点，最多再带一个对同一观看事件确有必要的辅助事实，辅助事实不算已经获得独立素材。任务少时由 AI 选择当前容量能承接的卖点，多时先轮动主卖点再设计不同观看事件。规划按容量分页，完整事实和已有任务持续作为上下文；Worker 不做语义分配。初始生成扣除人工保留项后的目标数，数量/覆盖/近似问题最多合并一次补充；补充不超过目标数的 20% 或真实数量缺口（取较大值）。向量检测到近似时，Worker 只把实际重复组和原文安全投影给补充规划 AI，由 AI 理解重复原因并改换观看事件；候选池内容重复率达到 30% 时 MMR 使用 60% 质量与 40% 新颖度，否则使用 70% 与 30%。独立 AI 读取全部确认事实和视觉边界，判断实际实现程度，允许绑定未预分配但实际使用的合法事实。Worker 只检查来源、ID、数量、结构、枚举、revision 和哈希，不做语义、关键词或字符相似判断。新批次（包括补充）先由独立 AI 逐分片完成全量画面执行修正，正常条目原样保留，修订同步主线、六维和正文；修正未完成时保留未完成草稿，不跳过修正或冒充成功。每个分片修正完成即可进入评分，不等待整批生成；向量和最终择优等待整轮完成。评分建议有风险时仍由专职 AI 审片并记录软提醒，但新批次不再追加评分后的修订—审片—复评循环。Worker 仅做身份、数量、时长结构和合法文本应用，不做语义判断。商品参考图经快照、租约、大小与 SHA-256 核验及压缩后用于事实视觉策略和 Turbo 候选生成，不进入评分请求；仅帮助认识外形与操作，不增加配方、功效或材质事实。`PROMPT_CANDIDATE_PRODUCT_IMAGES` 默认 true，仅用于受控文字/图片对照。新 Run 不复用旧计划，只有同 Run 恢复有效检查点。
- 单条生成任务完整继承所属方向的事实组合。产品名称、品类、规格和外观由商品快照提供真实性边界，不能替代业务事实覆盖；事实语义是否真正实现由独立评估模型逐项判断。
- 人工新增 Prompt 必填正文、主用途和片段时长；“还适合”的兼容用途、创意方向与六大维度均为选填，允许全部留空或只填写其中一项。未填写的创意信息以空字符串保存，不生成占位内容、不显示“待补齐”，也不因缺少辅助信息阻止保存或下游渲染。新增与编辑复用系统白底、蓝色主操作和灰色边框的弹窗；新增的创意信息默认折叠，正文优先，底部操作保持可见。已有条目的“编辑”弹窗只显示只读时长和 Prompt 正文；保存只提交正文与原时长，服务端保留原有用途、创意主线、六维信息和来源标签，不启动单条 AI 补齐或首页任务进度。条目来源标签由持久化来源决定：`AI` 显示“AI 生成”，`MANUAL` 显示“外部导入”；编辑不会改变来源标签。语义重复度表示最近一次 AI 批次的评估结果，人工新增或编辑条目时保留该结果，不因手动内容触发重新评估或改变百分比。第一版视频生成请求只编译已确认的 Prompt 正文，并在供应商请求边界追加一次批次共用禁用约束；创意主线与六维只用于生成质量评估、页面展示和业务追溯，不进入供应商提示词。Prompt 正文或共用禁用约束变化必须更新供应商请求内容指纹；历史创意主线或六维变化仍按 Prompt 工作副本的完整内容规则更新业务 revision。人工条目采用用户明确选择的用途并标记 `VERIFIED`；AI 生成条目仍须有完整创意结构，未完成分类的 AI `PENDING` 条目不能提交 WorkingArtifact 或进入视频渲染。
- Prompt 卡片仅提供等宽同行的“编辑、删除”，不再提供复制或单条重新生成、候选采用/撤销入口；禁止新建 `ITEM_REGENERATE` 请求，历史读取、在途回调和 `ITEM_EVALUATE` 保持兼容。已有条目时长只读，API 拒绝修改；人工新增允许整数 4～30 秒并独立于批次默认时长。整批 AI 生成仍遵守统一默认时长 4～15 秒。人工新增超过 15 秒的条目必须选择支持对应时长的 Seedance 2.5，不再自动切换模型或降分辨率；混剪新模板的槽位上限仍只采用原批次默认时长。
- 渲染顶部设置是“新任务的默认配置，不追溯修改已有素材”。整批新渲染与局部更新新增 Prompt，在创建任务前读取当前可见工作区的默认配置和 revision；多个不兼容的 Prompt 在同一弹窗逐条选择模型、画幅、分辨率，可把已合法的配置应用到全部冲突项，所有冲突解决后才进入生成确认。单条选择只用于本次对应任务，不改顶部默认配置。API 再次校验范围、能力和默认配置 revision，把最终参数冻结到每条任务快照；已有素材局部更新沿用原任务配置，兼容的新 Prompt 使用本次默认配置。隔离编辑 Run 复制当前父 Run 的渲染设置，不能从素材继承来源或空状态回退为其他参数。
- 渲染局部更新仅比较已确认 Prompt 与素材已采用的 JSON 来源快照：正文/共用渲染输入变化重新渲染，创意主线/六维/用途变化免费同步信息，新条目只补渲染，删除条目通过既有删除标记从当前素材池移除。单卡“更新素材”仅更新该卡片，顶部“局部更新”处理全部差异；确认弹窗区分重渲染、新增、信息同步、删除数量，仅前两项写 Outbox。已手动删除的素材不自动补回，独立导入与未变化素材保持不变。局部更新使用专用自动提交标记，在隔离编辑态完整成功且通过来源/文件校验后自动原位提交当前分支，无需另点保存；纯信息同步与移除同样立即校验提交。失败保留草稿与旧视频可预览，支持定向重试；轮询可恢复中断的提交，重复提交不增 revision。更新期间 Prompt 再次变化时先采用本次冻结结果，再保留真实剩余差异。已有人工编辑须先保存或取消，自动更新期间不混入导入、删除、返修等人工修改；这些操作仍明确保存后提交。历史冻结草稿不因升级自动采用。不重跑历史成片或自动触发混剪/包装。人工全删可保存空结果并局部清空素材池，AI 批次不得以零条结果冒充成功。
- 渲染顶部“重新渲染”是整批重生成入口：必须在新子 Run 读取当前分支最新、已确认的 Prompt 工作副本和当前渲染设置，按 Prompt 条目一对一创建全新任务；不得继承旧渲染批次、`render-*` 工作副本或任何外部导入视频。原分支的 AI 素材、人工导入素材及文件均保持可回溯，但不进入新分支素材池。Prompt 节点内人工新增且已确认的 Prompt 仍属于合法输入，不能与外部导入视频混淆。
- Prompt 批次设置按商品保存总数量、片段时长、投放渠道、视觉风格基调和禁用元素。视觉风格默认选择“AI 根据场景选择”；自动模式不向创意版图或方向规划添加整批共享风格约束，只允许单条创意在确有需要时自然使用光线、色彩或质感。指定风格只约束光线、色彩、材质和镜头质感，不反向制造业务场景。渠道只指导表达节奏，不作为正文元数据。禁用元素在生成时确定性编译成一份批次共用提示词；顶部批次设置独立自动保存为下一次整批生成的输入草稿，修改设置不改写已有 Prompt、共用提示词或下游状态。已有条目的新增、编辑、删除须在列表操作区进入隔离编辑态并“保存修改”，覆盖当前分支，不自动开叉；条目编辑不覆盖下一次生成的设置草稿，整批重新生成成功且内容变化才自动开叉。
- Prompt 的事实视觉使用策略使用营销洞察实际依赖的源资料包图片进行多模态策略编译，大量事实按输出容量分片。API 只快照该 revision 内可用的 `PRODUCT_IMAGE`，Worker 经有效租约读取并安全压缩后，与完整已确认事实目录一起传给策略模型，分片只限定当次需要输出的事实 ID。图片只用于识别商品真实外形、结构、可见细节和可操作部位，不得成为新的规格、卖点、材质、配方、功效或使用结论来源；图片不继续传给创意方向、候选生成或评分节点。无图片的历史任务继续使用纯事实文本。
- 视频渲染节点产出碎片化素材池，不负责把多个镜头合成成片。
- 普通渲染进度只统计本次实际生成的任务；局部更新显示“本次更新进度”，覆盖本次生成、免费信息同步与移除的全部处理项，文字分别说明视频完成数及已同步/移除数。免费项在事务成功后计完成，不写生成 Outbox、不冒充视频生成。未变化素材不计进度；创建请求返回前显示 0/本次数量，不复用旧批次 100%。服务端记录本次范围供刷新、轮询恢复；素材池总数量与本次任务进度分开显示，未全部完成不得因四舍五入显示 100%。
- 渲染素材来源标签依据持久化导入来源判断，不根据会随重试、重生成或返修变化的供应商任务 ID 判断。局部更新的编辑态切入与提交回切由页面后台同步；连续通知不得丢失，旧响应丢弃后继续轮询，不要求用户手动刷新。
- 每个已完成片段继续使用独立 `render-clip:{taskId}` 工作副本维护返修、重生成和版本依赖，整批使用 `render-batch:{productId}` 工作副本维护素材池索引；项目工作区概览只展示聚合素材池，不平铺同批单片段工作副本，点击素材池返回视频渲染节点查看明细。
- 已完成的 4–30 秒 MP4/MOV 素材允许在视频渲染节点发起整段参考视频返修：用户给出问题时间段、文字修改要求和可选归一化矩形区域，供应商请求只携带确定性返修提示词与当前采用的视频，不再携带产品参考图或原 Prompt。外部导入素材超过 15 秒时，返修与重新生成自动使用 Seedance 2.5；否则使用渲染节点当前模型。2.5 返修使用视频编辑协议，2.0 系列使用视频参考生成协议；重新生成使用已确认的反推提示词，不依赖导入草稿 ID 对应的上游 Prompt。返修结果先保存为候选，不覆盖当前素材；用户明确采用后才切换活动版本及实际时长，放弃则保留原版本。返修创建、Worker 领取、回调、自动重试与采用/放弃必须复用现有任务、Outbox、租约和批次 revision，并保持项目与运行隔离。整批渲染完整成功且通过服务端校验后自动提交；人工采用返修及其他修改在隔离编辑态“保存修改”时提交到当前分支的 WorkingArtifact，不自动开叉。
- 视频渲染按商品独立保存画幅、分辨率和 Seedance 能力。创建任务时固定读取已提交 Prompt 工作副本与当前渲染设置；技术设置变更只影响新任务，不回写 Prompt 或营销洞察。
- 外部导入素材重生成/返修按活动素材短边与用户设置选择不降档的标准分辨率；当前模型能力不足则升级。无法匹配时，15 秒以内采用 2.0/4K，超过 15 秒采用 2.5/1080p；该选择只影响当前素材任务，不能改变全局配置或 Prompt 时长上限。真实输出时长由 ffprobe 测量，供应商取整时长不能替代真实媒体时长。
- 模板混剪先生成可人工精修的时间轴数据，不应在“智能填充”时立即渲染视频。智能填充完整成功并确认时间轴后，该模板的可用工程立即进入成片输出的待渲染区域，先以仅画面状态展示；用户仍可继续智能成片包装，成功后原位补齐口播、字幕、配乐，不新增重复待渲染成片。
- 整批智能填充首先覆盖冻结输入的全部可用素材，再根据有效新搭配与可替换画面差异自适应扩充数量，不穷举填满安全上限，也不固定为一轮覆盖数量。素材只供其已归槽用途选取，单片素材不重复、槽位完整、归槽/时长/来源合法及不与已有完整组合完全相同仍为硬约束。覆盖后新增组合要有足够的可替换槽位和时长差异及新镜头对；单候选槽位的强制复用不贡献新意。覆盖阶段不因“最多共用两个槽位”提前停止；确实无法完整覆盖时必须指出缺失素材或容量原因，不能悄悄漏选后标记成功。既有历史任务恢复只能使用已选片且有合法截取结果的素材。
- 模板配置只维护六槽位顺序、标签、权威时长和转场；进入精修工作台不预生成演示工程。用户主动触发 AI 智能填充后，独立 Worker 根据同 Run 已确认的原始 Prompt 对六槽位评分（不参考 Prompt 推荐用途），匹配每条工程内部六个不同素材，对选中视频抽帧并由模型选择合法截取起点。归槽与截取检查点只在同 Run 有效输入下恢复，旧任务不能覆盖修改后的模板或素材。任务完整成功后自动提交 `mix-template:<templateId>` 与 `timeline-project:<templateId>:<variantId>` 工作副本，工程依赖记录实际素材片段 revision，并建立仅画面的待渲染批次；不要求用户再点击完成校验。算法批量组合复用仍有效的 AI 素材池，不为每个组合重做模型截取。
- 混剪模板删除属于明确确认后的永久删除：不因已有工程、包装或输出子分支而拒绝。确认后立即通过持久化删除回执隐藏该模板及其专属分支，取消该模板在途任务；后台按阶段清理配置、工程、包装、交付、资产、历史和 Redis 效果类聚合缓存，可恢复重试，不等待文件或缓存完成才返回。旧回调及旧草稿不能复活模板；其他模板、项目和共享上游素材保留。历史共享来源必须保持原身份和 revision，必要时只保留不可写且不展示的最小来源容器，不能替换成最新快照或破坏兄弟模板依赖。
- 删除的分支归属采用明确 `forkTemplateId` 或同 Run 的真实任务归属；父子关系、继承配置及配置哈希变化不能证明模板归属。旧版归属不明或多模板共享容器保守保留，只清理目标模板内容并将存活子分支接到安全上游。旧删除回执若包含其他模板任务所属 Run，后台必须停止该轮数据库清理并等待核查，不继续误删。删除后切节点先完成存活 Run 的导航交接，不向已删除 Run 保存草稿；文件与 Redis 清理仍在后台，不参与导航等待。
- 工作台顶部“重新智能填充”是模板整批重生成入口，不传当前成片ID。在独立子Run成功后生成目标模板的新批次，不叠加继承的旧工程；原分支、其他模板和失败时的原工程保留。单条恢复与新增素材追加仍使用各自既有路径，历史快照没有整批替换标记时不改变其恢复语义。
- 渲染素材删除只有保存成功才在 `render-batch` 发布明确删除来源；删除任务保留隐藏来源记录，历史文件不撤销。混剪素材库隐藏删除来源，仅实际引用的工程待更新。混剪局部更新在当前分支清除对应画面、关联原声、口播和字幕，保留空槽位置与原总时长、其他内容及 BGM；空槽允许黑屏预览和输出。纯删除不调用模型或最终编码，已导出的旧文件仍可用，需在成片输出主动局部更新才覆盖。整批重新智能填充直接读取最新素材，无需先局部更新；新增、编辑、删除及混合更新一律对全部有效素材重新归槽，不复用旧分类、人工归槽、匹配和截取，短素材不得归入更长槽位。首次填充、同任务失败恢复、单条恢复与新增素材局部追加仍保留其各自归槽规则。
- 成片输出按模板隔离已确认的待渲染工程。待渲染工程可以来自智能填充后的仅画面时间轴，也可以来自完成智能成片包装后的音画工程；包装成功原位升级尚未导出的同一批次。用户选择一个模板并设置分辨率、帧率后，主动点击“导出成片”才创建 FINAL_OUTPUT 队列任务；该操作渲染所选模板的全部成片。每次整批导出（含重新导出）都在当前模板的独立子 Run 执行，全部成功并写入 `final-delivery:<templateId>` 交付清单后才发布成片输出版本分支；失败或部分完成不发布，父分支中已交付的成片保持可用。参数冻结在输出快照中，失败恢复只作用于该模板批次，已成功成片不重复渲染。成片文件、项目资产及 `final-video:<templateId>:<variantId>` 工作副本逐条保存；不另设用户校验。成片输出继续负责预览、分页与下载。

## 资料导入

- 当前正式流程中，一个项目只维护一个活动产品；资料导入页面不提供单品/批量模式切换。历史批量草稿和接口仅保留兼容读取，新进入页面时统一恢复到单产品草稿。
- 资料导入节点不要求用户提前填写产品名称；产品名称由 AI 信息提炼从文档和图片中提取，并可在信息卡中人工修正。资料导入之后的节点仍按内部产品 ID 隔离数据，但单产品项目不展示产品选择器。
- 上传成功可进入当前节点草稿；格式和完整性校验通过后，用户在编辑态点击“保存版本”才提交产品资料包 revision。
- 删除后又添加完全相同文件，如果最终规范化内容指纹未变，确认时 revision 不增加。
- 不在资料导入节点维护时长、风格、渠道、禁用元素、画幅或分辨率；旧字段只供历史结果兼容读取。

## AI 信息提炼

- 当前信息卡只展示产品基础信息和统一卖点列表。卖点不分核心与次要，也不再拆成受众、痛点、决策动因和场景等平行字段。
- 口味、原料、工艺、结构、性能、吃法、使用方式、适用人群、用户需求、使用场景和可信背书，只要有资料依据且能帮助后续视频创意，都作为独立卖点事实保存。
- 每条卖点只表达一个命题，并保留来源证据；营销目标、时长、画幅、分辨率、视觉风格、渠道和禁用元素不属于产品卖点。
- 文档、表单和电商资料中的非空内容属于用户事实，页面不重复展示“用户事实”标签；图片识别只补充可见信息，并逐项显示轻量的图片识别来源说明，不得覆盖价格或挤掉用户清单项。
- 符合产品信息表格式的资料文档应确定性映射为用户事实，避免为字段搬运调用长耗时模型；只有无法可靠识别的非结构化文档才允许使用文档 AI 兜底。
- 图片分支可基于明确画面证据保守补充产品外观、包装文字、使用动作和可见场景等卖点，并标注来源；不得由画面推断配方、工艺、产地、认证、功效、销量或消费者评价。核心外观特征只在用户资料缺失时由识图补齐。
- 图片分支成功但所有候选均在语义整理中被淘汰时，主页面必须显示处理图片数、候选数和“本次没有新增图片补充”的安全摘要，避免用户误判为识图未执行；该摘要不得写入信息卡或营销洞察 WorkingArtifact。
- 卖点列表通常建议控制在 40 项以内，但 40 不是截断或编辑上限。文档 AI 优先去重和排除低价值内容；结构化标准资料中超过 40 项的独立有效事实必须完整保留，用户也可继续手工添加。竞品、泛行业常识、纯文字购买建议、保存或安全提醒，以及未经当前商品证据支持的健康功效不进入卖点。同主题但分别表达原料、工艺、感官、使用方式或消费需求的事实可以分别保留。
- 语义模型只对图片建议做与权威卖点的去重和事实边界复核，不再执行跨业务字段迁移。Provider 整体失败时保留全部用户事实，未经整理的图片建议不进入最终信息卡。
- 历史信息卡中的核心/次要卖点、可信背书、受众、痛点、决策动因和三类场景只在 API 读取边界按原顺序折叠到统一卖点；不调用模型、不改写历史记录、不增加 revision。
- 信息卡只维护可信产品与营销事实，不维护视频制作配置。Prompt 节点维护数量、时长、视觉风格基调、渠道和禁用元素；渲染节点维护画幅、分辨率和模型能力。
- AI 提炼成功后进入待审阅编辑态，不自动提交；用户点击“保存版本”才提交营销洞察工作副本，不修改则不得产生空 revision。
- 已确认版本后点“重新 AI 提炼”会先自动进入隔离编辑态再开跑，不需要用户先点“进入编辑”；“进入编辑”仍保留给“只手工改字段、不重跑 AI”的场景。另一个节点正在编辑时后端返回 409，页面提示先保存或取消当前编辑，不自动动那个节点。提炼成功本身不新增版本树节点，只有“保存版本”且内容相对编辑基线有变化才发布提炼分支。
- 相同资料包重新提炼可继续应用人工修正；确认上传了不同资料包后，新的文档卖点必须重新成为权威结果，旧的整组卖点草稿不得覆盖新资料。产品基础字段的明确人工修正可以保留，Worker 的 `generatedResult` 不得混入人工覆盖。
- 原始资料变更只让已存在且消费旧 revision 的下游待更新；尚未生成的下游不存在待更新副本。

## 模板混剪内的智能成片包装

- 智能填充运行锁按当前模板隔离，不用任务轮询驱动页面级请求锁。运行中的模板仍允许进入工作台查看进度，但不能修改其冻结工程；其他模板可正常切换、编辑和进入工作台。任务创建交接子 Run 前释放短请求锁，任务完成回写只合并所属模板，保留其他模板的最新草稿与当前选择。

- 当前模板的可选素材库统一按真实素材时长准入，不区分 AI 生成或外部导入：至少能容纳一个模板槽位才展示并计入归槽、搜索及分页。六槽均6秒时排除5秒素材；存在4秒槽位时5秒素材仍可参与合法槽位选材。新填充输入与完成校验采用同一口径；历史冻结任务保留原协议，完整上游集合继续供已有工程解析，不因素材库过滤删除源素材或历史绑定。

- 局部更新 APPEND 的新冻结快照允许空槽：先删除/替换已有工程引用，再归槽新增素材，使用同一冻结有效素材池组合。有合法候选的槽位正常选材，无候选槽位以明确空槽保留位置、时长与总长度，不伪造素材或截取；每条追加工程至少采用一条新增素材，不生成全空或重复组合。空槽属于待补充提醒，不表示更新失败或素材待更新；未实际采用的新增仍待处理。首次和重新智能填充仍要求完整成片，历史追加快照保持原校验。包装按实际画面开始时间排序，用明确槽位身份绑定用途与时间，跳过空槽，不按非空素材序号重排槽位；不为其生成口播/字幕，BGM 保持原总时长。空槽不参与转场，不跨空槽衔接两侧画面；可按现有拖入/替换操作补齐，不自动重做包装或最终导出。

- 混剪素材区在智能填充前后均显示“待归槽、六大用途槽位”，不提供“全部”标签。用途标签、素材/音色等顶部分类及成片项目操作保持单行、不随面板缩小压缩控件或换行，宽度不足时用横向滚动条访问。新建成片使用项目标题旁的小加号入口，保留原创建与锁定规则。素材卡片的“更换槽位”保存当前模板和 Run 的用途归槽草稿，不直接改变已有时间轴或提交产物。已归槽素材在智能填充中只能供对应用途槽位选材；待归槽素材由 AI 分类。任务冻结启动时的归槽快照，期间的新归槽修改只影响后续任务，完成回写不得覆盖归槽草稿。

- 包装是模板混剪节点内的独立异步任务，不增加固定工作流节点。复用智能填充的 Worker 和队列，`schemaVersion: 1` 仍执行填充，`schemaVersion: 2 + taskType: PACKAGING` 执行包装。
- 首次包装与重新包装均须先完成当前模板待处理素材的局部更新，包括新增、编辑和删除；创建编辑分支前提示具体操作，不以重新包装静默替换来源或重新截取。重新智能填充不受此先更新条件限制；历史在途任务仍按其冻结协议恢复。
- 精修工作台将新增、替换及删除统一为一个黄色“局部更新”入口和一条同名进度条，按钮名称固定且不附加数量；进度条右侧另显示任务真实阶段和已完成数量。用户主动点击后，混合变化先完成已有工程来源更新，成功后再追加新成片；复用既有 APPEND 及自动包装规则，失败、取消确认或切换作用域不继续追加。确认弹窗等待期间不伪造运行进度。当前 Run 的 APPEND 归槽检查点通过轻量 sources 轮询实时展示，不等待整体任务结束，不覆盖人工归槽或用户工程草稿。下载或截取失败后，完整且通过校验的归槽检查点仍可只读展示，须核对当前文件、来源 revision/哈希、模板配置及人工归槽版本；失败不代表已采用新增素材，不清除新增待处理或发布工程，取消、整批失败及来源不匹配的检查点不展示。
- 混剪子层级的树展示版本号按直接上游头节点递增：填充按模板配置头节点、包装按实际智能填充头节点、导出按包装头节点（未包装时按填充头节点）。同一头节点的兄弟版本连续编号，更换头节点后从01开始；继承任务不占号，不修改工作副本内部 revision。一个已发布分支只占一个版本号，局部更新、编辑及追加成片产生的内容 revision 和成片数量不得充当编号步长；包装头按首次完成时间确定顺序，后续追加成片的包装完成时间不得重排旧分支。新协议整批包装（包括首次及已导出纯画面工程）始终创建独立子 Run；终态至少一条成功才发布新包装分支，失败项完整保留包装前内容，全部失败不发布。单成片包装与局部更新追加自动包装原位提交，不新增分支，旧导出文件只有用户主动更新才覆盖。
- 用户主动发起后，冻结完整成片的视觉时间轴与实际依赖 revision；视觉理解只解释画面，口播商品声明只能引用依赖链中已确认的产品事实。按句配音，以实际音频时长生成字幕，为每条工程生成纯音乐并转存。
- 包装成功不执行 AI 内容审核或逐条人工包装确认，仅保留机械校验；包装完成回调在同一事务中提交 `timeline-project:<templateId>:<variantId>` 与 `timeline-package:<templateId>:<variantId>`，将智能填充建立的待渲染条目原位升级为音画工程。包装后用户可独立编辑画面与音画轨道：视频片段的起点/轨道/排列/转场、素材来源、绑定 revision、源截取区间或槽位时长变化，均不使已完成包装过期、不锁定或隐藏口播、配乐、字幕，也不阻止试听、编辑和成片输出。系统不判断旧口播/字幕是否适合用户后来选择的画面；输出时使用最新确认的画面排布和原有独立音画安排。异步包装尚未完成时仍按冻结快照、租约和 attempt token 校验写回，避免迟到任务覆盖新任务。
- 已导出的文件是当时的渲染结果；后续混剪编辑不能静默改写或自动付费重渲染。当前成片分支中的工程被编辑后，旧成片继续可播放和下载，只对实际变化的条目标记“待更新”；用户主动局部更新时在当前分支覆盖该条结果，整批重新导出仍创建独立分支。系统不判断旧口播/字幕是否适合后来选择的画面；实际文件缺失、不可读、任务未完成和项目隔离仍执行机械校验，用户主动操作轨道头锁定才是锁轨。
- 音频素材各自独立控制音量、静音、淡入淡出和时间位置，口播或字幕配音播放不能自动压低纯音乐。播放器与最终导出采用一致规则，分割后的音乐及导入音频同样不受其他轨道联动降音量；已导出文件不自动重渲染。
- 新生成的包装口播默认音量为 `2.0`（200%，约 +6 dB），通过既有独立音量字段应用于预览和导出，不烘焙进原始 PCM、不改变字幕/音频时间或配乐音量。已保存和人工编辑的音量在恢复时保持原值，历史工程不因默认值升级自动改动。
- 工作台包装流程图独立显示真实任务状态；整批按钮始终新建全部重新包装任务，不调用历史恢复接口。时间轴操作提示与缩放之间提供“成片包装”按钮，仅更新当前成片，右侧绿色进度条及阶段文字立即显示提交、运行、自动重试和结束状态。不展示恢复按钮、失败恢复横条或任何成片卡片包装标签；最终失败只在结束摘要及流程详情说明已保留原样。历史恢复协议兼容，但升级不自动启动旧失败任务。配置缺失明确失败，不回退模拟结果。
- 包装分片用于进度和恢复：每片最多四条，全局任务池默认六条成片并发、可配置且最多八条，完成一条即补位，不等待整片结束；预处理最多两条，模型与配音各自默认最多四路、音乐独立限流。逐条保存检查点，失败恢复不重做已有成功步骤。吞吐与剩余时间由服务端计算，供应商停滞时不得继续展示不可靠 ETA。
- 配音明确未建立连接时按单请求最多8次、600秒恢复，其他可恢复步骤默认追加2次，指数退避最高30秒；次数、等待时间和40分钟单条总预算持久化，重启不重置。等待释放供应商额度，每次尝试校验租约与取消，成功步骤不重复。响应中断、读写超时或崩溃后无法确认付费结果时不盲目重发；已获得音乐任务 ID 则继续查询。视觉结构错误缩小分组、单槽格式纠正有界，不采用无效输出。
- 新协议冻结完整包装前基线，运行视图只保留视频，清除全部非视频轨道（含独立音频、字幕及分离原声），保留原总时长、空槽、间隙和位置；不物理删除文件。逐条成功事务性提交新音画工程并即时显示，失败或取消保留完整原工程。首次成功可打开子 Run 任务工作区查看及编辑已结束条目，不提前发布分支或修改父分支；未结束条目按成片锁定，其他成片和模板可操作。终态只发布及汇总，不重写已经提交或人工编辑的工程。部分失败显示已结束及成功、失败数量，不用停滞的运行百分比冒充仍在执行。
- 新包装文案按整条成片统一编排：根据实际播放顺序、画面及已确认事实选择一条叙事主线，保持视角和语气一致、信息自然递进，避免每槽位重新介绍商品或重复同一卖点。名称/品类按身份建立、消歧和收束需要自然使用，不按关键词删词或固定次数硬限。连贯不等于把不同镜头虚构为同一次动作或强造因果。首次生成、缺失文案恢复、结构修正及配音超时缩句/重策划均参考整片和既有邻句；非目标口播只读，不改写邻句或补回用户已删除的口播。此规则适用于任意商品，不增设 AI 内容审核、额外语义重试或产品特例。
- 文案统一策划后仍按槽位独立落地，每槽位 4–15 秒、恰好一条完整自然口播，具体画面描述、配音及字幕不得跨素材；语义可承接，但不把半句话拆到下一素材。重叠目标槽位必须先调整时间轴，局部更新不扩大为未改槽位的校验或写入。直接从源素材截取代表帧，同项目/Run 内复用相同内容哈希和截取的视觉结果；只缓存视觉理解，不跨成片复用口播。旧整片分段包装只可播放，不能进入成片输出。单槽位重做保留其它槽位和配乐，来源/工作副本提交边界不变。已成功文案和音频不因升级重生成，新规则只在用户主动启动并需要策划/修正时生效。
- 第六步在用户点击“导出成片”后，通过同一个 Worker/队列的 `schemaVersion: 2 + taskType: FINAL_OUTPUT` 分支消费已统一确认的视觉、包装及其依赖。分辨率和帧率随快照冻结；FFmpeg 合成自然声、口播、配乐和烧录字幕，输出 H.264/AAC，并保存项目正式交付资产；每条独立保存状态，失败恢复跳过成功输出。分析用低清代理不能当作最终成片。实施及验证边界见[包装并发与成片输出](plans/2026-09-22-包装并发与成片输出.md)。
- 成片列表与模板配置分支树共用每模板当前路径定位，限定在当前视频渲染/手动复制谱系；不要求所选模板路径等于项目全局活动 Run，也不要求用户点击切换分支才能导出。导出服务重新校验模板当前批次，在该路径下创建输出子 Run；事务内冻结活动指针，其他编辑或任务冲突时拒绝，不自动重试。运行中的输出子 Run 不提前出现在树中，但页面保留其任务进度。
- 混剪模板列表展示同渲染/手动复制谱系下全部模板各自的当前工作流，普通模板选择不切换项目全局活动分支、不展示“同步分支”提示。列表与可写工作区分离：目录为各模板当前路径的只读投影；配置、精修、保存和局部更新使用选中模板的真实 Run 与草稿 revision，其他路径的目录条目不能序列化进该 Run。版本树中的显式版本切换及任务完成后的版本交互继续沿原有机制。
- 每个模板的当前工作流优先采用用户在版本树中明确选择的填充、包装或成片版本，并通过既有 WorkflowNodeState 持久化导航状态；返回模板配置、刷新或查看其它模板不重置该选择。未选择时才按最近已确认结果回退。模板配置头是该模板当前工作流的配置入口，不强制切回创建时快照；目录、画布、配置树与成片输出共用路径解析。选择记录不属于执行输入，不增加 WorkingArtifact revision、不修改工程或触发任务，也不随手动复制或跨来源头继承。
- 混剪成片卡片不显示包装成功、包装中、包装失败或未包装标签，包装状态集中在任务进度与详情。旧文件快照不被展示规则改写，实际工程差异仍显示“待更新”和局部更新入口。顶部画布依据当前 Run 工作副本 freshness 与每模板当前成片批次差异展示橙色“待更新”警告，不展示工作副本数量；模板列表按受影响成片数量显示“X 个成片待更新”。未生成的节点不伪造待更新状态，切换作用域清理旧提示。
- 画布待更新与正在查看的节点无关：各节点页面均读取当前来源谱系中各模板当前路径的服务端依赖状态。进入隔离编辑时按正式父 Run 展示已确认的下游告警，取消或无变化保存不清除告警；实际保存变更后重新计算真实受影响路径，不以空编辑草稿或单个模板就绪覆盖其他模板待更新。真实下游更新后重新读取才能清除对应告警，迟到请求和跨项目数据不得回写。
- 分支树按实际工作副本依赖提示各历史分支的待更新：受影响节点标黄边，保留当前红色路径；混剪模板、填充、包装、输出分别判断，不将无关模板一起标黄。祖先素材复制快照不能遮蔽已采用的最新来源；独立上游头与手动复制边界停止继承。局部更新只提交用户当前选择的 Run、模板及成片，其他分支仍待更新，由用户切换后主动更新，不能自动改写子节点工程或启动任务。
- 上游节点状态读取其实际来源头：渲染节点已保存的素材是当前结果，下游分支保留的旧素材快照只使对应混剪工程待更新，不能反向把渲染节点标黄。`needsAiFill` 只表示模板槽位配置变化；素材返修或重生成沿原有槽位差异执行当前分支局部更新，不强迫重新智能填充，兄弟混剪分支分别处理各自引用。
- 混剪精修工程的草稿自动保存成功后，只有当前 Run 尚无已确认的成片输出版本，未导出待渲染条目才按同项目、同 Run、同模板静默跟随最新草稿与已保存的包装音画修改；连续编辑按草稿 revision 防止旧请求回写，进入成片页也重新加载预览。一旦该分支已有成片版本，自动同步停止，具体成片只展示差异与“局部更新”；用户主动更新前不触发付费任务，更新时采用当前工程已保存的音画安排，并将最新可用画面重新渲染到同一分支。若当前画面素材已不可用，须先在混剪节点修复，不能覆盖旧文件。

## 下游依赖规则

人工新增、编辑、删除 Prompt（包括全部删除）均保留最近一次 AI 批次语义重复度及其原始评估数量，不重新计算百分比，也不将其重置为“待评估”。历史草稿误丢失该统计时，仅从同一结果记录的原始生成快照恢复展示，不修改正文、数据库或业务 revision；没有有效原始评估时不得伪造 0%。只有新的 AI 批次评估才能更新这一统计。

成片整批重新导出冻结新子分支中最新已保存的混剪工程及可用包装，全部条目重新渲染（包含待更新条目），不复制旧交付的画面排布。后台子分支渲染期间不抢占原活动分支，原模板当前成片分支仍可局部更新；两者任务、租约、快照、文件及发布分别隔离。前端保留原分支列表并独立显示新分支进度，完整成功发布后可查看新版本；后台任务不替代当前分支待更新计数。

每个下游保存实际消费的上游 `artifactId + revision`。资料包确认变化才使信息提炼待更新；营销洞察确认变化才使 Prompt 待更新。Prompt 自身的视觉风格基调、渠道或禁用元素变化不重新执行信息提炼；渲染设置变化也不使 Prompt 过期，只影响之后新建的视频任务。

Prompt 生成设置草稿（数量、时长、风格、渠道、禁用元素）的保存或恢复，不使已经确认的 Prompt 工作副本和视频素材失效。设置指纹继续用于生成任务的输入快照与领取/提交校验；只有确认提交的 Prompt 工作副本内容发生变化时，才使实际依赖旧 revision 的下游待更新。历史素材恢复必须逐项验证依赖 revision、内容哈希与文件，不能整体清除 STALE 标记。

同一渲染谱系的素材池若明确采用了下游分支中的已确认 Prompt，旧导航入口的更早 Prompt 快照不得反向作为渲染差异目标。渲染读取、更新确认、编辑副本准备与画布/版本树共用来源选择：核对实际采用的 artifact 身份及 revision/指纹，不按跨副本最大 revision 选源；之后真正保存的新内容仍参与净差异，即使其副本 revision 较低。复制快照的创建/更新时间不代表新的人工提交；隔离编辑与独立渲染谱系不得跨界改源，证据不足时保留原读取与告警。
