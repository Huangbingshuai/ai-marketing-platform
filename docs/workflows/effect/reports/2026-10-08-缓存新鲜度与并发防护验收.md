# 缓存新鲜度与并发防护验收

日期：2026-10-08。对应[计划](../plans/2026-10-08-缓存新鲜度与并发防护.md)。本轮修改共享缓存、前端预取及相关测试；未修改业务产物、任务协议或用户商品资料。

## 修复结果

1. Run 与版本向量改为同一条 PostgreSQL 查询，校验向量完整性；修复先读 Run、后读版本的快照间隙。
2. 命中后、并发等待后和加载后复核版本，读取过程中发生保存时重新读取。旧实现只阻止旧 DTO 写入缓存，仍会向当前请求返回旧 DTO，本轮已修复。
3. Redis 断连后依然合并同一版本的数据库回源；128 个不同键的在途回填上限，超限快速返回 503。Lua 原子校验回填锁 token，过期持有者不能覆盖新锁或发布数据。
4. 对已授权且已验证版本的 Prompt 结果缺失增加 4–5 秒负缓存，新结果创建后版本变化立即失效。空目录仍可缓存；不负缓存权限、未知 Run 或数据库错误。
5. TTL 抖动、连接代次、4–6 秒重连冷却抖动，防止集中失效和迟到连接命令。新旧缓存协议使用不同参数哈希，避免部署期间格式冲突。
6. 前端预取仅共享在途请求；JSON 写入和文件上传开始/结束都会使旧预取失效，读取等待期间发生写入也会重新获取。取消复用已完成的五秒旧快照。

## 测试证据

本轮最终相关测试 **256 项通过**：缓存 43 项（包含真实数据库/Redis和真实 HTTP 集成两项）、API 相关业务/配置 132 项、Web 81 项。

- 真实 PostgreSQL 连续两轮保存，随后 HTTP 读取立即获得新 revision；不同项目/Run 隔离。
- 真实冷加载暂停期间提交新内容，返回新内容；真实 Redis 命中后插入一次提交，返回新内容。
- 真实 Redis 回填锁被替换后，旧持有者既不发布缓存，也不删除新锁。
- 独立错误端口模拟 Redis 不可用，20 个并发请求只执行一次同版本 loader；未停止、清空或重配共享 Redis。
- 单元覆盖活动任务启动后绕过缓存、权限/数据库错误不缓存、负缓存创建后失效、TTL 分散、回填上限、持续写入有界重试、连接超时与旧失败隔离。
- 浏览器依次恢复导入、提炼、Prompt、渲染、混剪、成片输出，成片页面刷新后仍显示模板和列表；浏览器错误日志为空。未进行付费生成，不以页面观察代替并发测试。

## 实测性能与运行实例

本地 API 3100，当前真实效果类项目；每个接口顺序读取 10 次。没有清空 Redis，因此首次耗时不等于统一的冷启动基准。热读统计为后 9 次，样本不足以代表生产高并发 P95。

| 读取       | 本轮首次 HTTP | 后 9 次 P50 | 后 9 次 P95 |
| ---------- | ------------: | ----------: | ----------: |
| 导入工作区 |          26ms |        28ms |        30ms |
| 导入草稿   |          28ms |        26ms |        29ms |
| 信息提炼   |         105ms |        30ms |        38ms |
| Prompt     |         130ms |        26ms |        27ms |
| 渲染工作区 |         148ms |        27ms |        40ms |
| 混剪工作区 |        1014ms |        39ms |        55ms |
| 成片输出   |        2141ms |        28ms |        33ms |
| 版本树     |          25ms |        24ms |        26ms |

运行服务命中日志的 `loadMs=0`；另用 `verify-effect-read-cache.mjs` 对混剪、成片输出、版本树逐项对比真实 HTTP 与 Redis 内容哈希、版本及 TTL，均通过。Redis 实例实际为 7.4.10 standalone，内存上限 256MiB、`allkeys-lru`，检查时约 4.7MB、累计淘汰 0；实例计数不当作应用命中证明。

代码热更新重启期间首次测量遇到一次 `ECONNRESET`，待服务启动完成重跑后获得上表。并行构建时日志也出现过 Redis 超时后数据库回退；这说明故障链路生效，不代表所有请求都有热缓存速度。

## 边界

“实时”指新请求不因 TTL 使用已知旧版本，读取期间检测到变化会丢弃旧缓存；并非读取结束后自动推送所有新提交。任务状态继续使用原有权威读取与轮询周期。首次未命中、数据库查询、文件传输和浏览器渲染仍需时间，未承诺零延迟，也未完成生产多实例压测或所有付费任务端到端回归。
