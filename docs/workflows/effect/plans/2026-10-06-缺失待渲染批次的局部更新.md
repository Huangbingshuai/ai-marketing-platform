# 缺失待渲染批次的局部更新

## 范围与原因

效果类混剪工作台已有确认时间轴，但智能填充后的待渲染批次补建失败。普通同步要求 CURRENT 来源，无法补建引用旧素材的 STALE 工程，前端误报未确认。

## 实现边界

- 工作台局部更新按项目、当前 Run、模板、草稿 revision 和成片 ID 单次请求；服务端定位已有批次，不依赖前端列表推断是否确认。
- 批次缺失时，以 AVAILABLE 的已确认时间轴为确认凭据，STALE 不等于未确认。事务内建立临时基线并复用既有局部更新逻辑，在同一事务内校验最新素材、形成有效快照、写入 Outbox；任何错误整体回滚。
- 临时基线不能单独持久化，不需要旧视频文件仍存在；不新增工作副本 revision、不自动更新兄弟分支、不执行额外智能填充。
- 原成片输出更新、普通草稿同步、Worker 协议保持不变。不迁移数据库。

## 验收

覆盖缺批次且部分/全部工程 STALE、已有批次、未确认工程、旧 revision、最新素材不可用、重复请求与分支隔离。实际项目通过数据库事务回滚验证排队，不派发付费任务。验证 API/Web/Contracts 类型与相关测试、构建、diff 检查；浏览器验证原按钮调用新路径。

## 补充：其他模板的实际分支

- 真实“测试2”复现表明：在“测试3”的活动 Run 内切换模板列表，只更换模板 ID，仍使用复制到该 Run 的“测试2”草稿；其已确认时间轴与待渲染批次实际位于独立的“测试2”包装 Run。缺批次补建不能跨兄弟 Run 猜测确认关系。
- 模板列表选择及进入精修工作台复用 `effectTemplateBranchTips` 定位同渲染谱系下该模板的当前实际分支，保存离开前草稿，再激活已有分支、重新加载其草稿和确认记录。只交接模板、成片和配置/编辑视图，不复制工程、不新增版本、不启动任务。
- 分支树显式选择的历史 Run 继续保留；模板在当前 Run 尚无独立分支时继续使用当前 Run。异步导航过程中锁住编辑；保存失败、作用域变化、外部页面切换活动路径不能继续旧操作。
- 增加真实“测试2”已有批次的事务回滚验证、模板切换与历史分支导航回归；服务端不放宽确认、草稿 revision 或分支隔离校验。
- 局部更新提交前同样检查模板作用域；已打开的复制草稿先导航到实际分支，再恢复点击并展示真实受影响工程的确认弹窗。交接后保存模板选择，刷新不恢复到另一个复制模板。导航中旧填充/包装完成回调不能抢回活动路径。
