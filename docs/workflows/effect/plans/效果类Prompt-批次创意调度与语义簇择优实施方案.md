# 效果类 Prompt：批次创意调度与语义簇择优实施方案

## 1. 状态与目标

- 状态：实现完成，最新真实样本仍未通过质量门槛，已继续修复
- 开始日期：2026-08-31
- 工作流：效果类
- 业务节点：第 3 节点“Prompt 生成”

本轮保持当前八阶段拓扑和公开结果契约不变，在“连贯六维创意生成”内部增加批次创意方向规划，并让评估与择优识别真实场景、动作等业务语义簇，解决文字不同但大量内容仍集中于同一创意套路的问题。

直接上游仍为已提交的营销洞察与全局视频配置具体 revision。生成、评估和五次真实验收只更新领域草稿与 `WorkflowNodeState`；只有用户完成校验后才更新 `prompt-batch:{productId}` WorkingArtifact。

## 2. 实施内容

### 2.1 批次创意方向规划

- 仅 `BATCH_GENERATE` 增加一次轻量 AI 规划，基于已确认事实、事实视觉策略和共用提示词形成 8～12 个创意方向。
- 每个方向引用当前事实，包含简短方向、恰好两个优先变化维度、六轴语义族和最多两个避让套路。
- Worker 拒绝未知事实、不确定事实、重复方向和禁止推导；无效结构最多恢复一次，失败后不静默退回旧随机模式。
- 经校验的计划保存为 `COHERENT_CREATIVE_GENERATION` 阶段检查点，哈希绑定上游内容、视觉策略、共用提示词、目标数量和模板版本。

### 2.2 方向分配与生成

- 保留现有事实视觉分配，再按事实兼容性和最少领取原则分配创意方向。
- 50 条目标初始生成 70 条候选；每个生成任务只接收一个方向、两个优先维度和最多两个避让套路。
- 单条调用继续一次性生成创意主线、六维和干净正文，不传完整批次方向表或六类配额。
- `ITEM_EVALUATE` 与 `ITEM_REGENERATE` 不执行整批规划。

### 2.3 六轴语义分类与簇感知 MMR

- 评估结果内部增加叙事、场景、人物关系、产品动作、镜头和情绪六轴语义分类。
- 分类值只能来自本批动态词表或 `OTHER`；方向未完全实现仅作软提醒。
- 最终总分仍为 `70% 单条质量 + 30% 相对新颖度`；新颖度内部使用 `70% 干净正文向量 + 30% 六轴语义簇`。
- 普通相似与簇集中只影响排序，不能阻断精确数量。

### 2.4 定向补充

- 正文向量近重复超标，或最大场景族/产品动作族超过 40% 且存在兼容替代方向时，触发一次 `DIVERSITY` 补充。
- 补充最多 10 条，总候选不超过 80 条，并明确接收过多簇、缺少方向和已有避重信息。
- 补充结果重新参加同一评估和选择流程。

## 3. 契约与兼容

- 当前 Prompt 批次结果、Prompt 条目、HTTP 路径、Prisma Schema、WorkingArtifact 提交边界和八阶段图保持不变。
- 当前选择策略直接使用正文向量与业务语义簇联合 MMR；旧 Run 和旧分片只按保存结果读取，不再维护另一套运行时代码分支。
- API 必须在阶段更新时保留已验证检查点，并允许同一 Run 在租约恢复后复用；不同 Run、不同输入哈希和旧 attempt token 均不得覆盖或复用。
- 节点详情只展示方向数量、优先维度分布、前五场景/动作簇、选择前后集中度和补充原因，不展示事实 ID、方向全文、模型名、原始响应、向量或内部签名。

## 4. 测试与真实验收

自动测试覆盖方向引用与分配、70 条候选、轻量单条简报、检查点恢复、动态语义分类、70/30 权重、40% 补充触发、精确数量、人工操作、历史兼容和 WorkingArtifact 边界。执行 Worker pytest/mypy/Ruff、Contracts/API/Web 测试、类型检查、生产构建及 `git diff --check`。

真实基线为当前广式腊肠 50 条、15 秒批次：初始 60 条中厨房 31、切制 32；最终 50 条中厨房 29、切制 27；五项加权平均质量 94.35。

用户授权五次改造后真实付费验收，全部经浏览器、API、Outbox/RabbitMQ、真实 Ark Worker、持久化和页面展示完整链路。发生至少一次真实 Ark 调用即计一次，失败批次也占额度；不调用 Seedance、不点击完成校验。

平衡优化验收目标：

- 成功批次严格 50 条，冻结版本至少有 3 次完整成功批次。
- 五轮中位数厨房不超过 21/50、切制不超过 19/50；冻结批次分别不超过 23/50 和 21/50。
- 初始 70 条候选五轮中位数厨房不超过 26、切制不超过 27。
- 每轮至少 4 个有效场景族、5 个动作族、4 个叙事族。
- 综合质量不低于 93.35；完全重复、产品无关、事实编造、抽象事实视觉证明、食品逻辑错误和多种完整做法塞入一条均为 0；长动作链不超过 1 条。

完整结果保存于被 Git 忽略的 `.tmp/effect-prompt-diversity-e2e/`。仓库最终只提交脱敏统计、必要短证据和安全截图。

## 5. 实施结果

### 5.1 已完成实现

- `BATCH_GENERATE` 已增加批次级创意方向规划，当前默认产出 8 个经校验方向；每个方向包含两个优先变化维度、六轴语义族、兼容事实和避让套路。
- 50 条目标的首轮候选已提高到 70 条；单条任务只接收所属方向和本 slot 的局部事实别名，不接收完整方向表或其他 slot 的真实事实引用。
- Worker 会检查本条创意主线、六维与正文是否逐字借用了未分配的其他已确认事实；长度足以判断的跨 slot 事实会使该候选失效，短通用词不误报。
- 评估结果已增加六轴业务语义分类；缺失或部分分类只能由 Worker 依据本条六维/正文与动态词表确定性补齐，不能改写评分、事实证据或硬问题。
- 当前选择策略保持 `70%` 质量与 `30%` 新颖度；新颖度内部使用 `70%` 正文向量与 `30%` 业务语义簇。
- 场景族或产品动作族超过 40% 且存在兼容替代方向时，可触发一次最多 10 条的多样性补充；普通簇集中仍只软降权，不阻断精确数量。
- 数量补充和多样性补充共用批次级候选预算，总数硬性不超过 `ceil(目标数 × 1.6)`；50 条任务最多 80 条候选。预算耗尽后仍不足时保存 `NEEDS_REVIEW` 短批次，不生成第 81 条。
- API 已保留同一 Run 的方向检查点，节点详情可安全展示方向数量、优先维度分布、场景/动作/叙事分布、选择前后最大簇占比与补充原因。
- Worker 结果模型已前移校验共用提示词、禁用元素及内容哈希，避免跨层不一致到最终保存时才暴露。

### 5.2 自动测试结果

- Prompt Worker：198 项 pytest 通过，1 项显式付费集成测试跳过；mypy 与 Ruff 通过。新增测试已锁定 50 条最多 80 个候选、跨 slot 事实不得串用，以及 `ITEM_EVALUATE` / `ITEM_REGENERATE` 不调用批次方向规划。
- Contracts：3 个测试文件、17 项通过；类型检查通过。
- API：31 个测试文件、299 项通过；类型检查和生产构建通过。
- Web：29 个测试文件、160 项通过；类型检查和生产构建通过。
- 浏览器只读联调确认：运行进度可刷新恢复，详情显示 8 个方向、70 条候选目标、已完成分片、优先维度分布和最多 3 条真实样例；浏览器控制台未发现 warning/error。

### 5.3 五次真实付费验收结果

五次额度均发生真实 Ark 调用，因此已全部计入预算；没有调用 Seedance，也没有点击“完成校验”。五次均未成功持久化新的 50 条批次：

1. 创意方向输出达到长度限制而截断。
2. 创意生成完成，但部分评估结果缺少语义分类结构。
3. 创意生成严格结构化响应异常。
4. 创意生成严格结构化响应再次异常。
5. 生成、评估、向量择优均完成并在 Worker 内选满 50 条，但 API 在结果保存时拒绝完成请求。

针对前四类问题已经实施方向输入收缩、方向输出预算调整、规划超时独立化、slot 局部事实别名、语义分类确定性补全及批量坏分片隔离。第五轮失败后，用同一失败任务保存的 73 条合格候选重建当前结果：逐条均通过当前 API 校验，重建批次也能通过，说明当前代码未复现数据结构错误，更可能是当时 API 与 Worker 热更新内容不一致。为防止类似问题，Worker 已补充与 API 一致的共用提示词和哈希校验。

由于计划内五轮均没有形成可在页面查看、分页和导出的新 50 条结果，本轮不能比较厨房/切制占比、语义簇分布和最终质量分，也不能宣称同质化已得到真实验收。验收状态保持“未通过”，不得自动追加第六次。详细记录见 [五轮真实付费验收报告](../evidence/Prompt批次语义去同质化五轮真实付费验收-2026-08-31.md)。
