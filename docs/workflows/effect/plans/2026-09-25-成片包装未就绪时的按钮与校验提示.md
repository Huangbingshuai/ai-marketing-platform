# 成片包装跑完但未全部就绪时：按钮文案与校验提示

## 范围

- 只改混剪精修页的两处界面文案与判定：
  1. 包装主按钮的文案：只要**跑过一次包装且已结束**（不论 COMPLETED / PARTIAL / FAILED / CANCELLED），就显示「重新成片包装」。
  2. 底部「完成校验」的状态提示：区分「包装进行中」「包装未全部就绪（需恢复未完成项）」「还没跑过包装」，不再一律说「请等待全部成片包装成功且未过期」。
- 不改包装是否就绪的判定（`allReady` 仍要求全部可包装工程 COMPLETED）、不改后端、不改 worker、不改包装面板内部的恢复逻辑。

## 现状问题

用户报：「跑了一遍测试1模板的智能成片包装，成功之后按钮并没有变成重新成片包装，也不能完成校验。」

实测（2026-09-25，项目 `40d1273a-e1cd-4cae-8f83-02fdaf324dc1`，模板 `0254fafe-…`「测试1」）：

```
GET /template-mix/templates/0254fafe-…/packaging-runs?workflowRunId=65f5b90c-…
→ runs 1；bcfd465d PARTIAL；items 100；completed 97；failed 3；stale 0
```

三个失败项（`effect_packaging_items`）：

| 阶段     | 错误                                           |
| -------- | ---------------------------------------------- |
| CAPTIONS | 配音缩句改变了句子身份、时间或来源，已停止本条 |
| VOICE    | 纯音乐生成失败，请重做本条音乐                 |
| VOICE    | 纯音乐生成失败，请重做本条音乐                 |

即**包装确实没全部成功**（3/100 失败），但界面没有把这件事说清楚：

- `packagingActionText(ready, status)` 只在 `ready || status === 'COMPLETED'` 时返回「重新成片包装」；本次 `status='PARTIAL'`、`ready=false` → 按钮仍是「智能成片包装」，用户以为包装根本没跑。
- 底部校验提示按 `packagingReady` 二选一：就绪 →「全部成片包装就绪」，否则 →「**请等待**全部成片包装成功且未过期」。可这次没有任何任务在跑（`completedAt` 已写、`QUEUED/RUNNING` 都没有），「等待」等不到任何东西；真正要做的是在包装面板里点「恢复未完成项」。
- 面板里的进度条 `v-if="starting || active"`，任务一结束就消失；节点层也没有失败提示（`packagingLockNotice` 只在 `packagingLocked` 时渲染，而 `packagingLocked` 来自「有 QUEUED/RUNNING 的包装任务」或「已提交的 `timeline-package:*` 产物」，PARTIAL 未校验两者都不满足）。于是用户看到进度条跑完消失，就认为「成功」。

## 根因

两处判定都只认「全部就绪 / 正在跑」，漏掉了「跑过、结束了、但没全部就绪」这个状态：

- `effect-packaging-progress.ts:201` `packagingActionText` 把「是否重新包装」绑在 `ready`（= 全部 COMPLETED）与 `COMPLETED` 上。
- `EffectTemplateMixNodePage.vue:6360-6370` 的 `:status-title` 只有「就绪 / 否则请等待」两档。

## 设计

### 1. 按钮文案（`effect-packaging-progress.ts`）

```ts
/**
 * A run that is no longer queued or running has already produced (or attempted) a package, so the
 * action is a rerun — including a partial or failed one, where running it again is the only way
 * forward. Keying this on `ready` alone left the button reading "智能成片包装" after a finished run.
 */
export function packagingActionText(ready: boolean, status: PackagingRun['status'] | null) {
  const attempted = status !== null && !['QUEUED', 'RUNNING'].includes(status);
  return ready || attempted ? '重新成片包装' : '智能成片包装';
}
```

`ready=true` 仍返回「重新成片包装」（就绪后再点也是重跑）；`null`（还没读过任务）与 `QUEUED/RUNNING` 保持「智能成片包装」。

### 2. 校验提示（`EffectTemplateMixNodePage.vue`）

把 `:status-title` 的三元嵌套提成一个 computed，按真实阻塞点分支：

```ts
/**
 * The footer has to name the real blocker. "请等待全部成片包装成功且未过期" told the user to wait for a
 * run that had already ended: after a finished-but-incomplete run there is nothing to wait for, only
 * failed items to recover from inside the packaging panel.
 */
const validateStatusTitle = computed(() => {
  if (validated.value && packagingReady.value) return '当前模板已确认';
  if (pendingCount.value) return '仍有工程待同步';
  if (!complete.value) return '请先补齐所有素材槽位';
  if (packagingReady.value) return '全部成片包装就绪';
  if (packagingRunStatus.value === null) return '请先在包装面板中为全部成片生成包装';
  return ['QUEUED', 'RUNNING'].includes(packagingRunStatus.value)
    ? '成片包装进行中，请等待完成'
    : '成片包装未全部就绪，请在包装面板中恢复未完成项';
});
```

分支顺序与原 `:status-title` 一致（`validated && ready` → `pendingCount` → `complete` → 其余），只把最后一档拆细。

### 3. 为什么不动 `allReady`

3 个工程确实失败了，`完成校验` 会把整个模板的包装一次性提交，所以仍必须等全部就绪；本次只把「为什么不能校验、接下来该做什么」讲清楚。是否允许「部分就绪也能校验」是产品决策，不在本次范围。

## 非目标

- 不改 `allReady` / `canValidate` / `complete` 的判定，校验门禁强度不变。
- 不改后端 `packagedTemplateIds` / `packagingLocked`（PARTIAL 未校验时不锁模板是既有语义）。
- 不改包装面板内部（「恢复未完成项」按钮与 `retry` 接口已存在且可用）。
- 不改 worker，不重跑那 3 个失败项（那是用户在面板里点「恢复未完成项」的动作）。
- 不在节点层新增失败条数徽标（面板内已有 `N 条失败` 与阶段明细）。

## 验收

- `packagingActionText(false, 'PARTIAL' | 'FAILED' | 'CANCELLED' | 'COMPLETED')` 均为「重新成片包装」；`(false, 'RUNNING' | 'QUEUED' | null)` 仍为「智能成片包装」。
- 包装结束但未全部就绪时，底部提示为「成片包装未全部就绪，请在包装面板中恢复未完成项」；进行中为「成片包装进行中，请等待完成」；未跑过为「请先在包装面板中为全部成片生成包装」。
- 全部就绪时仍显示「全部成片包装就绪」，已校验时仍显示「当前模板已确认」。
- 相关单测与类型检查通过（对比既有失败集合只少不多）。

## 风险

- **文案改动**：`effect-packaging-progress.spec.ts` 已断言 `(false,'COMPLETED')`、`(true,null)`、`(false,'RUNNING')` 三例，本次改动全部保持；只新增 PARTIAL/FAILED/CANCELLED 与 `(false,null)` 的断言。
- **并行会话**：`EffectTemplateMixNodePage.vue` 与 `effect-packaging-progress.ts` 近期被多个会话改动，落地前需重新读文件。
- **本机 CRLF**：`?raw` 源码断言不归一化换行，多行断言在本机可能假红。
