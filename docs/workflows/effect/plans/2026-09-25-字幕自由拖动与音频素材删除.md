# 字幕自由拖动与音频素材删除（第四轮）

承接 `2026-09-25-时间轴音乐落轨与字幕拖动修复.md`。上一轮把「字幕纵向拖到边框得独立行」「挡板改按桶」写进了 `apps/web`，本轮修的是实测仍然不成立的两条：

1. 「字幕素材还是有问题，无法自由拖动，甚至原本的字幕素材拖动的时候碰到别的素材出现的竖形辅助线也没了，就把字幕素材也当成视频素材处理啊，交互都是一样的」
2. 「我发现点击素材按删除快捷键的时候又删除不了素材了」——经确认删不掉的是**音频素材**，且**没有弹出任何错误提示**

产品口径（本轮确认）：

- 字幕横向拖动**放开重叠，按轨道判定**：同一条轨道内不许重叠，不同轨道之间允许重叠。两条同时可见的字幕在画面上文字可能压在一起，这是接受的代价。
- 字幕交互**与视频素材一致**：自由拖动、碰到别的素材出现竖向辅助线、自动新增轨道并跳转视图。

## 一、字幕横向拖不动：挡板退化成「零行程」

**根因**：`captionBounds`（`EffectTemplateMixTimeline.vue:2168`）按**派生行**（`captionLaneById`）取左右邻居：

```ts
const lane = captionLaneById.value.get(caption.id) ?? 0;
const rows = timelineCaptions.value
  .filter((row) => (captionLaneById.value.get(row.id) ?? 0) === lane)
  .sort((left, right) => left.start - right.start);
const index = rows.findIndex((row) => row.id === caption.id);
return {
  minStart: index > 0 ? rows[index - 1]!.end : 0,
  maxEnd: index + 1 < rows.length ? rows[index + 1]!.start : Number.POSITIVE_INFINITY,
};
```

口播字幕（无 `trackId`）全部落在 `legacy-generated` 一组、由流水线**首尾相接**排出来，所以每一条的左边界就是自己的 `start`、右边界就是自己的 `end` —— 行程恰好为 0。

**实测证据**（本地 Postgres，2026-09-25，`effect_packaging_items` 最新一条 `71027be6-97a9-4770-8f02-42650a677b32`，测试4 · 2，项目 `65458686-034c-4258-b2dd-027d4ad15132`）：

```
captionLayoutVersion = SEGMENT_V3，narrationLayoutVersion = SLOT_V1
captions 共 14 条，manual 出现次数 0，trackId 出现次数 0
  caption-fafe2dac23795f26084ec942  0.000000 → 2.208750
  caption-ad568488fe56bf7503730f3a  4.000000 → 6.387375
  caption-1be80af412bfdaf7b15a8b16  6.387375 → 8.766333   ← 上一条的 end == 这一条的 start
  caption-2183e9e90838e91503c6b262  8.766333 → 10.979083
  …（其余同形）
```

每一条的 `minStart`/`maxEnd` 都等于自身，读起来就是「直接被前面的字幕卡住」。

**修**：删掉 `captionBounds`，`captionDragTarget` 直接给 `minStart: 0` / `maxEnd: Number.POSITIVE_INFINITY`。字幕和视频片段一样自由平移。

## 二、竖向辅助线消失：为字幕写的例外分支

**根因**：MOVE 分支里对字幕刻意关掉了磁吸（`EffectTemplateMixTimeline.vue:2530-2536`）：

```ts
if (drag.id.startsWith('caption:')) {
  drag.currentStart = requested;
  snapGuideTime.value = null;   // ← 竖线永远不会出现
} else { …snapDraggedBlock… }
```

上一轮的取舍是「字幕按口播时间定位，磁吸会把小修正吸到不相关的边上」。用户已推翻这个取舍。

**修**：删掉这个例外，字幕走和音频/视频完全相同的 `snapDraggedBlock`。帧对齐（`quantizeToFrame`）本来就已经在 `delta` 上做过了，保存的边界仍然合法。

## 三、纵向落行不生效：行是从轨道推出来的，且 `trackId` 被服务端丢掉

**根因 A（前端）**：`rowMove = !isCaption && audio.initialRows[audio.id] !== undefined`（`EffectTemplateMixTimeline.vue:2683`）——字幕被排除在「按行移动」之外，所以离开边框松手就是一次纯时间移动，纵向什么都不会发生。

**根因 B（跨层，本轮新发现）**：字幕的「行」是从 `trackId` 推出来的（`assignEffectTemplateMixCaptionLanes`，`effect-template-mix-state.ts:409`），而**服务端根本不允许非手动字幕带 `trackId`**：

- 校验：`effect-packaging.domain.ts:524-525` `c.trackId !== undefined && (!manual || …)` → `fail()`
- 写入：`effect-packaging.service.ts:582` `const resolvedTrackId = previous?.trackId ?? (manual === true ? trackId : undefined);`

所以 `splitCaptionTrack` 对一条口播字幕写的 `trackId` 在 `updateAudio` 里被**静默丢弃**：保存成功、时间改了、轨道没变、行也没变。

**实测证据**：上表 12 条最近 checkpoint 里 `trackId` 出现次数**全部为 0**，`manual` 也全部为 0 —— 即历史上从没有任何一条字幕成功获得过独立轨道。上一轮文档里「字幕获得独立一行（`trackId` 变化）」的验收项之所以看起来成立，是因为它只做了源码文本断言、浏览器手测未执行（该文「未做」已自认）。

**修**：

- 契约/校验：`trackId` 是编辑者的排版几何，和 `start`/`end` 同类，不再限定手动字幕。`effect-packaging.domain.ts` 的 `trackId` 只校验形状；`effect-packaging.service.ts` 改为 `previous?.trackId ?? (typeof trackId === 'string' && trackId ? trackId : undefined)`。
- 前端 `splitCaptionTrack`（`EffectTemplateMixNodePage.vue:3925`）不变 —— 它本来就对两种字幕都写 `trackId`，现在才会真的生效。
- Timeline 松手：字幕也参与 `rowMove`；圆整后的行和起始行不同 → `splitCaptionTrack`。加上原来的「边框放手」和本轮新增的「横向落到同轨邻居身上」共三条路都汇到同一个 `emit('splitCaptionTrack', id, start)`。

## 四、横向落到同轨邻居上：给它一条自己的轨道

同一条轨道内不许重叠（服务端与渲染端都拒绝），不同轨道允许。所以字幕自由平移后**落在同轨邻居身上**时，编辑器给它铸一条新轨道 —— 这正是视频片段「落在已占用的行上就往上找一条空行」的对应物，而字幕的行是从轨道推出来的，所以「换一条行」就是「换一个 `trackId`」。

```ts
const captionTrackKeyOf = (caption) =>
  caption.trackId
    ? `track:${caption.trackId}`
    : caption.manual === true
      ? `manual:${caption.id}`
      : 'legacy-generated';
```

这个键与 `assignEffectTemplateMixCaptionLanes` 的分组键**逐字相同**，也是本轮服务端/渲染端重叠判定的单位。

## 五、重叠校验改按轨道（契约之外的跨层改动）

**根因**：`effect-packaging.domain.ts` 与 `final_output.py` 都用一个**全局串行游标**判重叠 —— 服务端是 `let previousEnd = 0`，渲染端是 `previous = 0.0`，逐条要求 `previous <= start`。这条游标比轨道**粗得多**：字幕是按 `start` 排序后逐条比的，所以**任何**两条时间上重叠的字幕都会被拒，哪怕它们画在不同的行上、本来就该同时在画面里。这也是「字幕一横向拖动就报错」的直接来源。

**修**：两边同时把游标换成上面那个分组键（`track:<trackId>` / `manual:<id>` / `legacy-generated`），**每组一个游标**。

```ts
const track = c.trackId ? `track:${c.trackId}` : manual ? `manual:${c.id}` : 'legacy-generated';
if ((edited || segmentedCaptions) && c.start < (previousEnd.get(track) ?? 0) - 0.001) fail();
previousEnd.set(track, Math.max(previousEnd.get(track) ?? 0, c.end));
```

```python
group = (f"track:{row['trackId']}" if row.get('trackId')
         else f"manual:{row['id']}" if row.get('manual') is True else 'legacy-generated')
if not (math.isfinite(start) and math.isfinite(end)
        and previous.get(group, 0.0) <= start < end <= duration + .001):
    raise PackagingError('字幕越界或重叠')
```

对测试4 这类**全口播、全无 trackId** 的工程，`legacy-generated` 一组包住全部 14 条 → 与改动前**逐字等价**；对给了独立轨道的字幕，才从「没有挡板」变成「按轨道挡板」，与两端一致。

## 六、删除快捷键删不掉音频素材

**根因**：`deleteSelectedTimelineItem`（`EffectTemplateMixNodePage.vue:4081`）只处理四种东西 —— 选中的字幕、`detached:*` 分离原声、选中的转场、以及**选中的视频槽位**。`voice:*` / `capvoice:*` / `music` 这三种 checkpoint 拥有的音频片段**一条分支都没有**，于是整段静默落到最后的视频槽位分支：要么什么都不删（槽位没选中），要么删掉一个**不相干的视频槽位**。这与「没有任何错误提示」完全吻合。

**实测证据**：同一条 checkpoint 里 `voices` 6 条、`captionVoices` 1 条、`music` 存在；`effect_packaging_items` 里没有任何 `detachedAudios` 相关的删除记录（测试4 未分离过原声），也就是说用户点到的音频片段只可能是这三类之一。

**修（按可删性分三类）**：

| 片段                   | 处理                          | 原因                                                                                                                                                                                |
| ---------------------- | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `detached:<id>`        | 删（既有）                    | 变体自己的分离原声                                                                                                                                                                  |
| `capvoice:<captionId>` | **删**（本轮新增）            | 字幕口播由编辑器生成、只挂在字幕上，worker 已经是 `cp.get('captionVoices') or {}`                                                                                                   |
| `music`                | **删**（本轮新增，含 worker） | 纯音乐是一条独立文件，没有别的结构依赖它                                                                                                                                            |
| `voice:<lineId>`       | **明确提示，不删**            | 口播与脚本行强绑定：服务端要求每条 voice 有对应脚本行、每个脚本行有字幕、`ready` 时每个非叠加片段一行、每条就绪脚本行有字幕分段。删一条会连带整条脚本、字幕与成片结构，不是 UI 取舍 |

**关键改动**：

- 契约 `UpdatePackagingAudioRequest` 加 `removedCaptionVoices?: string[]` 与 `removeMusic?: boolean`。
- `effect-packaging.service.ts` 的 `updateAudio`：按这两个字段从 `next.captionVoices` 删键、`delete next.music`（`next = {...old}`，不删就等于没删）。
- worker `final_output.py`：`music` 从 `cp['music']` 改为可缺省 —— 校验/输入/滤镜段整体包进 `if music:`，`amix` 的输入数从 `2 + …` 改为 `1 + (1 if music else 0) + …`，文件集合那行的 `snapshot['packaging']['music']['fileObjectId']` 改为条件式；`effect-final-output.service.ts:327` 的 `cp.music!` 改为 `cp.music?.`。`packaging.py` 本来就是 `cp.get('music')`，不用改。
- 前端 `deleteSelectedTimelineItem`：**音频选中优先** —— 只要 `selectedAudioClipIds` 非空就只走音频分支并 `return`，不再落到视频槽位；`addMusicAssetToTimeline` / `pasteTimelineAudioMaterial` / 分离原声这三处直接赋值 `selectedAudioClipIds` 的地方同时清空 `selectedCaptionIds`，避免陈旧的选字幕把这次删除截走。

## 非目标

- **不允许同一条轨道内的两条字幕重叠**：这是服务端校验和渲染端硬性拒绝的不变量。落到同轨邻居身上时由编辑器铸新轨道解决，而不是放开。
- **不放开 `voice:*`（口播）删除**：见上表。行静音（`audioRowMuted`）是预览态，不是持久替代。
- **不给字幕加「合并回原轨道」的手势**：铸出去就留着，和视频片段往上找空行后不会自动回退一致。
- 不动 `packaging_media.py`、`packaging.py`、转场、叠加层。

## 风险与边界

- **字幕骑到别的轨道上**：铸新轨道后字幕的派生行由 `assignEffectTemplateMixCaptionLanes` 重新排（`trackId` 组排在最前，落在字幕区顶部），所以它**不一定落在放手那一行**，视图会跳到它真正落到的行（`scrollToCaption`）。这与「边框放手」既有语义一致。
- **两条不同轨道的字幕同时在画面里会压字**：已确认接受。它们的框位由 `captionBoxes` 决定，用户可以把其中一条挪开。
- **`music` 删掉后成片没有 BGM**：`amix` 少一路输入、时长仍由画面决定，`-shortest`/`-t duration` 不变，所以成片长度不受影响。
- **多选字幕整体拖动落到同轨邻居上会产生多步撤销**：`onWindowPointerUp` 的成组分支里，能自由平移的成员发一次 `moveAudioClips`，撞上同轨邻居的成员**各发一次** `splitCaptionTrack`（每次都是一次 `rememberTimelineEdit`），所以「撤销一步」只回退其中一条。单选（绝大多数情况）只有一步。要收敛成一步需要把 `splitCaptionTrack` 改成批量接口，本轮不做。
- **与并行会话同文件**：`EffectTemplateMixTimeline.vue` / `EffectTemplateMixNodePage.vue` / `packages/contracts` / API / worker 都有另一会话的未提交改动，本轮改动**全部是追加式或就地小改**。

## 验收

1. 拖动一条口播字幕**左右**：能越过同轨邻居；碰到邻居松手 → 该字幕获得独立轨道（`trackId` 变化），视图跳过去；保存后重新加载，轨道还在。
2. 拖动字幕时指针靠近别的素材边缘 → **出现竖向蓝色辅助线**（与视频/音频一致）。
3. 拖动字幕**上下**到别的行 → 幽灵跟手；松手在该行 → 获得独立轨道并跳转。
4. 拖动字幕到边框 → 仍是「新增独立轨道」。
5. 删除：选中一条**纯音乐** → Delete → 音乐片段消失，保存成功，成片重新渲染不含 BGM。
6. 删除：选中一条**字幕口播** → Delete → 该片段消失，字幕仍在。
7. 删除：选中一条**口播** → Delete → 明确提示「口播由脚本行生成，不能删除」，且**不会**误删视频槽位。
8. 删除：选中**分离原声** → Delete → 照旧删除。
9. 回归：拖视频素材到槽位仍是替换；不碰边框时音乐拖入仍是落到那一行；两个模板槽位手动拖成重叠仍被「槽位口播边界冲突」拦下。

### 3. 渲染端按轨道判重叠是逐字对齐的

对测试4 这类**全口播、全无 `trackId`** 的工程，`legacy-generated` 一组包住全部 14 条字幕 → 与改动前**逐字等价**。两侧的既有不变量用例都原样通过：`rejects captions that overlap after independent movement`（API）与 `test_overlap_is_rejected_without_lane_escape`（worker）。
