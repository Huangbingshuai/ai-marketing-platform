# 素材拖入轨道边框新增轨道

## 范围

- 从**素材库**拖一个视频素材进入时间轴时，若指针推到**某条视频行或字幕行的上/下边框**，该边框出现一条**横向蓝色辅助线**（视觉照抄既有的竖向磁吸线 `.snap-guide`）。
- 在辅助线上放手：在该边框处**新增一条视频轨道**（边框下方的行整体下移一行），把拖动的素材放上去，并把视图**自动滚动**到新轨道与新素材。
- 新素材**不受模板六槽位约束**：六槽位只是给用户的提示，素材可以落在轨道的任意位置、任意行。
- **现有素材的时间与行内容一个都不变**：新素材就落在放手的时间点，允许与现有素材在时间上重叠（渲染按行遮挡，上层盖住下层）。
- 新轨道上的素材**只做画面叠加**：不生成口播、不生成字幕，因此下面素材的**口播与字幕完全不受影响**，音频不会两条同时在说。

## 现状问题

- 时间轴的视频轨是**槽位驱动**的：`variant.slots` 是模板槽位的深拷贝，六槽位全部绑定后就没有位置再放素材。
- 从素材库拖入只能落到鼠标下的槽位并**替换**它的素材（`applyMaterialToSlot`），没有「新增一条轨道」的入口。
- 模板同步会**整体覆盖** `variant.slots`（`markEffectTemplateMixChanged`、`applyVariantToTemplate`），任何变体独有的片段都会被静默清掉。

## 设计

### 新片段是「叠加层片段」（`overlay: true`）

拖入的素材要成为一个「片段」才能存在。把新片段作为变体自己的额外槽位推进 `variant.slots`，下游的时间轴与渲染一行都不用改；区别是它带一个 `overlay: true` 标记，让**口播链路**把它排除：

| 链路 | 叠加层 | 原因 |
| --- | --- | --- |
| `visible_intervals`（`packaging_media.py`）按行遮挡 | 参与 | 这就是「盖住下面」 |
| `render()`（`final_output.py`）线性拼接 | 参与 | 画面与时长都要算它 |
| `packagingTimelineDuration` / `effectTemplateMixContentDuration` | 参与 | 成片长度取最远终点 |
| `packagingVisualTimeline` 视觉哈希 | **排除** | 叠加层是画面叠加层，加/删/移动它**不作废**已确认包装，字幕与音频仍可编辑；成片输出时再从当前变体把画面合并进渲染 |
| `packagingOverlayTimeline`（成片输出去重键用） | 参与 | 视觉哈希看不见它，去重键必须看见，否则加了叠加层再导出会命中旧 run |
| `narration_windows` / 口播脚本 / 配音 / 字幕 / 槽位视觉描述 | **排除** | 它没有解说，也不该占用口播预算 |

**为什么不能把叠加层从快照的 `clips` 里拿掉**：成片快照把包装快照整个展开复用 —— `effect-final-output.service.ts` 是 `timeline: { ...row.snapshot, duration, sourceTimelineHash }`，所以 `timeline.clips` 与 `packaging.clips` 是**同一个数组**。要渲染就得留着，要排除口播就得在 worker 的口播链路侧过滤。

**成片输出怎么把叠加层合回来**：`packagingClips` 与 `artifactVisitor` 从 `packagingSnapshot` 里抽成两个导出函数，成片输出对**当前变体的叠加层槽位**再调一次 `packagingClips`，把结果折进交给渲染器的 `timeline.clips`。折进去之前先丢掉快照里冻结的叠加层：用户删掉的那个不该再渲染，还在时间轴上的那个由实时结果提供 —— 两个都留会画两遍。每条的 `lane` 一律**从当前草稿重读**（`row.variant.videoLanes[clip.slotId]`）：插入叠加层会把下面的行整体下移，沿用冻结行号会把叠加层摆在它本该盖住的片段旁边。渲染 worker 只读 `clips`（`final_output.py` / `packaging_media.py` 全文没有 `variant`），所以合并到 `timeline.clips` 就够了。

`insertMaterialTrack(materialId, lane, start)` 建一个槽位形状的叠加层片段：

- `id`: `crypto.randomUUID()`；`overlay: true`；`role`: 由 `material.purpose` 映射（`HOOK→HOOK`、`PRODUCT_DISPLAY→PRODUCT`、`EFFECT→SELLING_POINT`、`END_CONVERSION→END`，兜底 `PRODUCT`）；`purpose`: `material.purpose`；`label`: `material.code`。
- `duration`: `clamp(round10(material.duration), 4, 15)`，且必须 `<= material.duration`（与模板槽位统一，不新增规则）。
- `transition`: `'硬切'`、`transitionDuration`: `0`；写 `bindings` / `bindingRevisions` / `offsets` / `bindingMetadata({ source: 'MANUAL', classificationReason: '拖入新轨道' })`，并追加 `manualSlotIds`。
- 校验（不满足只 `showNotice`，不建轨道）：素材可用、`material.duration >= 4`、同一变体内未重复使用该素材、素材有已确认 Prompt。最后一条对叠加层其实不需要（它不生成口播），但 `packagingSnapshot` 对 `clips` 里每个片段都要求 Prompt，保留它最省事且与成片契约一致。

### 时间完全不动

上一版的「边界吸附 + 涟漪插入」整个删掉：不再 `boundaries.reduce` 求吸附点，不再把 `start >= insertAt` 的槽位右移。

- 新片段 `start` = 放手处的时间（时间轴已经过 `snapTime` 的帧对齐与磁吸）。
- **只给新片段写起点**（`variant.timelineStarts ??= {}; const insertAt = Math.max(0, start);`），既有片段一条都不物化。物化会把包装确认时的那份视觉哈希重新述说一遍（`timelineStarts` 进 `packagingVisualTimeline`），而它根本不需要：`packagingTimelineClips` 对没有显式起点的槽位用顺序 cursor 兜底，而新片段**追加在 `variant.slots` 末尾**，cursor 只会排到它后面的位置，既有布局不会被推走。

### 行插入

复用已有的「插入行并把占用者下移」原语（`moveTimelineClips` 的 `insertLaneAt` 分支）：

- 所有已绑定的、`lane >= 插入行` 的槽位 `lane += 1`；新片段 `lane = 插入行`。
- 之后调 `normalizeVariantVideoLanes` 压缩行号，`videoLaneCount` 自然 +1。
- 相对行序不变 → `clearDetachedTransitions` 的同轨相邻判断仍成立，既有叠化不会被误清（新片段追加在 `variant.slots` 末尾且是硬切，循环里被 `continue` 跳过）。

### 口播链路排除叠加层

**契约 `packages/contracts/src/effect-template-mix.ts`**

- `EffectTemplateMixSlot` 加 `overlay?: boolean`，注释写明「只有变体自有的叠加层片段会置位，模板永远没有」。
- `syncEffectTemplateMixVariantSlots` 与 `applyVariantToTemplate` 的保留/过滤逻辑沿用上一版，不改。

**契约 `packages/contracts/src/effect-template-mix-packaging.ts`**

- `packagingSlotBoundaryError`：时长 4–15、编号唯一仍对**所有**行生效；「槽位口播边界冲突」只对 `slot.overlay !== true` 的行生效 —— 模板槽位之间**仍然不许重叠**（既有不变量原样保留）。
- `PackagingClip` 加 `overlay?: boolean`。
- `packagingTimelineClips` / `packagingTimelineDuration` 不改。
- `packagingVisualTimeline`：过滤掉叠加层槽位（连同它们的 `bindings` / `bindingRevisions` / `offsets` / `timelineStarts` 条目），剩下的**口播片段之间永不重叠**，所以能改变画面的只剩它们的**相对行序**。于是行号按**序压缩**比较（distinct lane 升序 → rank，rank 0 过滤掉）：叠加层插入会把所有口播行整体下移一格，那是同一幅画面，不该改哈希；真正的换序（谁在上谁在下）才改。
- 新增 `packagingOverlayTimeline(variant)`：列出叠加层的 `binding` / `bindingRevision` / `offset` / `start` / `lane` / `duration` / 转场，供成片输出去重键使用。

**API `apps/api/src/workflows/effect/template-mix/effect-packaging.domain.ts`**

- `packagingSnapshot` 的 clip 构造加 `overlay: slot.overlay === true`。
- 脚本校验 `slots.size !== snapshot.clips.filter((c) => !c.overlay).length`，与**非叠加层**片段数比较。
- 其余校验（`slotVision` / `timings` / `narrationMetrics` / `voiceFitAttempts`）都是「checkpoint 的 key 必须指向已知片段」的单向检查，worker 少写几条不会失败，不用改。

**Worker `workers/effect-template-mix/src/effect_template_mix/packaging.py`**

- 新增 helper `narrated_clips(snapshot)`，返回 `[clip for clip in snapshot['clips'] if not clip.get('overlay')]`。
- 把 `snapshot['clips']` 换成 `narrated_clips(snapshot)` 的 7 处：`narration_windows`、`script_structure_issues`、脚本规划上下文的 `'shots'`、部分重做的 `missing_slots`（`partial` 随之安全）、`slot_vision` 的遍历与收尾两处。
- `packaging_media.visible_intervals`、`final_output.render`、`captions_ass` **一行不改**。

### 时间轴交互（`EffectTemplateMixTimeline.vue`）

1. **边框命中**：`onMaterialDragOver` 里除现有 `materialDropSlotId` 外再算 `trackInsertTarget` —— 视频行边框 = `VIDEO_CLIP_INSET - 4 + lane * VIDEO_LANE_PITCH`（相邻两条片段之间 8px 空隙的中心），遍历 `0..videoLaneCount`；字幕轨取上下边框并一律映射到视频行 0；`clientY` 与某条边框相差 `<= TRACK_INSERT_THRESHOLD (6px)` 且最近的一条命中。命中时清空 `materialDropSlotId`，避免两种反馈打架。
2. **辅助线**：`trackInsertGuideTop` computed + `.track-insert-guide`（`.snap-guide` 的横版镜像：`height: 1px; left: 0; right: 0; background: #2563eb; box-shadow: 0 0 0 1px #bfdbfe; z-index: 17; pointer-events: none`）。
3. **放手**：`onMaterialDrop` 里命中边框 → `emit('insertMaterialTrack', materialId, lane, start)`，否则维持原来的 `assignMaterial`。
4. **字幕轨**：新增 `onCaptionTrackDragOver`，只在边框上接受拖入。
5. **自动跳转**：`defineExpose` 新增 `scrollToLane(lane, time)`，`nextTick` 后设 `scrollTop`，表头列由 `syncTrackScroll` 镜像。
6. 触屏指针拖拽路径本期不做边框命中，只覆盖鼠标 HTML5 拖拽。

### 边框目标分两种，按拖动内容过滤（第二轮）

`TrackInsertTarget` 是个带 `kind` 判别字段的联合：`{ kind: 'VIDEO'; lane; top }` 或 `{ kind: 'AUDIO'; row; top }`，`trackInsertTargetFrom(clientY, kinds)` 只枚举 `kinds` 里那一种。视频拖拽传 `VIDEO_INSERT_KINDS`，音乐拖拽传 `AUDIO_INSERT_KINDS` —— **这就是「音乐素材始终只能在视频轨道下面」的结构性保证**：视频拖拽根本看不见音频行的边框，反过来也一样。

- **拖动已有片段**（`updateDragTarget`）：与素材库拖入走同一套边框命中，但**只有单选时**才给（`drag.selectedSlotIds.length === 1`）—— 一组片段是整体平移的，没有「给整组开哪一行」的答案。命中时把 `drag.insertLane` 记下来，`onWindowPointerUp` 随 `moveClip` 一起 emit。
- **音频行边框**：每行贡献 `bounds.top`（该行）与 `bounds.bottom`（下一行，最后一行没有下边缘的顶边，所以由底边开新行）。
- **`insertLane` 必须显式传**：`nextLane` 一个数分不清「落在某一行里」和「落在边框上要新开一行」，所以 `moveTimelineClips` 用 `insertLane !== undefined || nextLane < currentLane` 决定 `forceInsertLane` —— 边框落点**不找空行**，它两边的行整体下移。
- **音乐落边框**（`addMusicAssetToTimeline` 的 `insertRow` 分支）：先把所有可见音频片段的行号**写实**（行号是稀疏存的、按 kind 兜底，不写实就没法整体移位），再把 `row >= insertRow` 的片段 `+1`，新轨道占 `insertRow`，最后 `normalizeVariantAudioLanes` 压缩。没有 `insertRow` 时维持原语义：落到放手那一行。

**预览无需改动**：`previewSlot` 本来就按 `lane asc, start desc` 排序取第一条，与 `visible_intervals` 一致，叠加层作为最上层自然胜出；`previewCaption` / `currentVoiceEntry` 因为叠加层没有口播与字幕，行为不变。

### 模板同步保留非模板槽位

两处整体替换改成「重同步模板槽位、保留非模板槽位」：

- 新增共享 helper `syncEffectTemplateMixVariantSlots(templateSlots, variantSlots)`（`packages/contracts/src/effect-template-mix.ts`）：按模板槽位 id 集合，返回 `模板槽位（深拷贝）+ 变体独有的额外槽位`。绑定、行号、起点都以槽位 id 为键，天然跟随。
- `markEffectTemplateMixChanged`（`effect-template-mix-state.ts`）与 `applyVariantToTemplate`（`effect-template-mix.domain.ts`）改用它。
- `applyVariantToTemplate` 另需**反向过滤**：只把源变体里属于模板的槽位提升为模板槽位，避免叠加层泄漏进 `workspace.template.slots` —— 那会破坏 AI 智能填充「正好六槽位且角色不重复」的门槛。

### 卸载叠加层

`removeMaterialFromSlot` 现在只删绑定、留下空槽。对**叠加层**改成整条移除：从 `variant.slots` 删掉该槽位并清掉 `videoLanes` / `timelineStarts` / `bindingMetadata`，再 `normalizeVariantVideoLanes`。否则一次拖入会永久留下一个空槽，挡住成片（`成片存在空槽、失效素材或越界截取`）。模板槽位保持既有「留空槽」语义不变。

## 非目标

- 不改 Prisma schema（草稿是不透明 JSON，`draftOf` 不禁止额外键，和 `videoLanes` 同一条路）、不改 `packaging_media.py` / `final_output.py` / `captions_ass`。
- 不放开模板槽位之间的重叠不变量：用户手动把两个模板槽位拖成重叠仍会被包装预检拦下。
- 触屏指针拖拽路径本期不做边框命中，只覆盖鼠标 HTML5 拖拽。

## 风险与边界

- **完全遮挡**：叠加层若把某个模板槽位整段盖住，那段画面全被遮住，但**该槽位的口播与字幕照常播放**（这是「画面叠加、声音不打架」的既定取舍）。视觉描述不受影响 —— `slot_vision` 是从素材自身抽帧，不依赖可见性。
- **时长仍限 4–15 秒**：与模板槽位统一，避免新增规则；`slotsValid` 上限 30 也照旧。
- **叠加层与模板槽位之间不再有重叠保护**：用户可以把叠加层拖到任意位置盖住任何东西。
- **叠加层改动不会让在途渲染失败**：渲染完成时的 `画面草稿已改变` 校验用的是 `sourceTimelineHash`，而它看不见叠加层。渲染跑的过程中挪动叠加层，成品仍是导出那一刻的画面位置 —— 这是「叠加层不作废包装」的必然代价，换来的是字幕与音频随时可编辑。
- 撤销覆盖：`captureTimelineSnapshot` 是整份变体 JSON 克隆，叠加层自动进撤销快照。

## 验收

- 从素材库拖素材到视频轨 → 鼠标移到某条行的上/下边框，出现一条横向蓝色辅助线；移开边框辅助线消失、槽位高亮恢复。
- 在边框上放手 → 新增一条视频轨道，素材落在该轨道、位于放手的时间点；**下面素材的起点与行内容一个都没变**；视图**只上下滚动**跳到新轨道，**水平位置保持在放手处**。
- 松手后查草稿：`variant.slots` 多一个 `overlay: true` 的非模板槽位，`workspace.template.slots` 仍是六个；既有槽位的 `timelineStarts` 与改动前逐条相等。
- 改一个模板槽位时长并保存 → 叠加层仍在。
- 触发包装 → 快照 `clips` 里能看到叠加层，但脚本/配音/字幕**只覆盖六个模板槽位**；成片渲染能出叠加层的画面遮挡。
- **叠加层不作废包装**：加/移/删叠加层后，字幕与音频素材**仍可编辑**（不弹「源时间轴已改变」），且能直接导出。
- **拖动已有片段**到某条视频行边框 → 出现辅助线；放手 → 该处新增一行，该片段落到新行，其余片段的时间一个都没变。
- **音乐库拖到音频行边框** → 出现辅助线；放手 → 该处新增一条音频轨，音乐落在上面，且仍在视频轨下面。
- 卸载叠加层素材 → 该槽位整条消失，行号压缩回去，不留下挡成片的空槽。
- 撤销一步 → 叠加层消失。
- 回归：不碰边框时，拖入素材仍是原来的「替换该槽位素材」行为；两个模板槽位手动拖成重叠仍被 `槽位口播边界冲突` 拦下。
