# 效果类缓存新鲜度与并发防护

## 范围与边界

覆盖六节点现有 Redis 只读投影及前端工作区预取。PostgreSQL、业务 revision、确认产物和任务提交边界不变；不新增接口、表或任务，不触发付费生成。缓存不能保证网络零延迟，也不能冻结读取之后发生的提交；目标是保存成功后的新请求读取新版本，检测到并发提交时丢弃旧缓存结果。

## 实施

1. Run 作用域与依赖版本向量在同一条 PostgreSQL 查询快照中读取；严格检查向量完整性。
2. 缓存命中、共享等待及回源完成后复核权威版本。检测到变化最多重新读取两次，持续变化时直接重新执行数据库读取，不返回已知失效的缓存。
3. Redis 故障仍按完整作用域和版本合并同进程回源；为不同键的并发回填设上限，过载快速失败而不建立无限队列。不同请求返回独立 DTO。
4. 回填使用带随机 token 的短租约；Lua 原子检查锁归属再发布，防止过期持有者回写。已有 TTL 抖动保留。
5. 穿透：项目校验始终执行；已校验作用域中的空结果可缓存，明确的业务资源不存在可短时缓存，并仍受权威版本约束；权限、未知 Run、数据库故障不作负缓存。
6. Redis 连接超时后阻止迟到命令，按连接代次熔断，避免旧请求破坏新连接；冷却加入抖动。
7. 前端预取仅共享在途请求，写请求开始/结束使旧预取失效，避免五秒窗口复用旧工作区。

## 验收

- 单元覆盖命中与保存竞争、并发回源、失效租约、两轮 revision 变化、负缓存创建后立即失效、TTL 抖动、断连/超时/迟到连接与恢复。
- 使用随机项目和独立缓存命名空间进行真实 PostgreSQL、Redis、HTTP 集成测试；共享 Redis 不停机，故障由独立错误端口连接模拟。
- 回归六节点既有读取、作用域隔离、活动任务绕过缓存；执行相关 Web/API 测试、类型检查、格式与差异检查。测量真实项目热读，不把测试夹具结果当生产性能承诺。

## 依据

[Redis cache-aside](https://redis.io/docs/latest/develop/use-cases/cache-aside/) 用于 TTL 和回源合并；[Redis 锁模式](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/) 用于租约及 token 校验。当前 Context7 工具不可用，查阅上述官方文档。
