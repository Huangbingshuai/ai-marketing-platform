# 混剪子节点按上游头节点编号

## 范围与事实

测试6已导出纯画面成片后，首次包装实际在原输出 Run 内完成，三条工程的口播、音乐、字幕均已保存。包装中锁定源工程，包装成功后按钮可以显示“重新成片包装”；旧导出文件不自动重新渲染。本次不改变此提交与付费边界。

版本树目前按整个模板累计包装次数，导致新的智能填充分支第一次包装显示版本03。本次修正树的展示编号：同一直接上游头节点下的兄弟版本依次编号，更换上游头节点后从01开始。

## 实现与接口

- 智能填充按模板配置所属头节点累计；智能成片包装按实际生成该工程的智能填充头节点累计；成片输出按包装头节点累计，未包装输出按智能填充头节点累计。
- 继承任务和工作副本复制不算一次新生成。包装完整成功才计数，首次包装写入已有输出 Run 仍按实际包装完成时间排序。
- 新填充分支没有包装产物时，不能继承旧填充分支的包装展示编号。
- 复用现有分支树响应，不改数据库 schema、工作副本 revision、依赖、任务、文件或资产；不迁移数据、不新增付费调用。
- 历史根 Run 中已经累积的产物 revision 保留为展示基线，不能推测其丢失的历史；普通子 Run 的一次发布只在对应上游范围内编号。

## 验收

- 同一填充头节点两次包装显示01、02；新填充头节点首次包装显示01。
- 同一包装头节点多次导出递增，更换包装头节点后首次导出显示01；未包装导出同样按填充头节点隔离。
- 同一模板下兄弟填充仍依次编号，继承副本不计数；未成功任务不占号。
- 覆盖先导出后在原 Run 首次包装、不同模板隔离及历史 revision 基线。
- 执行相关 API/Web 测试、类型检查及 git diff --check，浏览器核对测试6的工程包装状态与分支树显示。
