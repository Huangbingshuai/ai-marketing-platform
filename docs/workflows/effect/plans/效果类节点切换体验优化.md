# 效果类节点切换体验优化

## 范围

- 保持现有六节点流程、草稿自动保存和 WorkingArtifact 提交边界不变。
- 缩短 Prompt、信息提炼和片段渲染节点之间的重复进入等待。
- 降低片段渲染页首屏的视频并发请求与解码压力。

## 实施

### 第一阶段：重复进入与媒体初始化

1. 节点切换期间立即展示保存/切换状态，保存失败仍停留在原节点。
2. 缓存已经访问的三个 AI 节点；节点停用时停止轮询和请求，重新激活时先展示缓存内容并后台刷新。
3. 消除 Prompt 与渲染节点首次挂载时由默认商品选择触发的重复加载。
4. 视频卡片仅在接近视口时加载元数据，完整视频仍只在用户打开预览时读取。

### 第二阶段：切换关键路径与首访预取

1. 把目标节点激活请求移出界面切换关键路径：当前草稿保存成功后立即切换界面，激活状态在后台同步；失败时提示并重试，不回滚已经完成的本地切换。
2. 当前节点稳定后空闲预取相邻 AI 节点的只读工作区数据；预取结果只作为首屏缓存，正式进入节点时仍后台校验最新 revision。
3. 为预取和正式加载复用同一请求，避免用户在预取未完成时点击节点形成并发重复请求。
4. 增加切换耗时与预取命中测试，确保项目、workflow run 和 product 变化时不会复用旧缓存。

## 验收

- 切换操作立即有可见反馈，不改变完成校验语义。
- 重复进入节点不再出现整页空白加载态。
- 非当前节点不继续轮询。
- 渲染页首屏不会同时初始化整页 20 个视频。
- 相关前端测试、类型检查、构建和浏览器回归通过。
