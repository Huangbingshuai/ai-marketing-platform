# 混剪草稿与待渲染成片实时同步

## 范围与边界

效果类模板混剪的成片工程在草稿自动保存成功后，静默同步同一项目、同一工作流 Run 的成片输出「待渲染」快照。只改写尚未导出的 `PENDING_RENDER` 条目，不自动创建付费渲染任务，不覆盖已导出文件。已导出成片继续仅显示待局部更新。未成功包装的工程不凭空创建待渲染条目；包装完成时的入队逻辑保持权威。

## 数据与接口

- 复用 `POST final-output/sync`，请求增加可选模板范围和期望混剪草稿 revision，旧请求仍可调用。响应增加同步受阻的条目，明确提示需重新包装。
- 混剪草稿保存链已有 450ms 防抖和串行写入；保存成功后异步触发同步，连续编辑只保留最新一次待同步 revision。同步成功不弹提示，不阻塞剪辑；失败仅给去重后的轻量错误状态。
- 服务端在同项目/Run 范围内读取待渲染批次，只更新确实变化的条目。每条更新在事务内锁定混剪草稿 revision；旧请求不得覆盖新草稿产生的快照。包装约束失效时保持旧快照并返回受阻原因，不伪装同步成功。
- 成片页重新进入时同时刷新成片批次和混剪预览；列表继续以 API 快照为准，已导出成片只标待更新，用户主动点击局部更新才重新渲染。

## 验收

- 连续拖动、切换模板、快速保存及重新进入成片页时，待渲染条目按最新已保存草稿显示，无手动同步按钮和成功提示。
- 只改一条工程时其他条目 ID、快照、状态不变；跨项目、跨 Run、旧 revision 请求不写入。
- 包装失效时返回「需重新包装」而非覆盖快照；已导出成片不改文件或自动重导；同步不产生付费任务。
- 覆盖 API/Contracts/Web 测试、类型检查、构建与 `git diff --check`，并在 1920、1440、窄屏检查待渲染/失败/待更新界面。
