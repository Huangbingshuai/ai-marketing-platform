# 提示词到渲染局部更新：动态合并待更新差异

## 目标与边界

待更新比较素材实际采用的提示词与最新已保存提示词，不累计编辑事件。连续修改只采用最终结果；未采用的新增再删除、修改再恢复完整原内容抵消。独立导入及用户手动删除的素材不自动补回。未知来源或不可用批次不能当成删除。

保留手动保存：提示词保存后才影响渲染；渲染局部更新结果先进入隔离草稿，用户保存后才发布到混剪。取消不改变已确认素材。只改变当前来源谱系，不改写兄弟历史分支，不自动执行混剪、包装或最终导出。

## 差异与接口

共享 Contracts 统一计算新增、重渲染、免费信息同步、删除及净差异签名。生成输入含正文、共用约束和目标时长；信息含创意主线、六维及用途。来源使用稳定 ID 与既有分支映射，不按编号、名称或正文相似度匹配。

复用 refresh、幂等回执、任务快照及采用基线；新增可选确认签名、冻结上下文和无需更新响应。差异抵消不建立编辑副本、不写 Outbox、不调用模型。确认期间范围或费用类别变化要求重新确认。各卡片、按钮、批次、画布和分支树共用差异口径，保留独立的文件、失败、产品资料变化告警。

## 冻结、回写与保存

一次确认冻结提示词、约束、来源版本、参考文件、设置及操作集合。只有新增和正文生成输入变化创建付费任务；单卡更新不处理其他差异。同批在途更新不可重叠启动。

新协议任务在提示词再次保存后仍按冻结输入完成；不自动重启或追赶。保留项目/产品/来源、工程编辑、文件可用性、任务版本、租约和 attempt token 校验。成功只推进该素材草稿的实际采用基线，失败保留旧视频和旧基线。随后重算最新差异。

允许保存已完成且可用的冻结更新，即使提示词又变化；不能将最新批次 revision 写成素材实际采用版本。部分失败保留草稿并沿用既有完整性规则，成功素材不重复生成。手动保存原位发布 render-clip 与 render-batch，随后混剪依据实际素材变化计算净差异。

## 兼容与非目标

字段可选、不新增数据库表、不迁移历史文件、不物理清理旧视频。普通整批渲染和旧协议保持原来源边界。历史来源只能可靠恢复，不用最新版本伪装基准。实施使用 develop-workflow-node 技能，保留已有未提交改动。

## 验证

- 修改/恢复、连续修改、新增/删除、修改/删除、混合变化及共用约束变化。
- 任务期间再次修改/删除/新增、部分失败、幂等、确认变化、取消、恢复、并发、ID 映射及项目隔离。
- 手动保存前不影响混剪；保存后仅实际变化联动；空批次合法、历史文件保留。
- Contracts/API/Web/Seedance Worker 测试、类型检查、构建、git diff --check 和三种宽度浏览器回归。
- 不启动付费任务、不部署、不自动提交 Git；报告实际完成的验证和限制。

## 实施与验证记录（2026-10-07）

已按 develop-workflow-node 流程实施：

- Contracts 共享内容差异比较，服务端刷新确认签名与无需更新响应；区分重渲染、免费信息同步、新增和删除，不依赖 revision 增长判断内容差异。
- 局部更新冻结来源并逐素材记录实际采用内容；执行中上游再次保存不会把最新来源伪写为已采用来源。失败保留旧结果，完整抵消的失败替换允许恢复旧视频并同步恢复批次状态。
- 保留隔离草稿与手动保存；冻结局部更新不自动提交。支持更新期间保存上游提示词，渲染保存仍校验项目、资料、文件和人工编辑冲突。
- 渲染卡片、批次与工作副本分支状态使用净差异；混剪只消费已发布视频及其实际采用信息，不因提示词单独变化误判已发布画面变化。历史采用基准仅在来源、文件与文本哈希可靠对应时只读恢复。
- 页面恢复、焦点切换和轮询刷新状态，加入响应版本及作用域保护；确认范围或费用类别变化需重新确认。
