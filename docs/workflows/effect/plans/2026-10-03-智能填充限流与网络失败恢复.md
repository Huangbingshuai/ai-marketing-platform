# 智能填充限流与网络失败恢复

## 证据与范围

紫苏梅子酱「测试5」填充任务 `e85c8a6a-ada2-4ffd-a534-5e13c224b7c7` 首次执行遇到模型 429，自动恢复后在截取阶段遇到容器 DNS 连接错误。已保存 20 条归槽和 18 条选材结果，未保存截取结果；两次任务尝试已耗尽。现有 Provider 对 429 立即失败，网络重试没有等待。

## 实施

- 智能填充归槽与截取为临时错误提供最多四次请求尝试；结构无效继续保持原两次上限，永久 HTTP 拒绝立即失败。
- 429、408、5xx 和连接/超时错误使用递增等待，所有并发请求共享等待截止时间；数字 Retry-After 有效时纳入等待（上限 60 秒）。不把 HTTP 错误响应或端点信息展示给用户。
- DNS/网络失败不再触发归槽分片，避免连接故障时递归扩大请求。容量或结构问题仍可分片。
- 最新模板真实测试发现内部 API 断连导致检查点失败，心跳停止并耗尽租约恢复次数。内部 API 连接失败提供有界退避；幂等 GET/PUT 可重试超时和 5xx，存在不确定写入结果的 POST 不重放。心跳遇临时错误继续发送，409 等永久拒绝不重试。
- 真实截取阶段确认供应商提前关闭响应（RemoteProtocolError）未被归类为临时故障，直接误报结果无效；纳入相同退避恢复，并禁止为该类故障拆分归槽批次。内部 API 同类错误仅对 GET/PUT 重放。
- 当归槽和选材已成功但第一条截取尚未保存时，正常重试也复用归槽/选材检查点；完整执行输入哈希必须一致，选择的槽位、素材和时长仍校验。不改完成或截取回调的非空校验。
- 不改变模板、六槽位、来源校验、任务租约、付费输出或成功后分支发布规则。不增加第二套任务状态或接口。
- 在没有活动任务时部署 Worker。针对该已失败任务，在事务内核对冻结模板与当前工作区、素材/Prompt revision 和内容哈希，再重新排队既有任务；保留输入及全部检查点。若核对失败则停止恢复，不覆盖用户后续修改。

实际恢复核对时，用户已将痛点槽位从 8 秒改为 10 秒，模板 editVersion 从 7 升为 8。事务拒绝恢复旧快照并回滚，原失败任务与检查点均保留。验证需从最新模板重新发起正常智能填充，不重新激活旧快照。

## 验收

覆盖 429 → DNS 失败 → 成功、永久拒绝、结构错误重试上限、持续限流的终态与并发共享等待。执行 Worker 单测和语法/类型检查、API 相关回归及 diff 检查。恢复测试5，验证任务完整成功、完整六槽位工程、待渲染队列与真实页面状态。
