# 自适应画幅回写校验修复

## 范围与原因

效果类片段渲染消费已确认的 `prompt-batch:<productId>` 和产品资料包来源快照。
供应商已完成 15 秒、480p 视频并返回实际画幅 `3:4`，但 API 将其与请求策略
`adaptive` 直接比较，导致完成回调被拒绝，视频未入库。

## 实施

- `adaptive` 表示由模型选择画幅，允许合法有限正数的实际宽高比；固定画幅仍严格校验。
- 保留现有返修画幅舍入容差、时长与分辨率校验；兼容历史模拟供应商回传 `adaptive`。
- 内部回写失败且已达到供应商成功下载阶段的生成任务，重试时仅在完整请求快照未变、
  无已采用输出且已有供应商任务 ID 时复用原任务；只排除不进入模型输入的局部更新确认标记。
  其他重生成保持原有行为。
- 保留现有事务、Outbox、批次 revision、任务版本和租约，不放宽项目/Run/来源校验。
- 仅完整成功通过文件及来源校验后按既有边界提交 `render-clip` / `render-batch`；
  不自动混剪、包装或输出，不自动提交 Git，不新建真实付费模型任务。

## 验证

- 自适应实际画幅、非法画幅、固定画幅不一致、返修容差、时长/分辨率不一致。
- 完成回调保存实际画幅，旧 attempt / version 被拒绝。
- 回写失败恢复保留供应商任务 ID；Prompt、参考图、来源版本改变或非回写失败不复用。
- 相关 API 单元测试、类型检查、生产构建与 `git diff --check`。
- 核实运行 API 使用修复代码；真实失败批次恢复不通过“全部重新渲染”重建供应商任务。
