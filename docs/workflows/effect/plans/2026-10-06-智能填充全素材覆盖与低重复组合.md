# 智能填充全素材覆盖与低重复组合

## 范围与事实

效果类模板混剪智能填充。测试3读取同项目/Run 的 20 条已确认渲染片段及其 Prompt 和六槽位模板；旧算法将跨成片重合最多两个槽位作为硬停止条件，造成仅生成三条工程，部分素材未被选中。

## 策略

1. 第一优先级覆盖所有可用且时长、归槽合法的素材。单片六素材不同、六槽位完整、人工归槽、来源 revision、截取合法及非完全重复仍是硬约束。
2. 数量由边际差异自适应决定，不把100安全上限当成数量目标，也不机械限定为最大槽位素材数。先完成素材覆盖，再扩充有价值的组合；素材只能从其固定归槽池选取，不跨槽位补位，不通过变更截取点伪造不同组合。
3. 使用固定种子的有界候选采样、覆盖骨架和欠使用素材/镜头对引导搜索，不完整枚举笛卡尔积。排序兼顾未用素材、最相近成片的可替换画面差异、新镜头对、累计重复、使用均衡和AI匹配质量。
4. 覆盖后扩充必须同时满足：与每条已有成片相比，至少一半可替换槽位且至少一半可替换画面时长发生变化；至少一半可替换槽位间的镜头对为本批次/已有工程未使用的新搭配。只有单候选的槽位不贡献新意。默认半数阈值是可测试的结构性折中，不代表画面语义质量或全局最优。覆盖阶段允许为稀缺素材适当放宽差异门槛，但不能放宽来源、归槽、时长或完整组合去重。
5. API 新批次冻结覆盖要求，漏选可用素材、无法容纳完整覆盖或确实无法满足某槽位时明确失败，不能部分成功却宣称覆盖完成。无有效模型评分、时长不合法等结构问题给出素材编号，不猜测业务语义。
6. 选片阶段只对不同素材生成一次截取任务；回写只使用已选片并有合法截取结果的素材，避免部署后历史恢复新增未截取素材。既有任务没有覆盖要求字段时只保留读取/恢复兼容。

## 接口与边界

复用 AiSnapshot、classificationResult、selectionResult、trimResult 和 Run/Outbox/attempt；新增可选批次全素材覆盖标记，旧快照默认不启用。不增加数据库表，不修改历史工程、素材、包装或导出，不新增付费任务。智能填充完整成功后沿用 mix-template/timeline-project 工作副本及既有仅画面待渲染输出提交；下游依赖仍记录实际素材 artifactId + revision。
