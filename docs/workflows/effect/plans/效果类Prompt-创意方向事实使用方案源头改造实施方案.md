# 效果类 Prompt：创意方向事实使用方案源头改造实施方案

状态：已完成

## 一、目标

当前批次创意方向只返回 `compatibleFactIds`，最少允许一个事实；后续再由 Worker 选择一个 `focusFact` 并补充其他事实。该流程容易让不同方向携带相同事实集合，也会使真正的卖点、痛点、受众和场景在创意规划后再次被重新分配。

本次从创意方向规划源头改造为：

```text
完整已确认事实与视觉策略
→ AI 为整批方向规划事实使用方案
→ 每个方向携带多个有关联的事实及其创意用法
→ 每条生成任务完整继承方向事实组合
→ AI 评估事实是否真正实现
→ 按质量、覆盖和差异化选择
```

Worker 不再为批量任务挑选单一重点事实，也不把遗漏事实随机附加到某个方向。

## 二、内部契约

创意方向内部结构调整为：

```ts
type CreativeDirectionFactApplication = {
  factId: string;
  creativeUsage: string;
};

type CreativeDirection = {
  directionId: string;
  factApplications: CreativeDirectionFactApplication[];
  creativeDirection: string;
  priorityDimensions: CreativeDimensionKey[];
  semanticProfile: CreativeSemanticProfile;
  avoidFamilies: string[];
};
```

- 当上游存在至少两个可用业务事实时，每个方向规划 2～4 个业务事实；资料本身只有一个业务事实时允许单事实方向，禁止为了数量编造事实。
- `creativeUsage` 必须说明该事实怎样进入人物、场景、需求、动作或产品表达，不能只复述事实原文。
- 商品名称、品类、规格和外观继续由 `productSnapshot` 提供真实性边界，不计入方向所需的多个业务事实。
- 历史分片可以读取，但模板哈希变化后不得作为当前方向计划复用。

生成任务不再包含 `focusFactId`。任务继承方向的完整事实组合，候选对每个声明事实返回逐字证据位置。Worker 只校验事实引用属于本任务、证据文字真实存在，不判断语义是否完整；事实语义继续由独立评估模型判断。

## 三、规划、修订与生成

### 1. 批次方向规划

方向模型一次读取完整可用事实、视觉使用策略、共用提示词和视觉风格基调，负责：

- 为每个方向形成自然的多事实关系；
- 把所有必用业务事实至少应用到一个合理方向；
- 在容量允许时让核心事实进入多个不同方向，降低最终筛选后消失的风险；
- 保持不同方向的事实关系、叙事、场景、人物、产品动作和镜头具有实质差异。

### 2. 缺失事实修订

Worker 只检查未知事实、事实数量、全局必用事实覆盖和结构完整性。首次方向计划遗漏必用事实或事实用法不完整时，第二次调用将上一版方向计划、缺失事实和安全错误原因交还模型，要求模型重新规划完整批次。Worker 不修改模型返回的事实组合。

### 3. Prompt 生成

- 批量生成任务直接继承方向 `factApplications`，不再经过 `focusFact` 调度。
- 单条操作没有批次方向时，沿用现有条目事实或从已确认事实中形成小规模兼容组合。
- 生成模型同时输出创意主线、六维、正文和每个事实的证据位置。
- 评估模型独立判断各事实为完整实现、部分实现或未实现。

## 四、边界

- 不修改八阶段工作流拓扑、公开 HTTP 路径、Prisma Schema和 Prompt 批次公开结构。
- 不修改 WorkingArtifact 提交边界；仍只有用户完成校验后才提交 `prompt-batch:{productId}`。
- 不修改视频渲染、模板混剪、信息提炼及其他工作流。
- 不增加事实集合重复率、单事实占比等新的内容硬门禁；差异化主要由方向模型源头规划，Worker只保留结构与事实来源校验。

## 五、测试

- 每个富信息方向包含 2～4 个业务事实及具体用法。
- 所有必用事实由方向模型覆盖；遗漏时第二次调用收到修订上下文，Worker不补挂事实。
- 批量任务完整继承方向事实组合，不再生成 `focusFact`。
- 候选必须为本任务声明的每个事实返回真实存在的证据位置，语义由评估模型确认。
- 方向检查点因模板变化失效，历史分片仍可解析。
- 回归精确数量、覆盖补充、向量 MMR、共用提示词、单条操作和 WorkingArtifact边界。
- 执行 Worker pytest、mypy、Ruff 与 `git diff --check`。

## 六、实际实施结果

- 创意方向契约已改为 `factApplications[]`；富信息方向必须包含 2～4 项业务事实及各自的 `creativeUsage`。
- 批量任务直接继承方向事实组合，不再生成或调度 `focusFact/allowedFacts`；历史分片仅通过读取迁移兼容。
- 方向模型必须覆盖全部可用业务事实。首轮遗漏时，第二次 AI 调用会收到旧计划、缺失事实与安全错误并重做整批方向，Worker 不修改模型事实组合。
- 候选必须完整声明任务事实并逐项返回真实存在的证据位置；Worker 只校验引用与位置，评估模型负责语义完整性。
- 数量补充与最终通过口径已统一为业务事实覆盖，商品快照字段不会误触发末端补挂；公开 `insightCoverage` 仍保留完整事实审计。
- 新增回归覆盖：多事实方向、业务事实全局覆盖、AI 整批修订、任务完整继承、历史结构迁移、证据完整性和精确数量。

真实验证：

- `uv run --frozen pytest -q`：通过（1 项需要外部条件的测试跳过）。
- `uv run --frozen mypy src`：通过。
- `uv run --frozen ruff check src tests`：通过。
- `git diff --check`：通过。
