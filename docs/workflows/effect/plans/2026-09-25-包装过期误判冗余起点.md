# 包装「已过期」误判：冗余的时间轴起点不该重述视觉哈希

日期：2026-09-25
需求原话：

> 为什么测试4成片1的音频素材已经是白色锁定了啊，修复

即：打开 `测试4成片1` 时，音频片段**一上来就是灰白压暗的**、并且**拖不动**，用户没有点过任何静音或锁定。

---

## 一、范围

| 现象                                | 本轮口径                                                                                                                                                         |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 某条成片的音频片段开箱即「白 + 锁」 | 该成片的包装被判定为 `stale`。本轮修掉**产生这个误判的那一个原因**：`variant.timelineStarts` 里被物化出来的「和顺序排布完全等值」的起点，不该改变 `visualHash`。 |

**不改**：`stale` 的语义本身（真的改过画面就该过期）、`stale` 时的只读口径（过期的 checkpoint 不能写回服务端）、`is-stale` 的压暗视觉。

## 二、现状与实测证据

### 2.1 「白 + 锁」是 `stale` 的两个后果，不是两个新 bug

`apps/web/src/workflows/effect/template-mix/EffectTemplateMixTimeline.vue`：

```css

  opacity: 0.5;

```

（`:4267-4270`，注释原文：_kept on the timeline but marked, so the stale rows read as "out of date"_）

```ts

```

（`:637-639`；`:2127` `if (props.readOnly || !audio.editable) return;` 于是拖不动、`:3460` 边缘裁剪手柄也不渲染）

`.video-clip` 的 class 里有 `is-stale`（`:3201`）但**全仓库没有 `.video-clip.is-stale` 样式** —— 所以过期时只有**音频与字幕**片段变灰白，视频片段照旧。这正是用户看到的样子：音频素材白了，画面没白。

### 2.2 本地 Postgres 实测：三条里只有第二条命中，且原因是冗余起点

`测试4成片1` = 包装项 `e2936c33-a200-4267-ab7b-4a37d08a3621`（名称 `测试4·1`），变体 `d1d73b74-1f61-4bee-8c05-405507b644b3`，项目 `65458686-…`，2026-09-24 09:16 完成。

- **第三条不成立**：快照 9 条依赖全部 `CURRENT` + `AVAILABLE`（探针逐条比对 `revision`）。
- **第二条成立**，且**只有**这一条成片成立：按 `updatedAt` 倒序取最近 8 条，只有 `e2936c33` 的 `matchesVisualHash` 为 `false`。
- 差异**只有 `timelineStarts` 一项**（`packagingVisualTimeline` 逐字段 diff）：

```
DIFF timelineStarts.b0e8c7b2-…  live 0   frozen -      ← 顺序默认起点
DIFF timelineStarts.8b55b97b-…  live 4   frozen -
DIFF timelineStarts.d688fa0d-…  live 14  frozen -
DIFF timelineStarts.f6df8c5f-…  live 24  frozen -
DIFF timelineStarts.c20d0c2b-…  live 34  frozen -
DIFF timelineStarts.4ad21ff0-…  live 42  frozen -
diffs 6     （slots / offsets / bindings / videoLanes 全部逐字节相同）
```

`live.timelineStarts` = `{…:0, …:4, …:14, …:24, …:34, …:42}`，而 `effectTemplateMixTiming(variant.slots)` 的顺序默认起点**正是** `0,4,14,24,34,42`（槽位时长 `[4,10,10,10,8,4]`，前后两版一致）。即：**画面一模一样，只是把顺序布局写成了显式数字。**

哈希三连坐实：

| 量                                    | 值（前 16 位）         |
| ------------------------------------- | ---------------------- |
| `visualHash(live)`                    | `ef0b72aad4000e6d`     |
| **`visualHash(live)` 去掉冗余起点后** | **`078d9937746baa90`** |
| `visualHash(frozen)`                  | `078d9937746baa90`     |
| 落库的 `sourceTimelineHash`           | `078d9937746baa90`     |

去掉冗余起点后 `visualHash(live) === 落库哈希`，`matchesVisualHash` 第一步即命中 → 不再 stale。

### 2.3 全库只有这一条中招

遍历 403 条变体（5 个模板）统计「显式起点数 / 与顺序默认相等的显式起点数」：

```

测试4  其余 100 条        explicit starts 0/6   （个别 1/6）

测试1/2/3 其余           explicit starts 0/6   （个别 1/6）

```

`d1d73b74` 是全库唯一「6 条全部物化且全部等值」的变体。物化由 `EffectTemplateMixNodePage.vue:3427-3439` 的裁剪路径写入（第一次非空裁剪会把**所有**槽位的起点冻结成显式值，这是有意为之：一次裁剪之后，后面的起点不该再被前面的时长连带推动）。画面等值的冗余值一旦写进 `variant`，就**永久**改写了哈希 —— 之后再没有任何代码路径会把它删掉。

### 2.4 契约文件里已经有同一个原则，只是漏了 `timelineStarts`

`packages/contracts/src/effect-template-mix-packaging.ts:392-398`：

```ts
    // Missing lane and explicit lane 0 render identically. Editor normalization
    // must not invalidate already-paid packaging or confirmed visual sources.
    videoLanes: Object.fromEntries(...),
```

`videoLanes` 按**行序排名**归一化（行号 0 被过滤、行序只比相对次序）；`timelineStarts` 却是 `keep(variant.timelineStarts)` 原样进哈希。同一个「编辑器物化不该作废已确认包装」的原则，在起点上缺了一环。

## 三、设计

### 一、`packagingVisualTimeline` 里把「与顺序布局等值」的起点丢掉

在 `packages/contracts/src/effect-template-mix-packaging.ts` 的 `packagingVisualTimeline` 内，把 `timelineStarts: keep(variant.timelineStarts)` 换成一次**与 `packagingTimelineClips` 同构的顺序游标**：

- 用 `packagingTimelineClips`（同文件 `:445-452`）**完全相同**的推进方式遍历 `variant.slots`：`start = 显式值 ?? cursor`，`cursor = start + slot.duration`。
- 只有 `显式值 !== cursor` 的项才保留；`显式值 === cursor`（顺序布局本来就会给出这个起点）视为**没有**。
- 遍历覆盖**全部** `variant.slots`（含 overlay），输出只保留非 overlay 槽位 —— 与哈希里其余字段的 `keep()` 口径一致。overlay 也占时间，跳过它会让它后面的槽位算出错误的默认起点。

于是：真移动（起点 ≠ 顺序默认）照样改哈希；只把默认值写成显式数字不再改哈希。

### 二、同时要**认旧哈希**，否则会反向作废 29 条（实测发现，必须一起做）

改哈希形态有个必然的副作用：**库里已经落着的 `sourceTimelineHash` 是用旧形态算的**。用真实数据全量对了一遍 1113 条包装项，按「哪几种形态能重算出落库哈希」分类：

```
  781 条  归一化 == 原样起点 == HEAD 形态   （压根没有显式起点，三种形态重合）
   29 条  原样起点 == HEAD 形态，但 != 归一化  ← 旧形态落库，只改 contracts 会让它们由「不过期」变「过期」
    1 条  只有归一化形态                     ← 就是 e2936c33：确认时没有起点，之后才被物化
  302 条  三种都对不上                      ← 真的改过画面（或结构变过），本来就该过期
```

所以契约层归一化之外，还要在 `matchesVisualHash` 的**兜底分支**里把旧形态也算作「同一幅画面」。这正好是既有 `videoLanes` 的先例：`packagingVisualTimeline` 把行号按排名归一化，`matchesVisualHash` 第三步再把**原始行号塞回去**重算一遍，认掉归一化之前落库的哈希（`effect-packaging.domain.ts:38`）。本轮给这个分支补上「原始起点」即可：

```ts
return (
  workflowStateHash({
    ...packagingVisualTimeline(frozen),
    timelineStarts: packagingStoredTimelineStarts(frozen), // 新增
    videoLanes: frozen.videoLanes ?? {},
  }) === hash
);
```

`packagingStoredTimelineStarts` 是 contracts 里新导出的小函数（按非 overlay 过滤后的原样起点），保证「哪些槽位算口播」这条规则只有一处。

**客户端不需要动**：`EffectTemplateMixPackaging.vue:129-137` 那处 `JSON.stringify(sourceVisualTimeline) !== signature(variant)` 的两侧都是**读的时候用当前代码现算的**（`sourceVisualTimeline` 在 `effect-packaging.service.ts:385` 由 `snapshot.variant` 现算，不是落库值），所以两边一起归一化，天然一致。

### 三、不动别的

`matchesVisualHash` 的前两步、`stale` 的三条件、`is-stale` 的压暗、只读口径全部保持原样。修好之后 `e2936c33` 的第一条件命中，`stale` 自然变 `false`，音频片段回到常态并可拖动 —— 不需要数据迁移（`stale` 是每次读取时算的）。

## 五、非目标

- 不改 `stale` 的定义、不改过期成片的只读口径（过期 checkpoint 写回服务端本来就会被服务端拒绝，见 `EffectTemplateMixNodePage.vue:1697-1702`）。
- 不改 `.audio-clip.is-stale` 的压暗值，也不给 `.video-clip` 补 `is-stale` 样式。
- 不改前端裁剪路径「物化全部起点」的行为 —— 它是有意的（一次裁剪后布局必须冻结），只是不该改变哈希。
- 不写数据迁移：`stale` 在读取时计算，契约改完立刻生效。
- 不碰 `audioLanes`（换行本来就不进哈希，见 `2026-09-24-时间轴音频轨通用化与自由换轨.md`）。

## 六、风险与边界

- **可能让一条「本该过期」的成片不再过期**：只要它和哈希的差异**仅**是冗余起点。此时画面确实与确认时逐帧一致，所以不算漏判。全量实测只影响 1 条（`e2936c33`，即本次报障的那条）。
- **认旧形态会不会把真移动吞掉**：不会。真移动的起点不等于顺序游标，归一化后仍留在哈希里，旧形态也仍带着它 —— 实测 302 条「三种形态都对不上」的照样过期，且全量对拍里**没有任何一条由「不过期」变成「过期」**（见七·1）。
- **`timelineStarts` 含 overlay 槽位的键**：输出仍按非 overlay 过滤（与 `keep()` 一致），但**游标遍历用原始 `variant.timelineStarts`**，否则 overlay 之后的槽位会算错默认起点、把真移动误判成冗余。本轮用一个用例覆盖这一点。
- **与并行会话同文件**：`packages/contracts/src/effect-template-mix-packaging.ts` 此刻正被另一会话改写（`git status` 为 `M`）。本轮只改 `timelineStarts` 一段 + 追加一个导出，不重排既有代码。
- **`docs/2026-09-24-素材拖入轨道边框新增轨道.md:48`** 记录过同一个担忧（「物化会把包装确认时的那份视觉哈希重新述说一遍」），当时的规避方式是「只给新片段写起点」；本轮把兜底补在契约层，两条路都成立。
