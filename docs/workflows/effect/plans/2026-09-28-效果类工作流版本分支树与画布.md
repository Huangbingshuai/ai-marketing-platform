# 效果类工作流版本分支树与画布

## 目标与范围

为效果类固定六节点工作流增加以资料导入为根的版本分支。只有用户明确完成校验、规范化产物内容确实变化时才分叉。画布由工作流面板的“查看版本分支树”入口打开；选择分支后恢复该分支的节点、草稿和已确认产物。混剪模板不增加底层工作流节点，但所有模板在树中的“模板 → 智能填充 → 智能成片包装”视觉层直接展开，无须筛选。首期不改其余四条工作流，也不根据现有历史记录推测旧分支。

## 已确认的现状与必须先解决的约束

- `WorkflowRun` 已有项目与工作流隔离，但没有父分支和分叉点字段；活动 Run 读取目前按创建时间倒序，不能代表显式选中的活动分支。
- `EffectImportWorkspace.projectId` 目前唯一，`EffectImportDraft` 以 `projectId + mode` 唯一；导入产品、素材与后续领域记录都绑定具体 `workflowRunId`。只新增一个子 Run，现有节点不会自动读到父 Run 的产品与素材。
- `WorkingArtifact` 是每 Run、节点、业务键唯一的“最新工作副本”，变更时会原地递增 revision。旧 revision 没有不可变快照。直接在父 Run 提交后再建子 Run 无法恢复分叉前的父分支。
- 多个确认入口在同一数据库事务内同时更新领域记录和 `WorkingArtifact`；异步任务另有启动 Run 和冻结来源。分叉必须发生在这些事务的正确边界，不能由前端根据返回值补建。
- 用户已确认允许在首次编辑或启动生成任务前建立不显示在画布上的临时子分支。它必须先获得独立的领域草稿与媒体引用，再接收写入；只有校验通过且规范化内容变化才发布到树上。无变化确认不得留下可见分支，也不能取消或误投仍在运行的任务。

因此，分支元数据和画布必须与版本化存储、领域读取和确认事务一起交付；只做可视化树不能作为可用的版本管理功能。

## 实施进度与安全门槛

- 已增加效果类已确认 `WorkingArtifact` revision 的不可变快照与文件保留关系；新提交在原事务内记录变更前后的产物、依赖和文件绑定，清理器不得删除历史 revision 仍引用的媒体。这是自动分叉的存储前置条件，不等于分支隔离已完成。
- 已将资料素材、工作副本文件和上游工作副本依赖的外键放宽为同项目引用；写入校验仍只允许当前 Run 或其可见祖先，不能引用兄弟分支或跨项目数据。子 Run 的领域记录与草稿复制、异步任务回写和确认时发布仍未接通。
- 新增 `branchPublishedAt` 可见性边界；既有子分支按原创建时间回填为已发布，今后未发布的临时分支不进入画布，也不能通过分支切换接口激活。
- 尚需在首次编辑/生成前建立并切换到隐藏子 Run，将导入产品、提炼结果、Prompt、渲染、混剪和成片的领域草稿按分叉点隔离；确认事务比较业务哈希后发布或舍弃临时分支，并固定异步任务的启动分支。未完成这些数据库级回归前，不删除混剪上游旧素材过滤和包装来源校验，也不将画布标为自动分支已生效。
- 已有分支元数据迁移、按项目读取/激活分支的接口、工作流画布入口和全屏树界面。已确认产物的列表读取按分叉节点及模板范围作父链继承，并覆盖重名产物遮蔽与项目隔离测试。
- 全屏树保留六个真实工作流节点；混剪在画布中投影为“模板 → 智能填充 → 智能成片包装”三个视觉层，不增加底层工作流节点。画布白色背景横向填满弹窗，阶段列固定在画布最左侧；矩形项目名称头节点连接所有资料导入版本，其余节点以自上而下的父子曲线和箭头连接，同一阶段的不同版本、不同模板从共同父节点分叉。模板节点只显示模板名称，不把模板配置 revision 当成树上版本；其余已确认节点按实际 revision 显示“版本01”格式，并在下方显示已确认工作副本的创建时间，缺失则明确提示。当前完整工作流路径标红，未生成阶段以虚线矩形占位。多个产物 revision 不一致时列出实际版本号，不能凭最大值伪造统一版本号。运行中的旧接口若缺 revision 或创建时间，Web 从同项目、同 Run 的已确认工作副本接口补齐；仍无事实依据则显示“版本未记录”，不伪造编号。右侧重复节点详情、顶部模板筛选及底部已选版本栏已移除；点击非当前分支版本节点直接触发切换，切换前仍保存草稿。现有工作副本没有不可变的历史 revision 创建时间，因此工作副本的首次创建时间不得被解释为旧 revision 的单独确认时间。该展示仍仅依赖实际分支和产物数据，不推断旧版本。
- 资料导入页面已区分草稿并发序号与资料包已确认 revision；没有产品名称时仍能回填资料包的确认版本。草稿编辑不再提前把下游标为锁定。
- **Prompt 确认已接入真实自动分叉，其余节点尚未接通**：有旧 Prompt 已确认产物且新内容哈希不同，完成校验事务会复制分支内导入/提炼工作区与媒体引用、保留父 Prompt 结果和工作副本，将本次已完成 Prompt 结果及工作副本归属子 Run，发布并激活子分支；相同内容不分叉。测试项目“付费回归-轻量通勤双肩包-20260928”已将历史的 Prompt revision 1→2 显式修复为父/子两个真实 Run，旧版下游留在父 Run，新版渲染任务留在子 Run。数据库回滚测试覆盖旧版保留、变化分叉与无变化结果；API/Web/Contracts 全量测试与构建通过。
- 该 Prompt 切片目前在**完成校验时**分叉；校验前的设置与结果草稿仍在启动 Run 内，尚未达到本计划的“首次编辑即进入隐藏临时分支、父分支草稿也完全隔离”目标。导入、提炼、渲染、混剪、成片的确认自动分叉及运行中任务切换隔离仍待逐节点完成，不能把 Prompt 切片当成六节点版本管理全部完成。
- Prompt 分叉后，子分支的渲染、混剪与成片工作区必须从空草稿开始；只能读取子 Run 在分叉后主动创建的下游任务，不能把父 Run 或修复迁移时生成的旧任务作为子分支当前内容。已生成但不属于当前分支的渲染批次保留为可追溯历史并退出当前工作区，不删除媒体文件。测试项目的历史批次按精确项目/Run/批次 ID 一次性归档，父分支原有 10 条素材保持不变；重新渲染时在子分支创建新批次。
- 混剪分叉层目前依据子分支本地已确认产物种类投影：模板配置、智能填充时间轴或包装结果。正式开启自动分叉时，需在分支创建事务内持久化精确分叉层；不能长期依赖后续可能变化的本地产物反推。
- 上线门槛是逐节点通过父分支不变、无变化确认、运行任务晚到、模板隔离及分支切换恢复的数据库级测试；在此之前不得通过只复制 `WorkflowRun` 行或前端补建分支来宣称完成。
- 已核查资料导入的临时子分支方案：产品、素材及已确认产物必须一起迁移；当前文件外键绑定同一 Run，而文件存储键又按项目唯一。不能只复制产品行、让子分支引用父 Run 的文件对象，否则违反外键或使文件清理误删父分支仍需的素材。跨 Run 文件引用和生命周期规则须先有独立迁移及数据库级回归，再接入首次编辑和确认发布。
- 此前一轮曾完成 API 全量单测 589 通过、1 跳过；Web 全量测试仍有 15 个页面源码断言失败，不能标记为全绿。本轮全宽矩形树、箭头与工作副本创建时间回填后，版本树及 API 适配 Web 测试 13 项、资料导入布局测试 24 项、相关 API/Repository 测试 19 项通过；Contracts 构建、Web/API 类型检查与构建、`git diff --check` 通过。在双模板项目中检查了 1920、1440、390 宽度，确认模板分叉、日期、箭头、横向滚动和无新增控制台错误。自动分叉仍未启用，不能将双模板分叉误认为已有跨 Run 历史版本。

## 数据与接口

### Prompt 自动分叉的最小安全切片

1. 在生成或编辑首次写入前创建隐藏临时子 Run，并以稳定映射复制分支内导入工作区、草稿、产品、素材引用、信息提炼结果与节点草稿。全局唯一的产品 ID 不能直接在子 Run 重用；新旧产品 ID 的映射必须同时应用于领域外键、工作副本键、Prompt 输入快照与设置节点键。媒体只共享同项目 FileObject，并保留跨 Run 引用以免清理器误删。
2. Prompt 任务的 `workflowRunId`、`productId`、上游 `artifactId + revision + contentHash` 在入队事务内固定为隐藏子 Run；Worker 晚到结果只写该 Run。草稿或失败任务不发布子 Run，父分支的结果和设置不得被改写。
3. 完成校验的同一事务内比较规范化工作副本哈希：变化才提交子 Run 产物、设置 `branchPublishedAt` 并原子激活；无变化保留父分支，隐藏任务历史需可追溯但不进入画布。重复校验必须返回同一已发布分支，不能再开叉。
4. 切换前由 Web 保存草稿；校验响应返回实际 Run ID，由工作流容器重新读取活动工作区，确保 Prompt、渲染与树使用同一分支。切回父分支必须能恢复旧 Prompt 与原有渲染素材。
5. 对已经在原 Run 中完成 revision 1→2 的测试数据，仅在确认两版不可变快照、领域结果与下游任务归属都能完整迁移时做一次显式修复；不能仅新建一条 `WorkflowRun` 行或改画布标签。无法完整迁移的旧记录须保留历史快照入口，不伪称可切换分支。

该切片的数据库级验收：父 Run 校验前后关键领域行及工作副本哈希不变；子 Run 的产品、资料、提炼与 Prompt 均可独立读取；同项目媒体引用安全；无变化确认、并发重复确认、旧 Worker 晚到和跨项目访问不会产生错误分支。通过这些测试前不在正式页面启用自动分叉。

1. `WorkflowRun` 记录 `parentWorkflowRunId`、`forkNodeId`、可选 `templateId`、自动生成的展示标签、创建时间与当前节点。用单一活动指针在项目、效果类工作流空间内原子切换，其他分支仍可由冻结任务按自己的 Run ID 写回。
2. 分支创建前读取父链已确认产物并固定 `artifactId + revision + contentHash`。已确认产物须有不可变版本快照；当前工作副本可继续充当该分支的最新指针，但不得改写父分支的快照。文件内容只复用已有文件对象，不复制二进制媒体。
3. 将效果类导入工作区、草稿与产品的唯一约束及查询改成按分支作用域；需要稳定逻辑产品标识与分支内产品记录的映射。其余五节点读取通过统一分支来源解析器获得本地优先、父链只读继承的有效产物与领域对象；新编辑写入子分支自己的记录。
4. Contracts 增加分支树、各节点状态、模板内填充/包装版本与激活分支的请求响应。API 按项目和效果类工作流读取树、激活分支，并校验项目、祖先链与活动指针。切换失败不更改活动分支。
5. 所有完成校验入口在事务内计算规范化哈希：无变化不分叉；变化则创建子 Run、固定祖先快照并将本次提交写到子 Run。响应包含实际目标 Run ID，Web 更新工作上下文。任务创建时固定启动分支和来源版本，任务回写不得按当前活动指针改投其他分支。

## 交互

- `EffectWorkflowCanvas` 步骤计数旁增加“查看版本分支树”。全屏白色画布最左侧固定显示六个工作流阶段，混剪阶段展开三个可视子层；树在阶段列右侧的可用画布中整体居中，叶节点等距排列，新增分支时旧分支向左、新分支向右对称让位。横贯画布的交替浅色行带使左侧阶段与右侧版本保持对应。顶部以项目名称为唯一头节点，资料导入有多个版本时直接由项目头节点分叉。每个已建立的分支从实际分叉阶段向下形成矩形节点和带箭头的父子曲线，而不是按分支列出右侧详情。当前活动路径从项目头节点到成片输出整条标红；待处理阶段保留虚线矩形但不创建空产物。空、加载、错误、单分支和多分支均有明确反馈。
- 切换前调用当前节点已有草稿刷新方法；失败时留在原分支。激活成功后清理前端预取和项目内节点状态，按新 Run 重载工作区并恢复 `currentNodeId`。
- 画布顶部不显示混剪模板筛选；所有模板直接在“模板”层从视频渲染节点分叉，各模板的填充、包装与输出沿自己的路径向下连接。点击非当前分支的树节点直接切换工作上下文，不再显示底部已选版本栏或右侧重复详情。成片输出仍须关联消费的准确时间轴及包装版本。首期不提供手工改名。
- 弹窗支持键盘焦点、Escape 关闭、焦点恢复和窄屏滚动。

## 迁移与兼容

- 对每个现有项目，以当前活动效果类 Run 作为初始主干。旧 `WorkingArtifact` 和领域记录原位保留；只从迁移后发生的确认变化开始积累不可变分支快照，不伪造历史。
- 迁移需要先建立分支内导入数据的唯一约束和旧项目逻辑产品映射，再启用分叉写入；不得在只有画布和元数据时启用切换。
- 未生成的下游只显示待处理，不创建空 `WorkingArtifact`。旧分支继续可读可编辑；新分支的下游仅在实际确认后形成自己的产物。

## 验收

- 导入、信息提炼、Prompt、渲染、混剪填充、混剪包装和成片输出的确认均覆盖有变化/无变化/失败/重复请求；草稿和运行中的任务不产生分支。
- 父子分支的产品、素材、时间轴、包装和成片互不改写；同一 Prompt 可派生多个渲染分支，包装可继承同一填充，模板间隔离。
- 跨项目查询、并发激活、旧任务晚到、保存草稿失败均不改变错误分支的数据。
- 运行 Contracts、API、Web 的单测、类型检查、构建和 `git diff --check`，并在 1920、1440、窄屏浏览器验证弹窗及各状态。
