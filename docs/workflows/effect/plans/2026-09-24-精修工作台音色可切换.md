# 精修工作台：音色库取消包装后锁定

日期：2026-09-24
需求原话：_「这个音色无法选中了，只能试听」_ → AskUserQuestion 选择：**「取消这个锁定」**。

即：智能成片包装完成后，精修工作台里的**音色库应当仍然可选**，用于给之后新生成的字幕口播换音色；已包装成片的既有口播**不重配音**。

---

## 一、范围

1. 精修工作台「音色库」在包装完成后**可切换音色**（不再只读试听）。
2. 服务端 `saveDraft` 放行「只改音色」的草稿保存。
3. 新生成的字幕口播（`CAPTION_VOICE`）使用**模板当前音色**。
4. 锁定横幅文案同步修正，不再宣称「模板配置全部锁定」。

## 二、现状与关键约束（实测证据）

### 2.1 前端锁定是两段合成的，需要拆开

`apps/web/src/workflows/effect/template-mix/EffectTemplateMixNodePage.vue`：

- `:375` `const packagingLocked = computed(() => Boolean(activeEntry.value?.packagingLocked));` —— 包装完成后**持久为 true**（见 `apps/api/.../effect-template-mix.service.ts:746`）。
- `:376-384` `projectEditLocked` —— 包装**运行中**（`QUEUED`/`RUNNING`）或智能填充运行中才为 true；包装 `COMPLETED` 后为 false。
- `:385` `const templateEditLocked = computed(() => projectEditLocked.value || packagingLocked.value);`
- `:5350` `<EffectVoiceLibrary … :disabled="templateEditLocked" />`
- `:1438-1443` `selectVoiceProfile` 首行 `if (templateEditLocked.value) return;`

结论：把音色库从 `templateEditLocked` 换成 `projectEditLocked`，语义正好是「**运行中不许改，跑完了可以改**」，且槽位/转场/素材仍受 `templateEditLocked` 保护（`:4926`/`:4944`/`:4949`/`:4964`/`:4970` 不动）。

`EffectVoiceLibrary.vue:108-110` 已经按 `props.disabled` 分流：

```ts
async function selectAndPlay(profile) {
  if (!props.disabled) emit('select', profile.id);
  emit('audition');
```

`disabled` 一去，点击即 emit `select`，无需改组件。

### 2.2 只改前端会 409 —— 服务端 `saveDraft` 会拦

`apps/api/src/workflows/effect/template-mix/effect-template-mix.service.ts:711-746`：

```ts
const workspaceChanged = Boolean(
  before && next && workflowStateHash(before.workspace) !== workflowStateHash(next.workspace),
);
const templateChanged = Boolean(
  before && next &&
  workflowStateHash(before.workspace.template) !== workflowStateHash(next.workspace.template),
);
…
if (!before || !next ||
  ((activeSet.has(templateId) || activePackagingSet.has(templateId)) && workspaceChanged) ||
  (packagingSet.has(templateId) && (templateChanged || removedExistingVariant))) {
  throw new ApiHttpException(… '智能成片包装已开始，模板配置不能再修改' …, HttpStatus.CONFLICT, 'CONFLICT');
}
```

`template.voiceProfileId` 在 `workspace.template` 里，所以**只改音色也会让 `templateChanged` 为 true → 409**。

三个集合的语义（`:690-707`）：

| 集合                 | 来源                         | 含义                 |
| -------------------- | ---------------------------- | -------------------- |
| `activeSet`          | `lockedTemplateIds`          | 智能填充运行中       |
| `packagingSet`       | `packagedTemplateIds`        | **已包装过（持久）** |
| `activePackagingSet` | `activePackagingTemplateIds` | 包装**正在跑**       |

所以只要**只对 `templateChanged` 做音色屏蔽、不动 `workspaceChanged`**，运行中改音色仍会被 `workspaceChanged` 拦下（文案变成「智能成片包装正在执行，暂不能修改成片工程」），包装完成后才放行。这是最小且安全的切法。

`workflowStateHash`（`apps/api/src/platform/workflow/workflow-state-hash.ts`）先按 key 递归排序再 sha256，所以用解构把 `voiceProfileId` 摘掉即可稳定比较：

```ts
const withoutVoice = ({ voiceProfileId: _v, ...rest }: EffectTemplateMixTemplate) => rest;
```

### 2.3 换音色不会让已包装成片变脏（这一点是安全的）

`apps/api/src/workflows/effect/template-mix/template-mix-lifecycle.ts` 的 `templateConfigurationHash = workflowStateHash({ name, slots })` —— **不含 `voiceProfileId`**。因此换音色：

- 不会让已包装项变 `needsAiFill`；
- 不会让成片过期。

### 2.4 但新口播目前会沿用**冻结音色**，与「模板当前音色」不一致

`apps/api/src/workflows/effect/template-mix/effect-packaging.service.ts:656-660`（字幕口播合成）：

```ts
// The frozen profile is the one this item's other narration was rendered with, so the new line
// sounds like the rest of the film; the template's current choice is only a fallback for a
// historical snapshot that predates voice freezing.
const profile =
  snapshot.voiceProfile ?? this.voiceCatalog.selection(entry.workspace.template.voiceProfileId);
```

这段注释成立的前提是「包装后音色不可改」。解锁之后前提消失：用户换了音色却拿不到新音色，等于按钮白点。因此把优先级反过来：**模板当前音色优先，冻结音色只在模板没选时兜底**。

`effect-voice.catalog.ts:172-187` 的 `selection(id)` 在音色未配置/未验证时抛 `所选音色未配置或未验证，请重新选择音色`——音色库只列可选音色，正常路径不会命中。

### 2.5 横幅文案

`apps/web/.../effect-packaging-progress.ts:182-199` 的 `packagingLockMessage`，以及 `EffectTemplateMixNodePage.vue:4999-5002` 的常驻横幅，都写「**模板配置**和智能填充已锁定」。音色解锁后这句不再准确。
`effect-packaging-progress.spec.ts:79-87` 只断言子串（`'已完成'`/`'锁定'`/`'正在进行'`…），改词安全。

## 三、口径决策

| 问题                        | 决策                           | 理由                                                                         |
| --------------------------- | ------------------------------ | ---------------------------------------------------------------------------- |
| 已包装的既有口播            | **保持冻结音色，不自动重配音** | 用户只说「取消锁定」，没说重做已生成的成片；重配音等于重渲染，代价大且不可逆 |
| 新生成的字幕口播音色        | **模板当前音色**               | 与原始需求口径「用模板当前音色，一键生成」一致；否则换音色无意义             |
| 运行中（QUEUED/RUNNING）    | **仍然锁定音色**               | 包装快照已冻结音色，中途改会与本次任务不一致                                 |
| 槽位/转场/素材/重新智能填充 | **仍锁定**                     | 本次只放开音色，`packagingLocked` 对这些的语义不变                           |

1. `EffectPackagingService.voiceCatalog` 是构造默认值（`effect-packaging.service.ts:138`），测试里用 `vi.spyOn(service.voiceCatalog, 'selection')` 打桩，未改生产代码。

3. `effect-packaging-progress.ts` 的 `QUEUED`/`RUNNING` 两句**不改**——运行中音色确实仍锁定，原文案准确。
