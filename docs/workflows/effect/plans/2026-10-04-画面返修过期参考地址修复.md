# 画面返修过期参考地址修复

## 问题与边界

R-002 返修在创建 Seedance 任务时两次返回 HTTP 400，未获得返修任务 ID。旧 Ark 任务查询成功并不刷新生成视频 URL；该素材生成于 2026-09-29，当前返回地址不可读。错误响应只保存 HTTP 状态，没有供应商详情，不能声称知道当时 HTTP 400 的全部原因。

当前属于效果类视频渲染节点。返修输入继续冻结当前活动文件及版本、SHA-256、修改范围和要求；成功先保存候选，用户采用并保存修改时才提交 render-clip/render-batch 工作副本并通知下游。不改变原素材、自动采用规则或工作流分支。

## 实施

- 在供应商创建之前对参考 URL 做无 Ark 凭据的流式小范围读取校验，不依赖 HEAD，也不下载完整视频。
- 旧任务已删除、过期或源 URL 返回 403/404/410 时，允许 Worker 通过已有受租约保护的 API 获取系统保存视频的短时签名地址。
- 回退只发生在创建新任务之前；已有供应商任务只恢复轮询，不重复创建或付费。签名地址也必须可读才提交。
- 当前本地没有公网素材地址配置；明确提示需要配置，不能把 localhost 暴露给供应商、建立未授权隧道或伪装恢复成功。
- 保持供应商 HTTP 错误码分类及原有重试逻辑；不记录原始响应、Prompt、密钥或签名 URL。
- 修正 README 中“查询原任务能换新 URL”的错误描述。

覆盖有效源地址、源任务失效、源地址 403/404/410、小范围读取、临时网络错误、回退地址失效、缺少公网配置、原供应商任务恢复和凭据不泄漏。执行 Seedance Worker 全量 pytest、严格 mypy、`git diff --check`；无进行中渲染任务时更新原 Worker。真实付费返修须用户授权，不在诊断时自动重复提交。
