# 效果类 AI 信息提炼：语义整理轻量化改造计划

状态：已完成

## 目标

- 用户事实只参与语义诊断，保持原字段、原顺序和原内容，不由模型自动删改。
- AI 图片建议由语义模型完成去重、字段归类和容量内择优。
- 用户事实的重复、包含、字段疑似错误和歧义只形成可见提示，不阻止信息卡确认。
- 语义模型单次等待最多 30 秒，不再对同一超时请求原样重试。

## 数据与行为

- 用户事实包括表单、人工覆盖、用户文档和电商资料中的明确事实；单字段继续受 20 项编辑安全边界保护。
- 核心卖点 3 项、次要卖点 6 项、其他营销列表 5 项只限制 AI 图片建议可占用的剩余容量。用户事实超过推荐数量时原样保留并提示。
- 模型输入拆分为 `userFacts`、`imageSuggestions` 和逐字段剩余容量。
- 模型只返回每条图片建议的保留/舍弃与目标字段，以及用户事实的结构化语义提示，不再返回七个字段的完整选择清单。
- Worker 只校验稳定事实 ID、来源权限、结构和容量，不使用文本规则复判语义。
- 语义失败时保留全部用户事实，未经语义确认的图片建议不进入最终信息卡；原始图片分支结果继续保留。

## 接口与展示

- Result V3 和现有 HTTP 路径保持不变。
- 展示来源项增加可选语义提示，历史结果默认无提示。
- 用户事实仍不显示来源标签；存在问题时在对应编辑行下显示黄色建议，编辑该字段后清除旧提示。
- 语义提示不阻止完成校验和 WorkingArtifact 提交。
- 节点详情显示用户事实检查数、待确认问题数、AI 建议输入/保留/迁移/删除数和模型耗时。

## 运行配置

```text
ARK_SEMANTIC_TIMEOUT_SECONDS=30
ARK_SEMANTIC_MAX_ATTEMPTS=1
ARK_SEMANTIC_MAX_OUTPUT_TOKENS=2048
ARK_SEMANTIC_REASONING_EFFORT=minimal
```

## 验收

- 用户事实即使重复、字段疑似不合理或超过推荐数量，也不被自动删除、移动或排序。
- AI 图片建议与用户事实同义时只删除图片建议；图片建议之间可去重和迁移。
- 超时只调用一次，并在约 31 秒内降级完成。
- 历史结果、工作副本 revision 和 Prompt 下游依赖保持兼容。
- 通过 Worker、Contracts、API、Web 测试、类型检查、构建与浏览器回归。

## 实施结果

- 用户事实与 AI 图片建议已使用不同输入集合；最终信息卡始终先恢复用户事实，再按模型优先级加入容量内的图片建议。
- 模型输出已收缩为图片建议处理决定与用户事实提示；Worker 仅校验 ID、来源、结构和容量。
- 语义调用独立使用 30 秒超时、单次尝试、2048 输出 Token 和 minimal 推理强度。
- 语义失败会生成部分完成结果：用户事实继续保存，未整理的图片建议不会进入信息卡。
- API 工作区读取已包含语义整理分支元数据，前端可展示待确认提示；编辑对应字段后会清除该字段旧提示。
- 工作流节点详情已改为展示用户事实检查数、待确认问题数、图片建议处理计数、耗时和降级状态。
