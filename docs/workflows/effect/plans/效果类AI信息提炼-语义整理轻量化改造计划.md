## 同层重叠提示召回修复

2026-09-02 的真实运行 `5d911a85-3e9a-4974-be7c-4fbb1b0bdfd5` 已在约 22.2 秒内完整成功，语义整理耗时约 10.4 秒，但模型没有提示同一场景层中“共享明确场景核心、同时各自保留额外营销信息”的用户事实重叠。

本轮只修复用户事实提示召回，不改变图片建议容量、用户事实保护、Result V3、HTTP 路径、WorkingArtifact revision 或下游 Prompt 依赖：

- 模型必须先按卖点层、用户层和场景层分组，再穷举每层全部无序事实对，不能只检查措辞高度相似的事实。
- `OVERLAPPING` 不再限定为严格父子包含；两条事实共享一个可独立复述的具体业务命题，且至少一条还包含额外有效信息时，也应提示用户检查重叠。
- 仅共享商品、节日、渠道或宽泛主题，核心目的、动作、对象或场合不同的事实仍属于 `RELATED_DISTINCT`，不得提示。
- 每一对问题事实只输出一条提示，避免对称重复；Worker仍只校验事实 ID、业务层和结构，不参与语义判断。
- 生产 Prompt 保持商品无关；允许使用不绑定商品的抽象关系校准样例，具体失败样本仅进入显式 Ark 回归测试，默认测试不产生模型费用。

首次针对性 Ark 回归表明，单纯要求穷举事实对仍不足以召回复合句之间的重叠：模型会把复合句中的额外信息误当成整条事实完全不同。后续补充原子命题拆分规则：先把每条事实拆为可独立成立的最小业务命题，再逐项执行同义归一和关系判断；两条事实只要共享一个等价的具体原子命题，整句又各有额外信息，就必须判为 `OVERLAPPING`。

后续重复回归又发现，纯抽象定义仍会导致模型把“不同采购目的但共享时间背景”的事实误报为重叠。生产 Prompt 因此增加跨商品通用的结构校准样例，分别锚定“共享具体相聚命题的复合情绪事实”和“日常补货、集中备货、礼赠采购的不同购买目的”；样例不包含产品名称、品牌或具体失败原文。

实施结果：语义 Prompt 升级至 `5.6.0`。Provider在不复制事实正文的前提下，按 SELLING_POINT、USER、SCENARIO 及其字段对用户事实做结构化分组，帮助模型完整检查同层事实对；Worker仍未增加任何关键词、相似度或业务语义判断。Prompt新增原子命题拆分、完整事实对复查及商品无关关系校准，既召回复合情绪事实的共享核心，也保留不同采购目的。

验证结果：Worker全量 pytest 通过，默认跳过 5 项显式 Ark 付费用例；相关 29 项单元测试、mypy、变更范围 Ruff、格式检查与 `git diff --check` 通过。真实 Ark 验收中，`low` 推理在 45 秒仍超时，因此继续使用 Pro `minimal`；最终校准后，专注用户事实回归连续 2 次通过，包含图片建议的完整语义回归也连续 2 次通过，均同时满足“召回合理同层重叠”和“不误报不同购买目的”。

## 同业务层建议约束

用户事实的非阻断语义建议只在同一业务层内比较：核心卖点与次要卖点属于卖点层，核心痛点与决策动因属于用户层，使用、购买与情绪场景属于场景层。卖点层、用户层和场景层之间不得互相提示。

- 模型不得输出跨业务层的 `relatedFactIds`；`POSSIBLE_WRONG_FIELD` 只能建议迁移到同一业务层内的另一个字段。
- Worker 对跨层关联、缺少同层关联的重复/重叠提示及跨层迁移提示执行结构拒绝，不参与语义判断。
- API 对历史运行中的跨层建议做安全过滤，避免旧元数据继续显示。
- AI 图片建议仍可由模型迁移到更合适字段；本约束只针对展示给用户的用户事实语义建议。

实施结果：语义 Prompt 升级至 `5.3.0`；Worker 允许同层字段之间比较和迁移，拒绝跨层关联、跨层迁移及缺少同层关联的重复/重叠提示；API 会同步过滤历史结果中的跨层提示。Worker 29 项针对性测试与 API 24 项测试通过，Ruff、mypy、API 类型检查和 `git diff --check` 通过。

## 目标

- 用户事实只参与语义诊断，保持原字段、原顺序和原内容，不由模型自动删改。
- AI 图片建议由语义模型完成去重、字段归类和容量内择优。
- 用户事实的重复、包含、字段疑似错误和歧义只形成可见提示，不阻止信息卡确认。
- 语义模型单次等待最多 30 秒，不再对同一超时请求原样重试。

## 数据与行为

- 用户事实包括表单、人工覆盖、用户文档和电商资料中的明确事实；单字段继续受 20 项编辑安全边界保护。

- 模型输入拆分为 `userFacts`、`imageSuggestions` 和逐字段剩余容量。

- Worker 只校验稳定事实 ID、来源权限、结构和容量，不使用文本规则复判语义。
- 语义失败时保留全部用户事实，未经语义确认的图片建议不进入最终信息卡；原始图片分支结果继续保留。
