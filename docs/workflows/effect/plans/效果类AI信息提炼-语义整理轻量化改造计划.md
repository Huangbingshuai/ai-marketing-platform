## 商品无关语义关系协议

2026-09-02 的真实运行暴露出两类模型判断偏差：模型把主题相关但购买目的不同的场景误报为重复，同时保留了围绕同一可见属性的两条近义图片卖点。修复不把任何具体商品、节日、场景或措辞写成生产规则；具体失败样本只作为显式回归数据。

本轮保持 Result V3、HTTP 路径、用户事实保护、字段容量、WorkingArtifact revision 和单次 30 秒模型调用不变，只调整模型任务边界：

- 语义模型统一使用“可替换性 + 有效差异”协议。只有两条内容在业务对象、目的、场合、时间、人群、动作和关注点等有效维度上等价，互相替换不会损失信息时，才允许判为重复。
- 同一主题但存在独立业务维度的内容属于“相关但不同”，不得输出重复或重叠提示；父子包含只有在一条内容确实覆盖另一条时才成立。
- AI 图片建议先与全部用户事实和只读参照比较，再在整批图片建议内建立唯一保留集合；围绕同一中心可见属性且没有新增独立信息的建议只能保留一条。
- 图片内容只允许形成可直接观察或清晰读取的事实；把可见现象扩展为不可直接观察的状态、品质、体验、功效或真实性结论时，图片节点不输出，语义节点按低信息量舍弃。
- Worker仍只校验事实 ID、来源权限、字段层级、结构和容量，不新增关键词、字符相似度或业务语义规则。
- 生产 Prompt 不包含具体商品失败样例；具体购买场景误报和图片卖点重复仅保存在测试数据中。

验收要求：Prompt 模板必须包含替换测试、有效差异测试、相关但不同边界、整批图片建议唯一性检查和可观察证据边界；模板测试必须阻止具体商品回归样例重新进入生产 Prompt。默认测试不调用付费模型。

实施结果：语义 Prompt 升级至 `5.4.0`，图片 Prompt 升级至 `6.5.0`。生产 Prompt 已移除具体商品示例，并加入商品无关的关系协议、整批图片建议唯一性检查和可观察证据边界；具体误判样本只保留在显式 Ark 集成测试中。Worker全量 pytest 通过，显式付费用例保持跳过；Ruff、mypy 和 `git diff --check` 通过。本轮未调用真实 Ark，模型质量变化仍需在重建 Worker 后由真实提炼任务确认。

## 真实运行降级与来源一致性修复

2026-09-02 最新运行 `0fa04309-d555-4972-8c5e-c23411f050c7` 使用旧 Worker 镜像执行，语义模型在 13 秒内返回不可解析的结构化结果，分支降级为 `PARTIAL`，25 条用户事实得到保留，15 条图片建议全部排除。排查同时发现：降级元数据仍把结构校验写为 `VERIFIED`，最终来源继续沿用语义筛选前的融合来源，造成“图片建议保留为 0，但字段来源仍包含 IMAGE”的不一致。

- 最终来源依据语义整理后的实际字段值与权威来源重新计算；被排除的图片建议不得继续出现在来源链中。
- 节点详情区分“结构校验通过”和“模型响应失败后仅保留用户事实”。
- 重建提炼 Worker，并核对运行镜像加载图片 Prompt `6.4.0` 与语义 Prompt `5.3.0`。
- 不为修复结构异常增加相同请求重试，不改变用户事实保护和图片建议失败即排除的安全策略。

实施结果：语义 Provider 整体失败时，`validation.status` 现在明确记录为 `NOT_VERIFIED`；节点详情会展示安全失败原因和失败前实际耗时。最终来源会依据语义整理后的真实字段逐条重算，高优先级用户事实优先于同值图片建议，跨字段保留的图片建议仍正确标记为图片来源。API 对历史结果执行同样的只读来源校正，不修改历史 Result V3 数据。

部署结果：已重建本地 `effect-extraction-worker`，容器内确认图片 Prompt 为 `6.4.0`、语义 Prompt 为 `5.3.0`，Worker 已恢复消费 `effect.extraction.requested` 队列；本轮没有创建提炼任务或发起 Ark 付费调用。

## 同业务层建议约束

用户事实的非阻断语义建议只在同一业务层内比较：核心卖点与次要卖点属于卖点层，核心痛点与决策动因属于用户层，使用、购买与情绪场景属于场景层。卖点层、用户层和场景层之间不得互相提示。

- 模型不得输出跨业务层的 `relatedFactIds`；`POSSIBLE_WRONG_FIELD` 只能建议迁移到同一业务层内的另一个字段。
- Worker 对跨层关联、缺少同层关联的重复/重叠提示及跨层迁移提示执行结构拒绝，不参与语义判断。
- API 对历史运行中的跨层建议做安全过滤，避免旧元数据继续显示。
- AI 图片建议仍可由模型迁移到更合适字段；本约束只针对展示给用户的用户事实语义建议。

实施结果：语义 Prompt 升级至 `5.3.0`；Worker 允许同层字段之间比较和迁移，拒绝跨层关联、跨层迁移及缺少同层关联的重复/重叠提示；API 会同步过滤历史结果中的跨层提示。Worker 29 项针对性测试与 API 24 项测试通过，Ruff、mypy、API 类型检查和 `git diff --check` 通过。

## 真实运行质量补强

2026-09-02 的真实运行 `254a30c7-b91d-4df9-9064-24ea1762a163` 已在单次尝试内完成，语义整理耗时 9.728 秒，但暴露出三项质量问题：当前运行对人工覆盖字段产生的语义提示被 API 隐藏；图片建议未与用户提供的核心外观特征做语义对照；图片模型把“展示方式”误写为消费者决策动因。

- 修正多源融合冲突的字段中文名，工作流详情不再用笼统的“产品信息”代替视觉风格基线。
- 保持 Result V3、HTTP 路径、字段容量、用户事实保护、WorkingArtifact revision 和 Prompt 下游依赖不变。

验收包括 API 当前运行提示、Worker 只读参照透传、图片与语义 Prompt、结构容错、前端融合提示以及浏览器展示回归。

## 结构容错与 Pro 模型切换

2026-09-02 的真实运行中，语义模型在 10.9 秒内成功返回结构化响应，但其中至少一项决定未通过 Worker 的业务结构校验，旧逻辑因此丢弃整批 12 条图片建议。后续修复遵循以下边界：

- 语义整理专用模型切换为火山方舟 `doubao-seed-2-1-pro-260628`，使用低推理强度；图片识别、文档解析和其他节点模型不变。
- 仍只调用一次；超时继续保持 30 秒，结构化输出上限调整为 3072 Token。真实冒烟确认 Pro 的 `low` 推理在 30 秒内无法返回，因此保留更强模型并使用 `minimal` 推理，避免节点速度倒退。
- Worker 不增加任何语义规则，只做结构级容错：未知或重复决定被忽略、缺失决定视为删除、无目标字段的保留决定视为删除、超过容量的决定按模型返回顺序截留。
- 用户事实提示逐条校验；单条无效提示被忽略，不再使全部图片建议失效。
- 发生结构修正时节点标记为部分完成，但有效图片建议继续进入信息卡；节点详情展示结构修正数量和安全分类，不展示事实正文、模型响应或内部 ID。
- Provider 整体失败或 JSON Schema 无法解析时仍保留全部用户事实，并排除未经整理的图片建议。

## 目标

- 用户事实只参与语义诊断，保持原字段、原顺序和原内容，不由模型自动删改。
- AI 图片建议由语义模型完成去重、字段归类和容量内择优。
- 用户事实的重复、包含、字段疑似错误和歧义只形成可见提示，不阻止信息卡确认。
- 语义模型单次等待最多 30 秒，不再对同一超时请求原样重试。

## 数据与行为

- 用户事实包括表单、人工覆盖、用户文档和电商资料中的明确事实；单字段继续受 20 项编辑安全边界保护。
- 核心卖点 3 项、次要卖点 6 项、其他营销列表 5 项只限制 AI 图片建议可占用的剩余容量。用户事实超过推荐数量时原样保留并提示。
- 模型输入拆分为 `userFacts`、`imageSuggestions` 和逐字段剩余容量。
- 模型只返回每条图片建议的保留/舍弃与目标字段，以及用户事实的结构化语义提示，不再返回七个字段的完整选择清单。
- Worker 只校验稳定事实 ID、来源权限、结构和容量，不使用文本规则复判语义。
- 语义失败时保留全部用户事实，未经语义确认的图片建议不进入最终信息卡；原始图片分支结果继续保留。

## 接口与展示

- Result V3 和现有 HTTP 路径保持不变。
- 展示来源项增加可选语义提示，历史结果默认无提示。
- 用户事实仍不显示来源标签；存在问题时在对应编辑行下显示黄色建议，编辑该字段后清除旧提示。
- 语义提示不阻止完成校验和 WorkingArtifact 提交。
- 节点详情显示用户事实检查数、待确认问题数、AI 建议输入/保留/迁移/删除数和模型耗时。
