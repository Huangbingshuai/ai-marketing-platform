# 效果类 Prompt：单一语义裁判与轻量门禁改造方案

## 状态

已完成

## 目标

保留当前 Prompt 八阶段执行图与事实充分分配能力，将生成后的语义判断收敛为一次 AI 评估。Worker 只负责结构、来源、稳定 ID、数量、状态与哈希，不再使用关键词、字符包含、中文 n-gram 或自由文本规则判断事实、场景、动作和视觉证明的语义。

## 范围

- 效果类第 3 节点 Prompt 生成 Worker。
- 生成 Provider 的结构化输出校验。
- AI 创意评估与用途分类内部契约。
- 精确数量择优、事实覆盖补充与向量 MMR。
- Worker 单元测试、类型检查与文档。

## 非目标

- 不修改八阶段工作流拓扑。
- 不修改 HTTP 路径、Prisma Schema 或公开 Prompt 批次结果结构。
- 不修改 `WorkingArtifact` 提交边界。
- 不修改信息提炼、视频渲染或其他工作流。

## 实施方案

### 1. 生成阶段只校验事实来源

- 生成模型继续接收所属创意方向的已分配事实。
- 候选输出保留 `declaredFactIds`，不再要求返回逐字摘录的生成阶段 `factEvidence`。
- Worker 只校验事实 ID 与当前任务分配完全一致，以及正文和六维结构完整。
- 不再因事实原句没有出现在正文而丢弃候选。

### 2. AI 成为唯一语义裁判者

- 评估模型只接收当前候选与该候选已分配事实，判断事实是否完整实现、部分实现或未实现。
- 事实编造、产品完全无关、抽象事实错误视觉证明和结构破损依然可由 AI 返回稳定问题码。
- 一般不连贯、轻微时长不匹配、普通相似、用途偏斜和次要事实未使用只作为软提醒。
- Worker 不再二次解释 AI 返回的事实含义或视觉证明含义。

### 3. Worker 门禁收敛

Worker 硬校验仅保留：

- JSON/Pydantic 结构完整。
- `slotId`、事实 ID、枚举和数量合法。
- 事实 ID 来自当前分配，不得引用未知事实。
- 旧 attempt token、revision 和哈希不得覆盖新结果。
- 目标数量精确。
- 规范化后完全相同的正文或全套创意结构作为确定性重复。

Worker 删除：

- `evidenceText` 必须逐字出现的检查。
- 用事实值字符包含判断事实是否成立。
- 固定风格词、场景词或动作词匹配。
- 中文 trigram 作为业务相似度或回退策略。
- 根据自由文本推断事实绑定角色。

### 4. 择优与覆盖

- 正式运行只使用向量正文相似度与 AI 六轴语义族做 MMR 排序。
- 完全重复、事实编造、产品完全无关和结构破损不进入选择池。
- 其他评分和警告只影响排序，不直接造成数量缺口。
- 必用事实依据 AI 返回的实现状态做批次覆盖统计。缺少事实时优先定向补充，不删除其他正常候选。
- 补充后仍未覆盖的批次保留完整草稿并进入 `NEEDS_REVIEW`，不保存短批次。

## 契约与兼容

- 内部候选结构不再要求生成阶段 `factEvidence`。
- 评估结构保留事实 ID 与支持等级，由 AI 权威输出；Worker 只安全过滤未知 ID 和非法枚举。
- 公开 Prompt 批次结果、HTTP 路径、Prisma Schema 和 `WorkingArtifact` 键不变。
- 历史草稿与已提交 Prompt 保持可读，新运行使用新内部契约。

## 测试

- 事实合理改写且不包含上游原句时，候选不被 Worker 丢弃。
- 生成结果引用未分配事实 ID 时仍被拒绝。
- AI 判定事实编造、产品无关或结构破损时仍不进入选择池。
- 普通低分、部分事实实现和一般相似只降低排名，不形成硬淘汰。
- 批次缺少必用事实时触发一次定向补充，不会先删除已有候选。
- 正式配置不再接受 trigram 语义选择模式；Mock 使用确定性 Mock 向量。
- 50 条与 100 条配置均能精确保存目标数量或明确进入可复查草稿状态。
- 执行 Worker pytest、mypy、Ruff 和 `git diff --check`。

## 实施结果

- 生成候选不再返回或校验逐字事实证据，只保留任务分配的事实 ID。
- AI 评估器成为事实实现、事实编造、产品关联和抽象视觉证明的唯一语义裁判；Worker 只过滤未知事实 ID、非法结构和非法枚举。
- Worker 已删除事实原文包含、证据位置、固定风格短语、商品场景/动作关键词和中文 trigram 语义回退。
- 正式相似度路径固定为向量正文相似度加 AI 六轴语义族；Worker 只执行数值排序，不从文本推断语义。
- 单条“缺少深度业务事实”不再形成重复硬门禁；批次覆盖不足时保留完整草稿并进入 `NEEDS_REVIEW`。
