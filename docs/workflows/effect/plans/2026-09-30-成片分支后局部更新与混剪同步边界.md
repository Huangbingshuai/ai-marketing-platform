# 成片分支后局部更新与混剪同步边界

## 范围与非目标

效果类混剪草稿保存后，只有当前工作流 Run 尚无已确认成片输出版本时，才静默改写待渲染快照。一旦当前分支已有成片输出版本，混剪编辑不再改写其成片快照或文件；成片节点逐条显示需要更新的已导出成片，用户主动点击局部更新后，在当前分支只重渲染变化条目并覆盖该分支的交付结果。不新增分支、不自动发起付费任务。不改变智能填充、包装和其他工作流节点。

## 数据与接口

- 以当前 Run 已确认的 `final-delivery:<templateId>` 工作副本识别已有成片输出版本，兼容手动复制了成片结果的分支；不能以页面是否显示成片或单个批次的 `PENDING_RENDER` 状态代替分支判断。
- `POST final-output/sync` 按项目、Run、模板及草稿 revision 限定请求。已有成片版本时不改写快照；尚无版本时只更新 `PENDING_RENDER` 条目，防止旧请求覆盖新草稿。混剪保存成功后异步触发，进入成片页补偿重试。
- 成片列表契约逐条提供 `stale` 与汇总 `counts.stale`。服务端仅对已有成片版本且实际画面、来源、时长或已保存的口播/字幕/配乐安排变化的已导出条目计算待更新。前端标记具体成片并显示数量。
- 局部更新接口只允许当前活动成片分支调用，在事务中锁定混剪草稿和目标批次；只将用户选中且确实变化的条目快照更新为最新工程与包装音轨安排并入队。未变化条目、旧文件和其他分支不动。完成回调在同一分支更新成片与交付清单工作副本；失败保留旧文件供恢复。

## 兼容与迁移

不新增数据库列或批量迁移。既有输出分支通过已有交付清单工作副本识别；没有交付清单的历史未完成批次不伪装成已确认成片分支。旧客户端忽略新增待更新字段不影响读取。

## 验收

- 无成片分支时，混剪草稿保存后待渲染快照自动更新，不触发渲染任务。
- 已有成片分支时，同步请求不改写待渲染/已导出快照；成片列表只标记实际变化的条目。
- 点击局部更新只使变化条目入队，在当前 `workflowRunId` 内完成并覆盖交付；不新建 Run，不重复渲染未变化成片；运行中、旧分支及跨项目请求被拒绝。
- 覆盖复制分支、连续草稿 revision、运行中任务、失败恢复和导出前状态；执行 API、Web、Contracts 测试、类型检查、构建、`git diff --check`，并在 1920、1440、窄屏检查页面状态。
