# 渲染页面遗漏新增素材来源修复

## 已确认原因

已保存的渲染批次保留 22 条素材，活动混剪分支中仍有 20 条素材的历史任务快照。渲染工作区直接查询当前 Run 的批次；进入渲染编辑时也优先复制该旧快照，与混剪素材池使用的已确认来源口径不一致。

## 修复范围

- 渲染工作区复用已有渲染来源判定，读取当前来源谱系的已确认素材批次；项目、Run、产品映射必须精确且唯一。
- 进入渲染编辑时从同一已确认来源复制素材，保留新增的独立导入素材，并映射产品和任务 ID。
- 历史任务缺少创意标题和六维信息时，仅从其实际消费的同 ID、revision、哈希的 Prompt 补全展示，不借用旧分支或更新后的 Prompt。
- 正在编辑、独立渲染头、手动复制及未发布任务继续读取自己的结果，不合并别的谱系。
- 不按最大数量猜测来源、不补造素材、不重新调用模型、不修改旧工程与已交付文件、不自动提交 Git。

## 验证

- 来源新增、删除和不同数量均按已确认池读取，不按任务更新时间或数量选择。
- 未保存编辑不影响正式来源；取消/无变化保存不发布更改。
- 22 条素材来源进入编辑仍是 22 条，旧快照与其他项目不变。
- API 单测、回滚数据库回归、类型检查与构建、浏览器实际分页与素材计数，以及 git diff --check。

## 数据与迁移

复用 WorkingArtifact 与既有分支来源关系，不新增契约、表或平行状态；无需历史数据迁移。

## 已执行验证

- 7 个相关测试文件合计 128 项通过，包括已确认素材池 22 / 19 / 0 条的数据库事务回滚测试、编辑分支、来源隔离、素材状态和创意信息读取。
- API 类型检查、构建及 `git diff --check` 通过。
- 已更新本地 API，健康检查正常；真实紫苏梅子酱项目页面显示 22 个结果、成功 22、批次 revision 23。
- 每页 20 条时显示两页；第二页 R-021（15 秒）、R-022（6 秒）均已完成。历史任务标题已恢复，不再因分支 ID 不同显示“创意方向待同步”。
- 测试未重做素材、未调用付费模型、未改写用户已有工程或历史素材文件；数据库测试创建的独立夹具全部事务回滚。
