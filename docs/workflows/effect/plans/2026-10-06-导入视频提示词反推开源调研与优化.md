# 导入视频提示词反推：开源调研与有界优化

## 范围与业务边界

效果类视频渲染节点的人工导入识别，只更新同项目、同批次、同 attempt 的导入草稿。输入仍为已校验上传文件、内容哈希和真实 4–30 秒时长；不更改 Prompt 批次 revision。用户确认导入并保存渲染编辑后，才沿既有 `render-clip:{taskId}` / `render-batch:{productId}` 工作副本链路提供给混剪。识别不自动确认、不创建混剪工程、不改历史素材。

接口、Web 弹窗、导入确认流程、四类用途及六维字段不变；继续使用火山专用多模态模型。每次用户触发仅一次模型请求，不增加自动付费补充或重试。

## 实施

1. 新增仅用于视频导入的采样器，现有混剪和包装的 12 帧采样保持不变。
2. 基础采样包含首帧、接近末帧；按约 2 FPS 取样，长视频最多 40 帧。最多选择 4 个强变化点，补取前后证据，总预算 48 帧。不能保证逐帧边界或任意极短事件必然可见。
3. 两次本地 FFmpeg 解码：低分辨率变化检测、单次批量帧提取。进程并发最多 2 个导入视频；设置时限，取消时终止并回收子进程。提取返回实际解码帧时间，而非把计划采样点当作精确证据。
4. 变化检测失败时记录脱敏降级日志，继续真实基础采样；真实帧提取失败则按现有错误契约失败，不伪造帧或成功结果。
5. 按编号、实际时间输入证据；强化主体、支撑、接触、运动轨迹与结束状态，区分相机运动和主体运动。不从图像杜撰配方、味道、功效或声音。阶段只概括可见事件，不把局部像素变化机械编成新镜头。
6. 输出仍经已有结构化观察编译器生成 `【视频概览】→【逐秒镜头】→【结束画面】`，标签与 Prompt 节点对齐；创意方向、六维解释同一段实际事件。

## 成本、数据与迁移

无数据库迁移、无共享 DTO 变化、无新增依赖。图片输入预算高于旧 12 帧，单次模型输入成本可能提高；短视频少采、长视频有界，模型调用次数仍为 1。不开启付费测试，不修改或重跑已有导入草稿。

## 验收

- 机械采样：首尾、真实时长、顺序、预算、强变化点选择和无效输入。
- 真实 FFmpeg：快切插入画面、实际 PTS、横竖画幅、单次提取、首尾保留。
- 生命周期：并发隔离、变化检测降级、抽帧失败、超时及取消回收。
- 识别：格式与 Prompt 节点一致，仍仅一次模型请求，原有旧 attempt、回调重试、冻结时长测试不退化。
- Worker 相关与完整单测、类型检查、`git diff --check`；无 UI 改动，因此不扩大前端回归范围。
