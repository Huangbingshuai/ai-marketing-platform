# 精修工作台字幕轨交互修复

## 范围

修 5 个用户报的问题，全部在「效果类混剪节点 → 精修工作台」的字幕轨上：

1. 字幕库「添加」出来的空字幕会各占一条轨，轨道头显示「字幕 1」「字幕 2」……应统一显示「字幕」。
2. 新增的字幕素材左右拖动「一卡一卡」。
3. 视频轨道头「主视频」应改成「视频」。
4. 点字幕素材后不要直接把焦点丢进文本框，否则按 Delete 删的是字幕文本而不是字幕素材。
5. Ctrl+Z 撤销失效。

第一轮改完后用户复测又报了两条（详见「追加修复」）：

6. 选中字幕之后播放针不要跟着移动过去。
7. 选中字幕之后按 Delete 删不掉字幕。

## 现状问题

### 1. 轨道头文案

`EffectTemplateMixTimeline.vue:298` 的 `TRACK_LABELS` 写死了 `VIDEO: '主视频'`，`:307` 的 `trackLabel()` 对字幕轨拼了行号：

```ts
if (isCaptionTrack(track)) return `${TRACK_LABELS.CAPTION} ${captionLaneOfTrack(track) + 1}`;
```

行号来自 `assignEffectTemplateMixCaptionLanes()`（`effect-template-mix-state.ts:409`）：**每张从字幕库新增的字幕都有自己的 `trackId`**（`EffectTemplateMixNodePage.vue:3908`），因此各自成组、各占一条 lane。这跟音频轨已经统一叫「音频」的做法（`AUDIO_TRACK_LABEL`，`EffectTemplateMixTimeline.vue:297`）不一致——行号是位置不是身份。

### 2. 左右拖动「一卡一卡」——两个独立缺陷叠加

**缺陷 A：拖动中被别的轨道的字幕夹住。** `EffectTemplateMixTimeline.vue:1869` 的 `captionBounds()` 按**全时间轴**的 start 排序取前后邻居当围栏，完全不看 lane：

```ts
const rows = [...timelineCaptions.value].sort((left, right) => left.start - right.start);
const index = rows.findIndex((row) => row.id === caption.id);
return { minStart: index > 0 ? rows[index - 1]!.end : 0, ... };
```

多轨字幕落地之后这是错的：新字幕在 lane 0、旧字幕在 lane 1，两者时间重叠是**正常**的，但围栏把新字幕夹在旧字幕的 `end` 和 `start` 之间。实测这组数据：旧字幕 0–3s，新字幕（播放头在 0）0–3s，排序后 `minStart = 3`、`maxEnd = 3`，代入 `onWindowPointerMove` 的 `requested = max(minStart, min(maxEnd - duration, initialStart + delta))`（`EffectTemplateMixTimeline.vue:2216`）得到 `max(3, min(0, delta))`——指针左移卡片钉死在 3s，右移要超过 3s 才开始动，读起来就是「一卡一卡」。

**缺陷 B：抬手后位移被丢掉。** `EffectTemplateMixNodePage.vue:3584` 的 `movePackagingAudios()` 是本次未提交改动里为「组拖 + 落点换行」新写的，它的落库判断只认 `audioClipPlacements()`：

```ts
const placements = audioClipPlacements(variant);
...
const shouldApplyMove = rowMoves.length > 0 || moves.some(({ clipId, start }) => {
  const placement = placements.find((entry) => entry.clipId === clipId);
  return placement !== undefined && Math.round(start * 30) / 30 !== Math.round(placement.start * 30) / 30;
});
if (!shouldApplyMove) return;
```

而 `audioClipPlacements()`（`:3526`）由 `timelineAudioClipRefs()` 生成，**只含口播 / 纯音乐 / 分离原声，不含字幕**（字幕在 packaging checkpoint 里，不在 variant 的音频字段里）。字幕拖动发的是 `moveAudioClip(id, start)`（无 row，`EffectTemplateMixTimeline.vue:2359`），于是 `rowMoves = []`、`placement === undefined`，`shouldApplyMove` 恒为 false，**函数直接 return，字幕位置从来没落过库**。HEAD 里 `movePackagingAudio` 是直接写 checkpoint 的（`git show HEAD:...NodePage.vue` 第 1556 行），所以这是本阶段重构引入的回归。

### 3. 点字幕素材抢焦点

`EffectTemplateMixNodePage.vue:1897`：

```ts
// Clicking a caption card opens its text editor, so the caret lands where the user looked.
watch(editingCaption, (caption) => {
  if (!caption) return;
  void nextTick(() => captionTextInput.value?.focus({ preventScroll: true }));
});
```

只要选中**单条**字幕（`editingCaption` 非空）就把焦点塞进上方那个 `<input>`（`:5599`）。而 `onEditorKeydown`（`:4403`）对 `input/textarea/select/[contenteditable]` 一律提前 return，所以 Delete 交给输入框删文本、Ctrl+Z 交给输入框的原生撤销（对程序化写入的 value 是空操作）。

更麻烦的是**焦点一旦进去就出不来**：时间轴的 `onCaptionPointerDown` / `onClipPointerDown` 都调了 `event.preventDefault()`（`EffectTemplateMixTimeline.vue:1907` 等），这会挡掉 mousedown 的默认行为，点别的片段**不会**让输入框失焦。

### 4. Ctrl+Z 撤销失效

`TimelineEditSnapshot` 只装 variant（`EffectTemplateMixNodePage.vue:321`）：

```ts
type TimelineEditSnapshot = { selectedSlotId: string; variant: EffectTemplateMixVariant };
```

但精修工作台里字幕、口播、纯音乐、字幕框几何都写在 `selectedPackaging.checkpoint` 上（`captionItems`，`:1681`；时间轴 `timelineCaptions`，`EffectTemplateMixTimeline.vue:571`）。于是：

- **新增字幕**走 `addCaption()` → `editPackagingAudio()`（`:3916`），`editPackagingAudio`（`:1572`）全程不调 `rememberTimelineEdit()` → 撤销栈里根本没有这一笔。
- **移动字幕**走 `movePackagingAudios()` → `rememberTimelineEdit()`（`:3619`）→ `applyAudioStart()` → `editPackagingAudio()`。快照进了栈，但它拍的是**没被改动过的 variant**；`restoreTimelineSnapshot()`（`:436`）把 variant 原样写回去，字幕纹丝不动 → 按 Ctrl+Z 视觉上「什么都没发生」。
- 删除字幕（`:3687`）、裁剪字幕（`:1628`）、字号（`:2256`）同样走 checkpoint，同样不可撤销。

这条在上一阶段的计划里是**显式非目标**（`2026-09-24-时间轴音频轨通用化与自由换轨.md`：「不统一撤销语义：行号写 variant（进撤销快照），start 写 checkpoint（不进）」），现在用户把它当 bug 报，等于要求把这个非目标收回。

## 改动

### 阶段 1：轨道头文案（`EffectTemplateMixTimeline.vue`）

- `:298` `TRACK_LABELS.VIDEO` 改成 `'视频'`。
- `:307` `trackLabel()` 的字幕分支去掉行号，直接返回 `TRACK_LABELS.CAPTION`（`'字幕'`）。多条字幕轨同名，与「音频 ×N」一致。
- `captionLaneOfTrack`（`:309`）仍被框选（`:2084`）和画布渲染（`:2813`）用来把 lane 映射回轨道 key，**保留**，只是不再进标题文案。

### 阶段 2：字幕横向拖动（两个缺陷一起修）

- `EffectTemplateMixTimeline.vue:1869` `captionBounds()` 先按 `captionLaneById.value` 过滤出**同 lane** 的字幕再排序取邻居。同 lane 内 `assignEffectTemplateMixCaptionLanes` 保证互不重叠，所以围栏正好是同一行的前后邻居；独占一行的新字幕没有邻居，围栏退化成 `0 .. timelineDuration`，整条时间轴自由移动（时间轴末端仍由 `onWindowPointerMove:2217` 的 `timelineDuration - duration` 兜住）。
- `EffectTemplateMixNodePage.vue:3612` `shouldApplyMove` 补上字幕：加一个 `captionStartOf(clipId)`（从 `selectedPackaging.checkpoint.captions ?? variant.captions` 取当前 start），`placement?.start ?? captionStartOf(clipId)` 一起比。字幕没有 row，`rowMoves` 天然为空，`variant.audioLanes` 的写入也碰不到它，其余逻辑不用动。
- `EffectTemplateMixNodePage.vue:1609` `applyAudioStart()` 的 CAPTION 分支现在只走 `editPackagingAudio`，没有 packaging 时会弹「包装尚未完成，无法编辑音频轨道」。补一条 variant 分支（改 `variant.captions` + `bump()`），和 `addCaption()` / `deleteSelectedTimelineItem()` 已有的双分支写法对齐，否则「没有包装时能加字幕但不能挪字幕」。
- `EffectTemplateMixTimeline.vue:2389` 字幕组拖原本对组内每条各发一次 `moveAudioClip`，`rememberTimelineEdit()` 是每次 `movePackagingAudios()` 调一次，结果一次手势压进多笔撤销记录。改成整组只发一次 `moveAudioClips`（`group.flatMap(...)`），一次手势一笔撤销。

### 阶段 3：焦点与删除键（`EffectTemplateMixNodePage.vue`）

- 删掉 `:1897` 的 `watch(editingCaption, ...)` 自动聚焦。输入框只在用户点它时获得焦点。
- 加一个 `watch(selectedCaptionIds, ...)`：选中集合变化时，若焦点还在 `captionTextInput` 上就 `blur()`。因为时间轴的 pointerdown 会 `preventDefault`，浏览器不会自己搬焦点，必须显式做。选中集合只在时间轴侧变化（点卡片、框选、清空选择），打字不会触发，所以不会打断输入。

### 阶段 4：把 checkpoint 纳入撤销快照（`EffectTemplateMixNodePage.vue`）

- `:321` `TimelineEditSnapshot` 扩成 `{ selectedSlotId; variant; packaging: { itemId; checkpoint; updatedAt } | null }`。
- `:423` `captureTimelineSnapshot()` 用 `cloneCheckpoint(selectedPackaging.value.checkpoint)` 一并拍下（`cloneCheckpoint` 已在用，见 `:1587`）。
- `:445` `restoreTimelineSnapshot()` 在写回 variant 之后，把 checkpoint 写回 `selectedPackaging.value.checkpoint`，再 `scheduleAudioEdit()`。`audioBaseline` 沿用 `editPackagingAudio()` 的写法（`:1588`）——**只在当前 item 还没有 baseline 时**才把它指向还原前的 checkpoint：这样 `flushAudioEdit()` 的 `audioDiff` 算出来的正是「还原后的状态 vs 服务端状态」，撤销结果会被推到服务端，而不是因为 `audioBaseline` 为空被静默丢掉。之所以不能无条件覆盖 baseline：如果上一笔编辑还在 250ms 防抖窗口里没发出去，服务端持有的仍是**更早**的 checkpoint，覆盖成「还原前」会把服务端推到一个它本来就是的状态，白跑一次请求并白白推进 `updatedAt`。
- 写回 checkpoint 的前置条件与 `editPackagingAudio()` 对齐：`item.id === snapshot.packaging.itemId`、有 `runId`、`status === 'COMPLETED'`、`!item.stale`。任一不满足就只还原 variant，不做半吊子的本地还原（否则那笔还原永远推不出去，下一次编辑的 baseline 会把还原后的状态当成服务端状态，diff 里丢掉这次撤销）。
- 补 `rememberTimelineEdit()`：`addCaption()`（`:3885` 两个分支都要）、`deleteSelectedTimelineItem()` 的字幕分支（`:3689`）、`resizePackagingAudio()` 的 CAPTION 分支（`:1645`）、`changeCaptionScale()`（`:2263`）。
- **不**给 `setCaptionText()` 加快照：它绑在 `@input` 上，每次按键都会压一条。文本框内的撤销交给输入框原生行为，和主流剪辑器一致。这条写进「非目标」。

## 追加修复（第二轮：用户复测后）

### 6. 选中字幕不再移动播放针

`EffectTemplateMixTimeline.vue:1963` 的 `onCaptionPointerDown()` 里有一句 `emit('seek', Math.max(0, caption.start));`——全组件只有两处 `emit('seek')`，另一处是 `seekFromClientX()`（`:1081`，真正的拖拽/点标尺手势）。也就是说**只有字幕卡片这一种素材在选中时会seek**，音频块和视频块都不会。`:1987` 的注释已经写明了规则：「标尺和播放针是仅有的两个例外：两者都是 scrubbing 手势，所以它们 seek 而不动选中集。素材块就是素材，点它就是选中它。」字幕卡片属于素材块，跟着 seek 是多余的，读起来像「点一下字幕时间轴就跳」。删掉这一句即可，拖动时也不再跳。

### 7. 选中字幕后 Delete 删不掉字幕

`EffectTemplateMixNodePage.vue:4475` 的键盘守卫里有一条「目标是 `<button>` 就提前 return」：

```ts
target?.matches('button') &&
  !target.closest('.transition-junction') &&
  !activeTransitionSlotId.value;
```

而字幕库的「添加」按钮就是一个普通 `<button>`（`:5059`，`@click="addCaption"`，没有 `preventDefault`）。点它 → 焦点留在按钮上 → 新字幕被选中 → 按 Delete，`event.target` 是那个按钮 → 守卫 return → **什么都不会发生**。`Ctrl+Z` 同理被吞。

上一轮把「选中即自动聚焦文本框」删掉之后，焦点不再被搬进 input，于是这个按钮守卫第一次真正挡住了 Delete——用户看到的就是「以前删的是文本，现在什么都删不掉」。

守卫的本意是「不要把按键从交互控件手里抢走」，但按钮实际只会消费 **Space 和 Enter**（Space 触发点击、Enter 提交），Delete / Ctrl+Z / 方向键在按钮上本来就没有语义。所以把这条收窄成「按钮只拥有 Space 和 Enter」：

```ts
const buttonOwnsKey =
  Boolean(target?.matches('button')) &&
  !target?.closest('.transition-junction') &&
  !activeTransitionSlotId.value &&
  (event.code === 'Space' || event.key === 'Enter');
```

顺带把上一轮的 `watch(selectedCaptionIds, …)` 换成一个工作台级的捕获阶段 pointerdown（`onWorkbenchPointerDown`，绑在 `<section class="panel workbench">` 上）：**指针落在文本框以外就把焦点从文本框收回来**。原因是 watch 只在选中集**变化**时触发，而「点已经选中的那张字幕卡」不会改变任何值 → 不触发 → 文本框仍然握着键盘 → Delete 还是进文本框。捕获阶段 pointerdown 不依赖任何值变化，也不碰时间轴 shell 自己的焦点（只 `blur()` 那一个 input），所以不会影响时间轴的 Ctrl+C/V。

## 非目标

- 不动包装 Worker、成片输出契约、字幕渲染（字号/位置）的产物语义。
- 不重做撤销模型：仍是「编辑前拍快照 + 栈式回滚」，不引入命令模式或 diff 合并。
- 文本输入框内的逐字撤销仍走浏览器原生撤销，不进时间轴撤销栈。
- 不改轨道锁定 / 静音 / 显示的行为。
- 不给字幕轨加「新增轨道 / 删除轨道」按钮：轨仍随字幕存在与否自动出现和消失。

手工回归（需要跑起前端，逐条对应用户报的现象）：

1. 字幕库点「添加」三次 → 轨道头全是「字幕」，视频轨是「视频」。
2. 把新加的空字幕左右拖 → 跟手、不粘滞、松手停在新位置（刷新后仍在）。
3. 点字幕素材 → 焦点不进文本框，按 Delete 删掉的是字幕素材本身。
4. 点文本框 → 焦点进入，可正常打字；此时 Ctrl+Z 是文本框内的原生撤销。
5. 加一条字幕 → Ctrl+Z 字幕消失；再 Ctrl+Shift+Z 回来。移动/裁剪/删除/改字号同样可撤销。
