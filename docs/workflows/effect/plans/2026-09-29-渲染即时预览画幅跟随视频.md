# 渲染节点即时预览：画框跟随视频，而不是跟随画幅设置

## 用户反馈

「这个渲染节点的即时预览按钮的功能进入编辑和不进入编辑有所区别，修复 Bug，按道理说没有区别才对，不进入编辑的时候即时预览功能有问题，进入才正确。」

## 根因：画框由「画幅设置」决定，而设置是可变且只对新任务生效的

`EffectSegmentRenderNodePage.vue` 的 `effectSegmentRenderFrameStyle()` 用 `renderSettings.value.ratio`
算 `.large-preview` 的 `aspect-ratio` 与宽度，`.large-preview video` 是 `object-fit: contain`，所以画框比例
一旦和视频自身比例不一致，视频就会缩在画框里留黑边。

而 `renderSettings` 来自 `workspace.settings`，即该 Run 的 `SEGMENT_RENDER_SETTINGS:<productId>`
节点状态（`effect-segment-render.service.ts` 的 `settingsFromState(nodeState) ?? legacySettings(prompt.payload)`）。
这个设置**只作用于新建任务**（页面自己的文案：「画幅和分辨率只用于新的视频任务，不会让 Prompt 或提炼结果过期」），
所以「设置里的画幅」和「已渲染素材的画幅」本来就可以不一致。

两种模式因此解析到不同的比例：

| 状态     | settings 来源                                       | 比例         | 视频真实比例 | 结果             |
| -------- | --------------------------------------------------- | ------------ | ------------ | ---------------- |
| 非编辑态 | 该 Run 的节点状态（用户改过，可能已过期）           | 用户当前设置 | 历史渲染参数 | 画框与视频不一致 |
| 编辑态   | 隔离子 Run **没有**克隆设置节点状态 → 落到默认/旧值 | 默认值       | 同上         | 恰好一致         |

真机证据（项目 `65458686` 广式腊肠，同一条 560×752 的素材，探针实测 `.large-preview` 与 `<video>` 尺寸）：

```
修复前
[编辑态]   settings 画幅 9:16    frame 251×446  ratio 0.563   video 560×752 ratio 0.745  ← 不一致
[非编辑态] settings 画幅 3:4     frame 335×446  ratio 0.750   video 560×752 ratio 0.745  ← 一致

修复后
[非编辑态] settings 画幅 3:4     frame 332×446  ratio 0.745   video 560×752 ratio 0.745  ← 一致
[编辑态]   settings 画幅 9:16    frame 332×446  ratio 0.745   video 560×752 ratio 0.745  ← 一致
```

用户那边看到的正是镜像：紫苏梅子酱的 Run `95c92da8` 在 06:47 按 9:16/720p 渲染完 20 条素材，09:18:23
把设置改成了 1:1/480p/SEEDANCE_1_0，于是非编辑态画框 1:1、视频 9:16 → 预览明显不对；进入编辑后子 Run
没有设置节点状态、落到 9:16 → 反而「正确」。

## 改法

`apps/web/src/workflows/effect/segment-render/EffectSegmentRenderNodePage.vue`

- `effectSegmentRenderFrameStyle(maxHeightVh, videoSize?)`：拿到视频自身宽高就按它定画框，只有元数据
  到达前才退回当前设置的画幅占位。
- 新增 `previewVideoSize` / `repairVideoSize`，在两个弹窗的 `<video>` 上挂 `@loadedmetadata`
  读取 `videoWidth/videoHeight`；`clearPreview()` 里一并清空，避免上一条素材的尺寸残留。
- 即时预览与画面返修共用同一画框算法，两处一起跟随视频。

没有动服务端、契约或设置本身：**设置是否要跟着 fork 克隆**是另一个独立缺陷（见下），
本次只让预览画框不再依赖它。

## 测试

`apps/web/src/workflows/effect/segment-render/effect-segment-render-layout.spec.ts`
「sizes the immediate preview frame from the video itself, not the mutable render settings」：
断言画框优先取 `videoSize`、设置仅作占位、两个弹窗都挂了 `@loadedmetadata`、`clearPreview` 清空尺寸。

画面返修弹窗里的参考视频同样。

## 遗留（本次不改）

隔离编辑子 Run 不克隆 `SEGMENT_RENDER_SETTINGS` 节点状态，于是进入编辑后画幅/分辨率/模型显示为默认值
（实测 65458686：父 Run 3:4/480p/SEEDANCE_1_0，子 Run 9:16/720p/SEEDANCE_2_0）。这不只影响预览显示：
在编辑态直接点「重新渲染」会按这套默认参数提交付费任务。该缺陷落在
`apps/api/src/platform/workflow/effect-edit-session.ts` 的 fork 逻辑里，与并行会话正在改的自动分支
（`editSessionNodeId` 置空、克隆重映射）同一文件，需排期避让后再修。
