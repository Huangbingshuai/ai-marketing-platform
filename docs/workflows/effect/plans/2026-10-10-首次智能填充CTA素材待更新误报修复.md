# 首次智能填充 CTA 素材待更新误报修复

## 已核实原因与边界

- 效果类模板混剪读取当前已确认 `render-clip` / `render-batch`。广式腊肠当前渲染素材池 revision 5，有 33 条有效素材；首次智能填充生成 31 个工程，其中 5 个引用 R-032。
- R-032 的文件、工作副本 revision 1 均有效，生成后没有出现替换差异。其 `primaryPurpose=CTA` 是当前 Prompt/渲染合法值，但混剪读取只接受 `END_CONVERSION`，导致素材库漏掉它，仅引用该素材的工程出现来源不可用提示。
- 修复仅位于 API 消费读取边界，将共享 Prompt 用途规范化后投影为既有混剪用途；保持混剪六槽位、模型自主归槽、实际素材绑定与 revision 不变。不清除真实替换/删除/文件异常，不回写或重生成工程。

## 实施

1. 复用共享 `normalizeEffectPromptFragmentType`，把 `CTA` 及可确认的历史用途投影至混剪用途，保留 `END_CONVERSION` 兼容读取；主用途和兼容用途共用映射。
2. 更新混剪工作区和 sources 的读取投影缓存版本，避免已缓存的 32 条结果继续误报。其他项目/Run 缓存隔离规则不变，不全局清空 Redis。
3. 补充现行四用途、历史用途、未知用途、同文件克隆、真实来源变更与只读不增 revision 测试。

## 验证

- 首次填充的 CTA 素材仍在素材库，引用工程无净差异；真正换文件、删除与不可用仍提示待更新。
- API 单测、类型检查、构建、相关 Contracts/Web 差异展示回归、`git diff --check`。
- 确认无活动任务后按已有开发 watcher 生效，读取真实 API 验证素材池恢复 33 条、该模板待更新为 0；浏览器确认模板列表与画布同步。
- 不启动付费模型任务，不修改真实工程或清理历史文件，不自动提交 Git。
