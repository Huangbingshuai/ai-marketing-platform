# 连续渲染更新后的混剪目录净差异同步

## 事实与边界

- 效果类渲染 → 模板混剪。上游采用已保存的 render-batch/render-clip；下游工程按自身 bindingSources/bindingRevisions 比较，不推进未更新工程的基准。
- 广式腊肠服务端已同时计算 R-006、R-016 的替换、明确删除及 R-035/R-036 两条新增。当前模板列表分别投影不同工作流；轻量来源轮询只刷新当前可写 Run，其他模板及瞬时切换缓存留在上一轮。
- 本次只修复来源投影刷新与异步隔离，不创建队列、任务、分支或数据库状态，不自动执行付费混剪、包装或导出。

## 实施

1. 使用既有 sources 接口刷新目录内每个不同的当前模板 Run，复用共享净差异算法；不同模板的采用基准保持独立，不要求计数一致。
2. 原位刷新目录条目、待追加计数及瞬时切换缓存的素材来源；不覆盖用户编辑、选择、播放或滚动位置，不全页重新挂载。
3. 非当前 Run 的工程草稿 revision 若已变化，读取该 Run 的最新只读工作区，不能将新来源计数与过期工程组合；当前可写 Run 继续沿现有编辑冲突和刷新边界。
4. 单个模板来源读取失败保留其上次结果；项目/Run/目录切换、删除或编辑后的迟到响应不能覆盖新状态。目录异步加载迟到时保留已刷新来源投影。

## 验证

- 执行型 Web 回归：连续两轮素材变化，新增后删除抵消、替换只到最新版本、删除与替换并存、未选择模板同步、瞬时切换不回退、失败及迟到请求隔离。
- 复用 Contracts/API 净差异测试，Web 类型检查及构建，git diff --check。
- 只读浏览器检查真实模板列表；不制造真实编辑、不启动付费任务、不自动提交 Git。

## 实施与验证记录

- 目录轮询按不同模板当前 Run 去重读取 sources；原位刷新目录条目、待追加数量和瞬时切换缓存。远端工程 revision 变化才额外读取该 Run 的完整工作区，未变化时不重载工作台。
- 请求作用域、目录身份、草稿编辑令牌和 revision fence 共同拒绝迟到响应；逐 Run 的读取代际防止后返回的目录/工作区请求撤回已安装的新来源。代际仅用于浏览器异步排序，不是业务 revision 或新来源状态。
- Web 六个测试文件 86 项通过（含新增 14 项来源目录回归）；Contracts 净差异 10 项及 API 混剪服务 107 项通过。API 实库生命周期测试本次未启用，明确跳过 1 项；未修改 Worker 或执行付费生成。
- `pnpm --filter @ai-marketing/web typecheck`、`pnpm --filter @ai-marketing/web build`、`git diff --check` 通过。构建保留现有大块体积提示。
- 真实广式腊肠页面：测试1/测试2分别显示 18/15 条工程待更新，均显示 2 条新增。来回切换及后台轮询后数量不回退，当前模板未重置。1920×1080、1440×1000、1024×900 检查提示可见，尺寸已恢复；未编辑真实素材来人为构造两轮来源变化，连续变化由执行型测试覆盖。
