# 效果类目标受众与全局分辨率贯通实施方案

## 1. 范围与问题

本次涉及效果类工作流的“资料导入 → AI 信息提炼 → Prompt 生成”三段既有链路，不新增节点、不新增第二套视频配置，也不实现视频渲染。

- `targetAudiences[]` 是营销洞察的规范受众事实列表，但 Prompt 的“提炼信息应用映射”仍只读取历史兼容摘要 `targetAudience`，导致多个受众被合并成一个事实，无法在批次内轮动使用。
- `resolution` 已存在于全局视频配置、营销洞察结果和 Prompt `renderProfile`，但资料导入页面没有可见配置项，Prompt 映射阶段也没有把它登记为结构化全局约束。
- 资料导入契约仍列出 `2K / 4K`，与当前火山方舟创建视频生成任务接口的 `resolution` 枚举不一致。

## 2. 契约与数据流

- 全局视频配置继续使用既有 `EffectVideoConfig` WorkingArtifact，新增的是可见且受约束的“分辨率”编辑项，不建立新表或新状态。
- 分辨率值收敛到火山方舟 API 的 `480p / 720p / 1080p`；Seedance 2.0 的默认值采用官方默认 `720p`。
- 历史已保存的 `480P / 720P / 1080P` 通过大小写归一化继续有效；不再允许新配置使用 `2K / 4K` 或任意自定义字符串。
- AI 信息提炼继续把生效全局配置中的分辨率写入营销洞察结果，Prompt Run 继续冻结该营销洞察 WorkingArtifact 的 `artifactId + revision + contentHash`。
- Prompt 映射新增 `RESOLUTION` 约束事实。它进入覆盖指标和节点详情，但不进入单条 Prompt 正文；后续视频任务继续从批次级 `renderProfile.resolution` 读取。
- `targetAudiences[]` 中每个非空、非不确定条目分别生成一个 `TARGET_AUDIENCE` 必须事实；仅当规范数组缺失或为空时，才回退读取历史 `targetAudience` 摘要，避免双重映射。

## 3. 交互

- 资料导入的“全局视频配置”增加“分辨率”下拉项，只允许选择火山接口枚举。
- AI 信息提炼的“制作规则层”同步展示同一分辨率下拉项，沿用信息卡自动保存；这里同样只能选择 `480p / 720p / 1080p`，不能创建自定义值。
- 旧草稿若保存的是大小写不同的合法值，页面仍可显示并在下一次选择时写回规范小写值。
- 修改并确认全局视频配置后，沿用既有 revision 和下游待更新机制；Prompt 不直接依赖页面草稿。

## 4. 验收

- 受众数组中的多个受众形成多个稳定事实 ID，并能被现有事实分配器用于不同创意候选。
- 旧版只有 `targetAudience` 的输入仍能映射；同时存在数组和摘要时只采用数组。
- 分辨率出现在全局视频配置页面、信息提炼“制作规则层”、节点真实详情、Prompt 映射的 `appliedConstraints` 和最终批次 `renderProfile`，不出现在 Prompt 正文。
- `480p / 720p / 1080p` 可保存；大小写不同的历史合法值兼容；`2K / 4K` 和任意值被服务端拒绝。
- 执行 Contracts、API、Web、Worker 的定向测试、类型检查/构建和 `git diff --check`。

## 5. 实施结果

已完成：

- 资料导入页面与 AI 信息提炼“制作规则层”均新增分辨率选择，选项固定为 `480p / 720p / 1080p`；历史大写合法值按火山接口格式展示并在下次保存时规范化，服务端拒绝不支持值。
- `targetAudiences[]` 逐项映射为独立 `TARGET_AUDIENCE` 必须事实；数组为空时保留旧摘要回退，不重复映射。
- Prompt 内部契约和 JSON Schema 新增 `RESOLUTION`，Worker 将其登记到 `appliedConstraints`；批次 `renderProfile` 与 Worker 缺省值统一为 `720p`。
- Contracts 全量 17 项、API 全量 297 项、Web 全量 159 项测试通过；Prompt Worker 168 项通过、1 项显式集成测试跳过。
- Contracts、API、Web TypeScript 类型检查通过；Worker mypy 20 个源文件无错误，定向 ruff 通过；API 与 Web 生产构建通过；相关 ESLint、Prettier 和 `git diff --check` 通过。
- 浏览器在现有资料导入工作区确认分辨率字段可见，历史 `1080P` 显示为规范 `1080p`，下拉框只有三项火山接口枚举；窄屏配置卡无横向溢出，控制台无错误。本次只读验收，没有修改用户现有草稿。
