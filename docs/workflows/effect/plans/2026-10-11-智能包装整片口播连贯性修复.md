# 智能包装整片口播连贯性修复

日期：2026-10-11。范围：效果类模板混剪内的智能成片包装。

## 调研与采用点

- [MoneyPrinterTurbo 的脚本生成](https://github.com/harry0703/MoneyPrinterTurbo/blob/main/app/services/llm.py)：按视频主题生成整条脚本，并把脚本作为后续素材选择的上下文。采用整片叙事单位，不复制其 Prompt、供应商适配或素材检索实现。
- [ShortGPT](https://github.com/RayVentura/ShortGPT)：官方说明将脚本生成、配音、字幕、编辑组织为同一内容生产链。只借鉴内容统一编排的分工；未验证其当前实现的口播质量，不引用为质量保证。
- [Descript Quick Design](https://help.descript.com/ai-assistant/quick-design)：由脚本或转录拆分逻辑场景。采用脚本主线与镜头分段相区分的思路，不引入其软件、素材或服务。

这些项目不能直接保证本系统的营销文案质量。这里采用的是结构设计：整片先统一叙事，再按已固定的素材边界输出独立口播。

## 已查证原因

`plan_script` 虽一次返回多槽文案，但任务与规则明确强调每槽分别策划、各讲各的画面；结构修正只带问题槽，局部生成、超时重策划和局部缩句缺少完整成片及未修改口播上下文。这会诱导各槽重新介绍商品、重复主语，且修复路径会再次打断原本的衔接。上述是代码层机制分析，不把用户反馈冒充已经执行的真实模型评测。

## 边界

- 上游仍为冻结的同项目、同 Run 时间轴工程、实际素材与 Prompt 的工作副本 revision，以及依赖链中已确认的产品事实。
- 工作副本仍为 `timeline-project:<templateId>:<variantId>` 与 `timeline-package:<templateId>:<variantId>`，READY 经原 API 校验和事务提交；失败、旧 attempt 和取消不改变原有语义。
- 下游仍为用户主动触发的成片输出；不自动重写历史文案、不批量重包装、不重导出旧视频。
- 文案按整片统一创作，音频/字幕仍按槽位独立落地，不跨素材。空槽、间隙、人工移动和删除的非目标轨道保持原样。
- 不改变队列、API/Contracts、任务数量、版本树、TTS 音色、字幕时间戳或音乐独立音量。不增加内容审核环节、关键词去重、商品名称替换或额外语义重试。

## 实施

1. 建立只读整片上下文：按真实播放顺序传递所有非叠加素材的用途、时间、画面理解、既有口播和本次可写槽位；上下文不执行全片重校验，也不写检查点。
2. 统一通用写作规则：一条叙事主线、稳定说话视角、信息递进；商品身份只在需要时出现，避免逐镜重新开场；衔接不等于虚构因果或把不同镜头说成同一次连续动作。
3. 首次/恢复缺失文案、结构修正、真实配音超时缩句及重策划都携带整片上下文；仍只应用目标槽位返回内容。
4. 不增加语义审核或付费调用，保留原来的机械修正次数、成功配音和音乐恢复边界。
5. 同步业务指南和 Worker 说明。

## 验收

- 以食品、日用品、软件服务等合成事实测试上下文投影和通用规则，不在生产代码加入产品特例。
- 覆盖时间顺序、空槽/间隙、叠加素材排除、局部恢复和单槽更新、修正前后完整上下文、超时缩句/重策划、邻句与成功音频不被改写。
- 验证正常一次规划不增加模型请求；语义是否重复不由关键词硬拒绝；沿用来源、ID、事实引用与时间机械校验。
- 运行相关 Worker pytest、mypy 与 `git diff --check`。真实 Ark/TTS/音乐质量验证需另行明确授权，不能用 Mock 测试冒充。
- 生效前检查任务及队列；有活动任务则不重启消费者。

## 迁移

无需数据库或跨进程契约迁移。只对用户之后主动启动、尚需文案规划/修正的步骤生效；已成功保存的文案、配音和字幕不会因升级自动重做。
