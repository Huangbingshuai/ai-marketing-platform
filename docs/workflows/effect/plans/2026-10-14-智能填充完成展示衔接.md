# 智能填充完成展示衔接

## 范围和证据

效果类第五节点模板混剪，直接消费同项目/Run 已确认素材及其实际 revision 和模板冻结输入。现有 API 先完成任务及草稿写入，再确认 `mix-template:<templateId>`、`timeline-project:<templateId>:<variantId>` 并发布分支。Web 目前仅把 QUEUED/RUNNING 视为显示进度，任务完成即隐藏，结果读取、revision fence 或分支发布等待仍未完成；完成处理又会中止原轮询控制器，使后续读取异常无法继续跟踪。

只修改 Web 展示与结果读取恢复，不改 Contracts/API/Worker、业务提交或上下游边界。下游仅画面待渲染工程仍由原服务端自动提交，不编码、不生成音频、不创建第二套任务或修改付费重试预算。

## 实施

- 保留真实完成回执，按项目、来源 Run、执行 Run、模板和任务身份记录待载入结果；不伪造 RUNNING 状态或时间增长百分比。
- 复用原 `WorkflowRunProgress`，完成回写期间显示“正在同步成片工程”；确认输出工程、模板提交和解锁状态均已载入才隐藏。
- 原位任务保留目标模板锁；后台重新填充不清空或锁定父分支。分支发布及子工作区读取等待期间持续展示原进度，切换到正确工程后收起。
- 结果读取失败、旧 revision 或草稿保存冲突保持原内容，自动续读；失败/取消仍使用真实终态，不显示虚构完成。
- 保留草稿队列、revision fence、切换作用域检查和原成片选择；迟到响应不能跨项目、模板或 Run 安装。刷新时恢复实际锁定模板尚未载入的完成任务。

## 验收

单测覆盖完成回执先到、慢读取、未确认/旧快照、读取失败自动恢复、切换模板/Run/项目、后台分支发布等待和首次载入。执行相关 Web 单测、类型检查、构建和范围内 `git diff --check`。浏览器以明确隔离网络响应验证 1920、1440、窄屏和状态衔接；不执行付费生成，不重启服务、不提交 Git。

## 原型与迁移

已打开 `references/prototypes/effect/effect-mix-workbench.html`。工作台壳、三栏播放器、时间轴及按钮位置保持不变，复用正式进度组件，仅修正完成等待阶段的显示条件。无数据库/历史数据迁移，不自动重跑历史任务。工作区已有大量改动，仅补丁修改本任务范围。

## 实施结果

已完成 Web 修正，相关 96 项测试及含类型检查的构建通过，桌面/窄屏隔离浏览器回归通过。[验收记录](../evidence/browser/2026-10-14-fill-result-handoff.md)列明截图、范围与扩大测试中的 22 项未通过断言；不宣称全量通过或已验证付费生成。
