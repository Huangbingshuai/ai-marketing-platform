# 模板混剪包装：短槽位配音超时自动恢复

## 范围与非目标

- 只修复智能成片包装中“原文配音超时、同槽位缩句一次后仍超时”的可恢复失败。
- 保持每个槽位一条口播、标点逐段 TTS、真实采样边界字幕、槽位时间边界及已确认事实校验。
- 不新增容器、队列、Run 或整批隐式重跑；不自动重做成功槽位、音乐或视觉理解。
- 不对来源失效、未授权音色、配置缺失、音乐提交结果不明等错误自动重新付费。

## 数据与执行

- 在包装检查点记录每槽位一次自动重策划额度，并由 API 校验槽位 ID 与次数。用户主动重做该槽位时清除额度。
- 第二次配音仍越界时，Worker 收齐同成片并发槽位的结果，再只针对超时槽位重新策划一条较短、适合该槽位的口播。4 秒槽位优先无内部断句标点。
- 重策划使用原冻结画面和确认事实；新文案通过已有结构与事实引用校验。保留其他槽位脚本、已上传配音和音乐。
- 新文案可按现有规则缩句一次；若仍超时，保留检查点并标记失败，供用户手动单槽位重做。
- 断点恢复只处理缺失槽位；租约、取消、旧 attempt 回写继续沿用现有机制。

## 验证

- Fake Provider 验证短槽位首次失败后自动重策划成功、额度用尽后失败、其他成功槽位和音乐不重复请求。
- API 验证额度字段只接受冻结槽位的一次记录；单槽位主动重做清除该槽位额度。
- 运行 Worker、API、Contracts 相关测试及类型检查、`git diff --check`。
- 本次不自动发起新的真实付费批次；真实效果在用户下次主动包装时观察。
