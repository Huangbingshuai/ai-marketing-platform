# 重新填充按素材变化归槽

## 范围与边界

- 效果类模板混剪；首次包装及重新包装遇到当前模板待处理新增、编辑、删除素材，须先局部更新，创建编辑分支前返回明确提示。
- 重新智能填充直接冻结同项目、同来源谱系的最新已确认素材，不要求先局部更新。仍在独立子 Run 生成当前模板的新批次，不修改父分支或其他模板。
- 最新需求覆盖早先纯新增规则：只要素材库有新增、编辑、删除或混合更新，重新填充对最新全部有效素材全量重新分类、匹配、截取。槽位时长不能超过素材真实时长。
- 不区分纯新增与新增后又编辑；不拼接旧归槽快照。既有全量重填路径已满足此策略，增加回归验证而非建立第二套策略。
- 即使此前已完成局部更新，重新智能填充仍将最新全部素材重新归槽，不沿用局部更新后的归槽结果。

## 数据与实施

- 复用现有任务输入快照、分类检查点及 materialRoleAssignments，无新增工作流、状态表或跨进程 DTO。
- 整批重新填充不复用旧归槽、人工归槽、选片或截取；Worker 继续使用已有全量分类流程。仅同任务失败恢复保留合法检查点。
- 归槽时继续复用既有合法时长过滤与六槽位匹配，不按文本关键词推测语义。
- 无数据库迁移；历史任务、同任务失败恢复与新增素材局部追加保持既有语义。原有在途包装的截取协议保留，但新包装不再静默处理源素材替换。

## 验收

- 包装/重新包装：新增、编辑、删除以及分支创建期间的素材变化均拦截；当前模板无变化不受其他模板影响；局部更新后正常包装。
- 重新填充：新增（含新增后编辑）、编辑、删除、混合、先局部更新后重填、缺失历史及短素材边界。
- 单测验证最新素材输入快照、不继承初始分类及用途；Worker 测试验证全量素材发往模型分类，重新选片与截取仍覆盖全新批次。
- API/Web 类型与构建、Worker 相关测试及语法检查、git diff --check；不启动付费任务。

## 验证结果

- API 包装、混剪服务及领域测试 154 项；Web 素材更新与独立进度测试 23 项；Worker 消费、源素材更新与填充重试测试 43 项，合计 220 项通过。
- API/Web 类型检查及构建通过；Worker 语法检查与本次涉及文件的 `git diff --check` 通过。
- 已重启本地 API 加载修复，健康检查返回 200。对测试2首次包装分支及已有包装分支分别验证，均返回 409 与“当前模板有素材待更新，请先完成局部更新，再进行智能成片包装。”。
- 实际拦截验证前后分支数量均为 10，检查无排队或运行任务；未执行付费填充、包装或成片渲染。全量重填分类行为通过冻结快照与 Worker 模型调用替身验证，未声称实际模型生成已完成。
