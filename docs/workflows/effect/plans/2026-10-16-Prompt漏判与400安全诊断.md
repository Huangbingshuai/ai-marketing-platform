# Prompt 漏判修复与供应商 400 安全诊断（本地）

## 范围与边界

效果类素材 Prompt 节点，沿用任务冻结的 marketing-insight artifact/revision（前轮本地 revision 1，测试时重新核实），输出仍为 prompt-batch。完整成功通过服务端校验才发布新分支，失败不修改父分支或下游。保持 Turbo、评分模型、八阶段和数量/淘汰规则。仅修改 Prompt Worker 内部诊断、生成/修订指令与供应商安全诊断，不部署服务器、不渲染视频。

## 已观察原因

上一轮逐拍 evidence 仍是概述，无法明确区分主体/接触/遮挡变化与单纯景别变化；手部占用未逐拍记录，盖子到工具的缺口漏判；机位描述未单独判定是否自相矛盾。定向重写虽回应问题 ID，仍保留未被指出的跨拍矛盾。

上一轮 HTTP 400 的供应商响应未保存，不能恢复历史细分原因。现有 Provider 统一归为 REQUEST_REJECTED，缺少可安全用于定位的状态码、供应商错误码与请求 ID。400 不能直接等同内容审核或参数错误。

## 实施

- 独立诊断逐拍补充变化类型与真实增量、左右手/工具/承重点起止状态、相机运动类型及冲突判断、工具交接是否缺失。新请求要求这些紧凑字段，历史检查点继续可读；内容/模板指纹变化失效重诊断。
- 对 AI 已明确标出的镜头冲突/交接缺失，机械补齐未列入 issues 的引用，仍进入定向改写，不拒绝候选。仅景别变化/静止的枚举本身不自动判错，不设停留比例或动作数量门槛。
- 生成与修订明确：观察距离不是商品事件；连续停留需基于真实新揭示；占用的手先把原物落到具体承重面，再取工具；固定机位、固定角度与平移推进不能混称。修订对完整动作链负责，不能只更改被引用拍或辅助说明。
- 定向修订请求 Schema 明确 changed=true、非空完整替换字段与 resolutions，减少此前 changed 与替换内容矛盾造成的结构重试；这是协议约束，不提高语义拒绝门槛。
- Provider 记录安全诊断：HTTP 状态、已知错误码类别、未知错误码哈希、格式校验过的请求 ID、请求/Schema 哈希。禁止原始错误 message、响应正文、输入和凭证进入日志。未知 400 仍停止，不盲重发，不绕过安全策略。

## 验收

受控测试覆盖新诊断字段、辅助说明隔离、AI 显式冲突引用补齐、正常项不改写、定向改写 Schema、旧检查点兼容、隐私日志和 400 不重试。执行 Worker pytest、mypy、diff 检查并提交。确认本地无活动 Prompt，更新对应 Worker 后通过浏览器只启动一轮本地广式腊肠 30×15 秒、AI_AUTO 付费生成；报告 HTTP 结果、诊断/改写统计、真实正文逐条风险、耗时和重复度。失败保留草稿，不另开第二轮。

官方错误码参考：https://docs.volcengine.com/docs/ark/error-codes?lang=en（2026-10-16 查阅；用于已知错误码分类，不证明上一轮 400 的原因）。
