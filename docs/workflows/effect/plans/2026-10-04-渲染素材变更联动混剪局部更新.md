# 渲染素材变更联动混剪与成片局部更新

## 已确认范围

渲染节点确认素材变更后，混剪素材库读取当前分支最新的 `render-clip` 工作副本，只把实际使用变更素材的模板、工程和对应成片标为“待更新”。成片输出节点是局部更新的唯一入口。用户主动点击后，由模型重新选择截取起点，仅重做受影响槽位的口播和字幕；成功后覆盖当前分支的混剪工程、包装和成片，不创建新分支。

不沿用原素材的截取起点。时间轴位置、槽位时长、轨道、转场、其他槽位、音乐及手工字幕保持原样。重新智能填充、重新完整包装仍创建独立新分支，使用新分支启动时最新素材，父分支不变。不因检测到变更自动发起付费任务。

## 工作副本和依赖

- 上游：同项目、效果类 Run/模板路径可见的已提交渲染片段、活动渲染批次，以及任务启动时重新冻结的已确认可信事实与 Prompt 依赖。
- 草稿：`WorkflowNodeState(TEMPLATE_MIX)` 保存模板与独立时间轴工程；轮询素材不会覆盖未保存编辑。
- 输出：`timeline-project:<templateId>:<variantId>`、`timeline-package:<templateId>:<variantId>`、对应成片 item 和 `final-delivery:<templateId>`。
- 提交：素材选区、配音与字幕先写任务快照；最终视频校验落盘成功后，在事务中同步当前工程和包装及输出引用。新视频成功前旧视频及当前工程保持可用。
- revision：消费真实 `artifactId + revision + contentHash`。局部更新成功增加内容改变的工作副本 revision，不增加分支。模板聚合只有全部依赖恢复当前后才清除待更新。

## 实现

### 1. 素材身份与刷新

复用现有素材读取、同文件去重与来源保护。素材增加可选 `sourcePromptId` 和 `activeSource`：活动批次成员属于可选素材，旧工程仍绑定的归档素材仅供播放。空的已确认批次不回退为全部旧素材可选。

同 artifact ID 按绑定 revision 检测；新 ID 只在相同稳定来源身份且可用文件唯一时替换，不按名称、文案或文件名猜测。无法确认、映射有歧义、文件不可用或新素材比槽位短，保留旧结果并说明不能自动更新的原因。项目、Run、模板路径隔离沿用原有权威工作副本规则。

混剪页面每 5 秒读取轻量素材响应；停用/卸载停止轮询、取消请求，忽略切换项目或 Run 后的迟到响应。源刷新失败保留旧素材库。模板列表、工程卡片和当前工程显示实际使用素材的待更新状态，指向成片节点局部更新；不增加混剪侧第二个局部更新入口。

顶部混剪节点复用 sources 响应中的 `pendingProjectCount`，由服务端按同一个真实素材依赖函数计算。旧素材保留播放、但新素材使用新 ID 时，不依赖旧工作副本的 STALE 边才能显示待更新。切换 Run 后的迟到来源响应不会污染新分支的数量。

### 2. 成片节点局部更新

复用 FINAL_OUTPUT 任务和 Outbox，冻结工程、模板、当前包装、素材及批次版本。Worker 复用抽帧和模型选区、画面理解、槽位口播、真实 WAV 时长与字幕对齐能力；只处理变更槽位。

旧目标槽位生成口播、字幕及关联字幕配置从临时 checkpoint 移除，再生成新的结果。未受影响的口播/字幕、被用户删除的口播/字幕、手工字幕及音乐保持原样。服务端验证无关内容没有改变，新音频属于本任务、真实时长与断句帧数一致、截取/字幕/配音区间合法。

最终视频成功时，对同一混剪工程更新素材绑定、revision、模型起点、分离原音频来源和包装；同步视觉/包装工作副本、成片资产及交付记录。目标口播重新生成 ID 时，保留它原来的音频轨道行。包装快照保存新的素材依赖，后续包装可继续使用。失败、取消或输入二次变更不切换旧结果；输入未变的重试复用已保存的选区和音频，不重复支付已成功步骤。若素材或工程已二次变化，用户明确重试时重新冻结最新输入，避免反复执行已失效快照。

历史整片口播没有槽位来源时，不能可靠判定应删除哪段口播/字幕，局部更新在付费调用前明确拒绝并保留旧成片。重新完整包装仍可创建独立新版本；不推测旧口播与新槽位的对应关系。

### 3. 完整重做

智能填充只读取活动批次成员。完整重新包装在独立新分支重绑定最新素材，抽帧并重新选区后继续既有完整包装链路；冻结批次成员版本，拒绝任务期间再次变化的来源。父分支结果不回写。

保留既有例外：已交付但从未包装的纯画面成片首次补包装，仍按现有业务在当前输出分支补齐；本次没有改变首次包装规则。已有包装的完整重做仍新建分支。

## 契约、接口、迁移

共享 Contracts 增加向后兼容的素材来源、包装任务目标槽位/选区准备字段，以及 FinalOutputSnapshot 的可选 `sourceRefresh` 暂存信息。没有新增数据库表或第二套素材状态；旧结果读取不增加 revision，不自动启动模型。

复用现有公开局部更新接口，新增轻量混剪 sources GET 和受内部 Worker guard、项目范围、attempt token、租约保护的 trims/checkpoint/audio 回写。重复请求沿用活动任务与幂等约束。事务只操作数据库与 Outbox；模型、存储上传和编码在事务外执行。

最终提交锁定目标节点、输入工作副本及包装；再次校验当前工程/包装与冻结基线一致，素材及批次版本一致。编辑不被全局锁定，但任务不能覆盖用户执行期间新保存的编辑。

## 验收清单

1. 同素材 ID 新 revision、新 ID 唯一来源映射、歧义/缺失/过短来源、活动批次替换及空批次。
2. 只标记真实引用工程；无关工程和其他项目、Run、模板路径、旧分支保持独立。
3. 模型选择新截取起点，旧起点不作为强制答案；只替换目标口播/字幕，音乐、手工字幕与无关编辑保持不变。
4. 视频成功前旧结果不变；成功同步混剪、包装、成片与交付，同分支覆盖不增加 Run。
5. 重复请求、选区越界、租约、素材再次变化、输入被编辑、失败与重试不会错误覆盖或丢失旧结果。
6. 完整重做使用新素材并创建独立分支，父分支不变。
7. Contracts、API、Web、Worker 定向测试，数据库回滚集成测试，类型检查、构建、浏览器回归和 `git diff --check`。
