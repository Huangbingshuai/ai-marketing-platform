# 效果类 Prompt：质量门禁精简与语义事实绑定实施方案

> 状态：已完成（2026-09-01，已修正视觉证明责任边界）

## 一、目标

将候选生成后的多层重复门禁收缩为“客观硬错误淘汰、主观质量参与排序、批次问题作为提醒”。解决语义事实被字符相似度误判、一般相似被多次治理、合格未入选候选被误称为淘汰等问题。

## 二、业务边界

- 工作流：效果类第 3 节点“Prompt 生成”。
- 直接上游：已提交且为 CURRENT 的营销洞察与全局视频配置具体 revision。
- 当前生成、评估和人工修改只更新 Prompt 领域草稿与 `WorkflowNodeState`。
- 只有用户点击完成校验，且数量、分类、事实真实性与上游一致性通过后，才提交 `prompt-batch:{productId}` WorkingArtifact。
- 不修改第 4～6 节点、HTTP 路径、Prisma Schema、八阶段拓扑或 Prompt 公共结果结构。

## 三、实施内容

### 1. 事实绑定改为语义支持等级

- 现有评估调用同时返回事实证据的来源和支持等级：精确表达、完整语义表达、部分表达或不支持。
- Worker 只负责校验证据确实存在于该候选、factId 属于当前任务以及敏感事实未被扩写。
- 核心/次要卖点、视觉特征、营销目标和可信背书不再使用汉字二元组决定绑定。
- 部分表达只产生提醒，不冒充完整事实覆盖；完整语义表达可计入正式绑定。
- 产品名称、品类、规格、价格等身份或精确值继续使用结构化/精确校验。

### 2. 收缩候选硬淘汰条件

只保留：

- 输出结构损坏或引用未知事实；
- 产品完全无关；
- 明确编造事实或错误视觉证明；
- 正文为空、严重破损、客观无法生成或不符合片段级素材边界；
- 正文或完整创意结构完全重复。

模型质量分数不再直接制造硬问题。产品相关性、创意连贯性和可执行性低分改为排序降权或提醒。商品专属关键词动作计数与食品正则不再作为通用 Prompt 淘汰门禁。

### 3. 简化去同质化和补充

- 保留正文向量加动态六轴语义族的 MMR 择优。
- 删除场景/动作 40% 自动多样性补充和最终重复风险二次交换。
- 语义近似、场景集中和动作集中只作为统计提醒，不阻断 PASS。
- 完全重复仍硬删除。
- 只保留数量补充和必须业务事实覆盖补充；不再为软性多样性指标额外生成。

### 4. 简化批次与提交门禁

- Worker 保存草稿时要求精确数量、全部条目已完成分类、每条至少绑定一个深度业务事实、整批覆盖必须业务事实。
- 语义重复率不再决定 `PASS/NEEDS_REVIEW`，只作为质量提醒。
- API 完成校验保留数量、完全重复、分类完成、统一时长、硬问题、上游新鲜度和事实覆盖；不再用一般语义重复率阻止提交。
- 指标区分硬问题淘汰、完全重复、合格未入选和补充未采用，避免把所有未入选候选统称为质量淘汰。

## 四、测试

- 语义改写后的卖点、视觉特征、营销目标和信任背书能够正确绑定。
- 部分含义不会冒充完整事实覆盖，价格、规格和认证不得被语义扩写。
- 模型低分只影响排序，不直接淘汰结构完整、事实可信的 Prompt。
- 一般相似、场景或动作集中、语义重复率超标不阻断精确数量和草稿保存。
- 产品无关、事实编造、错误视觉证明、严重不可执行和完全重复仍被拒绝。
- 数量不足只执行数量补充；必须事实缺失只执行覆盖补充；不再执行多样性补充。
- 完成校验继续阻止短批次、未分类、完全重复、硬问题、事实覆盖缺失和 STALE 结果。
- 执行 Worker pytest、mypy、Ruff，API 相关测试、类型检查与 `git diff --check`。

## 五、实际实施结果

- 事实证据契约已增加证据来源与 `EXACT / SEMANTIC_FULL / PARTIAL / NONE` 支持等级。除产品名称、品类、规格和价格等精确字段外，卖点、痛点、受众、场景、营销目标、视觉特征与背书均可由评估模型按完整语义建立绑定。
- Worker 不再使用广式腊肠、厨房、切片等商品专属正则决定候选去留；低质量分和六维轻微漂移改为提醒。产品无关、编造事实、错误视觉证明、结构破损和完全重复仍为硬拒绝。
- 生产选择器已统一为 `70%` 单条质量与 `30%` 相对新颖度。场景、动作和普通语义集中不再触发额外生成或二次硬交换，只保留数量补充和必须事实覆盖补充。
- Worker、API 与前端均不再把 15% 语义重复度参考线作为提交条件。页面在偏高时显示“偏高，但不影响提交”。
- 节点详情将候选结果拆分为“硬问题淘汰”“完全重复淘汰”和“合格但未入选”，不再把所有未进入最终批次的候选统称为淘汰。

## 七、抽象事实视觉证明责任边界修正

评分模型负责判断候选是否用具体画面错误证明了配方、工艺、功效、认证等抽象事实。模型不能只返回 `ABSTRACT_FACT_VISUAL_PROOF` 问题码，还必须同时返回对应的事实引用、候选中的原文证据、证据来源以及被违反的视觉策略。

Worker 不再根据“候选绑定了不可视觉证明事实 + 模型返回问题码”自行推断二者存在语义关系。Worker 只验证：事实引用属于当前候选、证据原文真实存在、字段结构合法。缺少完整结构化诊断或证据不存在时，该问题只记为未验证提醒，不得成为硬淘汰依据。

实际实现新增 `abstractVisualProofFindings` 内部结构。评估模型必须返回 `factId / evidenceText / evidenceSource / violatedPolicy`；Worker 不读取事实视觉策略来决定问题是否成立，只检查事实引用和原文证据的完整性。新增三类回归：完整模型诊断保留硬问题、只有问题码时降级提醒、证据不存在时降级提醒。Prompt Worker 完整 pytest 通过（1 项显式跳过），`mypy src` 与 `ruff check src tests` 通过。
