# 智能包装冻结 Prompt 读取修复

## 范围与边界

- 效果类 TEMPLATE_MIX 内的包装创建；直接消费成片绑定的已确认 `render-clip` revision。
- 读取素材自身已采用且哈希匹配的 Prompt，不用后来编辑的批次正文替换实际画面描述。
- Prompt 批次不再作为冻结正文的执行依赖，但仍沿该素材明确指向的批次查找已确认商品信息；商品信息及其来源必须保持 CURRENT、AVAILABLE 和精确依赖 revision。
- 包装完整成功后的原位提交和 FINAL_OUTPUT 消费方式不变；不改变草稿、revision、模板/分支隔离及任务协议。

## 实现与验收

1. 复用 `hasAdoptedRenderPrompt`，与智能填充的冻结 Prompt 读取规则一致。
2. 修正依赖遍历：跳过批次正文的可变 revision 时，保留其商品事实依赖校验；不把批次其他素材或无关分支加入依赖。
3. 回归冻结正文、两轮批次修改、商品信息失效/revision 变化、未确认正文、导入素材与旧链路兼容。
4. 对真实测试1/测试2工程执行只读快照预检，不创建任务、不修改数据库、不调用模型/TTS/音乐。
5. 执行相关 API 测试、类型检查、构建与差异检查；不自动提交。

无数据库迁移，无 Web/Worker/共用契约变更。未获额外授权，不执行真实付费包装。
