# 信息提炼「重新 AI 提炼」一键进入隔离编辑态

## 现象与根因

**现象**：效果类工作流第 2 个节点（AI 信息提炼）在**已保存过版本**后，头部「重新 AI 提炼」按钮变灰、点了没反应；必须先点旁边的「进入编辑」，等页面重挂载后才又能点。用户期望：点 AI 提炼时自动进入编辑态并开始提炼。

**根因**（`apps/web/src/workflows/effect/information-extraction/EffectInfoExtractionNodePage.vue`）：

- 主按钮 `:disabled="currentRunning || !editing"`。`editing` 在非临时分支下等于 `currentState.workingArtifactRevision === null`，即只有「尚未确认版本」才为真；已确认版本后恒为 false。
- 唯一可用路径是先点「进入编辑」（`beginEffectNodeEdit`）建隔离临时 Run，父页 `refreshActiveRunInPlace` 换工作区，节点页因 `:key="extraction:${currentProjectId}:${workspace.workflowRunId}"` 重挂载，重挂载后 `editing` 才为真。

**为什么必须先进隔离编辑态**：`exitEffectEditInTransaction`（`apps/api/src/platform/workflow/effect-edit-session.ts`）只在「临时子 Run + 内容相对编辑基线有变化」时返回 `createdBranch: true`。若直接在父 Run 上重跑提炼，`draft.parentWorkflowRunId` 为空，走的是「在既有 Run 上提交首个版本」分支，`createdBranch: false` —— 用户要的「内容变了才新建提炼分支」不会发生。所以「一键」只能是在内部先建隔离编辑分支。

**顺带确认（不改）**：提炼成功本身不新增版本树节点。`listEffectRunBranches` 只取根 Run 与已发布分支，临时编辑 Run 被排除；提炼产物只在「保存版本」时提交。这与目标语义一致，本次不动后端。

## 设计

### 1. 跨重挂载的「待运行提炼」意图

重挂载会销毁组件实例，意图必须放在模块级。
`effect-info-extraction-state.ts` 新增 `requestPendingExtractionRun(projectId, productId)` / `takePendingExtractionRun(projectId)`：模块级 `Map<projectId, { productId, requestedAt }>` + 30s TTL，读取即删除（consume-once）。写法参照既有先例 `shared/effect-workspace-prefetch.ts`。

### 2. `EffectInfoExtractionNodePage.vue`

- **新增 `ensureExtractionEdit(productId)`**：`editing` 已为真直接返回；否则 `beginEffectNodeEdit(..., 'INFORMATION_EXTRACTION')`。若返回的 Run 与当前 Run 不同（说明建了隔离子 Run）→ 用 `result.data.productIdMap[productId] ?? productId` 记录待运行意图 → `emit('workflowRunChange')` → 返回 `false`（重挂载后续跑）。**必须走 `productIdMap`**：隔离 Run 的商品是克隆出来的新 ID。409 时给「请先保存或取消当前编辑，再重新提炼」。
- **改造 `runCurrentExtraction(options?)`**：守卫由 `!editing` 改为 `editBusy`；顺序为确认弹窗（`skipConfirm` 跳过）→ `flushPendingEdits()` → `ensureExtractionEdit(productId)` → 原有启动逻辑。`flushPendingEdits` 必须在 `ensureExtractionEdit` **之前**：`beginEffectEditInTransaction` 会克隆并重映射 `workflowNodeState`，先把未保存字段写进父 Run，重挂载后才不丢。
- **新增 `resumePendingExtraction()`**：`loadWorkspace` 成功且 `editing` 为真时，消费待运行意图；商品在新 Run 的商品列表里才设 `currentProductId` 并 `void runCurrentExtraction({ skipConfirm: true })`，不在则丢弃不报错。
- **按钮可用性**：主按钮去掉 `!editing`（改为 `currentRunning || editBusy || validating`），spinner 条件加 `editBusy`；FAILED / STALE 两个提示按钮由 `!editing` 改为 `editBusy || currentRunning`。「进入编辑」按钮、`:show-validate="editing"`、`baseFieldsReadonly` 保持与真实编辑态绑定，不动。

### 3. 不改动

- 后端与 `packages/contracts`：现有接口语义已满足，无改动。
- `validateCurrentResult` 的 `createdBranch` / `unchanged` 文案分支不动（保存版本的分支行为不在本次范围）。
- 资料导入、Prompt、渲染、混剪各节点不动。

## 实施与验证

### 落地内容

- `effect-info-extraction-state.ts`：`EFFECT_PENDING_EXTRACTION_TTL_MS = 30_000`、`pendingExtractionRuns`、`requestPendingExtractionRun`、`takePendingExtractionRun`。
- `EffectInfoExtractionNodePage.vue`：import 两个新函数；`loadWorkspace` 在 `resumeWorkspaceRuns()` 之后调 `resumePendingExtraction()`；`runCurrentExtraction` 头部改为「确认 → flushPendingEdits → ensureExtractionEdit」；新增 `ensureExtractionEdit` / `resumePendingExtraction`；主按钮 `:disabled="currentRunning || editBusy || validating"`、spinner `v-if="currentRunning || editBusy"`；FAILED / STALE 按钮 `:disabled="editBusy || currentRunning"`；三处 `@click` 由 `runCurrentExtraction` 改为 `runCurrentExtraction()`（带 `skipConfirm` 选项后需显式调用）。
- `agent-guide.md`：AI 信息提炼一节新增一条交互说明。

### 验证中发现并修复的问题

1. **既有断言计数失效**：`effect-info-extraction-layout.spec.ts` 原有 `pageSource.match(/@click="runCurrentExtraction"/g)` 长度为 3，三处 `@click` 改为 `runCurrentExtraction()` 后该正则不再匹配，改为匹配 `@click="runCurrentExtraction\(\)"`。
2. **禁用条件计数误判**：`pageSource.match(/:disabled="editBusy \|\| currentRunning"/g)` 实际为 3 处 —— 「进入编辑」按钮本就是该条件。改为精确匹配 `:disabled="editBusy || currentRunning" @click="runCurrentExtraction()"`，长度 2（FAILED / STALE 两个提示按钮）。
3. **CRLF 假红**：本机工作区是 CRLF，`?raw` 不归一化换行，带 `\n` 的多行 `toContain` 必假红。多行片段统一走文件内既有的 `normalizedPageSource`，其余断言保持单行。
