# 效果类 Prompt：语义重复度二次治理实施方案

> 状态：已完成

## 一、问题与目标

真实 50 条批次虽然已将语义重复度从 80% 降到 66%，但仍有 33 条进入 8 个重复组。向量结果与正文抽查一致，问题不是统计误报，而是固定 8 个创意方向被扩写为多条同场景、同产品动作的近义画面；质量优先的 MMR 只替换了少量候选；多样性补充与最终保护也没有逐条消解重复组。

本次只改造效果类第 3 节点 Prompt 生成 Worker，不改变数量优先、提炼事实边界、批次共用提示词、人工编辑生命周期或 WorkingArtifact 提交边界。

目标：

- 创意方向数量随批次规模增长，50 条任务规划 12～16 个方向。
- 首轮筛选先覆盖不同语义组，再在组内补齐数量。
- 超标补充直接避开当前重复大组的语义、场景和产品动作。
- 最终保护从整批结果比较升级为逐条替换，并始终保持精确数量。
- 无法达到 `<15%` 时继续保存 `NEEDS_REVIEW` 草稿，不覆盖上一份已确认工作副本。

## 二、实施范围

### 1. 动态创意方向

- 根据目标数量计算方向数：`ceil(targetCount / 4)`，限制在 8～16 个之间。
- 创意方向模型必须精确返回指定数量，不再固定 8 个。
- 校验继续要求真实事实、不同语义画像和足够的“场景原子 + 产品动作”组合。
- 方向计划模板哈希变化后，旧检查点自然失效并重新规划，不伪造迁移。

### 2. 语义组优先选择

- 使用同一批正文向量和 0.82 阈值构建候选语义连通组。
- 在满足强制事实覆盖的前提下，优先从尚未选中的语义组选择代表项。
- 全部可用组均已有代表后，再按质量、新颖度和组内负载继续补齐。
- MMR 调整为质量 55%、多样性 45%，普通相似仍是软排序，不以去重为由减少最终数量。

### 3. 定向多样性补充

- 重复度超标时，补充规模按重复超额计算，最多为目标数量的 40%。
- 候选池总容量从目标数量的 160% 提升到 180%。
- 将当前高风险组的语义签名、视觉签名、场景原子和动作模式传入补充分片作为避重上下文。
- 补充候选只有在能够减少重复条目或重复配对时才进入最终候选集合。

### 4. 最终逐条替换

- 先保留每个重复组中质量最高的代表项。
- 对其余重复项，从未选候选中寻找能够降低重复条目数、其次降低重复配对数的替代项。
- 替换不得破坏强制事实覆盖，不得引入硬质量问题，不得改变最终数量。
- 记录替换次数以及保护前后重复统计，不记录正文或内部向量。

## 三、测试与验收

- 动态方向数量：50 条得到 13 个方向，小批次和上限行为正确。
- 方向响应数量不符时明确拒绝。
- 语义组优先选择会先覆盖不同连通组，组不足时仍能精确补齐数量。
- 逐条替换能够在存在更优替代候选时降低重复条目，并保持强制事实覆盖。
- 定向补充规模、候选池容量和避重上下文正确。
- 回归数量优先、事实覆盖、人工保留条目、单条重生成、向量失败和 `NEEDS_REVIEW` 生命周期。
- 执行 Worker pytest、mypy、Ruff 和 `git diff --check`。

## 五、实际实施与验证结果

- 动态方向公式已落地：10 条保持 8 个方向，50 条规划 13 个方向，超大批次最多 16 个方向。
- 正文向量连通组已进入选择过程；强制事实覆盖优先级不变，同等条件下先覆盖未使用语义组，并对重复使用同组增加软惩罚。
- MMR 已调整为质量 `55%`、新颖度 `45%`；补充候选上限提升到目标数 `40%`，总候选上限提升到 `180%`。
- 最终保护已支持逐条替换，并验证能在保持 3 条准确数量的同时，将 1 个重复条目替换为不同语义候选。
- 完整 Worker 测试为 `108 passed, 1 skipped`；另执行 `mypy src`、`ruff check src tests`、Python 编译检查和 `git diff --check`，均通过。
- 本次未执行真实 Ark 付费生成，因此真实 50 条改善幅度仍需在重新构建 Worker 后通过新批次确认，不能用 Mock 结果替代生产结论。
