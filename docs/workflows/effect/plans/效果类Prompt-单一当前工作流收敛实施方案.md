# 效果类 Prompt 单一当前工作流收敛实施方案

状态：已完成
日期：2026-08-28

## 1. 目标

Prompt 生成节点只保留当前“输入快照 → 提炼信息应用映射 → 事实视觉使用策略编译 → 共用提示词编译 → 连贯六维创意生成 → 创意评估与用途分类 → 精确数量择优与补充 → 结果保存”工作流。新任务、运行恢复、节点详情和前端工作流弹窗不得再选择、展示或执行 V8～V11 历史拓扑。

内部继续由 `CURRENT_EFFECT_PROMPT_GRAPH_VERSION` 常量指向唯一可执行拓扑。具体存储字面量只用于跨进程兼容，前端不得展示，也不构成用户可选择的产品版本。

## 2. 数据处理边界

- 旧 Run、Stage 和 Shard 数据暂时保留在 PostgreSQL 作为不可见审计记录，不迁移、不伪造成当前节点，也不参与当前工作区恢复。
- 已完成的 Prompt 结果仍按结果 Schema 展示和编辑；“不再展示旧工作流”不等于删除用户已经生成的50条 Prompt。
- 旧拓扑的排队或运行中任务必须安全终止，禁止被当前 Worker 领取后按新图续跑。
- 新 Run 只写入 `CURRENT_EFFECT_PROMPT_GRAPH_VERSION` 指向的拓扑；API 节点详情和 Worker claim 只接受该当前值。

## 3. 跨层修改

- Contracts：保留数据库反序列化所需的旧字面量，但默认节点、边和新 Run 只指向当前拓扑；任何版本字面量均不对用户展示。
- API：删除历史图推断和历史节点投影；工作区不返回旧 Run；旧 Run 的进度、节点详情、Stage、Shard 和 claim 请求返回明确的“历史工作流已停用”。
- Worker：API 只会下发当前快照；旧任务在 claim 阶段终止，不会进入 Worker 图或模型调用。
- Web：删除 V11 徽标、“当前工作流/历史执行”切换和历史说明；弹窗始终展示当前八节点拓扑及当前 Run 的真实结果。

## 4. 验收

- 新 Run 固定使用当前拓扑，且页面不出现 V8/V9/V10/V11、版本或历史工作流切换。
- 旧 Run 不再成为工作区 `currentRun`，也不能被 claim、恢复或查看节点详情。
- 当前批次结果列表、编辑、单条重生成、人工评估和 WorkingArtifact 提交语义保持不变。
- Contracts、API、Web、Worker定向测试与类型检查通过，浏览器验证工作流弹窗只显示当前工作流。

## 5. 非目标

- 本次不物理删除旧数据库行，不删除已经生成的 Prompt 结果。
- 本次不修改当前工作流的模型提示词、MMR算法、视频渲染和混剪逻辑。

## 6. 实施与验收结果

- Web 已移除版本徽标、历史执行切换和历史版本说明；本地浏览器回归确认弹窗不再出现版本或历史入口，并展示当前8个节点。
- API 工作区只投影当前 Run；读取旧 Run 或旧节点详情返回 HTTP 410，旧 Stage、Shard、心跳和完成请求同样被当前图校验阻断。
- 队列认领旧 Run 时，API 将其终止为 `WORKFLOW_RETIRED`，不会把旧快照交给 Worker；创建新任务时若存在旧的排队或运行任务，会先终止旧任务再创建当前 Run。
- 数据库只读核查未发现排队或运行中的旧 Prompt Run，因此未执行一次性数据库状态修改。
- 已执行 API 3 个定向测试文件，共126项通过；API TypeScript 类型检查通过。
- 已执行 Web 2 个定向测试文件，共22项通过；Vue TypeScript 类型检查通过。
- Contracts 3个测试文件共15项通过，契约构建通过；Worker 当前图与事实视觉策略13项定向测试通过，mypy与ruff检查通过。
- 本地浏览器验收确认标题仅显示 `PROMPT WORKFLOW`，无 `V11`、`历史执行` 或工作流版本切换。
