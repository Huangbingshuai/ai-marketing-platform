# 局部追加归槽检查点失败后保留

## 观察与范围

广式腊肠项目“测试2”的局部追加任务已持久化 34 条归槽结果、132 条选片结果和 69 条截取结果，但下载素材时连接中断，任务失败在 73%。新增 R-035、R-036 已参与选片；追加没有完整提交，当前 40 条工程不能标记为已追加成功。

本次属于效果类模板混剪节点。直接上游是冻结的已确认 render-clip/render-batch（当前素材池 revision 7）；归槽检查点是任务中间结果，不是工程提交。完整成功后才提交 mix-template 与 timeline-project，影响成片输出。复用现有任务、检查点及 sources/workspace 投影，不新增状态或契约。

## 实施

1. 对当前 Run 的失败 APPEND，只有全量归槽结果通过现有机械校验时才恢复只读素材用途展示。沿用槽位配置、文件、revision、内容哈希与来源身份检查；不展示兄弟 Run、取消任务、整批失败或不完整/非法检查点。
2. 归槽检查点与素材已采用基准分开：失败任务仍失败，不发布截取或工程，不清除新增素材待处理，不增加业务 revision，不覆盖人工归槽。
3. 历史读取保留失败 APPEND 检查点，避免超过最近 20 条任务后归槽再次消失；继承路径仍只采用成功任务。升级读取缓存投影版本，避免旧缓存继续隐藏结果。
4. 核对已有素材下载有界网络恢复修复及 Worker 实际运行代码，补齐本次 ConnectError 的离线测试。只恢复同一冻结文件下载，不重复调用已完成模型步骤；不启动或重试当前失败任务。

## 验证及非目标

- API：失败后有效归槽保留、完整性与身份校验、跨 Run/模板隔离、新编辑防回退、历史分页、失败不推进采用基准。
- Worker：连接失败、中途断流、超时、服务错误有界恢复；租约/文件错误不重试；测试使用假网络，不调用付费模型。
- 执行相关单元测试、类型检查、构建和 git diff --check；只读检查真实 sources/workspace 与浏览器恢复。
- 不重试付费任务，不改失败任务终态，不制造追加工程，不修改已有 40 条工程，不自动提交 Git。安全更新 Worker 前核对任务与消息队列均空；否则仅交付代码并说明运行限制。
