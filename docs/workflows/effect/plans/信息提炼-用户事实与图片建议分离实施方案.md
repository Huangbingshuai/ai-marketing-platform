# 信息提炼：用户事实与图片建议分离实施方案

## 状态

已完成（2026-09-01）。

## 范围

- 资料包只承载产品基础、卖点、用户和场景信息，不再填写时长、画幅、分辨率、渠道、禁用元素和视觉风格等全局视频配置。
- 全局视频配置继续以资料导入节点提交的 `effective-video-config:{productId}` 为唯一权威来源。
- 文档和表单中的明确内容作为“用户事实”原样保留；图片识别只能补充可见、可验证的内容，标记为“AI 图片建议”。
- 标准化节点只做结构整理、稳定去重和字段限额处理，不再改写非空价格、产品信息或用户提供的列表项，也不再强制补齐缺失营销策略。
- 前端在结果草稿中逐项展示“用户事实”或“AI 图片建议”，用户确认后才提交营销洞察 WorkingArtifact。
- 修复分辨率未参与融合来源和冲突记录的问题。

## 非目标

- 不改变效果类固定六节点主流程和信息提炼 Worker 固定拓扑。
- 不新增 Prisma 表或数据库迁移。
- 不允许图片推断配方、产地、认证、功效、销量、价格或信任背书。
- 不让 Prompt 节点读取未确认的提炼草稿。

## 数据接口

保留 `EffectExtractionResult` 作为用户可编辑的权威业务内容，扩展公开产品状态中的安全来源视图：

```ts
type EffectExtractionValueOrigin = 'USER_FACT' | 'AI_IMAGE_SUGGESTION';

type EffectExtractionProvenance = {
  fieldOrigins: Record<string, EffectExtractionValueOrigin>;
  itemOrigins: Record<
    string,
    Array<{
      value: string;
      origin: EffectExtractionValueOrigin;
    }>
  >;
};
```

- 数据库继续使用现有分支输出和 `EffectExtractionResult.provenance` JSON 字段，不新增表。
- 历史字符串来源映射继续可读；无法确定逐项来源时默认显示“用户事实”，不得伪造 AI 建议。
- 人工新增或修改的值标记为“用户事实”；未改动的图片建议保留原标记。

## Worker 规则

1. `FORM` 只提供导入节点全局配置和产品名称等当前表单事实。
2. `DOCUMENT` 提取用户资料事实，不读取或生成全局视频配置。
3. `IMAGE` 只输出可见外观、陈列、场景和视觉气氛建议。
4. `FUSION` 保留用户事实优先级；API 根据同次运行的原始分支候选为最终数组逐项映射来源。
5. `NORMALIZATION` 后确定性恢复所有用户事实；图片建议只能填空或追加到剩余容量，不能挤掉用户事实。
6. 价格存在时原样保留；缺失时保持待补充，不生成建议价格。

## 兼容与迁移

- 现有 schema v3 结果继续读取，不原地改写历史业务内容。
- 历史 provenance 为字符串映射时由 API 转换为安全展示结构。
- API 根据当前 Run 的 `FORM / DOCUMENT / COMMERCE / IMAGE` 分支输出生成逐项安全来源视图；不复制模型原文，也不新增第二份事实源。
- 保存草稿后，人工覆盖字段优先标为“用户事实”；页面即时编辑时也同步更新来源标签。
- 全局视频配置仍由原 WorkingArtifact revision 和依赖关系控制下游待更新。

- 文档 Worker 会在保存 `DOCUMENT` 分支前清除六个全局视频配置字段；标准化完成前再次用 `FORM` 分支确定性覆盖制作配置。
