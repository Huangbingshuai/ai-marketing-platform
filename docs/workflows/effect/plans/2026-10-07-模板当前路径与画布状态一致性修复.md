# 模板当前路径与画布状态一致性修复

## 证据与边界

- 测试1在旧 Run `c1fdeb76-feeb-40e4-b613-b9eb188325a3` 已局部更新为13条工程；刷新后全局活动 Run 指向较晚创建但较早确认的旧5条路径。既有路径选择只使用分支创建时间及活动上下文，不能识别在原分支覆盖的局部更新。
- 当前13条画面工程均已就绪，但3份独立包装仍绑定画面工程旧 revision，分支状态将它们错误传播为混剪待更新。当前业务已明确画面调整不使既有独立口播、字幕、配乐失效。
- 输入仍为同项目、同渲染/手动复制谱系的已确认来源；局部更新在原 Run 覆盖模板与时间轴，不增加分支。最终导出的旧文件仍按真实差异待更新。

## 实现

- 在分支模板只读 DTO 增加可选的最近实际确认时间，来自现有不可变 revision 快照；不使用自动保存、告警写入或 Run 创建时间假装局部更新确认。
- 复用唯一模板路径函数，普通目录和画布按每模板最新确认路径读取。显式版本树历史导航继续保留原路径，不由普通选择激活全局分支；复制的历史模板不参与抢占。
- 首次加载的可编辑工作区也从同一目录选择，不能出现列表13条、编辑草稿5条的错配。配置页分支树高亮采用相同当前确认路径，精修页仍保留显式选中路径。
- 完成的独立包装忽略对应画面工程的版本依赖过期，保留真实事实依赖、包装自身版本、文件可用性与项目隔离检查。只读兼容投影，不重做包装、不改历史轨道或文件。
- 目录完整聚合更新后触发画布重新读取；迟到响应、读失败及跨项目保持既有隔离规则。

## 非目标与迁移

- 不创建新状态表，不删除历史分支，不自动生成、包装或编码成片。可选 DTO 字段，无数据库迁移，Worker任务协议不变。

- 完成包装不因画面 revision 变化误报；事实变化和真实画面消费者/最终文件仍待更新。
- 目录归零立即同步、更新中的迟到旧读取不能回写、进入编辑/取消保留真告警。
- Contracts/Web/API相关测试、类型检查、构建、diff检查；浏览器实际刷新、模板切换、渲染往返及关键宽度。全过程不启动付费任务。
