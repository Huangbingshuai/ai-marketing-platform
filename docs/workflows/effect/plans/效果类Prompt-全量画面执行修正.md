# Prompt 全量画面执行修正

状态：实现及 Worker 自动回归完成，工作流 UI 同步及浏览器付费验收中。沿用当前分支，2026-09-11。

## 原因和范围

图文对照均出现高 AI 分但仍有画面故障。当前卖点直达路径跳过全量执行编辑，仅在评分返回 executionFindings 后修补；漏判的候选没有修正机会，局部补丁也可能遗留六维与正文不一致。

本次收口为：卖点素材任务 → 草稿生成 → 全量 AI 画面执行修正 → 独立评分 → 向量择优。保留八阶段拓扑，将修正作为连贯创意阶段内部异步步骤。不新增表、HTTP 路径或公共 DTO。不换模型、不新增 Worker 语义门禁、不增加事实覆盖配额。

输入继续是当前项目商品已确认 marketing-insight 的 artifact/revision 和该快照商品图；自动保存仅更新节点草稿，只有明确完成校验才提交 prompt-batch，下游渲染按已确认 revision 消费。

## 实现

- 所有新生成候选（包括补充）必须完成独立 AI 执行编辑，再标记生成分片成功。正常批次评分后不再追加旧式局部执行补丁，以免最后一次写入让六维漂移；人工正文不自动重写。
- 使用现有 KEEP/REPAIR 文本路径编辑协议。AI 自行判断完整片段的时间、接触/支撑、材料、镜头和声音，并同步主线、六维、首帧、节拍和终帧中受影响的描述。没有问题保留原样，不将每条改成同一固定镜头。
- 修正模型可接收同一批已验证商品图，图片不能新增产品事实。评分只消费修正完成的正文，重新建立评分、绑定和向量，不能沿用修前评分。
- 保留 ID、事实引用、总数量、总时长；Worker 只应用合法路径、验证结构和持久化，不按商品词库判错。修正失败保留草稿及失败分片，允许同 Run 恢复，不能伪装为已修正。
- 源头模板解释合理开始时点、自然终态与镜头分工。全量编辑再核查，不能只加“自然”“由手驱动”等字样却保留矛盾。
- 修正不承诺消除视频模型所有故障；新增调用的质量与耗时收益需后续真实对照验证。

## 验收

工作流保持八阶段，将生成阶段显示为“素材创意生成与画面修正”。右侧展示 AI 修正方式与已完成条数，运行/失败分片中仅保存的草稿不算修正完成；旧任务没有执行标记时不伪造修正数据。计数由 API 根据成功分片实时投影，刷新后保持一致；完成不等于真实视频零故障。

跨食品、洗护、服饰、电子产品的机械编辑回归；无评分 findings 时仍修正；修正后才评分；KEEP 完全保留；图片接入/无图；事实、身份、时长不可更改；失败恢复；补充同样修正；无 Worker 语义判断；预检调用预算包含全量编辑。运行 Worker 全套测试、mypy、Ruff 和 diff 检查。公共契约不变。

## 实际验证

- Worker：434 passed，1 skipped（显式付费集成项）。测试包括多个产品、4/8/12/15 秒路径编辑、无评分发现时全量执行、修后才评分、禁止评分后的旧补丁、失败恢复不重新生成、图片/无图请求与精确数量预算。
- mypy src：26 个源文件通过。
- Ruff 严重错误规则 E9/F63/F7/F82：通过。默认全量 Ruff 报告 78 项存量风格/建议问题；对本次修改的 4 个 Python 文件逐个比较 HEAD 与当前，规则分组和数量均无增加。未为本次画面修复批量改动无关格式。
- 工作流 UI 已同步名称、职责和预计输出；API 按成功分片投影已修正条数，保留历史无数据语义。公共数据结构不变，只修改节点展示名称。
- API 详情 34 项、Web Prompt 46 项、Contracts Prompt 11 项通过；API 类型检查与构建、Web 生产构建（含类型检查）、专项 ESLint 通过。浏览器 1920、1440、390 宽度无弹窗横向溢出，ESC 关闭并恢复焦点。新增测试最初缺少真实分片任务时长字段，补齐测试夹具后通过。
