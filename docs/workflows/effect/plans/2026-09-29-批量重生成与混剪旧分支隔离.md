# 批量重生成与混剪旧分支隔离

## 范围

效果类上游整批重新生成发布新分支时，旧分支的混剪模板、时间轴、包装和成片输出继续绑定原先确认的来源，不因新批次出现而提示“旧素材过期”或要求重新智能填充。单条 Prompt、视频片段或混剪槽位的真实改动仍按精确依赖标记待更新。

## 非目标

- 不把旧批次素材并入新分支的智能填充候选库。
- 不放行文件缺失、跨项目引用、素材自身 revision/hash 改变、槽位截取越界或包装时间轴不一致。
- 不凭 `STALE` 一个字段推断历史记录究竟来自整批替换还是单条修改。

## 数据与处理

1. 批量 Prompt 生成在新 Run 发布时不改变父 Run 的渲染素材和混剪工作副本；同 Run 的非分支兼容路径也不得把整批替换当成逐条修改传播失效。单条修改继续按变更的 Prompt ID 精准标记。
2. 视频整批重渲染产生新 `render-batch` 时，新分支只选新批次片段；旧分支保留原 `render-clip`、`timeline-project`、`timeline-package` 的精确来源版本。单条返修/采用后，绑定旧 revision 的工程仍待更新。
3. 混剪候选和历史绑定分开判定：新填充只能使用当前分支的有效素材池；既有工程只按冻结的来源 `artifactId + revision + hash` 与文件状态判断。页面只显示真正需处理的单条来源问题，不把其它分支的新批次列为本分支的过期数量。
4. 历史 `STALE` 记录只有在不可变来源快照和分支归属能够证明属于整批替换时才可修复；证据不足时保持原状态，不批量清除标记。
