# Prompt 先逐段诊断、后定向修正（仅本地）

## 边界

效果类第 3 节点，直接上游为任务冻结的 `marketing-insight:<productId>` artifact/revision，本地腊肠前轮 revision 1，本轮重新核实。输出仍是 `prompt-batch:<productId>`；完整生成且服务端来源/结构校验成功后发布新分支。原分支、渲染及混剪任务不改，人工正文不重写。保持 Turbo 与既有评分模型，不部署服务器、不渲染视频。

## 方案

在既有全量画面修正阶段内，把“直接决定 changed”改为“独立逐段诊断 → 仅问题条目定向重写”，不是增加固定节点或评分后的补丁循环。

- 诊断只读真实首帧、每拍动作/驱动/机位/焦点/结果和终帧及事实边界，移除 informationDelta/continuityState 自评；每拍返回紧凑信息状态与具体证据，另列跨拍问题 ID、涉及节拍和原因。覆盖时长稀疏、重复观察、握持对象、反向受力、承重移交、工具占用、观察面、镜头运动和材料/时间条件。正常慢变化与短收束允许存在，不设动作数量或停留比例。
- 正常条目保持原样，不进入重写调用。有问题的条目把诊断作为明确输入，返回完整同步的主线、六维、shotPlan 与逐问题改动定位； Worker 仅核验身份、节拍范围、问题引用完整性和原来源哈希，不判断语义是否已经修好、不删除问题候选或提高分数门槛。
- 复用原 creativeItems JSON 内部检查点保存诊断及应用状态，绑定输入哈希与模板哈希。诊断成功先持久化，再重写；失败保留已诊断草稿，同 Run 重试不重做合法诊断/已应用结果。旧字段缺省兼容，新 Run 不复用旧检查点。失败/旧租约仍不能提交。
- 沿用现有并发、总调用保险丝、结构异常有界拆分恢复，不新增语义重试轮次。所有候选在本阶段完成后再评分/MMR，风险仍软提醒；诊断通过与模型声称修复均不等于真实视频无故障。

## 验收

测试覆盖无问题不重写、问题定位到改动的完整引用、伪造/重复 ID、节拍越界、诊断持久化、失败恢复、原内容变化失效、正常项与来源不变、辅助字段不进入诊断、原 Prompt 不进入日志。食品、护理、电子与箱包、4–15 秒共用协议，不使用产品关键词规则。执行 Worker pytest/mypy/diff 检查。

先提交代码，确认本地无在途 Prompt 再更新对应 Worker并验证哈希；浏览器仅发起一轮本地腊肠 30×15 秒付费重生成。报告诊断数/实际重写数、最终正文逐条静止及物理风险、重复度、耗时、失败恢复情况和未验证范围。只做一轮，不重开付费任务，不把文本评分当作视频实测。
