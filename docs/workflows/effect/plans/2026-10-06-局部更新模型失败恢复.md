# 局部更新模型失败恢复

## 范围与证据

效果类混剪工程局部更新复用成片输出任务：读取冻结的最新 render-clip revision、工程与包装基线，选区后仅重做变更槽位口播和字幕，成功才提交当前 Run 的 timeline-project / timeline-package；已导出的条目继续最终编码。不得新增分支、自动修改其他工程或删除旧结果。

实际失败记录：口播模型 120 秒超时；视觉模型 4096 Token 截断；共享视觉失败传播给另一条工程。普通包装有有界断点恢复，但 FinalOutputHandler.prepare_refresh 直接调用 process_item，未使用恢复函数。终态错误把模型失败写为渲染失败，且共享错误声称自动恢复。

## 实施

- 使用同一 PackagingHandler 的断点恢复，局部更新将重试次数写入现有 PackagingCheckpoint.automaticRetries；保留成功选区、视觉、配音与音乐。租约冲突、配置或永久拒绝不重试，音乐提交结果不明不重发。
- 包装模型独立配置超时（默认 300 秒）与输出上限（默认 16384），不改变素材导入或智能填充模型设置。
- 包装结构请求遇到截断，在配置上限内倍增输出容量；视觉达到上限仍截断则按槽位拆分请求，复用已抽帧数据与完成的视觉结果，不伪造语义或接受残缺响应。
- 失败显示模型阶段与安全原因，去掉未发生的自动恢复承诺。外部服务持续不可用时明确失败，旧结果保留。

## 契约与非目标

复用已有队列、lease / attempt、checkpoint 与当前分支提交机制，不新增 DTO、表或状态，不修改模板数量、字幕编辑、工作副本 freshness。此次修复不重跑成功项，不自动启动其他模板付费任务。

## 验收

- 截断扩容成功、上限终止、非包装请求不扩容；超时与永久错误区别处理。
- 多槽位视觉拆分后身份与数量仍完整，共享失败可恢复且不毒化缓存。
- 局部更新恢复仅执行未完成步骤，持久化次数并跨重启有界；旧 lease、不明音乐提交不重试。
- 部分成功条目不重跑，失败消息区分视觉/口播与编码。
- Worker 测试、类型检查、API 相关回归及 git diff --check；无活动任务后重建原 Worker，检查健康日志和实际配置。真实付费验证须报告真实结果，不能以 Mock 单测保证外部供应商永远成功。
