# 效果类 Prompt 分片流水与画面修正提速

状态：代码已实现，自动回归及本地部署完成，真实付费对比待验收。基线：2026-09-14 广式腊肠 100 条 × 15 秒，36.51 分钟，最终语义重复度 14%，画面可执行性 89.32。

## 范围与边界

效果类 Prompt 节点消费 `marketing-insight:{productId}` 的已确认 revision；自动保存领域草稿与 WorkflowNodeState，只有用户完成校验才提交 `prompt-batch:{productId}` 并使渲染待更新。保持八阶段、HTTP、数据库、模型与数量优先选择规则。

## 实施

1. 默认 AI 并发 2 → 4，共享限流器；遇到真实 429 时降到 2，保留供应商退避机制。
2. 批量任务按分片执行生成、独立 AI 画面修正、评分，前一个分片评分与后一个分片生成重叠。评分前仅需本分片完成；向量与最终选择仍等待整轮。
3. 评分保持完整事实上下文与输入预算，输出预算由 6144 → 8192，使短候选有容量合成四条一组；长候选仍按现有机械 token 预算拆分。不得截短正文或事实来加速。
4. 独立修正调用逐条返回原样保留或完整修订。AI 负责画面、时间、工具、材料和主线/六维同步；Worker 仅检查身份、数量、结构并编译正文。新批次评分后不再执行旧修正-审片-复评环；评分建议有风险时仍可独立审片并记提醒。
5. 生成但未完成修正的分片保持未完成草稿。重试复用当前 Run 的原稿，成功分片不重新生成；分片取消或异常必须等待兄弟任务退出，禁止后台继续回写。
6. 单条人工编辑与历史结果保留现有路径。失败评分分片恢复原索引和分组；新增评分分片使用已持久化索引之后的新索引，成功评价不重复调用。

## 验收

Mock 覆盖并发上限/429降速、生成与评分重叠、完成顺序不影响数量与最终顺序、修正缺项/错ID失败、原样保留不改正文、修正失败恢复、补充也修正、人工编辑不改写。执行 Worker pytest、mypy、修改范围 Ruff 与 diff 检查。真实对比沿用同商品 100×15 的设置，记录耗时、调用数、重复率与人工画面问题；20～25分钟仅为目标，不预先声称达到。

## 迁移

不批量改写历史数据、不跨 Run 缓存。已成功且未评分的历史生成分片恢复后重新完成独立修正；已有成功评分保留。新结果只写草稿。
