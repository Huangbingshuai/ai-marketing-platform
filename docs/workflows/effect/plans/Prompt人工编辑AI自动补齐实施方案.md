# Prompt 人工编辑 AI 自动补齐实施方案

## 目标

- 人工新增和编辑弹窗把 Prompt 正文放在创意信息之前。
- 用户填写 Prompt 后，可主动触发“AI 自动补齐”，生成创意主线和六维信息。
- 完整的人工输入直接保存，不再要求保存后进行单条 AI 质量评估。
- 片段类型始终以用户选择为准，AI 自动补齐不得覆盖。

## 实现边界

- 继续复用现有异步单条任务和幂等、revision、项目隔离能力，避免模型调用阻塞 HTTP。
- 现有内部 `ITEM_EVALUATE` 标识暂作存量任务兼容，页面与节点详情统一呈现为“AI 自动补齐”。
- 自动补齐会先保存当前 Prompt 草稿，再异步生成创意主线和六维；完成后回填当前弹窗。
- AI 返回的质量分数、用途分类和问题码不作为人工 Prompt 的覆盖依据；用户选择的片段类型和正文保持不变。

## 验收

- Prompt 为空时“AI 自动补齐”不可点击。
- Prompt 非空时可启动异步补齐，运行中弹窗不可重复提交或关闭。
- 补齐成功后弹窗展示完整创意主线与六维，片段类型、时长、正文不变。
- 手工填写完整创意主线与六维后可直接保存为可用条目。
- 页面不再出现“重新评估”“编辑后评估”“用途评估”等单条操作文案。
- 覆盖 409、任务失败、刷新恢复、ESC 和焦点恢复。

## 实施结果

- 已将 Prompt 正文移动到创意信息上方，并增加正文非空门槛的“AI 自动生成”按钮。
- 已取消卡片上的单条重新评估入口；完整手填结构直接保存为可用条目。
- 已复用异步单条任务完成回填，并确保正文、片段类型、时长及人工选择不被模型覆盖。
- 已通过 Contracts 构建、API 58 项相关测试、Web 30 项相关测试、Worker 全量测试、Web 生产构建、TypeScript 类型检查、mypy、Ruff 和 `git diff --check`。
