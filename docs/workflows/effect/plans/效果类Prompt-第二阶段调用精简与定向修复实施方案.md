# 效果类 Prompt 第二阶段调用精简与定向修复实施方案

## 状态

已完成。

## 目标

在不更换模型、不缩短最终 Prompt、不增加生成约束、不改变当前八阶段业务图的前提下，减少质量评估的重复输入、格式异常后的无效付费调用，以及创意方向规划的整批返工。

本阶段继续保持：AI 负责事实是否真正实现、场景动作含义和用途分类；Worker 只校验来源、稳定 ID、枚举、数量、结构、revision 与哈希，不进行关键词、字符相似度或自由文本语义判断。

## 范围

1. 质量评估改用精简的模型输出契约，只让模型返回事实结论、五项评分、用途、六轴分类和问题码；由 Worker 确定性补齐可从候选结构直接得到的签名与派生 ID。
2. 评估输入删除 ordinal、round、generatedAt 等无关字段，事实与视觉策略按本分片去重后只发送一次。
3. 评估分片同时受输入预算、输出预算、目标时长和最大条数约束；25～30 秒默认最多两条，异常长正文自动单条执行。
4. 保留结构异常后的递归拆分作为最后保险，但正常请求应在调用前完成合理装箱。
5. 创意方向继续使用现有稳定方向 ID 与局部修订机制；遗漏事实只修订受影响方向，不重新生成已通过方向。
6. 最终事实覆盖只使用 AI 已确认的 `realizedFactIds` 形成一份权威集合，择优节点和结果保存节点从同一口径投影数量与缺失项。
7. 阶段元数据增加安全的计划分片数、输入预算、实际评估调用数、拆分恢复数和局部方向修订数，不记录模型输入、响应正文或内部事实 ID。

## 非目标

- 不修改 Prompt 正文生成模板的创意要求。
- 不把多个 30 秒 Prompt 重新塞进一次候选生成调用。
- 不新增数据库表、公开 HTTP 路径或用户可见节点。
- 不自动提交 WorkingArtifact，不调用 Seedance。
- 不把 Mock 结果作为真实质量结论。

## 设计

### 1. 精简评估契约

Ark 严格结构化输出只包含模型必须判断的字段。`realizedFactIds` 从支持等级为 `EXACT` 或 `SEMANTIC_FULL` 的事实证据确定性派生；语义与视觉签名继续从结构化创意字段规范化得到，不要求模型重复输出。

### 2. 输入与输出双预算

Worker 以候选正文、创意主线、六维文本、目标时长和引用事实数量估算输入体量，同时按精简输出契约估算返回体量。加入下一条会超过任一安全容量时立即结束当前分片。

### 3. 局部方向修复

方向规划首先按稳定槽位生成；AI 复核只返回问题方向。缺失事实、关系不自然或跨方向重叠只把对应方向 ID 送入一次局部修订，未点名方向原样保留。Worker 只机械验证局部输出是否完整覆盖被点名的合法事实 ID。

### 4. 单一事实覆盖口径

最终选中项的 `insightBindings` 只来源于 AI 评估确认的事实。择优与保存共用同一个覆盖快照，避免不同节点分别计算后出现“缺 1 项/缺 2 项”的不一致。

## 验收

- 5、15、20、25、30 秒候选都能得到可解释的评估分片。
- 25～30 秒普通候选每次最多评估两条，异常长候选自动独立评估。
- Ark 评估 Schema 不再要求重复输出语义签名、视觉签名和派生事实 ID。
- 多条评估格式异常仍能递归拆分恢复，且拆分次数进入安全元数据。
- 方向局部修订不改动未点名方向。
- 择优节点与结果保存节点的必用事实总数、覆盖数和缺失数一致。
- Worker pytest、mypy、Ruff、相关 API 测试和 `git diff --check` 通过。

## 结果记录

2026-09-07 完成：

- Ark 质量评估已切换为精简输出契约。AI 继续负责事实实现、用途、评分、六轴分类和问题判断；`realizedFactIds` 及两个内部签名由已有结构确定性派生，不增加 Worker 语义判断。
- 评估输入不再发送候选 ordinal、round、generatedAt 和镜头计划等无关字段；候选事实与视觉策略继续按分片去重发送。
- 新增输入与输出双预算。默认输入规划预算为 12000 Token，25～30 秒每组最多 2 条；正文异常长时自动独立评估。
- 多条严格 JSON 异常仍只拆分当前分片；阶段安全元数据会记录计划分片、实际评估调用和拆分恢复次数。
- 创意方向沿用稳定 ID 局部修订，单个方向分片最多进行一次定向修复；未点名方向不重新生成。
- 择优与结果保存现在复用同一份最终必用事实覆盖快照，右侧节点详情不会再分别计算出不同缺失数量。

实际验证：

- Prompt Worker 全量 pytest 通过，付费集成测试按默认配置显式跳过。
- Worker mypy（19 个源码文件）和 Ruff 通过。
- API Prompt 相关 5 个测试文件共 86 项通过，API TypeScript 类型检查通过。
- 评估截断递归拆分、30 秒两条上限、覆盖补充后节点统计一致专项回归通过。
- Compose 配置解析和 `git diff --check` 通过。
- 本轮未执行新的真实 Ark 付费调用；真实耗时、Token 与格式异常率需要在下一次用户授权的正式批次中对比，不能用 Mock 结果冒充质量或成本结论。
