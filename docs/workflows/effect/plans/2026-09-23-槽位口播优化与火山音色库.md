# 槽位口播优化与火山音色库实施计划

日期：2026-09-23
状态：已按后续“开发”指令完成实现、增量迁移和现有服务部署；已获准执行并通过 1 条真实试听。长槽位新规则尚未重新执行整批付费包装。验证记录见 [开发与试听验收](../evidence/2026-09-23-槽位口播与音色库开发验收.md)。

## 1. 目标与现状

本方案属于效果类第五步“模板混剪”内的智能成片包装。解决两个问题：长素材槽位的口播过短，以及用户无法选择并试听火山音色。

当前代码只给口播提供最大字符数，钩子和结尾另有 15 字上限，并要求模型再少写几个字。此限制可能让长槽位留下过长静默，但字符数不能直接证明实际配音占用时间；改造后需要同时记录文案容量与真实音频时长。当前 TTS 从 Worker 配置读取固定音色，左侧“音频”资源页尚为占位。

上游继续使用同项目、同效果类 Run 已确认的 Prompt、素材片段和商品事实工作副本及其 revision；包装创建冻结视觉时间轴、来源依赖与音色。新包装仍只产生草稿，由节点底部统一完成操作提交视觉与包装工作副本，第六步负责真实渲染。音色选择自身只保存节点草稿，不增加视觉工作副本 revision。

## 3. 后续实施方案

以下为已批准的实施范围；第二节保留此前安全撤回的历史记录，不代表当前功能仍处于撤回状态。

### 3.1 槽位独立口播与长度

- 一个槽位恰好对应一条完整自然的口播，时长保持 3–15 秒。文案、配音、字幕均属于该槽位，禁止借用相邻素材时间。
- 按槽位时长和角色计算 `minCharacters`、`targetCharacters`、`maxCharacters`。取消钩子与结尾固定 15 字上限，改为随时长增长的较简洁表达目标。
- 模型读取槽位自身画面、角色和已确认事实，尽量贴近目标容量。允许一条口播含自然的完整句群，不以机械“一句话”约束压缩长槽位表达，也不能靠重复、空话或编造事实凑字数。
- 字符统计采用去首尾空白后、含标点的统一口径。长槽位（默认至少 6 秒）明显低于最小容量时要求修正一次；短槽位保留自然简短表达空间。初始容量以现有约每秒 3 字为保守上限，普通槽位目标约占容量 85%，钩子/结尾约占 75%，长槽位最小值分别为 65%/55%，取整数并满足最小值 ≤ 目标值 ≤ 最大值。系数作为后续小样本实测的调优参数，不能宣称它们等价于实际音频覆盖率。
- 文案过长/过短修正共用一次策划修正预算，反馈必须区分需扩展与需缩短，不能统一要求缩句。事实不足以自然扩展时保留明确失败原因，不引入 AI 审核环节。
- 真实 TTS 超时仅允许在同一槽位缩句一次，仍超时则失败；不加速、不截断词语。缩句后的真实音频优先满足时间边界，不再为追求最小字符数进入反复扩写循环。
- 保存每槽位文案字符数、最小/目标/最大容量、真实音频秒数、槽位秒数和利用率（真实音频时长 / 槽位时长）。在包装详情展示，低利用率作为调优证据，不自动再次付费重生成。

### 3.2 火山精选音色库与选择

- 复用左侧资源栏“音频”页，标题为“火山音色库”，素材、字幕、转场页保持现有用途。使用工作台既有浅色卡片、边框、选中态和加载态。
- 音色卡展示名称、性别、表达风格、当前选择和试听入口。库以服务端配置的精选目录为准，前端不硬编码另一套音色；只展示经过当前账户验证、已启用的音色，不把知道 speaker ID 当作已授权证明。
- 首版由现有服务端配置机制维护目录，不建设后台管理页面或账户全量自动同步。配置项包含稳定产品 ID、火山 speaker/resource 标识、展示资料、启用状态和验证记录；密钥不随目录返回浏览器。
- 选择保存到当前模板草稿，仅用于后续新建或主动重做包装。切换音色不自动付费、不标记已有包装过期、不改变已完成成片。
- 创建包装时冻结音色标识和必要的 Provider 配置版本，Worker 读取任务快照，不能读取用户此刻的新选择。默认音色必须是目录内已验证的当前配置音色。
- 重做整条口播时使用新选择；单槽位重做仅更换该槽位，其余已生成音频和 BGM 保留。重做音乐或字幕不改变原配音归属，结果需保留每条音频实际使用的音色信息。

### 3.3 真实试听

- 用户点击试听才创建一次 TTS 任务，使用服务端固定的产品示例文案。首次生成在按钮旁说明需要生成；命中成功缓存直接播放。
- 复用 `effect-template-mix` 容器、Python Worker、Outbox 和 `effect.template-mix.requested` 队列，通过 `schemaVersion: 2, taskType: VOICE_PREVIEW` 分支处理；不新增容器、队列、Worker 或 Compose profile。
- 试听使用独立记录，与包装 Run、工作副本确认和最终输出隔离。记录项目、工作流 Run、模板、音色/资源版本、示例文案哈希、幂等键、任务状态、attempt token、租约和文件引用。
- 缓存按项目、Run、模板、音色/资源版本及示例文案哈希隔离。重复点击复用排队、运行或已完成任务；同幂等键不同输入拒绝，并发创建由事务/唯一约束保证。
- 任务支持排队、运行、完成、失败、取消。领取、续租、上传与终态回写校验有效租约和 attempt；只有 WAV 校验、持久化与文件绑定成功才能完成。已保存音频可恢复，不能因响应丢失再次调用 TTS。
- 对付费提交结果不明的中断明确报告，不盲目重新提交。配置和权限失败由用户修复后主动重试；失败记录不能永远挡住后续有效重试。
- 试听只校验 TTS 配置，不能因音乐服务配置缺失而失败。账户权限变更导致音色不可用时显示实际失败，并禁用失效目录项，禁止静默换音色或 Mock。
- 页面轮询由服务端状态驱动；卸载或切换项目/Run/模板时终止轮询并隔离旧响应。一次只播放一个试听；开启主播放器时停止试听，避免声音重叠。
- 当前 Worker 单消息预取可能让试听等待一个长包装批次。实施时调整同一消费者内部调度，使试听有一个受限的处理机会，同时保持现有包装活动 Run 和全局供应商并发上限；不得把简单提高预取量当作无限并发。界面如实显示等待状态。

## 4. 接口、兼容与验收

### 公共接口与数据

- 新增读取精选音色目录，以及按项目、Run、模板创建/查询试听的 API。创建请求只接收有效音色 ID、作用域和幂等键，拒绝自由文本、任意 speaker 或外部音频地址。
- 内部接口包括试听 claim、heartbeat、WAV 上传、完成、失败和取消检查；Controller 使用可运行时校验的 DTO，业务与持久化分别放到 Service/Repository。
- Contracts 是跨层字段唯一来源：模板草稿新增可选音色选择；新包装快照含冻结音色；结果记录逐槽位音色及朗读指标；队列采用明确的任务类型联合，原 PACKAGING/FINAL_OUTPUT 消息仍要求原来的必要字段。
- 新增试听记录的增量数据库迁移；历史草稿、快照和音频无需改写或增加 revision。历史无冻结音色的待恢复任务沿用已有配置规则，并明确记录为历史默认来源；不能虚构它当时用了某个新音色。
- 缺失音色配置明确报错；已有音频始终可播放。试听文件沿用项目文件存储及清理机制，建立归属引用，避免被当作无主文件删除。

### 分步验证

1. Contracts/Worker：3、6、10、15 秒及越界时长；钩子、结尾、普通角色容量增长；每槽位恰好一条；短文案与过长文案反馈；有限修正；配音、字幕均不跨槽位。
2. API：项目与 Run 隔离、旧草稿兼容、音色选择持久化、快照冻结、单槽位重做保留其他音色/BGM、切换音色不导致旧结果过期。
3. 试听生命周期：并发双击幂等、请求重放、无音乐配置、未授权音色、文件损坏、旧 attempt 回写、租约过期、上传后终态响应丢失、取消、失败后主动重试和缓存复用。
4. 调度：包装活动期间试听可被处理且不突破供应商并发限额，不启动重复包装 Run，不影响原任务租约和检查点。
5. 浏览器：1920、1440 和窄屏；音频页加载/空/错误/已选状态；试听排队/播放/失败；保存后重进恢复；切换模板旧响应不污染新模板；主播放器与试听互斥。
6. 执行相关单元测试、Contracts/API/Web 类型检查和构建、Worker 语法/类型检查，以及 `git diff --check`。真实火山复测单独记录所用音色、槽位时长、音频时长、费用调用数及耗时；本次文档交付不触发付费测试。

### 交付标准

长槽位文案容量随时长增长，真实配音利用率可追踪；所有音频与字幕仍位于所属槽位。用户能在左侧音频页选择和试听已验证火山音色，下一次主动包装确实使用该音色；运行中与已完成的结果保持原有声音，刷新及恢复后也保持一致。

## 5. 运行与音色维护

- 增量迁移：`20260923160000_effect_voice_library`，只增加试听及幂等请求记录，不改历史包装数据。此前撤回留下的空迁移目录已移除，未删除数据库记录。
- API 可选配置 `TEMPLATE_MIX_VOICE_CATALOG_JSON`：JSON 数组，每项包括 `id/name/gender/description/version/speaker/resourceId/enabled/verifiedAt`。没有配置时保留当前账户已真实验证的 Vivi；`[]` 明确禁用目录。新增音色须由维护者验证当前账户权限后启用；权限变更或 speaker/resource 变更需更新 `version`。不要把密钥写入此配置。
- 公共入口位于 `.../template-mix/templates/:templateId/voice-profiles` 和 `voice-previews`，取消位于 `.../template-mix/voice-previews/:id/cancel`。只有创建试听才提交 TTS；选择音色不提交任务。
- Worker 入口位于 `internal/workers/effect-template-mix/voice-previews/:id/{claim,heartbeat,submit,audio,fail}`。`audio` 将文件绑定与完成状态在同一事务提交，没有第二次独立完成写入的失败窗口。
- 同消费者预取 2 条、长任务串行、试听串行，并共用供应商并发信号量。长任务处理期间可以处理到达的试听；同队列前方仍有其他长任务时如实排队，不承诺即时响应。
- Provider 协议依据：[火山 HTTP 单向流式 TTS](https://docs.volcengine.com/docs/DoubaoVoice/HTTPChunkedSSEUnidirectionalStreaming-V3?lang=zh)。返回音频统一保存为 24kHz、单声道、16bit PCM WAV；不在浏览器直接传递供应商密钥。
- 新旧包装兼容：旧结果显示“历史默认音色”，不猜测历史 speaker；仅新生成槽位记录冻结音色和利用率。重做音乐/字幕保留原音色；单槽位重做保留其他槽位音频及其音色。
