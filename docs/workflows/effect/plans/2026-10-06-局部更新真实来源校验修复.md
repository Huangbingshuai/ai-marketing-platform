# 局部更新真实来源校验修复

## 范围与边界

效果类渲染素材工作副本 → 当前混剪分支工程 → 局部更新快照。复用现有素材池、来源依赖、任务与提交机制，不放宽项目隔离、文件可用性、revision/hash 或合法谱系校验，不改写兄弟分支，不新增付费任务协议。

## 实施及接口

先以当前项目真实已保存工程在事务回滚中复现，并保留原始校验原因；定位素材替换后工程或依赖解析不同步的具体路径。统一局部更新与素材库的当前权威来源识别，保留实际旧绑定以判断变化，冻结当前合法来源再执行任务。只修正证实有误的机械校验与来源读取，不通过清空待更新或跳过来源校验伪装成功。

## 迁移与非目标

优先采用读取及快照构建修正；不修改真实历史数据，不删除旧成片或文件，不自动重新填充/包装，不启动未经授权的供应商调用。无 UI 改版。

## 验收

- 真实当前模板全部受影响工程在事务回滚中能够启动局部更新，不派发 Outbox。
- 同键返修、新键重新生成、未变化素材、历史分支复制依赖、连续来源更新。
- 缺失文件、错误 revision/hash、独立渲染头或跨项目素材仍拒绝。
- 更新仅修改所选分支，兄弟分支保持待更新；相关单测、数据库回归、类型检查、构建及 diff 检查。

## 根因与修正

当前权威渲染池来自另一个已发布混剪 Run 中确认的素材修改。旧读取只补齐该 Run 的渲染工作副本，没有补齐其依赖的同 Run Prompt、商品事实及资料副本；它们不在用户选择的旧分支祖先路径内。包装/输出严格沿 artifactId 校验时找不到实际依赖，被通用错误覆盖为“当前画面素材不可用”。

`listArtifacts` 现在从实际渲染来源遍历精确 WORKING_ARTIFACT 依赖，仅在同项目、该来源 Run 及其合法效果类祖先中批量加载上游三节点；遍历已载入中间节点、去重并防环。保留原始 revision/hash/availability/freshness 校验及依赖 ID，不用同名副本替代，不修改数据库，也不让节点过滤查询额外返回其他节点。

## 验证结果

- 首次真实项目回滚复现失败，内层原因是缺少素材实际引用的 Prompt/资料，而不是视频文件损坏；修正后当前测试1全部 5 条受影响工程可排队，快照绑定当前确认素材，事务回滚，不派发任务。
- 七个相关 API 测试文件 246 项通过，包含四种返修保存位置、来源 Run 的克隆 Prompt/事实依赖、未导出和已导出完成提交、所选分支更新后兄弟分支仍待更新。新增单位回归覆盖依赖部分已加载、节点过滤、跨项目/独立分支拒绝及 revision 冲突。
- 本地 API 生效后再次执行真实项目与完整输出回滚回归，3 项通过；实际 HTTP 来源返回 155 个工作副本，缺失依赖数为 0，健康接口正常。
- 当前工作区另有进行中的素材导入变更，全工作区类型检查被该改动的未生成 Prisma 类型及任务常量导入阻碍；未改动或撤销这些文件。以已提交 HEAD 构建隔离快照，仅叠加本次四个源码/测试文件，完整 API 类型检查和构建通过；相关 `git diff --check` 通过。
- 在确认填充、包装、输出、素材生成均无排队/运行任务后，仅部署本次仓储模块的构建产物并重启本地 API。未发布未完成的素材导入实现，不修改真实工程、活动分支或历史文件，不触发付费模型测试。
