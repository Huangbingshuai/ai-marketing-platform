# 模板混剪填充与包装锁定策略

## 目标

明确模板配置在智能填充、智能成片包装前后的可编辑边界，避免已确认成片与模板版本冲突；模板调整后给出明确的重新填充提示。针对单条成片重新智能填充时，复用已有的六槽位素材归属，跳过再次归槽与分配，只重新计算需要更新的裁切结果。

## 生命周期规则

| 阶段                   | 模板可编辑 | 可重新智能填充 | 行为                                                                 |
| ---------------------- | ---------- | -------------- | -------------------------------------------------------------------- |
| 智能填充排队/运行      | 否         | 否             | UI 禁用模板编辑，API 与 Worker 提交边界同时校验                      |
| 填充结束、包装尚未启动 | 是         | 是             | 模板变化保存成功并显示“需要重新智能填充”；包装入口解释并阻止过期结果 |
| 智能成片包装已启动     | 否         | 否             | 启动时原子设置持久锁；后续包装、失败和完成均不解锁                   |

包装启动后锁模板是单向状态。包装失败不自动允许模板编辑，避免同一模板对应的已生成/重试包装输入发生漂移。

## 实现范围

- 在模板草稿中区分临时智能填充锁、最近一次成功填充使用的模板配置指纹，以及包装开始后的持久锁。
- 读取工作区时根据成功填充快照与当前模板指纹计算是否需要重新填充；旧记录使用兼容比较，不把“曾有智能填充任务”误当永久锁。
- 模板修改只保存模板配置和过期提示，不因历史任务存在而返回冲突；时间轴工程的普通编辑边界保持独立。
- 创建智能填充时拒绝包装已启动的模板；在数据库事务内原子检查和设置填充锁。任务完成、最终失败时清理临时锁，重试排队中保持锁定。
- 创建包装时拒绝未重新填充的过期模板，并在同一事务内持久锁定模板。后续工作区与 API 对模板编辑、重新填充统一返回可读提示。
- 单条成片重填从当前成片的槽位绑定构造初始选择检查点，确保 Worker 跳过视觉分类/槽位分配阶段；使用新模板时长重新计算裁切，保证素材槽位不被再次打乱。
- 前端分别呈现“填充运行中”“模板已改需重填”“包装已开始不可修改/重填”三类状态；禁止按钮之外，点击包装时也解释具体原因。

## 校验

- API/Repository：智能填充运行中并发保存拒绝；成功/终态失败后解锁；模板变化能保存且标记待重填；包装过期拒绝；包装创建与持久锁原子化；锁定后编辑与智能填充均拒绝。
- Worker：单条重填携带六槽位已有素材选择，直接进入裁切阶段，不重新调用槽位分类/分配；素材绑定正确、裁切在新槽位时长内。
- Web：三个生命周期状态的提示、禁用和包装入口拦截；包装前模板变更可保存，重新填充后提示消失。
- 执行相关 API 与 Web 测试、契约类型检查及 `git diff --check`。

## 非目标

- 不改变工作流节点顺序、队列、容器、任务模型或六槽位业务语义。
- 不重新运行视觉理解、提示词生成或上游素材入槽流程。
- 不因模板配置编辑直接修改已存在包装结果；包装开始后也不提供绕过锁的人工编辑入口。
