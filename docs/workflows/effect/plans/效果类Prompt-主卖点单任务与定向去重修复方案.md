# 效果类 Prompt：主卖点单任务与定向去重修复方案

状态：已完成

## 目标

修复批量 Prompt 在卖点充足时仍把多项事实挤进同一条素材、补充轮不知道具体重复对象、候选池已明显拥挤却仍偏重单条评分的问题。保持当前八阶段、公开结果、API 路径、数据库结构和 WorkingArtifact 提交边界不变。

## 改造范围

- 新生成的素材任务以 `factIds[0]` 表示唯一主卖点，最多允许一个确有必要的辅助事实；历史检查点仍可读取。
- 卖点轮动只统计主卖点，辅助事实不能冒充已经获得独立素材。
- 向量索引测得的近似组以紧凑样例交给 AI 补充规划，AI 负责理解重复原因并设计不同观看事件；Worker 只搬运分组和已有文本，不解释语义。
- 候选池内容重复率达到 30% 时，MMR 从质量/新颖度 `70/30` 调整为 `60/40`。
- 多样性补充根据独立组缺口决定数量，但严格不超过目标数的 20%，且仍只补充一次。

## 非目标

- 不增加关键词、字符匹配、商品专用规则或新的硬淘汰门禁。
- 不恢复创意空间、方向、路线或用途配额。
- 不修改前端、公开契约、HTTP 接口和 Prisma Schema。

## 兼容与生命周期

持久化 `MaterialBrief.factIds` 继续接受旧检查点中的多事实数组；只有新 Ark 响应 Schema 和新任务校验限制为两项。新批次不复用旧 Run，失败 Run 仍按原检查点规则恢复。测试与生成只更新节点草稿，明确完成校验后才提交工作副本。

## 验收

- 自动测试覆盖主卖点轮动、新任务最多两项事实、旧结构可读取、30% 自适应 MMR、20% 补充上限和向量重复组进入 AI 补充上下文。
- 执行 Prompt Worker pytest、mypy、Ruff 和 `git diff --check`。

## 实施结果

- Ark 新任务响应 Schema 与 Worker 结构校验均限制为一个主卖点和至多一个辅助事实；历史多事实检查点仍可反序列化。
- 分页规划会按主卖点 ID 验证剩余事实轮动，辅助事实不再制造虚假覆盖。
- 多样性补充收到内容向量产生的实际近似组、对应创意主线、原观看事件和正文短摘，由 AI 负责判断并换事件。
- 候选池内容重复率达到 30% 即启用 `60/40` MMR，多样性补充严格封顶 20%。
- Prompt Worker 全量 pytest、mypy、Ruff 及仓库 `git diff --check` 已通过。
