# 局部更新自动包装进度归属

## 范围

效果类模板混剪节点。局部更新消费本次冻结的 Prompt / 渲染素材 revision，先更新已有工程，再 APPEND 新成片；已有包装模板的新增项继续原位自动包装。自动包装是同一次局部更新的最后阶段，不属于用户主动整批包装或单条包装。

## 实施

- 复用 Contracts 的 `APPEND_PACKAGE`、既有任务历史和轮询，不新增任务、数据库表或业务状态。当前 Run / 模板的自动包装进度交给同一黄色“局部更新”进度条，刷新后由真实任务恢复。
- 有自动包装时为追加及包装分段预留进度；未终态不显示完成。手动整批按钮及整批包装进度不投影 APPEND_PACKAGE，单条绿色进度规则不变。
- 保留任务真实冲突拦截；自动包装仅锁定本次新增目标成片，不能锁住未参与的原工程。锁定说明使用局部更新语义。
- APPEND 完成不自动选择新增成片，保留用户当前成片、槽位和播放位置。先同步追加结果及包装任务，再结束阶段交接。
- 不改后端包装范围、基线清理、提交边界或付费执行规则，不重做旧包装、不新增分支、不自动导出。

## 验收

- 覆盖混合变化、仅新增、无自动包装、刷新恢复、切模板 / Run、终态隐藏、迟到任务响应；手动整批和单条进度互不串用。
- 校验已有成片保留包装且不被误锁；新增成片包装逐条提交后继续即时显示。
- 执行相关 Web 单测、类型检查、构建与 diff 检查；浏览器检查 1920、1440、窄屏。不启动新付费任务，不重启正在工作的服务。
