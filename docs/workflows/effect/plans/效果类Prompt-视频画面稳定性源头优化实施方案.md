# 效果类 Prompt：视频画面稳定性源头优化实施方案

状态：已完成  
建立日期：2026-09-09  
所属工作流：效果类  
涉及节点：Prompt 生成

## 一、目标

针对真实 50 条视频中出现的手部与工具变形、物体状态跳变、多人身份漂移、流体行为失真和镜头切换后场景重置，从 Prompt 生成源头降低视频模型的执行负担，同时保留广告素材需要的产品信息、视觉细节和创意差异。

本次只修改 Prompt 生成节点，不修改视频渲染节点、参考图传递、混剪节点、成片节点或渲染后质量评估。

## 二、已确认问题

- 当前 15 秒 Prompt 平均接近 3 个节拍，部分条目同时安排多人、多工具、多种食材、多次机位变化和精确流体结果。
- “均匀覆盖、持续拉丝、完全不滴落、旋转后保持内部状态”等确定性结果超过生成式视频模型的稳定执行能力。
- 开口容器翻转、多人依次操作同一商品、多个小物体被筷子同步夹取等创意在文字上成立，但会显著增加画面故障概率。
- 现有 Prompt 质量评估对这些条目给出较高可执行性分数，但用户已明确本次不修改评估模型与评分节点。

## 三、固定边界

- 固定工作流与八阶段 Prompt 执行图不变。
- 一条 Prompt 仍对应一个 4～15 秒、无口播、可独立混剪的视频素材片段。
- 六维、创意主线、事实关系与结构化拍摄计划继续一次生成并围绕同一创意。
- Worker 只做结构、稳定 ID、数量、来源和哈希校验，不用关键词、字符相似度或自由文本规则判断语义。
- V6 公共结果、HTTP 路径、Prisma Schema、WorkingArtifact 提交边界和历史结果读取不变。
- 不通过硬编码某个商品、某类食材或固定动作词表实现修复。

## 四、实施内容

### 4.1 保持现有模型路由

- Prompt 候选生成、创意执行路线和质量评估继续使用当前已配置模型。
- 本次不通过更换模型解释或掩盖 Prompt 结构问题，先单独验证源头创作方法能否降低画面故障。
- 现有有分阶段模型环境变量与回退关系保持不变。

### 4.2 生成提示词改为“单一英雄事件”

候选模型先选择一个能代表产品价值的主要视觉事件，再生成拍摄计划：

- 4～8 秒通常一个节拍；9～15 秒通常 1～2 个连续节拍。
- 后续节拍必须推进同一动作，不得增加第二个独立任务。
- 同一时刻只保留一个主要操作关系；当画面已有多人、流体、柔性物体或大量小物体时，主动简化工具、机位和其他运动。
- 多人场景只允许一名主要操作者，其余人物作为稳定背景或非语言反应，不依次争用同一产品。
- 产品与容器动作必须符合初始开合、朝向和支撑状态；禁止为了展示内部状态而翻转已打开容器。
- 不要求视频模型精确保证“完全、始终、均匀、绝不滴落”等随机物理结果；改为描述可观察的主要变化和合理结束状态。
- 镜头变化只在能稳定保持产品状态时使用；复杂物体交互优先连续机位或轻量单向运镜。

上述内容由模型进行语义设计，Worker 不进行动作、场景或物理含义判断。

### 4.3 压缩供应商 Prompt 的重复信息

保留完整结构化 `shotPlan` 作为领域结果，但确定性编译时减少重复叙述：

- 合并画面目标、整体质感、环境、光线和首帧状态的重复句式。
- 每个时间段只保留景别、核心动作、必要的相机/焦点/运动来源和可见结果。
- 不删除产品身份、关键动作、状态承接或结束画面。
- 编译器只排版模型已经生成的内容，不补写、改写或推断商品语义。

### 4.4 生成端自检

候选模型输出前必须检查：

- 是否只有一个主要视觉事件和一条连续动作弧；
- 是否把多人、多工具、流体、柔性物体、多个小物体和复杂运镜叠加在同一条素材中；
- 跨节拍的产品开合、朝向、持物和容器状态是否有真实动作连接；
- 结束结果是否依赖视频模型完成不可控的精确物理承诺；
- 去掉声音后是否仍能看懂产品价值。

## 五、非目标

- 本次不修改质量评估提示词、评分权重、硬问题或软提醒。
- 本次不更换 Seedance 视频生成模型。
- 本次不实现参考图角色选择或渲染后视觉质检。
- 本次不自动发起真实付费 Prompt 或视频生成测试；如需真实测试由用户另行授权。

## 六、测试

- 配置测试：现有候选、方向与评估模型回退关系不发生变化。
- Prompt 模板测试：覆盖单一视觉事件、复杂度互斥、状态连续、容器安全和非精确物理结果。
- 拍摄计划编译测试：时间段完整、可选字段正确、无重复章节、历史结构仍可编译。
- Worker 回归：相关 pytest、mypy、Ruff 和 `git diff --check`。
- 不把自动测试通过宣称为真实视频质量已经提升；真实结论仍需要同商品对照渲染。

## 七、完成标准

- 新生成 Prompt 不再默认把 15 秒拆成接近 3 个独立镜头任务。
- 不再主动设计开口容器翻转、多人连续争用同一商品、复杂食材与工具同步旋转等高风险动作。
- 最终供应商 Prompt 保持具体可执行，但减少字段复述和不必要的精确结果承诺。
- 候选生成与评估模型路由保持当前行为，模型快照仍可追溯。
- 相关自动测试全部通过且未修改任务范围之外的现有用户改动。

## 八、实施与验证结果

- 已更新创意方向、补充方向、候选生成和拍摄计划模板，使模型从创意方向源头控制单条素材的执行复杂度。
- 已压缩最终供应商 Prompt 的重复标题；结构化 `shotPlan` 字段和业务语义保持完整，编译器仍不做语义推断。
- 未修改任何模型 ID、模型回退配置、质量评估提示词、评分逻辑或视频渲染节点。
- Prompt Worker 全量 pytest 通过；模板、拍摄计划、Provider 相关专项测试 63 项通过；Ruff 通过；`git diff --check` 通过。
- 仓库当前全量 mypy 检查仍有 96 个既存测试类型错误，主要来自历史测试夹具和协议桩，与本次修改文件无关；本次没有扩大范围修复这些基线问题。
- 本次未执行真实付费 Prompt 或视频渲染，因此只能确认生成规则和数据链路回归通过，不能把自动测试结果表述为真实视频故障率已经下降。
