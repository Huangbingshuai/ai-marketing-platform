# 效果类 Prompt：跨商品语义聚类替换关键词词库实施方案

> 状态：已完成

## 一、问题与目标

当前 Prompt Worker 为识别场景和产品动作的同质化，维护了“厨房、餐桌、切片、夹取、摆盘”等中文关键词正则。这些规则来自食品样本，只能识别词库中已有的表达：换成洗护、箱包、家电等商品时，新动作和新场景会大量落入 `OTHER`；同一语义采用不同措辞时也可能被拆成不同类别。

本次将去同质化依据改为当前批次 AI 已输出的动态六轴语义分类与正文向量，不再让商品专属关键词决定场景簇、动作簇、补充触发或 MMR 排序。

## 二、工作流边界

- 工作流：效果类。
- 业务节点：第 3 节点“Prompt 生成”。
- 直接上游：已提交的营销洞察与全局视频配置具体 revision。
- 草稿与提交：生成、分类和择优只更新 Prompt 领域草稿与 `WorkflowNodeState`；只有用户完成校验后才提交 `prompt-batch:{productId}` WorkingArtifact。
- 直接下游：视频渲染继续消费已提交 Prompt 批次，本次不修改第 4～6 节点。
- 不修改公开 HTTP 路径、Prompt 批次结果契约、Prisma Schema和八阶段工作流拓扑。

## 三、实施方案

### 1. 动态语义族成为唯一业务聚类依据

- 创意方向规划继续根据当前商品事实动态生成 `sceneFamily` 和 `productActionFamily`。
- 创意评估模型把候选的真实场景与主要产品动作归入本批动态词表。
- MMR 的六轴新颖度直接比较已验证的动态语义族；提高场景和产品动作在六轴簇分中的权重，但不设置硬配额。
- 场景或动作集中度、替代方向判断和定向补充全部使用评估后的动态语义族。

### 2. 删除商品专属关键词路径

- 删除食品动作正则、食品场景正则及对应中文指导词。
- 删除 `scene atom`、`action motif` 对方向分配、MMR 和补充触发的参与。
- 方向分配按 AI 规划出的“场景语义族 + 产品动作语义族”组合均衡，不再尝试从中文文本二次猜测类别。
- 评估缺失或返回未知类别时统一记为 `OTHER`，不得使用字符包含、编辑距离或汉字重合率强行归类。

### 3. 保留必要的确定性规则

- `factId`、枚举、内容哈希、规格、价格和精确重复继续使用结构化或精确校验。
- 食品状态、明显物理冲突和动作时长等可执行性规则继续保留；它们不参与创意语义聚类。
- 正文向量继续负责识别措辞不同但整体语义接近的 Prompt。

## 四、测试与验收

- 跨商品测试至少覆盖食品、洗护、箱包和家电的场景及主要动作，不引用任何固定商品动作词库。
- 同义改写由评估语义族归并，不再依赖字符重合。
- 缺失或未知语义分类变为 `OTHER`，不会被字符相似度误归类。
- 场景/动作超过 40% 时仍只触发一次软性定向补充，并保持精确数量优先。
- 回归方向分配、动态词表校验、向量 MMR、人工条目、事实覆盖和结果保存。
- 执行 Prompt Worker pytest、mypy、Ruff 与 `git diff --check`。

## 五、非目标

- 不新增模型调用或用户可见节点。
- 不为每个商品维护动作/场景字典。
- 不使用场景或动作硬配额淘汰候选。
- 不修改事实绑定语义判定；该问题另行治理。

## 六、实际实施结果

- 已删除食品专属的场景正则、动作正则、中文避让映射以及基于字符包含、编辑距离、汉字重合率的语义补全。
- 创意方向分配、MMR 六轴新颖度、场景/动作集中度与定向补充，现统一使用当前商品批次由模型生成并经 Worker 校验的 `sceneFamily`、`productActionFamily`。
- 缺失或不属于当前动态词表的分类明确记为 `OTHER`，不再根据正文字符猜测业务类别。
- 生成与评估模板已改为跨商品口径，示例覆盖洗护、箱包、家电和食品；示例只说明结构，不构成固定词库。
- 食品安全、事实真实性、物理可执行性等确定性校验继续保留，但不参与创意聚类或多样性排序。
