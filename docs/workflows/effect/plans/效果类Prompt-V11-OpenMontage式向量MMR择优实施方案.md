# 效果类 Prompt V11 OpenMontage 式向量 MMR 择优实施方案

状态：真实三品类验收通过，已切换 Vector
开始日期：2026-08-28

## 1. 目标

在 V11“精确数量择优与补充”阶段，将现有 `80% 质量 + 20% 新颖度` 的弱 MMR 改造成正文单向量驱动的 OpenMontage 式 MMR。一般语义相似只降低排序，准确达到用户目标数量仍是第一优先级。

本次不引入大模型判重、向量数据库、视频画面去重或新的前端配置，不修改 Prompt 结果 Schema、WorkingArtifact 提交边界和下游视频渲染契约。

## 2. 核心设计

- 新 Run 使用 `MMR_CONTENT_V2`；没有策略版本的历史 Run 保持旧选择策略。
- 只向量化 Prompt 正文，六维只参与覆盖统计和稳定决胜。
- MMR 分数为 `70% 质量相关度 + 30% 语义新颖度`。
- 全量生成将人工保留项作为固定参照；单条重新生成将其他批次条目作为固定参照。
- 向量使用 NumPy `float32` 矩阵归一化和点积，不持久化原始向量。
- 初轮仍生成目标数的 120%；只有高风险语义分组冗余超出软容忍量时，才额外生成一次最多目标数 20% 的候选。
- 多样性补充失败不影响已有准确数量，只记录安全化软告警。

## 3. 跨层边界

- API 输入快照增加选择策略版本和相似度固定参照；数据库继续使用现有 JSON 字段，不新增迁移。
- Worker 负责向量、MMR、风险分组、条件补充和安全阶段指标。
- 公开启动接口和结果结构不变；节点详情只投影数量、耗时、权重、分组和补充结论，不暴露模型、Endpoint、原始向量和内部 ID。
- Prompt 批次仍只在用户完成校验时提交 WorkingArtifact；本次选择算法变化不会提前更新工作副本，也不会直接标记视频渲染节点。

## 4. 验收口径

- 所有可完成批次严格达到用户目标数量。
- 无人工参照的 60 个候选只生成 60 份向量输入。
- 高风险近重复或语义冗余相对旧基线下降至少 15%，平均质量分下降不超过 2 分。
- 六维唯一值覆盖和已实现事实覆盖不得下降。
- 60 候选、2048 维的本地矩阵与 MMR P95 不超过 50ms。
- 先保持 `shadow`；食品、日用品和设备样本均达标后才允许切换 `vector`。

## 5. 实施记录

### 5.1 已完成实现

- 新 Run 快照写入 `selectionPolicyVersion=MMR_CONTENT_V2` 和固定参照；批量任务使用人工保留项，单条重新生成使用目标条目之外的全部现有 Prompt。
- 新策略只编译正文向量，使用 `effect-prompt-embedding-text-v2` 缓存键；没有策略版本的历史 Run 继续使用旧正文＋六维双向量算法。
- NumPy `float32` 矩阵一次完成归一化与相似度点积；MMR 使用 `70%` 质量、`30%` 新颖度，并用六维新增值、质量和稳定序号依次决胜。
- 数量补充最多三轮；语义高风险冗余超出软上限时，另有一次最多目标数 `20%` 的多样性补充。软目标没有达到时仍保存准确数量，只返回中文提醒。
- 分片任务持久化 `INITIAL / QUANTITY / DIVERSITY` 补充类型；V11 内部分片允许独立的第 4 轮。旧的在途 V2 分片缺少该字段时，根据上一轮是否已经达到准确数量推断补充类型，避免恢复后重复补充。
- 节点详情展示固定参照数、正文向量输入、请求与矩阵耗时、MMR 权重、补充前后冗余和多样性补充结果，不展示模型、Endpoint、向量或内部标识。

### 5.2 实际自动验收

- Worker 全量 `pytest`、`mypy src`、`ruff check src tests`：通过；付费 Ark 标记测试跳过。
- API 全量测试：31 个文件、289 条用例通过；新增 V11 round 4、节点安全投影和快照策略断言通过。
- Contracts：3 个文件、15 条用例及 TypeScript 类型检查通过。
- 60 个候选验证只产生 60 个正文向量输入，候选对比较数为 1770；历史算法的 60 个候选仍为 120 个向量输入，兼容路径未改变。
- 固定参照测试确认：与参照完全相同的候选从首条选择中被压后；参照本身不占目标数量。
- 全相同测试向量构造高风险批次：初始 12 条候选为 10 条目标触发且仅触发一次 2 条多样性补充，最终保存 10 条，累计向量输入 14、请求 2 次，并产生软提醒而非失败。
- 60×2048 维矩阵和 50 条 MMR 选择的本机 50 次非付费基准：P50 `0.769ms`、P95 `0.954ms`、最大 `1.252ms`，低于 50ms 门槛；NumPy 与参考余弦误差测试不超过 `1e-6`。
- `git diff --check` 通过，仅有仓库既有 LF/CRLF 转换提示。

### 5.3 真实付费三品类对照验收

2026-08-28 获得用户明确授权后，使用当前已开通的 `doubao-embedding-vision-251215` 多模态向量端点完成真实验收。付费范围只有文本向量，不调用文本生成、Seedance 或其他模型。

第一组为食品、日用品、设备共 180 组人工标注语义对照：

- 三元组字符基线：同义近重复召回率 `0%`，不同创意误判率 `0%`。
- 向量算法：同义近重复召回率 `56.67%`，不同创意误判率 `0%`。
- 相对字符基线召回提升 `56.67` 个百分点，超过至少提升 `20` 个百分点的门槛，且没有新增误判。
- 并发 `2` 耗时 `462.25ms`，并发 `8` 耗时 `250.03ms`。
- 本组产生 `169` 次向量请求、`7657` 个输入 Token。

第二组使用三个各含 60 条候选的受控业务候选池，分别由字符基线、旧 `80/20` 向量和新 `70/30` MMR 选择准确 50 条。验收结果如下：

| 品类   | 最终数量 | 字符基线高风险冗余 | 新 MMR 高风险冗余 | 平均质量变化 | 六维唯一值总数 | 事实覆盖 |    向量耗时 |
| ------ | -------: | -----------------: | ----------------: | -----------: | -------------: | -------: | ----------: |
| 食品   |       50 |                  1 |                 0 |     `+0.036` |        52 → 52 |    8 → 8 | `1832.63ms` |
| 日用品 |       50 |                  0 |                 0 |     `+0.066` |        52 → 52 |    8 → 8 | `2048.77ms` |
| 设备   |       50 |                  0 |                 0 |     `+0.066` |        52 → 52 |    8 → 8 | `1517.53ms` |

食品候选池的高风险冗余下降 `100%`；日用品和设备的字符基线本身没有高风险冗余，新 MMR 保持为零，因此按“零基线不新增冗余”判定通过，而不伪造无定义的下降百分比。三类数量均准确、质量没有下降、六维和事实覆盖没有下降，三次向量阶段均低于 `2.5s` 门槛。受控业务组共产生 `180` 次请求、`6337` 个输入 Token。

验收过程中还执行过一次错误样本构造：20 条所谓独立样本实际复用了同一机械模板，被向量正确聚成高风险组；该轮结果不用于算法结论，但产生 `180` 次请求、`7045` 个输入 Token。两次在模型调用前触发的样本 Schema 错误产生 `0` 次请求。连同第一组准确率基准，本次可核对的付费调用合计 `529` 次、`21039` 个输入 Token。调用数高于早期“最多 30 次”的文字预估，是因为该多模态端点每次最多接收一个文本；生产实现已通过并发 `8` 控制总耗时，并保持每个候选只生成一份正文向量。

### 5.4 上线决定

真实结果证明向量对字符算法漏掉的同义表达有显著增益，同时没有造成不同创意误判、数量不足、质量下降或覆盖下降。因此部署默认从 `shadow` 切换为 `vector`：新 Run 的权威选择由正文单向量 `70/30` MMR 完成；一般相似仍只影响排序，不形成硬删除或数量阻断。

保留 `shadow` 和 `trigram` 作为显式诊断与回退模式。若生产监控出现向量超时、错误率或成本异常，应显式切回 `shadow`，不得在 `vector` 运行中静默退回字符算法并伪装成功。
