# 效果类恢复缓存扩展

## 目标与实施边界

把可验证版本的恢复投影尽量纳入共享 Redis，减少重复进入六个节点的数据库读取和序列化。PostgreSQL 校验当前版本，保持项目、效果类 Run、产品、模板与分页隔离；实时任务、原始资料正文、二进制和签名 URL 继续走原有链路。公共接口与业务提交边界保持现状。

## 已发现问题

- 资料导入读取调用初始化事务，每次更新工作区 updatedAt，改变缓存依赖的物理版本，连带使后续节点缓存失效。
- 资料包元数据尚未进入 Redis；当前 50ms 最低加载门槛会使提炼、Prompt、渲染等较快读取跳过缓存。
- 资料导入读取还等待存储清理；清理任务已有持久化记录及每分钟后台处理器。
- 成片页恢复读取当前混剪工作区、版本树，再读取模板来源 Run，并进行缺失投影补偿。须继续核对这些读取/补偿是否必要，不能仅凭单接口命中宣称页面整体提速。

## 实施顺序

1. 初始化增加完整工作区的只读路径，缺失 Run/工作区/草稿模式时保留原有幂等初始化事务。
2. 将资料导入工作区与草稿元数据纳入版本校验缓存，模式进入缓存键；不缓存文件正文。存储清理由现有后台处理器执行，读取仅持久化过期预览的清理任务。
3. 默认允许所有已审核的恢复投影进入缓存，将 TTL 延长到 30 分钟；版本变化即时换键，TTL 不作为内容新鲜度依据。保留可配置的快速读取门槛用于实测回退。
4. 检查现有六节点缓存与成片恢复读取，优先删除已证实的重复开销。无法证明依赖完整的读取继续数据库兜底。
5. 使用真实 Nest HTTP、PostgreSQL、Redis 的隔离项目验证六节点资源命中、资料包两轮修改即时恢复、反复进入不改变版本、断连回退。测真实项目冷/热请求及浏览器节点切换，并报告未覆盖范围。

## 验收

- 所有缓存条目有 TTL、校验和、权威版本及有界大小；损坏、断连、活动任务、版本变化均有既有兜底。
- 反复读取导入页不会修改工作区或使其他节点缓存失效。
- 两次修改后马上读到新草稿；模式/项目/Run 隔离测试通过。
- 类型检查、相关测试、格式检查、git diff --check；不产生付费任务，不提交 Git。

## 实施结果（2026-10-08）

已实现步骤 1–3，另将渲染缓存提升到完整工作区，纳入经审核的效果类节点产物、产品分页与移除列表。返修 QUEUED/RUNNING 也触发实时读取。定期清理器独立处理过期预览；成功删除存储后只清除未转移、非有效预览的临时元数据，避免重复入队。

成片恢复的模板来源 Run 读取用于真实模板路径隔离，现阶段保留；缺失队列补偿属于既有恢复逻辑，没有缓存其 POST 操作。通用 Run 概览与混合产物列表仍直接读取数据库，不将未审核的原始资料 payload 放入 Redis。

真实 HTTP、数据库与 Redis 测试证明六节点的目标读投影已接入并命中缓存；相关 13 个测试文件、160 项测试通过。API 类型检查、相关 ESLint、生产构建通过。实测、命令及边界见 [验收记录](../reports/2026-10-08-恢复缓存扩展验收.md)。
