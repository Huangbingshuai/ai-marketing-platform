# 精修工作台：字幕口播对齐 / 可试听可拖动 / 轨道按键不再吃空格

日期：2026-09-25
需求原话（三条实测问题）：

> 1.生成的口播根本就没有对齐字幕；2.生成的口播音频素材根本听不了，移动也报错；3.音频素材轨道静音之后不应该使用空格键控制静音是否关闭，通过点击控制即可，轨道同的按键全部不要通过空格键控制

承接 `2026-09-24-精修工作台字幕生成口播.md`（字幕口播功能本体）。本轮不新增功能，只修这三条实测问题。

## 一、范围

| # | 现象 | 本轮口径 |
| --- | --- | --- |
| 1 | 生成的口播没有对齐字幕 | 合成结果**开头有一段引擎自带的近静音**（实测 0.68s），而片段 `start` 严格等于字幕 `start`，于是听感上「字幕已经出现、声音还没起」。在 **worker 合成侧裁掉这段前导静音**，保留 0.08s 预卷。 |

### 2.1 问题 2b：`captionVoices` 在 DTO 里不存在（已实测复现 400）

`apps/api/src/workflows/effect/template-mix/effect-packaging.controller.ts:106-116`：

`apps/api/src/main.ts:27-31` 是 `new ValidationPipe({ transform: true, whitelist: true, forbidNonWhitelisted: true })`，所以多出来的键一律 400。实测（API 跑在宿主机 3100 端口，无鉴权）：

### 2.2 问题 2a：`captionVoices` 从来没有被播放过

`apps/web/src/workflows/effect/template-mix/EffectTemplateMixPackaging.vue`：

- `:301-302` 只声明了两个元素：`voiceElement` / `musicElement`。
- `:350-367` `currentVoiceEntry` 只读 `selected.value?.checkpoint.voices`（外加 LEGACY 的 `selectedVariant.voice`）。
- `:389-481` `syncAudio` 只遍历 `[['VOICE', voiceElement, currentVoice, …], ['MUSIC', musicElement, currentMusic, …]]`。
- `:483-527` `startPlaybackAudio` 只给 `currentVoice` 做「静音预卷」（浏览器的用户手势限制要求如此）；`:528-543` `stopPlaybackAudio` 也只暂停这两个元素。

结论：`checkpoint.captionVoices` 既没有元素、也没有进入 `syncAudio` 的循环，**工作台里必然听不到**。

同时 `EffectTemplateMixNodePage.vue:830-867` 的 `previewHasPackagingAudio`（驱动右上角声音监控灯）也只统计 `voices` / `music` / `detachedAudios`，漏了 `captionVoices`。

> 为什么不能复用 `voiceElement`：字幕口播是**故意与槽位口播并排存在**的（见 `2026-09-24-精修工作台字幕生成口播.md` 决策 2「并列新增」），两者的 `start` 区间会重叠，一个元素只能跟一条，复用必然丢一条。

### 2.3 问题 1：片段几何是对的，音频本身头部有静音（已实测）

实测数据（项目 `65458686-034c-4258-b2dd-027d4ad15132`，成片 `71027be6-97a9-4770-8f02-42650a677b32`）：

- 字幕 `caption-2183e9e90838e91503c6b262`：`start = 8.766`，`end = 10.979`（长 2.213s），文本「加两颗青菜就能等出锅」。
- `captionVoices[caption-2183e9e90838e91503c6b262]`：`start = 8.766`、`duration = 3.010`、无 `offset`，文件 `34a28754-…`（144508 B）。
- 服务端写回点 `effect-packaging.service.ts:752-757`：`start: caption.start`（注释「Aligned on the caption by construction」），所以**存的几何是严格对齐的**。

把该 wav 下载后按 20ms 窗算 RMS 包络（24 kHz 单声道 16-bit，3.0097s，峰值 RMS 0.169，阈值 `max(0.005, 峰值×8%)`）：

```
..................................################...####.#######################........###############.#######.##..##....#########...................
0s                                0.68s                                                                                          2.64s            3.01s
```

- **前导近静音 0.68s**，语音 0.68s→2.64s，尾部近静音 0.37s。
- 对比流水线槽位口播的同一指标只有 0.20–0.25s 的前导。

即：字幕出现后 0.68s 才出声，字幕只有 2.213s 长，等于三分之一的时间是「字幕已在、声音没来」——用户描述为「根本就没有对齐」。

`packaging_media.py:25-34` 的 `pcm_wav` 是**逐字节写 PCM**，全仓库没有任何静音裁剪逻辑（`grep silence|trim` 无命中）。所以这不是几何 bug，是合成产物本身的头部静音。

### 2.4 问题 3：`buttonOwnsKey` 让焦点按钮吃掉 Space

`EffectTemplateMixNodePage.vue:4760-4792`（`onEditorKeydown` 挂在 `window` 上，`:4905`）：

```ts
const buttonOwnsKey =
  Boolean(target?.matches('button')) &&
  !target?.closest('.transition-junction') &&
  !activeTransitionSlotId.value &&
  (event.code === 'Space' || event.key === 'Enter');
if (target?.matches('input, textarea, select, [contenteditable="true"]') ||
    buttonOwnsKey || target?.closest('[role="dialog"]')) return;
…

```

轨道按钮（`EffectTemplateMixTimeline.vue:2984-3014` 的 `.track-actions`：锁定 / 显示 / 静音）都是 `<button>`。点一下静音后焦点留在该按钮上，再按空格：`buttonOwnsKey` 命中 → **提前 return，没有 `preventDefault`** → 浏览器原生 Space 激活再点一次该按钮 → 静音被关掉。用户要的「通过点击控制即可、轨道按键全部不要空格控制」正是这个。

## 三、设计

### 一、worker 侧裁掉字幕口播的前导静音

在 `workers/effect-template-mix/src/effect_template_mix/packaging_media.py` 里 `pcm_wav` 旁边新增纯 Python 的 `trim_leading_silence(pcm, rate)`：

- 20ms 窗 RMS 包络，阈值 `max(0.005, 峰值 × 8%)`（与实测口径一致）；
- 找到第一个越过阈值的窗作为起点，**保留 0.08s 预卷**（不切掉第一个音素的起振）；
- 全静音 / 起点本来就短于预卷 → 原样返回（不产生负索引）；
- 只在 `caption_voice.py` 调用它。

**为什么不改 `pcm_wav` 本身**：`pcm_wav` 同时服务流水线槽位口播（`packaging.py:613`），改它等于改变**已经付费生成**的既有成片的 `duration`。字幕口播是唯一「`start` 必须等于另一条内容（字幕）的 `start`」的音频，前导静音在它身上才构成错误。

**为什么不只裁尾**：尾部静音不影响「对不对齐」，裁尾会改 `duration`、进而可能改 `effectTemplateMixContentDuration`（黑尾长度），收益为零。本轮只裁头。

**为什么不在 API 侧改 `offset`**：那需要 API 解码 WAV、把音频包络逻辑复制到 TypeScript 里；worker 才是音频生产边界（`pcm_wav` / `music_wav` / ffmpeg 都在那儿）。

### 二、给工作台补第三个音频元素

`EffectTemplateMixPackaging.vue`：

- 新增 `captionVoiceElement` ref 与 `playbackBlocked.CAPTION_VOICE`；
- 新增 `currentCaptionVoiceEntry`（`id` 用 `capvoice:<captionId>`，正好与时间轴的 clipId 同名，`rowMuted` 才能按行静音）/ `currentCaptionVoice`；
- `syncAudio` 的遍历数组**追加第三条**（既有两条的字面量必须保持逐字节不变，`effect-packaging-audio.spec.ts:39-42` 在断言它们）；
- `play` 失败回调里 `isMusic` 的分支扩展成三选一（否则字幕口播的失败会被记到 `VOICE` 头上）；
- 把 `startPlaybackAudio` 里那段「静音预卷」抽成 `primeElement(audio, element, clipId)`，语音与字幕口播各调一次；`stopPlaybackAudio` 抽成 `releaseElement(element)` 释放三个元素。
  - 预卷是**必须的**：字幕口播的 `start` 通常远晚于用户按播放的手势，没有预卷时那一刻的 `play()` 会被浏览器以「非手势」拒掉，表现为「还是听不见」。

`EffectTemplateMixNodePage.vue` 的 `previewHasPackagingAudio` 并上 `captionVoices`（按 `capvoice:<captionId>` 查行静音），否则只有字幕口播在响时声音监控灯是灭的。

### 三、DTO 补 `captionVoices`

`UpdatePackagingAudioDto` 加：

```ts
@IsOptional() @IsObject() captionVoices?: Record<string, PackagingAudioEditDto>;
```

服务层（`effect-packaging.service.ts:539-560`）与契约（`:161`）都已就绪，零额外改动。

### 四、时间轴内的按钮不吃空格

```ts
const buttonOwnsKey =
  Boolean(target?.matches('button')) &&
  !target?.closest('.mix-timeline-shell') &&
  !target?.closest('.transition-junction') &&
  !activeTransitionSlotId.value &&
  (event.code === 'Space' || event.key === 'Enter');
```

- Space：不再提前 return → 落到 `:4814` 的 `event.preventDefault(); togglePreviewPlayback()`。`preventDefault` 在 keydown 上正好取消 `<button>` 的原生 Space 激活，所以**不会**再点一次静音。
- Enter：`buttonOwnsKey` 变 false 后没有任何分支消费 Enter，也不会 `preventDefault`，原生激活照旧 —— 键盘可访问性不退。
- 范围取整个 `.mix-timeline-shell`（含标尺、`.edge-trim-handle`、`.playhead-handle`），与用户「轨道同的按键全部不要通过空格键控制」一致。

## 五、非目标

- 不改「字幕口播不跟随字幕移动」的既有口径（`2026-09-24-精修工作台字幕生成口播.md` 决策 2）——那是「对齐」不是「绑定」。
- 不裁尾部静音，不动 `pcm_wav` 本身，不改流水线槽位口播的任何产物。
- 不给**已生成**的字幕口播做数据回填：需要用户重新点一次「生成口播」（新的字节与旧的 sha256 不同，服务端会正常替换）。理由见 §六。
- 不做「多路字幕口播同时播放」：一个元素一次只跟一条，与既有 `voiceElement` 的单条语义一致（字幕本身不重叠，正常路径下不会同时有两条在播）。
- 不改 `EffectTemplateMixTimeline.vue` 的按钮标记（用 `closest('.mix-timeline-shell')` 在键盘侧统一处理）。
- 不碰 `final_output.py` / 契约 / 其它 worker 模块。

## 六、风险与边界

- **必须重建 worker 镜像**：`compose.yaml` 的 effect-* worker 只有 `build:` 没有源码挂载，`docker compose --profile effect-template-mix up -d --build effect-template-mix-worker` 才会生效（否则改了源码也不生效，这正是上一轮「口播生成不出来」的原因）。
- **已生成的那条口播仍然是 0.68s 晚**：本轮改的是合成路径，磁盘上已存在的 wav 不会被改写。要看到效果必须重新生成一次字幕口播。
- **0.08s 预卷是硬编码的**：非常短的词（如「蒸好煎香」）如果引擎给的前导静音本来就只有 0.1s，裁掉后只剩 0.08s，听感上不会更差；全静音/异常输入有原样返回兜底。
- **阈值是相对峰值的**：`max(0.005, 峰值×8%)`。实测这条素材峰值 0.169、阈值 0.0135，前导噪声底约 0.005–0.01，判得很干净。若将来引擎输出整体音量很低（峰值 < 0.0625），阈值退化到 0.005 的绝对下限，仍不会把噪声底当语音。

### 7.4 实施偏差

1. **`fadeKind` 在调用点归一化，而非放宽契约签名**。`packagingAudioFade` 的 `kind` 参数类型是 `'MUSIC' | 'VOICE'`，直接传 `'CAPTION_VOICE'` 触发 `TS2345`。为避免与并行会话正在改的 `packages/contracts` 撞车，在 `EffectTemplateMixPackaging.vue` 的调用点加一行 `const fadeKind = kind === 'MUSIC' ? 'MUSIC' : 'VOICE'`（`kind` 只影响默认淡入淡出长度，且只区分音乐与语音）。
2. **`trim_leading_silence` 的「起点短于预卷」分支**：单测里 `silence(.1) + speech(1) + silence(.3)` 期望是 `silence(.08) + speech(1) + silence(.3)`，即只要前导超过 0.08s 就一律收到 0.08s（不是「最多裁 0.02s」）。
3. **worker 全量单测需显式 `--basetemp`**：Windows 上默认临时目录会 `PermissionError: [WinError 5] … pytest-of-mikasa`（与本轮改动无关），改到仓库内临时目录即 227 全过。
