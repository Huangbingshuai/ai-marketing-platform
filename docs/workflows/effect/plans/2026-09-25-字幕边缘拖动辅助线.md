# 字幕边缘拖动：吸附与竖向辅助线（第六轮）

承接 `2026-09-25-字幕自由拖动与音频素材删除.md`。上一轮去掉了「字幕不能拖」的挡板，字幕中段拖动已经和视频素材一致。但用户接着报：

> 「字幕素材出问题了，左右拖动的时候碰到别的素材的头尾出现不了竖线辅助线」

## 一、先证明是哪一种「左右拖动」

时间轴上字幕有两种横向手势，两条代码路径：

| 手势                   | 入口                                                                       | 走的拖动分支     | 辅助线               |
| ---------------------- | -------------------------------------------------------------------------- | ---------------- | -------------------- |
| 抓字幕中段平移         | `onCaptionPointerDown` → `beginAudioDrag(..., 'MOVE', ...)`                | `MOVE`           | 上一轮已统一，**有** |
| 抓字幕左右两端把手伸缩 | `beginCaptionTrim(..., 'LEFT'/'RIGHT')` → `beginAudioDrag(..., side, ...)` | `LEFT` / `RIGHT` | **从来没有**         |

`snapGuideTime` 改动前全仓库只有两处赋值：视频 `MOVE`（`:2365`）与音频/字幕 `MOVE`（`:2581`）。**`LEFT` / `RIGHT` 两个分支既不调用 `snapDraggedBlock`，也从不写 `snapGuideTime`** —— 所以字幕（以及口播、纯音乐）伸缩边缘时不可能出辅助线。

真浏览器探针（Playwright + Vite 5173，用用户「测试4」模板的真实几何：六槽位 `4/10/10/10/8/4` → 视频边缘 `0/118/414/710/1006/1243`，14 条字幕，口播与纯音乐同真实快照）逐帧采样 `.snap-guide` 与字幕卡片矩形：

```
pps ≈ 29.587（1361px / 46s，由视频边缘反推）

MOVE（抓 c5 中段右移，尾巴去碰 t=24 的视频边缘）
  guide 480 → 命中 c6 头；guide 557 → 命中 c7 头；guide 604 → 命中口播 c5 尾；
  guide 710 → 命中 t=24 视频边缘，captionRight 正好停在 710        ← 有辅助线

TRIM-RIGHT（抓 c5 右把手右移，尾巴穿过 t=24 的视频边缘 710）
  尾部 492 → 516 → 540 → … → 708 → 732 → … → 828，guide 全程 null  ← 无辅助线，直接穿过

TRIM-LEFT（抓 c5 左把手左移）
  captionLeft 全程 414，纹丝不动                                   ← 连动都不动
```

两条结论都被代码解释清楚：

1. **TRIM-RIGHT 无辅助线**：`RIGHT` 分支只算 `currentDuration`，不查 `snapEdges`、不写 `snapGuideTime`。
2. **TRIM-LEFT 完全不动**：`LEFT` 分支的下界是 `Math.max(drag.minStart - drag.initialStart, -drag.initialOffset)`。字幕的 `captionDragTarget` 是 `offset: 0`（字幕是纯文本，没有源素材），于是 `-drag.initialOffset = 0`，下界被钳成 0 —— 只能往右缩，永远不能往左伸。用户说「左右拖动」而实际只有「右」能动，正是这一条。

所以这不是「辅助线丢了」，而是**边缘伸缩这条路径上从来没有吸附，其中左边缘连位移都没有**。

## 二、修法：给伸缩一个单边吸附

`MOVE` 吸附的是「整块的首尾两端」，所以 `snapDraggedBlock` 一次探 `[0, rawStart]` 与 `[duration, rawStart + duration]` 两个点。伸缩只动**一个**端点，用不了它，于是新增一个单边版本，辅助线仍写同一个 `snapGuideTime`，因此伸缩与平移画出来的是同一条线：

```ts
const snapEdgeTime = (
  time: number,
  ignored: Set<string>,
  window: { max: number; min: number },
): { guide: number | null; time: number } => { … }   // 阈值同为 7px，窗口外不算命中
```

三个分支共用同一个 `ignoredIds`（原先在 `MOVE` 里内联构造，提到分支外，顺带让三处语义一致）。

**左边缘**——先修「动不了」，再吸附：

```ts
const headFloor =
  drag.initialSourceDuration === Number.POSITIVE_INFINITY
    ? drag.minStart // 字幕无源素材，可一路退回时间轴起点
    : Math.max(drag.minStart, drag.initialStart - drag.initialOffset); // 有源的只能露出被裁掉的那段
```

`sourceDuration === Infinity` 是全仓库唯一的「无源素材」标记（`captionDragTarget` 是唯一写它的地方，`:2230`），而且 `RIGHT` 分支早就靠它算出「无上界」。用它比新加一个布尔字段更贴近既有表达。

**右边缘**——保持原有上下界，只把「算长度」换成「先算出端点、吸附、再折回长度」：

```ts
const tailCeiling = Math.min(
  drag.initialStart + drag.initialSourceDuration - drag.initialOffset,
  drag.maxEnd,
);
const tailFloor = drag.initialStart + minimumDuration;
```

口播/纯音乐的 `sourceDuration` 是 `offset + duration`（`:691`/`:712`），所以 `tailCeiling` 恰好等于当前尾巴 —— **它们本来就不能往右伸长，改完仍然不能**，只是现在往左缩的时候会吸附。视频槽位的 `edgeTrimDrag`（`:2521-2554`）**不动**：槽位由模板首尾相接铺开，边缘天然重合，吸附没有可命中的对象；那条路径还背着 4–15 秒与源素材长度的槽位不变量，属于另一件事。

## 三、实测（Playwright 探针，改后重跑）

```
TRIM-RIGHT
  guide 557，captionRight 正好 557（命中 c7 头）
  guide 710，captionRight 正好 710（命中 t=24 视频边缘）      ← 出现辅助线且精确落位

TRIM-LEFT
  captionLeft 404 → 385 → 364 → 344 → 325（guide 325 = c4 尾 t=10.976）
            → 304 → 284 → 271（guide 271 = c4 头 t=9.169）    ← 能动了，且吸附到别的字幕首尾

MOVE（回归）
  guide 480 / 557 / 604 / 710，与改前逐帧一致
```

`guide 325` 与 `guide 271` 分别等于 c4 的 `end = 10.975708` 与 `start = 9.168542`，正是用户说的「别的素材的头尾」。

## 四、非目标

- **不改视频槽位 `edgeTrimDrag`**：见上，槽位边缘由模板铺排决定，重合是常态。
- **不在伸缩落点做「同轨重叠则新建轨道」**：`MOVE` 落点有 `captionOverlapsOwnTrack` → `splitCaptionTrack` 的处理，伸缩落点没有，这是**改动前就存在**的行为。吸附只会把尾巴更容易地停在邻居的头上（一个合法的、不重叠的落点），不会新增重叠。留给后续。
- 不动 `snapEdges` 的构成、阈值 7px、`snapEnabled` 磁铁开关、行静音、以及任何契约 / API / worker 侧代码。

## 手动验收

用广式腊肠项目 `65458686-034c-4258-b2dd-027d4ad15132`「测试4」模板：

1. 选中一条字幕，抓**右**把手往右拖，尾巴碰到下一条字幕的头 / 视频片段边缘 → 出现蓝色竖线并精确停住。
2. 抓**左**把手往左拖 → 现在能伸长（以前纹丝不动），碰到上一条字幕的尾 / 视频片段边缘 → 出现蓝色竖线并精确停住。
3. 抓字幕中段平移 → 辅助线与落位和本轮之前一致（回归）。
4. 同样手势试口播、纯音乐片段 → 伸缩时也出辅助线；右边缘仍然不能超过源素材长度。
5. 关掉磁铁按钮 → 三种手势都不吸附、不出线。
