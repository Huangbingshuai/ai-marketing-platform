# 删除混剪模板后渲染新增素材丢失修复

## 已观察的问题

项目回退到原始渲染 Run 后读取20条。R-021、R-022 的已确认导入文件及完整来源快照仍保存在多个历史渲染副本中，文件身份一致。模板清理按专属 Run 删除所有工作副本，只保留仍有下游引用的来源，因此上游素材池索引也可能被删除。删除最后一个模板不等于删除渲染素材。

## 范围

- 修正效果类混剪删除的后台清理：资料、提炼、提示词、渲染产物是共享上游，不因引用归零删除。保留原身份、revision和最小来源容器，继续隐藏已删除模板分支。
- 活跃谱系的素材查询允许读取保留容器中的共享上游及精确依赖闭包；被删除模板的工程和输出、删除 Run 自身的读取仍不可见。
- 不改模板删除确认、异步响应或防复活保护，不自动生成视频，不修改独立历史渲染副本。
- 当前数据只恢复明确缺失的两个已确认导入项，保留当前20条画面和已存在的删除标记；不采用未确认编辑、不按数量或时间选择整批历史结果。
- 恢复脚本默认只读，按明确项目、来源批次和目标批次校验；逐项检查已确认素材池成员、任务版本、文件身份和指纹。应用时锁定项目与批次，复用现有产物构造及提交方法，事务失败全部回滚，重复执行不追加。

## 验证

- 隔离数据库验证无人引用的上游素材池和单片仍保留，模板专属工程、包装、输出仍删除。
- 验证共享来源容器不能再被识别为其他模板的活分支、不能被迟到请求复活。
- 恢复前后只输出安全数量和状态；检查两条真实文件可读取；不调用模型，不产生 Outbox。
- 相关单元/数据库测试、API 类型检查、构建与 diff 检查；实际 workspace 和浏览器复核22条及第二页。

## 非目标

不清理历史文件、不恢复已删除混剪模板、不重做20条视频、不推送或提交 Git。

## 2026-10-09 实施与实际验证

- 修正后台清理和公共素材读取两层边界。隔离数据库回归覆盖：共享池保留22条、当前来源不回退、删除分支不可见、模板专属数据清除、重复删除和 Redis 隔离。
