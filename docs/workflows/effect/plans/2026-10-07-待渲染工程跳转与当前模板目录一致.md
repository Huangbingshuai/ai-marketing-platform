# 待渲染工程跳转与当前模板目录一致

## 范围与证据

- 效果类模板混剪及成片输出。待渲染工程尚无最终成片文件，不应把跳转解释为历史分支切换或成片更新。
- 当前代码点击待渲染工程会激活其输出批次 Run，再恢复项目，容易把历史批次带回混剪配置页。输出模板只读取全局 Run 的草稿，而非混剪使用的每模板当前目录。
- 输出列表 API 没有启用当前确认路径模式；草稿同步要求所选 Run 具有项目全局活动指针，与模板工作区独立选择矛盾。
- 卡片用三列拼图，但当前草稿找不到对应历史工程时只返回一张封面，仍占固定三列，出现大片空白。

## 实现

- 复用现有混剪目录和当前路径算法，包含未生成工程的模板，禁止历史批次补回已删除模板。
- 待渲染卡片只携带项目/模板/工程/真实 Run 定位精修工作台，不激活全局分支、不开启任务或编辑分支。
- 保存草稿按实际编辑 Run 和 revision 对齐未导出队列；取消全局活动指针依赖，保留事务内项目、Run、revision、条目状态及已导出工作副本保护。
- 输出预览依据对应模板当前工作区，单图和多图占满卡片，并复用现有缩略图缓存。

## 非目标与迁移

- 不修改固定节点、历史最终文件和已导出成片；已导出成片变化仍由用户局部更新。
- 无数据库迁移、无自动编码、无模型调用。复用既有 API 和契约。

## 验收

- 单测覆盖当前路径覆盖旧批次、空模板、不同 Run 的卡片定位、未导出草稿同步及迟到 revision 拒绝。
- Web/API 类型、构建与相关回归、diff 检查。
- 真实浏览器查看输出列表，点击待渲染工程直接进入对应成片，返回输出仍保留当前目录；核对1920/1440/1024预览和空模板状态。

## 实际验证

- Web 7 个相关测试文件、94 条测试通过；API 2 个相关测试文件、124 条测试通过。覆盖真实页面处理函数、跨项目迟到读取、跨 Run 工程定位、当前目录与导出路径一致、未导出同步不创建任务/分支/待更新、旧 revision 拦截。
- Web 类型检查与生产构建通过；API 类型检查与构建通过；diff 检查通过。Web 构建仍有既有大包警告。
- 本地 API 的普通 `dist/main.js` 启动方式已确认；全部六类活动任务为 0 时重启，实际 API 列表为测试1=13、测试2=11、测试3=15，均待渲染且 stale=0。测试4=0 从共用模板目录显示空态，不创建输出批次。
- 正式浏览器点击测试3成片01与02，直接定位对应精修工程；返回配置仍是四个模板和 13/11/15/0 工程，项目全局活动 Run 保持不变。测试3的45张预览缩略图全部加载，未出现空白占位。
- 已检查冻结 `effect-workflow.html` 的成片页，保留页面层级、卡片和分页；根据用户真实数据要求复用正式模板目录，单图按实际图数铺满卡片，不沿用原型 Mock。
- 视口能力对当前浏览器没有实际改变尺寸（DOM 实测宽度1265）；1920/1440/1024独立宽度验收未完成，不记录虚假的宽度通过。保留实际视口的浏览器截图，并已清理尺寸名称不准确的本次临时截图。
- 未启动付费模型、成片包装或编码任务，未改写历史输出文件，未进行 Git 提交。
