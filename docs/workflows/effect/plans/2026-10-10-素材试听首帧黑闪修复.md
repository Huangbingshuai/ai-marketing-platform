# 素材试听首帧黑闪修复

## 范围与原因

效果类模板混剪节点的素材库试听。现有点击处理每次调用 `video.load()`，并在视频尚未解码时立即展示视频层，导致先露出黑帧。

直接上游为已确认 `render-batch` / `render-clip` 的素材及 revision；本次只改变临时试听展示，不修改素材、工程草稿、WorkingArtifact、提交边界或下游成片状态。正常的成片播放链路不变，不调用模型、不新增接口或数据库字段。

## 实施

- 复用素材卡片同来源、版本、时间点的缩略图缓存，加载时覆盖视频；无缓存时展示加载占位，失败展示可重试说明。
- 等浏览器提交真实解码帧后才移除占位。支持视频帧回调及兼容浏览器的双动画帧检查，不能仅凭元数据就绪切入。
- 不再无条件重载视频；相同素材重新试听只回到起点，不跳过真实内容的黑色帧。
- 快速切换时取消旧帧等待，隔离旧媒体事件和异步播放结果；关闭、失活和卸载清理等待与播放。

## 验收

- 单测覆盖首次加载、元数据未解码、暂停首帧、兼容回退、快速切换、同源重播、失败及清理。
- 回归既有素材试听、时间码与成片首帧/播放测试，执行 Web 类型检查、构建和 `git diff --check`。
- 浏览器检查真实素材切换、重播、暂停以及 1920 / 1440 / 窄屏的占位与播放器布局。不以截图宣称所有设备绝无黑帧。

## 实际验证（2026-10-10）

- 六个相关测试文件共 51 项通过：素材首帧等待、素材试听隔离、时间码时钟、成片首帧、成片时钟及播放启动。
- `pnpm --filter @ai-marketing/web build` 通过，包含 `vue-tsc` 类型检查；保留现有打包体积超过 500 kB 的提醒。
- `git diff --check` 通过（已有工作区 LF/CRLF 提醒，不是空白错误）。
- 浏览器使用广式腊肠真实素材，仅试听，不改变工程或启动任务。R-002 / R-005 新加载时实测 `readyState=0`、视频不可见、同素材缩略图已加载；随后解码就绪显示视频并移除遮罩。R-003 → R-004 连续切换后停留在最终素材，暂停保留画面；R-005 重新试听回到起点并使用已缓冲的视频。
- 检查 1920、1440、390 三种宽度，窄屏播放器可访问。临时视口已恢复，测试标签页已关闭；未中断用户原有智能填充任务。
- 加载失败、旧回调取消及无视频帧回调的兼容路径由单测覆盖，未在真实页面注入网络故障；未执行付费生成或全工作区测试。
