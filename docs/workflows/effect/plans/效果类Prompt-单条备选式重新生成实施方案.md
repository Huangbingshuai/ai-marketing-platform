# 效果类 Prompt：单条备选式重新生成实施方案

状态：已完成（交互简化）

## 交互简化改造

本轮移除“保留产品关联、彻底换创意、按意见重做”三种前置模式，以及要求用户理解六维含义的“保留内容”高级设置。用户只需要选择不满意原因并按需填写具体要求，系统生成三个职责互补的备选：

1. 表现变化：保留原条目的已确认事实组合，改变场景、主动作、叙事或镜头实现。
2. 方向变化：从当前信息卡的已确认事实中选择不同组合，重新建立产品表现方向。
3. 针对性优化：围绕用户勾选的问题和补充意见优化；没有补充意见时生成兼顾事实、差异与可执行性的平衡方案。

三个职责属于系统内部生成策略，不再要求用户在生成前理解或选择。事实边界、共用提示词、编号、时长和列表位置始终保持；三个候选仍须独立评估并全部验证通过，采用前不更新领域草稿。

兼容边界：公开请求增加 `AUTO_DIVERSE` 模式，新页面只发送该模式；旧模式继续可读，历史 Run 不迁移。内部任务记录候选职责，使分片重试和恢复后仍能执行相同分工。

## 目标

把当前“后台三选一并立即覆盖”改为用户可控的备选流程：系统生成并评估 3 个候选，原 Prompt 在用户确认前保持不变；用户明确采用候选后才更新领域草稿，并可在未发生后续修改时撤销。

## 范围与边界

- 仅改造效果类第 3 节点的 `ITEM_REGENERATE`。
- 不新增 Docker 容器、数据库表或用户可见业务节点。
- 直接上游仍为 CURRENT `marketing-insight:{productId}` 与当前 Prompt 设置。
- 备选生成只写 Run、Shard 与 Stage 元数据，不创建新的 Prompt 结果草稿。
- “采用候选”只创建新的领域草稿，不提交 WorkingArtifact。
- 只有“完成校验”继续提交 `prompt-batch:{productId}`；视频渲染仍只消费已提交工作副本。

## 用户流程

1. 用户选择不满意原因并按需填写具体要求，不需要判断改动幅度或锁定六维内容。
2. 页面启动现有异步 `ITEM_REGENERATE` Run，当前 Prompt 保持可见。
3. Worker 生成并独立评估 3 个候选，使用批次其他 Prompt 作为差异化参照。
4. Run 完成后返回安全化候选预览，默认标出推荐方案，但不自动替换。
5. 用户选择“采用这个方案”后，API 使用 result revision、Run 输入指纹和目标条目进行原子校验与替换。
6. 页面提供一次撤销；发生其他结果修改后撤销失效，避免覆盖新编辑。

## 契约与数据

- 启动请求使用系统自动分工模式并携带原因代码和可选具体要求；旧重生成方式与 `replacementDimensions` 继续兼容历史请求。
- Run 公开响应增加可选 `regenerationPreview`，最多包含 3 个已验证候选。
- 候选完整结果保存在现有 `RESULT_SAVE.metadata`，不新增持久化结构。
- 增加采用和撤销请求，均要求 `expectedRevision` 与幂等键。
- 候选过期、结果已变化、上游已变化或候选不属于该 Run 时拒绝写入。

## Worker

- 单条重生成精确保留 3 个已验证候选，不再在 Worker 中压缩成 1 个。
- 原产品事实、用户原因、修改意见和其他 Prompt 相似度参照共同进入生成上下文。
- 三个生成任务分别承担表现变化、产品重点变化和意见优化；生成模板要求候选形成不同的场景、主动作或镜头实现，不能只替换措辞。
- 独立评估继续负责事实真实性、产品相关性、创意连贯性、可执行性与用途分类。
- Worker 只校验事实 ID、结构、数量、哈希和租约，不恢复字符语义门禁。

## 前端

- 默认界面只展示不满意原因和可选具体要求，不再展示重生成方式或六维锁定。
- 完成后展示原 Prompt 与 3 个候选，突出发生变化的维度、推荐用途和易懂结论。
- 用户可采用任一候选、保留原文或再次生成；采用成功后提供撤销入口。
- 运行、失败、刷新恢复、409、ESC、焦点恢复和窄屏均需覆盖。

## 测试

- Contracts：新增枚举、请求、预览和采用/撤销响应的兼容性。
- Worker：单条生成 3 个候选、事实优先、差异参照、全部评估、失败不产出预览。
- API：预览不修改草稿、采用原子替换、稳定 ID/编号/位置/时长、并发冲突、幂等和撤销。
- Web：轻量输入、运行状态、三候选比较、采用、撤销、失败与刷新恢复。
- 执行相关测试、类型检查、构建、Ruff、Mypy 和 `git diff --check`。

## 实施结果

- 单条重新生成现在会保留 3 个已验证备选；任务完成时不会创建或覆盖 Prompt 结果。
- 用户采用候选后才更新领域草稿，并保持原条目的稳定 ID、编号、列表位置、素材标签和片段时长。
- 采用接口同时把结果关联到本次重新生成 Run；未采用的预览 Run 不再阻塞后续“完成校验”。
- 撤销只在采用后且结果没有发生其他修改时有效，避免覆盖更新后的内容。
- 页面已提供问题原因、可选具体要求、三候选对比和一次撤销；三个重做方向改为系统内部自动分工。
- 未新增 Docker 容器、数据库表、Prisma 迁移或用户可见业务节点。
