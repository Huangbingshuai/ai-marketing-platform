# 效果类 Prompt：单条备选式重新生成实施方案

状态：已完成（完整创意重生成与时长调整）

## 目标

单条重新生成直接复用当前 Prompt 节点的生成与评估能力。用户无需理解内部生成模式，只需要调整本条片段时长、勾选不满意原因，并按需填写具体要求。系统生成三个完整候选，原 Prompt 在用户采用前保持不变。

## 当前用户流程

1. 用户点击某条 Prompt 的“重新生成”。
2. 页面默认带入原片段时长，允许在当前视频模型支持范围内修改。
3. 用户可多选“与产品关联不够、创意太普通、场景不合适”等原因，也可以补充具体要求。
4. Worker 为三个候选分别领取少量已确认事实，重新生成创意方向、六维信息和干净正文。
5. 独立评估继续核对事实实现、产品相关性、创意连贯性、时长可执行性和用途分类，并形成可信事实绑定。
6. 页面展示三个已验证候选及各自时长，用户明确点击“采用这个方案”后才替换节点草稿。
7. 采用后稳定 ID、编号和列表位置不变，片段时长更新为本次选择的时长；未发生其他修改时可撤销并恢复原内容与原时长。

## 生成边界

- 新请求固定采用 `FULL_REGENERATE`，页面不再提交旧的重生成模式、旧六维或维度锁定信息。
- 原 Prompt 和原六维不进入生成模型上下文，避免模型只做续写或同义改写。
- 原条目与批次内其他 Prompt 作为向量择优的固定相似度参照，降低返回原样内容和批次近似内容的概率。
- 每个候选都必须同时产出非空创意方向、完整六维和正文；事实引用只能来自当前已提交的信息卡与事实应用表。
- 新时长进入异步任务快照、模型生成任务、候选结果和最终采用结果。时长作为结构化渲染参数，不写入可见 Prompt 正文。
- 共用提示词仍是批次级权威约束：生成时提供给模型但不复制进正文，视频请求编译时只追加一次。

## 生命周期与兼容

- 仅改造效果类第 3 节点的 `ITEM_REGENERATE`，不新增 Docker 容器、数据库表、Prisma 迁移、HTTP 路径或用户可见业务节点。
- 备选结果保存在现有 Run 的 `RESULT_SAVE.metadata`，任务完成不会创建或覆盖 Prompt 结果草稿。
- “采用候选”只更新 `WorkflowNodeState` 对应的领域草稿，不提交 `prompt-batch:{productId}` WorkingArtifact。
- 只有用户点击“完成校验”才提交新的 WorkingArtifact；视频渲染仍只消费已提交工作副本。
- 旧 `AUTO_DIVERSE`、`PRESERVE_PRODUCT_RELATION`、`NEW_CREATIVE` 和 `CUSTOM` 仅保留给历史请求读取，新页面不再发送这些模式。
- 请求、应用与撤销继续使用 result revision、Run 输入快照和幂等键，过期候选或旧 revision 不能覆盖新编辑。

## 实施内容

- Contracts：启动请求增加可选 `targetDurationSeconds`，重生成模式增加 `FULL_REGENERATE`。
- API：按当前 `renderProfile.capabilityKey` 校验新时长；快照保存新时长，并将目标条目和批次其他条目一起作为相似度参照。
- Worker：完整重生成使用通用事实分配，不再给三个任务分派“表现变化、产品重点变化、意见优化”角色；模型上下文不包含旧正文与旧六维。
- Worker：三个候选继续经过既有评估，最终结果包含创意方向、完整六维、事实绑定、推荐用途与兼容用途。
- Web：弹窗增加片段时长输入，移除内部策略说明；候选预览以折叠方式展示创意方向与六维变化。
- 应用候选时保留稳定 ID、编号、位置和创建时间，采用新时长；撤销恢复完整原条目。
