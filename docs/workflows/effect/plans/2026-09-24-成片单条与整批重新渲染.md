# 成片输出：单条 / 整批重新渲染

## 范围

- 成片输出页支持**单条成片重新渲染**（每张卡片一个按钮）与**整批重新导出**（主按钮第二次点击变成「重新导出成片」并带转圈图标）。
- 分辨率 / 帧率设置行常驻可用，不再在首次导出后被只读文案替换。
- 覆盖语义：就地覆盖旧产物 —— 旧 `fileObject` 标记 `ORPHANED` 并排入存储清理，`Asset` 就地更新而不是新建第二行；失败时旧成片必须保留。
- 统一性：整批重新导出把当前选中的规格写进全部条目 snapshot；单条重新渲染沿用该条自己已存的 snapshot，不让单条跟批次跑偏。

## 非目标

- 不改 `retry()`（失败恢复契约：不重渲染已成功的视频）、`cancel()`、`claim()`、`finish()`。
- 不改 Worker Python 侧：`claim()` 只把非 `COMPLETED` 条目重置为 `QUEUED`，`work()` 里 `pending` 天然只含被重置的条目，单条重渲染无需 Worker 改动。
- 不改 `packages/contracts` 与 Prisma schema（无迁移）。

## 后端改动

`effect-final-output.service.ts`

1. `start()` 合并「导出 / 重新导出」：`QUEUED|RUNNING` → 409；终态先对每条 item 跑 `current()` 校验上游，再逐条 reset 成 `QUEUED` 并重写 snapshot，run 置 `QUEUED` 且清 `attemptToken/leaseExpiresAt/completedAt`。事务超时 `60s → 120s`（100 条 × 上游校验与 `complete()` 同量级）。
2. 新增 `renderItem(projectId, runId, itemId)`：`FOR UPDATE` 锁 run；`QUEUED|RUNNING` / `PENDING_RENDER` → 409；条目不存在 → 404；`current()` 校验；只 reset 这一条（**snapshot 不动**）；run 置 `QUEUED` 并入队。
3. `upload()` 就地覆盖三处：
   - artifact commit **之前**把 item 的 `fileObjectId` 置 null，否则孤儿守卫 `finalOutputItems: { none: {} }` 不成立，旧 blob 永远不会被标记。
   - 接住 `commitValidatedArtifactsInTransaction` 的 `previousStorageKey`，事务提交后 `enqueueCleanup(..., 'FINAL_OUTPUT_REPLACED')`。
   - `asset` 按 `latest.assetId` 分叉：有则 `assetVersion.deleteMany` → `asset.update({ currentVersion: 1 })` → 建一条 v1 兼容行（照 `AssetRepository.recreateCurrent`）。`idempotencyKey` 保留在行上不动，唯一约束不会被二次插入，**P2002 从构造上消失**。

`effect-final-output.controller.ts`：新增 `POST final-output/:runId/items/:itemId/render`（无 body，不受全局 whitelist 管道影响）。

### 实测发现：逐字节相同的重渲染必须短路

`workingArtifactContentHash` 只吃 `fileChecksum` / `files[].sha256`，**不含 `storageKey`**。同规格重渲染是确定性的，产出字节与上一版完全一致 → artifact commit 返回 `unchanged: true`，此时它仍指着旧 blob。

若不处理：`enqueueCleanup(previousStorageKey)` 会删掉 artifact 正在引用的活文件，同时旧 `fileObject` 因为 `finalOutputItems: { none: {} }` 成立被误标 `ORPHANED` —— 悬空引用。

因此 `upload()` 增加 `unchanged` 分支：删掉本次多建的 `fileObject` 与上传副本，条目恢复成原 `fileObjectId`/`assetId` 且保持 `COMPLETED`，**不排清理**。

## 前端改动

`EffectFinalOutputNodePage.vue`

- 删除 `frozen-settings` 只读段与设置行的 `v-if` 门禁；描述文案分三态（待渲染 / 渲染中不可修改 / 可随时调整并覆盖本批）。
- 按钮图标级联：`LoaderCircle.spin`（`busy || active`）→ `RefreshCw`（`run.status !== 'PENDING_RENDER'`）→ `Play`；文案 `正在创建任务…` / `渲染中 N/M` / `重新导出成片（N）` / `导出成片（N）`。
- `startRender()` 去掉 `PENDING_RENDER` 早退；重新导出前弹 `requestActionConfirmation`。
- 新增 `itemRerenderingId` + `rerenderItem(item)`，POST `/items/${item.id}/render`。**用自己的 ref 而不是 `busy`**，单条重渲染不灰掉整页按钮。
- 两个 watcher 放宽：设置不再只在 `PENDING_RENDER` 时可编辑；`refresh()` 仍只为无记录的模板播种规格，用户的改动能扛住 4 秒轮询与模板切换。
- 卡片新增 `.item-rerender-button`（照 `.download-button`）；删掉失效的 `.frozen-settings` 规则。
