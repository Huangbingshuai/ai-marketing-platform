# 时间轴音乐落轨与字幕拖动修复（第三轮）

承接 `2026-09-24-时间轴边框新建轨与拖入替换.md`。上一轮把「边框新建轨 / 拖入替换」的代码写进了 `apps/web`，本轮修的是**实测仍然不成立**的三条：

1. 「音乐库中的音乐素材拖到音频轨道的边框的辅助线那里还是没有新增轨道填入音乐」
2. 「音乐素材替换的时候还是没有出现暗色替换视觉，视频素材已经有了」
3. 「字幕轨道的字幕还是不能像其他素材那样上下左右拖动并且自动新增轨道跳转素材」

上一轮的验收清单第 1、2 条是**浏览器手测未执行**（见该文「未做」），本轮先按代码与数据库把三条各自定位到根因，再改。

## 一、音乐落轨：被 `templateEditLocked` 静默丢掉

**根因**：`addMusicAssetToTimeline` 的守卫是 `if (!variant || templateEditLocked.value) return;`，而

```ts
const templateEditLocked = computed(() => projectEditLocked.value || packagingLocked.value);
```

`packagingLocked` 只要模板上有一份 **CURRENT 的 `timeline-package:` 工作产物**就为真（服务端 `toWorkspaceData` 按 `packagedTemplateIds` 回填）。也就是说，**在「包装已完成、音频区可编辑」这个状态里，音频区的拖入被整条丢掉**：

```ts
const audioEditable = computed(
  () => !props.readOnly && props.packaging?.status === 'COMPLETED' && !props.packaging.stale,
);
```

两者恰好互斥 —— 音乐行画得出来、能选中、能换行，唯独从素材库拖进来不生效，正是用户看到的「辅助线出得来，松手没新轨道」。

**实测证据**（本地 Postgres，同日）：

```
测试4 模板 8483bfb2-3043-4e46-b4e0-12cd908a70cd  packagingLocked = True
effect_packaging_items 最新一条 71027be6-97a9-4770-8f02-42650a677b32
  status = COMPLETED，runId 非空
  checkpoint.music = { start: 0, volume: 0.12, duration: 46, fileObjectId: 8c1793cf-… }
  checkpoint.captions 共 14 条，captionLayoutVersion = SEGMENT_V3，narrationLayoutVersion = SLOT_V1
```

**服务端并不禁止这次改动**：`saveDraft` 的细粒度守卫（`effect-template-mix.service.ts:697-764`）只在 `templateChanged`（模板配置变了、音色被遮蔽）或 `removedExistingVariant` 时拒绝，变体自身的编排（`audioLanes` / `detachedAudios` / `captions`）照常保存。所以放宽到 `projectEditLocked` 是安全的。

**修**：

- 守卫改为 `if (!variant || projectEditLocked.value) return;`（音乐落在哪一行是**编排**，和「片段在行之间移动」同类，只有模板冻结或运行中才拒绝）。
- 新增 `scrollToAudioRow(row, time, duration)` 并在 `defineExpose` 暴露：新开的行在视口下方，不跳过去这次拖入看起来仍然「什么都没发生」。行高从**行自己的元素**量，不按行距算 —— 上面的行只有一条 `AUDIO_LANE_HEIGHT` 高。
- 编辑页在 `addMusicAssetToTimeline` 末尾 `nextTick` 后调 `scrollToAudioRow(landedRow, start, duration)`，`landedRow` 由 `audioRowOf(refs, lanes, 'detached:<id>')` 从**落库后的行号**反推（不是拖入时那一行）。

## 二、暗色替换视觉：命中判定从来没被调用过

**根因**：`.audio-clip.is-material-target` 的样式和模板绑定（`EffectTemplateMixTimeline.vue:3319`）上一轮就写好了，但 `musicDropClipId` **在 HEAD 里从头到尾没有被赋过值** —— `onMusicTrackDragOver` 只写了 `musicDropRow.value = audioRowOfKey(track);`，`audioClipIdAtPoint` 这个函数当时并不存在。于是压暗层永远不出现，替换分支 `if (replaceClipId)` 也永远进不去。

**修（命中判定）**：按视频轨已经验证过的方式读事件本身，而不是 `document.elementFromPoint`：

```ts
const audioClipIdAtPoint = (event: DragEvent, track: AudioTrack): string => {
  const target =
    event.target instanceof Element ? event.target.closest<HTMLElement>('.audio-clip') : null;
  if (target?.dataset.audioId) return target.dataset.audioId;
  const time = dropTimeFromClientX(event.clientX, false);
  return (
    audiosForTrack(track).find(
      (audio) => time >= audio.start && time < audio.start + audio.duration,
    )?.id ?? ''
  );
};
```

行的内边距下没有片段，用指针的时间兜底 —— 那是片段唯一还能在的另一处。

**修（压暗只在真能替换的片段上出现）**：`replaceAudioWithMusic` 只接受 `detached:*`（素材源在工程草稿上的片段）。其余音频片段（口播 / 字幕口播 / 包装音乐）的源在**服务端拥有的包装 checkpoint** 上，`PackagingAudioEdit` 里**没有 `fileObjectId` 字段**（`packages/contracts/src/effect-template-mix-packaging.ts:122-130`），服务端 `updatePackagingAudio` 也只重建 `start/offset/duration/volume/fadeIn/fadeOut`。所以那些片段**换不了源**，给它们画压暗层等于承诺一次一定会被拒绝的替换：

```ts
const replaceableAudioClipId = (clipId: string): string =>
  clipId.startsWith('detached:') ? clipId : '';
```

指针落在不能替换的片段上时退回「落到这一行」，和任何其它行一样（`musicDropRow` 那一支）；压暗、整行高亮、落轨三者从此只有一条规则：**能替换的片段接住这次拖入，其余落到那一行**。

> **这一条直接影响验收方式**：测试4 的音频区只有 6 条 `voice:slot-*`、1 条 `capvoice:caption-*` 和包装音乐 `music`，**一条 `detached:*` 都没有**，所以在这个工程上看不到压暗层是**预期**的。要看到它，先双击一段视频素材「分离原声」，得到 `detached:<uuid>` 之后再拖音乐上去。把包装音乐也放开是**契约 + API + worker 三层的改动**（要允许客户端给 checkpoint 换源），上一轮已列为非目标，本轮不动。

## 三、字幕拖动：纵向从来没算过，横向的挡板位置错了

**根因 A（上下没反应）**：`beginAudioDrag` 刻意把字幕排除在 `initialRows` 之外（`if (mode === 'MOVE' && !target.id.startsWith('caption:'))`），而 `onWindowPointerMove` 的纵向那一段又是 `if (drag.initialRows[drag.id] !== undefined)` 才走，`captionClipStyle` 还硬写 `top: AUDIO_CLIP_INSET` —— 三条一起把字幕的纵向移动彻底焊死。上一轮加的「字幕边框 → 新轨道」因为**拖不动**而永远够不到。

**根因 B（左右被挡）**：`captionBounds` 按**同一行**取左右邻居。测试4 的 14 条字幕全是口播字幕（`manual` 缺省、无 `trackId`），`assignEffectTemplateMixCaptionLanes` 把它们全部分到 `legacy-generated` 一组、同一行，于是**每一条都被前后两条钉住**，读起来就是「直接被前面的字幕卡住，很机械地左右横移」。

**修 A（纵向）**：

- 新增 `captionAreaTop()`（第 0 条字幕条的上边）与 `dragRowOf(clipId)`（字幕 → 它被排进的车道号，其余 → `audioRowOf`）。
- `beginAudioDrag` 对 `MOVE` **一视同仁**地冻结每一行的起始行号（字幕的「行」是排出来的车道号），并按行高设 `ghostTop`：`AUDIO_CLIP_INSET + row * (caption ? CAPTION_LANE_HEIGHT : AUDIO_LANE_HEIGHT)`。
- `onWindowPointerMove` 的纵向块按字幕/音频取各自的区域原点、行高、片段高（字幕 34 / 28，音频 50 / 44），照旧不夹取 —— 拖到最后一行的下面就是新开一行。
- `captionClipStyle` 把幽灵在字幕区里的坐标**回算到它起始的那一条行元素**里：`drag.ghostTop - initialLane * CAPTION_LANE_HEIGHT`。
- 抬起时 `const rowMove = !isCaption && audio.initialRows[audio.id] !== undefined;` —— 字幕的「行」是从 track 推导的，不能当成音频行号报上去；它走既有的 `splitCaptionTrack`（边框放手）或纯时间移动。
- CSS：`.caption-clip.is-dragging` 补 `z-index: 8`（和 `.audio-clip.is-dragging` 同一条规则）。字幕行是一条条独立的窄条、按 DOM 顺序堆叠，不加这条，卡片一离开自己那行就会被下一行盖住。

**修 B（挡板改按桶）**：挡板**必须保留** —— 两条字幕不允许同时出现，`effect-packaging.domain.ts:561-564` 在同一桶（`manual ? 'MANUAL' : 'NARRATION'`）内检查 `c.start < previousEnd - 0.001` 就 `fail()`，worker 侧 `final_output.captions_ass` 更是直接抛 `字幕越界或重叠` 让成片渲染失败。但**挡板的位置不该是「行」**：

```ts
const manual = caption.manual === true;
const rows = timelineCaptions.value
  .filter((row) => (row.manual === true) === manual)
  .sort((left, right) => left.start - right.start || left.id.localeCompare(right.id));
```

桶正是服务端和渲染端各自检查的单位。对测试4 这类全口播字幕，按桶和按行的结果**完全一样**（口播字幕今天共用一行），所以这是等价改写；对**手动字幕**（素材库加的卡片，各自带一个新 `trackId` → 各自独占一行）和**被 `splitCaptionTrack` 拆出去的口播字幕**（新 `trackId`、但 `manual` 仍是 false），按行等于**没有挡板** —— 拖过去重叠 → 保存 400 / 渲染失败。按桶才和两端一致。

**修 C（顺序说明修正）**：`assignEffectTemplateMixCaptionLanes` 里 `trackId` 组排在最前（`order: 0`），所以新 `trackId` 的字幕落在字幕区**顶部**，不是上一轮文档写的「最后一组」。`scrollToCaption` 是读 `captionLaneById` 反查车道号的，所以跳转一直是对的，只有文档描述错了。

## 非目标

- **不放开「包装音频（口播 / 字幕口播 / 包装音乐）可被素材库替换」**：需要给 `PackagingAudioEdit` 加 `fileObjectId`、放开服务端校验、并确认 worker 用新源渲染的时长/淡入淡出仍然成立，是契约 + API + worker 的改动。
- **不允许两条字幕在时间上重叠**：这是服务端校验和渲染端硬性拒绝的不变量，不是 UI 取舍。
- 不给字幕加磁吸：`onWindowPointerMove` 里对字幕刻意不做 `snapDraggedBlock`（字幕是按口播时间定位的，磁吸会把小修正吸到不相关的音视频边上），本轮不动这个决定。
- 不动 `packaging_media.py` / `captions_ass` / 契约 / API / worker：本轮全部改动落在 `apps/web`。

## 风险与边界

- **压暗层在测试4 上看不到**：见第二节的说明 —— 该工程没有 `detached:*` 片段。这是**可见性**问题，不是缺陷。
- **字幕横向仍然会停在邻居上**：挡板是服务端/渲染端的不变量。对全口播字幕，它的行为与改动前**逐字相同**（按桶 = 按行）；对手动字幕与拆分出去的口播字幕，行为从「没有挡板」变成「被同桶邻居挡住」，这是**修掉一个 400**，但也确实更紧。
- **字幕纵向拖到别行后仍然要满足不重叠**：`splitCaptionTrack` 给的是**行**，不是「允许重叠」。所以拆出去的字幕只能落在同桶邻居的空隙里。
- **字幕卡片会骑到相邻行上面**：靠 `z-index: 8`，只对 `.is-dragging` 生效，松手即恢复。
- **与并行会话同文件**：`EffectTemplateMixTimeline.vue` / `EffectTemplateMixNodePage.vue` 本工作区仍有另一会话的未提交改动，本轮改动**全部是追加式或就地小改**，没有重排既有代码。

## 验收

1. 音乐库拖一个音乐到音频区 → 指针推到音频行上/下边框 → 出现横向辅助线；在辅助线上放手 → **新增一条音频轨**，音乐落在上面，视图跳到新行与新片段。
2. 双击一段视频素材「分离原声」得到 `detached:*` 片段 → 再把音乐拖到它上面 → 该片段**变暗 + 描边**；松手替换它，长度按被覆盖片段，音乐更短则拒绝并提示。
3. 音乐拖到口播 / 包装音乐上 → **不出现压暗层**，落到那一行（与任何普通行一致）。
4. 拖动轨上已有的字幕片段**上下** → 幽灵跟手，可以跨过其它字幕行；拖到字幕行边框放手 → 该字幕获得独立一行（`trackId` 变化）、起点为放手处、长度不变，视图跳过去。
5. 拖动字幕片段**左右** → 在同一桶的邻居之间自由移动；到达邻居边缘时停住（这是不变量，不是卡死）。
6. 回归：拖视频素材到槽位上仍是「替换该槽位素材」；不碰边框时音乐拖入仍是「落到放手那一行」；两个模板槽位手动拖成重叠仍被 `槽位口播边界冲突` 拦下。
