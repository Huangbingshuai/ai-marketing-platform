# 效果类 AI 信息提炼：图片自适应精细识别实施方案

## 目标

在不增加 LangGraph 节点、不改变营销洞察 WorkingArtifact 提交边界的前提下，保留普通产品图的秒级识别，同时提高包装文字、规格、标签和认证标识等细节的读取可靠性。

## 范围与非目标

- IMAGE 分支继续逐图处理并通过内部 API 外部化结果。
- 默认执行低细节首轮；仅当模型判定图片包含需要精读的包装文字、标签、规格或认证标识，或文件名明确属于包装/标签类资料时，追加一次高细节识别。
- 首次提炼允许读取项目隔离缓存；已有结果上的“重新 AI 提炼”显式绕过图片缓存，成功后仍写回最新缓存。
- 不新增公开节点、不展示模型档位、Token 或内部判断原因，不改变表单、文档、电商、图片的融合优先级。
- 不实现通用 OCR 服务，不对所有图片固定执行两次模型调用。

## 契约与数据流

- `StartEffectExtractionRunRequest` 新增向后兼容可选字段 `refreshImageRecognition`。
- API 将请求转换为不可变快照字段 `bypassImageCache`，并纳入请求哈希以保持幂等语义；该执行选项不进入来源内容指纹，不使业务内容无意义地待更新。
- Python 快照兼容 schema v2/v3，历史快照默认不绕过缓存。
- Worker 缓存键继续包含图片内容指纹、模型、Prompt 版本、图片 Schema、细节策略和预处理版本。自适应策略升级会自然失效旧缓存。

## 自适应识别

`ImageVisibleFacts` 增加仅供 Worker 决策的布尔字段 `highDetailRecommended`。首轮 Prompt 只在包装小字、规格、标签、认证或密集文字需要精读时返回 true；纯产品外观和普通场景图返回 false。

当首轮使用 `detail=low` 且需要升级时，同一图片再以 `detail=high` 调用相同严格 Schema。高细节结果负责最终文字硬事实；视觉描述等非文字字段在高细节缺失时可保留首轮可见事实。两次调用的安全 Token、尝试次数和耗时合并记录，不保存图片、Prompt 或模型原始响应。

高细节复核若因临时网络、限流或模型错误失败，当前 Run 保留已成功的低细节结果继续融合，但该降级结果不写入图片缓存；后续提炼仍有机会重新执行高细节复核，避免一次临时失败长期固化低精度结果。

## 测试与验收

- Contracts/Web：首次提炼不刷新缓存，重新提炼发送刷新标记。
- API：布尔字段校验、请求哈希隔离、快照持久化、历史请求默认值和项目隔离。
- Worker：普通图单次低细节、包装图低到高升级、文件名兜底、高细节文字覆盖、调用指标合并、缓存命中与主动绕过。
- 回归：TypeScript 类型检查与测试、Web/API 构建、Python pytest/mypy、Compose 配置和 Worker Docker 构建。
- 真实付费验收单独显式启用；默认自动测试不产生 Ark 费用。
