# 包装来源校验一致性与写回吞吐修复

## 范围与证据

- 效果类模板混剪内的包装任务；不改变固定节点、首次原位/重新包装子分支及逐条解锁规则。
- 测试1任务的 CAPTIONS 失败可在只读数据上复现：创建及执行使用 publishedRenderSource，输出 prepareValidation 未使用相同投影，已采用且哈希合法的 Prompt 被历史 STALE 拦截。已有投影复核11条同类失败均可通过，不能据此免除真实来源冲突。
- 当前记录的检查点累计中位耗时约244秒，配音本地排队约116秒。应减少重复完整来源读取及配音额度内的非供应商等待，不通过盲目提高供应商并发掩盖瓶颈。

## 边界

- 直接上游为冻结输入的 render-clip、确认事实及资料工作副本，始终核对实际 artifactId/revision；不改用最新或兄弟分支资料。
- 编辑草稿仍为 TEMPLATE_MIX WorkflowNodeState；READY 事务提交 timeline-project 与 timeline-package 后才完成条目，下游待渲染工程原位同步，不编码视频。
- 沿用 Contracts、PackagingCheckpoint、租约、attempt、Outbox 与现有来源投影；无数据库迁移、无新表、无旧失败自动重启。
- 用户已要求停止定时跟踪：自动化已暂停；当前任务不擅自取消。活动任务期间不编辑热更新 API 源码，不重启服务或 Worker。

## 实施

1. 统一 prepareValidation 的已发布素材读取投影；目标条目校验失败保留具体错误，真实 revision/哈希/不可用来源仍拒绝。
2. 测量并收敛检查点热路径，仅读取必要节点来源；保留同项目/Run 来源解析，不缓存权威状态、不跳过取消或租约验证。
3. 检查配音恢复围栏：已成功的请求在本进程恢复时不重复计费，等待或内部写回失败不误认为供应商响应未知；不明付费响应保持保守失败。
4. 将配音队列与供应商实际请求耗时分离，避免检查点写回占用供应商并发额度；保留有界重试和跨重启预算。

## 验收与非目标

- API：已采用快照合法/非法哈希、真实来源变化、revision不符、不可用文件；单条写回不受其他成片影响，完整终态仍原子提交。
- Worker：并发、内部 API 暂时失败、成功配音复用、取消/重启/不明响应围栏、额度释放及自动重试；不重复供应商请求。
- 执行相关API与Worker测试、类型检查、构建、git diff --check；用当前记录做只读回放验证，不触发付费生成。
- 不新增用户提示/恢复按钮，不改音乐创意或模型，不自动提交Git；真实付费吞吐与供应商质量未测时明确说明，不承诺永不失败。
