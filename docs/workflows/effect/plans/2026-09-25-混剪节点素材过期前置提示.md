# 混剪节点素材过期前置提示

## 范围

- 素材过期是**前置条件**问题，要在混剪节点「点智能填充之前」就说清楚，而不是让服务端报「剩余未使用素材不足以再生成一条完整成片」。
- 只补信息与前置拦截，**不放开**智能填充对「当前素材」的要求，**不动** Prompt 失效粒度，**不动**素材的现有能力（过期素材仍可预览、仍可手动拖入槽位）。

## 现状问题

用户报：「紫苏梅子酱项目智能填充不了，报这个错误：剩余未使用素材不足以再生成一条完整成片，我不是有 100 条素材吗」。

实测（2026-09-25，直查 `ai_marketing` 库 `projectId = 40d1273a-e1cd-4cae-8f83-02fdaf324dc1`）：

```
SEGMENT_RENDER    → 101 条，freshness 全部 STALE   （100 条 render-clip + 1 条 render-batch）
PROMPT_GENERATION → 1 条，CURRENT
effect_template_mix_ai_runs      → 0 行
effect_packaging_runs            → 0 行
working_artifacts(TEMPLATE_MIX)  → 0 行
```

- 100 条素材过期：2026-09-14 13:19 跑过一次 `BATCH_GENERATE`（`effect_prompt_runs` 最后一次，`73a0c5c6…`）。逐条比对 Prompt 正文 sha256：**100/100 全变**。Prompt 批次升到 revision 3，渲染批次停在 revision 2（`effect_segment_render_batches.sourcePromptRevision = 2`），于是 `effect-prompt.repository.ts:1867` 的按-Prompt 失效逻辑把这 100 条片段全标了过期。
- 报错来源：`effect-template-mix.service.ts:1061`。智能填充读素材走 `sourceArtifacts`（`effect-template-mix-ai.repository.ts:81`），只取 `freshness='CURRENT'` → 拿到 0 条 → `maximumWeightedAiSelection`（`effect-template-mix.domain.ts:124`）返回 null → 抛那句文案。文案把「素材过期」说成了「素材不足」。
- 包装读素材走 `listArtifacts`（不过滤 freshness），所以包装不受影响。

界面上为什么看不出来：

- `EffectTemplateMixNodePage.vue:5426-5441` 的素材卡 `:class` 只有 `selected / used / disabled / dragging`，没有任何过期标记；`materialFrom` 已经给出 `available = availability === 'AVAILABLE' && freshness === 'CURRENT'`（`effect-template-mix.service.ts:354`）。
- `:5304-5318` 智能填充按钮的 `:disabled` 用的是 `workspace.materials.length < 6` —— 数的是**全部**素材，100 条过期素材照样让它可点。
- `:5228-5231` 配置视图写着「已载入 100 个已确认视频片段」，同样把过期素材算作已确认。

## 调研结论（决定了下面的设计）

1. **只做前置提示，不改服务端语义**。智能填充的快照与回连校验都依赖 `freshness='CURRENT'`（`effect-template-mix.service.ts:1615-1641` 的 `sourcesCurrent`），放开它会连带改回连校验，不在本次范围。
2. **按钮只在该「必然失败」时禁用**。服务端要求每个待填槽位拿到一条**不重复**且 `duration + 0.001 >= slot.duration` 的当前素材（`effect-template-mix.domain.ts:124` 的 `maximumWeightedAiSelection`）。「当前素材数 < 待填槽位数」与「某槽位比所有当前素材都长」都是**必要条件**，据此禁用不可能拦下服务端本来能成功的填充。
3. **待填槽位数要看人工锁定**。服务端 `lockedSlotIds = target?.manualSlotIds ?? []`（`effect-template-mix.service.ts:1007`），被人工锁定的槽位不从候选里出。客户端按同一口径算，并且只把「所有人工锁位都有效」当作前提 —— 这是**保守**方向（真失效时服务端反而要更多素材，不会被我误拦）。
4. **过期素材保留全部现有能力**。`materialFrom` 用 FileObject 的稳定地址，注释里写明「so old artifacts remain playable after their working-artifact freshness changes」；包装也接受过期片段。所以卡片仍可预览、仍可手动拖入，只是标出来它不会被智能填充选中。
5. **不做跨节点跳转**。页面只有 `emit('next')` 去成片输出节点（`:2962`），没有去视频渲染节点的通用导航，所以提示只给文字指引（「请先在视频渲染节点重新生成」）。

## 设计

只改 `apps/web/src/workflows/effect/template-mix/EffectTemplateMixNodePage.vue`（加 `effect-template-mix-layout.spec.ts` 的源码断言）。

### 1. 新增 computed（放在 `displayedMaterials` 之后）

```
availableMaterials   = workspace.materials.filter(m => m.available)
expiredMaterialCount = workspace.materials.length - availableMaterials.length

aiFillBlockReason: string | null =
  没有素材            → 「上一步没有已确认的视频素材，请先在视频渲染节点生成素材。」
  候选为空            → 「当前没有可用素材（其中 K 条已过期：对应的 Prompt 已更新）；请先在视频渲染节点重新生成素材后再智能填充。」
  候选 < 待填槽位      → 「当前可用素材 M 条（其中 K 条已过期…），不足 N 个待填槽位；请先在视频渲染节点重新生成素材后再智能填充。」
  某槽位无可用素材能盖住 → 「当前可用素材都短于「X」所需的 Y 秒…；请先在视频渲染节点重新生成更长的素材。」
  否则                → null
```

候选 = 当前素材 − 人工锁定槽位已绑定的素材；待填槽位 = 模板槽位 − 人工锁定槽位。`（其中 K 条已过期…）` 只在 K > 0 时出现。

### 2. 智能填充按钮与入口

- `:5304` 的 `:disabled` 把 `workspace.materials.length < 6` 换成 `Boolean(aiFillBlockReason)`，并加 `:title="aiFillBlockReason ?? '按模板规则为六个槽位挑选素材'"`。
- `startAiFill`（`:4383`）在 `packagingLocked` 检查之后、`flushPendingEdits()` 之前加一道 `if (!refreshAffectedSlots && aiFillBlockReason.value) { showNotice(..., 'warning'); return; }` —— 这样「重试」等绕过按钮的入口也不会白跑一次请求。`refreshAffectedSlots`（自动更新截取区间）的判定条件不同，不拦。落地时放在 `!workspace || mutating || activeAiRun` 那条静默返回**之后**：正在跑的请求不该再弹一条素材警告。

### 3. 素材池

- 素材池顶部（`.material-role-filters` 与 `.material-grid` 之间）在 `expiredMaterialCount > 0` 时插一条横幅：`N 条素材已过期（对应的 Prompt 已更新），智能填充不会使用它们；请先在视频渲染节点重新生成。`
- 素材卡 `:class` 加 `expired: !material.available`，名称行加「已过期」角标，`title` 说明原因与去处。可拖、可预览、可更换槽位 —— 只加信息。

### 4. 配置视图文案（`:5228`）

- 有当前素材：`已载入 M 个已确认视频片段（另有 K 条已过期）`。
- 全部过期：warning 文案，指向视频渲染节点。
- 一条都没有：保留原来的 warning。

### 5. 样式

- `.material-grid article.expired`：虚线边 + 降饱和。
- `.material-expired-badge`：沿用 `.material-ai-role` 的尺寸，橙底。
- `.material-expired-banner`：沿用 `.template-lock-banner` 的配色，`flex` 布局、`AlertCircle` 图标。

## 非目标

- 不放宽 `sourceArtifacts` 的 `freshness='CURRENT'` 过滤，不改 `maximumWeightedAiSelection`。
- 不改 Prompt 失效粒度（Prompt 的 `id` 每次跑都会变，`refreshScope='SELECTIVE'` 跨运行走不到 —— 用户明确说先不要改）。
- 不改服务端报错文案（前端已经拦在前面；服务端文案留待后续单独处理）。
- 不做跨节点跳转、不加 Prisma 迁移。

## 验收

- 素材全部过期时：素材池出现横幅、每张卡片带「已过期」角标、智能填充按钮禁用且 tooltip 说明原因。
- 部分过期但足够填六个槽位时：只出横幅与角标，按钮仍可点（不误拦）。
- 某槽位时长超过所有当前素材时：按钮禁用，tooltip 指出是哪个槽位、需要多少秒。
- 配置视图的素材计数不再把过期素材算作「已确认」。
- 相关单测与类型检查通过（对比既有失败集合只少不多）。
