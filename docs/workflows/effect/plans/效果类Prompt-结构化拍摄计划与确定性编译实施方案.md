# 效果类 Prompt：结构化拍摄计划与确定性编译实施方案

状态：已完成（2026-09-05）

## 一、目标

在不增加模型调用次数、不恢复片段用途配额、不增加固定场景或镜头模板的前提下，将效果类 Prompt 从“模型直接自由书写一段正文”调整为：

```text
产品专属创意版图与方向
→ 同一次候选生成调用产出结构化拍摄计划
→ Worker 仅做结构、时间和来源校验
→ 确定性编译为完整、可读、可渲染的片段 Prompt
→ 现有 AI 质量评估与用途分类
```

重点解决长时段 Prompt 信息不足、人物口播内容缺失、动作时间分配不清、镜头与动作脱节和结束画面不明确的问题，同时保持现有差异化来源和向量 MMR，不因统一表达结构提高重复度。

## 二、业务边界

- 所属工作流：效果类。
- 当前节点：Prompt 生成。
- 直接上游：当前商品已确认的营销洞察 WorkingArtifact revision，以及本节点保存的数量、时长、视觉风格、渠道和禁用元素。
- 当前输出：Prompt 领域草稿；只有用户点击“完成校验”才提交 `prompt-batch:{productId}`。
- 直接下游：视频渲染节点；继续读取已提交 Prompt 工作副本，不读取内部拍摄计划。
- 本次生成和真实测试不得自动完成校验，不得覆盖已有 WorkingArtifact。

## 三、核心数据

新增 Worker 内部结构化拍摄计划，不改变公共 Prompt 批次 Schema：

```ts
type MaterialShotPlan = {
  overview: {
    visualIntent: string;
    visualStyle: string;
    audioDirection: string;
  };
  scene: {
    environment: string;
    lighting: string;
    initialState: string;
  };
  beats: Array<{
    sequence: number;
    durationWeight: number;
    framing: string;
    action: string;
    camera: string;
    visibleResult: string;
    dialogue: string | null;
    sound: string | null;
  }>;
  finalFrame: string;
};
```

候选生成模型在现有一次调用中同时返回 `creativeCore`、六维、事实引用和 `shotPlan`，不再自由返回最终 `content`。Worker 只允许执行以下确定性工作：

- 校验字段、枚举、稳定 ID 和事实 ID 来源；
- 校验节拍序号连续，并按照相对时长权重确定性分配完整时间段；
- 校验非空字段和基础数量；
- 按固定排版顺序编译文本；
- 不解释事实语义，不补写动作、台词、场景、卖点或镜头。

公共 `EffectPromptItem.content` 继续是最终可复制的干净正文；六维、用途、事实绑定和视频渲染下游契约保持不变。

## 四、按时段的软密度

模型根据时段获得建议节拍范围，不把它作为淘汰门禁：

| 时段 | 建议节拍 | 目标 |
| --- | --- | --- |
| 5～8 秒 | 1～2 | 一个核心动作和一个清楚结果 |
| 9～15 秒 | 2～3 | 建立画面、产品动作和收束 |
| 16～20 秒 | 3～4 | 允许短口播或完整使用过程 |
| 21～30 秒 | 4～6 | 同一目标下的连续阶段，不扩成多地点完整广告 |

实际节拍数可在合理范围内变化。创意差异继续来自产品专属创意版图、事实组合、方向和优先变化维度，结构化字段只负责完整表达，不提供固定内容。

## 五、编译格式

确定性编译器输出：

```text
【视频概览】创意目的、视觉方式与声音方向。
【场景与光线】环境、光线和首帧状态。
【0～N秒】景别与主体动作；镜头如何跟随；出现什么可见变化；必要时包含逐字台词和声音。
【N～M秒】……
【结束画面】人物、产品、关键道具和镜头的最终状态。
```

- 不写画幅、分辨率、模型、用途标签或共用提示词。
- 人物开口时必须提供逐字台词；没有安全具体台词则使用无口播画面。
- 声音只描述与本画面有关的环境声、拟音、口播或轻量音乐方向。
- 禁用元素仍由共用提示词在视频请求编译时追加一次。

## 六、兼容与恢复

- 不新增 Prisma 表、公开 HTTP 路径或公共 Schema 版本。
- 内部 Pydantic 类型新增可选兼容解析，仅新候选要求真实 `shotPlan`；历史阶段分片和历史结果继续读取。
- 新任务重试仍只恢复已完成分片；拍摄计划保存在现有分片条目中，不写入 Graph State 正文。
- Mock 使用相同结构生成确定性测试计划，不能静默伪装真实结果。

## 七、验证

自动测试：

- 不同时段的节拍建议和时间边界；
- 时间段连续、无重叠和完整覆盖；
- 台词、声音和结束画面的确定性编译；
- Worker 不执行事实语义补写；
- 候选生成仍为一次模型调用；
- 旧分片、人工条目、单条重新生成和公共 V6 结果兼容；
- 精确数量、向量 MMR、共用提示词和 WorkingArtifact 边界不回归；
- Worker pytest、Ruff、mypy，必要的 API/Contracts/Web 检查，生产构建与 `git diff --check`。

真实付费测试按代表时段执行，不逐秒测试。至少使用不同商品覆盖短、中、长时段，检查：

- Prompt 是否具备可执行首帧、连续节拍、明确台词/无口播、镜头动作和结束画面；
- 是否存在虚构事实、物理错误、空泛讲解和时长过密/过稀；
- 相对改造前重复度没有显著上升；
- 生成耗时没有因新增模型调用增加。

发现实现 Bug 时先修复并跑自动回归，再继续真实测试。本次不调用 Seedance，不自动完成校验，不自动提交或推送 Git。

## 八、实际实施结果

已落地：

- 候选生成在同一次 Ark 调用中返回创意主线、六维与结构化拍摄计划，没有增加新的模型调用阶段。
- Worker 只校验结构、事实 ID 来源、节拍顺序与时间覆盖，并确定性编译“视频概览、场景与光线、逐秒镜头、结束画面”；没有新增商品语义判断。
- 重复度向量只比较观众实际看到或听到的创意内容，不再把固定标题、通用光线、音频和排版骨架作为主要相似依据。
- 最终相似度取正文风险与“正文＋六轴语义”风险的较高值，修复语义簇分数稀释正文高相似度、导致页面长期显示 0% 的问题。
- 多样性补充接收真实拥挤候选的场景、人物关系、产品动作和六维摘要，只影响补充方向规划，不向每条初始生成任务增加全批约束。
- 空台词中的 `null / none / 无 / 不适用` 在结构层归一化为空，避免编译出“逐字台词：null”。
- 按时长动态预留结构化输出空间。15 秒四条分片由 4,800 Token 提升到 6,200 Token，30 秒单条提升到 2,400 Token；这是输出上限，不是正文长度要求。
- 生成与评估模板把现有真实性边界提前为预检，不增加固定场景、镜头或文案模板。

## 九、真实付费验收

均通过正式浏览器、公共 API、Outbox/RabbitMQ 与真实 Ark Worker 执行；只保存节点草稿，未点击“完成校验”，未调用 Seedance。

| 商品与时长 | 结果 | 五项加权平均 | 候选池正文冗余率 | 最终重复度 | 硬问题 |

| 山茶花氨基酸洗发露，12 条 × 30 秒 | 完成 12/12 | 92.70 | 47.37% | 8.33%（1 条、1 组） | 0 |
| 紫苏梅子酱，12 条 × 15 秒 | 完成 12/12 | 92.36 | 30.00% | 0%（最高配对风险 0.7815，低于 0.82 阈值） | 0 |
| 广式腊肠，12 条 × 5 秒 | 完成 12/12 | 92.43 | 15.79% | 0%（最高配对风险 0.7575，低于 0.82 阈值） | 0 |

结论：固定表达结构没有导致重复度升高。长、中、短三个代表时段均生成了明确首帧、可执行动作、可见结果、必要的逐字台词和结束画面；最终重复度分别为 8.33%、0%、0%。后两批的 0% 是所有最终配对均低于阈值的真实结果，不是旧版分数稀释造成的假 0%。

真实链路中还发现并处理了两类问题：

- 15 秒四条分片曾有一次达到 4,800 Token 输出上限后自动拆分，最终任务成功；随后提高了同分片输出余量，避免先超限再拆分的额外等待。
- 海盐芝士曲奇项目只有提炼草稿、没有已提交营销信息卡，公共 API 按设计返回 409；未擅自提交上游 WorkingArtifact，也未产生 Ark 付费调用。

三批均因少量整批事实未进入最终 12 条而保持 `NEEDS_REVIEW`，但数量精确，且没有硬问题。这是现有批次覆盖提醒，不是结构化拍摄计划或重复度失败。
