# 包装创建草稿版本冲突修复

## 范围

效果类模板混剪节点内整批及单条包装的创建边界。上游继续采用当前 Run 的已确认 Prompt 与渲染素材 revision；输出仍为包装成功后提交 timeline-project/timeline-package，最终视频只由用户主动导出。复用现有草稿、包装接口、Outbox、幂等键，不改数据库或 Worker 协议。

## 证据与修复

- 截图报错来自包装创建服务的草稿 revision 校验，不是供应商生成失败。当前测试1存在尚未创建包装任务的子 Run。
- 创建服务先开子 Run 再验证请求版本，且来源与目标共用同一个 expectedDraftRevision；过期请求可能留下无任务子 Run，跨 Run 的版本校验也没有独立表达。
- 创建前校验来源版本；分支复制事务在来源节点锁下再次验证。任务创建分别冻结来源、执行 Run 的 revision，并在事务中再次核对，不能以移除版本校验或盲目重试解决。
- 现有分支复制协议保留来源 revision；重用的未完成子 Run 若已发生编辑，仍拒绝创建，不能把“刚读取到子分支新 revision”当作原始冻结基线。
- 前端点击包装后先完成已有保存，再只读核对当前工作区。若只有导航或无关模板变化，安全安装最新读取并采用真实 revision；目标模板内容变化时保留原编辑并明确阻止，不能悄悄包装另一份内容。读取期间切换、编辑或迟到响应均丢弃，不刷新整个页面或启动额外付费任务。

## 验收

覆盖过期来源在开分支前拒绝、分支复制竞态、父子 revision 不同、任务入库前来源/目标再次变化、同幂等键重放、原位包装、无关模板更新及本地编辑保护。执行 API/Web 相关测试、类型检查、构建与 diff --check；浏览器写请求拦截验证，不运行付费包装，不清理用户历史子 Run。
