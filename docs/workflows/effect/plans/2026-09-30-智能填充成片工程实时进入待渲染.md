# 智能填充成片工程实时进入待渲染

## 范围

效果类模板混剪的智能填充完整成功并确认时间轴后，立即为该模板建立或刷新成片输出的待渲染批次。此时成片是可编辑的仅画面工程；后续智能成片包装完成时沿用现有批次与条目，加入音频、字幕及包装依赖。未填满或无效的工程不进入待渲染。输出页无需用户手动同步，继续按当前轮询/进入页面刷新读取。

## 非目标

- 不在智能填充时启动付费成片渲染，也不假装包装已完成。
- 不改动六节点结构、混剪模板分支规则或已导出成片的局部更新语义。
- 不复制媒体文件，不修改其他工作流。

## 数据和接口

- 复用 `EffectFinalOutputRun` 的 `PENDING_RENDER`、同模板唯一当前待渲染批次、`FinalOutputSnapshot` 和 `unpackaged` 字段，不新增表或公共接口。
- 仅画面快照绑定已确认的 `timeline-project:<templateId>:<variantId>` 精确 ID/revision/hash，冻结可用源片段文件、截取与轨道；包装字段为空结构。包装成功后用同一条目 ID 原位升级，并加入 `timeline-package` 依赖。
- 智能填充完成回调在草稿写入和工作副本确认后执行建批次；重复回调、旧草稿 revision、跨项目、运行中包装和已有成片版本都不得产生重复或覆盖输出。若确认已成功而回调后的同步短暂失败，成片页进入时通过现有同步接口仅修复已有确认时间轴、尚无待渲染批次的模板。保存草稿后的实时同步继续更新未导出批次；有成片版本则停止自动覆盖。

## 迁移与验收

无数据迁移。旧项目未包装的已完成填充在再次填充成功后建立批次；已有待渲染批次原位更新。测试单/多条工程、包装升级、幂等、缺失源文件、草稿冲突、已有成片版本保护，以及不启动付费队列。执行相关 API、Web、Contracts 检查及 `git diff --check`，回归输出页空、待渲染和包装升级状态。
