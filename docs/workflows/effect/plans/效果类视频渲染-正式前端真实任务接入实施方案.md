# 效果类视频渲染：正式前端真实任务接入实施方案

## 目标

将效果类工作流第 4 节点从前端 Mock 任务区切换到现有真实视频渲染后端，形成“加载工作区 → 创建真实批次 → 轮询任务 → 预览视频 → 单条重生成/返修 → 完成校验”的最小闭环。

## 输入与版本边界

- 直接上游：当前商品已确认的 `prompt-batch:{productId}` 工作副本。
- 创建批次时提交上游 Prompt revision、当前渲染设置 revision 和一次性幂等键。
- 每条 Prompt 固定创建一个视频任务；后端冻结该批次消费的 Prompt、设置和完整产品图片集合。
- 页面只展示 API 返回的批次与任务状态，不维护第二套可恢复的任务事实。

## 输出与提交边界

- 生成完成只代表视频进入当前素材池草稿，不自动提交工作副本。
- 用户点击“完成校验”后，由后端提交 `render-clip:{taskId}` 与 `render-batch:{productId}` 工作副本。
- 已提交批次从后端 `commitStatus` 恢复；上游变更后的旧批次显示为 stale，并允许按最新 Prompt 创建新批次。

## 本次范围

- 补充工作区的 Prompt 数量、任务兼容用途和返修版本契约。
- 接入批次创建、查询轮询、单条重生成、视频内容读取、返修候选、候选决策和完成校验 API。
- 视频预览通过鉴权内容接口读取真实对象存储内容，并在关闭弹窗时释放本地 Blob URL。
- 导入、批量导出和删除尚无真实后端接口，本次明确禁用，不保留可触发的 Mock 行为。

## 并发与幂等

- 浏览器每次用户操作生成独立幂等键；重复提交由服务端去重。
- 前端只创建一个批次请求，不循环提交 50～100 次；服务端事务一次创建任务与 Outbox。
- RabbitMQ/Worker 负责受控并发，前端以 3 秒单定时器轮询，不并发堆叠请求；失败后 5 秒重试。
- 页面切换商品、重新加载或卸载时终止加载、轮询、操作和预览请求。

## 非目标

- 不自动替用户提交付费 Seedance 批次。
- 不在本次新增外部视频素材导入、批量下载或删除 API。
- 不改变 Prompt 编译、模型适配器、Worker 并发策略和后续模板混剪职责。

## 验收

- 正式页面不再导入 Mock service。
- 无批次时展示真实 Prompt 数量；确认后只发出一个真实批次创建请求。
- 页面刷新后可恢复同一真实批次，运行中自动轮询，完成后可播放真实视频。
- 单条重生成、返修、候选采用/放弃和完成校验均携带批次 revision。
- 通过 Contracts、API、Web 相关测试、类型检查与 `git diff --check`。
