# 效果类 Prompt V11 向量语义择优一期实施方案

状态：一期历史方案已由单向量 MMR V2 取代；部署已切换 `vector`
开始日期：2026-08-28

## 1. 目标与边界

本期只改造效果类 Prompt V11 的“精确数量择优与补充”阶段。使用火山方舟图文向量 API 的纯文本输入能力，为每条候选生成正文向量与六维创意向量，在 Worker 内完成余弦比较和贪心择优。向量相似度只降低候选排序，不作为一般相似内容的硬删除条件，最终数量必须优先与用户设置一致。

本期不接入大模型裁判、向量数据库、图片/视频向量或新的前端配置；虽然供应商模型属于多模态向量模型，本期只发送文本。不修改公开 API、结果 Schema、Prisma、WorkingArtifact 提交边界和历史 Run。V8～V10 与既有 V11 结果继续只读。

## 2. 数据流与故障语义

1. 连贯六维创意生成与用途评估继续产生候选和质量分。
2. Worker 确定性编译正文语义文本与六维创意文本。
3. 向量适配器按批调用火山方舟，Run 内按文本哈希缓存，不持久化原始向量。
4. 计算正文余弦、创意余弦和六维结构重合度，形成候选对新颖度。
5. 保留完全重复与现有硬问题过滤；按 `80% 质量 + 20% 新颖度` 逐条选择到准确数量。
6. 首轮不足时生成补充候选，只为新增文本请求向量。

`shadow` 模式同时计算旧三元组和向量结果，旧结果仍作为权威选择；向量失败只记录明确告警。`vector` 模式由向量结果接管，向量失败时任务重试或失败，禁止静默降级。

## 3. 配置与并发

- `PROMPT_SIMILARITY_MODE=trigram|shadow|vector`
- `ARK_PROMPT_EMBEDDING_MODEL=doubao-embedding-vision-251215`：显式模型 ID，不回退生成模型。
- `ARK_PROMPT_EMBEDDING_API_MODE=multimodal`
- `ARK_PROMPT_EMBEDDING_TIMEOUT_SECONDS=30`
- `ARK_PROMPT_EMBEDDING_MAX_ATTEMPTS=3`
- `PROMPT_EMBEDDING_BATCH_SIZE=64`
- `PROMPT_EMBEDDING_MAX_CONCURRENCY=8`

默认 50 条生成 60 个候选，共 120 条向量输入。官方多模态端点每次最多包含一个 `text`，因此实际为 120 次单文本请求，由独立信号量并发执行，不占用生成模型并发。`PROMPT_EMBEDDING_BATCH_SIZE` 对该端点会自动收窄为 1。60 个候选仍只在本地计算 1770 对，不引入向量库和逐对远程比较调用。

## 4. 验收

- Provider 覆盖乱序响应、维度错误、空向量、429、5xx、超时、退避和日志脱敏。
- 比较三元组、仅正文向量、正文加创意双向量三种方案。
- 所有批次必须精确达到目标数量，一般相似不得形成数量阻断。
- 同义近重复召回相对三元组提升至少 20 个百分点；不同创意误判率不超过 10%，且不比基线恶化超过 3 个百分点。
- 选中集合近重复数量降低至少 15%，原质量平均分下降不超过 2 分。
- 本地 1770 对计算不超过 300ms；真实小样本验证并发 8 优于并发 2。完整 120 次请求的生产耗时需在影子批次中继续观测，不再沿用“不超过 2 个远程请求”的错误门槛。
- 真实付费验收最多调用 30 次火山向量接口，不调用文本生成、Seedance 或其他付费模型。

- V11 选择器支持 `trigram / shadow / vector`。影子模式不改变保存结果；向量模式使用双向量新颖度；单候选跳过远程调用。
- Stage 仅投影请求数、Token、耗时、相似度分布、选择集合重合率和候选序号，不包含模型名、Endpoint、正文或原始向量。

### 5.3 早期错误与接口纠正

- 首次使用官方旧示例 `doubao-embedding-text-240515` 未获得有效向量。
- 查询账号可见模型目录后，对较新的 `doubao-embedding-large-text-250515` 执行单文本冒烟，仍返回 `InvalidEndpointOrModel.NotFound`。
- 本次可确认的付费接口请求上限为 7 次，低于授权的 30 次；所有请求均失败于模型/Endpoint 可用性检查，未返回可用于统计的 Token、P50/P95 或语义向量。
- 用户确认现有 Key 已授权 `doubao-embedding-vision-251215`。此前失败的根因是把图文向量模型误发到文本 `/embeddings` 端点，而不是 Key 权限不足。
- 2026-08-28 使用官方 `/embeddings/multimodal` 完成单文本连通性检查：模型返回 2048 维有限向量，34 个输入 Token，端到端约 496ms。未记录向量内容或请求标识。
- 适配器已按供应商约束把多模态请求限制为单个 `text`，同时保留显式 `text` 模式兼容未来文本 Endpoint；后续真实语义与并发结果记录在下一节。

### 5.4 251215 真实对照结果

- 真实集成测试使用 18 次向量请求、765 个输入 Token；本轮接口纠正包含前置冒烟与一次响应结构定位，总调用仍在既有 30 次授权上限内。
- 小样本包含 3 组同义近重复和 3 组不同意图。固定阈值 `0.82` 下，三元组召回率为 `0%`、误判率为 `0%`；向量召回率为 `100%`、误判率为 `0%`。这证明模型能识别词面差异较大的同义动作，但样本量不足以直接宣布全面上线。
- 相同 4 条文本的真实并发对照：并发 2 为 `320.14ms`，并发 8 为 `187.01ms`，并发 8 快约 `41.6%`，因此多模态单文本端点默认独立并发设为 8。
- 251215 实际响应为单个 `data` 对象，而旧示例还存在 `data[]` 结构。解析器已兼容两种结构，并验证向量维度一致、有限且非全零。
- 当前本地运行配置为 `shadow`：向量结果进入安全指标，但保存结果仍由三元组基线决定。待积累覆盖更多产品和完整 60 候选批次的召回、误判、耗时与选择集合差异后，再决定是否改为 `vector`。

### 5.5 Shadow 决策指标与本地性能整改（已完成）

2026-08-28 对最近三个完整 50 条批次执行只读核查：向量阶段平均耗时约 `4047.3ms`，最多 `4123.7ms`；本地 1770 对比较平均约 `1093.1ms`；每批平均 `118.7` 次单文本请求、`14193.3` 个输入 Token。双向量选择与三元组基线的集合重合率为 `88%～96%`，但现有指标尚不能回答被替换的 2～6 条是否真实降低了近重复，也不能证明质量分是否发生可接受的变化。

本轮保持 `PROMPT_SIMILARITY_MODE=shadow`，不改变权威保存结果，不调用新的付费模型。实施范围固定为：

- 对 2048 维向量在进入两两比较前只归一化一次，比较阶段只计算点积，避免每个候选对重复计算范数；60 候选、1770 对的本地比较目标恢复到 `300ms` 内。
- 使用同一套双向量风险口径分别评估三元组基线、仅正文向量和正文加创意双向量三个已选集合，记录各自的近重复对数、最高相似风险、平均质量分和六维唯一值覆盖。
- 记录双向量相对基线的近重复变化、平均质量分变化和实际替换条数；当基线不存在近重复对时明确标记“不适用”，不得用 `0%` 制造改善假象。
- 指标只保存数量、分数、耗时、Token、候选序号和六维覆盖计数，不保存向量、完整 Prompt、模型名、Endpoint 或供应商原始响应。
- 在至少覆盖食品、日用品、设备且拥有人工盲评的完整批次前继续保持 `shadow`；只有近重复下降、质量损失和延迟同时满足第四节门槛，才另行切换 `vector`。

实施结果：

- 向量比较改为每份文档向量只归一化一次，随后对候选对只计算点积；2048 维、60 候选、1770 对的本地非付费基准为 `169.226ms`，达到 `300ms` 目标。
- 影子 Stage 新增三种选择集合的统一双向量风险评估：近重复对数、最高风险、平均质量分、六维唯一值覆盖总数、已实现事实覆盖数，以及相对基线的替换数、近重复变化和质量变化。
- 当基线近重复对数为零时，下降比例明确标记为不适用；影子模式与向量故障语义保持不变。
- Worker 全量非付费测试、`mypy src` 和 `ruff check src tests` 通过；未调用真实火山模型。当前仍不具备仅凭三个真实影子批次切换 `vector` 的证据，继续保持 `shadow`。

### 5.6 扩大真实付费验收与上线决策

用户于 2026-08-28 明确授权真实付费测试。本轮仅调用火山方舟向量接口，没有调用文本生成、Seedance 或其他付费模型。官方多模态向量接口规定每种输入类型最多一个，因此 `doubao-embedding-vision-251215` 的纯文本测试仍按单文本请求执行。

跨品类标注集结果：

- 标注集包含食品、日用品、设备三类产品，覆盖六种素材意图和五种环境变化，共 `180` 组平衡语义对。
- 实际产生 `169` 次向量请求、`7657` 个可统计输入 Token。
- 固定阈值 `0.82` 下，三元组召回率 `0%`、误判率 `0%`；向量召回率 `57.78%`、误判率 `0%`。相对召回提升达到门槛，但仍漏掉约 `42.22%` 的同义表达。
- 并发 2 耗时 `462.72ms`，并发 8 耗时 `160.16ms`，继续保留独立并发 8。

三个现有完整 60 候选真实批次回放结果：

| 批次 | 基线近重复对 | 双向量近重复对 |   降幅 | 替换条数 | 平均质量变化 |   向量耗时 |  本地比较 |
| ---- | -----------: | -------------: | -----: | -------: | -----------: | ---------: | --------: |
| 1    |           25 |             22 | 12.00% |        3 |       -0.099 | 3015.812ms | 594.091ms |
| 2    |           32 |             30 |  6.25% |        2 |       -0.071 | 3209.779ms | 359.159ms |
| 3    |           32 |             31 |  3.12% |        6 |       -0.012 | 2676.229ms | 326.590ms |

汇总结论：

- 三批均严格选择 `50/50`，六维唯一值覆盖和已实现事实覆盖没有下降，平均质量变化约 `-0.061` 分，质量损失门槛通过。
- 近重复对合计从 `89` 降到 `83`，只下降 `6.74%`，未达到至少 `15%` 的上线门槛。
- 仅正文向量与正文加创意双向量在三批中选择集合完全相同，当前创意向量没有表现出增量选择价值，却占用一半远程请求。
- 本地比较平均约 `426.6ms`，最慢 `594.1ms`，真实向量下仍未稳定达到 `300ms` 目标。

最终决定：保持 `PROMPT_SIMILARITY_MODE=shadow`，不切换 `vector`。原因不是向量无效，而是当前 `80%质量 + 20%新颖度` 的择优策略对最终集合的近重复改善不足，且双向量尚未证明相对正文向量的增量收益。后续应先在影子数据中调整择优权重或创意文本编译，并补充非食品完整候选批次；在近重复下降达到 `15%`、质量下降不超过 `2` 分且性能达标前，不允许向量接管权威结果。

不得在后续报告中记录密钥、原始向量、完整 Prompt 或供应商原始响应。

### 5.7 被单向量 MMR V2 取代

本节是对上述历史结论的最终修订，不修改或伪造当时双向量 `80/20` 方案的真实失败数据。后续实现参考 OpenMontage，将算法改为正文单向量、NumPy 矩阵和 `70%质量 + 30%新颖度` MMR，并加入固定参照和按风险补充候选；完整设计与付费验收见《效果类Prompt-V11-OpenMontage式向量MMR择优实施方案》5.3～5.4节。

新算法的三品类付费验收确认：180 组标注集的同义召回相对字符基线提升 `56.67` 个百分点且误判率保持 `0%`；三个60选50业务候选池均精确返回50条，质量、六维和事实覆盖没有下降，向量阶段均低于 `2.5s`，且没有新增高风险冗余。因此先前“继续保持 shadow”的结论只适用于已经废弃的双向量 `80/20` 算法，当前部署配置已切换为 `vector`。
