# 效果类 Prompt V11 向量语义择优一期实施方案

状态：一期实现与受控真实验收完成；本地默认进入 `shadow` 观察期
开始日期：2026-08-28

## 1. 目标与边界

本期只改造效果类 Prompt V11 的“精确数量择优与补充”阶段。使用火山方舟图文向量 API 的纯文本输入能力，为每条候选生成正文向量与六维创意向量，在 Worker 内完成余弦比较和贪心择优。向量相似度只降低候选排序，不作为一般相似内容的硬删除条件，最终数量必须优先与用户设置一致。

本期不接入大模型裁判、向量数据库、图片/视频向量或新的前端配置；虽然供应商模型属于多模态向量模型，本期只发送文本。不修改公开 API、结果 Schema、Prisma、WorkingArtifact 提交边界和历史 Run。V8～V10 与既有 V11 结果继续只读。

## 2. 数据流与故障语义

1. 连贯六维创意生成与用途评估继续产生候选和质量分。
2. Worker 确定性编译正文语义文本与六维创意文本。
3. 向量适配器按批调用火山方舟，Run 内按文本哈希缓存，不持久化原始向量。
4. 计算正文余弦、创意余弦和六维结构重合度，形成候选对新颖度。
5. 保留完全重复与现有硬问题过滤；按 `80% 质量 + 20% 新颖度` 逐条选择到准确数量。
6. 首轮不足时生成补充候选，只为新增文本请求向量。

`shadow` 模式同时计算旧三元组和向量结果，旧结果仍作为权威选择；向量失败只记录明确告警。`vector` 模式由向量结果接管，向量失败时任务重试或失败，禁止静默降级。

## 3. 配置与并发

- `PROMPT_SIMILARITY_MODE=trigram|shadow|vector`
- `ARK_PROMPT_EMBEDDING_MODEL=doubao-embedding-vision-251215`：显式模型 ID，不回退生成模型。
- `ARK_PROMPT_EMBEDDING_API_MODE=multimodal`
- `ARK_PROMPT_EMBEDDING_TIMEOUT_SECONDS=30`
- `ARK_PROMPT_EMBEDDING_MAX_ATTEMPTS=3`
- `PROMPT_EMBEDDING_BATCH_SIZE=64`
- `PROMPT_EMBEDDING_MAX_CONCURRENCY=8`

默认 50 条生成 60 个候选，共 120 条向量输入。官方多模态端点每次最多包含一个 `text`，因此实际为 120 次单文本请求，由独立信号量并发执行，不占用生成模型并发。`PROMPT_EMBEDDING_BATCH_SIZE` 对该端点会自动收窄为 1。60 个候选仍只在本地计算 1770 对，不引入向量库和逐对远程比较调用。

## 4. 验收

- Provider 覆盖乱序响应、维度错误、空向量、429、5xx、超时、退避和日志脱敏。
- 比较三元组、仅正文向量、正文加创意双向量三种方案。
- 所有批次必须精确达到目标数量，一般相似不得形成数量阻断。
- 同义近重复召回相对三元组提升至少 20 个百分点；不同创意误判率不超过 10%，且不比基线恶化超过 3 个百分点。
- 选中集合近重复数量降低至少 15%，原质量平均分下降不超过 2 分。
- 本地 1770 对计算不超过 300ms；真实小样本验证并发 8 优于并发 2。完整 120 次请求的生产耗时需在影子批次中继续观测，不再沿用“不超过 2 个远程请求”的错误门槛。
- 真实付费验收最多调用 30 次火山向量接口，不调用文本生成、Seedance 或其他付费模型。

### 5.3 早期错误与接口纠正

- 首次使用官方旧示例 `doubao-embedding-text-240515` 未获得有效向量。
- 查询账号可见模型目录后，对较新的 `doubao-embedding-large-text-250515` 执行单文本冒烟，仍返回 `InvalidEndpointOrModel.NotFound`。
- 本次可确认的付费接口请求上限为 7 次，低于授权的 30 次；所有请求均失败于模型/Endpoint 可用性检查，未返回可用于统计的 Token、P50/P95 或语义向量。
- 用户确认现有 Key 已授权 `doubao-embedding-vision-251215`。此前失败的根因是把图文向量模型误发到文本 `/embeddings` 端点，而不是 Key 权限不足。
- 2026-08-28 使用官方 `/embeddings/multimodal` 完成单文本连通性检查：模型返回 2048 维有限向量，34 个输入 Token，端到端约 496ms。未记录向量内容或请求标识。
- 适配器已按供应商约束把多模态请求限制为单个 `text`，同时保留显式 `text` 模式兼容未来文本 Endpoint；后续真实语义与并发结果记录在下一节。

### 5.4 251215 真实对照结果

- 真实集成测试使用 18 次向量请求、765 个输入 Token；本轮接口纠正包含前置冒烟与一次响应结构定位，总调用仍在既有 30 次授权上限内。
- 小样本包含 3 组同义近重复和 3 组不同意图。固定阈值 `0.82` 下，三元组召回率为 `0%`、误判率为 `0%`；向量召回率为 `100%`、误判率为 `0%`。这证明模型能识别词面差异较大的同义动作，但样本量不足以直接宣布全面上线。
- 相同 4 条文本的真实并发对照：并发 2 为 `320.14ms`，并发 8 为 `187.01ms`，并发 8 快约 `41.6%`，因此多模态单文本端点默认独立并发设为 8。
- 251215 实际响应为单个 `data` 对象，而旧示例还存在 `data[]` 结构。解析器已兼容两种结构，并验证向量维度一致、有限且非全零。
- 当前本地运行配置为 `shadow`：向量结果进入安全指标，但保存结果仍由三元组基线决定。待积累覆盖更多产品和完整 60 候选批次的召回、误判、耗时与选择集合差异后，再决定是否改为 `vector`。
