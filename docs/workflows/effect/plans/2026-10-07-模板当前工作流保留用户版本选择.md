# 模板当前工作流保留用户版本选择

## 原因与边界

返回模板配置会释放历史工作台定位，再按最近已确认时间计算每模板当前路径，因此手动选择的旧版本被重置。效果类模板混剪仍消费已确认 render-clip / render-batch，输出 mix-template / timeline-project；本次只修复导航状态，不改变素材依赖、工程内容、revision 或待更新逻辑。

## 实现

- 复用分支 activate 接口和 WorkflowNodeState 保存明确选中的模板路径；按项目、渲染/手动复制谱系、模板隔离，不创建版本表或新任务。
- 显式选择填充、包装或成片版本，即使已是全局活动 Run，也记住该模板的选择；点击模板配置头只是打开该模板的当前配置，不把创建时快照强制设为当前。
- 分支树投影可选 currentSelectedAt 字段，共用路径解析优先用户选择；没有选择记录时仍按已确认结果回退。普通模板切换不改变其它模板路径。
- 模板配置、精修、画布及成片输出复用同一服务端路径；返回、刷新、切换其他模板后均保留选择。后台更新不能用确认时间抢占用户选择；新版本完成并明确打开时记录新选择。
- 只记录导航，不复制或改写模板、工程、包装、交付，不调用模型、不增加 WorkingArtifact revision。

## 验证与兼容

旧数据无需迁移，字段可选。验证两个模板独立切换、旧版本与新版本确认时间冲突、返回/刷新、同 Run 重新选择、取消/失败不记录、跨项目和不同谱系隔离、复制记录不继承。执行 Contracts、API、Web 测试、类型检查与构建、Worker 契约消费兼容检查、git diff --check；浏览器回归版本选择→返回模板配置→再进入/刷新。

## 实测结果

- Contracts 91、API 70、Web 98、Worker 24 项测试通过。API/Web 类型检查、Contracts/API/Web 生产构建及 git diff --check 通过。
- Contracts 常规类型检查仍被已有 effect-segment-render.spec.ts 的 import.meta 与 CommonJS 配置冲突阻断；使用 ES2022 module 覆盖的类型检查通过，未改动该无关测试。
- 本地真实项目中重新选择已活动的测试1包装版本02，服务端保存该模板的选择时间；返回配置、刷新、切换测试2再返回、重新进入精修均保持5条工程，而非版本01的13条。测试2与测试3仍分别保持11与15条工程。
- 配置页分支树将测试1包装版本02标为当前路径，版本01不再标为当前；渲染素材仍为22条。未调用模型、未创建分支或改动成片内容。
