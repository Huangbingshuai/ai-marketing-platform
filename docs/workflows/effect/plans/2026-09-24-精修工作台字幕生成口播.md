# 精修工作台：按字幕一键生成新口播

日期：2026-09-24
需求原话：*「我需要点击某个字幕之后可以选择一个音色生成这个字幕的新的口播，请你在字号控制那里添加这个按钮，然后新增的字幕直接对齐字幕生成在字幕轨道中，如果字幕轨道放不下则新增字幕轨道放置新的口播」*

已确认的三个口径（AskUserQuestion）：

| 问题 | 选择 |
| --- | --- |
| 音色选择 | **用模板当前音色，一键生成**（不做音色选择器） |
| 已有口播 | **并列新增**（保留原口播，新口播另起一轨并行） |
| 后端范围 | **接受，四层一起做**（contracts / API / worker / web） |

---

## 一、范围

点击精修工作台里的一条字幕 → 在**字号控制那一行**出现「生成口播」按钮 → 用**模板当前音色**把这条字幕的文本合成为一段新的口播 → 该口播**起点对齐字幕起点**，落在**音频轨**上；音频轨放不下时**新开一轨**（已有的音频素材整体下移，不覆盖）。

四层都要动：

1. `packages/contracts`：checkpoint 新增 `captionVoices` 集合 + 请求/队列消息类型 + 时长函数。
2. `apps/api`：新增编辑器侧「请求合成」路由 + worker 侧「写回音频」内部路由 + domain 校验 + outbox 投递。
3. `workers/effect-template-mix`：新增 `CAPTION_VOICE` 任务的消费分支与合成处理器；渲染器把新口播混进音轨。
4. `apps/web`：按钮、请求、落地到音频行、时间轴绘制、拖动/裁剪/音量/淡入淡出/撤销全部打通。

## 二、现状与关键约束（实测证据）

### 2.1 不能复用 `checkpoint.script` + `checkpoint.voices`

`checkpoint.voices` 的键**必须**能对上一条 `script` 行：

- `apps/api/src/workflows/effect/template-mix/effect-packaging.domain.ts:410-437`，其中 `:417` 是 `!line ||` —— 直接 `fail()`。

即使硬塞一条 `script` 行，还会连续撞上四处：

- `:517-535`：`ready` 时**每条 script 行都必须有对应的口播字幕分段**（`(ready && !parts?.length)` → fail），且分段的 `text` 拼接必须等于行文本、`segmentFrames` 必须逐段对齐。
- `:557-574`：`ready` 时 `narrationCaptions.length` 必须等于 `script.length`（分段版要求「非空」），且每条 script 行的 voice 必须带 `segmentFrames`。
- `:583-621` `canonicalizeCheckpoint`：按 `script.find(s => s.id === id)` 把 voice 的 `start` 重置成 `line.start`、`offset` 归零；部分重做前会跑。
- `apps/api/src/workflows/effect/template-mix/effect-packaging.service.ts:308-330`：`component: 'VOICE'` 重做会 `delete cp.script; delete cp.voices; delete cp.captions;`（带 `slotId` 时按槽位删）—— 编辑器生成的条目会被整片抹掉。

结论：**必须新增一个编辑器自有、与流水线解耦的集合**，沿用 `captionBoxes`（`effect-template-mix-packaging.ts:141-150` / `domain.ts:540-546`）那套「组件重做不影响、id 只校验形状」的先例。

### 2.2 渲染器按值遍历口播，且已经支持编辑器几何

`workers/effect-template-mix/src/effect_template_mix/final_output.py`：

- `:284` `voices = list(cp['voices'].values())` —— 按值遍历，多一条就会被渲染。
- `:285-303` 每条 voice 统一处理 `offset`（裁头）、`start`（时间轴位置）、`volume`、`fadeIn/fadeOut`；`:292` 校验 `start + length > duration + .001` 即报错。
- `:338` 音乐闪避窗口 `windows` 由 `voices` 生成（新口播会自动让音乐让路）。
- `:351-354` `amix=inputs={2 + len(voices) + len(detached)}`，`:339` `music_index = source_count + len(voices) + len(detached)` —— 全部由 `len(voices)` 推导。
- `:412-415` 渲染前收集输入文件 id 集合，漏掉就会 `KeyError`。
- `:216` `duration = float(timeline['duration'])`；该时长由 `apps/api/src/workflows/effect/final-output/effect-final-output.service.ts:246` 用 `effectTemplateMixContentDuration(variant, cp)` 覆盖（`:241-244` 注释明确「成片长度跟随内容」）。

所以渲染侧只需在 `:284` 把新集合并进 `voices`、在 `:414` 并进文件 id 集合，裁剪/移动/音量/淡入淡出**零额外代码**。

### 2.3 时长函数必须跟着改

`packages/contracts/src/effect-template-mix-packaging.ts:385-397` `effectTemplateMixContentDuration` 目前汇总 `voices` / `music` / captions。新口播不并进去的话：比画面长的口播会触发 `final_output.py:292` 的 `口播真实音频时长与包装不一致` 直接渲染失败，黑尾延伸也不生效。同一函数被 `apps/web/.../EffectTemplateMixNodePage.vue:578`（播放头范围）和 `EffectTemplateMixTimeline.vue:473` 使用。

### 2.4 现有「音频行」机制可以直接复用

- `apps/web/src/workflows/effect/template-mix/effect-template-mix-audio-lanes.ts:71-103` `timelineAudioClipRefs`：决定「哪些音频片段在时间轴上存在」，是行归属、静音、持久化的唯一判定处（`:66-70` 注释）。口播 id 形如 `voice:<lineId>`。
- `:29-33` `DEFAULT_AUDIO_LANE = { VOICE: 0, MUSIC: 1, DETACHED: 2 }`。
- `EffectTemplateMixNodePage.vue:3626-3654` `resolveAudioPlacement`：占位则向上找空行，上面没有空行就**在请求行插入新行并把已有素材下移**（`:3648-3653`），正是需求里「放不下则新增轨道」的语义。
- `:3601-3625` `audioClipPlacements` 把 clipId → `{duration, start}`，`resolveAudioPlacement` 依赖它拿到真实时长。

**一个坑**：`movePackagingAudios`（`:3660-3714`）的 `shouldApplyMove`（`:3697-3706`）在「行号没变且时间没变」时直接 `return`。程序化落位恰好就是这个形态（新口播已在字幕起点、目标行是默认 0 行），插入新行会被丢掉。所以落位需要一个小函数直接复用 `resolveAudioPlacement`，不能只调 `movePackagingAudios`。

### 2.5 编辑器侧的音频读写入口

- `EffectTemplateMixNodePage.vue:1440-1453`：`packagingAudioTarget` 把 clipId 解析成 `{kind, key}`，`packagingAudio` 按 kind 取音频对象。加一个 kind 就能让 `applyAudioStart`（`:1659-1690`）、`resizePackagingAudio`（`:1694-1723`）、`changePackagingAudioVolume`（`:1724-1730`）、`audioStandard`（`:2009-2021`）全部自动支持。
- `:1492-1521` `audioDiff`：把本地 checkpoint 与已保存副本做差，只有 `voices/music/captions/boxes` 四类；新集合要加一条。
- `:1556-1602` `flushAudioEdit`：250ms 防抖后的 PUT；`:1615-1638` `editPackagingAudio` 负责建立 `audioBaseline`。
- `EffectTemplateMixTimeline.vue:628-665` `timelineAudios` 按 `ref.id.slice('voice:'.length)` 取音频；`:1573-1586` 复制素材同样按前缀取。

### 2.6 服务端现有的写入口都不适用

- `effect-packaging.service.ts:468-582` `updateAudio`：`PUT .../items/:itemId/audio`，只接受 `voices/music/captions/boxes` 的**几何编辑**，不接受新音频文件。
- `:699-803` `upload`：`POST internal/.../items/:itemId/audio/:role`，需要 `x-attempt-token` 且 run 处于 `RUNNING` + 租约未过期（`workerItem` `:616-625`）—— 编辑器触发的合成没有包装租约。
- 角色正则 `:709` `/^(music|voice-[a-zA-Z0-9_-]{1,50})$/`，`effectPackagingFile` 对 `(projectId, itemId, role)` 唯一且**拒绝替换为不同 sha256**（`:729-734`）—— 与「同一条字幕可以重新生成」冲突。
- 内部路由的鉴权是 `EffectTemplateMixWorkerGuard`（`effect-template-mix-worker.guard.ts:10-21`，`x-worker-token` 定时安全比较），与租约无关，可直接给新路由复用。

### 2.7 合成能力只在 worker 里

- `workers/.../packaging_provider.py:82` `async def voice(text, *, speaker, resource_id) -> bytes`：返回 24kHz 单声道 16bit PCM，120s 上限，401/403→`VoicePermissionError`，429/5xx→`PackagingTransientError`。
- `workers/.../packaging_media.py:25-34` `pcm_wav(pcm) -> (wav_bytes, duration)`。
- `workers/.../voice_preview.py:32-105` 是现成的「一次付费 TTS + 上传」模板。
- `workers/.../consumer.py:106-113` 把 `VOICE_PREVIEW` 放在 `long_task` 信号量**之外**（`:112` 起才进 `long_task`），因为它是短任务；新任务同样应当这样排队。

API 侧解析音色：`effect-packaging.service.ts:234` `this.voiceCatalog.selection(entry.workspace.template.voiceProfileId)` 已注入可用；`PackagingSnapshot.voiceProfile`（`effect-template-mix-packaging.ts:199-201`）是包装时冻结的同一个音色。

### 2.8 outbox 的键约束

`apps/api/prisma/schema.prisma:923-943` `JobOutbox.aggregateId` 是 `@db.Uuid`，唯一键是 `(projectId, jobType, aggregateId)`；`jobType` 是 `VarChar(120)`（新 taskType **不需要迁移**）。

- 现有投递（`effect-packaging.repository.ts:64-95`、`effect-voice.repository.ts:20-53`）都用 `aggregateId = runId` 并靠 `upsert.update` 重新武装同一行。
- **字幕 id 不是 UUID**（`packaging_captions.py:94` 生成 `caption-<24hex>`，编辑器手动字幕只要求 `/^[a-zA-Z0-9_-]{1,50}$/`），所以 `aggregateId` 不能用 captionId。
- 若用 `aggregateId = itemId`，同一条成片对两条字幕连续点两次会**互相覆盖**同一行，前一个请求丢失。

## 三、设计决策

### 决策 1：新增独立集合 `captionVoices`，键 = 字幕 id

```ts
// PackagingCheckpoint
/** 编辑器为某条字幕单独生成的口播，键是字幕 id；与流水线的 script/voices 无关。 */
captionVoices?: Record<string, PackagingAudio>;
```

- **为什么不塞进 `voices`**：见 2.1，五处硬约束。
- **为什么键用字幕 id 而不是新生成 id**：一条字幕最多一条「字幕口播」，天然去重；时间轴 clipId 为 `capvoice:<captionId>`，与 `voice:<lineId>` 不冲突。
- **字幕被删掉怎么办**：条目允许成为孤儿（与 `captionBoxes` 的既有口径一致，`domain.ts:542-543`）。删字幕不该静默删掉用户花过钱的口播；它仍然作为音频片段显示在时间轴上，可单独删除。
- 校验（新块，放在 `voices` 校验之后）：
  - 条目形状：`fileObjectId` 非空、`duration > 0`、`start >= 0`、`volume` 在 `[0, PACKAGING_AUDIO_GAIN_CEILING]`、`fades` 合法、`segmentFrames` 形状同 `voices`；
  - `start + duration <= EFFECT_TEMPLATE_MIX_MAX_CONTENT_SECONDS`；
  - 编辑器写路径（`edited`）：允许自由移动/裁剪，`offset + duration <= (原 offset + 原 duration) + 0.05`（沿用 `updateAudio:507-510` 的口径）；
  - worker 写路径（`!edited`）：`start === caption.start`（与需求「直接对齐字幕」一致）。
  - **不**要求字幕存在（允许孤儿），**不**做互相之间的重叠检查（编辑器音频本就允许多轨并行）。

### 决策 2：`captionVoices` 用「对齐 + 独立」语义

新口播落位时 `start = caption.start`，之后**不再跟随字幕移动**（与 `checkpoint.voices` 和字幕的关系一致：编辑器可自由错位）。这是「对齐」而非「绑定」。

### 决策 3：轻量 job，不做 claim/lease/fence 生命周期

投递：编辑器路由在事务里写一行 outbox，`aggregateId = randomUUID()`（每次请求独立一行，不覆盖），payload 带 `{ schemaVersion: 2, taskType: 'CAPTION_VOICE', projectId, runId, itemId, captionId, text, profile, requestId }`。

worker 处理完把 wav POST 到内部路由，由服务端写 checkpoint 并落 `effectPackagingFile`。

**明确不做** `EffectVoicePreview` 那套 claim/heartbeat/submit/fail/recoverExpired（`effect-voice.repository.ts:128-215`）。理由：

- 那套 fence 存在的意义是「**自动重试**不得重复付费」；本任务没有自动重试（独立 uuid 行不会被重新武装，`job-outbox.repository.ts` 只在投递失败时退避重投），所以没有对应的风险来源。
- 写回按 `captionId` 覆盖，天然幂等：重复投递只会多付一次合成、写回同一键，不会产生错误状态。
- 代价：worker 中途崩溃时该请求不会自动重来，需要用户再点一次（前端按钮超时后提示可重试）。这是本方案唯一「比预览任务弱」的地方，**请重点确认是否接受**。

### 决策 4：编辑器的「文本前置条件」代替乐观锁

合成必须读**服务器存的字幕文本**（不能让客户端传文本，否则等于开放任意文本的付费 TTS）。而字幕文本框有 250ms 防抖（`scheduleAudioEdit`），刚打完字就点按钮可能读到旧文本。

处理：请求体带 `{ captionId, text }`，服务端 **`text` 只当断言**：

```
if (caption.text !== body.text) throw new ConflictException('字幕文本尚未保存，请稍后重试');
```

合成一律使用服务端自己存的 `caption.text`。同时**不**要求 `expectedUpdatedAt`：本写入只新增一个键，不会覆盖任何既有几何，乐观锁在这里只会和编辑器自己的 flush 抢锁。

### 决策 5：落位复用 `resolveAudioPlacement`，但要单独的放置函数

按 2.4 的坑，新增 `placeGeneratedCaptionVoice(clipId, start)`：算 `audioClipPlacements` → `resolveAudioPlacement(..., DEFAULT_AUDIO_LANE.VOICE, new Set([clipId]))` → `rememberTimelineEdit()` → 需要插入新行时把 `lane >= insertRowAt` 的既有素材整体 +1 → 写 `variant.audioLanes[clipId]` → `normalizeVariantAudioLanes` + `bump()`。

## 九、实施偏差（相对 §四 的改动清单）

### 9.1 内部写回路由没有 `:requestId`，也没有 `.../fail`

- 实际路由：`POST internal/workers/effect-template-mix/caption-voices/:runId/items/:itemId/audio`（multipart，字段 `projectId` / `captionId`）。
- 没有实现 `POST .../fail`。理由：本方案不落持久化任务行，失败码没有任何服务端落点，前端也没有查询通道，实现它只会多出一个没人读的写入口。失败语义改为：worker 侧 `nack(requeue=not redelivered)`（最多重投一次，`test_voice_library.py::test_caption_narration_failure_is_requeued_at_most_once` 覆盖），前端 90s 超时后提示可重试。这是决策 3 取舍的直接后果。

### 9.2 `placeGeneratedCaptionVoice` 之外还需要一处「到达条目穿越合并」

`onPackagingSelected`（`EffectTemplateMixNodePage.vue`）在「本地有未保存几何」时会**整份丢弃**轮询回来的 checkpoint。新口播到达时如果用户恰好又拖了别的片段，`audioBaseline` 非空，新条目会被一起丢掉，`watch` 永远看不到它，用户只能等到 90s 超时提示。因此在该分支里按 `pendingCaptionVoice.captionId` **精确**把服务端那一个条目搬进保留的本地 checkpoint（只搬这一个键，避免覆盖本地对其它 `captionVoices` 条目的未保存拖动）。

### 9.3 `packagingAudioFade` 的 `kind` 形参不接受 `CAPTION_VOICE`

契约里是 `kind: 'MUSIC' | 'VOICE'`。`onAudioParamsChange` 里原本直接传 `target.kind`，新增 kind 后会变成类型错误，故在循环内归一化 `const kind: 'MUSIC' | 'VOICE' = target.kind === 'MUSIC' ? 'MUSIC' : 'VOICE';`。`audioStandard` 的返回值同样做了归一化。

### 9.4 没有为「删除新口播」新增入口

§六.5 的人工验收原本写了「删除」一项，但实际未实现：既有 `voice:` / `music` 等打包音频片段在时间轴上**本来就不提供删除**（`deleteSelection` 只处理 `caption:` 与 `detached:`），本次没有扩大范围。新口播与既有口播草稿一样只能静音（按行静音）或重新生成覆盖。若需要删除，得新增一条「删除 checkpoint 内某条 captionVoices 条目」的 API，属独立改动。
