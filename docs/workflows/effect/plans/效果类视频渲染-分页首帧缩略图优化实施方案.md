# 效果类视频渲染分页首帧缩略图优化实施方案

## 目标

视频渲染素材列表不再为了展示首帧同时加载和解码多条完整 MP4。新完成的视频在 Worker 已持有视频字节时生成轻量首帧缩略图，并与同一输出版本一起保存；前端分页优先加载可缓存图片，只有用户主动预览或返修时才加载视频。

## 边界

- 工作流：效果类。
- 节点：视频渲染。
- 直接上游：已确认的 `prompt-batch:{productId}` 工作副本及其 revision。
- 当前输出：每条 `render-clip:{taskId}` 与整批 `render-batch:{productId}`。
- 提交边界：仍然只有“完成校验”；缩略图是视频输出衍生文件，不单独产生 WorkingArtifact 或业务 revision。
- 直接下游：模板混剪继续消费活动视频文件，不消费缩略图。

## 实施范围

1. Contracts 为视频输出增加向后兼容的可选 `poster` 元数据。
2. Seedance Worker 对真实视频执行 MP4 faststart 无损整理，并提取约 480px 宽的 JPEG 首帧；后处理失败时保留原视频并允许无缩略图降级。
3. Worker 完成回调同时上传视频和可选首帧文件。
4. API 在同一任务事务内登记两份 FileObject，并让首帧随生成、重新生成、返修采用/放弃及旧文件清理一起切换。
5. 内容接口支持读取 `VIDEO` 或 `POSTER`，版本化 URL 使用私有长期缓存；未带版本的历史调用保持 `no-store`。
6. Web 卡片优先使用服务端首帧 `<img>`；历史无首帧任务保留 IntersectionObserver 降级，但限制并发并使用异步 Blob 编码。

## 非目标

- 不改变 Seedance 模型调用、提示词编译、任务并发或计费。
- 不为缩略图建立新的工作副本、项目资产或用户编辑入口。
- 本次不强制同步回填所有历史视频；历史数据按兼容降级显示，后续可增加独立补建任务。

## 数据与迁移

- `EffectSegmentRenderTask` 增加活动输出和返修候选各自的可空首帧 JSON 元数据。
- 老记录字段为空，读取契约返回 `poster: null`。
- 首帧元数据包含 FileObject ID、文件名、MIME、大小、SHA-256 和所属视频版本。
- 采用返修候选时连同首帧一起切换；放弃候选或覆盖旧输出时将对应首帧 FileObject 标记为孤儿。

## 并发与失败策略

- 后处理在 Worker 内异步等待独立 ffmpeg 子进程，不阻塞事件循环。
- 每条任务只在视频下载完成后处理一次；任务版本和租约仍由现有完成回调校验。
- faststart 或首帧生成失败不让已经生成成功的视频失败，API 接受无首帧结果并由前端走受控降级。
- 前端历史降级设置小并发队列，避免分页时同时启动全部视频 Range 请求和解码。

## 验收

- 新任务完成响应包含首帧元数据，首帧内容接口支持项目隔离、版本校验和缓存头。
- 页面分页时有首帧的卡片只请求图片，不请求视频内容；点击预览后才请求视频。
- 历史无首帧数据仍可展示并预览，不阻断列表。
- 重新生成和采用返修结果后展示新版本首帧，旧首帧不串用。
- Contracts、API、Web、Worker 聚焦测试、类型检查、构建和 `git diff --check` 通过，并完成浏览器分页回归。
