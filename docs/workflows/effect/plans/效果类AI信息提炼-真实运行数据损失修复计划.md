# 效果类 AI 信息提炼：真实运行数据损失修复计划

## 状态

第四轮语义全量决策已完成，待真实付费任务复验。

## 背景与证据

2026-09-01 的真实“广式腊肠”提炼任务已验证结构化文档解析、确定性标准化和图片识别能够正常工作，但仍发现三处数据损失：

1. Docling 的“字段标题 + 项目列表”输出中，最后一个列表字段会把随后出现的“填写确认”说明误收为业务事实。
2. Worker 曾允许保存最多 20 条次要卖点，但 Contracts 与 API 的历史生成上限仍为 6，导致已融合的图片建议在持久化前被静默截断。复测后确定 AI 生成上限统一为 10，用户编辑安全边界继续为 20。
3. 语义整理模型可能把同字段内主题不同的事实错误标为 `SAME_MEANING`，当前 Worker 会直接执行该合并。

## 修复范围

- 文档确定性解析器识别说明、确认和备注段落；项目列表开始后遇到普通说明段落立即结束当前字段，不把说明文字写入信息卡。
- 将次要卖点的 AI 生成与跨层适配容量统一为 10；核心卖点继续保持 1～3 项，用户可编辑列表的公共边界仍为 20。
- 语义整理只执行经过确定性保护的合并：
  - `PARENT_CHILD` 必须能由规范化文本的真实包含关系验证；
  - `SAME_MEANING` 必须具备较强的文本骨架重合；
  - `SAME_FAMILY` 继续只记录关系，不删除事实；
  - 无法确定时保留全部原始事实。
- 收紧语义 Prompt 的定义和反例，但不改变节点、接口、数据库或任务生命周期。

## 非目标

- 不改变来源优先级和图片识别字段范围。
- 不修改全局视频配置、人工覆盖、确认提交或 WorkingArtifact revision 语义。
- 不扩大核心卖点、场景、受众和信任背书的既有数量边界。
- 不修改 Prompt 生成及其他效果类节点。

## 验收

- “填写确认：……”等尾注不再进入情绪场景或其他列表字段。
- 8 条有效次要卖点能够完整通过 Worker、Contracts 和 API；超过 10 条时按来源优先级保留前 10 条。
- “节庆采购需求”与“外观品质判断”等主题不同事实即使被模型误报，也不会被 Worker 合并。
- 真正近似重复的事实仍可合并；父子关系只有在文本包含可验证时生效。
- Worker、Contracts、API 相关测试、类型检查和 `git diff --check` 通过。

## 真实结果

- 文档解析新增项目列表终止规则与确认/说明/备注过滤，真实资料包中的“填写确认”不会再进入情绪场景。
- `EFFECT_EXTRACTION_MAX_SECONDARY_SELLING_POINTS` 第一轮由 6 放宽；第二轮按用户确认收敛为 10。Worker、Contracts 与 API 的 AI 生成容量保持一致，8 条回归用例完整保留，用户手工编辑仍可使用 20 条公共安全边界。
- 语义 Prompt 升级至 `2.2.0`，并增加 Worker 确定性保护。真实故障样例“节庆采购需求”与“外观品质判断”即使被模型误报为同义也会保留两条。
- 修正了父子事实代表项排在原列表后方时无法正确归并的既有边缘问题。
- Worker 全量测试通过，4 项显式外部集成测试按门控跳过；变更文件 Ruff 与 17 个 Worker 源文件 mypy 通过。
- Contracts 17 项测试、类型检查与构建通过；API 信息提炼 63 项测试、类型检查与生产构建通过；本次文件 `git diff --check` 通过。
- 本地 `effect-extraction-worker` 镜像已重建，容器已重新消费 `effect.extraction.requested` 队列。
- Worker 全目录 Ruff 仍报告既有 `consumer.py` 未使用 `Any` 导入；该文件不属于本次修改，未扩大范围处理。

## 第二轮真实复测问题

- 语义整理已正确合并重复购买场景，但标准化仍从 `FUSION` 重新取值，并从原始来源重建数组，导致已合并事实再次出现。
- 图片模型把香料、竹篮、蒸笼等场景道具写入次要卖点；容量放宽后会把这些非产品属性展示给用户。
- 本地 API 在 Contracts 构建前已启动，仍缓存旧的 6 条容量，需要在代码验证后重启。

第二轮将让标准化只对五个语义字段复用经过保护的语义候选；产品硬事实、卖点来源优先级和人工覆盖保持不变。图片卖点只接收图片模型输出的产品/包装可见核心价值，场景道具仅允许进入场景或视觉氛围字段。

## 第二轮实施结果

- `NORMALIZATION` 现在以受保护的 `SEMANTIC_REFINEMENT` 候选作为输入，并在恢复权威来源后，仅对痛点、决策动因、使用场景、购买场景和情绪场景应用语义整理结果。真实样例中的“家庭日常采购 / 家庭日常食材采购”不会再在最终结果中同时出现。
- 图片补充卖点只接收图片模型归入产品本体或包装可见价值的核心项；图片模型输出的香料、竹篮、蒸笼等场景道具不再被融合为次要卖点。图片 Prompt 升级到 `6.2.0`，增加字段归类和输出前自检。
- AI 生成的次要卖点最终上限固定为 10，Worker 与 API 都有 12 条收敛到前 10 条的回归覆盖；公共编辑 Schema 继续允许 20 条，避免历史草稿和人工编辑数据被结构层破坏。
- Worker 全量测试通过（4 项显式外部集成测试按门控跳过），Ruff 与 17 个 Worker 源文件 mypy 通过。
- Contracts 17 项测试、类型检查和构建通过；API 信息提炼 64 项测试、类型检查和生产构建通过。
- 本地信息提炼 Worker 已重建并成功消费队列；本地 API 已在 Contracts 重建后重新启动，`/api/health` 返回 200。

## 第三轮：语义判断完全交给模型

真实复测发现，图片建议“肥瘦纹理分明，肉质油润有光泽”和“肥瘦纹理清晰分明”仍会同时保留。原因不是模型没有判断，而是 Worker 在模型之后继续用字符骨架、修饰语名单和文本包含关系复判语义；模型换一种自然表达后，确定性规则就会否决正确的语义分组。

本轮固定职责边界：

- 语义模型同时接收核心卖点、次要卖点、痛点、决策动因和三类场景，并独立判断 `SAME_MEANING / PARENT_CHILD / SAME_FAMILY`。
- Worker 不再使用字符相似、关键词、修饰语名单或文本包含关系判断语义，只验证事实 ID 存在、字段一致、分组结构合法以及来源权限。
- 用户事实是权威输入：两个用户事实即使被模型放入可删除分组也全部保留；用户事实与图片建议同组时只能保留用户事实作为代表；纯图片建议可按模型结果归并。
- `SAME_FAMILY` 始终只记录主题关系，不删除原始事实；模型不得改写或生成事实，只能选择输入 ID。
- 图片识别 Prompt 禁止仅凭外观生成“判断品质”“高端品质”等不可验证结论，只允许描述可见形态、纹理、包装、用途和储存便利。

验收结果：语义模块覆盖了非字面父子关系、图片卖点同义归并、混合来源保留用户事实和多用户事实防删除；相关 43 项测试与 Worker 全量测试通过，17 个源文件 mypy 通过，变更文件 Ruff 检查通过。未执行付费 Ark 重跑，真实效果需在下一次用户重新提炼后确认。

## 第四轮：跨字段归类、全量图片卖点与模型择优

最新真实 Run 发现三项剩余问题：图片分支产生的次要卖点未全部进入语义模型；模型只能在同字段内归并，无法纠正 AI 图片建议的错误字段；字段超量时标准化阶段仍会按原顺序截断。实施目标如下：

- 核心卖点与次要卖点中的全部图片建议都进入语义模型，不在 Worker 中提前按文字或字段猜测价值。
- 语义模型可以把 AI 图片建议移动到核心/次要卖点、痛点、决策动因或三类场景中的更合理字段；用户事实不允许移动。
- 模型可跨字段声明同义或父子关系，并返回每个非空字段最终保留的事实 ID。字段超量时由模型按信息价值择优，Worker 只校验 ID、来源、数量和结构。
- Worker 不使用字符相似、关键词、文本包含或业务语义规则复判模型结论；不合法的模型决策使语义节点进入部分完成并保留原始信息，不能静默伪造整理结果。
- 默认语义模型从 Mini 升级为当前主 Turbo，并使用低思考强度；严格结构化输出上限同步提高，避免完整选择计划被截断。

验收重点：同义图片卖点只能保留一条；“整根形态判断”和“切片用法判断”等不同角度不得错误合并；错误落入卖点的图片展示建议可由模型迁入决策动因；字段超量时不存在 Worker 顺序截断；用户事实始终保留。

### 第四轮实施结果

- 语义契约升级为一次返回 `groups / placements / selections`：关系组可跨字段，只有图片建议允许改字段，每个非空字段必须返回完整最终 ID 清单。
- 核心卖点未入选项、图片核心卖点余项和图片次要卖点现已全部进入语义输入；“图片次要卖点生成了但进入模型前丢失”的链路缺口已关闭。
- 默认语义模型改为当前主 Turbo，使用低思考强度；超时调整为 60 秒，严格结构化输出预算调整为 4096，明确输出截断时的第二次预算为 6144。
- Worker 仅做精确空白清理、ID/来源/数量/结构校验和用户事实保护，不包含字符相似、关键词、文本包含或字段业务判断。模型决策非法时节点进入 `PARTIAL` 并保留原始事实，不伪造已完成的语义整理。
- 新增跨字段改归类、跨字段同义合并、字段超量模型择优、用户事实不可删除、整根与切片不同角度保留及完整图片卖点入模回归测试。
- Worker 全量测试通过，4 项显式外部集成测试按门控跳过；变更文件 Ruff 与 17 个 Worker 源文件 mypy 通过。未执行付费 Ark 重跑。
