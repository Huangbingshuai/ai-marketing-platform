# 导入图片预览复用优化

## 范围与依据

效果类资料导入节点，直接来源为当前项目资料，确认边界仍是保存产品资料包；不改变草稿或 WorkingArtifact revision，不影响信息提炼依赖。复用现有共享导入组件，兼容定制类调用。

资料列表元数据已接入 Redis，文件内容接口仍为 private, no-store。缩略图下载的是原始图片；先前只有当前 DOM 图片能被查看弹窗复用，离开节点后再次进入会重复下载。文件接口还通过完整草稿和完整产品恢复路径校验单个文件。

## 实施

- 在浏览器当前页面内缓存已成功加载的图片，按受保护内容路径和 updatedAt 隔离；缺失版本不缓存，替换文件更换键。缓存最多 24 张、解码像素预算 32 MiB、有效期 5 分钟，不使用持久化存储或 Redis 保存二进制。
- 返回导入页用缓存图片绘制缩略图；查看内容弹窗复用相同图片，避免重复下载。失败、未完成与超预算图片不缓存，重试保持可用。
- DOCX/纯文本查看成功后复用解析结果，按文件路径、版本和类型区分，最多 8 项、2 MiB、5 分钟；关闭或失败不缓存未完成解析，PDF 保留原读取路径。
- 单文件首次读取直接查询当前效果类活动 Run 下指定资料、模式、产品及文件，保留项目权限、移除状态与隔离检查，不加载完整草稿和其它产品。
- 保持 HTTP no-store、原文件访问、只读查看和下游确认边界。

## 验证

单测覆盖版本替换、项目路径隔离、TTL、数量与像素预算、失败不缓存、跨挂载复用和原读路径隔离；运行 Web/API 相关测试、类型、构建及 diff 检查。浏览器验证实际资料缩略图、节点往返和弹窗展示，记录观察与未验证限制。

## 实施及实际验收

2026-10-08，本地 API 3100 / Web 5173，真实紫苏梅子酱项目，只读回归，没有修改商品资料或发起付费任务。

- 导入 → 提炼 → 返回导入后，三张缩略图均为缓存 Canvas，aria-busy=false，没有创建网络图片元素。主图查看弹窗同样复用原图，Canvas 为 1212 像素宽，无加载态；关闭后焦点回到原查看按钮。缩略图绘制限制为 120 像素，避免在小图容器中复制全尺寸画布。
- 浏览器验证 1920、1440、390 宽度。390 的弹窗 clientWidth 与 scrollWidth 都为 350，无弹窗横向溢出。[1440 主图](../evidence/browser/2026-10-08-import-image-cache-1440.jpg)、[390 主图](../evidence/browser/2026-10-08-import-image-cache-390.jpg)、[1920 资料列表](../evidence/browser/2026-10-08-import-image-cache-list-1920.jpg)。
- 经 Web 代理读取细节图和主图各 3 次全部 HTTP 200，耗时分别为 344/114/128 ms 与 181/143/148 ms；原图 131792 / 549567 bytes，仍为 private,no-store。这是修改后单机样本，不是冷/热对比或 P95 保证。
- 错误项目、产品、导入模式访问原图均返回 404，未绕过隔离。
- 实际 DOCX 文件本身有效，Node 读取可得到 1369 字符，但原浏览器 Worker 的动态依赖 URL 返回 504（过期/缺失的 Vite 优化模块）。将 `mammoth/mammoth.browser` 加入显式预构建后，模块返回 200；真实浏览器正文呈现 1367 字符（trim 后），第二次打开没有加载态或错误。没有保留临时诊断消息或输出正文。
- 期间观察到开发 HMR 的项目上下文丢失，刷新后恢复。该已有问题不作为本次图片缓存修复已解决的结论。
