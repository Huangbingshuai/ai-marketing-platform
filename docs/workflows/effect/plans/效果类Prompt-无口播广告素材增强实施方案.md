# 效果类 Prompt 无口播广告素材增强实施方案

状态：已完成（自动验收）

## 一、目标与边界

- Prompt 节点继续生成一条 Prompt 对应一个可混剪的视频素材片段，不生成完整广告脚本。
- 新生成素材不包含人物口播、逐字台词、旁白、人声解说或依赖对口型的表达。
- 保留与画面同步的环境声和产品动作 Foley；配乐、统一口播与字幕由后续混剪/成片能力负责。
- 片段时长继续使用 4～15 秒，不改变 Prompt 批次、WorkingArtifact、HTTP 路径或 Prisma Schema。
- 历史 Prompt 保持原样可读；本次规则仅影响新生成和新评估结果。

## 二、当前问题

- Worker 的结构化镜头契约包含 `dialogue`，生成模板和时长提示允许人物开口，编译器会把它输出为“逐字台词”。
- 抽象事实仍可能被分配到需要“直接讨论”的创意方向，模型容易用人物讲解完成事实覆盖。
- 生成与评估对“素材片段”的定义不一致：生成允许口播，部分 API 历史质量规则却把口播视为素材越界。
- 模板仍残留 16～30 秒的旧时长说明，与当前 15 秒硬上限冲突。

## 三、开源调研采用原则

- [LTX-Video 官方仓库](https://github.com/Lightricks/LTX-Video)的 Prompt 指南强调按时间顺序、动作优先、字面精确，并写清主体、环境、镜头和光线；本节点采用这些原则，但不照搬完整成片脚本。
- [Wan2.1 Prompt Extension](https://github.com/Wan-Video/Wan2.1/blob/main/wan/utils/prompt_extend.py)在保留输入原意的前提下补充外观、空间关系、动作与运镜；本节点同样禁止为了画面丰富另造业务结论。
- [HunyuanVideo Prompt Rewrite](https://github.com/Tencent-Hunyuan/HunyuanVideo/blob/main/hyvideo/prompt_rewrite.py)区分语义保真与视觉美学增强，[官方说明](https://github.com/Tencent-Hunyuan/HunyuanVideo)也提示偏重视觉增强可能损失语义细节；本节点因此让事实边界优先于风格词。
- [Open-Sora](https://github.com/hpcaitech/Open-Sora)支持可选的模型 Prompt refinement，但当前实现不新增第二次付费润色调用；在现有一次结构化生成中形成视觉意图和镜头计划，再由确定性编译器排版，避免额外时延和语义漂移。

## 四、实现方案

1. 从内部 `MaterialShotPlan` 移除总览音乐/人声方向和节拍 `dialogue` 字段，只保留可选动作现场声。
2. 生成模板改为“静音仍可理解”的广告素材导演：首帧建立主体与商品关系，一个视觉传播任务，一条连续动作弧，镜头每次变化都提供新信息。
3. 指定人物只能通过使用、选择、互动和非语言反应参与，不对镜讲话、不形成可辨识口型。
4. `TEXT_ONLY` 抽象事实不再要求素材直接讨论；只允许影响商业背景或留给后续文案，不作为画面必须证明的任务。
5. 评估器新增 `SPEECH_DEPENDENT_MATERIAL` 硬问题，语义判断只由 AI 完成；Worker 仅验证问题码、结构、事实 ID 和数量。
6. 编译器不再输出“声音方向”和“逐字台词”，只在有必要时输出环境声或动作音。
7. 清理生成与评估模板中的 16～30 秒旧规则，统一为 4～8 秒单一事件、9～15 秒连续动作弧。

## 五、验收

- 新结构化生成 Schema 不再包含 `dialogue` 或总览音乐/人声字段。
- 新 Prompt 不包含编译器生成的“逐字台词”，人物讲话不能成为商品价值成立的必要条件。
- Prompt 在静音状态下仍能通过首帧、产品动作、可见变化和结束状态表达素材用途。
- 4～15 秒时长、事实来源、六维一致性、数量优先、向量择优和历史结果读取不回归。
- 执行 Worker 单测、模板测试、API/Web 相关测试、类型检查及 `git diff --check`。
