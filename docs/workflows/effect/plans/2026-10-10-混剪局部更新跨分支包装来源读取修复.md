# 混剪局部更新跨分支包装来源读取修复

## 已观察问题

广式腊肠项目的测试1局部更新在准备阶段报“包装来源 revision 已改变”。只读核对确认：共享渲染头中的新素材，依赖测试2已发布 Run 内的确切 Prompt 工作副本；读取测试1时仅加载渲染素材所属 Run 的祖先，漏掉该 Prompt，商品事实和文件本身并未因此丢失。

## 范围与实现

- 效果类 SEGMENT_RENDER → TEMPLATE_MIX，复用 WorkingArtifact 明确依赖和现有谱系判定；不新增状态、表或任务。
- 共享素材的依赖闭包允许从同一渲染谱系内已发布的混剪/输出 Run 及合法祖先读取，仍严格按 sourceArtifactId 查找，不按名称或相同 key 替代。
- 仅补齐读取；不修改素材、工程、包装、业务 revision 或数据库历史。局部更新仍由用户确认执行，冻结与事务回写边界不变。
- 保留项目、工作流、谱系、未发布分支隔离，以及可用性、实际 revision、工程编辑、租约与 attempt token 校验。

## 验证

- 回归共享渲染素材位于根 Run、确切 Prompt/事实位于另一已发布混剪 Run 的场景。
- 验证其他项目、独立渲染谱系、未发布兄弟草稿不会进入闭包；真实 revision 改变仍拦截。
- 执行依赖读取、包装、局部更新相关 API 单测、类型检查和 diff 检查。
- 使用真实项目只读输入运行包装来源预检，确认错误消失；不创建任务、不调用模型、不自动导出或提交 Git。

## 实施与验证记录（2026-10-10）

- 已补齐共享渲染谱系内已发布 Run 的确切依赖容器读取。新增正向测试先复现失败，修复后通过；新增隔离和 revision 校验测试均通过。
- 依赖读取、分支新鲜度、包装 domain/service、成片来源刷新及权威来源头共 226 项单测通过；局部更新准备 16 项通过（同文件其他 115 项未执行于该筛选命令）。API 类型检查、备用目录生产 TypeScript 编译和 `git diff --check` 通过。
- 扩大执行成片输出 service 全文件时共 131 项中 6 项失败，涉及整批重新导出的参数/批次与当前工程校验；这些分支不调用本次修改的素材依赖读取实现，本次未改写该输出逻辑。不将该文件记为全量通过。
- 常规 `pnpm --filter @ai-marketing/api build` 因既有 `dist/config` 目录 EBUSY 锁失败；未强制关闭其他进程，改在系统临时目录完成生产 TypeScript 编译。
- 运行中的 API 是 `dist-dev/main` 热更新进程，GET 已确认新依赖读取生效，健康检查正常。测试1的 31 条工程中 18 条待更新，替换及新增集合的 4 个唯一来源全部通过真实只读包装来源/确认事实预检。
- 未执行付费局部更新、包装或输出，不修改项目历史或生成结果；端到端付费成功仍需用户主动确认后验证。
