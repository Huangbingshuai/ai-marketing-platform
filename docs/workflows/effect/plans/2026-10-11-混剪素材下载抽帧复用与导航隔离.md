# 混剪素材下载抽帧复用与导航隔离

## 原因与范围

2026-10-11，广式腊肠项目测试2局部 APPEND 的已记录异常为 Worker 下载素材时的 `httpx.ConnectError`，不能据此断言用户切节点或 API 热重启是原因。页面停用只停止轮询、读取与播放，不发送后台取消请求。

效果类模板混剪消费冻结的已确认 `render-batch`、逐素材 revision/文件及模板槽位。继续按当前 Run/attempt 写入分类、采样和逐成片截取检查点；完整成功由现有 API 校验、原位提交工程，影响后续包装及成片输出。失败不提交、不自动重跑。

## 实施

1. 同一个冻结任务的未完成选材按稳定素材 ID 分组，每种素材只下载、抽帧并记录采样一次，不再为每条组合重复下载源视频。
2. 组内每条成片仍独立调用现有选区逻辑，保留槽位时长、不同截取起点及逐条检查点；不改变分类、组合与付费任务边界。
3. 复用仅限本次冻结快照和 attempt 的临时目录，不跨项目、Run、任务或后续素材版本。已完成截取仍从原检查点恢复，不重新生成。
4. 下载和抽帧沿现有并发上限；失败或取消时等待所有子协程退出再清理临时文件，不残留后台写回。连接恢复沿现有有界下载重试，业务拒绝、文件异常不绕过校验。
5. 增加切节点只停止前台读取的回归测试，不新增自动取消、任务重试或启动行为。
6. 持续下载断连明确显示连接中断及检查点保留，不误报素材内容无效；不改写历史失败任务的错误记录。

本次只读核对：失败任务含 132 次选材、32 条不同素材。新实现同等输入最多下载和抽帧 32 次，减少约 76% 的重复源读取；这是调用量比较，不代表已测得实际耗时提升。

## 验收

- 多组合复用素材时下载/抽帧/采样一次，独立截取和检查点数量不减少；不同素材及不同任务快照不共享。
- 已完成截取保留原起点，未完成项继续独立选区；下载持续失败不调用选区或提交工程。
- 并发有界；失败取消后无迟到选区/检查点，临时文件清理完成。
- 执行 Worker 测试、mypy、前端生命周期测试及差异检查。无活动任务和待消费队列时才更新本地 Worker。
- 不启动或重试真实付费任务、不改写历史失败记录、不自动提交 Git。
