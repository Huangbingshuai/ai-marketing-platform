# 模板槽位配置：解除「智能成片包装后永久锁定」，并删除限制提示

## 用户反馈

> 「把这些限制提示删除，根本就没必要说出来，还有智能成片包装的时候的同一个位置的提示，没必要啊：智能成片包装已完成，模板槽位配置已锁定，音色仍可切换；仍可重新智能填充（会新建分支）；仍可新建并手工精修成片。还有这个鬼锁定模板槽位配置根本没必要啊，我还要让用户自由调整槽位再重新填充啊，请你优化修复bug」

两个诉求：**（一）** 删掉那两处「限制提示」文案；**（二）** 包装完成后模板槽位仍要能改，改完再重新智能填充。

## 根因：包装锁定是「一次性写入、永久生效」的

`packagingLocked` 的取值来自 `packagedTemplateIds()`
（`effect-template-mix-ai.repository.ts:122`）：只要有 **QUEUED/RUNNING 的包装任务** 或
**CURRENT + AVAILABLE 的 `timeline-package:<templateId>` 产物**，该模板就是「已锁定」。
包装成功后产物永久存在，所以这个锁**再也不会解除**。它被三处当成限制用：

| 层       | 位置                                                                                                  | 行为                                               |
| -------- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 前端禁用 | `EffectTemplateMixNodePage.vue:449` `templateEditLocked = projectEditLocked \|\| packagingLocked`     | 模板名、槽位时长、槽位上下移、转场全部 `:disabled` |
| 前端文案 | `:5549`（模板配置面板）与 `:5650`（精修工作台，`packagingLockNotice`）                                | 常驻「模板槽位配置已锁定；…」                      |
| 服务端   | `effect-template-mix.service.ts:902-919` `saveDraft`：`packagingSet.has(id) && templateChanged` → 409 | 草稿保存被拒                                       |
| 服务端   | 同文件 `:2404-2414` `mutate()`：`!allowPackagingLocked && packagingLockedIds.includes(id)` → 409      | `applyVariant`/`refillVariant` 等被拒              |

还有一个更隐蔽的加重项：`packagingInFlight`（`:436-440`）把「状态未知」也算作「正在包装」
（`!packagingRunStatus.value || …`）。而 `packagingRunStatus` 只由精修工作台里的包装组件在
**EDITOR 视图**挂载时上报，**模板配置视图根本没有这个状态** → 恒为 `null` → 恒判为「正在包装」。
于是即便把 `packagingLocked` 从 `templateEditLocked` 里摘掉，配置面板依旧被锁。

**Why:** 重新智能填充（`createAiRun`）早就设计成「落在自己的分支上」，代码注释也写着
「an already-packaged template is not a reason to refuse」。也就是说「包装后不能改模板」这条限制
与下游的分支模型自相矛盾：填充允许，但填充的输入（槽位配置）不允许改。

**How to apply:** 只保留「**正在执行**」的锁（填充在跑、包装在跑），删掉「**已经跑完**」的锁。
已经跑完的产物在自己的 Run 里，改动模板只会让 `needsAiFill` 变 true，从而要求先重新填充再包装 ——
这条既有的、基于内容哈希的护栏才是真正管用的护栏，不需要一把永久锁。

## 改法

### 一、前端：锁只跟「正在执行」有关

`apps/web/src/workflows/effect/template-mix/EffectTemplateMixNodePage.vue`

- `packagingInFlight`：状态未知不再视为「正在包装」——
  `packagingLocked && ['QUEUED','RUNNING'].includes(packagingRunStatus ?? '')`。
- `templateEditLocked` 不再叠加 `packagingLocked`，与 `projectEditLocked` 同源。
- 删除 `packagingLockNotice` 与两处 `v-if="packagingLocked"` 的 `.template-lock-banner`
  （`:5546-5550`、`:5649-5651`）；「正在填充/正在包装」的临时提示保留，否则输入框静默禁用更难懂。
- `packagingLocked` 仍保留：它继续挡住「删除已有包装产物的模板」。

`apps/web/src/workflows/effect/template-mix/effect-packaging-progress.ts`

- 删除 `packagingLockMessage()`（用户引用的那句话就是它 `COMPLETED` 分支的返回值）。

### 二、服务端：允许改配置，只拦「正在执行」

`apps/api/src/workflows/effect/template-mix/effect-template-mix.service.ts`

- `saveDraft`：`packagingSet` 分支只保留 `removedExistingVariant`
  （防止把 `timeline-package` 产物引用的成片工程从草稿里删掉），
  `templateChanged` 不再拒绝；`activeSet` / `activePackagingSet` 的 `workspaceChanged` 原样保留。
- `mutate()`：把包装判断从「有产物就算锁定」换成「**包装任务正在执行**」
  （`activePackagingTemplateIds`），已完成的产物不再挡住 `applyVariant`/`refillVariant`。
  `allowPackagingLocked` 选项与 `createEmptyVariant` 的调用参数因此失去意义，一并删除。

改完的链路：改槽位 → `needsAiFill` 变 true → 包装按钮提示「当前模板或成片仍需重新智能填充」
→ 逐条重新智能填充（落新分支）→ 才能再包装。分支与父产物都保持可回溯。

## 测试

- `effect-packaging-progress.spec.ts`：删掉 `packagingLockMessage` 的断言块，保留
  `emit('status')` 与 `@status=` 的接线断言。
- `effect-template-mix-layout.spec.ts`：`templateEditLocked` 定义、`packagingInFlight` 的
  「未知状态不算执行中」、两处限制横幅已删除。
- `effect-template-mix.service.spec.ts`：把「包装后模板配置保持锁定」改为
  「包装后可以改模板名/槽位时长，只有删除既有成片工程仍被拒」；新增
  「包装已完成的模板可以 `createEmptyVariant`」。

`PACKAGING_LOCKED` 收窄到「正在执行」，本轮把「模板配置」这一层也一并放开，方向一致、无重复实现。

需重新智能填充；重新智能填充后（新分支）可再次包装；精修工作台里包装任务**正在跑**时仍显示临时锁定提示。
