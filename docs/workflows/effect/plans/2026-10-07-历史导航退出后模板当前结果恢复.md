# 历史导航退出后模板当前结果恢复

## 证据与范围

- 效果类模板混剪。真实 API 当前测试1为13条工程、素材差异0；浏览器点击版本树的测试1模板入口却展示创建时0条工程。历史包装入口读取旧5条工程，旧导航继续钉住配置页目录。
- 输入仍为同项目、同渲染谱系已提交素材及模板当前确认路径；局部更新继续覆盖原 Run 的 mix-template 与 timeline-project 工作副本，不开叉。

## 实现与非目标

- 模板目录始终使用现有每模板当前路径算法；历史选择只约束精修工作区，不能把目录改成历史副本。
- 模板配置入口及返回配置释放历史工作区约束，保存当前草稿后读取当前目录和对应工作区；迟到读取沿用既有 scope、AbortController 和草稿写入保护。
- 保留显式历史填充/包装查看和当前分支局部更新。不改写历史成片，不创建任务，不清除真实待更新，不变更 API、契约或数据库。
- 正常切换前的等待保存使用普通请求，不使用页面卸载的 keepalive 请求。实测当前草稿请求体79,997字节，原 keepalive 保存出现 `Failed to fetch`，导致进入或退出工作台失败；卸载路径仍独立保留既有机制。

## 验证

- 导航/目录/返回配置编排回归：模板入口不钉住旧路径，历史精修保留自己的 Run，退出后恢复13条当前工程；普通切换、刷新、跨项目与保存失败不丢草稿。
- Web 类型检查、构建、相关单测及 diff 检查；API只读核对工程数量与来源差异。
- 浏览器复现后验证树模板入口、历史包装返回、各模板切换、刷新及1920/1440/1024宽度。不启动模型任务。

## 实际验收（2026-10-07）

- 11个相关测试文件、155项回归通过，覆盖历史导航消费、目录当前路径、工作区加载、退出保存、素材局部更新及画布状态。
- Web 类型检查和最终生产构建通过；`git diff --check` 通过。构建仍有既有大包体积提示，不影响编译。
- 真实浏览器：从测试1历史包装版本02的5条工程退出，目录恢复当前13条；再次进入和退出工作台、测试1/2/3切换、整页刷新均保持当前13/11/15/0，混剪画布显示就绪。
- 1920、1440、1024宽度检查通过；未启动智能填充、局部更新或包装模型任务，未修改历史确认产物。
- 浏览器证据：`../evidence/2026-10-07-template-current-state-after-history.png`。

## 返回配置等待修正（同日追加）

- 用户进一步说明是点击后很久才返回。代码确认 `leaveEditor` 等待 `syncOutputOnExit`，因此后台待渲染区同步未返回时，配置视图也不能切换；普通本地请求未复现长时间停顿，使用悬而未决的同步 Promise 回归复现该阻塞。
- 返回配置只等待当前编辑 Run 的草稿保存，再显示配置并重新读取当前目录。保存成功仍沿原队列后台同步输出；导航到成片输出继续等待该队列，保存失败仍留在编辑页。不改变任务、工作副本 revision 或局部更新逻辑。
- 先加入回归，旧实现3项失败；修正后7个相关文件91项测试通过。覆盖后台同步未完成即可返回、保存失败不离开、成片输出仍等待同步，以及历史退出恢复当前路径。
- 最终 Web 类型检查、构建和任务文件 `git diff --check` 通过。浏览器当前模板返回301ms、历史包装工程返回277ms；1440/1024/1920宽度分别288/295/297ms，均保留测试1当前13条及列表、画布就绪状态。这是本地实测耗时，不是网络或后台繁忙时的性能保证。
- 证据：`../evidence/2026-10-07-template-return-without-output-wait.png`。浏览器未修改素材或时间轴、未启动付费任务。
