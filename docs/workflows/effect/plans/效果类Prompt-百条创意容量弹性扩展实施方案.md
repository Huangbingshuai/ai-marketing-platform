# 效果类 Prompt：百条创意容量弹性扩展实施方案

## 状态

实施中。

## 背景与目标

当前 50 条、75 条和 100 条批次的创意方向上限都是 24。100 条批次会让每个方向承担过多候选，在事实完整覆盖的情况下仍然会出现场景、主动作和镜头组合重复。

本次只扩展 Prompt 节点的创意规划容量，不改八阶段拓扑、公开结果契约、HTTP 路径、Prisma Schema 和 WorkingArtifact 提交边界。

## 上下游与边界

- 直接上游：已提交的 AI 信息提炼工作副本 revision、事实视觉使用策略、共用提示词和批次设置。
- 当前输出：Prompt 领域草稿和 `WorkflowNodeState`。测试不点击“完成校验”，不覆盖已确认的 `prompt-batch:{productId}`。
- 下游：只有用户完成校验并提交新 revision 后，视频渲染才应待更新。
- Worker 不解释商品语义；只校验来源事实 ID、稳定 ID、数量、结构和哈希。

## 实施方案

1. 创意方向随批次弹性扩展：50 条保持 20 个，75 条调整为 26 个，100 条调整为 32 个。
2. 每个产品专属创意空间平均最多承担 4 个方向。100 条批次因此需要 8～10 个空间，数量不足时由 AI 重新规划。
3. 方向分配继续仅按 AI 产生的 `territoryId + primaryActionId` 做稳定 ID 负载均衡，不使用商品关键词、字符相似度或自由文本规则。
4. 同步放宽内部方向规划与 AI 复核的结构上限至 32，不修改单条 Prompt 结构。

## 验收

- 单元测试覆盖 50/75/100 条的方向数以及空间最小容量。
- Worker pytest、mypy、Ruff 和 `git diff --check` 通过。
- 通过正式浏览器执行一次紫苏梅子酱 100 条×15 秒真实 Ark 付费测试。
- 结果必须精确 100 条，记录空间数、方向数、事实覆盖、硬问题、完全重复和语义重复率，并与原 100×15 秒 63% 重复率基线对比。
- 不调用 Seedance，不自动提交 WorkingArtifact。
