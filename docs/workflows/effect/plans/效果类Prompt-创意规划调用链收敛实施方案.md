# 效果类 Prompt 创意规划调用链收敛实施方案

## 状态

已完成（自动回归与一次真实 Ark 浏览器验收）。

## 目标

在不改变效果类 Prompt 八阶段拓扑、事实充分绑定、无口播素材边界、15 秒时长上限、最终候选数量与质量评估口径的前提下，减少“连贯六维创意生成”前置规划中的模型调用次数和串行等待。

以 10 条、15 秒批次为基准：前置创意规划从真实验收中的约 20 次模型调用收敛到正常路径 6～8 次，完整任务从约 31 次调用收敛到约 14～18 次。大批次继续按结构化输出容量拆分，不能用单次超长响应换取表面上的调用减少。

## 工作流边界

- 直接上游：当前项目、当前商品已经确认的营销洞察 WorkingArtifact，以及本节点保存的数量、时长、风格、渠道和禁用元素设置。
- 当前草稿：生成结果和阶段状态继续保存到 Prompt 领域草稿与 WorkflowNodeState。
- 提交边界：只有用户点击“完成校验”才提交 `prompt-batch:{productId}` WorkingArtifact；本次改造不自动提交。
- 直接下游：视频渲染继续只读取已提交 Prompt 工作副本；确认内容变化后沿用既有 revision 与 stale 规则。
- 非目标：不修改公开 HTTP 路径、Prisma Schema、V6 结果结构、Web 页面或四类用途分类；不调用 Seedance。

## 实现方案

### 1. 创意空间批量复核

- 将当前“每个创意空间一次 AI 调用”改为“整套创意空间一次批量 AI 调用”。
- 复用现有 `CreativeLandscapeAuditResponse`，一次返回全部空间 ID、需调整事实关系和局部修订 ID。
- Worker 仍只校验空间 ID、事实 ID、数量和结构，不解释语义。
- WEAK 继续作为提醒；只有 AI 明确判为 UNSUPPORTED 才进入一次局部修订。

### 2. 多空间方向安全装箱

- 首次方向规划不再固定按单个空间调用，而是按照方向槽位容量把多个空间合并成一个结构化请求。
- 每次最多输出 8 个方向；同一空间过大时仍可拆分，避免 Ark 输出上限截断。
- 每个装箱请求携带自己的稳定方向槽位、必须覆盖事实和允许事实白名单；各箱并行执行。
- 单箱结构或事实覆盖异常只允许一次增量修复，不能重跑已经成功的其他箱。

### 3. 方向复核扩大批次

- 事实与方向关系复核从每批 7 条提高到每批 12 条；10 条任务正常只需一次关系复核。
- 全批视觉重复复核继续保留一次，因为它负责跨箱判断，不能由 Worker 的字符规则替代。
- AI 点名的问题方向最多进行一次局部修订；修订后不再重复整套语义审核，仅保留结论供后续候选质量评估参考。

### 4. 调用与耗时观测

- 阶段元数据记录空间规划、事实分配、空间复核、方向规划、方向关系复核、全批重复复核和局部修订的调用次数。
- 仅记录计数、Token 与耗时，不记录模型输入、原始响应、事实 ID 或内部 Prompt。
- 阶段详情继续展示既有安全摘要，结果和用户感知拓扑不变。

## 测试与验收

- 批量空间复核必须完整覆盖所有空间；未知、重复或遗漏 ID 被拒绝。
- 10 条任务的 8 个方向能够合并为一个方向规划箱；50/100 条按最多 8 个方向安全拆分。
- 每个方向槽位、主动作、必须事实和允许事实仍保持正确，失败只重试当前箱。
- 方向关系复核按 12 条拆分，全批重复复核仍只执行一次。
- Mock 测试断言 10 条正常路径的前置规划调用次数显著下降，生成候选数、最终数量、事实覆盖和质量状态不变。
- 执行 Prompt Worker pytest、mypy、Ruff 和 `git diff --check`。

## 兼容与风险

- 历史检查点继续读取；模板哈希变化后当前新 Run 自动重新规划，不跨 Run 复用旧计划。
- 批量复核输出变大，但最多 10 个空间，仍显著小于候选 Prompt 和质量评估响应。
- 大批次方向继续受每箱 8 条上限保护；不通过提高 Token 上限掩盖结构问题。

## 实施与验收结果

2026-09-07 使用正式浏览器链路对“紫苏梅子酱”执行了一次 10 条、15 秒真实 Ark 批次。没有调用 Seedance，也没有点击“完成校验”。

- Run 第一次任务尝试即完成，未发生 JSON 截断、格式异常、超时或业务重试。
- 完整任务耗时 413.1 秒；改造前同商品、同数量和同时长基线为约 473.9 秒，缩短约 60.8 秒（12.8%）。
- Ark 调用从基线约 31 次降为 19 次，减少 12 次（38.7%）。其中前置创意规划实际为 7 次，进入计划的 6～8 次目标范围。
- 完整调用比原估计的 14～18 次多 1 次，原因是系统按既有策略执行了一轮必要的多样性补充，并非重复规划或失败重试。
- 结果严格为 10/10 条且全部为 15 秒；10 条均为 `VERIFIED`，完整重复数与语义重复率均为 0。
- 五项平均分分别为：产品相关性 95.0、创意连贯性 93.1、画面可执行性 92.6、商业素材价值 89.6、视觉表达清晰度 93.7。相对旧批次整体波动约 1 分以内，没有出现因调用收敛导致的明显质量下降。
- 33 项必需事实覆盖 27 项、仍缺 6 项，因此草稿保持 `NEEDS_REVIEW`；这与旧基线相同，未通过放松提交边界掩盖问题。
- 浏览器刷新后可恢复新生成的 10 条结果，运行中设置只读、完成后恢复可编辑；已提交 WorkingArtifact 未被自动覆盖。
