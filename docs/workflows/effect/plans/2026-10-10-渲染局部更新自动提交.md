# 渲染局部更新自动提交

## 范围与边界

效果类片段渲染消费已确认 `prompt-batch:{productId}` 的具体 revision 和资料包；沿用隔离 MANUAL Run、任务快照、Outbox、租约和原位合并事务。局部更新完整成功且通过来源/文件/结构校验后自动提交 `render-clip:{taskId}` 与 `render-batch:{productId}`，不新增版本分支、不自动运行混剪或输出。

显式人工编辑（导入、删除、返修采用等）仍由用户保存。已有人工编辑时先保存或取消，再执行自动局部更新，防止将无关修改一起提交。新增专用编辑元数据标记，不迁移数据库结构；历史冻结草稿不因升级被自动采用。

## 实施

- 局部更新事务记录自动提交批次标识及冻结来源；付费任务完成、免费信息同步/移除后均尝试校验提交。
- 轮询恢复中断的自动提交，重新读取提交后的记录；重复回调不重复推进 revision。
- API 返回自动提交中及已采用分支定位，前端自动返回原分支，更新提示不再要求手动保存。
- 自动更新期间禁止混入人工素材修改；部分失败保留草稿与旧文件，只能重试差异或明确取消。
- 更新期间再次变化的 Prompt 不覆盖已冻结来源；采用结果后仍展示真实剩余差异。
- 广式腊肠 R-001 已成功草稿通过既有 validate 原位合并，核对文件、来源与父批次基线后执行；不创建任务或 Outbox。

## 验收

单测覆盖自动/手工边界、免费更新、失败、删除、来源二次变化、重复回调与轮询恢复；事务测试覆盖原位合并、兄弟分支隔离和 revision 幂等。执行 Contracts/API/Web 类型检查及相关构建、`git diff --check`，浏览器核对原分支素材与待更新提示。不执行付费生成。
