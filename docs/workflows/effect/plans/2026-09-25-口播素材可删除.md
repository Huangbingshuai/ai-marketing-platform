# 口播素材可删除：只删配音，保留脚本行与字幕（第五轮）

承接 `2026-09-25-字幕自由拖动与音频素材删除.md`。上一轮让字幕口播、纯音乐、分离音频都能删，**唯独脚本行口播删不掉**：

> 「这口播素材根本删除不了：口播由脚本行生成，不能删除；可在音频行上静音」
> 「给我完完全全移除这些限制」

## 产品口径（本轮确认）

1. **字幕与口播只是时间对齐，不是绑定**——「字幕肯定要保留啊，不要做这些绑定啊，就只是字幕和口播对齐而已，和剪映的一致」。删一条口播**不删字幕、不删脚本行**，只删那一条音频。
2. **重新包装全部重新生成**——「重新包装全部成片的口播、字幕、纯音乐都全部重新生成」。因此**不需要**任何持久化的「这条没有口播」标记。
3. 行静音的持久化**这轮不动**。

## 一、删不掉的根因：`ready` 检查点三层互锁

限制不是 UI 的一时之快，而是 `ready` 检查点不变量的直接投影（`effect-packaging.domain.ts`）：

| 层     | 要求                                 | 出处（改前）                                                              |
| ------ | ------------------------------------ | ------------------------------------------------------------------------- |
| 脚本行 | 每条非叠加层片段都要有一行           | `:444` `slots.size !== clips.filter(!overlay).length`                     |
| 配音   | **每一行都要有一份配音**             | `:642` `script.some((s) => !voices?.[s.id])`                              |
| 字幕   | 每一条都要挂在一行上、并与其配音对齐 | `:544` `(!manual && (!script \|\| !audio))`、`:563`/`:567` `audio!.start` |

删掉 `voices[lineId]` 立刻让第二、三层非法，所以服务端只能拒绝。

**修**：把 `voices` 从「每条脚本行必备」降级为「脚本行的可选覆盖层」。只放宽这一种状态，其余不变量（行数 == 非叠加层片段数、字幕数 == 行数、模板槽位不许重叠、时长与编号）**原样保留**——因为脚本行与字幕都留着。

- `:544` → `(!manual && !script)`：字幕仍必须挂在一条已知脚本行上，但不再要求那行有配音。
- `:563`/`:567` 的 `audio!.start` 加 `audio &&` 前置：这是**防崩**而非放开。否则 `edited=false` 的 worker 写入路径遇到缺配音会抛 `TypeError`（500）而不是干净地跳过对齐校验。
- `:599` 帧对齐校验 → `(captionsV3 && audio && (…))`：字幕分句与 PCM 帧的对应只在配音还在时才有意义。
- `:642` **删掉** `script.some((s) => !voices?.[s.id])` 这一条——本次限制的根源。
- `:648` → 「**如果**配音存在，它必须带 `segmentFrames`」。
- `canonicalizeCheckpoint` 不用改：它按 `checkpoint.voices` 的现存键遍历，缺的键自然不参与，局部重做不会凭空造回一条配音。

## 二、顺带修一个线上 400

`removedCaptionVoices` 与 `removeMusic` 在契约（`effect-template-mix-packaging.ts:168,170`）、服务（`effect-packaging.service.ts:541,546,570,626`）、编辑器（`EffectTemplateMixNodePage.vue:1657-1661`）里都在用，**却没有出现在 `UpdatePackagingAudioDto`** 上，而 `main.ts:26-32` 是 `whitelist: true, forbidNonWhitelisted: true` —— 也就是说上一轮做的「删纯音乐 / 删字幕口播」在浏览器里一直是 **400**。服务端单测全绿是因为它们直接调 service，绕过了全局 pipe。

**修**：DTO 补 `removedVoices` / `removedCaptionVoices` / `removeMusic` 三个字段，`removedVoices` 与 `removedCaptionVoices` 用 `@IsArray() @IsString({ each: true }) @Matches(/^[a-zA-Z0-9_-]{1,80}$/u, { each: true })`，只查形状——未知 id 由服务忽略（删一条被并发重做已经丢掉的配音是正常竞态）。

## 三、删除通道

删除无法用几何 diff 表达（没有片段可发），所以每种能删的东西各有一条通道：

```
voices          →  removedVoices: string[]        （本轮新增，键为脚本行 id）
captionVoices   →  removedCaptionVoices: string[] （上一轮，本轮补 DTO）
music           →  removeMusic: true              （上一轮，本轮补 DTO）
```

`updateAudio` 里删除**先于**编辑，且同 id 同时出现时**编辑胜出**（与 `removeMusic && !body.music` 的既有取舍一致）：

```ts
if (body.removedVoices?.length) {
  voices = { ...(old.voices ?? {}) };
  for (const id of body.removedVoices) if (!body.voices?.[id]) delete voices[id];
}
if (body.voices) {
  voices = { ...(voices ?? {}) };   // ← 从删除后的 map 拷贝，不再回到 old.voices
  …
}
```

`if (body.voices)` 分支原本从 `old.voices` 重新拷贝，会把刚删的键**又捞回来**；改成从 `voices` 拷贝，一次请求才能既删一条又移另一条。

## 四、Worker：一行都不用改

逐条核实过，缺一条配音在 worker 侧是完全正常的状态：

- `final_output.render` 按 `cp['voices']` + `captionVoices` **实际存在的键**拼混音、按实际条数算 `amix` 输入；`captions_ass` 只遍历 `cp['captions']`。所以缺一条配音天然可渲染。
- `synthesize`（`packaging.py:616-617`）只跳过已在 `voices` 里的行，`:696` 对 `cp['script']` 全量并发调用；缺配音的行在重新包装时会被重新 TTS，正是用户确认的语义。**任何一条合成失败都会在 `:700-701` 直接抛出**，所以走到字幕重生成分支（`:734`）时 `voices` 必然是满的，`:747` 的 `voices[line['id']]` 不会 `KeyError`——曾经想加的 `.get()` 兜底是不可达的死代码，已放弃。
- 字幕重生成分支的守卫是 `{c.voiceLineId} != {line.id}`；字幕留着、`voiceLineId` 未变 → 集合仍相等 → 分支整体跳过。

因此**本轮不改 worker 源码，也不需要重建 effect worker 镜像**。

## 五、编辑器

- `deleteSelectedAudioClips`（`EffectTemplateMixNodePage.vue:4112`）：`voiceSelected` 布尔量改成 `voiceIds` 集合，`removesVoice` 与 `removesCaptionVoice` 同构；在既有的 `editPackagingAudio` 回调里加 `delete next.voices?.[id]`。拒绝分支只剩 legacy `voice` / 未知 id，提示统一为「该音频片段不能删除」——「口播由脚本行生成，不能删除；可在音频行上静音」这句话从代码里消失。
- `audioDiff`（`:1536`）加 `removedVoices` 键集 diff，并入「全空返回 null」判断与返回对象。
- `flushAudioEdit`（`:1662`）透传 `removedVoices`。
- 配音片段从音频行消失是自动的：音轨由 `checkpoint.voices` 的键派生（`effect-template-mix-audio-lanes.ts:98`）。`rememberTimelineEdit()` 保证一步撤销。
- 行静音（`audioRowMuted`）不动。

## 六、非目标

- 不做持久化「无口播」标记：不动变体槽位、不动 `packagingVisualTimeline`（视觉哈希不变 → 已确认包装不会因此变陈旧）、不强制重新包装。
- 不改行静音的持久化。
- 不改 `packaging_media.py` / `final_output.py` / `captions_ass`。
- 不改模板槽位之间的重叠不变量、时长 4–15 秒、槽位编号唯一。

## 手动验收（广式腊肠项目 `65458686-034c-4258-b2dd-027d4ad15132`「测试4」模板）

1. 选中一条口播按删除 → 不再弹提示，音频行上该片段消失，**对应字幕条与其余口播一动不动**。
2. 刷新页面 → 删除已持久化：`checkpoint.voices` 少一个键，`script` 与 `captions` 逐条不变。
3. 撤销一步 → 口播片段回来。
4. 触发成片渲染 → 该段没有口播与闪避，**字幕照常出现**，成片时长与其它片段不变。
5. 重新包装 → 被删的口播、字幕、纯音乐全部重新生成。
6. 回归：删纯音乐、删字幕口播不再 400；删普通视频素材、拖字幕、模板槽位重叠拦截等既有行为不变。

本轮不动 worker，所以**不需要重建 effect worker 镜像**；只有 `apps/api` / `apps/web` / `packages/contracts` 需要重新构建或重启。
