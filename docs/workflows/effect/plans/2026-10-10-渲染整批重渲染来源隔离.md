# 渲染整批重渲染来源隔离

## 范围

- 视频渲染节点顶部“局部更新”移到操作区最左侧，并复用后续节点黄色局部更新按钮的视觉语义。
- 渲染期间复用混剪节点的共用进度组件，以黄色进度条持续显示整体进度，并在右侧展示完成数与异常数；人工导入视频不计入生成任务进度。
- “全部重新渲染”统一改名为“重新渲染”。
- 整批重新渲染只读取当前分支最新、已确认的 Prompt 工作副本及当前渲染设置，在新子 Run 创建全新渲染批次。
- 新子 Run 不继承旧渲染批次、逐片工作副本或外部导入视频；外部导入素材只保留在原分支。

## 非目标

- 不改变 Prompt 条目的来源语义；Prompt 节点内人工新增且已确认的 Prompt 仍是合法渲染输入。
- 不改变局部更新、单条重新生成、外部导入素材返修与重新生成流程。
- 不自动发起 Seedance 任务，不迁移或删除历史分支文件。

## 数据与并发边界

- 创建 BATCH 子分支时只继承资料导入、信息提炼、Prompt 及渲染设置；不采用历史渲染来源头，也不复制旧渲染领域记录和 `render-*` 工作副本。
- API 在子 Run 内重新读取 `prompt-batch:<productId>`，校验 `CURRENT + AVAILABLE + expected revision` 后，逐条编译任务快照；前端数量或旧批次任务不能成为权威输入。
- 新批次任务集合必须与该 Prompt 工作副本条目集合一一对应，任务快照不得含 `importedMaterial`。原分支和历史文件保持可回溯。

## 验证

- Web 源码回归按钮顺序、名称和黄色样式，执行相关单测、类型检查及浏览器多宽度回归。
- API 单测断言子 Run 内读取的最新 Prompt revision、任务 ID 集合和无导入素材快照。
- 分支策略单测与可选数据库测试断言 BATCH 子分支不复制任何渲染批次/任务/工作副本；MANUAL 编辑仍保留原复制行为。
- 执行 `git diff --check`；不触发真实付费生成。
