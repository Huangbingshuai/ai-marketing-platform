# 混剪画布待更新一致性修复

## 范围与问题

效果类第五节点消费已确认的渲染素材池；智能填充及局部更新成功后原位确认
`mix-template:<templateId>`、`timeline-project:<templateId>:<variantId>`，包装另确认
`timeline-package:<templateId>:<variantId>`，最终输出消费对应工程。
本次只修复展示投影，不改变提交边界、revision、工程、任务或历史分支。

模板列表通过 `effectTemplateMixSourceChanges` 判断工程差异，并单独统计待追加素材。
画布目前又将版本树通用 STALE 状态与目录数量取最大值，导致已同步的目录无法清除旧警告。

## 实施

- 共用 `EffectTemplateMixSourcesData` 向后兼容增加每模板 `pendingProjectCounts`。
- API 用原有同项目、同 Run 的来源比较计算各模板数量，保留原聚合字段。
- 画布按既有 `effectTemplateBranchTips` 解析各模板当前路径，仅消费该模板数量与新增素材；
  不把同 Run 里其它模板或历史兄弟分支的聚合数量重复带入。
- 完整目录投影（包含零）及完整当前路径来源投影优先于通用历史 STALE。
  无完整投影的旧 API 保守回退；读取失败不清除已知状态。
- 切换作用域、并发读取、编辑父 Run、旧响应迟到、自动更新后的重新读取保持隔离。

## 验收与非目标

单测覆盖目录零清除旧 STALE、真实另一模板待更新、同 Run 历史模板不串计数、
两轮变化、目录回报期间迟到请求、读取失败及切换作用域；API 验证每模板与聚合一致。
执行相关 Web/API/Contracts 单测、类型及构建检查、diff 检查，浏览器检查刷新与模板切换。
不创建付费任务，不自动同步兄弟分支，不清空数据库 STALE，不修改版本树历史节点的业务含义。
