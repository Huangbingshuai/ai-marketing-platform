# 局部更新跟踪与实时归槽

## 范围与边界

效果类模板混剪继续只用一个黄色“局部更新”按钮和一条同名进度条。右侧增加真实阶段及已完成数量；不增加取消、详情或第二个任务入口。

直接输入仍是同项目、同效果类 Run 已提交的 Prompt / render-clip 工作副本及冻结 revision。只改变已有任务检查点的读取与展示，不生成第二套状态，不修改现有成片，不提交 WorkingArtifact，不改变 mix-template / timeline-project 确认及下游待更新边界。

## 数据与实现

- 复用 Worker 逐批保存的 classificationResult、既有 AI Run stageDetails 与轻量 sources 接口，无新增 DTO、表或数据迁移。
- sources 可展示当前 Run 正在执行 APPEND 的有效分类检查点；失败、取消、其他 Run、普通重新填充的中间结果不参与此投影。
- 中间结果必须匹配当前模板版本、槽位时长及素材文件/revision/指纹；历史已完成归槽作为未收到新检查点素材的回退，已有人工覆盖仍优先。
- 局部更新进度轮询同步 sources，不等待整个归槽、匹配、抽帧、截取流程完成；切换作用域或请求失败不得清空素材库或覆盖用户草稿。
- 新素材只能进入时长不超过其素材时长的槽位。重新智能填充全量重新归槽、局部更新保留旧工程并追加成片及按原规则包装均不改变。
- APPEND 归槽计数只统计冻结 incremental.materialIds 中本次新增的素材及其去重检查点，不使用整个素材库数量。阶段提示分别标明“已归槽 X/Y 条新增素材”“已抽帧 X/Y 条素材”“已处理 X/Y 个镜头”；组合和保存阶段不展示内部 0/1 检查点。百分比继续表示真实整体进度，不从阶段计数反推。
- 全局局部更新进度复用 WorkflowRunProgress 的 update 色调：混剪及当前分支成片更新统一黄色进度、深黄色文字和浅黄色底框；普通智能填充、包装和整批导出保持默认蓝色，不改变可见性或任务状态。
