# 效果类 Prompt：语义重复度评估与展示改造计划

状态：已完成

## 目标

- 在“创意评估与用途分类”阶段统一生成正文向量和批次语义重复评估。
- 以相似度不低于 82% 的连通重复组计算冗余条目，`重复条目数 / 最终条目数` 必须严格低于 15%。
- 评估结果供数量择优、定向补充、完成校验和结果页面共同使用，不恢复用户可调阈值。
- 复用同一批次向量，人工编辑只重新计算变化条目；历史结果缺少可信评估时显示“待评估”。

## 边界

- 直接上游仍为已确认的营销洞察和全局视频配置工作副本。
- 生成、评估和人工编辑只更新 Prompt 节点草稿；只有完成校验后提交 `prompt-batch:{productId}`。
- 不修改效果类第 4～6 节点，不改变共用提示词、统一时长或六维连贯创意生成语义。
- 不新增 Prisma 表或生产依赖，内部语义审计数据使用现有任务阶段元数据保存，公开接口仅返回聚合指标。

## 实施要点

1. Contracts 增加固定阈值与 `semanticEvaluation` 聚合指标，并兼容缺少该字段的历史结果。
2. Worker 在逐条质量评估后构建向量索引，筛选复用索引；最终按连通分组计算重复条目比例。
3. 重复度达到或超过 15% 时执行一次多样性补充，仍不合格则保存 `NEEDS_REVIEW` 草稿。
4. API 使用内容指纹验证评估新鲜度，完成校验阻止待评估或超标批次。
5. 页面工具栏、评估节点、择优节点和结果保存节点展示安全化重复度统计。

## 验收

- 50 条中 7 条重复为 14%，允许通过；8 条为 16%，必须复核。
- 恰好 15% 不得通过；相似组按 `n - 1` 计数，不按组内配对数放大。
- 产品名称、品类、共用提示词和渲染参数不造成误判。
- 向量失败不产生虚假 0%；历史结果显示待评估。
- 人工新增、修改、删除和单条重生成后，重复度与完成门禁保持一致。

## 实施结果

- Contracts、JSON Schema、Pydantic、Worker、API 与 Web 已统一增加 `semanticEvaluation`；历史结果缺少该字段时由 API 投影为“待评估”，不伪造 0%。
- Worker 在“创意评估与用途分类”节点生成正文向量索引，精确择优直接复用同一索引；相似度达到 82% 的边按连通分量聚合，每组按 `n-1` 计数。
- 50 条的严格上限为 7 条重复；达到或超过 15% 时执行一次多样性补充，仍超标则保存 `NEEDS_REVIEW` 草稿并阻止完成校验。
- 结果保存阶段只持久化正文哈希、内容指纹和重复关系边，不保存正文副本或向量。删除条目可用可信审计关系重算；新增或正文变化会恢复为待评估；共用提示词和不改变正文的编辑保留原语义评估。
- 页面工具栏展示“计算中 / 待评估 / 符合要求 / 需要优化”，工作流详情同步展示评估数量、82% 标准、重复组、重复条目和最终比例。

实际验证：

- Contracts：17 个测试通过，构建通过。
- Worker：82 个测试中 81 个通过、1 个需显式 Ark 配置的集成测试跳过；mypy 严格检查 16 个源文件通过。
- API：31 个测试文件、228 个测试通过；全量类型检查与 Prompt 相关 ESLint 通过。
- Web：29 个测试文件、152 个测试通过；类型检查和生产构建通过。
- `git diff --check` 通过。
- 当前环境未安装 Ruff，因此未执行 Ruff；重新生成本地 Prisma Client 后，API 全量 TypeScript 类型检查通过。
- 浏览器已连接真实“广式腊肠”项目并从页面发起 50 条付费验收；运行中工具栏正确展示“正在计算语义重复度”。本轮在完成 70 条真实候选后由用户中止，系统以 `TEST_STOPPED` 终止，因此没有伪造最终重复度，也没有把部分结果提交为工作副本。
- 真实候选对比：旧批次 50 条和新候选 70 条均为 100% 商品语义锚定；新候选 70 条正文全部唯一，形成 69 条不同创意主线、61 种镜头表达和 35 种人物表达。新候选的规范场景为 11 类，说明商品相关性与创意主线明显稳定，但场景维度仍是下一轮完整验收需要重点观察的方向。
- 联调发现并修复历史“事实视觉策略”检查点字段与当前 Worker 严格契约不一致的问题：API 现在只下发哈希和计划结构均可验证的检查点，旧 `promptVersion` 检查点会被忽略并重新计算，不再阻塞新批次认领。
- 最终数值标签的达标、超标和待评估状态已由页面结构测试、状态单元测试与生产构建覆盖；由于本次付费运行被用户中止，浏览器未产生可宣称为可信的最终重复度数值。
