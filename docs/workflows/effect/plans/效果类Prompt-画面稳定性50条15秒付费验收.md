## 范围与预算

用户授权最多 20 次真实付费批次，本次按 50 条 × 15 秒执行，仅生成 Prompt，不渲染视频。先使用上次存在画面故障的紫苏梅子酱，比较同商品、同上游、同设置的生成结果。生成和评估继续使用现有 Turbo 模型。

真实请求经过公共 API、Outbox、RabbitMQ、Ark Worker 与 API 持久化。测试不点击完成校验，不提交或覆盖有效 WorkingArtifact。完整快照与计数账本保存在 Git 忽略的 `.tmp/prompt-stability-paid-20260909/`，本文仅保存脱敏结论和必要短证据。

## 对照方法

- 机械统计：最终数量、平均正文长度、节拍数量、AI 五项评分、向量重复度、耗时与调用失败。
- 人工逐条审查：动作负担、多人操作、工具与物体因果、跨镜连续性、精确物理承诺、无口播产品价值及实质同质化。
- 语义审查仅用于离线质量报告，不加入 Worker，不使用产品关键词计数冒充语义结论。
- Prompt 文本质量改善不能直接证明视频故障率下降，本轮没有视频对照。

第二轮在浏览器展开 50 条并逐条阅读最终正文，以下是代表性问题而非自动关键词判定：

- P003：瓶子自转时相机同步环绕，又要求瓶肩、侧面依次展示；相对运动关系不清，可能抵消展示角度变化。
- P038：手推动瓶子自由旋转，要求恰好停在正面；同时写“固定机位”和向前推近，仍有不必要的精准物理和镜头歧义。
- P015、P021、P042：一勺或少量刮刀酱需要依次完成五六个精确落点；工具补料、动作预算没有交代清楚。
- P017、P043：分别要求十秒完成六碟分酱、五秒完成六碟基础分酱；三拍缩减建议未解决路线中串联的多次完整动作。
- P019、P034、P036：三碗淋酱、三串刷酱、四人轮流舀酱仍放在一条素材，主体、容器和操作切换偏多。
- P014：直接从商品玻璃瓶连续淋出粗细均匀的螺旋细线，仍把精细摆盘效果当成必然物理结果。
- P032、P039：要求酱体细长拉丝、回缩或持续不断；是否具备这样的材料行为仍需真实依据，浓稠不能自动推出长丝弹性。
- P029：正俯固定终帧要求同时清楚看到肉片正反两面，呈现要求冲突。
- P008：首帧先称卡扣空置，又让手取下卡扣前的空瓶；包装与收纳器具适配性也被写成确定优势。
- P024：开盖商品瓶横放，缺少合理支撑与防洒安排；P012 无门柜在结尾变成柜门敞开，存在跨段状态漂移。
- P001、P016、P023、P030 的核心动作相对明确，但“均匀完整覆盖、不滴落、边界平直”等结果承诺仍偏精确；简单并不自动等于广告表现更好。

第二轮两项未覆盖标签为“适合烤肉、沙拉与冷菜搭配”和“需要蘸食、拌菜和刷烤多用途”。正文中实际存在这些类别的不同用法，所以不能将该指标直接解释为整个批次没有使用这些信息；复合事实的绑定与批次覆盖口径仍需单独检查，不能通过强迫单条拍全多种用法来解决。

目前只证明正文更短、平均节拍更少；没有证明可执行性、商业价值或视频故障率得到明显改善。两轮人工核查均发现残留问题，第二轮质量未达预期。已使用 2/20 个真实批次额度，第二轮自动恢复计入该批次并产生额外调用成本；不继续用剩余额度重复验证同一模板。

下一步建议优先处理源头指令的优先级：创意路线描述营销意图，正文生成允许保留意图但简化高风险动作；多用途用批次表达，不要求单条完成全部操作。应削减路线中精确材料表现、多个细小落点及多人轮流操作，并允许镜头创作选择一种清楚的主体/相机相对运动，而不是叠加更多机械门禁。Worker 仍只做确定性结构工作，不判断语义。以上进一步改造尚未实施。
