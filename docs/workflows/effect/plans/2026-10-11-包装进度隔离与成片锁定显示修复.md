# 包装进度隔离与成片锁定显示修复

## 范围与依据

效果类模板混剪节点内的包装任务。直接输入仍为所选模板真实 Run 中已保存的画面工程与已确认素材依赖；成功事务提交 `timeline-project`、`timeline-package`，下游成片输出不自动编码。

只读核对测试1实际任务后，发现仅有 `BATCH_PACKAGE`，没有误建单条任务。单条按钮使用了任意操作类型的当前条目；成片编辑锁已经生效，但轨道的锁图标只读取旧的整工作区包装锁，未读取逐成片任务锁。

## 实施

- 单条绿色进度只接收 `SINGLE_PACKAGE` 活动条目；整批、追加及历史无操作字段的任务不得显示单条进度。整批蓝色进度沿用现有逻辑。
- 时间轴轨道锁与成片编辑锁共用当前成片的排队/运行状态，不能手动解除任务锁；不改写手动锁标记。`RUNNING + READY` 仍保持锁定。
- 首条完成后进入同一任务的子 Run 时，保留已知任务快照与逐成片锁，避免重新发现任务前出现可编辑空档；跨项目、跨模板及无关 Run 不继承该快照。
- 成功提交解锁；最终失败/取消保留包装前内容并解锁，继续允许单条包装或人工编辑，不新增永久失败锁。
- 不改变后台任务、重试、分支和提交协议，不启动付费任务，不重启运行中的 API，不自动提交 Git。

## 验证

- 覆盖整批/单条操作隔离、提交中、排队、运行、READY 未提交、所有终态及手动锁保留。
- 覆盖同任务子 Run 交接与无关作用域清理。
- 执行相关 Web 测试、类型检查、构建与 `git diff --check`。
- 浏览器只读/拦截写入回归 1920、1440、窄屏；不创建真实包装任务。

## 执行记录

- 前端修复单条进度操作类型筛选、逐成片轨道任务锁、整批提交即锁定，以及同一包装任务进入子 Run 时的快照交接；后端与 Worker 本次未修改。
- 包装相关测试及来源更新测试共 120 项通过；覆盖 `RUNNING + READY`、终态移除、失败后可编辑、跨作用域清理与手动锁保留。
- Web 类型检查及生产构建通过，构建仍有既有的大包提示；`git diff --check` 通过。
- 浏览器回归使用正式单条控件及时间轴组件，写请求拦截；1920、1440、720 下整批无绿色单条进度、单条任务有进度，运行时三个轨道均锁定且不能手动解锁，成功/失败/取消后进度消失并解锁。该回归是受控状态测试，不是新付费任务端到端验收。
