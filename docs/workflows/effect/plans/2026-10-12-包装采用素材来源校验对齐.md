# 包装采用素材来源校验对齐

## 范围与证据

- 效果类模板混剪节点内的包装快照创建；复用 `artifactVisitor`，不新增状态、接口或任务。
- 测试1智能填充已完成，当前有45条工程；包装创建被“包装来源工作副本已失效”拦截，没有包装任务受理。
- 已确认渲染素材携带哈希校验的 `adoptedPrompt`；其显式依赖的历史 Prompt 批次为 STALE，但所依赖的商品事实 revision 1 仍 CURRENT / AVAILABLE。
- 现有包装逻辑已不消费可变 Prompt 批次正文及 revision，却仍要求该批次 CURRENT，与素材采用快照的规则冲突。

## 实施边界

- 仅对具有合法采用正文哈希的渲染片段，允许通过仍 AVAILABLE 的显式 Prompt 来源读取商品事实依赖，不以该批次 freshness 拒绝。
- 商品事实及资料来源继续递归校验可用性、新鲜度和实际 revision；没有采用快照的旧素材仍走原严格校验。
- 不改变任何 WorkingArtifact、revision、文件、分支、锁定或自动重试语义。不替换成其它兄弟分支的 Prompt/事实，不删除校验或只隐藏错误。
- 输出仍为 `timeline-project:<templateId>:<variantId>` / `timeline-package:<templateId>:<variantId>`，逐条事务提交及下游成片输出规则不变。
- 当前直接来源由工程绑定的素材 artifact/revision 与其明确事实依赖决定，而不是跨副本 revision 大小。

## 验证

- 覆盖历史 Prompt STALE、连续修改、无采用快照、非法正文哈希、不可用 Prompt、商品事实缺失/过期/revision 改变及兄弟隔离。
- 可选只读集成测试从本地 API 读取指定项目/Run，逐条构造真实工程包装快照；不创建 Run、任务、Outbox 或付费请求。
- 执行包装 Domain / Service / Repository、渲染采用快照及成片输出相关测试，API 类型检查、构建和 `git diff --check`。
- 修改前核实没有活动生成任务；确认开发 API 热更新实际生效。不以构建代替运行验证，不主动启动付费整批包装。

## 非目标与迁移

不修改 Web/Contracts/Worker，不新建数据库表，不批量清除 STALE，不自动重启旧失败任务，无数据迁移。

## 实测结果（2026-10-12）

- 修复前，新增单测与测试1只读集成测试均在历史 Prompt freshness 检查处复现相同错误；修复后均通过。
- 6个测试文件共358项通过：包装 Domain、Service、Repository、只读来源集成、渲染采用快照、成片输出 Service。
- `pnpm --filter @ai-marketing/api typecheck`、`pnpm --filter @ai-marketing/api build`、`git diff --check` 通过。
- 活动任务只读检查无排队/执行中的生成任务；现有标准开发进程自动热更新，已核对新进程与 `dist-dev` 修复代码。用该运行构建的快照函数读取真实 API 数据，45条工程、270个画面全部通过来源校验。
- 没有创建包装任务、Run 或 Outbox，没有调用收费供应商；未执行完整付费包装端到端，未修改前端布局。
