# 版本树视觉与浏览优化

## 范围与验收

用户明确要求继续优化版本树美观度，并借鉴开源项目。保留项目与首个导入节点垂直、原始主干垂直、兄弟分支按创建顺序向右展开。仅修改现有 Web 组件和显示几何，不改业务状态、版本归属、活动指针、局部更新或工作副本。

1. 紧凑的节点和层间距，减轻背景分区和阴影；现有红色当前路径及黄色待更新语义不变。
2. 卡片以标题、创建时间、当前位置/待更新形成信息层级；提供完整可访问名称，不增加重复状态面板。
3. 现有工具栏增加查看全图、定位当前和缩放。纯本地视口状态，不触发 API 写入、分支切换或付费任务。缩放后节点和连线及左侧层级保持同一坐标比例。
4. 加载、空、错误、禁用、已完成、待更新沿用现有处理。焦点锁定、ESC 关闭和焦点恢复继续有效。

## 借鉴与取舍

- Vue Flow：官方示例的缩放/视口控件、自定义节点及 smoothstep 连线模式，https://vueflow.dev/examples/ ，MIT。
- AntV X6：HTML/SVG 自定义节点及图谱展示能力，https://github.com/antvis/X6 ，MIT。
- ELK：分层图布局，https://github.com/kieler/elkjs 。本次不采用自动重排，避免违背主干与创建顺序要求。

本次复用设计模式，不拷贝第三方源代码、不引入图编辑引擎。现有 SVG+Vue 已支持固定八绘图层与业务导航，引入引擎并不能直接解决信息密度和视觉问题，反而会扩大本次验证范围。后续若确需自由拖拽或超大图，再评估引擎。

## 数据接口与迁移

无 API/Contracts/Worker 变更，无数据库迁移。输入继续是 EffectWorkflowBranchTreeData，点击版本继续使用 effectBranchDestination。缩放与滚动只作用于当前弹窗，关闭即销毁。

## 测试

补充纯函数视口计算测试，检查有限缩放范围、适应全图、中心保持及定位当前。运行现有版本树、画布与导航相关测试、Web 类型/构建及 diff 检查。正式浏览器检查 1920、1440、窄屏，验证初始主干、全图、缩放、定位当前及 ESC。

冻结原型没有版本树区，且本地 file URL 浏览器检查不可用；以现有组件、真实页面和用户明确要求作为本次设计边界，不声称像素还原。

## 第二轮：专业画布与模板谱系分区

用户反馈第一轮仍过于普通，授权继续学习开源项目优化 UI。参考 Dify 的类型图标/卡片层级及 React Flow Turbo Flow 的定制节点与强调描边，使用浅色专业画布方向；不采用与整个平台割裂的发光暗色默认主题。参考官方页面：https://github.com/langgenius/dify 、https://reactflow.dev/examples/styling/turbo-flow 。只学习设计模式，不复制源码，特别不将第三方业务状态引入项目。

本轮范围：类型图标+左对齐版本卡、深色项目卡、柔和画布层级、按真实树连线归属的模板背景分区、当前节点更明确的视觉焦点。既有全图/缩放/定位沿用。主干垂直、兄弟向右、版本编号、待更新和业务导航不变。

分区只从现有 layout 的节点/edges 派生，同 templateId 在不同模板头或手动复制 Run 下分别分组，不能按 templateId 合并独立谱系。背景不响应点击、不标黄、不充当新工作流节点。分区几何采用统一节点尺寸与父子坐标，补充独立复制、无后代模板、不同模板、不重叠与纯展示测试。继续运行 Web 单测、类型/构建及浏览器多宽度验证。

### 第二轮结果

- 用户确认“浅色专业画布：图标卡片、模板分区、轻量浮动控件”。采用阶段类型图标、左对齐版本标题、日期/状态底栏、深色项目入口、按真实连线分开的模板谱系区域。参考 coral-ai-tool-ui 的图标/圆角/信息层级规则，保留本项目配色与红黄业务状态，未新增图引擎依赖或复制开源源码。
- 节点统一 184×88，行距 124、列距 232；组件和连线几何共用尺寸常量。全图为可选概览，默认仍至少 80%，定位当前恢复 100%。视图控件移至画布底部，适配全图预留其高度。
- 62 项相关测试通过，Contracts 重编译及 Web 类型检查/生产构建通过。初次 Web 构建遇到已有契约 dist 落后于源码导致缺少 `view` 类型，重编译 Contracts 后通过，没有改动业务接口。保留已有 >500kB 构建警告。git diff --check 通过。
- 真实浏览器：1920×1080 全图 72%，17 节点全部位于视口内，4 个独立模板区域，17 个阶段图标，项目与首个导入中心同轴；所有节点均不与浮动控件重叠。1440×900 全图 56%，另保存 100% 当前节点视图。
- 768×1024 与 375×812 定位当前后卡片可读；375 下页面与 dialog 无横向溢出，浮动控件完整可见，当前卡片完整可见。定位仅聚焦测试3智能填充版本02，无分支切换。
- 已观察真实同步加载/禁用和加载完成状态。空/错误及黄边组合沿用并由既有测试覆盖；当前项目没有待更新节点，未制造数据库状态以凑截图。

## 第三轮：居中树形与仅边框状态

用户最新要求移除大片红色区域，改用红/黄/灰边表示状态，并替代“后续分支只往右”的旧布局：整体以项目为中心、向两侧均衡展开，像一棵树。

- 范围：仅布局几何、版本树展示及相关测试。复用现有身份、owner、父子边、版本、导航和待更新计算，不修改 API、WorkingArtifact、Run 指针或任务，不做数据库迁移。
- 布局：兄弟仍按实际创建时间从左到右排序，各子树占用独立叶子列范围；父节点位于自身子树范围中心，项目位于整体画布中心。单一后代与父节点垂直；不同后代按各自宽度展开，不能伪造节点强行镜像。
- 视觉：移除所有模板谱系区域背景（含红色大块）与其计算模块；卡片统一白底，用既有红/黄/灰边表示真实状态，当前且待更新继续采用红黄组合描边。视图控件、类型图标、创建时间和原交互保持。
- 验收：更新旧的“主干坐标永不变/只向右追加”测试；补充整体中心、对称兄弟、宽度不等子树、单链同轴、同层防碰撞、输入重排/名称/选中不影响布局。相关单测、类型/构建、diff 检查以及 1920/1440/窄屏浏览器回归。
- 参考边界：冻结原型未提供版本树区域，本轮按用户明确反馈有意调整正式组件，不声称像素还原。

### 第三轮结果

- 去掉模板区域背景及其纯展示计算模块，卡片保持白底，原有红/黄/灰描边、红黄组合边框、版本和交互不变。布局按叶子占用范围居中，单链仍垂直，多分支两侧展开；相同创建时间以节点 key 稳定排序，不受输入数组顺序、改名或选中状态影响。
- 62 项布局/状态/视口/导航测试通过；Web 类型检查与生产构建通过，仅有既有 >500kB chunk 警告；相关 diff 检查通过。
- 1920×1080 与 1440×900 全图分别 72%/56%，真实 17 个节点全部可见；无节点碰撞，区域背景数为 0，卡片全部白底。项目中心与整个节点左右边界中心误差小于 0.01px。
- 768×1024 与 375×812 定位当前恢复 100% 并聚焦原测试3填充版本02，没有切换版本；手机卡片/控件完整可见，无页面横向溢出。ESC 关闭恢复入口焦点，清除临时视口覆盖。
- 已观察真实同步加载和完成态，其他空/错误/待更新状态由保留的测试覆盖，没有制造业务状态。证据：同目录 `branch-tree-centered-1920.png`、`branch-tree-centered-1440.png`、`branch-tree-centered-768-current.png`、`branch-tree-centered-375-current.png`。
