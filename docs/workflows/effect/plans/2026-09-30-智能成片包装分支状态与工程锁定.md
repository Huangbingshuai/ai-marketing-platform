# 智能成片包装分支状态与工程编辑

## 范围

效果类模板混剪节点按当前 `projectId + workflowRunId + templateId` 判断包装入口。新智能填充分支没有本 Run 的包装任务时显示“智能成片包装”；当前 Run 已执行包装后显示“重新成片包装”。切换 Run 或模板时立即清空旧包装状态，再读取目标 Run。

首次包装创建独立子 Run，冻结任务输入快照；被读取的智能填充分支由该子 Run 的包装任务锁定，模板配置与源成片工程不再原地修改。包装子分支的工程与音画轨道仍可精修。重新智能填充创建新的混剪分支，新分支尚无自己的包装任务，展示待包装状态；原包装分支保持可编辑。已包装分支再次发起整批包装仍创建独立子 Run，不反锁已有包装分支。

后台任务创建子 Run 时不切换项目当前激活的 Run，前端也不自动跳转。用户等待重新智能填充或重新包装时，继续在原包装工程编辑；成功后再由用户从版本分支树主动打开新分支。首次包装的源智能填充分支仍按上述输入锁定规则只读。任务进度按子 Run 单独读取，不得把子 Run 的草稿、素材绑定或包装条目装入父分支工作台。

尚无已填充成片工程的首次智能填充维持原有进入任务分支的流程，以便直接查看首批生成进度与结果；已有成片工程时才留在原分支后台重新填充。

## 数据与接口

- 复用现有包装任务/条目与工作副本，不增加数据库迁移。工作区增加可选的只读投影 `packagingSourceLocked`，由服务端按同项目、同父 Run、同模板的直接子包装任务计算；不信任客户端草稿值。
- 分支复制时清除 TEMPLATE_MIX 草稿中的旧 `packagingLocked` 标记；此字段只表示当前 Run 已开始包装。源锁由子包装任务推导，只有没有本 Run 包装任务的源分支才进入只读状态。
- 源分支的模板和成片工程拒绝原地编辑，但仍允许“重新智能填充”新建分支；包装分支允许继续调整视觉和音画轨道。已有包装产物的删除保护仍由包装任务及工作副本判定。
- 自动任务分支使用内部 `keepParentActive` 与幂等分支创建键；同一请求重试复用同一子 Run，不改变当前激活分支。任务完成只发布新分支，保持父分支为当前分支。
- 包装面板从服务端读取当前分支最近一个尚未发布的直接子包装任务。页面刷新后仍可看到其进度，并可对部分失败项发起现有恢复操作；子任务条目不混入父分支的包装条目。
- 智能填充也从服务端读取当前分支尚未发布的子任务，刷新后继续显示进度；同模板后台填充仍在运行时拒绝重复创建任务。进度读取不替换父分支的时间轴数据。

## 验收

- 已包装分支重新智能填充成功后，新分支入口显示“智能成片包装”，可继续编辑填充结果；旧包装仍只留在旧分支。
- 首次包装启动后，源智能填充分支不可原地编辑成片工程；包装分支可编辑其工程和包装轨道。
- 重新智能填充后切回原包装分支，仍能看到并编辑包装结果；新填充分支与旧分支独立。
- 新智能填充分支尚无本分支包装任务，显示“智能成片包装”；新分支里的画面填充结果与旧包装分支相互独立。
- 已包装分支点击“重新成片包装”创建独立子 Run，父分支保持原样。
- 重新智能填充及重新包装启动后，刷新页面仍显示原包装分支的完整工程；等待期间可继续编辑原分支，完成后版本树出现新分支，只有用户主动选择才切换。
- 跨项目、Run、模板切换不短暂显示前一作用域的包装文案或状态。
