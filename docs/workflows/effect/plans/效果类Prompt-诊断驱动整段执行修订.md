# 效果类 Prompt：诊断驱动的整段执行修订

状态：第二轮真实付费验收完成，已修复验收暴露的闭环缺口，待后续批次验证最终版本

## 目标

在不增加用户可见业务节点、不改变 Prompt 批次结果契约的前提下，降低片段级视频 Prompt 中的多物体精细操作、镜头相对运动冲突、材料行为失真、动作驱动缺失和前后状态断裂。

## 现状问题

当前候选生成后会先执行一次全量稀疏文本修订。该协议只能替换现有文字叶子，禁止增删节拍、调整节拍顺序和时长权重。跨越首帧、动作、镜头、可见结果与终帧的问题因此容易只修一处，留下互相矛盾的旧字段；全部候选无差别修订还增加调用耗时，却不能证明每条都需要修改。

## 实施方案

保持 Prompt 节点八阶段拓扑不变，重构“创意评估与用途分类”阶段内部流程：

```text
候选生成
→ AI 综合评分
→ 专职执行审片 AI 输出带位置的执行诊断
→ 仅对存在明确诊断的候选执行整段拍摄方案重写（最多两次）
→ 每次重写后由专职执行审片 AI 复查
→ AI 对重写结果复评一次
→ 仅在问题消失、事实覆盖不回退且质量仍在保护线内时采用
→ 两次仍未修复的候选移出择优池，由数量补充流程产生替代候选
```

生成与修订统一采用一份规范拍摄方案：

- `overview`：素材目标与整体质感，不重复具体运镜和动作。
- `scene.initialState`：开拍前已经成立的商品、人物、工具、支撑与空间关系。
- `beat.action`：本节拍唯一主要动作及对象。
- `beat.camera`：相机自身的位置与运动，不混写主体动作和对焦。
- `beat.focus`：对焦对象或焦点转移。
- `beat.motionSource`：物体运动的操作者、工具、重力、支撑或已确认机构。
- `beat.visibleResult`：本节拍结束时真实可见的变化。
- `finalFrame`：由前述动作自然到达的稳定结束状态。

整段修订允许重新组织 `shotPlan` 的节拍数量、顺序与时长权重，但必须保持候选 ID、事实引用、核心创意、产品关联、总时长和独特观看事件不变，不得添加新卖点、产品结构或功效。Worker 不判断动作、场景、镜头或材料语义，只验证模型输出的结构、身份、事实来源、编译结果和哈希。

## 生命周期与兼容性

- 不改变 `EffectPromptBatchResult`、HTTP 路径、Prisma Schema 或 WorkingArtifact 提交边界。
- 新 Run 不复用旧 Run 的候选或修订结果；同 Run 已落盘的修订检查点可恢复。
- 历史缺少执行诊断或整段修订记录的 Run 继续按原结果读取。
- 评分前全量盲修取消，避免每条候选多一次固定付费调用；综合评分不再兼任执行诊断，专职审片只读取结构化拍摄方案和时长。
- 专职审片逐条建立状态、左右手/工具、相机和材料因果账本；Worker 只复制带位置的 AI 诊断，不做关键词、字符或语义判断。
- 只为确诊候选付费整段修订；修订必须同时通过专职执行复查和综合质量复评。评分模型的少量随机波动使用有下限的容差，不再把已修好的方案仅因一两分波动恢复为问题原稿。
- 中断在 `STARTED` 的修订检查点不再被当作完成结果；重试会保留已经完成的诊断并从缺失的修订继续执行。
- 两次修订后仍被专职审片确认有问题的候选标记为 `UNRESOLVED_EXECUTION`，不得进入最终择优。Worker 只执行 AI 诊断对应的状态机规则，不解释动作语义。

## 验收

- 自动测试覆盖：无诊断不调用修订；有诊断可更改节拍数量、顺序和时长权重；身份、事实引用和核心创意不可改变；修订后必须复评；事实覆盖或评分回退时保留原稿；失败检查点可安全恢复。
- Prompt 模板覆盖字段单一职责、完整因果链、相机/主体/焦点分离、动作驱动、真实材料行为和 15 秒内可完成性。
- 执行 Prompt Worker 单元测试、mypy、Ruff 与 `git diff --check`。
- 真实付费验收另行记录；不调用视频渲染，不自动完成校验。

## 实施结果

- 已移除生成阶段对所有候选执行的固定稀疏修订调用。
- 执行修订已改为评分诊断触发，并返回完整 `shotPlan`；可调整节拍数量、顺序与相对时长。
- 第一轮真实 50×15 验收严格产出 50 条、重复度 8%、平均画面可执行性 90.6，但综合评估的执行诊断为 0；人工逐条核查仍发现多手多工具切换、短时多阶段操作、单夹具掰开、材料拉带等漏检，因此该轮不判定画面质量达标。
- 针对真实漏检，已将执行诊断从综合评分中拆为评分节点内的专职 AI 审片；修订后先由专职审片复查，再由综合评估复评，仅在执行诊断消失、事实覆盖不回退且质量分不下降时采用。
- 第二轮真实 50×15 验收严格产出 50 条、重复度 12%，综合评分为产品相关性 95.8、连贯性 93.4、画面可执行性 89.4、商业价值 90.1、视觉清晰度 93.9。专职审片确诊并尝试修订 27 条，但当时实现只采用 3 条，23 条回退为已知有问题的原稿，另有 1 条停留在 `STARTED`；人工复核仍能在 P001、P003、P004、P007、P009 等条目看到固定机位与跟拍并存、短时换工具、单手筷子折叠和跨角度机位跳变。本轮还因本地 API 短暂无法连接触发一次任务级重试，随后依靠同 Run 分片恢复完成。因此该轮证明“专职审片能发现问题”，但未证明最终 Prompt 已达标。
- 已根据第二轮证据补齐闭环：修订最多执行两轮；放宽纯数值波动造成的误拒绝，同时保持事实和最低质量保护线；未修复候选不再伪装成通过项，而是退出择优并交给数量补充；中断检查点安全恢复；页面改为展示可恢复的审片条次和未修复淘汰数，不再显示重试后归零的供应商调用计数。
- Worker 对带租约的幂等阶段/分片回写增加短时网络重试，吸收 API 热重启等瞬时连接中断；领取任务仍不自动重试，避免未知领取结果造成重复 attempt。
- 工作流节点详情已把修订进度归入“创意评估与用途分类”，不再在创意生成节点显示全量修正。
- 第二轮后 Prompt Worker 全量测试、mypy、Ruff、API 节点详情测试与 API 类型检查均已通过；按用户要求未再启动新的付费批次。
