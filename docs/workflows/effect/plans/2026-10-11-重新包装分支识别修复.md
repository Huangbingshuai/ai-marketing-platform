# 重新包装：已发布部分成功分支识别修复

## 范围与事实

效果类模板混剪内的整批包装。测试1的新协议整批任务已结束并发布子 Run，但版本树仍把所有 PARTIAL 包装当成旧式未完成任务隐藏，导致再次包装的当前模板路径校验失败。

直接上游为当前模板时间轴、素材及产品事实的已确认工作副本和实际 revision；输出仍为 timeline-project / timeline-package。只修复已发布结果的树投影与当前路径衔接，不改变任务输入、提交事务、付费调用、重试或成片输出边界。

## 实施

- 仓储轻量查询 PARTIAL 任务中实际成功条目的新协议 BATCH_PACKAGE 标记，不把完整输入快照装入版本树。
- 树可见性、包装头及兄弟版本编号采用同一完成条件：原 COMPLETED，或新协议 PARTIAL 且至少一条实际成功；子 Run 仍必须已经发布。旧协议 PARTIAL、运行中、全失败和未发布任务继续保持原边界。
- 更新树缓存投影版本，避免修复后命中旧过滤结果。
- 核对逐条结果提前进入子 Run 后的结束交接，保证用户当前查看的已发布包装路径可继续重新包装，不绕过来源、编辑 revision 或并发冲突校验。
- 不迁移/批量改写历史工程、不启动任务、不自动提交 Git。
