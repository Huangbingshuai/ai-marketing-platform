# 时间轴边框新建轨与拖入替换（第二轮修复）

承接 `2026-09-24-素材拖入轨道边框新增轨道.md`。上一轮把「视频素材拖到视频行边框 → 新增轨道」做通了，本轮修的是**音乐与字幕没有跟上、跳转位置不对、拖到已有片段上没有替换反馈**这五条实测问题。

## 范围（对应五条实测问题）

1. **音乐库拖到音频行边框不出辅助线** —— 拖到音频行上/下边框时用户看到的是**整行被框住**（`is-drop-target` 的整行描边），横向辅助线没出来。
2. **字幕片段不能像视频片段那样拖动新增轨道** —— 这里的「字幕素材」指**轨上已有的字幕片段**（素材库的「字幕」页签只有一个标题栏 + 添加按钮，没有可拖的素材）。
3. **已有的音乐片段、字幕片段拖到轨道边也没有辅助线** —— 指针拖拽路径（`audioDrag`）从来没有算过边框，只有视频片段的指针拖拽算过（`updateDragTarget`）。
4. **视频素材跳转后落点靠右** —— 新片段的**时间大于松手时鼠标的时间**，问题在吸附/时间换算，不在滚动。
5. **拖到已有片段上要能替换** —— 拖到某个已有片段上时，那条片段要**变暗 + 描边**表示会被替换，松手就替换它，**新素材的长度严格按被覆盖片段的长度**，素材不够长就算了。

## 现状问题

- **音频行没有「片段之间的空隙」可以瞄**：视频行的边框是相邻两条片段之间 8px 空隙的中心，而音频行只有一行高、片段内缩 3px，指针能停的「边框带」只有 `TRACK_INSERT_THRESHOLD = 6px`。6px 落在 50px 的行里几乎必然先命中整行的 `is-drop-target`，用户看到的就是「一整个框都是辅助线」。
- **指针拖拽路径没有边框计算**：`onWindowPointerMove` 的 `audioDrag` 分支只算 `currentRow`（片段落到哪一行），从来没调用 `trackInsertTargetFrom`。所以「拖动已有音乐/字幕片段」这一路完全没有辅助线，也没有新开行的语义。
- **字幕没有「行」的概念可写**：字幕行是从**字幕自己的 track 推导**出来的（`assignEffectTemplateMixCaptionLanes`：按 `trackId` 分组，再在组内按重叠压行），磁盘上没有行号。所以「给字幕新开一行」= **给它一个新的 `trackId`**，和 `addCaption` 的做法一致。
- **素材库落点被磁吸带偏**：`onMaterialDrop` 用 `dropTimeFromClientX`，而它内部走 `snapTime` —— 磁吸会把落点吸到 7px 内任意片段的起点或终点。磁吸对「贴着邻居接上去」是对的，但对**边框落点**（自由放置、允许重叠）是错的：用户落在 t，片段却落在 t+0.1 的某个邻居起点上。
- **跳转只保证露出片段头部**：`scrollToLane` 只在片段头部落在视口外时才横向滚动，落在右边缘附近时**尾巴被切掉**。
- **替换只有「选中」这一种视觉**：`.video-clip.is-material-target` 是浅蓝底 + 蓝框，读起来像「被选中」而不是「会被压住」；音频片段则完全没有这个状态，音乐拖到音频片段上只能落到那一行、不会替换它。

## 设计

### 一、加宽音频行的边框命中带

`AUDIO_INSERT_THRESHOLD = Math.round(AUDIO_LANE_HEIGHT / 4)`（= 13px），并且只在枚举音频边框时用它：

```ts
let bestDistance = kinds.has('AUDIO') ? AUDIO_INSERT_THRESHOLD : TRACK_INSERT_THRESHOLD;
```

一行 50px，上下各 13px 命中带，中间 24px 仍然表示「用这一行」。视频行保持 6px 不变 —— 它有真正的空隙可以瞄，不需要放宽。

### 二、字幕片段拖到字幕行边框 → 新建字幕轨

- `TrackInsertTarget` 加第三种 `{ kind: 'CAPTION'; lane; top }`，新增 `CAPTION_INSERT_KINDS`；`trackInsertTargetFrom` 里枚举 `captionTrackElements` 的上下边框，`lane` 取该行的车道号、底边开 `lane + 1`。
- **哪种拖动看得见哪种边框**是结构性保证：视频拖拽只传 `VIDEO_INSERT_KINDS`，音乐/音频片段传 `AUDIO_INSERT_KINDS`，字幕片段传 `CAPTION_INSERT_KINDS`。三者互不可见。
- 指针抬起时 `emit('splitCaptionTrack', captionId, start)`。编辑页：
  - 在**当前正在编辑的那一份字幕源**（选中成片 → checkpoint；否则变体）里找到这条字幕，给它换一个新的 `trackId`，**保留它自己的长度**，只改起点；
  - checkpoint 那一路走 `editPackagingAudio`，因为**只有它会给这次编辑拍下保存基线**（直接改对象不会进入 `audioDiff`，永远存不下去）；
  - `nextTick` 后调新暴露的 `scrollToCaption(captionId, time, duration)` 跳过去。
- 字幕行是**一条一条独立的窄条**（不是一个高车道），所以纵向位置 = 第一条字幕条的位置 + 车道号 × `CAPTION_LANE_HEIGHT`。

> 行号不由落点决定：字幕行的顺序是 `assignEffectTemplateMixCaptionLanes` 按 track 分组推导出来的，新 track 会排到最后一组。也就是说「在边框上放手」保证的是**字幕获得自己的一行**，不是「一定落在你点的那一行」。要在这一点上做到精确，得改字幕行的推导规则（`effect-template-mix-state.ts`，本轮正被并行会话改写），不在本轮范围。

### 三、已有的音乐/字幕片段拖到边框也出辅助线

`onWindowPointerMove` 的 `audioDrag` 的 `MOVE` 分支里补上边框计算：

```ts
const insertTarget = dragGroupIds(drag.id).length
  ? null
  : trackInsertTargetFrom(
      event.clientY,
      drag.id.startsWith('caption:') ? CAPTION_INSERT_KINDS : AUDIO_INSERT_KINDS,
    );
trackInsertTarget.value = insertTarget;
drag.insertRow = insertTarget?.kind === 'AUDIO' ? insertTarget.row : null;
drag.insertCaptionTrack = insertTarget?.kind === 'CAPTION';
```

- **只有单选才给**：一组片段是整体平移的，没有「给整组开哪一行」的答案（和视频片段同一条规则）。
- `AudioDragState` 加 `insertRow: number | null` 与 `insertCaptionTrack: boolean`，在 `beginAudioDrag` 里初始化。
- 抬起时：字幕且命中 → `splitCaptionTrack`；音频且 `insertRow !== null` → `moveAudioClip(id, start, insertRow, insertRow)`；否则维持原语义。
- 编辑页侧：`TimelineAudioMove` 加 `insertRow?: number`，有它时**跳过 `resolveAudioPlacement` 的「优先找上面空行」**——边框是用户给出的答案，不是待优化的提示；行插入用既有的 `insertRowAt` 原语（`>= insertRowAt` 的行整体 +1）。
- `shouldApplyMove` 额外把 `insertRow !== undefined` 算作「有变化」：把片段拖到**它自己那一行的边框**上时行号与时间都没变，但用户确实要求开一行，否则这一手会被静默丢掉。

### 四、边框落点不再磁吸

`dropTimeFromClientX(clientX, snap = true)`；`onMaterialDrop` 命中视频边框时传 `false`，只做帧对齐（`quantizeToFrame`）：

```ts
return snap ? snapTime(raw) : quantizeToFrame(raw);
```

理由：边框落点是**自由放置**（可以和已有片段重叠，这就是「盖住下面」），磁吸的语义是「贴着邻居接上去」，两者冲突。槽位替换那一路仍然磁吸。

### 五、跳转要露出整个片段

抽出 `revealTimelineColumn(time, duration)`，`scrollToLane` 与 `scrollToCaption` 共用：

- 片段宽度 **大于视口**：对齐头部，左侧留 24px 边距；
- 头部在视口左边距以内：贴到左边距；
- 尾巴超出右边缘：把右边缘推进到尾巴 + 24px。

`scrollToLane(lane, time, duration = 0)`、`scrollToCaption(captionId, time, duration = 0)`，编辑页在 `insertMaterialTrack` / `splitCaptionTrack` 里把 `duration` 一起传过去。

### 六、拖到已有片段上：变暗 + 描边，并且能替换

**视觉**（视频片段与音频片段共用）：`.is-material-target` / `.is-material-pointer-target` 用 `::before` 盖一层 `rgba(15, 23, 42, 0.5)` 压暗（`::before` 在两条片段上都没有被占用，`::after` 已被 `is-low` 角标占用），描边画在元素自己的边框上，两者互不冲淡。

**替换行为**：

- **视频素材 → 已有视频片段**：沿用既有的 `applyMaterialToSlot`（本来就实现了「素材短于槽位就拒绝，绝不改槽位时长」），本轮只补上「变暗 + 描边」的视觉。
- **音乐素材 → 已有音频片段**：新增 `replaceAudioWithMusic`。
  - 命中判定用 `document.elementFromPoint(...).closest('.audio-clip')` 读 `data-audio-id`（HTML5 拖拽不会在指针下插入真实元素，`elementFromPoint` 拿到的就是真实命中的那条）；命中时清空 `musicDropRow`，两种反馈不打架。
  - 编辑页只允许替换**分离原声**（`detached:*`）：口播片段绑在脚本行上、包装音乐绑在已确认 checkpoint 上，从草稿侧换掉会让 checkpoint 描述一段已经不存在的音频。
  - **长度严格按被覆盖的片段**：`music.duration < audio.duration` → `showNotice('... 短于被覆盖的片段，无法替换')` 直接拒绝；否则保留被覆盖片段的 `start` / `duration`，新素材从自己的头部开始（`offset = 0`）、`sourceDuration` 取新素材全长。

## 风险与边界

- **字幕新行的落点是推导出来的**：新 track 排到最后一组，所以「在中间某条字幕行的边框上放手」得到的新行在字幕区底部，而不是指针所在的那一行。这是既有字幕行模型的限制，已在上面写明。
- **音频边框带 13px 会吃掉行高的中间 24px**：一行只有 50px，指针停在行中间偏上/偏下会变成「开新行」而不是「用这一行」。这是为了「看得见辅助线」付出的代价 —— 6px 带在这条行上实测根本抢不过整行高亮。
- **替换只覆盖分离原声**：音乐拖到口播 / 包装音乐上仍然是「落到那一行」（不替换），并给出提示。宁可拒绝，也不让 checkpoint 与实际音频脱节。
- **音乐替换后不做淡入淡出继承**：`detachedAudios` 没有 fade 字段（fade 是打包侧的概念），所以替换只换源、长度、名字，音量沿用。

## 验收

1. 音乐库拖一个音乐到音频区 → 指针推到某条音频行的上/下边框 → 出现**横向蓝色辅助线**（不是整行框住）；移到行中间 → 辅助线消失、该行整行高亮。
2. 在音频行边框上放手 → 该处**新增一条音频轨**，音乐落在上面，原来的行整体下移一行。
3. 拖动**轨上已有的音乐片段**到另一条音频行的边框 → 同样出辅助线，放手后新开一行、片段落到新行。
4. 拖动**轨上已有的字幕片段**到字幕行的上/下边框 → 出现辅助线，放手后该字幕**获得独立的一行**（`trackId` 变化），起点为放手处、**长度不变**，视图跳到它。
5. 从素材库拖视频素材到视频行边框放手 → 新片段的时间**等于放手时鼠标的时间**（不再被吸到邻居的边上），视图**完整露出这条片段**（右边缘不再被切掉）。
6. 从素材库拖任意素材到**已有片段**上 → 该片段**变暗 + 描边**；视频素材松手 → 替换该片段素材（素材短于槽位仍被拒绝、槽位时长不变）；音乐素材松手到**分离原声**上 → 替换该片段（长度按被覆盖片段，音乐更短则拒绝并提示）。
7. 回归：不碰边框时，音乐拖入仍是「落到放手那一行」；拖视频素材到槽位上仍是「替换该槽位素材」；两个模板槽位手动拖成重叠仍被 `槽位口播边界冲突` 拦下。
