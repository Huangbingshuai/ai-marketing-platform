# 包装口播自适应表达密度

范围：效果类模板混剪内的智能成片包装。用户确认保留整片连贯性，同时根据画面、事实和可用时长自然安排单句或多句，不强制每个素材多句，也不以短句换取连贯。

## 原因与边界

- 现有 `lines` 是每槽一个工程段落，内部已经支持标点拆分配音和多条真实时间戳字幕；不需要新建第二套口播协议或把句子数变成素材数。
- 当前生成与修正规则反复使用“一条/每句/完整单句”，段落与句子的职责不清；虽允许长槽句群，但没有明确整片表达密度的决策任务。截图是实际反馈，不把提示词改动视为已完成模型质量验收。
- 超时缩句参考额外乘 `.8`，即轻微超时也建议大幅删减；改为参考真实超时比例并只留少量安全余量，仍以最终配音硬校验，不加速、不截断、不改时间。
- 上游仍为冻结的同项目/Run 时间轴工程、素材/Prompt 的实际 revision 与已确认商品事实。READY 沿原 API 校验与事务提交 `timeline-project:<templateId>:<variantId>` 和 `timeline-package:<templateId>:<variantId>`；下游用户主动导出，不自动处理旧成片。

## 实施

1. 明确每槽返回一份口播段落，`text` 可含一个或多个完整句子；句数、展开程度和有意留白由 AI 根据整片节奏、内容及素材时长决定，不设置句数或最低利用率硬门槛。
2. 给出每槽可用秒数与柔性的配音时长参考，要求避免全片各槽开头一句、后半段机械大段空白；有充分事实与画面时展开新信息，不为填时长重复商品、堆连接词或编造事实。
3. 首次策划、结构修正、超时缩句与重策划共用密度规则；缩句按真实超时量适度精简，允许保留多句和自然断句，不一律缩为口号。
4. 保持现有按句 TTS、每槽独立音频、多条字幕与真实时间戳。局部重做只更新目标，邻槽、空槽、删除项、已成功音频、配乐与默认口播音量不变。
5. 用户追加确认按槽位用途创作：按契约真实六角色 HOOK、PAIN_POINT、PRODUCT、SELLING_POINT、TRANSFORMATION、END 给模型明确职责，不按位置猜用途。用户进一步澄清 END 不是只承接前文，最后一句必须有听得出结束的自然结束语，可收尾、告别或克制邀请尝试；不统一套告别模板、不重新介绍或另开卖点，长结尾也不省略结束语，不编造促销。初始、结构修正、缩句及重策划都保留用途指引；不加关键词语义硬校验。

## 验证与非目标

- Mock 覆盖不同槽长、单句/多句混合、不强制短文案失败、多句配音/字幕边界、局部修正只改目标、轻微超时不额外砍掉20%、恢复不重复请求及失败不提交。
- 执行相关 pytest、mypy、API 原有包装域回归、差异检查；有活动任务时不重启 Worker。
- 不改 API/Contracts/Web、不迁移数据库、不增加语义审核或模型调用次数、不自动重写历史项目、不提交 Git。真实生成/试听需明确授权。
