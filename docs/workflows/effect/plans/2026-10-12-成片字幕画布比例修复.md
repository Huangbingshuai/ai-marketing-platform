# 成片字幕画布比例修复

## 范围与原因

效果类模板混剪预览与成片输出共用包装检查点。现有字号默认 16，预览直接作为 CSS 像素，导出却直接作为 720p/1080p 等画布的像素，导致烧录字幕过小且分辨率越高越小。

## 实施

- 将既有 `captionFontSize` 明确为 360 像素高参考画布上的逻辑字号，默认 16、编辑范围 8–48 不变。
- Contracts 提供参考高度和尺寸换算；Web 按未缩放播放器画布高度换算，Worker 按最终输出画布高度换算 ASS 字号及多行间距。缩放播放器时不重复计算缩放。
- 无字幕框与自定义字幕框使用同一字号规则；保留字幕文字、起止时间、归一化位置和历史 scale 忽略规则。
- 不增加字段或数据库迁移，不改变业务 revision、来源依赖或任务生命周期。直接上游仍是本 Run 的已确认时间轴及包装工作副本，输出仍只在用户主动导出时提交。
- 历史字号兼容读取；已有视频烧录内容无法原位改变，不自动重新包装、导出或触发付费生成。

## 验收

- Contracts 与 Python 对参考高度、缺省字号、边界字号以及横竖屏多分辨率进行一致性测试，确认不是固定输出像素或最高 48 像素截断。
- 回归 Web 字号编辑和画布尺寸跟踪，执行相关测试、类型检查、构建与差异检查。
- 使用本地 FFmpeg 合成短测试片验证真实烧录；浏览器检查 1920、1440 和窄屏字幕比例，不触发真实生成任务。
