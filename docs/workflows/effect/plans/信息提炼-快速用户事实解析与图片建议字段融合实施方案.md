最新真实任务 `ff811af9-cfc5-4b9d-b71a-5be939a86b79` 虽在单次尝试内完成，但暴露出三项实现偏差：

1. 当前资料包经 Docling 输出为“标题 + 段落/列表”，确定性解析器却只识别 Markdown 表格，导致 DOCUMENT 错误进入 `AI_FALLBACK` 并额外调用模型。

本轮修正：

- 确定性解析同时支持信息表格和标题/段落/项目列表，仍以字段识别数量、身份字段和内容字段作为保守命中门槛。

- 强化图片字段归类指令：节庆、礼赠、家庭餐桌等明确画面必须进入相应购买/情绪/使用场景，不能只写成卖点。
- NORMALIZATION 保留原工作流节点，但对已经结构化的融合结果执行确定性契约化；只有确定性构造异常时才允许模型兜底。

## 改造范围

1. DOCUMENT 仍只负责用户资料事实，不生成全局视频配置或图片建议。
2. 对符合信息提炼表格式的 Markdown 表格进行确定性字段解析，不调用模型。
3. 对无法可靠识别为结构化信息表的普通文档，继续使用 AI 兜底，但改为最小思考、单次调用、受限输出和独立短超时。
4. IMAGE 提取可见事实，并基于明确画面证据保守建议卖点、痛点、受众、决策动因、营销目标和场景；不可验证的配方、产地、认证、功效、销量和价格仍禁止推断。
5. 图片建议直接进入对应信息卡字段的剩余容量并逐项标注来源，不新增独立建议区；核心外观特征仅在用户资料没有提供时由图片识别补齐。

## 数据与生命周期

- 不新增 Prisma 表或数据库迁移，继续从本次 Run 的 IMAGE 分支输出构造图片建议。
- `EffectExtractionProvenance` 为字段和列表项补充安全来源文件名，历史结果缺少来源时使用兼容兜底，不伪造具体文件。
- 文档快速解析和图片建议展示只更新信息提炼草稿；用户点击“完成校验”后才提交营销洞察 WorkingArtifact revision。
- Prompt 生成仍只消费已提交的营销洞察，不读取 IMAGE 原始分支或未确认建议。

## 验收

- 标准资料表无需 DOCUMENT 模型调用即可恢复产品、卖点、用户和场景事实。
- 普通非结构化文档仍能走 AI 兜底，且单次失败不会在 Worker 内形成长时间重复等待。
- 被选择进入信息卡的图片建议在对应字段内显示，并保留来源文件名；未进入结果容量的候选不额外铺成大区块。
- 图片建议不覆盖价格、规格、产品事实或导入节点全局视频配置。
- Contracts、API、Web、Worker 相关测试、类型检查、构建和 `git diff --check` 通过。
