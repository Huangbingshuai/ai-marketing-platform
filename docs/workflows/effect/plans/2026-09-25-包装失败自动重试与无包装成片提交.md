# 包装失败自动重试与无包装成片提交

## 背景

用户在「测试1模板」跑了一遍 100 条智能成片包装，结果：

- 按钮没有变成「重新成片包装」，也点不动「完成校验」；
- 追问：**「这个失败的成片我不是做了自动重试吗为什么没有重试」**、**「失败的成片应该有所提示」**、**「即使失败了也不能阻止用户完成校验啊」**。

前一轮已经修掉了按钮文案与校验提示的诚实性（见 `2026-09-25-成片包装未就绪时的按钮与校验提示.md`），但那一轮只是**把真实原因说出来**，没有解决「为什么失败」和「失败之后怎么办」。这一轮解决这三件事。

## 实测证据（决定了下面的设计）

### 2. 自动重试在同一次运行里确实跑过，但**没跑在这三条上**

```
select count(*) filter (where checkpoint ? 'automaticRetries') with_retries,
       count(*) filter (where not checkpoint ? 'automaticRetries') without_retries,
       count(*) filter (where status<>'COMPLETED') failed
  from effect_packaging_items where "runId"='bcfd465d-1650-4e16-89f2-28214caaffa8';

 with_retries | without_retries | failed
--------------+-----------------+--------
            4 |              96 |      3
```

100 条里有 4 条真的花掉了重试预算（`automaticRetries` 有值），而 3 条失败项**连这个键都没有**——即 `recover_packaging_item` 的重试分支根本没有进入。原因在代码里很明确：

```python
retryable = (isinstance(exc, (PackagingTransientError, httpx.TransportError, ProviderOutputError)) or
             isinstance(exc, ProviderError) and exc.retryable)
```

两处真实失败抛的都是**裸 `PackagingError`**：

- `shorten_voice_line` 的缩句改写了句子身份 → `PackagingError`；
- `query_music` 的 `status != 2` → `PackagingError`。

裸 `PackagingError` 在 `recover_packaging_item` 里被当成「终局判决」，直接写 `errorMessage` 收工。所以「做了自动重试」这个前提没错，**是这两类错误没被归进可重试集合**。

### 3. 纯音乐那条即使进了重试也没用

`produce_music` 的轮询循环拿着 `cp['musicTaskId']` 反复 `query_music`。供应商已经判死的任务，再轮询一百次也只会返回同一个判决；重试必须**换一首**，而不是重问。旧代码在 `status != 2` 时既不区分「判死」和「读不懂」，也不清掉死任务 ID。

## 设计

### 1. worker：让「可修的缺陷」进入重试预算

`packaging_provider.py`

- 新增 `MUSIC_FAILED_STATUS = 3`（供应商的终局失败码）与 `MusicTaskFailed(PackagingError)`。
- `query_music` 的 `status != 2` 分支拆成两支：
  - `status == 3` → 打一行过滤后的日志（只回显数字状态，绝不回显供应商原文），抛 `MusicTaskFailed`；
  - 其它未知状态 → `PackagingTransientError('音乐任务状态未知，保留原任务自动恢复')`。**未知状态不再等于失败**：它同样不是「歌已经好了」的证据，此时重提等于为一个可能还在跑的任务付第二次钱。
- 顺手把 `music_request` 里内联的 `safe_code` 提成模块级 `safe_token`，两处日志共用。

`packaging.py`

- 新增 `VoiceFitRewrite(PackagingError)`：缩句改写了 `id / slotId / start / end / factIds` 时抛它。句子身份、时间、来源是确定性保护的，模型给出不合规样本属于**模型缺陷**而非对成片的判决，换一次采样可能就合规。
- `recover_packaging_item` 的可重试集合加入 `MusicTaskFailed` 与 `VoiceFitRewrite`。预算仍是既有的 `automaticRetries < 2`。
- `produce_music` 捕获 `MusicTaskFailed` 时先 `save('MUSIC', {'musicTaskId': None})` 再抛出：**忘掉死任务**，这样紧接着的重试会重新提交一首新歌，而不是重放同一个判决。

`musicTaskId` 允许 `null` 作为「供应商判死」的显式标记：contracts 类型放宽为 `string | null`，API 校验器显式放行 `null`（校验器的正则只放字符串，而 checkpoint 合并是浅合并 `{...old, ...patch}`，省略键无法清空）。

### 2. API：失败项按「无包装成片」提交，不再一票否决

`effect-final-output.service.ts` 的 `complete()`：

- `QUEUED / RUNNING` 之外（即 `COMPLETED / FAILED / CANCELLED`）都可以提交；
  `RUNNING / QUEUED` 抛 `仍在包装中；请等待包装结束后提交`（真正没跑完，等一下就有结果）。
- `FAILED / CANCELLED` 的成片以 `checkpoint = { voices: {}, captions: [] }` 提交，`unpackaged: true`，跳过 `requireSlotPackaging`。
- `matchesVisualHash` 与上游依赖新鲜度两道闸**保留**：跳过包装不等于跳过「这条成片是否已经被改过」的检查，否则会把用户已经替换掉的画面导出去。

`FinalOutputSnapshot` / `FinalOutputItem` 新增 `unpackaged?: boolean`，`toDto` 透出，成片列表可以说明「为什么这条是哑的」。

**worker 侧确认无需改动**（已核对 `final_output.py`）：

- `render()` 读 `cp['voices']`（:292）与 `cp['captions']`（:369）是无条件取值，`cp.get('music')`（:338）可缺省；`FinalOutputHandler.execute` 同样要求 `snapshot['packaging']['voices']`（:427）。所以「无包装」必须携带 `{ voices: {}, captions: [] }` 这个**键存在但为空**的形状。
- 渲染时长只由 `timeline['duration']` 决定，而它取 `effectTemplateMixContentDuration(variant, cp)`；空 checkpoint 下回落到视频/分离原声末端。尾部没有视频素材的位置由 `packaging_media.visible_intervals` 输出 `clip=None`，`final_output.py` 渲染成 `color=c=black`——即尾部黑屏、画面照常。

### 3. 前端：把「失败」说出来，并且不拦路

`EffectTemplateMixPackaging.vue`

- `allReady` 从「每一条都必须 `COMPLETED`」改成按变体求**结论**：

  ```
  type Conclusion = 'PACKAGED' | 'FAILED' | 'PENDING';
  ```

  `PACKAGED` = `COMPLETED` + `SLOT_V1` + 无槽位边界错误；`FAILED` = `FAILED | CANCELLED`；其余（含 `stale`、边界错误、还在跑）为 `PENDING`。`allReady` = 没有任何 `PENDING`。
- 新增 `failures` 事件，携带 `{ variantId, name, message }[]`。

`EffectTemplateMixNodePage.vue`

- 接收 `failures`，`packagingFailureByVariant` 供卡片逐条标注：红点 `project-status.failed`、卡片红边、以及一行「包装失败 · 将仅出画面」，`title` 里带真实 `errorMessage`。
- 顶部新增失败横幅（`data-testid="packaging-failure-banner"`），点名前 3 条并说明「仍可完成校验，这些成片会以无包装成片提交，仅保留画面、没有口播字幕配乐」，按钮直接打开包装面板去恢复。
- `validateStatusTitle` 在 `packagingReady` 且有失败时改成
  `成片包装就绪，其中 N 条失败将按无包装成片提交（仅画面）`——「就绪」两个字不能把「有几条会是哑的」藏起来。

`EffectFinalOutputNodePage.vue`

- `item.unpackaged` 时加一枚「无包装」胶囊，并把元信息从「内嵌字幕」换成「无口播 / 字幕 / 配乐」。哑成片和渲染失败在界面上必须能分开。

## 补记：第一版漏掉的 worker 回读路径（实测发现）

第一版只在**提交路径**（`complete()`）放宽了 `requireSlotPackaging`，漏了 **worker 读写路径**。结果三条无包装成片一提交就失败：

```
    id    |   name   | status | progress |                  err
----------+----------+--------+----------+------------------------------------------
 8c50e9b7 | 测试1 · 26 | FAILED |        0 | 输出来源或结果校验失败，请回模板混剪恢复
 4b272715 | 测试1 · 38 | FAILED |        0 | 输出来源或结果校验失败，请回模板混剪恢复
 081d6b59 | 测试1 · 59 | FAILED |        0 | 输出来源或结果校验失败，请回模板混剪恢复
```

链路：worker 拿到条目后第一件事就是 `PUT …/items/:id/progress`（`final_output.py:423` 的 `progress(1)`）→ API `progress()` → `workerItem()` → `current()` → **无条件** `requireSlotPackaging(snapshot.timeline, snapshot.packaging)`。空 checkpoint 没有 `narrationLayoutVersion: 'SLOT_V1'`，直接抛 `ConflictException`；worker 的 `except ApiError` 分支判定为非重试错误，于是把「输出来源或结果校验失败，请回模板混剪恢复」写进 `errorMessage`。

`current()` 是 `progress` / `content` / `upload` / `retry` / `renderItem` 五条路径的共同闸门，所以这一条漏掉等于无包装成片永远渲染不了。

修法：`current()` 里按 `snapshot.unpackaged` 分流——

```ts
if (snapshot.unpackaged) {
  // 渲染器无条件读这两个键，所以无包装成片只被这两条约束
  if (!snapshot.packaging || typeof snapshot.packaging.voices !== 'object' ||
      snapshot.packaging.voices === null || !Array.isArray(snapshot.packaging.captions))
    throw new ConflictException('无包装成片的结构无效');
} else requireSlotPackaging(snapshot.timeline, snapshot.packaging);
```

下面的 `matchesVisualHash` 与依赖新鲜度检查照旧执行——画面仍然受保护。`start()`（首次导出）不校验 checkpoint，所以「能提交、能排队、一渲染就死」的现象正好对上。

**教训**：`unpackaged` 是一个**跨整条链路**的新状态，不能只在写入端放行；凡是复用 `current()` 的路径都要一起想。第一版的单测只覆盖了 `complete()`，没覆盖 `progress/content/upload`，所以没兜住。现在补了 `picture-only output items` 两条用例（正常回读 + 缺键被拒）。

## 非目标

- 不放开 `freshness='CURRENT'` 过滤，不改 Prompt 失效粒度。
- 不改 `stale` 语义（它 gate 住 `editPackagingAudio`，翻它会把用户锁死）。
- 不动 `packagingTimelineDuration`（那是「视觉时间轴长度」，还被 `timeline-project` 的 `durationSeconds` 元数据用着）。
- 不加 Prisma 迁移：`snapshot` 是冻结 JSON，`unpackaged` 只对**新提交**的输出生效；存量输出行读出来是 `undefined` → `false`。
- 不把「未知音乐状态」也当成失败去重提：那样会为一个可能还在跑的任务付两次钱。

## 验收

- 包装 PARTIAL（97/100）后「完成校验」可用；3 条失败项进入输出，列表上标注「无包装」，播放有画面、无口播字幕配乐。
- 缩句身份违例与音乐判死这两类错误现在会花掉 `automaticRetries` 预算（≤2）；音乐判死后会清掉死任务并提交新歌。
- 失败项在混剪节点有横幅 + 逐卡片标注，`validateStatusTitle` 说明会按无包装提交。
- 时间轴已改动的失败项仍然拒绝（`的包装已过期`）。
- worker / API / web 单测与两端类型检查通过（对比既有失败集合只少不多）。

## 风险

- **输出里会混入半成品**：用户已明确选择「失败项也提交，用无包装空成片占位」。恢复该条并再次完成校验会以**新的输出运行**补回音频（`inputHash` 不同，不会被幂等去重掉），旧运行仍在。
- **`VoiceFitRewrite` 多花一次采样**：最坏 2 次重试 × 100 条 = 200 次缩句调用。缩句本身是短输出的小调用，且只在模型给出不合规样本时才发生。
- **`MUSIC_FAILED_STATUS = 3` 是推断**：文档未拿到，代码里对未知状态一律走「保留原任务」的保守分支，所以即便 3 不是失败码，最坏也只是退回旧的「判死」语义，不会误付。日志会打出真实数字状态以便事后校正。

关键回归用例：

- `submits the %s film as a picture-only one instead of blocking the batch`：`FAILED / CANCELLED` 的成片以 `{ voices: {}, captions: [] }` + `unpackaged: true` 进入输出，同批 `COMPLETED` 的成片保留口播。
- `waits instead of submitting while the last item is still %s`：`RUNNING / QUEUED` 仍然拒绝并提示 `仍在包装中`。
- `still refuses a film whose timeline changed after the packaging failed`：跳过包装不等于跳过 `matchesVisualHash`。
- `tells the output list why a film plays without sound`：`toDto` 透出 `unpackaged`。
- `lets the worker fetch its sources and report progress`：无包装条目能通过 `current()`，`progress` / `content` 不再被包装校验拦下。
- `rejects a picture-only snapshot missing the keys the renderer reads`：`voices` / `captions` 缺键仍然被拒。
- `test_film_confirmed_without_a_package_renders_picture_only`：空包装真的能渲染出时长正确、带 AAC 轨、无字幕事件的成片（真跑 ffmpeg）。
