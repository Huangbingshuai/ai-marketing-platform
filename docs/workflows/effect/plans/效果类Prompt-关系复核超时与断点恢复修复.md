# Prompt 关系复核超时与断点恢复修复

状态：已完成实现与自动回归（2026-09-08）；未新增付费验收。

## 边界

仅效果类第 3 节点内部执行治理。消费当前商品已确认营销洞察 artifact/revision 与 Prompt 设置；输出仍为领域草稿，仅用户完成校验提交 prompt-batch:{productId} 后才影响渲染。八阶段图、评分、事实语义和数量规则不变。保留其他未提交修改，不改视频渲染。

## 实施

- 关系复核与全批重叠复核独立超时默认 180 秒，普通候选评分仍 120 秒，Provider 单次尝试仍为 1。
- 关系复核最多 6 个方向一批，同时按序列化输入规模估算预算拆批；预算只决定批大小，不裁剪事实或做语义判断。单方向超预算仍完整复核并记录安全诊断。
- 在开始关系复核前保存已结构验证的空间、方向、当前修订次数；每个复核分片通过结构/ID 校验即保存完成结果。语义需修改的合法审查意见也保留，不伪造成通过。
- 使用现有阶段 metadata.checkpoint 与内部 stageCheckpoints 通道，增加可选内部 reviewProgress，不新增公开字段、HTTP 或数据库表。只在同一 runId、上游/视觉策略/共用提示词/设置/模板哈希一致时恢复；已改变方向不复用旧复核。恢复后仍运行全批语义复核，不跳过质量要求。
- 并行回写串行化，等待同批在途任务收尾并保存成功分片后再传播失败，避免成功结果丢失或旧调用后台继续回写。
- 记录子步骤、输入估算规模、批大小、独立超时、耗时、尝试次数和异常类别；不记录正文、原始响应或密钥。

## 验证

覆盖配置路由、不同规模拆批、内容不丢失、失败分片局部恢复、跨任务与哈希变化不复用、旧 attempt 拒绝、阶段更新保留检查点和公开投影不泄露内部数据。执行 Worker 测试、mypy/Ruff、API 相关测试/类型检查及 diff 检查。不新增付费测试，不自动提交 Git。

## 实际实现及验证结果

- `ARK_PROMPT_DIRECTION_REVIEW_TIMEOUT_SECONDS=180` 用于关系复核与全批重叠复核；普通评分仍为 120 秒。未修改模型、输出 Token 上限、生成模板或质量门槛。
- 默认 `PROMPT_DIRECTION_REVIEW_BATCH_SIZE=6`，`PROMPT_DIRECTION_REVIEW_INPUT_BUDGET=12000`。预算使用当前分片相关事实、视觉策略、空间和方向的序列化字符规模，加固定指令/Schema 余量估算；不是厂商精确 Token 数。容量较大时会少于 6 条一批，单方向超预算仍保留完整输入并记录告警信息。
- 复核进度在现有 `metadata.checkpoint.plan.reviewProgress` 中保存，不新增跨进程传输通道。恢复同时验证 runId、输入指纹、模板哈希、方案哈希和审查轮次；每个完成分片重新执行结构与 ID 校验。AI 修订进入新一轮审查时，不复用上一轮意见。
- 模拟一批连续超时：其他并行批次仍保存完成；同一 Run 换 attempt 恢复后只调用失败批次，不重新生成空间/方向。模拟全批重叠复核超时：恢复后也不重复已经完成的关系复核。
- 新 Run、上游指纹、设置、模板、方案哈希或方向内容改变时，不复用旧进度。阶段普通更新保留检查点；过期 attempt 无法写回。公开详情不包含内部 reviewProgress 或审查正文。
- Worker：`pytest` 262 passed、1 skipped（未启用付费集成测试），`mypy src` 20 文件通过，`Ruff src tests` 通过。
- API Prompt 相关测试 90 passed；API typecheck/build 通过。Compose 配置校验、Worker 镜像构建与 `git diff --check` 通过。
- 确认没有运行/排队 Prompt 任务后更新 Worker。没有创建真实付费任务、视频任务或提交工作副本，也没有自动提交 Git。

说明：自动测试证明超时预算正确路由、拆批和断点恢复有效，不证明供应商从此不会超时。拆小批次可能增加调用次数；真实耗时、费用和质量变化仍需后续同配置付费对照测试确认。
