# 效果类 Prompt 与渲染同分支保存及手动复制分支

## 目标与边界

Prompt 生成、视频渲染节点的人工编辑使用“保存修改”：已确认内容变化时更新当前分支的工作副本 revision，不自动创建树分支。仅实际受影响的下游产物待更新，原有素材、时间轴与成片保留并可编辑。整批 Prompt 或视频渲染完整成功且规范化内容变化后，继续自动产生新分支。资料导入、信息提炼及混剪、成片的确认规则不在本次修改。

版本树新增“从当前分支新建分支”：复制当前分支六节点的已确认业务状态，创建后立即激活并展示一条完整并行路径。未保存草稿和运行中任务不复制；媒体文件仅复用同项目引用，不复制二进制。

## 数据与接口

- 沿用 `WorkflowRun`、`WorkingArtifact` 及不可变 revision 快照。人工编辑仍在隔离临时 Run 内完成；Prompt／渲染保存时在同一事务中校验来源和父分支基线、将合法结果与领域记录映射回父 Run、递增内容变化的工作副本 revision、计算增量失效、恢复父 Run 为活动分支。取消编辑不触碰父 Run；无变化保存不增加 revision；临时 Run 留作任务审计但不发布。
- Prompt 下游按条目渲染输入指纹（正文、时长、共用渲染约束）比较。仅创意说明等非渲染输入改变时仍更新 Prompt 业务 revision，但不使视频失效。渲染按实际变化的片段工作副本追踪依赖；批次索引 revision 不得单独使全部时间轴失效。已有片段可保留旧的冻结来源并证明其渲染输入指纹等价；新任务固定当前 Prompt 的 `artifactId + revision + contentHash`，旧任务不能回写新结果。过期产物只作提示，不清除、锁定或自动付费重做。
- 新增项目作用域、带幂等键的手动分支创建接口及契约。服务端验证当前活动分支、无进行中的编辑、项目权限，并在同一事务内创建子 Run、复制已确认的导入／提炼／Prompt／渲染／模板／时间轴／包装／成片领域状态与工作副本，重映射分支内 ID 和依赖，原子激活。运行中的任务保留原 Run；新分支不继承其未确认结果。分支类型标记为手动完整复制，避免沿用按节点截断下游的自动分叉读取规则。
- 保存父分支前固定已有子分支继承的 `artifactId + revision + contentHash`，使其读取不可变快照而非父分支最新指针。现有子分支在部署时按当时可见的已确认内容建立基线，不尝试推断更早历史。已有媒体引用及文件保留规则继续生效。

## Web 与文档

- Prompt、渲染编辑态按钮、状态文字和返修提示统一改为“保存修改”；保存成功刷新原分支。完整批量重新生成仍自动开新分支，不添加第二个生成按钮。
- 版本树提供“从当前分支新建分支”按钮；有未结束编辑时先要求保存或取消。新分支立即从项目根节点展示并行完整路径，相同内容显示相同 revision，活动路径标红；草稿与运行任务不伪装成已确认版本。
- 更新效果类工作流指南及旧实施计划中“Prompt／渲染人工保存必定发布子分支”的过时表述；保留其他节点的原规则。

## 验收

- Prompt 单条输入变化仅使对应素材及消费者待更新；非渲染字段变化不使素材失效；无变化保存不加 revision。渲染单片段修改只影响实际引用该片段的工程与成片。
- 保存、取消、失败回滚、并发提交、任务晚到和切换分支均不污染原分支或其他分支；既有子分支在父分支保存后内容保持不变。
- 手动复制包含全部已确认六节点数据与模板，父子后续可独立编辑；重复幂等请求不创建多分支，跨项目请求被拒，媒体不重复复制，草稿和运行中任务不复制。
- 运行 API、Contracts、Web 相关单测与数据库级回归、类型检查、构建、`git diff --check`；浏览器回归 1920、1440 和窄屏下的编辑、错误、空树、复制及切换状态。

## 实施与验证

### 落地内容（按层）

- 契约 `packages/contracts/src/workflow-working.ts`：`EffectWorkflowBranch.creationKind`（`INITIAL | NODE_CHANGE | MANUAL_COPY`）、`CreateEffectWorkflowBranchRequest` / `CreateEffectWorkflowBranchData`。
- 数据模型 `apps/api/prisma/schema.prisma` + 迁移 `20260929160000_effect_manual_branch_and_edit_purpose`：`WorkflowRun.branchCreationKey`（项目 + 工作流 + 工作流空间唯一，供幂等）、`WorkflowRun.editSessionPurpose`（`MANUAL | BATCH`）。两个迁移已在 `_prisma_migrations` 确认应用。
- 编辑会话 `apps/api/src/platform/workflow/effect-edit-session.ts`：`beginEffectEditInTransaction(..., purpose)` 的复用与创建都按 purpose 区分；`exitEffectEditInTransaction` 的发布与丢弃两条路径都清空 `editSessionPurpose`。
- Prompt 保存 `effect-prompt.repository.ts`：`applyManualPromptEditInTransaction` —— 校验父分支基线语义哈希（不等则 `PROMPT_EDIT_PARENT_CHANGED`）、把子 Run 的 `workflowNodeState` / `effectPromptRun` / `effectPromptResult` 与工作副本映射回父 Run、只把 `changedPromptIds` 命中的 `render-clip` 置为待更新、以 `invalidateDependents: false` 提交、`exitEffectEditInTransaction(..., false)` 并断言退出的就是父 Run。
- 渲染保存 `effect-segment-render.repository.ts`：`applyManualRenderEditInTransaction` —— 按父 Run 定位目标批次、校验父子 Prompt 来源 revision 一致、把子任务输出文件对象迁到父 Run、必要时递增父批次 revision、只失效真正变化的 `render-clip` 下游；`commitValidatedBatchTransaction` 按 `editSessionPurpose === 'MANUAL'` 分流，`'BATCH'` 仍走 `publishEffectNodeEditInTransaction`。
- 手动复制 `apps/api/src/platform/workflow/effect-manual-branch.ts`：项目行 `FOR UPDATE` → 幂等键命中且父分支一致即返回既有分支 → 定位活动 EFFECT Run → `beginEffectEditInTransaction(..., 'MANUAL')` → 复制六节点领域状态与工作副本（ID 重映射、`manual:${childRunId}:...` 幂等键、媒体只重映射引用不复制二进制）→ 标记 `forkNodeId='MANUAL_COPY'` 并原子切换 `activeKey`。
- 接口 `workflow-working.controller.ts` / `workflow-working.service.ts`：`POST workflow-runs/effect/branches/:workflowRunId/fork`；服务层加 `manual:${parentRunId}:${key}` 命名空间与 160 字符上限校验，无可用父分支返回 409。
- 成片输出 `effect-final-output.service.ts`：三处 `fileObject` 查询去掉 `workflowRunId` 作用域，改为项目内定位——手动复制出的分支要能读到仍属父 Run 的媒体。
- Web：`EffectWorkflowBranchTree.vue` 的「从当前分支新建分支」按钮与 `forkDisabled`；`EffectImportNodePage.vue` 的 `forkCurrentBranch`（先 `flushPendingEdits`，失败即阻止并提示）与 `@fork` 接线；Prompt / 渲染编辑态按钮、状态文字与返修提示统一为「保存修改」。
- 文档：`docs/workflows/effect/agent-guide.md` 中 Prompt／渲染两条改为「保存修改覆盖当前分支、不自动开叉；整批重新生成成功且内容变化才自动开叉」；`2026-09-28-效果类工作流版本分支树与画布.md` 记录 Prompt 切片已落地。

### 验证中发现并修复的问题

1. **`applyManualRenderEditInTransaction` 用错了父批次谓词**：原先按 `activeKey: 'ACTIVE'` 找父批次，DB 实测已完成批次 `activeKey` 全为 NULL（该字段只标记进行中的批次），必然抛 `RENDER_EDIT_PARENT_BATCH_MISSING`。改为与编辑会话一致地取「`archivedAt: null, committedAt: { not: null }` + 按 `createdAt desc, id desc` 最新」。
2. **渲染分支 DB 回归还停在旧语义**：`effect-segment-render.branch.database.spec.ts` 断言「改动过的渲染保存会发布子分支」，与本计划相反。改为断言子 Run 未发布、`editSessionNodeId` 为空、活动分支仍是父 Run，且父 Run 的 `render-clip:` revision 确有前进。
3. **该用例的「变化」模拟不真实**：`artifactInputs` 的 `unchangedCurrentClip` 有意忽略 `version`，只抬 `activeOutputVersion` 不会重新提交片段（实测只有 `render-batch:` 变化），「revision 前进」断言恒为 0。改为翻转 `outputContentHash` 首位十六进制字符，真实改变片段的内容身份。
4. **Web 过期断言**：`effect-segment-render-layout.spec.ts` 仍断言按钮文案「保存版本」，页面已改为「保存修改」。
5. **补测试缺口**：版本树的新建分支按钮与禁用态（`effect-workflow-branch-layout.spec.ts`）、`forkCurrentBranch` 的先刷草稿再复制（`effect-import-layout.spec.ts`）、`WorkflowWorkingService.createEffectManualBranch` 的键命名空间与超长键拒绝（`workflow-working.service.spec.ts`）。
