# Prompt 编辑基线防回退

## 范围与证据

效果类 Prompt 人工编辑及其直接下游渲染。已采用的 Prompt 第 13 版位于同渲染谱系的已发布分支；导航入口仍保留继承的第 11 版。渲染读路径已正确采用前者，但 Prompt 编辑复制仅按导航入口选源，用户保存一次新增、删除、编辑时同时带回了旧内容。

## 实施与边界

- 编辑开始复用渲染的明确来源解析；复制实际选中的 Prompt 及其可追溯上游，不跨独立谱系、不按最大 revision、不把草稿当确认内容。
- 记录实际复制的来源身份、revision、哈希和导航写入目标版本。保存时重新解析、核对来源及目标；不一致即拒绝覆盖并保留编辑草稿。历史编辑态亦须与当前实际来源比较，不能继续用旧导航快照作为保护基线。
- 保存仍原位提交导航父 Run 的 `prompt-batch:<productId>`，不改素材采用快照，不触发模型、渲染、混剪、包装或导出。
- 用户已授权恢复当前腊肠批次：以正确采用基线为底，将旧基线到本次保存的明确条目差异机械合并，保留新增、删除 P019、编辑 P020；新条目编号使用 P037，避免与既有 P035 冲突。保留原始快照与审计，不更改语义重复度。

## 验证

- 旧继承快照与已采用新来源、真正的新人工修改、同内容、不相关谱系、隔离编辑、取消及迟到写入。
- 一次增删改只产生对应的一条新增、一条删除、一条重渲染；两轮编辑、刷新和保存冲突不误删已有条目。
- 聚焦单元与回滚数据库测试、API 类型检查、构建、差异检查；浏览器只核对工作区与更新确认，不执行付费确认。
- 现有真实批次恢复须用来源与目标 revision 围栏、事务及既有工作副本提交机制；不直接覆盖历史记录。

## 实施结果

- 编辑入口采用统一确认来源，并沿确切依赖复制提炼/资料来源；仅复制工作副本明确指向的已提交结果，忽略更新但尚未确认的完成结果。
- 保存按明确父 Run 匹配商品 ID 别名，不依赖 JSONB 键顺序；同时检查实际来源和写入目标的版本围栏。冲突返回 409，保留隔离草稿；历史无围栏的编辑态仍须通过实际来源内容核对。
- 已授权的腊肠恢复经默认回滚预演后应用，Prompt 工作副本从 revision 12 增至 13，共 34 条。当前真实差异为 P020 重渲染、P019 移除、P037 新增，各一条。旧 P035、P036 及 P006、P016 优化正文保留；语义重复度 6.67% 未变。旧 revision 快照保留，渲染批次及任务未修改，Outbox 增量为零。
- 浏览器正式页面核对：顶部局部更新 3 项，确认弹窗显示重渲染 1、新增 1、同步信息 0、移除 1；取消确认，未启动付费任务。Prompt 显示 34 条、6.7%，进入/取消编辑后保留内容与差异。
- API 聚焦回归 345 项通过（18 项环境测试默认跳过）；另行开启回滚数据库验证 11 项通过，包含正确来源复制、未确认结果排除、来源/目标冲突、旧编辑态拦截、无变化保存及三轮累计净差异。恢复工具 3 项测试通过。
- API 类型检查、非清空输出的生产构建与差异检查通过。未执行模型、视频渲染、混剪、包装、输出或 Git 提交；不将本次聚焦测试等同于全项目全量验收。
