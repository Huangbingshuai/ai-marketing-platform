## 分步实施

1. 现有 AI 执行编辑与评分后修订检查完整片段，将相同冲突及受影响的初态、动作、镜头、结果和终态一起修正；输出仍采用原有局部补丁，不加一次模型调用。Worker 只应用合法字段、校验结构和身份。
2. JSON 批次先解析信封，再逐条执行原严格 Schema，保留结构有效条目；记录安全错误类别，不记录原文。只请求缺失条目，结构有效草稿在后续请求前保存到现有分片；恢复时只请求未取得的条目。永久结构错误隔离到条目，网络失败或取消中止后续调用。全部草稿仍须完成原 AI 执行编辑后才能计入可用候选。
3. 方向容量由规划 AI 根据独立观看价值决定，每方向 1～5 条，不再机械生成相同数量的替代机位路线。Worker 只按已返回路线的数量与稳定 ID 安排任务，不判定路线是否相似。初始和多样性候选不循环复用事件填满冗余池；最终用户数量不变，不足仍进入原有数量补充。历史无路线检查点保持读取，数量恢复继续数量优先。第一轮只部署前两项；等待时在本地准备第三项，第一轮结束、报告后再部署比较。
