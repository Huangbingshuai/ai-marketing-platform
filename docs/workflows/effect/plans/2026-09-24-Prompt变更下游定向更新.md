# Prompt 变更后的下游定向更新

## 目标

统一效果类 Prompt、视频渲染、模板混剪、成片输出的版本更新行为，确保 Prompt 确认变更后，下游明确显示待更新且保留可恢复数据；全量 Prompt 更新允许重新渲染与重新智能填充/包装，单条或多条 Prompt 更新只影响对应素材及其实际使用的成片工程。

## 范围

- Prompt 已确认 WorkingArtifact 的变更识别与依赖粒度。
- 渲染节点对全量/部分 Prompt 变更的待更新呈现和定向重新渲染入口。
- 模板混剪保留模板配置；全量上游更新后可重新智能填充与智能成片包装。
- 单条/多条 Prompt 更新只让相关渲染素材及引用这些素材的变体待更新，并使相关包装和成片输出不再作为当前版本使用。
- 成片节点停止把已过期结果作为当前有效工程展示/继续导出；历史结果与文件可恢复，不做无提示硬删除。

## 非目标

- 不自动发起 Seedance、语音、音乐或 FFmpeg 任务，避免无确认的成本与覆盖。
- 不清除混剪模板的六槽位配置、模板命名及工程结构。
- 不删除数据库中的历史产物、导出文件或项目资产；“移除”指从当前可继续编辑/导出的有效集合中撤下，并提供过期/历史状态。
- 不修改效果类固定节点顺序和既有显式确认/WorkingArtifact 提交边界。

## 当前链路与待解决问题

- Prompt 确认结果当前主要写入 `prompt-batch:<productId>`；渲染批次也冻结整个 Prompt artifact 的 revision/hash。
- 每个 `render-clip:<taskId>` 当前依赖同一个 Prompt 批次 artifact，因此只修改单条 Prompt 也可能将整批渲染、混剪、包装、成片递归标记为 STALE。
- 渲染批次的启动、完成校验都要求批次级 Prompt revision 完全相同；因此部分 Prompt 更新后，不能可靠地只重做受影响片段并保留其余素材。
- 混剪模板与时间轴工程虽分别保存，但全量 Prompt 更新后旧绑定/包装必须从活动编辑与输出流程撤下，同时保留模板配置供重新填充。
- 成片 Worker 按冻结依赖校验；已完成文件应继续作为历史记录，不应因上游更新而物理删除。

## 目标规则

1. Prompt 草稿/候选变化不触发下游更新；只有 Prompt 明确确认且规范化内容变化后触发。
2. Prompt 依赖按稳定 Prompt ID 细化，同时保留批次级设置/资料来源依赖。单条内容变更只失效其对应渲染片段；批次公共参数或全量重生成导致所有 Prompt 实际输入变化时，全量失效。
3. 渲染重做仍由用户显式触发。仅新版本素材对应的 render clip artifact 更新；未变 Prompt 的现有素材继续可用。
4. 混剪模板配置与素材绑定/视觉时间轴分离。上游全量失效时保留模板和变体结构，清空/归档旧填充绑定及其包装草稿，并显示“素材已更新，请重新智能填充”；部分失效时只标记引用受影响素材的变体待更新。
5. 部分失效变体在素材重做后优先按稳定 Prompt/素材身份原位重新绑定，保留槽位、顺序、裁切与手工编辑；无法合法保留时提示重新智能填充。受影响的口播/字幕/配乐包装应撤下并要求重新智能成片包装。
6. 成片输出按模板+变体版本撤下过期工程的当前状态，不再允许基于其旧包装继续导出；保留旧文件及任务作为历史版本。
7. 更新检查必须按 `projectId + workflowRunId` 隔离，使用乐观 revision、哈希和任务 attempt 防止并发旧结果回写。

## 实施顺序

1. 盘点 Prompt、渲染、混剪、包装和成片的 artifact keys、存储状态、重试 API 与 UI 状态；补充可回归的跨层失效测试。
2. 增加 Prompt 项级可追溯工作副本或等价的稳定子版本快照，并提供历史批次兼容/懒迁移；所有跨进程 DTO 只在 contracts 定义。
3. 调整渲染工作批次，使任务记录各自消费的 Prompt 子版本，支持只对变更 Prompt 创建任务并合并到当前素材池。
4. 调整模板混剪状态机，区分模板配置、视觉填充、包装版本；全量更新重置活动填充/包装而保留模板，部分更新只处理引用受影响素材的变体。
5. 调整成片节点有效性筛选与 UI 提示，过期输出保留历史但不可误认为当前/继续导出。
6. 最后执行 API/Contracts/Web 测试、类型检查、构建、diff 检查及浏览器回归。

## 验收

- 重新生成/编辑未确认 Prompt 时，下游状态不变；无差异确认不增加 revision。
- 全量 Prompt 确认变更：全部旧渲染标记待更新；混剪模板还在；旧绑定、包装和成片从当前输出面板撤下；新渲染完成后可智能填充及智能包装；旧资产可在历史中找回。
- 单条或多条 Prompt 确认变更：仅对应素材待重渲染；无关素材和工程继续可用；相关工程在重渲染后保留可合法复用的剪辑编辑，但旧包装/成片不能继续作为最新版本。
- 新素材完成渲染校验后，仅对确实引用其旧版本的已填充成片显示“更新受影响素材位”按钮；点击后固定现有槽位素材归属和时间轴布局，只对这些槽位的新素材抽帧并重新选择源片截取起点。其他槽位的素材和截取点不得重算；旧截取点只可作参考，不可越过新素材时长约束。
- 受影响素材位重算成功后仍只更新混剪节点草稿；用户完成混剪校验后，才进入受影响槽位的口播/字幕更新与最终成片重导出。旧混剪、包装及成片保留为历史版本，不覆盖、不物理删除；在新链路确认前不得把旧包装当作新素材对应的当前输出。
- 旧 Worker 回写、跨项目/Run 数据、丢失素材、部分失败、取消与重试不得覆盖新的确认结果。
