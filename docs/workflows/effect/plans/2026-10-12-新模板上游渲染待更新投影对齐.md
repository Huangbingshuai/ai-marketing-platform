# 新模板上游渲染待更新投影对齐

## 观察与边界

效果类片段渲染、模板混剪的顶部画布展示。新模板实际消费最新已确认渲染素材工作副本，不因普通导航、新建模板或填充任务改变上游 revision。

只读核对“广式腊肠”当前渲染源：渲染接口返回 34 条、`stale=false`、`refreshScope=NONE`、无待处理 Prompt；新模板来源同样为 34 条，后台智能填充已在运行。版本树将上游渲染判为就绪，但通用工作副本投影包含历史依赖闭包中的 STALE 记录。画布在版本树/素材投影读取尚未结束时回退通用计数，产生与真实渲染工作区不一致的橙色告警。

## 修改

- 上游四节点只采用现有服务端版本树的当前路径状态；不以包含历史依赖闭包的通用工作副本列表替代上游状态。
- 收到同项目、同作用域的有效版本树后立即更新其节点状态，不等待混剪素材来源、多模板路径的读取；混剪和输出仍保持各自精确依赖计算，不改为全局清零。
- 初次未知不伪造待更新；真实待更新继续展示，短暂读取故障保留最后可信状态，旧项目/Run 迟到响应不得回写。
- 无数据库、Contracts、API、Worker 变更，不修改已有填充输入、来源身份或 revision，不重启进行中的任务、不自动启动付费任务，不提交 Git。

## 验证

覆盖版本树延迟、素材来源延迟、历史 STALE 闭包、真实 Prompt 变化、失败保留告警、切换项目/Run 及迟到响应。执行相关画布、混剪来源单测、类型检查、构建和 diff 检查；浏览器检查三种宽度的实际状态，不重新生成用户素材。

- `pnpm --filter @ai-marketing/web exec vitest run` 指定 canvas-freshness、canvas-edit-freshness、canvas-mix-freshness、source-catalog、template-catalog 五个文件：58 项通过。新增异步回归验证树延迟时历史 STALE 不反向标黄、混剪来源挂起时上游真实状态立即展示，以及真实 STALE 在读取故障后不被清除。
- `pnpm --filter @ai-marketing/web typecheck`、`pnpm --filter @ai-marketing/web build`、`git diff --check` 通过；构建只有既有大分块提示。
- 浏览器刷新后只读查看新“测试1”工作台，用户先前启动的智能填充已完成，观察到 45 条工程。1920、1440、768 宽度均显示“片段渲染 就绪”，无错误横条。截图：[1920](../evidence/browser/2026-10-12-new-template-render-freshness-1920.png)、[1440](../evidence/browser/2026-10-12-new-template-render-freshness-1440.png)、[768](../evidence/browser/2026-10-12-new-template-render-freshness-768.png)。
