# 效果类 AI 信息提炼移除表单分支与资料包整理实施方案

状态：已完成

## 目标

当前信息卡已统一为产品基础信息和卖点列表，但提炼子工作流仍保留了不再提供业务事实的表单配置分支，仓库内效果类产品资料包也仍是旧的卖点、受众、痛点和场景分层格式。本次同时收敛工作流与资料格式，让文档中每条卖点可直接进入当前信息卡。

## 子工作流

新任务只执行：

```text
资料快照
→ 文档解析 / 图片识别 / 电商链接
→ 多源融合
→ 语义整理
→ 标准化与结果保存
```

- 从公开拓扑、Worker LangGraph、API 状态和前端工作流弹窗移除 `FORM` 节点。
- 产品名称、品类和其他基础信息只从文档、图片、电商资料或人工修改获得，不再从资料导入页的表单候选值融合。
- 人工修改仍由提炼结果草稿和 `manualOverrides` 保护，不依赖表单分支。
- 历史 Run 中已存在的 `FORM` 记录不删除数据，但不再出现在当前工作流图、来源归因或新任务中。

## 资料包格式

修改仓库内 11 份效果类产品资料包和 1 份下载模板，统一为：

1. 产品基础信息：品类、产品名称、核心规格、价格带和核心外观特征。
2. 卖点：逐条编号的统一卖点列表，不再划分核心、次要、受众、痛点或场景。

卖点整理规则：

- 每条只表达一个可独立理解的产品事实或使用价值。
- 删除营销目标、空泛情绪、购买场景、重复包装描述和只是换词的同义表达。
- 保留有资料依据的规格、原料或材质、结构、感官、性能、操作方式、适用人群与真实使用场景。
- 新增的创意方向必须能由资料中的确认属性推导，不增加功效、认证、销量、未确认工艺或其他硬事实。
- 文档标题和字段名称与确定性文档解析器保持一致，不为字段搬运调用文档 AI。

## 生命周期边界

- 直接上游仍是已确认的产品资料包 `artifactId + revision`。
- 生成和人工修改只更新待确认提炼草稿与 `WorkflowNodeState`。
- 用户点击完成校验且内容指纹变化后，才提交 `marketing-insight:{productId}` 新 revision。
- 只有已经消费旧营销洞察 revision 的 Prompt 结果才标记待更新。
- 重写仓库内示例资料包不自动修改数据库中的已上传资料，用户重传并确认后才产生新资料包 revision。

## 验证

- Contracts、API、Web 和 Worker 对新拓扑一致，新 Run 不产生 `FORM` 分支。
- 文档、图片或电商链接任一有效来源可独立完成融合，无任何可用来源时明确失败。
- 人工修改、内容指纹、WorkingArtifact revision 和 Prompt 待更新规则保持不变。
- 12 份 DOCX 均使用文档运行时生成，逐页渲染检查，并通过 Docling 与确定性解析器回读。
- 每份示例资料包不存在完全重复卖点，不包含营销目标或视频制作配置，且至少覆盖产品属性、使用方式和差异化场景。
- 执行 Worker pytest、mypy 与 Ruff，Contracts/API/Web 单测、类型检查、构建与 `git diff --check`。

## 实施结果（2026-09-10）

- Contracts、API、Worker 和 Web 已统一移除当前 `FORM` 节点；新任务只执行文档、图片和电商三个资料分支，历史数据库中的旧 `FORM` 记录只在 API 内部类型边界容纳，当前执行图和节点详情不展示。
- 11 份商品资料包与 1 份下载模板已统一为“产品基础信息 + 卖点”格式。商品资料各包含 14～16 条去重卖点，覆盖确认的产品属性、外观或感官、操作方式和差异化使用场景，不包含营销目标、视频配置或无依据功效。
- 12 份 DOCX 经 Docling 与确定性解析器完整回读；全部文档均为单页。捆绑运行时未提供 LibreOffice，标准渲染器因此无法启动，改用本机 Word 只读导出 PDF，再由捆绑 Poppler 转为 PNG，并逐页完成视觉检查。
- 浏览器实页确认工作流弹窗为 `资料快照 → 文档/图片/电商 → 多源融合 → 语义整理 → 标准化与结果保存`，无“表单配置”节点，桌面布局无溢出。
- 测试结果：Worker `91 passed, 5 skipped`；Contracts `26 passed`；API `292 passed`；Web `201 passed`；Contracts/API/Web 类型检查、API/Web 生产构建、相关 ESLint、mypy 与 `git diff --check` 通过。Worker 当前开发环境未安装 Ruff 可执行文件，因此未单独执行 Ruff；Python 单测与 mypy 均通过。
