# 效果类 Prompt：创意方向均衡分配修复计划

> 状态：已完成

## 一、问题与证据

真实 50 条任务的语义重复度达到 80%。批次评估本身计算正确，异常来自候选生成前的创意方向分配：70 个初始候选中，同一个“家庭餐桌煲仔饭开盖”方向被分配 23 次，其他方向仅得到 4～12 次。

旧算法先把方向归入粗粒度场景原子，再平均分配场景桶。五个厨房方向被压缩为一个桶，而单独的餐桌方向独占另一个桶，导致“场景桶均衡”反而破坏了“具体创意方向均衡”。补充生成又可能重复使用相同的“方向 + 主要事实”，进一步放大正文相似度。

## 二、修复范围

- 创意方向按“真实场景原子 + 具体主动作”识别分配桶。
- 每个具体方向获得独立数量上限，70 个任务、8 个方向时每个方向最多 9 个。
- 同一批次的初始生成和定向补充共享已使用的“方向 + 主要事实”记录，优先选择未使用组合。
- 创意方向模型输出至少覆盖 5 种场景动作组合，同一组合最多出现 2 个方向。
- 保留现有事实边界、共用提示词、质量评估、语义重复度和精确数量生命周期，不调整 API、前端或 WorkingArtifact 提交边界。

## 三、非目标

- 不降低 82% 相似判断标准和 `<15%` 重复度目标。
- 不通过隐藏或篡改重复度解决问题。
- 不改变 Prompt 总数量、时长、用途分类或下游 Seedance 请求结构。

## 四、验收标准

- 复现生产方向结构时，70 个任务在 8 个方向间分配为每个 8～9 个，原先 23 个的单方向不再超配。
- 方向规划存在三个以上相同场景动作组合时直接拒绝并重试规划。
- 14 个初始候选和 2 个补充候选能够使用不同的方向事实组合并参与向量评估。
- Worker 全量单元测试、Ruff、Mypy 与 `git diff --check` 通过。

## 五、实际实施与验证结果

- 分配器已从“粗场景桶轮转”改为“场景动作桶负载均衡 + 单方向数量上限”。
- 生产问题结构的回归测试中，70 个候选在 8 个方向间分配为 8～9 个，餐桌方向不再获得 23 个任务。
- 初次生成和定向补充会恢复并复用已使用的“方向 + 主要事实”组合记录，降低补充阶段重复同一创意骨架的概率。
- 创意方向规划结果新增场景动作组合校验：8 个方向至少覆盖 5 种组合，同一组合最多 2 个方向。
- Worker 全量 Pytest、Ruff、Mypy 和 `git diff --check` 已通过。
