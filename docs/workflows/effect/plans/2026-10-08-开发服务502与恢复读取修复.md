# 开发服务 502 与恢复读取修复

## 证据与边界

13:47 的日志出现 `Cannot find module apps/api/dist-dev/main`；当前同时存在两个使用同一 dist-dev 的 Nest watcher。Prompt 直连 3100 和经过 5173 代理现已返回 200（约 20ms），但源码变更时重复编译/重启仍会复发。Redis 命中无法解决 API 进程暂时不存在。

本次只调整本地 API 启动保护和共用 JSON 只读请求的短时重试，不更改节点草稿、确认产物、上游 revision、缓存契约或生成任务。

## 实施与验收

1. API dev 入口增加按工作区隔离的进程互斥；重复启动不再创建第二个 watcher。检查已有直接启动的 Nest watcher，保留明确的诊断信息。互斥随进程退出释放。
2. JSON GET 遇到 502/503/504 或网络断连时有界重试；保留 AbortSignal，取消/切换作用域即停止等待。写请求、鉴权和业务错误不重试，防止重复业务操作。原始文件请求保持现状。
3. 确认没有活动任务后，只停止已核实的重复 API watcher，启动单个新入口；不重启 Redis 或 Worker。
4. 覆盖互斥并发/释放、GET 成功恢复/持续失败/取消、写请求不重试、普通 4xx/500 不重试；类型、构建、相关测试及 git diff --check。
5. 浏览器确认 Prompt 已恢复；通过代理连续读取并验证再次启动 dev 不改变监听进程。记录开发热更新仍存在短暂重启窗口，不承诺生产零停机。

## 实施结果

上述调整已实施。互斥和旧 watcher 识别采用现有 Vitest 测试框架，3 项测试通过；共用 HTTP 客户端及 Prompt/节点切换相关回归共 72 项通过。Web/API 类型检查、Web 生产构建及相关 ESLint 通过。实际重复启动不会创建新的 watcher，Prompt 经过 5173 代理连续 15 次读取均返回 200；最新一次采样 16–123ms。浏览器刷新恢复 20/20 条 Prompt。

启动入口保持 Nest 当前支持的相对 tsconfig 参数，通过工作区内 CLI 路径保留进程识别信息；未使用绝对 tsconfig 路径。验收过程中发现的该兼容问题已修复，并重新启动验证当前服务。

当前 Windows 运行入口 PID 40436、唯一 Nest watcher PID 13492（PID 会随后续运行变化），运行进程指向 dist-dev/main。迁移前查询异步任务、返修及项目删除任务均为零，只停止核实属于本工作区的 API 子树；未重启 Redis、Worker 或触发生成。

开发重启超过 5 秒、持续服务故障仍会显示错误；这不是生产零停机方案。未在生产部署或其他操作系统回归。浏览器曾记录 13:56 时段的资料导入 HMR 上下文异常，当前完整刷新后 Prompt 已恢复；没有据此宣称整站所有历史错误均已排除。
