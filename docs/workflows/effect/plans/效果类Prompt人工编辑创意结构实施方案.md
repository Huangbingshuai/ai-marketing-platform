# 效果类 Prompt 人工编辑创意结构实施方案

## 目标

允许用户在人工新增或编辑 Prompt 时同步维护片段主用途、创意主线和六维创意信息，并明确提示这些结构化内容会参与视频生成，需与正文保持一致。

## 实现边界

- 复用现有 Prompt 节点草稿、`ITEM_EVALUATE` 异步任务和 WorkingArtifact 提交边界，不新增业务节点或数据库表。
- 编辑已有 Prompt 时预填当前创意主线和六维；新增 Prompt 时允许留空交由 AI 从正文补齐，也允许用户完整填写。
- 人工填写结构后，评估器只校验产品事实、正文与结构一致性、用途和质量，不覆盖用户填写的创意主线与六维。
- 正文、创意主线和六维必须作为同一组视频生成输入；共用提示词仍只追加一次。
- `PENDING` 与 `NEEDS_REVISION` 条目继续阻止完成校验和视频渲染。

## 契约与校验

- Prompt 条目新增/编辑请求增加可选 `primaryPurpose` 与 `creativeCore`，继续复用现有可选 `dimensions`。
- 创意主线与六维必须同时缺省或同时完整提供，禁止只提交部分结构。
- API 校验字段长度并保存人工结构；没有人工结构时写入待分析占位内容。
- Worker 根据目标条目是否仍为待分析占位，决定“推导结构”或“保留结构并评估”。

## 页面交互

- 编辑弹窗增加创意主线和六维输入区。
- 提示用户人物、场景、产品动作、镜头和情绪需要与 Prompt 正文一致，并明确这些字段会影响后续视频生成。
- 编辑弹窗不提供自动 AI 分析开关；保存只更新 `PENDING` 草稿，用户可从卡片单独启动评估。

## 验收

- 编辑已有条目后主用途与七个结构字段按原值回填并可修改。
- 部分填写结构时前端和 API 均拒绝保存。
- `ITEM_EVALUATE` 不覆盖人工填写的创意主线和六维，但会更新事实绑定、用途、质量状态和重复度。
- 未填写结构的新条目仍可由 AI 从正文补齐。
- Seedance 请求包含正文、创意主线和六维，且共用提示词只出现一次；请求哈希随任一结构字段变化。
- 执行 Contracts、API、Worker、Web 相关测试、类型检查、构建、浏览器回归及 `git diff --check`。
