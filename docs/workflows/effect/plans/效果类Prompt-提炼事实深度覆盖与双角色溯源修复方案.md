# 效果类 Prompt：提炼事实深度覆盖与双角色溯源修复方案

状态：已完成

## 一、问题与目标

当前 Prompt Worker 已完整读取营销洞察，但事实经过“创意方向规划、单条分配、生成声明、质量评估、最终绑定”后逐层收缩。实际批次会反复保留产品名称、规格和外观，而核心卖点、痛点、受众、决策动机、购买场景与营销目标大量缺失。

本次保持效果类第 3 节点现有八阶段拓扑、HTTP 路径、Prisma Schema 和 WorkingArtifact 提交边界不变，修复以下问题：

- 整批创意方向没有覆盖全部必用事实；
- 业务背景事实影响了创意，却无法进入评估和溯源；
- 语义上真实使用的场景、受众和动机因字面不一致被误删；
- 最终择优只考虑质量与差异，没有优先保留承担缺失事实的合格候选；
- 页面把直接画面依据和创意背景依据混在一起，无法解释事实如何被使用。

## 二、实现范围

### 1. 整批事实调度

- 创意方向模型继续负责当前批次的 8～12 个创意方向。
- Worker 校验方向引用后，确定性地把尚未进入方向的必用事实分配到负载最小、业务关系相容的方向。
- 自适应事实可以进入方向候选，但不作为完成校验的硬条件。
- 单条任务仍只接收一个视觉任务、最多两个业务背景和产品锚点，不把完整信息卡重新塞给单条生成模型。

### 2. 双角色事实评估

- `visualTask` 继续表示正文需要直接实现的事实。
- `businessContext` 继续表示用于决定场景、人物、动作、叙事和商业语气的事实。
- 质量评估器同时接收两类已分配事实；业务背景必须引用正文中的真实短证据，但不再要求与信息卡原文机械重复。
- Worker 继续拒绝未知事实、未分配事实、虚构事实和抽象卖点的视觉证明。

### 3. 覆盖感知择优

- 现有质量与新颖度权重保持不变。
- 在仍有必用事实未覆盖且存在合格候选时，先在能够补齐缺口的候选中按原有质量与新颖度公式择优。
- 没有可补齐候选时继续正常选满数量，不以覆盖问题制造短批次。
- 最终仍缺少必用事实时标记 `NEEDS_REVIEW`，不伪造绑定。

### 4. 结果与页面

- 复用现有 `PRIMARY / CONTEXT / EVIDENCE` 角色，不新增数据库字段。
- 每条 Prompt 将“画面直接依据”和“创意背景依据”分组展示。
- 恢复批次 `insightCoverage` 指标，记录必用、已覆盖、缺失、自适应暂未使用、排除及全局约束。
- 工作流详情只展示安全数量和业务标签，不展示事实 ID、模型输入或内部 JSON。

## 三、生命周期边界

- 直接上游仍为已提交的营销洞察与全局视频配置具体 revision。
- 生成、评估和覆盖重算只更新 Prompt 领域草稿与 `WorkflowNodeState`。
- 只有用户完成校验后才提交 `prompt-batch:{productId}` WorkingArtifact。
- 本次不修改第 4～6 节点，不执行视频渲染，不自动提交或推送 Git。

## 四、验收

- 创意方向计划覆盖全部必用事实，未知或排除事实仍被拒绝。
- 业务背景事实能够通过正文真实语义证据进入 `CONTEXT` 绑定。
- “新春递送腊肠”可以绑定“年货送礼”，但不能因此绑定未出现的礼盒、折扣或工艺证明。
- 最终选择在合格候选存在时优先覆盖尚未使用的必用事实。
- 批次覆盖指标与每条绑定一致，缺失事实使批次进入 `NEEDS_REVIEW`。
- 页面分开展示直接依据和创意依据，历史结果仍可读取。
- 执行 Worker pytest、mypy、Ruff、Contracts/API/Web 相关测试、类型检查及 `git diff --check`。

## 五、真实结果

- Worker 将全部必用和自适应事实补入兼容创意方向，并按“当前使用次数、必用优先级、来源顺序”轮动单条事实焦点；50 条目标的 70 个候选任务不会再长期只领取产品名称和规格。
- 评估器同时接收直接事实与已分配的语义背景事实。受众、痛点、动机、营销目标、卖点和三类场景可凭正文中的真实语义证据绑定；产品名称、规格和视觉特征仍必须作为直接事实校验，不能借“背景”名义冒充已使用。
- 精确数量选择保留原质量与新颖度公式，但在有合格候选时优先补齐尚未覆盖的必用事实；无法补齐时仍选满数量并将结果标记为 `NEEDS_REVIEW`。
- 结果契约恢复 `insightCoverage`，API 在人工修改、删除和重新评估后重新计算覆盖；页面把“画面直接依据”和“创意背景依据”分开说明。
- 浏览器在本地正式页面验证了展开/收起和两类依据分组；未触发新的付费生成，旧批次不会被原地伪造新绑定，需重新批量生成后才能看到新的覆盖结果。

实际验证：

- Worker：`pytest -q` 全量通过（1 项外部集成测试按配置跳过），`ruff check .` 通过，`mypy src` 通过。
- Contracts：构建通过，3 个测试文件共 17 项通过。
- API：类型检查和生产构建通过；Prompt 质量、节点详情、服务测试 3 个文件共 42 项通过。
- Web：类型检查和生产构建通过；事实依据布局与状态测试 2 个文件共 6 项通过。
- `git diff --check` 通过。
