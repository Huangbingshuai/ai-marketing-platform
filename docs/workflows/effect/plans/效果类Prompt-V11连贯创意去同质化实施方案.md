# 效果类 Prompt V11：连贯创意去同质化实施方案

## 1. 状态与范围

- 状态：已完成
- 开始时间：2026-08-28
- 工作流：效果类
- 业务节点：第 3 节点“Prompt 生成”

本轮在现有 V11 事实分配、连贯创意生成、独立评估和精确数量选择基础上，提高单条提示词的完整性和批次差异化。只修改 Prompt Worker、模板、测试和文档；不修改视频渲染节点，不增加模型调用，不改变 V6 公共结果、HTTP 路径、Prisma Schema 或 WorkingArtifact 提交边界。

## 2. 生命周期边界

- 直接上游仍为已提交且为 CURRENT 的营销洞察与全局视频配置具体 revision。
- 生成、评估和选择只更新领域草稿与 `WorkflowNodeState`。
- 只有用户完成校验后才更新 `prompt-batch:{productId}`。
- 第 4 节点继续消费已提交 Prompt；本轮不实现 Seedance 视频生成或模型二次改写。

## 3. 改造内容

### 3.1 连贯创意模板 V3

- 创作角色改为厂商无关的产品素材创意导演。
- 单次调用继续同时生成创意主线、六维和完整正文。
- 正文必须包含商品相关的主体、场景、连续动作、产品表现、镜头和必要的光线/情绪。
- 每条镜头与光线必须服务当前动作和产品事实，不得批量套用统一正向质感前缀。
- 不为追求差异使用与产品、受众或可信场景无关的实验室、书桌、长椅等画面。
- 抽象配方、成分、工艺和背书不得被包装成肉眼可证明的纹理、光泽或效果。
- 已有语义和视觉签名只用于软避重，不能迫使模型牺牲产品相关性。

### 3.2 独立评估模板 V2

一次评估调用内部采用五个窄职责视角：商品事实、创意连贯、可见动作、商业素材价值、差异与套路。评估器仍只诊断、评分和分类，不重写正文。

- 商品无关、事实捏造、严重六维冲突、多独立场景和不可执行画面属于硬问题。
- 通用质感词堆砌、目的句代替可见动作、普通相似和镜头表达偏集中只属于软提醒。
- `hardIssues` 与 `warnings` 使用稳定问题码，避免自然语言建议污染批次统计。

### 3.3 Worker 软诊断与选择

- Worker 对“电影感、高级质感、浅景深、暖色调”等成组堆砌增加确定性软提醒，不直接淘汰。
- 对“展示品质、体现卖点、营造氛围”等目的句增加软提醒，要求后续候选优先使用可见动作。
- 新颖度从场景、人物、产品关联点、镜头四维升级为叙事、场景、人物、产品关联点、镜头、情绪全六维。
- 完全重复继续硬淘汰；普通相似只降低排序。

## 4. 兼容与测试

- 模板版本升级后只影响新 Run，历史 V11 分片和 V5/V6 结果继续可读。
- ITEM_REGENERATE 和 BATCH_GENERATE 使用同一 V3 规则；ITEM_EVALUATE 不重写用户正文。
- 测试覆盖模板职责、稳定问题码、通用套话软提醒、目的句软提醒、全六维新颖度以及现有事实证据和精确数量回归。
- 执行相关 pytest、mypy、Ruff 与 `git diff --check`，真实 Ark 与 Seedance 默认不调用。

## 5. 实施结果

完成内容：

- 连贯创意模板升级为 `effect-prompt-v11-coherent-creative-v3`，移除生成角色与 Seedance 的直接绑定，明确一次调用输出完整素材 Prompt。
- 模板增加镜头—动作关系、产品相关场景、统一正向套话、目的句和抽象事实视觉证明边界；已有签名继续作为软避重信息。
- 独立评估模板升级为 `effect-prompt-v11-creative-evaluation-v2`，一次调用内使用商品事实、创意连贯、可见动作、商业素材价值、差异与套路五个窄职责视角。
- Worker 增加 `GENERIC_STYLE_STACKING` 和 `PURPOSE_SENTENCE_INSTEAD_OF_VISIBLE_ACTION` 两项确定性软提醒，不改变候选硬通过结果。
- 回退新颖度计算从场景、人物、产品关联点、镜头四维扩展到完整六维；当前工作区已有的向量/影子选择改造保持不变。

## 8. 两次付费质量对比

第 1 次真实批次使用当前广式腊肠 revision 2、50 条、统一 15 秒，60 条创意候选均生成成功。评估阶段按每片 5 条执行时，多次出现 Ark 返回 `status=completed` 但严格 JSON 提前结束；其中一个分片在一次格式恢复后仍失败，整批未保存结果。该批次如实计为失败测试，不作为质量提升样本，也未写入领域草稿或 WorkingArtifact。

根据这次真实故障，评估分片从 5 条缩小到 3 条。评估内容和评分标准不变，滑动并发不变；修正目的仅是降低单次严格结构化输出长度，避免局部格式异常使整批付费生成作废。修正后的相关 pytest 22 项、mypy 和 Ruff 均通过。

人工逐条复核进一步发现：

- `P003、P006、P014、P023、P041、P049` 仍用肉纤维、粉质感或观察切面暗示“纯猪肉无淀粉”，模板中的禁止边界没有被稳定执行。
- `P039、P044` 仍把成品光泽或摆放糖酒料汁与糖酒腌制工艺直接关联，存在把抽象工艺画面化的风险。
- `P009、P040` 出现拆开腊肠后未经烹制直接品尝，`P019` 让顾客隔着包装闻到风味，存在食品使用逻辑错误。
- `P016、P021、P045` 在 15 秒内安排较长操作链或三种完整做法，可执行性被模型高分掩盖。
- 50 条中 30 条仍在厨房、27 条包含切制动作；虽然六维字符串各不相同，但业务语义并没有形成同等程度的差异化。

结论：V3 在镜头与动作衔接、正文完整度和平均评分上有可确认的小幅提升，并保持 50 条精确数量、商品相关和无完全重复；但提升没有达到“大幅提升”。抽象事实的画面证明、食品使用常识、场景集中和局部同质化仍未解决。后续不能只继续润色生成模板，应把“不可视觉证明事实”“必须烹制后食用”和场景族群覆盖加入事实分配与确定性评估，再取得新的付费授权后复验。本轮没有调用 Seedance，也没有写入领域草稿或 WorkingArtifact。
