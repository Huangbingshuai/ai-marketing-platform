# 混剪模板删除版本冲突自动核对

## 边界

效果类第五节点模板混剪。共享上游仍是已确认 Prompt、渲染素材及其实际 revision；本次只修正明确确认删除后的 Web 请求衔接，不生成任务或修改上游。继续使用现有删除 API、删除回执及后台配置/工程/包装/交付清理；共享上游和其他模板不变，不新增契约、表或删除协议。

## 原因与实施

删除请求直接发送本地整个 `TEMPLATE_MIX` 草稿 revision。其他模板删除、后台清理及导航保存推进草稿版本后，缓存版本可能过期，即使目标模板内容相同也遭到 409 拒绝。服务端严格 revision 校验保留。

- 原删除请求若遇到明确“模板已修改”的 409，自动只读加载该目标真实 Run 的最新工作区。
- 冻结确认后已保存的目标模板内容，复用草稿合并的确定性可编辑内容比较；忽略服务端计算锁定和状态，不忽略真实配置、工程、包装轨道或人工归槽。
- 最新目标与确认内容一致，且当前项目、Run 作用域和模板当前路径仍一致、本地目标未再编辑时，用最新 revision 有界重发一次。真实变化、第二次冲突、切换作用域或普通网络错误不盲目删除。
- 核对读取不安装整份远端草稿，不覆盖其他模板的本地修改；受理后立即移除模板并释放提交态，不等待后台文件/缓存清理或全工作区读取。

## 验证

覆盖缓存版本过期但目标不变、导航/其他模板变化、目标真实变化、读取期间本地编辑、跨项目/Run/模板路径切换、第二次冲突与失败后可再次删除。原有异步删除、兄弟分支及共享上游保护测试继续运行。执行 Web 类型检查、构建和 diff 检查；浏览器检查三种宽度及确认取消，不实际删除用户的 48 条工程进行验收、不启动付费任务、不自动提交 Git。

- Web `vitest run` 指定 deletion-action、deletion、draft-race、template-catalog 与 shared/deletion 五个文件：59 项通过。实际执行 SFC 删除动作和 hydrate 逻辑，覆盖一次自动核对重发、真实远端/本地编辑拒绝、跨作用域丢弃、二次冲突停止、保留无关编辑、删除回执不等待全工作区读取。
- API `EFFECT_TEMPLATE_DELETE_DATABASE_TEST=1` 指定 deletion 和 deletion.database 两个文件：12 项通过。使用随机私有 PostgreSQL schema 验证真实异步清理、租约失效、防复活、兄弟分支/共享来源保护；不迁移公共数据库或删除用户数据。
- Web 类型检查、生产构建及 `git diff --check` 通过；构建仅有既有大分块提示。未改 API/Worker/Contracts，未重启服务。
