# 效果类 Prompt：事件差异化与部分补充恢复优化

状态：实现及自动回归完成，真实效果待验收。2026-09-10。

## 依据与目标

正式紫苏梅子酱项目上一轮 50 条 × 15 秒：语义重复度 52%，初始目标 70 条实际保留 55 条，事实补充后候选池 65 条；多样性补充的少数方向持续结构错误，导致已保留的有效方向未进入 AI 复核。独立事实和不同六维标签不等于不同画面事件。

目标：从规划和生成输入减少近似事件，恢复有效补充利用率；不调高重复阈值，不用降低质量标准换数量，不做单商品规则。

## 范围与非目标

- 仅效果类 Prompt Worker 内部及模板、测试；不新增节点，不修改公开 DTO、HTTP、Prisma、模型路由、候选总量或评分/MMR 权重。
- 沿用 `marketing-insight:{productId}` 的已提交 artifact/revision 快照及统一卖点；当前正式测试基线消费提炼 revision 1。
- 自动生成仅更新领域草稿与 WorkflowNodeState；用户完成校验才提交 `prompt-batch:{productId}`，之后视频渲染消费该 revision。此次改造不确认、不覆盖工作副本、不运行视频渲染。
- Worker 仅处理来源、ID、结构、数量、重试和 AI 结论；事件相似、事实关系和物理合理性由 AI 判断，不引入字符匹配或商品关键词。

## 实施

1. 规划模板以可见事件和商品价值为差异单位；区分独立素材与同事件替代机位，事实数量不能冒充创意容量。不增加输出字段或硬门禁。
2. 候选模型始终接收所属方向的兄弟路线精简摘要，即使分片或失败拆分只剩一条，也能比较本条与其他路线。只给该方向的路线，不给整批规则表；每条保持一个简单事件，不通过增加操作复杂度求不同。
3. 全批 AI 复核及分类强调上位动作关系，不按物品、修饰词或细分角度无限细分标签；保留同动作但真实价值不同的合理素材。
4. 多样性补充保留稳定 ID 的结构有效方向。原有结构恢复预算耗尽时停止补缺，对保留部分执行原有关系/全批重叠 AI 复核；只有复核通过才投入生成。无有效方向或复核失败仍返回空，不伪造通过、不新增无限重试。
5. 延续上一轮的失败分片顺序恢复修复，避免首个子分片失败后其余付费调用游离运行；正常生成并发不变。

## 数据与兼容

扩充模型输入简报中的兄弟路线摘要、全批复核路线关系及补充样例的实际事件，均来自既有 executionRoutes / shotPlan；不改模型输出或历史分片结构。旧任务无路线时摘要为空，无 shotPlan 时保留主线和六维。模板哈希沿用现有内容哈希机制。补充方向实际数量按通过复核的数量记录；可选多样性候选数不超过通过复核的路线总量，避免少数路线循环复用。最终目标数量、原有数量补充机制不变，不跨 Run 复用。

## 验证

- 模板及 Provider 输入测试：拆分单条仍看到兄弟事件，不夹带其他方向、全批事实或候选正文。
- 补充恢复：部分成功、全失败、AI 不通过、AI 异常、取消、稳定 ID 与未点名方向保留、调用预算、实际数量。
- Worker 全量非付费 pytest、mypy、Ruff、git diff --check。
- 实现后不把自动测试通过等同于重复度改善。后续真实测试须从正式浏览器发起，使用正确项目、同数量/时长/风格比较；不自动提交 Git。

## 实施与验证记录

- 已修改空间、方向、候选、全批复核及补充模板，按事件而非装饰差异组织创意；未增加输出字段、模型调用阶段或评分门槛。
- Provider 投影原有兄弟路线与真实事件，Worker 不生成、解释或归类任何事件文本。
- 部分补充经 AI 复核后可投入生成；测试覆盖 4 个方向中持续失败 1 个时保留 3 个，实际生成 6 条不同路线，而不是重复填满 8 条。全失败、复核拒绝、复核结构错误、取消和整体响应失败均有回归。
- 已通过全批 AI 复核的新方向不再被分配器按拥挤上位族二次过滤：同族可以有不同事件，避免过滤后反复复用仅剩路线。回归验证共享场景族的新方向仍使用全部 6 条不同路线。拥挤信息仍传给 AI 做补充设计，最终向量择优不变。
- 已保留上一轮顺序拆分恢复修复及其他已有改动；未触碰并行任务的 Web、API、提炼节点和素材文件。
- `uv run pytest -m "not ark_integration"`：392 passed，1 deselected（付费集成测试未执行）。
- `uv run mypy src`：25 个源文件通过；`uv run ruff check src tests`：通过；`git diff --check`：通过，只有现有 LF/CRLF 提醒。
- 此轮未部署或重启运行中的 Worker，未发起新付费批次、未提交工作副本、未提交或推送 Git。52% 仍是上一轮真实基线，不宣称本轮已改善到某个百分比；下一轮须从正式浏览器发起同配置测试后比较。
