# 效果类前四节点自动确认及编辑态

## 当前实施状态（2026-09-29）

- 前四节点已接入未发布临时分支、进入编辑/取消/保存版本；资料导入和提炼仍由用户审阅后提交，提炼任务成功后直接进入编辑态。
- Prompt 整批完整成功后自动提交，渲染整批完整成功后自动提交；不完整或校验失败保留草稿。人工编辑仍需显式保存版本。旧“完成校验”按钮已从这四个节点移除。
- 已通过定向 API、Web、Contracts 测试及数据库回滚测试；真实测试项目完成导入、提炼和 20 条 Prompt 的付费生成，Prompt 自动提交为 revision 1。另在既有测试项目的隐藏渲染编辑分支完成单条 5 秒 Seedance 付费重渲染，人工保存后发布了新的渲染分支，父批次仍为 revision 21，子批次提交为 revision 23。
- BATCH 兼容导入可逐项确认尚未确认的商品，已确认商品仍受保护；渲染批次提交与隐藏分支发布已经合并在同一数据库事务中，发布失败会整体回滚。旧批次的幂等读取恢复仅作为兼容兜底。

## 实施顺序

1. 先建立前四节点可复用的未发布临时分支创建、退出与发布操作，并补齐导入产品、资料、提炼、Prompt、渲染领域记录的按阶段复制。分支创建前后做父 Run 行与工作副本哈希对比测试。
2. 再让四个节点首次修改写入临时 Run，取消操作只退出临时 Run，保存操作执行原确认校验并按内容指纹发布或回到原分支。
3. 最后才移除原“完成校验”按钮；提炼完整成功后进入待审阅编辑态，Prompt/渲染完整生成结果自动确认。部分失败和待选择候选仍停留在可恢复草稿状态。

## 范围与非目标

调整效果类资料导入、AI 信息提炼、Prompt 生成、视频渲染四节点的确认交互和版本提交时机；不改变六节点流程、混剪/成片的确认边界，也不把任务成功但不可用的结果伪装为已确认产物。现有分支的已确认内容与媒体必须保持可回溯。用户已确认替换的是这四个节点的“完成校验”操作。

## 用户语义

- 导入节点的文件上传/链接解析成功仅写草稿，不能自动确认商品资料；用户在编辑态点击“保存版本”时才提交资料包。初次进入无已确认产物时直接处于编辑态。
- AI 信息提炼完整成功后直接进入编辑态供用户审阅，不自动提交事实；“保存版本”才执行服务端校验并提交，内容变化时新建分支。
- Prompt 整批生成或整批重新生成、渲染整批生成或整批重新生成成功，且通过与原“完成校验”等价的服务端机械校验后，自动采用结果、提交工作副本。规范化内容指纹变化时在对应阶段生成一个新分支；相同内容不产生空版本。
- 单条 Prompt 重生成成功只产生三个候选；采用候选才视为编辑修改。视频返修成功只产生候选；采用返修才视为编辑修改。失败或部分成功的任务不自动提交。
- 用户主动进入编辑态后，所有人工修改仅写入隔离草稿；“取消编辑”恢复进入编辑前选中的已确认分支，不提交 revision；“保存版本”先执行同一套服务端校验，再在内容变化时发布子分支。校验失败留在编辑态并显示具体问题。未进入编辑态时禁止修改已确认节点的资料、卖点、Prompt 条目和渲染素材，预览、复制、下载和分支切换仍可用。
- 纯预览、设置输入、候选生成、任务启动、重复回调、无变化保存都不创建可见分支。再次编辑历史分支可以从该分支开叉，不能改写它。

## 数据与接口

1. 复用 `WorkflowRun`、`WorkingArtifact`、领域草稿和现有确认服务，不建立第二套版本状态。为四节点在已有确认产物之后的第一次编辑或重新生成建立未发布的临时子 Run；按分叉阶段把导入产品、上游已确认工作副本、所需领域记录和媒体引用映射到子 Run。渲染还须复制当前已确认 Prompt 及其结果，以及既有渲染任务的活动输出快照，避免重新渲染覆盖父 Run。临时分支仅对当前编辑/任务可见，不在版本树出现。
2. Worker 请求、回调、重试固定任务启动时的 `workflowRunId`、来源 `artifactId + revision + contentHash` 和 attempt token。切换分支后，晚到结果仍只更新启动分支；若该分支不再是当前活动上下文，提交可以完成，但不得抢回活动指针。
3. 将原确认校验抽成可复用的服务端提交方法。整批任务最后一个结果落库后，持久化触发幂等自动提交；提交与分支发布/激活在同一事务内，按结果 ID、批次 revision 和内容哈希防重复。结构、数量、文件、来源或候选状态不满足条件时保留草稿和错误，供编辑/重试，不写 `WorkingArtifact`。
4. 编辑态 API 负责开始、保存、取消及恢复；取消不删除已确认产物或媒体，未发布临时分支保留必要审计信息并退出活动上下文。人工修改继续使用已有草稿接口，但必须附着于临时 Run。保存仅在所有待保存请求完成后触发；失败不离开编辑态。
5. 提交响应返回目标 `workflowRunId` 与是否新增分支。Web 以 API 的活动分支为准重载节点和树；刷新后根据服务端状态恢复运行、编辑或已确认状态，不能依赖一次性前端布尔值。

## 迁移与兼容

- 旧项目当前 Run 仍是初始主干；已确认历史不反向推断新分支。旧的未确认草稿保持可读，首次进入编辑或重跑时再转入临时子分支。
- 在渲染分支复制和父分支不变的数据库测试通过前，不对已有已确认渲染批次启用自动发布；不能以在原 Run 上直接提交新 revision 代替分支。
- 移除前四节点的“完成校验”按钮，编辑态提供“取消编辑”“保存版本”。提炼完成后进入审阅编辑态，不自动提交；其他自动提交流程的页面文案、进度和错误态须与实际结果一致。

## 验收

- 导入初次编辑保存提交资料包；历史资料分支进入编辑后上传/删除仅改临时分支，取消保留旧素材，保存变化分叉且无变化不分叉。
- 提炼首批及整批重新提炼完整成功后进入编辑态；审阅或人工修改后保存才提交，取消保留旧事实，保存变化分叉。
- Prompt 首批及整批重生成完整成功自动确认；单条候选仅采用后待保存；编辑取消不变、保存变化分叉、无变化不分叉。
- 渲染首批及整批重渲染完整成功自动确认；部分失败、文件缺失、来源过期和待采用返修不会提交。采用返修并保存后分叉；父分支的旧媒体与任务仍可播放。
- 多商品/多项目隔离、重复回调、并发保存、分支切换时任务晚到、编辑取消和浏览器刷新均有 API/数据库回归；版本树只展示已发布且有已确认内容的节点。
- 执行相关 API、Web、Contracts 测试，类型检查、构建、`git diff --check`，并在 1920、1440、窄屏浏览器验证编辑/自动成功/失败/切换状态。
