# 通用品类拍摄状态与最小修订

2026-09-10；状态：代码与离线回归完成，真实质量待验证。

## 范围与非目标

只修改效果类 Prompt 节点的规划、正文生成与生成内执行修订。直接读取任务快照中的营销洞察 artifactId/revision、事实视觉策略和 Prompt 设置；结果只更新节点草稿，用户完成校验才提交 `prompt-batch:{productId}` 并使消费旧 revision 的渲染产物待更新。不修改评分模型、评分模板、MMR、数量门禁、公开八阶段、HTTP、Prisma 或公共结果字段。不换模型、不增加调用轮数、不自动提交、不启动新付费测试。

## 实施

1. 创意空间与方向决定观众关注点、事实关系、主要事件及可见变化，不提前锁定手部轨迹、工具换握、机位或相机运动；保留原有事实与路线字段和差异化职责。
2. 正文模型统一设计首帧状态、连续动作、终态及各段观察关系。用已有 shotPlan 字段表达，不添加固定公开模板字段、字数门槛或商品词库；自然材料变化不等于完美不滴落或均匀成型。
3. 生成内修订不再返回整条改写：AI 对每条返回 KEEP 或 REPAIR，后者附冲突字段路径、简短原因与最小文本字段替换。没有明确问题返回 KEEP，原条目原样保留。相关首帧、结果、镜头与六维仅在冲突关联时同步修正。
4. 修订输入保留真实事实、视觉边界、时长和原草稿，去掉上游拍法建议与整批规划压力。Worker 只验证稳定 ID、替换路径、结构、重复路径及结果 Schema，不解释原因或内容。不可修改事实引用、编号、节拍数量/顺序/权重；不支持任意 JSON 路径或全对象替换。

内部响应为新的 Provider 专用 Pydantic Schema；只在模型调用边界使用，落盘仍为原 CreativeCandidate。已有成功分片不迁移，同一 Run 未完成草稿继续按既有恢复机制处理，新任务模板哈希变更。没有数据库或公共契约迁移。

## 验收

- KEEP 原内容、维度、事实和时长不变；REPAIR 只改明确字段，模型不能改稳定信息、插入路径、替换整段对象或删条目。
- 拒绝重复/缺失候选、越界或重复路径、KEEP 携带修改、空修订和字段类型错误；失败继续原有可恢复流程，不能静默跳过。
- 修订不携带旧执行路线、creativeUsage 或上游视觉拍法 instruction；保留事实值和禁止推导边界。
- 使用多个品类和 4/8/12/15 秒离线测试，验证通用路径处理，无商品关键词或 Worker 语义规则。Mock 仅证明编排与协议，不证明真实生成质量。
- 执行 Worker pytest、mypy、Ruff 和 git diff --check；本轮不变 UI，不启动浏览器付费生成。真实质量、重复度和耗时改善仍待另行浏览器对照。
