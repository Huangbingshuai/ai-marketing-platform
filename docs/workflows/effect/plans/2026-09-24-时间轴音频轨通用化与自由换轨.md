# 时间轴音频轨通用化与自由换轨

## 范围

- 时间轴的音频轨去掉语义：所有音频轨都叫「音频」，口播 / 纯音乐 / 分离原声的**唯一区别是片段颜色**。
- 音频片段可以像视频素材一样**自由上下拖动换行**，行号落库持久化。
- 行按占用情况压缩：空行不出现，没分离原声就没有原声行；拖到最底部才新建行。

## 现状问题

- 轨是按内容钉死的：`trackOfAudio(kind)` 把口播、纯音乐、分离原声各钉在一条固定轨上，轨内再用 `assignIntervalLanes` 自动分层。轨因此带语义，用户无法把片段放到想放的行。
- 音频片段不能上下换轨。视频早就可以：`variant.videoLanes[slotId]` 存行号，`updateDragTarget` 用 `clientY` 算幽灵和目标行，抬手 `moveClip(slotId, start, lane)` 落库。音频的 `AudioDragState` 虽然记了 `startClientY`，但只服务音量手势，MOVE 模式完全只看 `clientX`。
- 轨是按内容固定出现的，所以没分离原声也会凭空多出一个空音轨。

## 设计

### 行号持久化（照搬 `videoLanes`）

- `EffectTemplateMixVariant` 增加 `audioLanes?: Record<string, number>`，键是时间轴片段 id：口播 `voice:<lineId>`、纯音乐 `music`、分离原声 `detached:<uuid>`、旧版整片 `voice` / `music`。
- 缺省值 `VOICE→0 / MUSIC→1 / DETACHED→2`，存量工程外观不变（口播在上、纯音乐在中、原声在下）。
- 保存前压缩成 `0..n-1`，照抄 `normalizeVariantVideoLanes`。
- `packagingVisualVariant` 必须把 `audioLanes` 一起解构剔除（它是 `...visual` 展开剩余字段），否则换行会改动已确认的 `timeline-project` 产物。`packagingVisualTimeline` **不加** `audioLanes`：换行不改变渲染结果，不该让已有包装变陈旧。
- API 无需改动：草稿走 `SaveEffectTemplateMixDraftDto { draft: Record<string, unknown> }`，`draftOf` 只校验已知字段、不禁止额外键，和 `videoLanes` 同一条路，不需要 Prisma 迁移。

### 行的唯一事实来源

新建 `apps/web/src/workflows/effect/template-mix/effect-template-mix-audio-lanes.ts`。时间轴和编辑页必须用同一个函数算行号，否则渲染、静音、落库三处会对不上：

- `timelineAudioClipRefs(variant, packaging, materials, projectId)` —— 复刻 `timelineAudios` 的成员规则与 `detachedAudioRows` 的 `sourceUrl` 过滤，返回 `{ id, kind, source }[]`。
- `rawAudioLane` / `occupiedAudioLaneValues` / `audioRowOf` / `audioRowCount`（`Math.max(1, ...)`，空行自动消失）。
- `compactAudioLanes` —— 只压缩可见片段的行号，**绝不删除看不见的键**（重打包会换 lineId，在 `installWorkspaceData` 阶段 `selectedPackaging` 还是空，删键会把口播行号全清掉）。

### 时间轴

- `type AudioTrack = \`AUDIO:${number}\``，`VisibleTrack = 'CAPTION' | 'VIDEO' | AudioTrack`；`AUDIO_TRACK_LABEL = '音频'`。删掉 `trackOfAudio`、`audioLaneByTrack`、`audioLaneCount`、`audioLaneOf`。
- `trackHeight` 的音频分支必须**正好等于** `AUDIO_LANE_HEIGHT`，否则幽灵的 `Math.round(pointerTop / AUDIO_LANE_HEIGHT)` 会和实际行漂移。
- 自由上下拖：`AudioDragState` 加 `currentRow / ghostTop / initialRows`；MOVE 模式在水平吸附之后按视频那套算幽灵位置与目标行，**故意不夹紧**，让片段能拖过最后一行、落点再建行。CSS 去掉音频行的 `overflow: hidden`，拖拽中的片段抬 `z-index`。
- 抬手：单个发 `moveAudioClip(clipId, start, row)`；组拖新增 `moveAudioClips(moves)`。
- 每行一个静音键（「一个轨道一个」）。行号是位置不是身份，静音是预览态开关，跟着行号走。
- 音乐素材不再限定纯音乐轨：`acceptsMusicAssetDrag` 只判 `!trackLocked[track]`，落点行随 `addMusicAsset` 上报。

### 编辑页

- `audioRowByClipId` computed；`normalizeVariantAudioLanes` 在 `installWorkspaceData`、每次音频移动后、分离 / 拖入 / 粘贴之后调用。
- 新增 `movePackagingAudios(moves)`，镜像 `moveTimelineClips`：`resolveAudioPlacement` 处理占位冲突（优先上方空行，否则插入行并把占用者下移），`excluded` 保证组拖原子；分离原声追加到最底部新行。
- 静音改成 `audioRowMuted: ref<boolean[]>` + `mutedAudioClip(clipId)`，三处播放消费方按行判断：`syncDetachedAudio`、`previewHasPackagingAudio`、`EffectTemplateMixPackaging.vue` 的 `syncAudio`（`currentVoice` 要保留 script line id）。

## 非目标

- 不改包装 Worker 的配音、音乐生成方式和成片输出契约。
- 不做跨行框选（框选仍按行），不新增手动增删轨道的按钮。
- 不统一撤销语义：行号写 variant（进撤销快照），start 写 checkpoint（不进）。

## 验收

- 表头只有 字幕 / 主视频 / 音频（×N），音频轨名字不出现「口播」「纯音乐」「原声」。
- 音频片段可以自由上下拖动换行，落到被占用的行会换位，拖到最底部会新建行。
- 行按占用压缩：删空一行后该行消失；没分离原声就没有第三条音频行。
- 每行一个静音键，只静音本行上的片段。
- 音乐素材可以拖到任意音频行。
- 换行不改变 `visualHash`，不会让已有包装变陈旧。
- 相关前端单测与类型检查通过。
