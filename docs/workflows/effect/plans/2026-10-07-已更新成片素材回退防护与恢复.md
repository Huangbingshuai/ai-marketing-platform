# 已更新成片素材回退防护与恢复

## 范围与事实

- 效果类模板混剪，只读取同项目、同渲染谱系的已提交素材头。
- 实际确认历史显示：测试1成片02/04/05在2026-10-06中午已采用R-004第2版，晚间确认却改回另一混剪分支的第1版。新增两条素材没有改动R-004视频，但使此前回退再次被识别。
- 复用现有按素材头合并逻辑，增加草稿换素材、确认时间轴两个边界的防回退检查；不能仅相信旧复制素材的CURRENT标记。

## 非目标

- 不重新智能填充、不改变六槽位、时长、人工排布或包装音画；只恢复三个受影响槽位此前已确认的截取点。
- 不修改其他模板/历史分支，不创建付费任务，不覆盖已有导出文件。
- 不增加契约字段、接口或第二套状态，不统一清除STALE。

## 数据与恢复

- 使用当前素材池成员和逐片段已确认素材头判定实际来源，禁止不同文件的旧复制素材重新覆盖当前素材。相同文件的合法复制ID仍兼容。
- 已有待更新工程允许保留原绑定自动保存其他编辑；只有引入旧绑定或重新确认旧来源才拒绝。
- 本次恢复严格限定当前测试1三条工程：核对确认快照中的第2版来源、当前被回退的第1版来源和最新有效素材一致后，只恢复对应槽位的绑定、revision及已确认截取点。恢复后的确认工程必须与历史第2次确认内容完全一致，不覆盖后来新增的草稿音画编辑。
- 同一事务内通过既有saveDraft、prepareValidation、commitValidatedArtifacts提交草稿与这三条工程及模板依赖，记录新的正常业务revision，保留旧确认快照。事务前锁定节点并校验活动任务、草稿revision和绑定身份；任何不符立即回滚。
- 已完成包装不重写，不自动恢复其他历史分支的时间轴。
- 精确数据恢复提交使用既有Repository事务提交方法，不执行对其他分支的级联写；读取时仍根据实际依赖计算差异，不隐藏真实导出文件待更新。

## 验证

- 单元测试：旧复制素材仍CURRENT也不能回退；确认同样拒绝；同文件复制、不同Prompt换材可保存；不改绑定的待更新草稿可保存。
- 提交事务也重新读取当前来源头，祖先复制行即使revision仍匹配、CURRENT未变，也不得用不同的旧文件覆盖；避免迟到Worker或校验后素材变化绕过Service。
- 数据库回滚测试：恢复前后六槽位、截取点与包装字段保持一致；恢复后本模板无旧素材差异，新素材仍待追加；其他分支不变。
- API类型检查、构建、相关来源/追加/确认回归、git diff --check；实际只读复核三条工程的源片段依赖。

## 实施结果

- 草稿换材、确认及Repository提交事务均增加当前来源头检查；保留同文件复制兼容及待更新工程的其他草稿编辑。
- 真实项目事务先演练回滚，再精确恢复测试1三条工程R-004第2版及5.417秒已确认截取点。三条时间轴以正常确认方式升至revision4，旧快照仍保留。
- 事务断言：五条工程均六槽位、38秒，旧成片素材差异0，新增待追加素材2；其他WorkingArtifact、其他节点草稿及包装数据逐字段不变。
- 浏览器验收：五条成片均无旧素材待更新标记，成片05片尾R-004、字幕、六条口播及配乐仍显示；顶部仅保留两个新增素材追加入口。全局混剪画布仍可因新增素材及其他独立模板的真实差异显示待更新，不统一清除。
- 相关API单测与数据库回滚测试通过，类型检查、构建通过；无付费任务或导出文件覆盖。
