# 效果类 Prompt 商业运镜意图增强实施计划

状态：已完成

## 目标

在不增加业务节点、模型调用类型、公共字段或供应商依赖的前提下，将成熟的广告摄影原则吸收到现有效果类 Prompt 生成链路，提升镜头对商品价值的揭示能力，并减少“为了变化而运镜”、复合运镜冲突和无信息增量的镜头描述。

## 节点边界

- 工作流：效果类。
- 当前节点：第 3 节点 Prompt 生成。
- 直接输入：已确认的营销洞察工作副本 revision、批次设置、商品参考图快照和批次共用约束。
- 编辑状态：生成结果只写 Prompt 领域草稿和 `WorkflowNodeState`。
- 提交边界：只有用户明确点击“完成校验”才提交 `prompt-batch:{productId}`；本次真实测试不自动提交工作副本。
- 直接下游：视频渲染。只有已确认 Prompt 批次发生新 revision 时才按既有规则标记待更新。

## 实现范围

1. 连贯创意生成
   - 每条短素材只选择一个主导观察策略；简单固定机位也是合法选择。
   - 运镜只有在能揭示新的商品信息、动作结果、结构关系或尺度关系时使用。
   - 镜头描述明确起点、路径或速度、主体关系和结束观察位，避免只写“电影感推进”等空泛术语。
   - 商品轮廓、关键结构、标签与操作接触点按当前事实和商品图保持稳定，不用相机与商品同时复杂运动制造差异。

2. 评分前全量画面修正
   - 继续对所有新候选做独立 AI 全量检查；无明确问题时原样保留。
   - 修正只处理真实冲突，并同步受影响的创意主线、镜头维度和 shotPlan；不得把简单镜头强行改复杂。
   - 对焦、变焦、相机移动和主体移动分别判断，确保镜头终点真正看得到要表达的商品价值。

3. 独立评估与问题修订
   - AI 评估额外判断运镜是否有商业信息增量、是否与商品动作和可见结果一致、是否堆叠无动机技巧。
   - 仍使用现有 warning、分数和 executionFindings，不新增硬门禁或 Worker 语义判断。
   - 新素材继续在评分前接受全量画面修正；评分只记录软提醒，不在评分后追加旧式局部补丁。

## 非目标

- 不接入 AI-HIVE、fal 或其他外部视频执行服务。
- 不安装第三方 Skill 到生产 Worker。
- 不把画幅、分辨率、Seedance 型号或供应商参数写入 Prompt。
- 不新增广告脚本节点、运镜规划节点、模型调用阶段或公共 Schema 字段。
- 不机械要求推、拉、摇、移、环绕，也不把一条素材扩写成完整成片。

## 验证

- Prompt 模板测试：验证单一主导观察策略、运镜动机、镜头终点、商品稳定锚点和简单镜头保留原则均进入正确阶段；同时验证未引入外部供应商和渲染参数。
- Worker 回归：创意生成、评分前全量修正、失败恢复、评估与修订相关测试。
- 静态检查：Ruff、mypy（按现有 Worker 配置）、`git diff --check`。
- 真实付费验收：使用现有 Ark 批量脚本执行一次 50 条、15 秒测试，不触发 Seedance 渲染；记录真实调用、耗时、数量、质量分、镜头问题提醒，并人工抽查商品关联、镜头动机、动作连续性和复杂度。

## 完成记录

### 实际改动

- 连贯创意模板新增厂商无关的商业运镜动机：相机只在能新增商品信息时移动，简单固定机位继续是合法方案。
- 评分前全量修正恢复为所有新候选的必经步骤；分片先保存未复核草稿，修正成功后才进入评分，失败可从同 Run 分片恢复。
- 修正器按 `dimensions.camera → beats.camera/focus/action/visibleResult` 的完整时间顺序检查相机路径。六维声明固定机位时，后续节拍不能无说明推进、升降、改变方位或跟随。
- 时间规则限定的是无法在目标时长内自然完成的状态变化，不限制合理动作数量。任何需要等待加工、固化、充电、干燥、烹制、装配或其他长时变化的过程，不得通过拆分节拍伪装为即时完成；可保留实时可拍的局部事件，或从首帧已完成状态开始揭示结果。
- 独立评估增加无信息增量运镜、技巧堆叠、商品稳定锚点丢失和跨节拍相机矛盾的软诊断。所有规则均为全品类表述，正式模板不包含验收商品名称、食品专属动作或第三方 Skill/供应商名称。
- 付费质量脚本恢复当前 Provider 接口、同 Run 可重试执行，并移除原先写死“广式腊肠”的商品锚点统计。

### 真实付费验收

- 样本：当前已确认的“紫苏梅子酱”营销洞察，38 条统一卖点；50 条、统一 15 秒、向量择优。
- 参考图旧签名已失效，因此本次使用同一份文字事实执行纯文本验收；未调用 Seedance、未提交 WorkingArtifact、未写入正式项目结果。
- 结果：生成 54 条候选，精确选择 50 条；完全重复 0；AI 综合均分 92.80，最低 10% 平均 89.38；产品相关性 95.62、连贯性 93.06、可执行性 90.24、商业价值 89.90、视觉清晰度 93.14。
- 批次耗时 732.89 秒；Ark 成功调用 53 次、失败 1 次，共 789312 Token。一次生成分片结构化 JSON 无效后由同 Run 恢复，最终任务成功。
- 风险：结果仍为 `NEEDS_REVIEW`，选中项中保留 5 个 `CAMERA_ACTION_MISMATCH`、5 个 `DURATION_TOO_DENSE` 等软提醒。人工抽查确认部分问题是“六维写固定而后段移动”以及长时状态变化缺少因果时间，并据此完成上述通用规则收紧。
- 收紧后将本批次 10 条风险样本分两批付费重放，修正器改写 4 条并保留 6 条。重放证明通用规则能纠正主要矛盾，但也说明 AI 软修正不会保证所有边缘问题归零；这些提醒继续保留给人工校验，不提升为 Worker 关键词门禁。

### 已知边界

- 本次验收是 Prompt 质量测试，不代表 Seedance 最终视频一定按镜头描述执行。
- 付费批次带随机性，单批高分不等于所有商品稳定达到同一分数。
- 不为某一商品写特例；后续若发现同类问题，只能抽象为动作耗时、状态因果、相机路径或商品识别锚点等通用规则。

### 效果判断

- 结论为“部分有效，未证明整体提升”。同商品、同 50 条 × 15 秒的历史全量修正批次 AI 综合均分为 93.77，本次为 92.80，下降 0.97；两批存在参考图是否可用及模型随机性差异，因此该数值不能作为严格因果实验，但至少不能支持“质量已经提高”的结论。
- 本批完全重复为 0、通用摄影技巧堆叠为 0，说明单一主导观察策略没有造成明显模板化回归；然而仍有 5 条 `CAMERA_ACTION_MISMATCH`，画面故障信号没有归零。
- 定向重放的 10 条风险样本中，4 条被改写；部分固定机位与移动矛盾得到同步调整，但仍观察到个别条目修改主要动作后残留旧的驱动或结果描述。根因不是缺少更多商品案例，而是稀疏字段替换对跨字段状态同步仍不稳定。
- 本轮没有实际渲染视频，不能断言真实画面故障率下降。可确认的是诊断覆盖更明确、部分镜头冲突得到改善；不可确认的是整体 Prompt 质量提升和最终视频稳定性提升。
- 后续若继续治理，应单独验证“整段结构化修订”与当前稀疏替换的对照效果，不继续向通用模板堆叠具体商品示例，也不把软诊断升级成 Worker 关键词门禁。

## 五条高风险样本定向复测

- 从上述付费批次中固定选择全部 5 条带 `CAMERA_ACTION_MISMATCH` 的已选素材，逐条重新执行评分前全量画面修正，再用同一批评估请求复评；没有重新生成创意，因而可以直接比较同一正文的变化。
- 5 条中只有 1 条被修正器改写，另外 4 条返回保留原文。改写项把“固定机位同时推近”调整为固定机位变焦，但复评仍指出该素材存在等待状态被压进 15 秒的问题。
- 复评报告中的 `CAMERA_ACTION_MISMATCH` 从 5 降为 0，但该数字不能视作 5 条全部修好：其中 4 条正文和镜头方案完全没有变化，只是评估模型本轮没有重复报出同一问题。这证明单次 AI 评分存在判断波动，不能用 warning 计数下降代替正文差异检查。
- `DURATION_TOO_DENSE` 从 1 增至 2；其中一条仍是“加料后短时等待即完成状态变化”，另一条是高温作用结果在短时间内被描述为稳定完成。时间因果问题没有因商业运镜规则自动消失。
- 可完整记录的成功复测包含 5 次修正和 1 次统一复评，共 39251 Token、60477 毫秒供应商延迟。此前一次执行在完成 2 条后遇到 1 次 `AI_RESPONSE_INVALID` 并中止；它们未计入上述 Token 汇总，但作为真实调用尝试保留在测试结论中。

### 新发现的流程缺口与修复

- 根因不是继续缺少 Prompt 规则，而是两个独立 AI 判断可能不一致：评分前修正器可以选择保留，后续评估器仍可能给出带节拍和字段定位的明确执行故障。
- 原实现对已经过评分前修正的新素材一律跳过评分后修订，因此评估器已经发现的问题仍会进入最终候选。定向复测中的 4 条未改正文证明该假设不成立。
- 当前实现保留评分前全量修正；当独立评估随后返回位置化 `executionFindings` 时，允许执行一次完整 `shotPlan` 重写并立即复评。它不是旧式稀疏字段补丁，不允许循环修订，且人工编辑条目仍保持不可自动改写。
- 修订只有在事实不丢失、没有新硬问题、位置化故障消失且质量不下降时才采用；否则保留原候选和人工复核提醒。
- 该流程缺口修复已完成自动状态机回归。由于用户授权的本轮五个逻辑样本已经全部执行，没有追加第六条付费样本来宣称修复后的真实改善；最终视频故障仍需 Seedance 渲染验收。
