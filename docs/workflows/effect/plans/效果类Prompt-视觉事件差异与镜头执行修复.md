# Prompt 视觉事件差异与镜头执行修复

状态：三轮真实浏览器续测已完成；重复度、事实覆盖、精确数量和结构恢复达到本轮目标，15 秒动作密度仍未全面达标（2026-09-08）。

## 范围与边界

仅效果类第 3 节点。输入为已确认营销洞察的 artifact/revision、当前商品批次设置、事实视觉策略与共用禁用约束；输出仍为节点草稿。用户完成校验后才提交 `prompt-batch:{productId}`，提交新 revision 才影响视频渲染。八阶段、4～15 秒、数量优先、用途分类、MMR 权重及软重复告警不变。不修改其他工作流、渲染设置、Prisma 表或公开结果结构，不做商品关键词或 Worker 语义判断。

## 实施切片

1. 镜头内部契约：景别只描述距离/角度，相机运动与对焦分工；增加可选运动来源和焦点字段，历史 shotPlan 缺少时保持原文编译。新生成要求显式提供，静止或不适用可为 null。编译器只排版，不推断动力或物理正确性。
2. 评估诊断与局部修订：现有 AI 评估返回最多三条有节拍位置的执行诊断；只对有明确诊断、无硬问题、非人工内容的候选发起一次局部 AI 字段修订及一次复核。保留 ID、事实、主线、时长和未改字段，不用规则补正文；复核不改善则保留原候选与软提醒，不影响数量。尝试前写现有评估分片检查点，成功的候选与评估原子保存，恢复时不重复已尝试修订。无新公开字段或 HTTP 路径。
3. 创意源头差异：复用 executionRoutes 的视觉事件、场景关系、产品动作与结束状态，强化起因—动作—结果—商品价值设计和跨路线可替换性审查，不增加固定动作配额。补充允许 AI 提出已有空间内的新动作，必须通过现有事实/关系 AI 复核与全批重叠 AI 复核后才能采用；Worker 仅验证引用与结构。

## 接口与兼容

新增字段只用于 Worker 内部模型和现有 JSON 分片/规划检查点，缺省保持历史可读。公开 V6 结果与跨进程信封不变。新模型输出 Schema 与本地 Pydantic 对齐；内部诊断与修订对象不进入公开结果。修订仅影响 AI 草稿候选，不编辑人工保留、人工新增/编辑的正文。不跨 Run 复用。

## 实际落地与验证结果

- 修复全批视觉复核漏传 `executionRoutes` 的数据缺口：新增 AI 编写的短 `eventOutline`，全批复核只接收摘要控制输入体积；分批关系复核继续读取完整路线。摘要忠实性和实际事件差异仍由 AI 判断。
- 增加可选焦点/运动来源与有位置的执行诊断，保持历史 Pydantic 读取和旧正文编译；新生成的响应 Schema 显式要求两个镜头字段以及路线摘要。没有新增公开 DTO、表、路径或节点。
- 修订与复核分别最多一次，检查点先落地；复核超时、空返回、目标错误、未改善或事实丢失均保留原稿，人工内容跳过。成功正文与评分作为同一分类分片 JSON 原子保存，API 详情改用已采用正文，不公开诊断原文或检查点。中断后不重复已开始修订，哈希/字段不一致的检查点不会恢复。
- 补充新增动作经过独立 AI 关系复核与全批去重审查。修复了旧全批复核结果最少 8 项与局部复核 1～2 项的契约冲突；主规划的方向数量要求未变。全局动作 ID 不允许被覆盖或被多个空间认领。
- 本次未改 MMR 权重、相似阈值、事实使用规则或数量提交边界。新输出字段增加传输预算，4 条 15 秒候选约 8000 Token；6144 Token 的评估输出上限下，短候选通常每批 3 条。额外修订可能增加总耗时和费用，尚未做真实收益承诺。

## 授权后的首次真实验收与修正

用户后续授权提交与付费测试，已提交 `d078277`（未推送）。通过独立前端 5178/API 3002 的正式页面，对当前已确认紫苏梅子酱信息发起 100 条 × 15 秒批次；没有调用视频渲染，没有点击完成校验。

任务首次尝试在约 302.5 秒后于创意方向规划终止，错误为 `AI_OUTPUT_TRUNCATED`。其中一个方向规划调用用时约 138.9 秒，输出达到 8192 Token，供应商返回 `status=incomplete, reason=length`。这是明确截断，不是超时；未进行任务级无效重试，Run 与具体阶段均进入 FAILED。没有生成本轮 Prompt 正文，因此不能给出本轮重复率或声称质量改善。

已确认结构性风险：初次规划仍以 8 个方向一组，100 条任务每方向 5 条执行路线，单次响应约需展开 40 条路线与事实关系。新增视觉事件摘要进一步增加输出负担。修正为每调用最多 4 个方向，保持总方向、路线、事实边界和全批复核不变，不提高 Token 上限，不用规则补正文。该调整预防大分片触顶，但不能保证任意模型响应永不超限；32 个方向的初次规划调用由 4 次增加到 8 次，真实耗时与费用需重新验证。

补充证据：同组另一个已启动的并行调用最终达到 180 秒超时；它发生在 Run 已因截断终止之后，没有导致重新排队。日志共记录 10 次 Ark 调用启动，8 次完整响应、1 次截断、1 次超时。有用量响应的 9 次调用合计输入 59871 Token、输出 31333 Token；超时调用未返回用量，因此不能将此作为完整账单。旧 100 条草稿刷新后仍可查看，仍显示旧批次重复度 29%，不是本轮测试结果；上游指纹、设置哈希和 WorkingArtifact 均核对未变。

分片修正后：Worker 298 项测试通过、1 项付费测试排除，mypy（23 文件）、Ruff、`git diff --check` 通过。测试额外断言默认每组不超过 4 个方向、全部稳定槽位/动作/强制事实引用不丢失，现有修订与镜头修复回归仍通过。已重建 Worker；没有启动第二个付费批次，修正后真实成功率、质量、重复度与速度尚未验证。测试产生的分片修正和本节记录保留为未提交修改，未修改已完成的 `d078277` 提交。

## 第 2～3 轮部署后复验

后续已用允许的本地服务管理方式部署 Prompt API 与 Worker，并继续通过正式浏览器、API、Outbox、RabbitMQ 和真实 Ark Worker 执行两轮同源同设置任务。两轮均在任务第 1 次尝试内完成 100 条，刷新、分页和批量导出正常；没有点击“完成校验”或调用 Seedance。

- 第 2 轮：140 条初始候选加 20 条多样性补充，最终重复度 14%，26/26 必用事实覆盖，AI 加权平均质量 92.83；局部分片恢复 9 次。该轮暴露 API 候选目标误报、可选证据来源枚举波动和补充方向避让项超量三个结构问题。
- 第 3 轮：部署结构容错修正后，140 条初始候选加 2 条事实补充和 20 条多样性补充，最终重复度 13%，26/26 必用事实覆盖，AI 加权平均质量 92.80；局部分片恢复降至 2 次，补充方向首次返回即通过，硬问题淘汰为 0。
- API 现在保留 Worker 的真实候选目标数；未知的可选证据来源只被归一为空；补充方向超出的避让项只做结构截取。三项处理都不解释正文或事实语义。
- 第 3 轮仍有 23 条动作过密软提醒，人工抽查也看到多动作链和复杂镜头关系。因此本方案的稳定性与重复度目标可以进入远程评审，但镜头执行质量仍须继续优化，不能标记为“全面质量完成”。
