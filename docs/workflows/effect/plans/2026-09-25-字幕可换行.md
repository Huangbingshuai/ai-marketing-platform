# 字幕可换行：把落点解析成「行」，并允许回到隐式字幕行（第七轮）

承接 `2026-09-25-字幕边缘拖动辅助线.md`。上一轮补齐了字幕伸缩边缘的吸附。用户接着报：

> 「字幕素材移动到上面的轨道之后就回不来了，就算没有素材也挪不回来」

## 一、先证明「回不来」是三件事叠在一起

真浏览器探针（Playwright + Vite 5173，用户「测试4」模板的真实几何：六槽位 `4/10/10/10/8/4`、14 条**全部无 `trackId`** 的字幕、口播与纯音乐同真实快照）逐帧采样 `.caption-clip` 的 `top` 与派生泳道图。改前：

```
INITIAL          全部 @lane 0
上拖 1 行         拖动中 top 51  → 松手后 top 85（c5 新铸轨道占 lane 0，其余 13 条被挤到 lane 1）
下拖 1 / 2 / 6 行  拖动中 top 119 / 153 / 289 → 松手后 top 85（每次都弹回最顶行）
                  trackIds 里 c5 全程是 subtitle-track-*
```

下拖 6 行时 c5 所在时刻的下方明明是空的，仍然弹回顶行 —— 与用户描述逐字吻合。三层原因，缺一不可：

| 层         | 位置                                                                            | 行为                                                                                                                                                                          |
| ---------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 时间轴松手 | `EffectTemplateMixTimeline.vue` 字幕 `MOVE` 分支                                | 字幕**只要竖向动过**（`rowChanged`）就 `emit('splitCaptionTrack', …)`，从不报告「落到哪一行」                                                                                 |
| 泳道排序   | `effect-template-mix-state.ts` 的 packer                                        | `track:<id>` 的 `order = 0` 排在 `manual`(1)/`legacy`(2) 之前；同 order 内 `right.key.localeCompare(left.key)` 降序 → **新铸的 `trackId`（时间戳最大）永远排 lane 0（最顶）** |
| 无人清除   | web 只赋值；API `effect-packaging.service.ts` 的 `previous?.trackId ?? trackId` | `trackId` 一旦写上就再也去不掉；即使客户端想换行/回退，服务端也把旧值钉回去（原注释写着 "It is never dropped once set"）                                                      |

所以「回来」需要两件事：**落点能表达「回到某条已有行」**，以及**`trackId` 能被清除**。用户已用两个回答钉死边界：落到已有行且时间上重叠 → 照旧新开一条轨道；落到现有行范围之外的空白 → 新建一条轨道（新轨道出现在字幕行顶部，用户已确认）。

## 二、修法

### 1. 把「行」变成一等概念（`effect-template-mix-state.ts`）

原先同一个 key 表达式被抄了四份（state 的 packer、timeline 的 `captionTrackKeyOf`、API `domain.ts`、worker `final_output.py`）。本轮把 web 侧两份合一：

- 新增 `effectTemplateMixCaptionTrackKey(caption)` —— 唯一的 key 定义（`track:<id>` / `manual:<id>` / `'legacy-generated'`），timeline 改为调用它，删掉本地副本。
- 抽出内部 `captionLanePlacements(captions, fps)`，把原先内联在 `assignEffectTemplateMixCaptionLanes` 里的分组 + 排序 + `laneEnds` 打包逻辑原样搬进去；`assignEffectTemplateMixCaptionLanes` 从它派生，**输出逐条不变**（既有 state 断言是护栏）。
- 新增 `effectTemplateMixCaptionRowKeys(captions, fps): string[]` —— 长度 = 总泳道数，第 `i` 项 = 第 `i` 条泳道所属 group 的 key。因为每个 group 占据一段连续泳道，逐 group 展开即可。**这是把竖向落点从「动了没动」变成「落到哪一行」的关键**：同一个 group 的每条泳道都报同一个 key，所以一组 legacy 字幕被铺成多行时，落到其中任意一行都算「回到 legacy」。

### 2. 时间轴：解析落点（`EffectTemplateMixTimeline.vue`）

`captionOverlapsOwnTrack` 泛化为 `captionOverlapsTrack(clipId, start, duration, key, moving?)`，`key` 由调用方给；`captionOverlapsOwnTrack` 保留为薄封装（多选刚性滑动那条分支照旧用它）。松手分支从「一个二值判断」改成四个出口：

```ts
const ownKey = effectTemplateMixCaptionTrackKey(own);
const targetKey = effectTemplateMixCaptionRowKeys(timelineCaptions.value, props.fps)[
  audio.currentRow
];
const overlaps = (key: string) =>
  captionOverlapsTrack(audio.id, audio.currentStart, audio.initialDuration, key);

if (
  audio.insertCaptionTrack ||
  targetKey === undefined ||
  (targetKey !== ownKey && overlaps(targetKey))
)
  emit('splitCaptionTrack', captionId, audio.currentStart); // 边界 / 越界 / 目标行会重叠
else if (targetKey !== ownKey)
  emit('moveCaptionToRow', captionId, audio.currentStart, targetKey); // 加入已有行 ← 新增
else if (overlaps(ownKey)) emit('splitCaptionTrack', captionId, audio.currentStart);
else emit('moveAudioClip', audio.id, audio.currentStart);
```

`audio.currentRow` 本来就是「字幕区相对、不夹取」的行号，所以拖出上下边缘天然是 `undefined`，不需要额外夹取。新增事件 `moveCaptionToRow: [captionId, start, rowKey]`。

顺带的改善：竖向抖动（`currentRow` 仍落在自己那一行）不再新铸轨道 —— 以前只要 `rowChanged` 就铸。

### 3. 编辑器：写回行（`EffectTemplateMixNodePage.vue`）

`splitCaptionTrack` 的管线抽成 `writeCaptionRow(captionId, start, trackId: string | null)`：`null` 是 `delete target.trackId`（回到隐式行），否则写入给定 `trackId`；`splitCaptionTrack` 变成薄封装，`subtitle-track-…` 的铸造字面量**原样保留**（`?raw` 断言逐字依赖它）。

新增 `moveCaptionToRow`：`legacy-generated` → 清除；`track:<id>` → 采用该 id；`manual:<id>`（行号里带着别的卡自己的 id，结构上无法加入）→ 退回新建轨道。

`audioDiff` 的字幕映射必须能表达「清除」：`...(trackId ? { trackId } : {})` 会把「baseline 有、current 没有」丢成 `undefined`，而服务端把 `undefined` 当「保持旧值」→ 清除静默失效。改为 baseline 有而 current 没有时显式发 `trackId: null`。

### 4. 契约 + API：`null` 表示清除

- 契约 `PackagingCaptionEdit` 是交叉类型，成员不能就地放宽，改成 `Pick<…> & { manual?: boolean; trackId?: string | null }`。
- DTO 的 `trackId?: string` → `string | null`（`@IsOptional()` 本来就同时跳过 `null` 与 `undefined`，所以「清除」和「保持」共用一个字段；`whitelist`/`forbidNonWhitelisted` 仍保留这个带装饰器的键）。
- 服务 `:606`：`previous?.trackId ?? trackId` → `trackId === null ? undefined : (trackId ?? previous?.trackId)`。显式 id 采用、显式 `null` 清除、缺省保持。旧写法连「换一条别的行」都会静默失败。
- `effect-packaging.domain.ts` **不改**：形状检查遇到字面量 `null` 会 `fail()`，但服务在校验之前已把 `null` 归一成 `undefined`；这个顺序依赖由 domain spec 的用例钉住。
- worker **不改**：`final_output.py` 用 `row.get('trackId')` 真值判断，`None` 天然落到 `legacy-generated`。

## 三、实测（Playwright 探针，改后重跑）

```
INITIAL           rowKeys = ['legacy-generated']，14 条全 @lane 0
上拖 1 行          c5 → subtitle-track-…（c5@0，其余 13 条 @1）   ← 没有可加入的行，新铸（决定 2）
下拖 1 行          c5 → legacy（trackId 被清除，14 条回到一行）  ← 回得来了
下拖 2 / 6 行      超出唯一一行 → 新铸轨道（决定 2）
```

改前 `下拖 1 行` 与改后同样一次手势的区别，就是用户报的那一条：改前 `trackIds` 里 c5 永远是 `subtitle-track-*` 且 `top` 弹回 85；改后 c5 变回 `legacy`、14 条字幕回到同一行。

## 四、非目标

- **不修 worker 侧的同源缺陷**：`packaging.py:743-745` 只在布局版本与 `voiceLineId` 集合都匹配时才保留已存字幕，否则从 `captions_for_voice`（`packaging_captions.py:93`，从不写 `trackId`）重建 —— 重新包装会静默丢掉编辑器排好的行，与 `service.ts` 的承诺矛盾。这是独立 bug，且要重建镜像，另行处理。
- 多选字幕组的落点目标（今天整组仍按各自规则 split）。
- 视频槽位 `edgeTrimDrag`、`manual:<id>` 行不可加入（结构上不可能）、`snapEdges`/7px 阈值/磁铁开关/行静音。
- 不改 `ready` 不变量、模板槽位重叠规则、任何渲染路径。

## 手动验收

用广式腊肠项目 `65458686-034c-4258-b2dd-027d4ad15132`「测试4」模板（字幕默认全在隐式行）：

1. 选中一条字幕下拖 1 行 → 落在紧邻的下一行；下拖 6 行 → 落在第 6 行；**不再弹回顶部**。
2. 刷新页面 → 落点保持（该条 `trackId` 是目标行那条的 `trackId`，或落在空白区时是一条新的 `subtitle-track-*`）。
3. 把它上拖回最底部的隐式行 → 回到 `legacy-generated`（`trackId` 被清除），其余 13 条字幕排布与初始一致。
4. 把一条字幕拖到另一条已有字幕行、时间上重叠 → 照旧新开一条轨道。
5. 拖到现有行上下范围之外的空白 → 新开一条轨道，出现在字幕行顶部（已确认）。
6. 回归：拖字幕中段/左右把手（上一轮）落位与辅助线不变；删口播、删纯音乐、模板槽位重叠拦截、撤销一步不变。
