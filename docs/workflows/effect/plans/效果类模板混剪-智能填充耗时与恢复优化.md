# 效果类模板混剪：智能填充耗时与恢复优化

## 范围与验收

- 保留首次 AI 填充最多 20 条工程、六槽位匹配、人工锁定和算法组合的既有语义。对同一 Run 中重复的 `materialId + slotId` 只下载、抽帧和调用截取模型一次，按原 `variantIndex + slotId` 写回全部独立结果；失败仍保持有界重试和原子终态。
- 已完成 Run 的分类缓存改为逐素材复用：槽位分类签名一致，且素材 ID、编码、原始 Prompt、Prompt 工作副本 revision、视频工作副本 revision 与内容哈希一致时才复用该条；新增或变更素材交给模型分类，不能用推荐用途或关键词补齐。
- 记录每次任务的排队、分类、匹配、下载/抽帧、截取模型与写回耗时及缓存命中/重复截取数量，只记录 ID、数量和毫秒，不记录 Prompt、视频、存储地址或供应商正文。
- 已发布 Outbox 但超过可配置等待时间仍为 `QUEUED` 的任务由 API 定时检查并有限重投；重投与失败终态使用项目、Run、任务 ID 和状态条件更新，旧消息被 Worker 领取时必须安全跳过。

## 非目标

- 不改变模板结构、20 条上限、页面视觉或工作副本提交边界；不编码最终视频，不把已完成分类跨项目或跨工作流 Run 复用。
- 不新增第二套任务或素材状态，不预先触发付费模型；本次验证仅在用户主动测试时发起任务。

## 数据、迁移与兼容

- 沿用现有 `EffectTemplateMixAiRun`、`JobOutbox`、Worker claim/progress/checkpoint/complete 接口。分类缓存仍从同项目同 Run 的历史 Run 快照和结果读取；不新增公开 DTO。
- 为任务增加独立的无人领取恢复次数，默认 0，已有记录兼容；数据库迁移仅添加列。重投保留同一 Run 和同一幂等键，Outbox 改回 `PENDING`，不创建新任务。超过上限后给出安全中文失败状态，不无限重投。
- 阶段耗时进入脱敏结构化日志；现有 `createdAt/startedAt/completedAt` 仍是端到端耗时的权威时间戳。日志不改变业务 revision。

## 测试

- API：逐条缓存命中、单素材变化、槽位或 revision 变化、跨项目/Run 隔离；无人领取的边界、有限重投、旧消息与并发 claim、已终态不重投。
- Worker：重复选片只发生一次下载/抽帧/模型截取、每个 variant 仍有独立检查点；部分已完成检查点恢复、异常取消和阶段计时字段。
- 执行 API/Worker 聚焦测试、类型/语法与构建检查、`git diff --check`。若真实任务可安全发起，再对比优化前后的同范围耗时和六槽位结构，不把热缓存样本当作冷启动结论。
