# Prompt 视觉事件修复：付费续测报告

日期：2026-09-08。新增授权上限 20 次，已使用 3 次。仅测试效果类 Prompt，不渲染视频、不点击“完成校验”，因此没有覆盖已有 `prompt-batch:{productId}` 工作副本。

## 结论

同一份紫苏梅子酱已确认信息、100 条 × 15 秒设置完成三轮真实 Ark 浏览器回归。三轮均在任务第 1 次尝试内精确保存 100 条，必用事实覆盖均为 26/26。最终语义重复度从对照批次的 29% 依次降至 20%、14% 和 13%，AI 加权平均质量保持在 92.39～92.83。

结构稳定性在第 3 轮明显改善：局部分片恢复从第 2 轮的 9 次降至 2 次，补充方向首次返回即通过，未再出现 `evidenceSource` 枚举错误或 `avoidFamilies` 数量越界。浏览器刷新、分页和批量导出均正常，且页面持续明确显示“尚未提交工作副本”。

这不等于内容质量已经全面完成。第 3 轮仍有 23 条“15 秒动作过密”软提醒，人工抽查也发现多次换盘、连续滚动/切取、镜头移动与正文指令关系复杂等问题。当前可以确认“数量、事实覆盖、重复度和结构恢复链路达到本轮目标”，不能确认“所有镜头都足够简洁可执行”，更不能从 Prompt 测试推断最终视频效果。

## 各轮真实链路

### 第 1 轮：首次完整成功

- 方向规划拆小后不再出现输出截断，任务第 1 次尝试完成。
- 157 次 Ark 请求中 151 次成功解析、6 次结构异常；只恢复受影响的局部分片，没有整批重跑。
- 返回用量合计输入 1,439,144 Token、输出 341,685 Token，不含向量接口。
- 多样性补充方向曾被规划但未被采用，最终从初始 140 个候选中择优 100 个；未入选的 40 个候选不是硬淘汰。
- 浏览器验证 100/100、15 秒、20 页 × 5 条、翻页、刷新和服务端批量导出。

### 第 2 轮：重复度继续下降，暴露结构兼容问题

- 初始 140 条加 20 条多样性候选，共 160 条参与择优，最终保存 100 条。
- 最终重复度 14%，AI 加权平均质量 92.83，动作过密提醒 11 条。
- 局部分片恢复 9 次，评估调用 86 次，方向结构修复 3 次。
- 发现三个结构问题：API 把 Worker 的真实候选目标数错误投影为 120；可选 `evidenceSource` 出现未知值时使整项结构失败；补充方向返回超过两个 `avoidFamilies` 时触发不必要的结构重取。
- 浏览器刷新后仍为 100/100，批量导出成功，无控制台错误；草稿未提交为工作副本。

### 第 3 轮：验证结构容错修复

- API 保留 Worker 的真实 `candidateTargetCount=140`，不再按旧公式覆盖。
- 初始 140 条，加 2 条事实覆盖补充和 20 条多样性补充，共 162 条参与择优，最终保存 100 条。
- 最终重复度 13%，AI 加权平均质量 92.80，硬问题淘汰 0，26/26 必用事实全部覆盖。
- 局部分片恢复降至 2 次，评估调用 73 次，方向结构修复 2 次。补充方向首次返回即通过，没有再次出现 `avoidFamilies` 数量错误。
- 可选证据来源出现未知值时只清空该可选字段，仍保留其余合法证据结构；Worker 不据此解释事实语义。
- 日志记录 186 次 Ark 请求启动与返回，其中 182 次完整解析；有用量响应合计输入 1,661,221 Token、输出 375,695 Token，不含向量接口。
- 浏览器刷新后仍为 100/100、15 秒，20 页 × 5 条；批量导出成功，无控制台错误，仍为未提交草稿。

## 实施中的问题与处理

| 问题                   | 影响                                                         | 当前处理                                                                         |
| ---------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 有诊断却漏修           | 合法 AI 执行诊断未重复出现在 warnings 摘要时，局部修订未触发 | 直接使用结构合法的 AI 定位诊断；Worker 只校验字段、稳定 ID、枚举、结构和调用预算 |
| 进度显示矛盾           | 节点顶部计数与真实分片结果不一致                             | API 使用同一份安全阶段投影统一计数                                               |
| 补充阶段不可感知       | 已进入补充规划，页面仍显示评估完成                           | 模型调用前先把择优节点写为 `RUNNING`                                             |
| 候选目标数被旧公式覆盖 | 实际生成 140 条，公开指标误报 120 条                         | API 优先保留 Worker 持久化的真实指标                                             |
| 可选枚举波动           | 未知证据来源导致整项结构被拒绝                               | 只对未知可选来源归一为空；不改变正文、事实或评分语义                             |
| 避让套路数量越界       | 补充方向因多返回一项而重复请求                               | 结构层最多保留前两项；不判断其业务含义                                           |
| 动作仍可能过密         | 15 秒内安排过多产品动作或镜头变化                            | 保留为 AI 软提醒和人工质量风险，不使用 Worker 语义门禁或数量淘汰掩盖             |
