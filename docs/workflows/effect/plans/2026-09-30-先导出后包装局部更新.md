# 先导出后智能包装的分支与局部更新

## 范围

效果类仍保持六个固定节点。版本树将混剪节点内部的智能填充、智能成片包装分别画成层级，成片输出位于其下游。允许智能填充后直接导出纯画面成片。

当用户在已导出、尚未包装的活动成片分支首次执行智能成片包装时，包装结果提交到当前 Run 的混剪工作副本，不为此次包装再建立兄弟 Run。正在包装时锁定该 Run 的源工程；完成后保留已导出的文件，并将与最新包装不同的成片显示为“待局部更新”。用户主动点击局部更新才按该分支当前工程及原分辨率、帧率重新渲染，成功后覆盖当前分支的对应资产和交付清单。已有包装结果的再次包装仍沿用独立子分支，以保留旧包装版本。

## 接口与迁移

复用现有包装任务、混剪工作副本、成片批次和 `local-update` 接口。不增加固定节点、公开端点或数据库字段；版本树响应新增可选的 `packagingInOutputBranch` 展示标记。新的首次包装按上述规则写入。

紫苏梅子酱项目测试3模板的已完成包装曾错误地产生子分支。按用户选择，执行一次定向迁移：保留原导出 Run 与四条成片文件，复制子分支独有的素材工作副本及其依赖，将四条已完成包装结果映射到原 Run，并将包装音频文件的归属改为原 Run。提交包装工作副本后，原批次的四条成片标记待局部更新；激活原导出 Run，隐藏错误子分支但保留其数据供追溯。迁移不调用 AI，也不自动重新渲染。

## 验收

- 智能填充后未包装的纯画面导出继续可用。
- 已导出分支首次包装期间不跳转 Run，旧文件可播放下载，工作台禁止改动；完成后工作台解锁，版本树在该分支显示包装位于导出上方。
- 成片页按实际包装差异显示待局部更新，点击后只重渲染选中条目，不创建分支，保持原输出规格。
- 重新包装仍保留旧分支及旧文件；跨项目、跨 Run 不复用任务或工作副本。
- 迁移后版本树显示原导出分支同时包含包装与导出，错误子分支不再显示；原成片 4/4 文件仍可用、4/4 待局部更新。
- 相关 Web/API 类型检查和差异检查通过；依用户本次要求不额外执行测试。
