# 首次成片包装原位执行与逐条解锁

## 已确认规则

- 首次整批包装在当前模板的当前 Run 执行，不创建子 Run。已有已提交的 `timeline-package:<templateId>:*` 才视为重新包装，重新包装创建独立子 Run，原分支保持可编辑。
- 失败、取消及仅创建过包装任务不代表包装成功，不能据此将首次包装变为重新包装。
- 首次整批、单条及追加包装只锁定执行 Run 内排队或运行的目标成片；成功事务提交或最终失败/取消保留基线后立即解锁。`RUNNING + READY` 不能提前解锁。
- 原位包装逐条提交 `timeline-project` 和 `timeline-package`，复用现有任务、检查点、重试、Outbox 与租约。下游仍为成片输出，不自动编码；终态隐藏进度。

## 边界与实施

效果类模板混剪节点直接消费已确认渲染素材、采用 Prompt 及事实依赖的明确 revision。冻结当前模板、完整包装基线和草稿 revision，服务端继续校验项目、Run、模板、来源、文件和并发编辑。

1. API 创建时用当前 Run 的已提交包装工作副本判定首次/重新包装，不用历史任务存在性或前端按钮文案判定；保留非全局模板路径授权、幂等与 revision fence。
2. 编辑保护仅锁定任务所属 Run；创建任务的重叠检查仍覆盖父子 Run，不能因释放父分支编辑而重叠启动相同目标。
3. Web 沿用已有精确 Run、模板、成片及任务终态的锁定投影，不引入新的状态或协议。首次任务受理后直接显示当前 Run 的真实进度。
4. 更新效果类指南，覆盖首次、失败后再试、部分成功后重新包装、取消、子 Run 与原分支隔离等回归。

## 迁移与非目标

- 不迁移历史任务或取消分支、不物理删除历史文件，不自动重启已失败或取消任务。
- 用户已明确授权中断的测试1任务 `3ca5abe3-788a-46df-87a6-f5f3dfde0101` 已经取消；旧 attempt 不得继续写入。
- 不改供应商协议、自动重试预算、最终编码、其他节点或固定工作流，不新增表或跨进程字段。

## 验证

- API：首次无子 Run；已提交包装才创建子 Run；失败/取消历史不触发开叉；单条/追加保持原位；已有来源和克隆 revision 校验不放宽。
- 锁定：原位目标排队、运行及 READY 阶段不可编辑；完成/失败/取消立即解除；其他目标及重新包装父分支可编辑；创建重叠检查仍覆盖父子 Run。
- 执行相关 API/Web 单测、类型检查、构建和 `git diff --check`；只读核查取消状态和本地服务实际生效。本轮不再启动付费包装，不自动提交 Git。
