# 混剪模板目录读取修复

## 范围与事实

效果类模板混剪节点的只读目录读取。继续消费已确认素材及各模板当前 Run 的工程，保存边界、`mix-template` / `timeline-project` 工作副本 revision 和成片输出待更新规则不变；不调用模型、不修改数据库或增加版本。

实测紫苏梅子酱项目：当前工作区首次读取约 571 ms，再次读取约 35 ms；版本树约 516 ms，四个模板当前路径读取约 48–97 ms。前端 `installWorkspaceData` 推进编辑请求 epoch 后，目录回调检查安装前的 epoch 会丢弃正常目录响应，并留下永久 LOADING。工作区已补充安装后 token，但目录等待期间的普通编辑依然会让只读目录丢失。

## 修复

- 可写工作区仍使用原有编辑 epoch、草稿 revision 与作用域校验。
- 只读目录回调不使用可写草稿 epoch；保留活动页面、AbortController 身份、项目、Run、已安装作用域保护。目录展示继续通过现有 `mixTemplateCatalogEntries` 覆盖当前 Run 的最新本地条目，不安装目录内的旧工程草稿。模板删除继续取消在途读取。
- 目录所有路径读取复用现有有界读取机制，超时明确失败并允许重试，不无限转圈。
- 不用过期缓存或错误分支的模板作为临时列表，不改变目录完整成功后才发布的规则。

## 验收

执行真实页面 load 函数的回归测试：安装导致 epoch 改变、目录等待期间编辑、项目/Run 切换、迟到响应、读取失败及重试；验证目录覆盖只影响展示，不覆盖本地草稿。运行模板目录、工作区读取、草稿竞态、编辑隔离相关测试、Web 类型与构建检查及差异检查。浏览器验证首次加载、返回、刷新和模板切换，记录可见目录耗时。

## 已执行验证

- Web 的 `effect-template-mix-edit-context`、`effect-template-mix-template-catalog`、`effect-template-mix-draft-race`、`effect-template-mix-workspace-load` 四个测试文件：72 个用例通过。补齐旧测试执行真实页面逻辑时缺失的依赖，并将格式敏感断言改为允许换行。
- `pnpm --filter @ai-marketing/web build`：Vue/TypeScript 类型检查及 Vite 构建通过，保留现有大 chunk 警告。
- 浏览器真实项目刷新后完整四模板目录出现时间为 936 ms（一次本地测量，不代表所有部署环境）。测试1与测试3切换均恢复对应配置；1440、1920 和 768 宽度下目录正常显示，新建按钮可用。
- 无 API、契约、Worker 或数据库逻辑修改，无模型/渲染任务、正式工作副本提交或 Git 提交。失败、取消、迟到响应和草稿保护由模拟回归覆盖，未在真实项目破坏数据制造异常。
