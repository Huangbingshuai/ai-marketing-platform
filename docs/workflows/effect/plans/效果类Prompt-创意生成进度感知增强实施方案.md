# 效果类 Prompt：创意生成进度感知增强实施方案

状态：已完成

## 目标

在不改变模型输入、模型调用顺序、候选数量、事实分配、质量评估、向量择优和最终结果的前提下，让用户持续看到 Prompt 批量任务的真实进展。

## 边界

- 保持效果类六个业务节点和 Prompt 八阶段内部拓扑不变。
- “创意空间规划”和“创意方向规划”只作为“连贯六维创意生成”内部里程碑展示，不新增 WorkingArtifact。
- 重新批量生成仍从输入快照开始，不增加跨 Run 缓存。
- 只复用同一 Run 已有的故障恢复分片和检查点语义。
- 不修改 Prompt 正文、六维信息、事实绑定、用途分类、评分或选择结果。

## 实现

1. Worker 在现有创意生成阶段写回安全的阶段摘要：创意空间规划、事实分配与空间复核、创意方向规划与复核、候选分片生成。
2. API 从已持久化阶段元数据和分片记录投影产品创意空间数、创意方向数、候选目标、已生成候选、完成分片和待处理分片，不暴露模型、事实 ID 或内部响应。
3. Web 主进度区优先展示当前节点的服务端摘要；工作流卡片展示运行中摘要；用户打开节点详情后，随 Run 更新时间自动刷新已完成部分。
4. 自动刷新只在弹窗打开且选中当前运行节点时启用，页面离开、产品切换或弹窗关闭时清理定时器和请求。
5. 工作流不拆成四个容易造成误解的规划节点，而是把既有阶段统一显示为“创意规划与 Prompt 生成”；右侧按照“产品创意空间 → 该空间下的创意方向”展示已验证规划结果。

## 验收

- 同一 Mock 输入改造前后最终 Prompt 批次规范化 JSON 完全一致。
- 主页面能依次显示创意空间规划、创意方向规划、候选生成、用途评估、数量择优和保存阶段。
- 运行中节点详情能逐步显示候选与分片数量，刷新页面后继续恢复。
- 不增加模型调用次数，不改变调用顺序和并发度。
- Contracts、API、Web、Worker 相关测试、类型检查、生产构建与 `git diff --check` 通过。

## 实施结果

- Worker 仅在既有 AI 调用前后写入安全阶段摘要，并在既有候选分片计划中补充分片总数、恢复数和候选数；未修改 Provider 入参、调用顺序、并发信号量、候选数量或结果对象。
- API 将阶段元数据与已持久化分片组合为“当前步骤、产品创意空间、创意方向、候选目标、实时分片进度”等用户可读字段，不暴露事实 ID、模型输入或内部响应。
- Web 主进度条和运行中节点卡片优先展示服务端真实摘要；选中当前运行节点时随 Run 更新时间刷新详情，关闭弹窗和卸载页面时会清理定时器与请求。
- 创意空间规划、空间复核、方向规划和关系复核在界面上合并为一个节点。节点详情完整展示安全化的空间名称、适用画面、差异目标、动作范围及其下属方向，不显示空间 ID、方向 ID、事实 ID 或模型原始响应。
- 既有 Mock 结果回归继续验证目标 10 条时生成 14 条候选并精确保存 10 条，Prompt 内容、事实绑定、用途和统一时长断言保持通过。新增状态上报不参与结果计算。

- API：241 项测试通过，类型检查与生产构建通过。
- Web：158 项测试通过，类型检查与生产构建通过。
- 格式与差异：相关文件 Prettier 检查及 `git diff --check` 通过。
- 浏览器：本地正式页面可正常打开工作流弹窗，八阶段拓扑与空状态正常，ESC 可关闭并恢复页面，控制台无错误。本轮未启动新的真实批量任务，因此没有产生付费模型调用；运行中分片状态由 API 运行态投影测试覆盖。
- 层级展示补强：Contracts 17 项、API 节点详情 12 项、Web 页面布局 17 项测试通过；API/Web 类型检查与生产构建通过。浏览器再次回归时本地会话没有可用项目，页面正确显示“项目状态不可用”且控制台无错误，因此空间—方向真实数据展示以 API 运行态夹具和 Web 渲染契约测试完成验证，未为测试创建项目或改写业务结果。
