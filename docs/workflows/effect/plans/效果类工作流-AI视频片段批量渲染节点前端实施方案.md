- 最后更新时间：2026-09-04

## 目标与实施范围

本次只实现效果类工作流第 04 步“AI 视频片段批量渲染”的前端页面、独立 Mock Service、必要状态模型、父工作流接线和前端测试。页面以 `references/prototypes/effect/effect-workflow.html` 为冻结视觉基准，在 1280×720、DPR 1.25 下复刻标题区、统计卡、批量工具栏、双列任务卡、分页、预览弹窗、来源 Prompt 弹窗、工作副本状态栏和节点底栏。

本次不修改后端、数据库、Prisma、HTTP 接口和 `packages/contracts`；不调用 Seedance、外部模型或任何真实网络；不修改已完成的资料导入、AI 信息提炼和 Prompt 生成页面；不开发模板混剪和成片输出节点；不提交 Git。

## 开发前强制核对

1. 当前属于效果类工作流第 04 步 `SEGMENT_RENDER`，用户可见名称为“AI 视频片段批量渲染”。
2. 直接上游是第 03 步已完成校验的 `prompt-batch:{productId}` 工作副本；不存在第二个必要上游。前端 Mock 以稳定 Prompt ID 模拟该快照，不读取 Prompt 页面临时草稿。
3. 真实业务应产生 `render-batch:{productId}` 和 `render-clip:{taskId}`；本次仅在独立前端 Mock Service 中维护同形态的会话数据，不伪造服务端记录。
4. 任务筛选和弹窗状态只属于页面交互状态；开始渲染与单条重生成由 Mock Service 更新当前会话中的模拟结果。本次不调用 `WorkflowNodeState` 或提交真实 `WorkingArtifact`。
5. 真实业务中，已提交视频素材池的有效内容变化会使第 05 步模板混剪的既有结果 STALE；本次不开发或模拟第 05 步状态传播。
6. 下游稳定依赖应包含 Prompt ID、Prompt 内容指纹、片段类型、渲染任务 ID、素材版本和内容哈希。本次 Mock 使用 `projectId + workflowRunId + productId + promptId` 生成稳定任务标识，不依赖页面数组序号。
7. 本次明确不开发 Prompt 生成、模型选择策略、Seedance Worker、真实视频播放、模板混剪、成片合成和项目归档。

## 页面结构与视觉基准

- 节点主卡：白色背景、28px 内边距、26px 圆角、`#dbe4f6` 边框与浅阴影。
- 标题区：44px 橙色步骤徽标，21px 主标题，13px 说明；右侧为当前商品和 40px 高批量渲染主按钮。

## Mock 数据与交互

Mock Service 按项目、工作流、产品隔离会话数据，统一负责加载、批量渲染、自动重试和人工单条重生成。组件通过 `AbortSignal` 取消产品切换和卸载后的旧操作，不在组件中散落定时器。

默认工作区只包含 50 条已就绪 Prompt，不预先创建渲染任务。用户确认批量渲染后才创建 50 个一一对应的任务，并按确定性规则推进排队、生成和自动重试；可恢复失败最多自动重试两次，仍失败则标记异常，支持人工单条重生成。

- 保留工作区无关修改，不覆盖 Prompt 生成及其他模块的现有变更。

## 2026-09-04 首次进入与批量渲染交互修复

### 调整原因

现有 Mock 在加载节点时直接创建 50 条任务，并预置 47 条完成、3 条生成中，导致“尚未点击开始批量渲染”与“已有批次恢复”两种业务状态混淆。正式契约已经以 `batch: null` 表示尚未创建批次，因此前端 Mock 也必须先展示无批次状态，只有用户确认开始后才创建一条 Prompt 对应一条任务。

### 本次范围

- Mock 工作区新增显式批次阶段与待渲染 Prompt 数量；首次加载只有已就绪 Prompt，没有任务卡。
- 保留原型标题、设置卡、四项统计、工具栏和双列卡片视觉；无批次时在列表区域展示开始引导空状态。
- 点击“开始批量渲染”先展示包含商品、任务数、模型能力、画幅和分辨率的统一确认弹窗；确认后才创建任务。
- Mock Service 在独立后台流程中推进排队、生成、自动重试、部分失败；切换商品或节点后流程继续，重新进入可恢复当前会话状态。
- 运行中任务只读；已完成任务允许预览；异常任务支持人工单条重新生成。全部任务完成且无异常后才允许完成校验。
- 本次继续只修改 Web 前端及该计划，不修改 API、数据库、Contracts、Worker、Prompt 节点、模板混剪或成片输出。

### 工作流边界

- 直接上游仍是已确认的 `prompt-batch:{productId}`；Mock 用 50 条稳定 Prompt 记录模拟该快照。
- 设置与页面选择只属于节点草稿；本次 Mock 的“完成校验”不提交真实 WorkingArtifact。
- 正式提交边界仍是完成校验，届时应提交 `render-batch:{productId}` 与 `render-clip:{taskId}`。
- 只有正式提交后有效内容变化才会使既有模板混剪结果待更新；本次不模拟下游传播。

### 验收补充

- 单元测试覆盖首次加载零任务、确认后创建 50 条排队任务、后台进度、自动重试、异常恢复、商品切换恢复和重复开始保护。
- 浏览器覆盖未开始、确认弹窗、排队/运行、部分失败、人工重生成、全部完成以及窄屏布局。
- 已执行相关 Vitest、完整 Web 测试、Web 类型检查、ESLint、构建和 `git diff --check`；结果见上方“实际实施与验收结果”。
