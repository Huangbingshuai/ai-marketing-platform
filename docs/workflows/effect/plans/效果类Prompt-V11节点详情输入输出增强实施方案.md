# 效果类 Prompt V11 节点详情输入输出增强实施方案

状态：已完成

## 目标

在不改变 Prompt V11 拓扑、生成逻辑、草稿与 WorkingArtifact 提交边界的前提下，将工作流右侧详情从平铺指标升级为“本次输入、执行情况、本次输出”三段式信息。每类批量结果最多展示 3 条真实样例，同时保留总数和剩余数量。

## 数据与兼容

- 节点详情契约新增可扩展 `sections`，保留原有 `fields`、`blocks` 供历史客户端使用。
- V11 从输入快照、阶段元数据、分片和草稿结果投影真实数据；Worker 只补充缺失的安全业务元数据，不新增数据库表。
- V8～V10 使用相同的输入/输出外壳展示原有安全投影，不伪造 V11 六维、用途或事实绑定。
- 不展示模型、模型指令、原始响应、事实 ID、分片 ID、存储键、签名或内部 JSON。

## 页面行为

- 输入与输出默认展开，执行情况默认折叠。
- 尚未运行时展示预计输入和预计输出；运行中只标注已完成部分。
- 共用提示词、Prompt 正文和六维信息支持展开查看。
- 结果保存必须明确说明当前保存的是节点草稿，只有完成校验才会提交工作副本。

## 验收

- 七个 V11 批次节点均返回输入和输出分区，并覆盖实际、部分、预计和空状态。
- 每类样例最多 3 条，总数仍反映完整批次。
- 历史拓扑、安全脱敏、窄屏、ESC、刷新和错误状态保持正常。
- 通过 Contracts、API、Web、Worker 相关测试、类型检查、构建和 `git diff --check`。

## 实施结果

- Contracts 已增加输入、输出、执行分区及真实创意样例契约，并保留旧版顶层字段兼容读取。
- Worker 已为提炼映射、共用提示词、创意生成与用途评估沉淀安全业务元数据；并修复并行分片完成后阶段仍停留在“执行中”的状态收口问题。
- API 已从输入快照、阶段元数据、分片与 V6 草稿组合安全详情，真实样例最多展示 3 条，不返回事实 ID、分片 ID、模型内容或存储信息。
- Web 已完成三段式详情、长文本折叠、真实 Prompt 样例、窄屏全宽展示，并兼容滚动部署期间尚未返回 `sections` 的旧 API。
- 浏览器已验证输入/输出默认展开、执行信息默认折叠、窄屏无横向溢出、ESC 关闭与焦点恢复。
