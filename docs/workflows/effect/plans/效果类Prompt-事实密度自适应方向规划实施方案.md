# 效果类 Prompt：事实密度自适应方向规划实施方案

状态：已完成

## 目标

修复创意方向数量只随 Prompt 数量变化、没有考虑必用业务事实数量的问题，并避免事实稀少时每个方向被迫机械复用同一组事实。

本次仍属于效果类第 3 节点“Prompt 生成”的“连贯六维创意生成”内部改造，不增加用户可见节点，不修改 Prompt 批次公共契约、HTTP 路径、Prisma Schema、WorkingArtifact 提交边界或第 4～6 节点。

## 上下游与提交边界

- 直接上游：已提交且为当前有效内容的 `marketing-insight:{productId}` WorkingArtifact，以及已提交的全局视频配置。
- 编辑状态：生成、重试和真实验收只更新 Prompt 领域草稿、Run 与 `WorkflowNodeState`。
- 提交边界：只有用户点击“完成校验”且结果满足数量与质量条件时，才更新 `prompt-batch:{productId}` WorkingArtifact。
- 直接下游：视频渲染只消费已提交 Prompt 批次；本次测试不调用 Seedance。

## 方向容量规则

每个创意方向最多自然承载 4 项业务事实，当前工作流继续保持 8～16 个创意方向。方向数量同时考虑：

```text
数量多样性基线 = min(16, max(8, ceil(targetCount / 4)))
事实覆盖下限   = ceil(mandatoryBusinessFactCount / 4)
最终方向数     = max(数量多样性基线, 事实覆盖下限)
```

在发起创意版图 AI 调用前机械检查：

- 没有任何卖点、痛点、受众、决策动机、营销目标或确认场景时，明确阻止生成；产品名、品类和规格不能冒充业务事实。
- 必用事实超过 `targetCount × 4` 时，明确提示当前用户数量不足以及至少需要的 Prompt 数量。
- 事实覆盖下限超过 16 时，明确提示当前单批 8～16 方向最多自然承载 64 项必用事实；不调用模型、不静默遗漏事实。

## 稀疏事实分配规则

整批仍必须覆盖每项必用业务事实，但不再无条件要求每个方向都使用 2 项业务事实：

- 业务事实不少于方向数的 2 倍：每个方向至少 2 项业务事实。
- 业务事实不少于方向数但不足 2 倍：每个方向至少 1 项业务事实。
- 业务事实少于方向数：至少 `业务事实数` 个不同方向承载业务事实，剩余方向可使用已确认的产品身份、规格或视觉事实形成不同产品表达；不得伪造新的营销事实。
- 任何事实数量下，全部必用业务事实都必须在整批方向中至少自然使用一次。

语义关系继续由创意版图 AI、事实主承载 AI、方向 AI 和独立 AI 复核判断。Worker 只核对事实来源、稳定 ID、数量、容量、覆盖和结构，不使用关键词或字符相似度判断业务语义，也不自行补挂事实。

## 错误恢复与兼容

- 事实遗漏、重复和未知引用继续把精确诊断交回事实分配 AI 局部重取。
- 创意空间不再使用“最多 8 项事实”的固定上限。同一业务主题可以承载更多自然相关事实，Worker 按每 4 项主承载事实增加一个方向槽位；避免 AI 为绕开容量而把同一主题拆成多个同义空间。
- 事实与空间或方向语义不自然时，继续由独立 AI 要求业务重规划。
- 方向目标数和事实密度写入模板哈希所覆盖的模型输入；同一 Run 的合法检查点可恢复，重新批量生成仍从头调用模型。
- 历史结果继续可读，不为历史 Run 伪造新方向数量或事实分布。

## 测试与验收

自动测试至少覆盖：

- 50 条、37 项事实仍规划 13 个方向。
- 10 条、37～40 项事实提升为 10 个方向并完整覆盖。
- 事实超过用户最终容量时在模型调用前返回明确错误。
- 65 项事实超过当前 16 方向上限时明确失败。
- 1～3 项稀疏事实只要求整批分散覆盖，不强迫每个方向复制同一组合。
- 0 项业务事实明确失败，产品名称或规格不能冒充覆盖。
- 富信息商品仍要求每个方向至少 2 项业务事实。
- Mock 全链路、检查点恢复、单条重生成、数量择优和 WorkingArtifact 边界不回归。

执行 Prompt Worker pytest、mypy、Ruff 和 `git diff --check`。自动回归通过后，使用当前已提交营销洞察执行受控真实 Ark 测试，严格停在最终 Prompt 生成之前；若真实链路出现 Bug，先修复并重跑自动测试，再继续付费测试直到方向规划成功。真实结果、调用次数、事实覆盖与剩余风险回填本文后将状态改为“已完成”。

## 实施与验收结果

已完成以下改造：

- 方向数量同时按 Prompt 数量和必用业务事实数量计算，并在首次 AI 调用前检查 0 事实、用户 Prompt 数量容量和 64 项单批方向容量。
- 富信息、中等信息和稀疏信息批次分别使用不同的事实密度要求；不再无条件要求所有方向绑定两项业务事实。
- 创意方向模型明确接收本批密度要求，Worker 只检查 ID、数量、结构与全局覆盖。
- 创意空间取消固定 8 项事实上限。同一自然业务主题可以集中承载事实，方向槽位按每 4 项主承载事实自动增加。
- 内部创意空间契约支持 1～10 个真实空间，稀疏商品不再被迫虚构五个空间。

自动验证结果：

- Prompt Worker `pytest -q`：143 项通过，1 项显式跳过。
- Prompt Worker `mypy src`：通过。
- Prompt Worker `ruff check src tests`：通过。
- 新增了 37 项事实、40 项事实、用户数量不足、65 项超限、0 项事实、稀疏事实，以及单空间承载超过 8 项事实的专项回归。

真实 Ark 验收使用当前已提交的广式腊肠营销洞察，只执行到创意方向复核并在最终 Prompt 生成前停止：

- 第一次测试发现固定 8 项空间容量会导致自然聚类反复重分配，随即停止并修复，没有生成最终 Prompt。
- 修复后的第二次测试成功：37 项必用业务事实规划为 13 个方向、6 个真实创意空间，覆盖 37/37。
- 13 个方向均形成不同事实组合和不同六轴语义档案；场景—主动作组合 12 组，最大重复 2 条。
- 每方向绑定 3～4 项确认事实；全部核心卖点、次要卖点、受众、痛点、决策动机、营销目标和三类场景均完整覆盖。
- 独立 AI 语义复核最终无遗留问题，未发现事实牵强、未确认条件依赖或语义错位。
- 成功轮共 12 次 Ark 调用，累计约 113,395 Token，耗时约 371 秒；完整原始结果只保存在 Git 忽略的本地验收目录。
- 测试未调用 Seedance、未生成最终 Prompt、未点击完成校验，也未覆盖现有 WorkingArtifact。
