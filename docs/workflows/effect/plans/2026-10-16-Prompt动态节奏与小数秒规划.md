# Prompt 动态节奏与小数秒规划

## 范围与边界

优化效果类素材 Prompt 节点，适用于任意商品及当前 AI 批次支持的全部 4～15 秒时长，不扩张生成时长范围、不自动改写人工条目。上游仍为同项目/Run 已确认 `marketing-insight:<productId>` 及其 artifactId、revision；输入快照、租约、分片恢复和完整成功后自动提交 `prompt-batch:<productId>` 保持不变。下游片段渲染只在用户主动生成时使用新正文，不启动渲染、混剪或包装。

## 原因与方案

- 旧生成建议短片一个节拍，评分要求一个动作并停留，整秒权重分配会把单一动作摊满整段。
- 一个商业事件可以含多个因果连续的子动作或观察阶段。节拍不是切镜：可保持同机位连续推进，也可明确硬切；不增加无关操作、事实或多场景广告。
- 内部 `MaterialShotBeat` 增加可选 `durationSeconds`，精度 0.1 秒。新生成/修订逐拍填写，总和必须等于目标；全部缺省的历史计划保留旧 `durationWeight` 分配和正文。禁止混合填写或静默拉伸错误时长。字段是 Worker 内部模型/检查点，不进入公开结果契约。
- 生成、前置全量修正、历史修订和评分同步：正常使用速度，不默认慢动作；每段有真实动作进展或新观察信息，尾部短暂收束；真实有观看价值的静物、自然慢过程和留白允许存在，不能机械凑节拍。
- 沿用 DURATION_TOO_SPARSE / DURATION_TOO_DENSE 软提醒和商业价值评分，不加语义硬门槛、不增加模型节点/重试循环、不更换模型。

## 时间能力边界

小数秒是内部节奏意图，不承诺渲染模型精确响应或毫秒级切镜。官方 Seedance 2.5 指南区分 2.0 的镜头序号与 2.5 的整数秒时间戳。本次不改渲染供应商协议；正文仍有清晰顺序、动作完成点及可见结果，不能只靠时间数字表达动态。

来源：https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=en

## 验证与付费验收

- 覆盖全部整数目标时长 4～15 秒、小数精度、总和/混填/越界、六节拍短片、旧编译不变、格式剥离、修正后重新编译。
- 跨品类用食品、洗护、设备、箱包的普通测试数据检验机械编译；模板测试确保没有商品专用脚本或旧单节拍限制。测试不证明 AI 语义质量。
- 执行 Worker 非付费 pytest、mypy、相关 API/Web 回归及 diff 检查。
- Git 只提交本次文件/文档段落；核实 Prompt 队列无活动任务后更新 Worker 并核对运行文件。
- 经正式浏览器对原广式腊肠项目重新生成一轮，沿用原数量/时长/AI 自动风格。旧分支保留，保存两份完整导出对照；逐条检查有效推进、过长无信息停留、物理冲突、事实边界和重复度，报告耗时与未验证范围。
- 只授权本轮 Prompt 付费生成，不付费渲染。原批次可能含人工编辑/不同条目时长，因此对比仅对同长度 AI 条目作描述性分析，不冒充严格随机 A/B。

## 实施验证

- Worker：463 项通过；排除 1 项未授权的付费集成、4 项既有人工六维模型类型相等断言。后四项使用 HEAD 的原始 models.py 在内存加载复现，同样失败，不改动无关业务。
- mypy：27 个源文件通过。Web Prompt：75 项通过。API Prompt：144 项通过、6 项跳过、2 项既有 mock 方法缺失失败（products / commitValidatedResult）；本次无 API 源码改动，不记为全绿。
- 新 AI 请求 Schema 强制数值 durationSeconds，历史模型缺省可读且序列化不追加 null，保留旧候选检查点指纹。每条请求原有 temporalIntent 中的单动作/两拍与字数压缩指导也已同步移除。
- 付费前基线：正式广式腊肠项目 33 条（AI 29、外部导入 4），目标设置 30 条×15 秒、淘宝、AI 自动风格；页面显示上轮重复度 6.7%。原分支已有人工正文修改，不能视为纯原始生成对照。
