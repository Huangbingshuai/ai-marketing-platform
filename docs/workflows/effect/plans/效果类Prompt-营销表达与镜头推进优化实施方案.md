# 效果类 Prompt 营销表达与镜头推进优化

## 状态与边界

代码实施与自动回归已完成；真实创意质量对比待验证。仅优化当前效果类第 3 节点的创意方向及拍摄计划生成模板。

输入仍是本 Run 固定的已确认营销洞察 artifactId/revision、事实视觉策略、方向事实组合和 Prompt 设置。输出仍保存领域草稿及 WorkflowNodeState；只有用户完成校验才提交 `prompt-batch:{productId}`，之后视频渲染按原有 revision 规则消费。模板修改本身不修改历史草稿、WorkingArtifact 或下游状态。

## 实现

1. 在原有 creativeDirection 中简洁表达观众关注点、产品价值与可见事件；factApplications 继续承载事实的自然使用方式，不添加字段、长推理或额外模型调用。
2. 拍摄模型在原有 creativeCore、overview、action、camera、visibleResult、dialogue、sound 中完成营销表达。镜头切换服务于新信息、注意力转移或情绪变化；同场景连续动作允许合理切镜，也允许一镜到底。
3. 加入少量带前提的跨品类微型示例，示范需求驱动、细节揭示、人物选择等不同方式，不提供全批套用的脚本或固定顺序。示例不是当前商品事实。
4. 表演、光线、声音与焦点按创意需要具体化；有人开口时仍提供逐字台词。不要求每个节拍写齐表情、音乐、台词，不使用统一前缀，不靠字数和镜头数证明质量。
5. 初始方向、补充方向、批量生成和单条重生成使用同一表达原则。所有时长沿用原有软密度提示和输出预算。

## 非目标

- 不改 Schema、HTTP、数据库、八阶段拓扑、模型路由、并发或调用预算。
- 不改评分、硬问题、MMR、事实覆盖或数量补充算法；不增加 Worker 语义判断。
- 不把素材升级为完整广告脚本，不承诺未经验证的功效或广告转化效果。
- 不自动启动付费任务、不提交工作副本、不自动提交 Git。

## 验证

- 模板渲染及 Provider MockTransport 验证生成请求确实使用更新后的导演指导，事实和共用约束不丢失。
- 跨品类、4/8/15/20/25/30 秒回归确认原结构可解析，镜头、台词和声音由模型输出原样进入编译结果，不增加调用。
- 保持事实、安全边界及独立评估模板不变；模板内容哈希沿用现有机制。
- 执行 Worker pytest、mypy、Ruff 和 git diff --check。
- 自动测试只能验证接线与兼容性。真实质量、重复度、耗时和成本需另用同商品同参数真实批次对比，不能从 Mock 得出改善结论。
