# 包装失败保留基线与局部更新修复

## 已核对问题与范围

- 效果类模板混剪节点，测试1的第二轮整批包装部分失败。成片13保留了上一轮包装与输出快照，但新 Run 未复制同节点的 timeline-project / timeline-package 工作副本。普通祖先读取正确地阻止了同模板跨填充分支继承，导致局部更新报“包装工作副本不可用”。
- 直接上游仍是当前已确认渲染素材与冻结 revision；局部更新成功只提交当前 Run 的工程及包装，下游输出不自动编码。
- 不改变重试、归槽、付费任务、分支发布规则或界面；不清理文件，不批量改写历史数据。

## 实施

1. 新建重新包装子 Run 时，复用现有工作副本复制及 ID / 哈希重映射流程，额外携带当前模板的已确认混剪基线。重新填充仍不复制当前节点结果。
2. 兼容已存在的缺基线包装分支：仅在确有新协议整批失败条目、当前成片输出快照明确引用旧包装、包装检查点未改变且当前无同键工作副本时，读取快照明确引用的祖先工程与包装。校验同项目、同效果类谱系、模板、成片、精确 revision / hash 和可用性；不通过模糊名称或最新历史结果猜测。
3. 兼容读取只服务本次工程重写，不修改祖先、不增加业务 revision、不启动包装任务。后续局部更新仍由原事务提交当前 Run 的真实结果。当前副本存在但失效、文件失效、非祖先及内容不一致继续拒绝。

## 验证

- 单元覆盖重新包装与重新填充的复制范围、历史基线读取、同键失效不回退、revision / hash 漂移、兄弟分支 / 项目 / 模板隔离及检查点不一致。
- 真实数据库回滚验证新包装分支复制，及测试1失败成片的已确认基线可读取；不创建付费任务、不持久化测试分支。
- API 相关测试、类型检查、构建与 git diff --check；核对运行服务实际生效。无需修改 Web / Contracts / Worker。
