# 时间轴轨道头三态视觉：隐藏变暗 / 视频静音只压音频条 / 锁定变栅栏

日期：2026-09-25
需求原话（三条）：

> 首先轨道头的眼睛关闭之后应该是整个轨道变黑，然后视频素材的声音键点击后也应该像音频轨道那样的交互变白，然后锁头点击之后应该锁住整个轨道不允许变动，应该是整个轨道变成栅栏那种，反正和剪映一致

同日用户对其中两条给出修订：

> 眼睛关闭的轨道变黑太深了；视频素材声音关闭应该是下方的音频轨道变白而已

承接 `2026-09-24-时间轴边框新建轨与拖入替换.md` / `2026-09-25-时间轴音乐落轨与字幕拖动修复.md`。本轮只补**轨道头三个按钮对应的视觉反馈**，不新增交互能力。

## 一、范围

| # | 现象 | 本轮口径（含同日修订） |
| --- | --- | --- |
| 1 | 点眼睛关掉轨道后，只有片段被压得很淡，轨道本身还是浅色，「看不出这条轨关了」 | **整条轨道变暗**：轨道底色转成中间调的石板灰（不是黑，见三·一），片段同时去色压暗。 |
| 2 | 点视频轨的喇叭，**什么视觉都没有**；音频轨点静音片段会「变白」 | 只把片段**底部那条音频波形条**压成灰白；**画面本身不动**（见三·二）。 |
| 3 | 点锁头只有鼠标变成 `not-allowed`，轨道上看不出锁了 | 整条轨道铺**斜纹栅栏**，一眼看出被锁。 |

## 二、现状与实测证据

三个按钮都在轨道头同一处（`EffectTemplateMixTimeline.vue:3105-3135`）：

```html
<div class="track-actions">
  <button :title="trackLocked[track] ? '解锁轨道' : '锁定轨道'" @click="trackLocked[track] = !trackLocked[track]"> … Lock/Unlock
  <button v-if="track === 'VIDEO' || isCaptionTrack(track)" @click="toggleTrackVisible(…)"> … Eye/EyeOff
  <button v-if="!isCaptionTrack(track)" @click="emit('toggleAudioMute', track, !trackMuted(track))"> … VolumeX/Volume2
</div>
```

- `trackVisible`（`:1146-1147`）→ `props.videoVisible` / `props.captionVisible`；`trackMuted`（`:1154-1155`）→ 视频取 `props.videoMuted`，音频行取 `props.audioRowMuted[行号]`。
- 三个 class 绑定分别落在 `:3184`（字幕轨 `is-hidden`/`is-locked`）、`:3234`（视频轨）、`:3385-3388`（音频轨 `is-locked`）。

### 2.1 隐藏：只压子元素，不压轨道

`:3810-3813`

```css
.timeline-track.is-hidden > :not(.track-empty-copy) {
  opacity: 0.12;
  pointer-events: none;
}
```

轨道自身仍是 `.timeline-track.video-track { background: #f7f9fc }`（`:3784-3787`），字幕轨还是 `:3794-3802` 的浅色横条渐变。所以「关掉眼睛」看起来只是片段变淡，**轨道没有变黑**。

### 2.2 视频静音：class 与样式都不存在

音频片段（`:3406-3407`）带 `'is-muted': trackMuted(track)`，样式 `:4291-4293`：

```css
.audio-clip.is-muted {
  opacity: 0.42;
}
```

音频片段底色是深色（`.voice-clip { background: #2f4b8f }`、`.bgm-clip`、`.detached-audio-clip`，`:4276-4290`），`opacity: .42` 叠在浅色轨道底上就是用户说的**「变白」**。

视频片段 `:3246-3256` 的 class 对象里**没有 `is-muted`**，`.video-clip` 全仓库也没有任何静音样式 —— 所以点视频轨的喇叭**没有任何反馈**。

### 2.3 锁定：只有光标

`:3807-3809`

```css
.timeline-track.is-locked {
  cursor: not-allowed;
}
```

**编辑拦截本身已经完备**，不需要补：`trackLocked` 在拖入/拖动/选中/落轨各处都有守卫 —— 视频 `:1226`、`:1290`（dragover）、`:1474`、`:1507`、`:1615`、`:1965`、`:1980`；音频 `:2099-2100`（`audioRowLocked`）、`:2103`、`:2136`、`:2144`；字幕 `:2222`、`:2253`、`:2305`。缺的只是「看起来锁住了」。

## 三、设计

### 一、隐藏 → 整条轨道变暗（修订：不是黑）

```css
.timeline-track.is-hidden,
.timeline-track.caption-track.is-hidden {
  background: #8f9aab;
}
.timeline-track.is-hidden > :not(.track-empty-copy) {
  opacity: 0.3;
  filter: grayscale(1);
  pointer-events: none;
}
```

- 底色单独写一档中间调，**字幕轨要用同样的选择器覆盖**它自己那条 `repeating-linear-gradient`，否则字幕轨关眼睛后仍是浅色。
- 色值取 `#8f9aab`：它是轨道自身底色 `#f7f9fc` 与本应用强调色 `#263b59`（锁定栅栏用的那支深蓝）的**中点**，所以「这条轨关掉了」看得出来，又不会变成一块黑。第一版写的 `#1b2431` 太深，用户实测后要求调亮。
- 子元素从 `opacity: .12` 提到 `.3` 并去色：底色已变暗 + 去色已经足够说明「这条轨关了」，片段轮廓还看得见，方便用户找回要开的那一条。
- `pointer-events: none` 保持原样（隐藏轨道不可点选），本轮不改这个口径。

### 二、视频静音 → 只压片段底部那条音频条（修订）

视频片段 class 对象加一行：

```ts
'is-muted': trackMuted('VIDEO'),
```

样式**不再压整个片段**，而是覆盖 `EffectTemplateMixWaveform` 那条 18px 底边音频条的调色板：

```css
.video-clip.is-muted .clip-waveform {
  --wave-border: #ccd5e1;
  --wave-border-solid: #ccd5e1;
  --wave-bg: #eaeef4;
  --wave-bg-solid: #eaeef4;
  --wave-line: #ccd5e1;
  --wave-line-solid: #ccd5e1;
  --wave-bar: #c2cbd7;
}
```

- 视频片段 = 缩略图胶片 + 底部一条音频波形条（`EffectTemplateMixWaveform.vue:102-117`，`layout` 默认 `strip`，`bottom: 0; height: 18px`）。「视频素材声音关闭」关的是**这条音频条**，画面不该跟着变。
- **不能用 `opacity`**：音频片段静音用 `opacity: .42` 之所以读作「变白」，是因为它底下的轨道是浅色；视频片段的音频条底下是缩略图，半透明只会透出画面。所以这里直接把这支调色板换成灰白，得到同一眼「哑掉了」的读感。
- `.clip-waveform` 正是子组件的**根元素**，父组件的 scoped 规则能直接命中它；父规则 `.video-clip.is-muted .clip-waveform` 权重也高于子组件自己的 `.clip-waveform` / `.has-samples`。
- 第一版写的是 `.video-clip.is-muted { opacity: 0.42 }`（压整个片段），用户实测后要求改成「下方的音频轨道变白而已」。

### 三、锁定 → 斜纹栅栏

```css
.timeline-track.is-locked::after {
  content: '';
  position: absolute;
  inset: 0;
  z-index: 6;
  pointer-events: none;
  background-image: repeating-linear-gradient(
    45deg,
    rgba(38, 59, 89, 0.16) 0 6px,
    transparent 6px 12px
  );
}
```

- 伪元素铺满整条轨道，`z-index: 6` 高于片段（片段没有更高的 z-index；拖动中的片段是 8，松手即回到栅栏之下，可接受）。
- `pointer-events: none`：拦截仍由既有的 `trackLocked` 守卫负责，栅栏只负责「看得见」。
- 用半透明深蓝斜纹而不是纯色遮罩，片段仍可辨认，和剪映的锁定表现一致。

## 五、非目标

- **不改任何行为口径**：隐藏轨道仍不可点选、锁定轨道仍不可选中/拖动/落轨、静音仍按行独立 —— 本轮全部是视觉。
- 不给音频轨加眼睛、不给字幕轨加喇叭；按钮组合保持现状。
- 不做剪映的「隐藏轨道仍可在时间轴选中」——那是行为改动，另开一轮。
- 不动 `videoMuted` / `videoVisible` / `audioRowMuted` 的状态与持久化（在 `EffectTemplateMixNodePage.vue`）。
- 不碰 `.audio-clip.is-muted` 的既有值。

## 六、风险与边界

- **锁定栅栏盖在片段之上但不可点**：拦截靠 `trackLocked` 守卫而不是这层遮罩，所以遮罩漏在哪个元素上都不会让锁定失效；反过来，遮罩也挡不住任何已经放行的操作。
- **隐藏轨道的片段仍保留轮廓**（`opacity: .3`）：如果用户觉得不够暗，只要调底色这一个值，不改结构。
- **修订后视频静音不再改变画面**：`is-muted` 仍挂在 `.video-clip` 上（它同时是「这条轨静音了」的钩子），只是样式落到了子元素 `.clip-waveform`；父 scoped 规则命中子组件根元素这一点依赖 Vue 的 scoped 行为，已由单测断言源码、`vue-tsc` 0 error 兜住。
- **与并行会话同文件**：`EffectTemplateMixTimeline.vue` 此刻仍被另一会话高频改写。本轮只做**就地小改 + 纯 CSS 追加**，不重排既有代码；提交前需要在无并发写入时重跑一次。
- 拖动中的片段 `z-index: 8` 会短暂盖过栅栏，这是「正在拖动」的正常层级，松手即恢复。
