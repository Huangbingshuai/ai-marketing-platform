# 效果类 Prompt：模型驱动创意版图与方向复核实施方案

状态：已完成

## 目标

解决同一批创意方向虽然使用了不同文字标签，实际仍集中在相同厨房场景和切制动作的问题。语义规划、归类和复核全部交给 AI；Worker 只校验结构、事实来源、数量、ID、哈希和检查点，不使用商品关键词、字符相似度或自由文本规则判断场景与动作含义。

## 范围

只调整效果类 Prompt 节点现有“连贯六维创意生成”阶段的内部步骤，不新增用户可见节点，不改变 Prompt 批次公共结构、HTTP 路径、Prisma Schema、WorkingArtifact 提交边界或下游视频渲染契约。

## 内部流程

```text
当前提炼信息表
→ AI 规划产品专属创意版图
→ AI 按版图生成多事实创意方向
→ 独立 AI 复核实际版图归属
→ 必要时由 AI 重规划拥挤或错位方向
→ 分配到单条 Prompt 生成任务
```

### 1. 产品专属创意版图

模型根据本次已确认事实、事实视觉策略、视觉风格基调和共用提示词，生成产品专属创意空间。每个空间包含稳定 ID、通俗名称、兼容事实、主场景边界、可用主动作以及建议承载的方向数量。建议数量总和必须等于本批创意方向数量。

创意空间由模型按产品动态生成，不在 Worker 中写死“厨房、切片、送礼”等词库。换商品后必须重新规划。

### 2. 创意方向生成

模型接收已验证的创意版图，为每个方向明确选择一个创意空间和一个主动作，并生成 2～4 项相关事实的具体使用说明。全部业务事实仍须在整批方向中至少使用一次。

每个方向只允许一个主要场景和一个连续主动作。产品可以处于切片、打开或已摆放状态，但产品状态不得自动等同于主动作。

### 3. 独立 AI 语义复核

独立评估调用读取创意版图和全部方向，重新判断每个方向实际实现的创意空间与主动作，并指出错位、同义改名、多场景或多主动作问题。Worker只验证评估结果是否覆盖全部方向、引用合法版图和动作 ID，并按模型结论决定是否请求一次整批重规划。

Worker不得自行根据方向文字猜测其场景或动作，也不得随机替换事实或创意空间。

### 4. 分配与检查点

后续候选任务按模型确认的创意空间与主动作均衡领取方向。Worker只依据稳定 ID 和模型给出的建议承载数量做机械分配，不读取场景、动作正文作业务判断。

创意版图、方向计划和语义复核结果保存到现有阶段检查点。输入事实哈希、视觉策略哈希、共用提示词哈希、目标数量或模板哈希变化时检查点失效；不跨 Run 复用。

## 验收

- Mock Provider 完整覆盖版图规划、方向生成和独立复核。
- 创意版图建议数量之和严格匹配目标方向数。
- 未知事实、未知版图、未知动作和缺失方向复核被结构校验拒绝。
- Worker 不包含商品专属场景或动作关键词，也不通过字符相似度判断方向语义。
- 方向计划继续覆盖全部卖点、痛点、受众、决策动机、营销目标及确认场景。
- 单条生成任务只接收所属方向，不接收完整批次版图。
- 相关 pytest、mypy、Ruff 与 `git diff --check` 通过。

## 非目标

- 本次不调整创意评估模型的质量评分权重。
- 不实现视频渲染、视频内容分类或 Seedance 调用。
- 不增加硬编码场景配额，不使用规则模板兜底创意。

## 实施结果

- 新增 AI 产品专属创意版图契约：版图空间、兼容事实、具体主动作和建议承载数全部由模型输出。
- 创意方向必须引用版图稳定 ID，并严格按照模型给出的 `targetSlots` 生成；Worker只核对引用、数量和事实来源。
- 新增独立 AI 方向语义复核：复核模型不相信方向自报标签，重新判断实际版图与主动作；需要调整时由方向模型整批重规划一次。
- 方向分配改为按 AI 版图 ID 与动作 ID 机械均衡，不再读取自由文本场景和动作含义。
- 创意版图、方向及复核结果随现有阶段检查点保存；模板内容纳入统一哈希。
- 未修改公共 Prompt 批次结构、HTTP 路径、Prisma Schema、八阶段拓扑或 WorkingArtifact 提交边界。

## 真实验证

已执行：

```text
uv run --frozen pytest -q
uv run --frozen mypy src
uv run --frozen ruff check src tests scripts
git diff --check
```

结果：Worker 全量 pytest 通过（1 项按原配置跳过），mypy 通过，Ruff 通过，`git diff --check` 无空白错误。

随后使用当前已提交的广式腊肠信息表执行了一次受控付费测试，并严格停在具体 Prompt 生成之前。事实视觉策略调用成功；创意版图调用在 4096 Token 处返回 `status=incomplete / reason=length`，因此方向生成和独立语义复核没有继续执行。真实响应表明 Ark 会把隐藏推理和结构化正文共同计入输出额度，富信息卡即使只规划 5～10 个版图空间也可能耗尽 4096 Token。

已据此修复：创意版图、方向规划和批次语义复核统一使用可配置的策略输出额度（默认 8192），并从版图和方向输入中删除不再需要的重复兼容事实列表，保留事实原文、视觉角色、可见指令、上下文指令和禁止推导边界。修复后重新执行 Mock 全量回归；本轮未在未经额外授权的情况下再次产生付费调用，也未执行 Seedance 渲染。

用户继续授权后，使用同一已提交信息表继续受控付费联调。真实链路进一步暴露并修复：长哈希事实 ID 抄写错误、必用事实主分配遗漏、`targetSlots=0`、Ark 标记 `completed` 但 JSON 中途结束、模型把主分配事实漏抄到兼容数组等问题。事实视觉策略、版图和方向调用统一使用请求内短别名 `F1/F2...` 并在返回后机械恢复；版图和方向的结构化 JSON 异常只局部重试当前步骤一次；版图事实或配额无效时由 AI 整体重规划一次，Worker 不做语义补挂。`requiredFactIds` 本身即声明相容性，系统只做集合合并，不再要求模型在两个数组重复抄写同一 ID。

最终成功验收严格停在具体 Prompt 生成之前：读取结果 revision 1、WorkingArtifact revision 1、来源指纹 `e8f816…a26d`；6 次成功 Ark 调用共计输入 54,314 Token、输出 13,212 Token、总计 67,526 Token，累计供应商耗时 253.33 秒，端到端 273.14 秒。产出 8 个创意空间和 13 个方向，32/32 项必用业务事实全部覆盖，13 组事实组合、13 组空间与主动作组合均不同，独立 AI 语义复核最终通过。

人工复核显示同质化较旧基线明显下降：明确厨房烹饪方向约 6/13，明确切片或铺片主动作约 2/13；旧结果约 8/13 集中厨房且约 8/13 涉及切片。仍有少量方向的事实关系偏弱，例如袋装送礼查看场景绑定“切片均匀”，以及用外观和分享状态暗示“品质稳定”。因此本次只确认“创意版图与主动作去同质化、事实全量分配链路”通过，不宣称具体视频 Prompt 质量已完成最终验收；后续应由独立 AI 复核继续检查每项事实与方向的自然相容性，不得转回 Worker 关键词或字符规则。

## 事实与创意关系自然度增强

本轮增强现有“AI 规划产品专属创意版图”，不删除版图、不新增业务节点，也不增加模型调用次数：

1. 版图模型为每个兼容事实给出该事实在本版图中的自然使用依据，不能只输出 factId 列表。
2. 方向模型只能从版图已确认的事实适配关系中选择事实，并继续说明事实如何共同进入当前创意。
3. 独立语义复核除重新判断实际版图和主动作外，还逐项判断方向中的事实应用是否自然、是否依赖未确认画面条件、是否把抽象痛点或卖点伪装成视觉证明。
4. 复核模型输出需要修订的方向 ID；方向模型按复核结论重新规划这些方向，Worker按稳定 ID 机械保留未点名方向。Worker 只校验事实 ID、方向 ID、数量、结构和复核结果覆盖完整，不自行理解事实语义，也不随机替换事实。
5. 若某项必用事实无法在当前版图中自然承载，复核结论必须要求重新规划相关方向；不能为了覆盖率把它塞进送礼、包装或其他不相容场景。

验收要求：

- 送礼方向不得再用“切片均匀”一类无法在该场景自然体现的事实凑覆盖。
- 未确认包装透明度时，包装方向不得通过袋内纹理证明产品油润或切面特征。
- “担心品质不稳定”等抽象痛点只能作为真实人物需求或决策语境，不能由分享、外观或单次食用画面证明已解决。
- Mock 与结构测试覆盖事实逐项复核、未知 factId、缺失事实复核、复核触发重规划和检查点恢复。
- Worker pytest、mypy、Ruff 和 `git diff --check` 通过后，将状态改回“已完成”并记录真实结果。

实施结果：现有创意版图契约增加逐事实 `factCompatibilities`，包含自然使用方式和最多三项不成立条件；独立语义复核增加逐方向、逐事实的 `factReviews`，由评估模型给出 `NATURAL / WEAK / UNSUPPORTED`。只要模型判定任一事实关系不自然，该方向就必须进入 AI 重规划清单；需要交换事实时，评估模型必须同时点名接收调整的方向。Worker按稳定 directionId 机械合并修订结果并保留未点名方向，仅校验兼容说明与 factId 集合一致、每项计划事实恰好被复核一次，以及复核结论和重规划 ID 自洽；没有新增商品词库、字符匹配或 Worker 语义判断。

已执行完整 Worker pytest（除原有 1 项按配置跳过外全部通过）、mypy、Ruff 和 `git diff --check`。本轮未获得新的付费调用授权，因此没有宣称真实 Ark 对上述三类历史弱关系已经完成线上复验；模板哈希变化会使旧检查点失效，新任务将重新规划版图和事实关系。
