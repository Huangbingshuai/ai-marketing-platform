# 效果类 Prompt：长任务心跳容错实施方案

## 状态

已完成。

## 背景

洗发露 100 条×30 秒真实任务在创意规划阶段持续运行时，Worker 的一次内部 API `ConnectTimeout` 会直接终止心跳协程。业务图仍继续调用 Ark，但 90 秒租约不再续期，API 随后把仍在工作的 Worker 误判为失联并重新排队；旧尝试完成后只能收到 409。

## 边界

- 仅修改效果类 Prompt Worker 的租约心跳容错，不改变八阶段图、Prompt 生成算法、公开契约、HTTP 路径、数据库结构和 WorkingArtifact 提交边界。
- 直接上游仍为已提交的营销洞察与视频配置；输出仍只保存 Prompt 节点草稿，用户完成校验后才提交 `prompt-batch:{productId}`。
- 不吞掉无效 attempt token、租约过期等 4xx 错误；旧 Worker 仍不能覆盖新尝试。

## 实施方案

1. 心跳保持每 30 秒发送一次。
2. 网络、超时、429 或 5xx 等可重试错误不再结束心跳协程，5 秒后重新发送。
3. 重试成功后恢复正常 30 秒周期；持续失败时最终会收到非重试的租约冲突并停止旧尝试。
4. 心跳等待必须响应任务结束信号，任务完成后不能遗留后台协程。
5. 增加单元测试，覆盖一次瞬时故障后恢复，以及非重试错误立即上抛。

## 验收

- Worker 消费者测试、全量 pytest、mypy、Ruff 与 `git diff --check`。
- 重建 Prompt Worker 后，通过独立 5174 前端执行山茶花氨基酸洗发露 100 条×30 秒真实付费测试。
- 结果必须精确 100 条，记录事实覆盖、候选淘汰、重复度、质量分和刷新恢复情况。
- 不点击 Prompt“完成校验”，不调用 Seedance。

## 实施结果（2026-09-04）

- 心跳协程现在会在网络、超时、429 和 5xx 后等待 5 秒重试；租约冲突等不可重试错误仍立即结束旧尝试。
- 增加了瞬时心跳故障恢复与不可重试错误上抛测试。Prompt Worker 全量 pytest 通过（1 项按环境跳过），mypy、Ruff 和 `git diff --check` 通过。
- 第一次真实 100 条×30 秒批次在旧 Worker 上暴露一次 `ConnectTimeout`，API 将任务恢复为第 2 次尝试后成功保存 100 条草稿。这次异常用于确认根因，不作为修复后的稳定性结论。
- 重建 Worker 后，第二次真实 100 条×30 秒批次从事实视觉策略开始完整重算，在第 1 次任务尝试内成功保存 100 条草稿；全程心跳持续返回 200，没有租约误回收或跨尝试覆盖。
- 两次结果均保持 33/33 必用事实覆盖、0 条硬问题淘汰、0 条完全重复、100/100 精确数量，且未提交 WorkingArtifact、未调用 Seedance。
- 第一轮最终语义重复度为 43%，第二轮为 48%。这说明长任务稳定性已修复，但洗发露 100 条大批次仍存在浴室、按压泵头等创意集中；该项属于后续创意容量优化，不由心跳容错改动掩盖。
- 首轮人工抽查发现 4 条 Prompt 把“画面不作为配方证明”写成口播。生成模板已明确将事实视觉策略和免责声明限定为内部创作边界；第二轮 100 条正文复查为 0 条此类元说明，同时正文中时长、画幅和分辨率均为 0 条。
