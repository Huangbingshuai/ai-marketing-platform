# 效果类 Prompt：四类素材用途收敛实施方案

状态：已完成

## 一、范围与边界

- 当前节点：效果类第 3 节点“Prompt 生成”。
- 直接上游：已提交的 `marketing-insight:{productId}` 与全局视频配置工作副本及其 revision。
- 节点草稿：Prompt 批次领域草稿；仅用户点击“完成校验”后提交 `prompt-batch:{productId}` WorkingArtifact。
- 直接下游：视频渲染消费已提交 Prompt 批次；用途只作为请求快照、素材标签和素材池分组，不拼入 Seedance Prompt 正文。
- 本次不改变八阶段执行图、创意方向规划、事实分配、候选数量、质量择优、共用提示词和提交边界。

## 二、目标语义

新生成结果只允许四类素材用途：

| 枚举              | 中文名称     | 定义                                                                     |
| ----------------- | ------------ | ------------------------------------------------------------------------ |
| `HOOK`            | 钩子片段     | 用问题、悬念、痛点或反差吸引注意                                         |
| `PRODUCT_DISPLAY` | 产品展示片段 | 展示产品身份、包装、外观、质地或使用动作                                 |
| `EFFECT`          | 效果片段     | 展示产品解决需求后的结果、卖点表现或使用价值，不等同于未经确认的功效证明 |
| `CTA`             | 结尾转化片段 | 承担购买引导、品牌收束、稳定停留或字幕安全区                             |

旧六类结果在读取边界进行兼容投影：

```text
HOOK                       → HOOK
PAIN                       → HOOK
PRODUCT_DISPLAY            → PRODUCT_DISPLAY
SELLING_POINT_EXPLANATION  → EFFECT
CTA                        → CTA
OUTRO                      → CTA
```

投影同时处理主用途、兼容用途并去重，再按四类重新计算统计；不改写正文，不自动增加 WorkingArtifact revision。新生成、新编辑与新渲染快照只保存四类值。

## 三、实施项

1. Contracts：同步 TypeScript 枚举、标签、严格 JSON Schema、兼容用途上限与相关测试。
2. Worker：同步 Pydantic 枚举、AI 用途分类提示、Mock 分类、用途统计和事实适用表；创意生成任务继续不接收用途类型。
3. API：在批次解析前兼容旧六类条目和用途统计；同步校验、搜索、编辑、节点详情与测试。
4. Web：筛选、数量、卡片、编辑、单条重生成、导出、节点详情和视频渲染素材分组统一为四类。
5. 下游：Seedance 请求正文保持不变；请求快照、任务类型和项目资产标签使用四类兼容结果。
6. 文档：更新根 `AGENTS.md`、效果类工作流指南与 README 的长期口径。

## 四、验收

- 批量创意生成输入不包含四类用途或类型配额。
- AI 评估只返回四类枚举，一条 Prompt 仍可有一个主用途和多个兼容用途。
- 旧六类领域草稿和 WorkingArtifact 可继续查看、筛选、导出和进入视频渲染。
- 旧 `PAIN`、`SELLING_POINT_EXPLANATION`、`OUTRO` 不出现在新的公共结果与渲染快照中。
- 四类筛选同时支持只匹配主用途或匹配主用途与兼容用途。
- Contracts、API、Web、Worker 相关测试、类型检查、构建和 `git diff --check` 通过。

## 五、实际实施与验证结果
