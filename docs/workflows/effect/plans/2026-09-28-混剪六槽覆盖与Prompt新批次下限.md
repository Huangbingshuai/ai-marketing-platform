# 混剪六槽覆盖与 Prompt 新批次下限

## 范围

- 效果类模板混剪的 AI 归槽：在已分类、可用且时长足够的素材中，若六槽存在互不重复的可行匹配，先各保留一条，再将剩余素材硬分配到唯一槽位类别。
- 效果类 Prompt 新批次的最低目标数量改为 20，Web 编辑与 API 创建任务均校验。
- 在现有测试项目中真实生成 Prompt、渲染视频并尝试智能填充，记录成功与失败原因。

## 非目标与兼容

- 不按槽位给 Prompt 生成设配额，不修改已确认 Prompt、渲染素材或旧成片的 revision。
- 不改变模型分类分数；零分或时长不够的素材不能伪装成可用槽位。低匹配结果继续标记供人工检查。
- 历史 10 条 Prompt 批次、任务快照及结果仍按旧下限读取，不迁移、不重写。新下限只拦截新批次设置与创建。
- 不改跨进程 DTO 字段或数据库结构。

## 数据与接口

- `EFFECT_PROMPT_LIMITS` 增加新批次下限常量；保留历史读取下限。Web 对新编辑值钳制到 20，API 保存设置和创建 `BATCH_GENERATE` 时再次校验。
- 混剪复用已有分类结果和槽位时长；仅改服务端硬分配算法。分类结果仍写原任务，草稿与 WorkingArtifact 的提交边界不变。

## 验收

- 10 条素材中存在六槽互异可行匹配时，智能填充不再因贪心分配使某槽为空；缺少正分或足时长候选时仍明确失败。
- 历史 10 条结果可读取；新设置 10 或 19 条被 API 拒绝，20 条可创建任务；Web 显示 20～100。
- 运行 Contracts、API、Web 相关测试、类型与构建，以及真实任务回归；执行 `git diff --check`。
