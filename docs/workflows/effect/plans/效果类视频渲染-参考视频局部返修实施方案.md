# 效果类视频渲染-参考视频局部返修实施方案

- 当前状态：已完成第二版（Ark 原任务复用与 2.5 编辑路由）
- 创建时间：2026-09-08

## 目标与范围

在效果类工作流第 04 步“视频渲染”内部增加局部返修能力。用户针对一条最长 15 秒的已完成素材选择问题时间段并填写修改要求，系统将完整原视频作为 Seedance `reference_video` 输入，生成一个独立修复候选；原 Prompt 与当前采用的视频保持不变，直至用户明确采用候选。

本次覆盖：

- `packages/contracts`：返修请求、时间区间、可选矩形区域、候选版本、Worker 参考视频输入契约。
- `apps/api`：项目隔离、幂等、批次 revision、来源版本校验、返修候选持久化、采用/放弃、签名参考视频地址与 Range 流式读取。
- `apps/api/prisma`：任务当前采用版本、不可变原始生成快照、返修运行状态与候选文件字段。
- `workers/seedance-worker`：取得短期签名参考视频 URL，并按 Ark `video_url + reference_video` 结构调用现有供应商任务接口。
- `apps/web`：在现有渲染素材卡中增加返修入口、时间段与修改说明表单、候选预览以及采用/放弃交互；现阶段页面仍沿用既有 Mock 工作区边界，同步提供等价交互状态。

## 非目标

- 不新增工作流节点，不接入 LAS，不改变 Prompt 节点内容。
- 不截取片段后再调用模型；最长 15 秒的原视频完整输入模型。
- 不在第一版实现逐帧画笔蒙版、目标跟踪、局部像素合成或 FFmpeg 时间段回贴。
- 不承诺模型在指定时间段外像素级完全不变；第一版通过明确的时间指令、候选对比和人工采用控制风险。
- 不自动采用修复结果，不因返修任务完成直接提交 WorkingArtifact。
- 不自动重试供应商创建结果未知的请求，避免重复计费。

## 节点与版本边界

1. 业务上游仍是当前批次冻结的 `prompt-batch:{productId}` 与商品资料包快照；返修不修改二者。
2. 返修直接来源是当前任务已经采用的输出文件及其 `activeOutputVersion + contentHash`。
3. 原始生成请求快照单独保留为不可变 `generationRequestSnapshot`；返修期间的模型请求只写入当前运行快照，返修结束后恢复原始生成快照，避免后续“重新生成”误用返修提示词。
4. 同一素材同一时刻只允许一个返修任务。返修创建时冻结来源版本、时间段、可选区域、修改说明、模型参数与来源文件哈希。
5. Worker 完成后只写返修候选文件，不能覆盖当前采用文件。用户选择：
   - `ACCEPT`：候选成为当前采用版本，原文件标记为待清理；渲染工作副本变为草稿已变化。
   - `DISCARD`：候选标记为待清理，当前采用版本保持不变。
6. “采用修复版”只改变节点草稿；用户再次点击节点“完成校验”时才提交 `render-clip:{taskId}` 与 `render-batch:{productId}` 新 revision，并按既有依赖机制使已存在的模板混剪结果待更新。

## 供应商输入与文件安全

- 返修提示词只包含：任务类型、原视频唯一参考声明、修改时间段、可选区域、用户修改要求、必要技术边界和低强度保护原则；不拼接原 Prompt、创意主线或六维信息。
- 用户修改要求在返修提示词中具有最高优先级，并要求产生肉眼可见的对应变化。保护原则不得逐项锁定色彩、光影等可能正是用户要求修改的属性，也不得削弱或抵消用户意见；未选择矩形区域时不编造空间区域约束。
- 系统自产视频优先冻结当前采用版本对应的 Ark `providerTaskId`。Worker 在创建返修任务前查询原 Ark 任务，取得新的临时 TOS 地址，不依赖本地 MinIO 或 API 具备公网地址。
- 返修固定自动路由 Seedance 2.5 精确编辑能力；供应商请求使用 `omni_reference_task_type=edit`、`duration=-1` 与 `ratio=adaptive`。完成校验继续严格检查时长和分辨率；Ark 返回自适应实际宽高比时，返修结果允许相对目标画幅 3% 以内的编码取整差异，普通生成仍要求画幅值完全一致。
- 仅当历史或外部视频没有可复用 Ark 任务 ID 时，Worker 才向 API 申请短期签名参考视频 URL。签名绑定 `taskId + taskVersion + fileObjectId + contentHash + expiresAt`，服务端使用常量时间比较校验。
- 对外参考视频接口只允许读取当前返修快照冻结的文件，支持 HTTP Range，过期、版本变化、哈希不符或签名不符均拒绝。
- 生产环境若需要返修无 Ark 来源任务的视频，必须配置外网可访问的 `SEEDANCE_REFERENCE_PUBLIC_BASE_URL` 和独立的 `SEEDANCE_REFERENCE_SIGNING_SECRET`；缺失时只拒绝该回退场景，不回退 Base64 或 Mock。
- 供应商 URL、签名、完整返修提示词和原视频内容不得写入日志或 RabbitMQ；Worker 将 `httpx/httpcore` 请求日志提升到 WARNING，防止对象存储签名 URL 在 INFO 日志中泄漏。

## 并发与幂等

- 返修继续复用现有 `effect.segment-render.requested` 队列、任务租约、attempt token、创建限速和下载并发，不建立第二套任务系统。
- 创建返修与采用/放弃分别要求稳定幂等键；同键同请求重放返回当前状态，同键异请求冲突。
- 返修请求必须携带预期批次 revision 和预期来源视频版本。事务内锁定批次和任务，防止重复点击、旧页面或两个用户同时返修覆盖。
- Ark 创建成功后持久化供应商任务 ID。后续状态查询遇到 DNS、连接超时、429 或 5xx 时在同一 Worker 租约内带退避继续只读轮询并刷新心跳；恢复任务始终复用已有供应商任务 ID，不重复发送创建请求。
- 返修运行失败时保留原始采用视频；失败状态只属于返修候选，不使原素材从素材池失效。

## 验收标准

- 契约覆盖：合法返修、时间越界、区域越界、候选版本与决策。
- API 覆盖：项目隔离、幂等重放/冲突、旧批次 revision、旧来源版本、并发返修、完成不覆盖原文件、采用/放弃、失败保留原文件、签名过期/篡改与 Range 读取。
- Worker 覆盖：仅返修任务获取视频 URL；供应商请求包含一条 `reference_video`；已有供应商任务恢复时不重复获取 URL 和创建任务；原任务查询与结果轮询的暂时网络失败可在不重复计费的前提下恢复。
- Web 覆盖：只允许已完成素材返修；时间范围不超过素材时长；候选生成、预览、采用和放弃；ESC 关闭与焦点恢复。
- 执行 Prisma validate/generate、Contracts/API/Web 定向测试与类型检查、Worker pytest/mypy、相关构建和 `git diff --check`。
