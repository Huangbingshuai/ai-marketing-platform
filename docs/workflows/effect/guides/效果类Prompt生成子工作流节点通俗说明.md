# 效果类 Prompt 生成子工作流通俗说明

> 本文只描述系统当前唯一的 Prompt 生成流程，不使用代码版本号。

## 一句话理解

系统先把已经确认的商品信息整理成“哪些能直接拍、哪些只能当背景、哪些不能用画面证明”，再批量生成连贯的六维创意，独立评估后择优保留用户要求的准确数量。

一条 Prompt 对应一个可独立渲染的短视频素材片段，不是一条完整广告成片。

## 当前流程

```text
输入快照
→ 提炼信息应用映射
→ 事实视觉使用策略编译
→ 共用提示词编译
→ 连贯六维创意生成
→ 创意评估与用途分类
→ 精确数量择优与补充
→ 结果保存
```

## 1. 输入快照

作用：冻结本次任务真正使用的数据，防止任务执行过程中页面修改导致前后不一致。

输入：当前商品、已提交的信息提炼结果、Prompt 总数量、统一时长、共用提示词、需要保留的人工条目。

输出：不可变的任务输入快照和上游 `artifactId + revision + contentHash`。

例子：用户要求为“广式腊肠”生成 50 条、每条 5 秒。任务启动后，即使页面又把数量改成 60，本次任务仍按冻结的 50 条执行；下一次任务才使用 60。

## 2. 提炼信息应用映射

作用：把信息卡中的商品信息变成带稳定事实 ID 的可信事实，并排除空值和待确认内容。

输入：产品名称、品类、规格、外观、卖点、痛点、受众、场景、营销目标和制作约束。

输出：可使用事实、批次约束和被排除事实。

例子：“广式腊肠”“腊味肉制品”“油润红亮切面”可以进入后续流程；“价格待确认”会被排除，模型不能自行编造价格。

## 3. 事实视觉使用策略编译

作用：判断每条事实怎样进入画面，而不是把所有事实都直接塞进 Prompt。

输入：上一步的可信事实。

输出：每条事实的视觉角色：

- 产品身份锚点：让画面能认出当前商品，例如“广式腊肠”。
- 可直接呈现：摄像机能真实看到，例如“油润红亮切面”。
- 可通过动作呈现：通过蒸、切、夹取、摆盘等动作表达。
- 仅作商业背景：可以影响创意方向，但不能声称镜头已经证明。
- 仅适合文字表达：不应硬拍成视觉证据。
- 禁止视觉证明：不能从画面推出成分、认证、功效等结论。

例子：“三七肥瘦黄金配比”可以影响卖点方向，但普通镜头不能证明精确配比；“切面油润红亮”则可以安排切片特写直接呈现。

该节点针对整批商品事实执行一次，并按内容哈希复用，不会为 50 条 Prompt 重复运行 50 次。

## 4. 共用提示词编译

作用：整理所有 Prompt 共同遵守的一段批次级要求。

输入：禁用元素和用户补充的品牌、人物、画面等统一要求。

输出：一段权威共用提示词及内容哈希。

例子：“不要出现医疗功效宣称，不要虚构品牌认证，人物保持成年人形象。”生成时模型会收到这些约束，但系统不会把它重复写进每条可见正文；渲染请求编译时只追加一次。

## 5. 连贯六维创意生成

作用：一次性生成完整创意主线、六维信息和干净正文，避免把独立词池随机拼在一起。

六维是：叙事结构、场景、人物、产品关联点、镜头语言、情绪基调。

输入：本条可见画面任务、少量商业背景、产品锚点、事实边界、共用提示词和避重参考。

输出：候选 Prompt、创意主线、六维信息及使用的事实 ID。

例子：同一条创意可以是“年夜饭上桌前，成年人切开蒸熟的广式腊肠，镜头从蒸汽中的中景推进到油润切面特写，氛围温暖团圆”。场景、人物、动作、产品和镜头共同服务同一件事，不会出现“办公室人物 + 户外长椅 + 厨房切片”这种拼接。

目标 50 条时，首轮会多生成一批候选，给后面的评估和择优留出空间。每个生成分片只处理少量候选，多分片受统一并发门限控制。

## 6. 创意评估与用途分类

作用：独立检查候选是否真的与商品有关、事实是否可信、画面是否能拍，并给出推荐用途和兼容用途。评估器只评价，不重写正文。

输入：候选 Prompt、六维信息、实际引用事实和事实视觉策略。

输出：产品相关性、创意连贯性、画面可执行性、商业素材价值、视觉清晰度，以及推荐用途和兼容用途。

例子：只有“成年人拨开遮挡物、镜头悬念观察”但完全没有腊肠、腊味场景、真实痛点或产品动作的内容，会因商品无关被淘汰。围绕“家宴摆盘焦虑”但暂未展示完整产品名的钩子，只要与真实商品事实有明确关系，仍可以通过。

六类用途只在生成后分类，不是六条独立生产线，也不是生成配额。

## 7. 精确数量择优与补充

作用：从合格候选中选择质量高且相互有差异的准确数量。

输入：所有候选的质量结果、正文向量、人工保留项和目标数量。

输出：最终选中条目、数量统计、提醒和补充任务（如需要）。

选择时综合独立质量与相对新颖度。普通相似只降低排序；正文完全相同，或创意主线与六维组合实质完全相同，才作为硬重复。

例子：用户设置 50 条，系统必须最终保存正好 50 条。首轮合格候选不足时，系统只针对真实缺口补充，并把已选内容作为避重参考；达到数量后立即停止。仍不足时保存为“需要检查”，不能冒充合格批次。

## 8. 结果保存

作用：保存本次领域草稿、质量结论和节点状态。

输入：最终选中条目、共用提示词、渲染参数、质量统计和上游快照。

输出：当前 Prompt 批次草稿。

生成成功不等于正式提交。只有用户点击“完成校验”，并且数量准确、所有人工编辑条目已经重新评估，系统才更新 `prompt-batch:{productId}` 工作副本。

## 业务 revision 与代码版本的区别

系统不再用编号代码版本选择 Prompt 流程，但以下业务字段必须保留：

- `WorkingArtifact.revision`：已确认业务内容真正变化时递增。
- 上游 revision：记录本批 Prompt 消费了哪一次已确认的信息卡。
- 结果 revision：人工保存时用于并发冲突检查。
- `contentHash`：判断内容是否真的变化，并复用安全检查点。

这些字段回答的是“用户数据变没变、当前任务用了哪份数据”，不是“代码运行哪一版”。
