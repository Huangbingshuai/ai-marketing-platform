## 3. 已实施修复

- 将方向规划压缩为 8 个简洁方向，提高其独立输出预算，并使用独立 180 秒超时。
- 单个生成任务只暴露本 slot 的 `F1/F2…` 局部事实别名，Provider 回收时映射回本条允许事实，阻止跨任务引用。
- Provider 还会确定性扫描创意主线、六维和正文；若出现未分配且长度足以判断的其他已确认事实，该候选会被隔离，防止“不报事实 ID 但抄了别条事实正文”。
- 评估缺失的六轴分类可由 Worker 使用本条六维/正文和动态词表确定性补齐；未知值只能落到 `OTHER`。
- 批量生成中的单个坏分片在两次严格结构失败后可隔离，由 140% 候选余量或数量补充吸收；网络、限流和服务端故障仍按任务策略处理。
- Worker 在发送完成请求前校验禁用元素、共用提示词及其哈希，和 API 使用相同 UTF-8/JSON 规则。
- 所有数量补充与多样性补充统一受 `ceil(目标数 × 1.6)` 预算限制；50 条任务不会产生第 81 个候选，预算内仍不足则进入 `NEEDS_REVIEW`。
- 专项测试确认人工单条评估和单条重生成不会发起批次创意方向规划调用。
- 用第五轮保存的安全分片重建 73 条合格候选，所有候选逐条通过当前 API 条目校验；重建的 50 条 V6 批次通过当前完整结果校验。该验证不产生 Ark 调用，也没有写回业务数据。

### 6.2 已确认的改善

- 修复后连续两轮成功，均严格得到 50 条，且没有触发数量补充。
- 两个成功批次的产品无关内容、完全重复、渲染参数正文泄漏、共用提示词正文泄漏和典型无关场景均为 0。
- 每条均出现产品或品类表达；两批的六维唯一值保持较高，说明差异化没有退化为少量模板换词。
- 第四轮在一次任务尝试内完成，证明当前分片并发、阶段屏障和保存链路能够稳定跑通。

### 6.3 尚未解决的设计缺口

- 上游存在 3 个核心卖点、3 个核心痛点、4 个决策动机、4 类目标受众和营销目标，但两个成功批次对这些类别的已验证绑定均为 0；事实使用明显偏向产品名称、视觉特征和使用场景。
- 两批分别有 20/50、17/50 条收到 `DURATION_TOO_DENSE` 提醒，15 秒软时序约束仍需收敛。
- 主用途集中在产品展示和卖点讲解；结尾转化与片尾品牌没有形成主用途。六类用途不是生成配额，因此这不是数量失败，但会削弱下游素材池用途广度。
- 加权质量分来自现有评估模型，只能与确定性检查结合使用，不能单独证明商业创意质量已经达到最终目标。

因此，当前设计可判定为“工程链路有效、质量改善部分有效”。事实选择从生成任务中拆出是正确方向，但下一步仍需增加批次级核心事实轮动、受控同义证据识别和稀缺用途软奖励，不能恢复六类固定生成配额或重型硬门禁。

## 7. 当前代码的后续浏览器联调与质量复核

后续使用正式页面再次发起同商品 50 条、统一 30 秒的真实任务。任务经过公共 API、Outbox、RabbitMQ、真实 Ark Worker、80 条候选上限、一次定向补充和结果保存，最终得到精确 50 条；任务层遇到一次真实读取超时后，通过租约、检查点和第 2 次任务尝试恢复完成。页面联调同时暴露并修复两项跨层缺陷：

- 补充轮次回到评估阶段时，API 曾把总进度从 83% 回退到 59%；现在阶段可以回访，但总进度只允许单调增加。
- 后端已经完成时，页面可能因一次轮询网络异常停在 60%；现在轮询会容忍短暂失败，并在工作区刷新后重新应用同一任务的权威终态。

该批模型评分为 93.33，数量、完全重复和产品相关性通过，但逐条人工审查仍判定未达标：厨房或备餐场景 25/50，切制动作 37/50，40 条处于实质近似簇；至少 5 条包含真实烹饪等待，2 条存在生熟状态歧义，2 条用包装外观暗示抽象“锁鲜”效果。因此不能用模型高分替代人工质量结论。

针对该结果，当前代码继续实施了以下修复：

- 选择器把“切片、拆袋、摆盘、夹取”等正文底层动作纳入新颖度；共同出现任一底层动作即按实质重复降权。
- 底层动作超过 40% 会触发一次定向补充，并把拥挤动作作为补充任务的明确避让项。
- 创意生成不再把切片当成食品素材的默认准备动作，优先执行批次方向分配的具体主动作。
- 30 秒内出现分钟级等待、从生制品完整熟制后继续切配上桌等真实时间跨度时，候选直接退出选择。
- 需要熟制的产品直接铺到“刚离火/刚蒸好”的成品饭菜时，Worker 会识别为食品状态冲突。
- 抽象事实视觉证明由 Worker 根据事实视觉策略确定性复核；同时移除普通炒菜被模型误报为抽象证明的错误硬判定。
- 有效短证据可以匹配较长的上游事实原文，例如正文“煲仔饭”可正确绑定“煲仔饭烹饪”，不再制造大批错误证据提醒。

修复后自动回归结果：Prompt Worker 219 项通过、1 项显式付费测试跳过，mypy 与 Ruff 通过；Contracts 17 项、API 相关 52 项、Web 相关 23 项通过，类型检查与 API/Web 生产构建通过。上述修复尚未获得新的真实批次质量样本，因此文档状态继续保持“未通过”，不能提前宣称同质化问题已经解决。
