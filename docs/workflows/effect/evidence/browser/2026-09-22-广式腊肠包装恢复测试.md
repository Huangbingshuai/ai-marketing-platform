## 已定位与修复

- 口播审核将“腊肠可以做拼盘”的推荐用法视为“当前画面正在摆拼盘”，以缺少展示误判成矛盾；另从抽帧米饭外观推断非糯米，超出了画面可确定的事实。
- 策划和缩句共用同一审核规则：先区分背景商品解说、推荐用法与当前画面动作声称；后者必须提供直接相反的可见证据才能判画面矛盾。事实缺乏支持依旧拒绝，不使用关键词算法筛除审核结果。
- 修正反馈要求移动一句后重新安排完整时序，可删除不适合的句子，而不是保留数量强塞；传入总时长和前稿所有时间窗口。未放宽时间校验或截断配音。
- Worker 50 项测试通过、21 文件 mypy 通过。无活动任务时部署到原 Worker 后恢复正式 Run。
- 成片 04 审核 HTTP 200 后 ProviderError，未进入结构错误日志；按 Provider 控制流指向 `status=incomplete` 容量错误。审核输出从 2048 提升到现有模型允许的 8192，增加安全容量日志、在 UI 保留 Provider 的安全错误提示。新增脱敏日志回归后 Worker 51 项通过；不把推断包装成已读取原始供应商响应。
- 成片 04 新口播仍给首句约 4.5 秒可用窗口安排过长文本；新增新策划字符容量预检，必须先减少内容再配音，不截断或加速。该预算不应用于已经实测合法的保存音频，回归验证这一边界。缩句审查明确原始句、改变句 ID，仅审查这次修改及上下文影响。Worker 52 项通过。
- 只在提示词写容量公式仍无法可靠约束模型时序。新模型内部协议改为 `windowIndex/text/factIds`：系统按总时长给出约 8 秒窗口及显式字符容量，模型选择窗口组织口播，系统换算 start/end，独立事实和对应画面审核不变。API/历史检查点格式不变，不改已保存结果。55 项 Worker 测试及 mypy 通过后部署。
