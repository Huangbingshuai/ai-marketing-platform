# 智能填充提交关键路径第二轮验证

日期：2026-10-14。范围：广式腊肠项目测试4及效果类隔离分支复制；未重新执行模型生成。

## 原因

测试4分支创建记录为05:45:36.397Z，智能填充任务入库为05:45:44.698Z，二者相隔约8.3秒。这不是完整浏览器提交计时，但说明创建回执之前的服务端准备仍明显耗时。

只读模拟将所有写操作和锁截获在内存中，发现分支复制37条渲染记录会执行37次单条插入、一次重新读取、37次快照改写。之前按模板收窄历史查询没有消除这段逐条数据库往返。

## 修改及业务边界

预分配新的任务ID，按原顺序构建任务字段和第一阶段ID映射。待artifact ID及内容指纹映射完成后，一次createMany插入最终请求快照，移除读取新任务后再逐条更新的流程。

渲染版本、采用版本、任务状态、重试统计、返修候选、文件身份和引用字段完整保留。复制的历史供应商任务不投递执行；产品、批次、工作副本和任务仍在同一事务内，插入失败整体回滚。没有通过清空其他模板、删去校验或提前伪造任务回执实现提速。

## 数据库验证

三层验证使用现有数据，测试事务均抛出专用回滚标记，不提交、不派发任务。完整分支/提交基准仅在该项目无活动填充及包装任务时执行。活动指针读取在测试代理中模拟为选中的已发布父分支，真实全局指针写入被拦截；因此这些数字是受控服务端基准，不是浏览器真实POST耗时。

每轮前后核对分支数、渲染任务数、填充任务数、Outbox数、工作副本数量/revision汇总及当前指针，均不变。无付费调用。
