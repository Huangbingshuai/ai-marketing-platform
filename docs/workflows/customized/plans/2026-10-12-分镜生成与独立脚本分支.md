# 定制类分镜脚本生成与独立脚本分支实施计划

状态：已完成实现与受控验收，独立 Worker 已部署；真实模型创意质量、账户可用性及费用尚未验收。2026-10-12 用户确认实施；具体观察与未验证范围见[验收记录](../evidence/2026-10-12-分镜生成验收.md)，不把计划当成测试结论。

## 目标与边界

接通第三节点真实生成、编辑、保存、恢复与版本分支，独立部署 Worker。输入为有效已确认 customized-brief 的 artifactId + revision；每份完整脚本成功并校验后立即发布一个兄弟分支，不等待同批其他方案。默认选择第一份成功脚本，后续记住用户选择。再次创作新增方案并保留既有方案。

保持六个业务节点；本次不实现下游 Prompt、图片、视频及交付任务。脚本对象是文字需求，品牌图片仅保留固定版本引用，不进入视觉模型，不推断产品事实。

## 设置及 UI

- 默认展示目标时长、方案数量：30 秒、3 份；AI 支持整数 15–180 秒、1–5 份。历史及手工内容仍兼容原时长范围，不截断。
- 更多设置包含叙事结构（AI / 参考 / 自定义）和补充要求；制作目标、受众、产品与品牌约束直接消费简报。创作依据可查看真实版本。
- 共用 WorkflowRunProgress、编辑动作、确认、加载、错误、字段、底部导航、画布及版本树。
- 抽取效果类 Prompt 内嵌工作流面板，两类接入同一组件；保留拓扑、输入/执行/输出、结果块、刷新、折叠、键盘、ESC、遮罩、焦点恢复和迟到请求保护。
- 目录是只读聚合投影；写入属于选定脚本实际 Run。保留对比、编辑、排序、导入导出、逐镜人物/产品/场景需求。
- 主脚本仅为默认打开偏好，每份已确认脚本均有独立后续路径。

## 内部执行链

| 阶段         | 点击后的真实业务内容                               |
| ------------ | -------------------------------------------------- |
| 信息卡快照   | 品牌、产品、卖点、受众、约束及本次设置             |
| 多方案构思   | 名称、切入点、产品关联、发展及方案区别             |
| 完整故事创作 | 故事正文、开场、发展、收束、对白安排               |
| 资产需求整理 | 人物/产品/场景定义、已知特征、待设计内容及引用位置 |
| 逐镜脚本创作 | 镜头画面、景别、运镜、对白、声音、时长、对象引用   |
| 脚本审校     | 具体问题、镜头、事实依据、建议与检查结论           |
| 定向修订     | 修改前后、原因与复核；无需修订明确跳过             |
| 保存脚本分支 | 实际名称、脚本入口、来源版本和保存结果             |

先联合规划，再按方案并行。不同方案不只替换标题或名字；不强求覆盖全部卖点。AI 判断语义，代码检查结构、ID、引用、来源、数量、正时长与总时长（误差不超过 1 秒）。独立审校后最多一次定向修订及复核，仍不合格不发布。

Pro（doubao-seed-2-1-pro-260915）负责构思、故事、审校及事实/故事修订；Turbo（doubao-seed-2-1-turbo-260628）负责对象定义、逐镜细化和结构修订。独立配置、冻结型号、禁止静默降级。初始全局并发 2，有界退避、分段检查点；记录实测耗时，不承诺固定完成时间。

依据：[火山模型列表](https://docs.volcengine.com/docs/ark/model-list?lang=zh)、[火宝拆镜](https://github.com/chatfire-AI/huobao-drama/blob/master/backend/workspace/prompts/storyboard_breaker.md)、[RichiDrama](https://github.com/Moemu/RichiDrama)、[Script2Video](https://github.com/reaink/script2video)。采用工作流方法，不复制上游品牌、配置或许可证声明。

## API 与版本

专用根路径 projects/:projectId/workflows/customized/storyboard；覆盖工作区、设置、任务创建/查询/详情/恢复/取消、脚本编辑/取消/保存/路径选择。区分 workflowRunId、taskId、scriptId；幂等键与 expectedRevision 必需。Worker 使用独立 Token、租约、attempt token 的内部接口。

持久化批次、方案、阶段与脚本；复用 WorkflowRun、WorkingArtifact、依赖、Outbox、清理。脚本 key 为 customized-script:<scriptId>，独立分支归属不借用 templateId。同一来源下并列分支；单份发布事务幂等。草稿自动保存，人工明确保存更新当前分支，不另开叉；同内容不增 revision，409 保留本地修改。

人工空白脚本首次有效保存才发布；导入重映射身份。旧多方案草稿读取不自动发布，首次保存迁移。上游变化保留历史、只标记真实依赖下游。下一步只引用当前脚本确认版本，不创建下游模拟结果。

部分失败保留成功脚本与检查点；恢复不重做成功内容。进度来自真实阶段和方案完成量，断网不冒充失败。取消、项目删除、失效租约拒绝迟到回调。

## 部署、实施与验收

新增 workers/customized-storyboard、独立队列/Token/Compose 服务。轻量共享结构化请求与 HTTP 底座保留提炼兼容入口；不安装 Docling、Torch、浏览器、视频工具或模型卷。

顺序：共享面板及效果类回归 → 契约/迁移/分支/API → Worker/检查点/逐份发布 → 前端 → 独立部署及文档。不自动提交 Git，不中断在途任务。

验收：五种产品、1/3/5 方案、15/30/180 秒及不同结构；八节点完整真实详情；并列分支、逐份成功、部分失败恢复、再次创作、编辑取消、同内容保存、两轮来源变化、兄弟隔离；重复消息、重启、限流、超时、非法输出、租约与迟到回调；1920/1440/窄屏与空/错误/运行/完成/待更新/409。

检查：相关单测与数据库集成、pnpm typecheck、pnpm build、pytest/mypy、Compose config、git diff --check。受控适配器明确标记；真实付费验证分别记录型号、耗时、调用量、费用，不以模拟替代。
