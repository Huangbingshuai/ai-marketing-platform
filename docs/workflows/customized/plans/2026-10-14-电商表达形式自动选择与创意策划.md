# 电商表达形式自动选择与创意策划

日期：2026-10-14；状态：已被用户后续的“五类二次选择、分别创作”要求替代，停止继续实施，未作为默认策略部署。本文保留被替代设计，不作为当前产品要求。

## 范围与依据

用户只选择“电商带货”，不增加形式、人物或创意的用户配置。系统根据确认简报、受众、结构要求和已有稿，先选择适合的表达形式与创意，再按所选形式写稿。参考[飞书产品手册](https://ncnejrxxru2v.feishu.cn/wiki/GyzNwFRdBi1ZQXkbL4FcPQjunzg)中的口播带货、促销转化、场景种草、痛点解决、功能演示五类，不把参考页面当作本项目实现声明。

仅修改定制类第三节点。消费已确认 customized-brief 的固定 artifactId/revision，草稿与任务沿原作用域；完整脚本审校通过后沿原事务提交 customized-script:<scriptId>。下游资产准备与视频制作消费准确脚本 revision，不改其生成逻辑，不生成图片或视频，不自动提交 Git。

## 选择与写作

新任务冻结 commerce.6；旧 commerce.1 至 .5 的提示、Schema 和恢复行为保持原样。六份短候选各包含表达形式、选择原因、讲述主体和具体创意，以及原购买问题、演示链、事实引用。独立择优先核查这些安排，再输出原方案身份与必须兑现内容，不重复改写。正文根据每份入选形式使用专项写作规则；同一批可有不同形式，不要求覆盖五类或每种只能一份。

口播适合直接推荐时优先考虑：人物直接面向观众，提供可说出口的完整口播，穿插产品细节与演示。促销必须有确认优惠，不能凭空促销；场景种草以自然使用激发需要；痛点解决展现真实摩擦与有依据的改善；功能演示清楚回应买前疑问。人物、手部演示、旁白或屏幕讲解按产品适配，软件不要求拿着实体包装。允许具体观察、提问、悬念、视角和行为设计，不用夸张功效、虚假证言、竞品或故事冲突充当创意。

商业审校只读取所选形式作为验收范围，仍以实际正文为证据；检查推荐/演示是否兑现、口播是否自然、创意是否服务购买利益。事实侧保留完整简报与实际篇章时长，参考总时长不进入事实硬性比较。任一实质错误进入原一次修订和双路复核，仍错不发布。

## 契约与展示

新开发 Schema 要求 expression={format, reason, presenter, creativeIdea}；旧 Schema 保持。服务端按冻结版本校验形式枚举、非空文本、原候选身份和投影，代码不猜测语义。所选形式与创意保留在检查点和写作上下文，最终正文仍用现有完整剧本结构，不另建业务产物或表。

共享工作流详情显示每份候选与入选稿的形式、原因、讲述主体和具体创意；不增加输入组件，不复制工作流弹窗。正常主要调用仍为2+3N，共享并发2，两份脚本有界推进；不增加一轮专门类型分类调用。

## 验收

受控验证五种形式、食品/护肤/硬件/家居/软件、混合批次、旧版恢复、新版缺失/非法表达字段、写作分流与修订/复核保留形式、失败检查点恢复；跨层契约 Schema 一致、API 实际 HTTP、共享详情展示、类型/构建/mypy/pytest/diff。无活动任务时安全更新 Worker，按已有授权在充电器项目进行真实付费生成并人工阅读口播/创意，不用模型 PASS 代替人工质量结论。记录耗时与 tokens，不推测人民币费用，不以单产品结果证明全品类质量。
