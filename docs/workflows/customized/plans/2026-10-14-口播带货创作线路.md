# 口播带货创作线路

本计划取代同日的五类二级选择及表达形式自动选择计划。用户仅选择“口播带货”，没有二级类型、创作要求和促销方案。沿用定制类第三节点、现有 Worker 与内部 ECOMMERCE 标识，不修改其他视频类型。

## 输入、输出与边界

消费任务冻结的已确认 customized-brief artifactId + revision；页面现有方案数量、软参考时长和可选脚本结构不变。完整正文及双路审校成功后沿现有事务自动提交 customized-script:<scriptId>；失败保留检查点。资产准备、视频制作仍消费实际脚本版本，不在此处制作图片或视频。

## 执行线路

信息卡快照 → 创作依据 → 类型路由 → 口播推荐策略与创意 → 独立择优 → 完整口播正文 → 商业表达及事实/执行独立双审 → 必要的一次定向修订和复核 → 保存。

短策划一次开发六个不同推荐角度，补充讲述者与口吻、推荐逻辑、讲述与演示分工、具体创意；不是六个类型。缺少决定性产品资料才停止，不要求用户补创意。独立选择保留原候选及必须兑现内容，不再次重写候选。

正文写出人物面对观众的完整自然口播，开场及收束保留讲述主体，产品操作和近景支持推荐。软件可以结合屏幕，大件可站旁介绍，不硬性要求手持、性别或虚构亲测经历。审校只从实际正文判断推荐理由、价值呈现与信息容量，策划不作为正文已实现的证据。事实审校独立读取完整资料，不捏造价格、功效、认证、用户证言。

## 速度、兼容及展示

新任务冻结 2026-10-14-presenter.3。短策划采用任务冻结的 Turbo 低推理，择优、正文及双审采用 Pro 中等推理；正常 N 份为 2+3N 次主要调用，模型总并发2、最多两份同时推进。最多一次候选重开发，恢复不重置预算，单份成功立即发布。

首轮真实验收发现参数密集的口播被放行；presenter.2要求按型号、英文和数字单位的真实读音逐段检查容量，策划及写作取舍辅助规格。presenter.1冻结保留，详见[真实验收](../evidence/2026-10-14-口播带货真实验收.md)。

第二轮复核阻止了工作前提缺失的稿件发布。presenter.3在策划及正文统一建立能源、连接、输入材料或权限等实际前提，再呈现工作结果，区分外观展示和运行状态；适用于所有产品，不用充电器关键词机械补句。审校调用量、一次修订预算及旧策略恢复规则不变。

旧策略继续按其冻结配置恢复，其他项目旧脚本不迁移。依据用户明确授权，仅充电器项目旧26份脚本已通过现有删除接口移除，简报保持 revision1。新任务不再创建五类二级状态或数据库字段。

复用效果类共享进度、工作流与节点详情组件；节点详情展示具体讲述策略、创意、演示安排、候选取舍和正文证据，完成后进度消失。界面“电商带货”统一为“口播带货”。

## 验证

覆盖五种产品的受控1/3/5份生成、Schema及TS/Python投影一致、缺失/非法策略、双审及一次修订、恢复不重复调用、旧策略回归、API事务及真实详情。运行 Worker pytest/mypy、相关Contracts/API/Web测试、工作区typecheck/build、Compose及diff检查。使用现有充电器项目进行真实火山文字模型测试，独立记录正文、耗时、调用量与审校结论；受控测试不充当付费质量验收。
