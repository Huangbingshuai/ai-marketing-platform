# 正式剧本生成与付费验收

## 范围与提交

定制类脚本创作消费已确认 customized-brief 的准确 artifactId/revision，继续复用独立脚本 Worker、任务/检查点和兄弟脚本分支。完整生成、独立审校及服务端校验成功才发布 customized-script:<scriptId>；旧脚本与已有资产/视频产物不自动改写。本次不生成资产图片或视频，不提交 Git。

## 设计

参考[火宝剧本提示词](https://github.com/chatfire-AI/huobao-drama/blob/master/backend/workspace/prompts/script_rewriter.md)的场景标题、自然动作段落和角色对白格式，不复制其固定场次时长或小说改编前提。

- 新任务冻结 storyFormat=SCREENPLAY_V1；旧任务沿用原格式和检查点，恢复不重新购买已成功内容。
- 模型按连续场次/叙事段落输出完整正文（S01｜内景 · 地点｜时间），描述可执行动作、人物反应、事件变化和必要对白。不写景别、运镜或渲染 Prompt，不强制加对白，也不靠堆产品参数增加篇幅。
- 复用 beats 保存完整场次文本与时长；新格式单段最多 60 秒，合计与目标偏差不超过 1 秒。代码将段落原文拼接为唯一正文，避免模型重复生成正文和段落列表引起不一致与额外 token。保留现有 Story 产物结构及下游消费方式。
- 独立审校同时检查产品事实、品牌约束、方案差异、正文与概述一致性、场景事件的可理解性和实际时长容量。长片不得只是短梗概加时长；留白可以存在，但需有明确可呈现的动作/变化，不能以凑字数判断质量。
- 有问题最多一次定向修订及一次独立复核；新格式修订仍只输出一份正文来源，保存检查点后复核，网络恢复不重新修订。机械格式/时长问题最多纠正一次，不能用代码推断语义。
- 前端缺少 story.content 的历史方案只显示缺失说明；概述保留在创作说明中。头部不再把概述字数写成剧本字数，导出同样明确区分。

## 性能与验证

保留全局有界模型并发 2、联合构思及逐份发布。省去正文/段落重复生成，审校输入只传完整场次一次；不为正常脚本增加无意义模型调用。

先跑契约/API/Worker/Web 受控测试、类型、构建与 diff 检查，再核对无活动任务并更新独立 Worker 和 API 实际进程。用已有充电器项目进行真实付费测试：30 秒多方案及 180 秒长剧本；记录单阶段耗时、调用量/token、修订原因、事实依据、正文质量和浏览器展示，实际费用仅在账单有依据时报告。付费测试已由用户授权，不覆盖原方案。
