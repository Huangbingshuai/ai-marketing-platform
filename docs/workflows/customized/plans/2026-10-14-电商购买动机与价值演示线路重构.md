# 电商购买动机与价值演示线路重构

日期：2026-10-14；状态：实施中。用户授权重构并使用现有充电器项目真实付费测试。

## 边界

仅定制类脚本创作的 ECOMMERCE 线路。直接消费确认的 customized-brief artifactId/revision，草稿仍属现有节点状态；完整脚本审校通过后由现有事务自动提交 customized-script:<scriptId>，后续资产准备和视频制作消费该脚本准确 revision。六业务节点、用户输入、品牌/剧情/到店策略不变；不生成图片或视频、不自动提交 Git。

新带货任务使用独立冻结策略，初版为2026-10-14-commerce.1，当前为2026-10-14-commerce.4；其他类型保持各自现行版本。旧带货任务按原单路构思/审校恢复，不因新默认规则重购或重写。

## 执行与质量

信息卡快照 → 创作依据准备 → 类型路由 → 购买动机与演示策划 → 带货方案独立择优 → 完整带货脚本 → 商业表达与事实/执行双审 → 必要的一次定向修订和双路复核 → 自动保存。

策划一次联合开发6个短方案，分别明确具体受众处境、购买理由、购买疑问、真实事实引用，以及演示的起点、动作、可见结果、表达边界。受众处境可作创作假设，不能冒充真实调研或用户证言。不同方案改变购买问题和呈现方式，不以换人物/地点或逐条规格当作差异；不设品类关键词模板。食品感官、护肤质地与使用体验、硬件操作、家居布置、软件任务均按各自已知事实成立，不能用虚构前后对比或量化效果制造价值。

独立选择只评估和选择已有短方案，不重复改写创意计划。选择足量可执行方案并保留需要兑现的行为与结果；全部薄弱最多替代开发与重新选择一次，仍不足则未完成，不用编造资料或普通长稿凑数。结构与身份非法最多一次机械纠正，候选、选择和预算持久化，恢复不重置。

正文直接消费选中方案；先让人看到需求和对应的产品价值，再补充确实帮助理解/决策的信息，不把准确性限制扩成全规格拍摄清单。允许口播、演示、对照及情境，不强制短剧、超现实、优惠、三秒钩子或行动号召。对照不能编造竞品或效果；事实不足的功效只可解释已知信息，不伪装实验。

独立商业表达审校只依据实际正文，检查购买动机、价值演示、信息容量。只有口号、规格罗列或单纯完成操作不足以证明购买利益；常规演示只要确实让目标人群理解一个真实利益即可成立，不要求品牌广告式隐喻。事实侧保留全简报，核对功效、能力、报价/促销、操作因果、结构和真实时长。两路任一实质错误阻止发布，复核不能只看修改过的局部。

## 契约与交互

Contracts增加带货开发/选择模型与JSON Schema；Python一致性测试。复用现有事实编号、任务、租约、Outbox、Provider、补丁、单份发布和恢复，不新增表/Worker。新增执行阶段为ECOMMERCE_MOTIVATION，目录仍归ECOMMERCE_CONCEPT；前端继续共享效果类工作流弹窗、进度及节点详情，展示真实购买理由、演示链、依据边界、全部候选取舍和审校问题。历史图不增加虚构步骤。

## 性能与验收

正常 N份为2+3N主要调用，所有模型请求共享并发2；每份返修增加3次，替代开发最多增加2次。开发与择优用精简输出和medium，减少重复概述及重复传历史，不截断正文或事实。记录端到端与各次调用耗时/token，实际费用按供应商账单，不承诺固定时长。

验证食品、护肤、电子、家居、软件的受控正常/反例，1/3/5份、缺资料、伪造事实/身份、弱案预算、双审部分失败恢复、非法输出、旧策略冻结和复核失败不发布；API覆盖来源/顺序/结构/质量引用及最终采用稿。浏览器核对新节点真实内容、完成隐藏进度和旧方案保留。运行相关单测、pytest/mypy、类型检查、构建、Compose与diff；无活动任务时更新服务，再在现有充电器项目浏览器创建真实付费带货批次并人工阅读全文。不能以模型PASS或受控跨品类测试宣称全品类创意达标。


## 真实测试后的调整

`.1`真实单份通过但仍三次复述尺寸，且混合所有类型的旧故事避重把方案逼向参数讲解。`.2`从实际任务出发、只对照带货历史、减少重复；三份实际完成，独立审校拦住产品已入包却又出现在包旁、以及单口参数没有结合实际任务等问题。两份定向修订后复核发布，整批632秒；这不是快速验收达标的充分证据。

`.3`短候选开发改用冻结detail模型（Turbo），其他阶段继续冻结creative模型（Pro），正常同时推进两份脚本，避免后续所有正文抢在前面脚本的审校之前排队。商业审校增加购买疑问作为范围，仍只以正文实际实现作证，禁止为单一利益稿强制补全产品其他卖点；原`.1/.2`恢复不采用这些新规则。实际Turbo中等推理开发122秒，未表现出型号替换就提速；该单份完成363秒，经过一次真实返修。

当前`.4`仅短候选开发/其结构纠正使用Turbo低推理；独立选择、正文、事实与商业审校及复核保持Pro中等推理。保留全量确认事实、独立选择、两路审校、结构检查、弱案替代和一次返修上限，不通过放宽错误门槛提速。模型名称及策略在任务中冻结，历史`.3`仍按Turbo中等推理恢复。该配置以本轮真实生成和人工阅读验收，不把低推理配置或Schema通过直接当作创意质量保证。
