# 分镜容量、视频片段分层与结构修订重构计划

日期：2026-10-19。状态：V2主链路已实施，充电器浏览器付费联调已执行；完整验收矩阵尚未全部覆盖。实际结果与未完成范围见[验收记录](../evidence/2026-10-19-分镜V2浏览器付费验收.md)。用户实施授权后已部署独立视频Worker；不自动提交Git。

## 1. 目标与范围

重构定制类「视频制作」节点内部的 AI 分镜及提示词链路，解决四个已经在真实充电器项目中出现的问题：时长容量被锁死、电影镜头与视频任务混用、修订不能改变结构、审校结论缺少可靠证据。

固定流程保持「资料导入 → 信息提炼 → 脚本创作 → 资产准备 → 视频制作」。本计划不重新设计上游创作类型、不重写已确认脚本、不改变资产整理和图片生成业务、不新增业务节点或 Worker。视频制作继续使用独立 `customized-production-worker`；资产准备继续由 `customized-assets-worker` 处理。

本次实施覆盖真实分镜、对象绑定、片段提示词、人工编辑、失败候选核对、任务恢复及相关契约。保留现有图片/视频制作入口和预览位置；不接通新的实际视频渲染、TTS、字幕合成或交付能力，不以文字审校证明生成媒体质量。

## 4. 时长与内容容量

### 4.1 三种时长各归其位

1. **参考时长**：上游创作设置及正文篇章估时提供规模参考，不是已确认的精确剪辑时间轴。
2. **制作时长**：本节点按完整内容、声音、表演与切镜实际规划，等于最终视频片段时长合计；这是分镜确认后的执行依据。
3. **固定时长要求**：只有用户明确开启或来源中有明确要求时生效，不能由「参考 30 秒」自动推断。精确来源及用户选择写入任务快照。

新增 `durationPolicy`：默认 `REFERENCE`。按使用者最新要求，视频制作不提供额外总时长设置面板，不重复脚本创作的输入；固定时长仅消费已有的明确设置或来源要求。固定时长直接使用本次明确数值，不能静默取 beats 合计。冲突的多个明确要求先报告，不能靠文档最后一项覆盖。

`REFERENCE` 按内容合理展开，不为凑秒数增添剧情。规划说明实际预计时长、与参考差异及原因；后续完成采用该制作时长，允许结构修订给出合理的新时长，不再硬套上游估时。若篇幅大幅偏离，AI 解释具体内容负担供用户判断，不以任意百分比作语义硬拒绝。

`FIXED` 在同一次 PLAN 调用先判断可行性。可通过合理并行动作、画外音跨镜、明确省略非关键过程来实现；不能删除已确认原话、伪造加速或新编产品信息。装不下时保存容量报告，停止付费逐镜创作；沿用 FAILED 状态，新增契约化原因 `DURATION_CAPACITY_CONFLICT`，不自动重试语义冲突。展示建议制作时长和需要调整的原文范围，用户可以修改本次时长重新生成，或主动回脚本节点调整并确认新版本。本节点不直接覆盖上游稿。

任务输入冻结用户选择及已有结构化时长要求。只存在自然语言来源的精确时长，由 PLAN 引用原文识别并保存为来源约束；与用户选择冲突时先报告，不静默修改输入快照或改成另一模式。若需重新选择，以新任务执行，旧检查点不混用。

### 4.2 在规划阶段做容量核对

代码先为固定脚本建立不可变原文片段索引；AI 在 PLAN 中标注事件、语音、画面文字及对应原文区间，代码核验实际范围，不能让模型重写所谓原文。需要保留的是剧本明确的对白、旁白、OS、VO、播报和画面文字；叙述性动作说明允许转为摄影表达，不要求逐字出现在视频中。

容量报告包含：原句及说话者、语言/表达方式、估时范围、必要停顿、可同时发生的画面动作、必须先后完成的动作、起止状态、建议镜头承接和未确定项。字数、数值求和及原文差异由代码计算；语义、自然表演和动作能否并行由 AI 判断。

不使用统一「字数除以 4」硬判所有语言。英文型号、数字、停顿及表演需要单独说明；估时是文字制作判断，尚未合成的声音不能显示为测得时长。无对白广告只核对实际画面与动作负担，不强行添加口播。

声音以完整语句为单位保存，可以连续覆盖多个镜头；不把同一句旁白复制到每个镜头，不机械要求所有动作加说话时长串行相加。跨视频片段的连续声音保存同一来源及切分范围，在提示词中明确承接，不让后一个片段重说整句；实际音频无缝衔接留给未来音频/渲染集成验证。

### 4.3 服务端与 Worker 采用同一政策

- 移除 V2 的 `sum(shots) ≈ sum(story.beats)` 校验；历史任务保留旧规则。
- 校验镜头正时长、片段与镜头求和、全片合计、声音区间、固定模式容差和能力边界。使用毫秒整数进行规范化计算，界面显示秒，避免浮点误差累计。
- 固定模式默认全片容差不超过 1 秒，容差是最终总量边界，不要求每个请求批次各自再享有 1 秒。
- 参考模式以已持久化规划/修订的制作时间轴为依据，代码只核对结果与当前采用时间轴一致，不判断美学是否应该更长。

## 5. 场次、视频片段、镜头与请求批次

| 概念           | 含义                                                           | 示例                     |
| -------------- | -------------------------------------------------------------- | ------------------------ |
| 场次 Scene     | 连续时空与叙事环境，关联已确认场景资产；一个场次可以有多个片段 | 出发前的家中桌面         |
| 视频片段 Clip  | 一次后续视频生成任务的制作单元，包含一个或多个镜头             | 「旧充电器占包」片段     |
| 镜头 Shot      | 一次连续机位观察，明确构图、运镜、起幅与落幅；硬切产生下一镜   | 桌面俯拍，手拿起旧充电器 |
| 请求批次 Batch | 为调用效率合并的模型请求，可包含多个片段，保留完整业务身份     | 一次请求生成同场若干片段 |

片段默认保持同一兼容场次；明显换地点、换时空或进入独立产品定版，建立新的场次/片段。镜头内不靠「随后硬切」夹带另一镜；视频片段可以明确包含硬切的多个子镜。连续运镜与动作演进不必强行拆碎，不设固定镜头数或景别配额。

请求可继续按约 60 秒规划内容及 token 预算打包，**60 秒是请求优化阈值，不是视频模型能力或单片段上限**。长内容优先按场次/可执行边界分批；超长单场可以分多个请求，但保留完整原文索引、场内基准及相邻边界契约。已经分好的业务片段不能因为请求合并而丢失身份。

### 5.1 模型能力处理

复用现有 Provider 及共享能力定义建立制作能力投影，不从效果类复制一套供应商常量。当前通用能力表位于 `effect-prompt-generation.ts`，若抽取到供应商无关文件，保留旧导出并先回归效果类。

当前表只覆盖时长、画幅和分辨率等已有字段，不能假称已经包含参考图上限、多镜切换和音频能力。缺少的能力通过明确配置及验证补齐，记录来源/版本/模式；未知项标明未确认，不凭空填供应商支持。

本次生成冻结 `renderCapability` 快照：已选择模式按其准确上下限分配片段；未选择时使用显式制作规划配置并标「待渲染模型校验」。允许保存文字计划及提示词，后续真实渲染前必须完成能力校验。模型切换使受影响片段需要重新适配，不能静默裁切时长或重发付费任务。

### 5.2 绑定分清三层

1. **完整素材库**：当前脚本已确认对象的可选目录，产品、人物、场景、道具均保留。
2. **镜头实际出场**：本镜可见或有身份连续性需求的对象及状态说明；画外声源单独记录，不能假装该人物露脸。
3. **片段制作引用**：由子镜头实际需求去重汇总，并说明每项在哪一镜使用。提示词对象引用必须覆盖这些已确认需求；实际上传参考图是其中有可用图片且符合能力的子集，缺图显示待素材。

场景、可辨识产品、关键道具及实际出场人物不漏绑；无关背景物不为凑完整性绑定，手部特写也不强行显示所有在场人物。旁白配音身份与需要视觉参考的人物身份分开。产品继续独立，不降为只挑少量重要道具。

对象定义不足时，保存确切缺口并指向资产准备，不擅自创建假 ID。图片未渲染不阻断文字分镜及提示词，不能显示为视频就绪；本次不启动视觉模型。

## 6. 统一 V2 契约与兼容

采用带版本的联合契约：V1 保留现有 `{ assets, shots }`；V2 为 `{ schemaVersion: 2, assets, videoPlan }`。V2 不再另存一份可写的顶层旧 shots。旧视图需要时只做只读投影，所有写入必须回到对应版本的唯一实体。

| V2 结构                   | 必需含义                                                                             |
| ------------------------- | ------------------------------------------------------------------------------------ |
| `videoPlan.sources`       | 准确脚本、Brief、目录依赖与内容指纹；品牌图片只记录实际引用版本                      |
| `durationPolicy / timing` | 模式、参考数值、固定要求、制作总时长、估时说明、能力校验状态                         |
| `sourceUnits / events`    | 不可变原文索引、AI 标注事件及出处；原文由服务端回填，不作为额外人工输入              |
| `scenes`                  | 稳定场次 ID、场景对象引用、时空说明和空间/状态基准                                   |
| `clips`                   | 稳定片段 ID、场次 ID、有序 shotIds、转场、能力依据及必要衔接说明                     |
| `shots`                   | 稳定镜头 ID、观看信息、构图/景别/角度/运镜、可见动作、起止状态、时长、事件和对象引用 |
| `cues`                    | 台词、旁白、画面文字等原文落点及类型；声音/文字安排是独立实体，不重复嵌入每镜        |
| `coverage`                | 事件、原句及文字落到哪些镜头/片段，未兑现内容及原因；语义完整性由独立审校核对        |

场次、片段和镜头分别保存一次，通过 ID 及有序引用关联。片段/全片时长由镜头与时间安排计算，不让模型维护多份互相矛盾的合计。声音 cue 保存原文范围及连续覆盖的镜头区间；局部时间以片段/镜头为锚，整片起点由服务端派生，避免前部调时导致所有后续对象 revision 无意义变化。

结构化声音只涉及文字及时间规划，不引入实际音频素材上传/生成。原文口播跨度由代码验证无遗漏、无非授权重复和非法改写；事件是否语义兑现仍由 AI 判断。明确要求重复的话语使用不同来源出现位置，不用简单字符串去重删除。

### 6.1 提示词归属变化

- V2 的一次 Prompt 任务对应一个 Clip，读取该片段的全部子镜头、声音安排、起止状态及必要相邻边界。正文按相对时间说明各镜与切换，不把多镜误写成一镜到底。
- Prompt 引用对象严格来自本片段确认需求；正文使用名称/结构化引用，不暴露内部 ID。完整目录不再次送入模型。
- 保留事实核查、时长、镜头表达和实际需求审校。原分镜存在实质问题时报告具体来源问题，不允许提示词悄悄改写已确认分镜或减少绑定集合。
- 新目标使用契约化 `target: { kind: 'CLIP', id }`；V1 继续 `shotId`。服务端拒绝同时提交两种目标或版本不匹配，不将 clipId 填入数据库语义为 shotId 的列。
- V1 的 Prompt 与旧 artifact key 原样读取；V2 新建 `customized-clip-prompt:<clipId>`。迁移不把旧提示词伪装成已经按新多镜结构审过的提示词。

V2 Prompt 的 PLAN 阶段直接由已确认片段编排输入和相对时间，不再调用模型重写一遍导演规划；GENERATE 使用 Turbo，独立 REVIEW 使用 Pro，正常每个片段 2 次主要调用。确有问题最多一次受控修订及独立复核，分别保存检查点。用户逐片段触发，不因分镜完成或打开目录自动购买整片提示词。界面仍使用同一工作流组件，确定性完成的规划说明其实际处理，无问题的修订明确跳过。

## 7. 新的执行链路与调用预算

沿用六个持久化阶段及效果类共享工作流面板。阶段内的真实细节比增加流程图节点更重要，不为每项导演工作添加一次模型调用。

| 阶段                      | 输入与执行                                                         | 持久化结果及用户详情                                      | 模型调用                  |
| ------------------------- | ------------------------------------------------------------------ | --------------------------------------------------------- | ------------------------- |
| SNAPSHOT 创作依据         | 核对已确认脚本、Brief、资产目录、时长政策及能力；建立原文索引      | 实际正文、选定对象、依据版本、时长口径与缺口              | 无                        |
| PLAN 导演规划与容量核对   | 同一次调用识别事件/原句、核对容量、分场及分片段、定义边界状态      | 原文声音安排、容量报告、场次/片段安排、为何切分及待确认项 | Pro 1 次                  |
| GENERATE 分场创作与绑定   | 按固定业务计划分批生成镜头；引用真实对象；请求有界并行             | 可读分镜表、子镜头、声音落点、实际绑定、批次检查点        | 每批 Turbo 1 次           |
| REVIEW 对照原文独立审校   | 只以来源和实际成稿为证；核对覆盖、容量、镜头语法、事实、状态与绑定 | 有级别的问题、实际证据、正常维度结论                      | 常规 Pro 1 次             |
| REPAIR 问题修订与独立复核 | 无阻断问题时跳过；否则字段补丁或结构补丁，合成后独立复核           | 具体变化、旧新对应、逐条问题是否解决；失败候选保留        | 最多修订 1 次 + 复核 1 次 |
| SAVE 保存待确认分镜       | 服务端复核来源、租约、完整结果和草稿 revision                      | 完整工作台草稿及保存状态；用户明确保存才确认              | 无                        |

普通单批成功路径 3 次主要调用；一次修订后为 5 次。B 个创作批次正常为 `B + 2` 次。长结果若超出安全上下文，独立审校按固定场/片段范围分批，带必要相邻边界和完整相关原文；真实次数为 `B + 1 + R`，R 为审校批次数，必须如实统计，不把多个请求写成一次。

跨批覆盖和数值完整性由代码汇总，跨边界语义明确分配给后一个批次核对；需全局阅读的创意/情节关系保留完整正文及实际关键序列，不用摘要替代原句或隐藏漏检。批次边界与审校范围写入快照，恢复不得改变。

继续冻结现有 Pro/Turbo 精确型号及阶段配置，不静默降级，不因偶发错误切换模型。业务策略新增 `shotWorkflowVersion=2` 与独立 `strategyVersion`；PROMPT 同样冻结新片段策略，旧任务沿原版本恢复。导演/审校 Pro，逐镜细化 Turbo；结构修订先用 Pro，纯结构合法性纠正沿用原阶段模型。

## 8. 可以真正解决问题的结构性修订

### 8.1 按问题选择工具

| 问题                                             | 修订方式         | 允许变化                                     |
| ------------------------------------------------ | ---------------- | -------------------------------------------- |
| 局部表述、错误运镜、漏绑已存在对象、局部事实断言 | 字段补丁         | 仅列出的镜头/字段；正常内容与身份保留        |
| 多次切镜塞入一条、动作过多、语音安排不合理       | 结构补丁         | 拆/合镜头、重分片段、调整声音覆盖和时长      |
| 相邻状态冲突、连接过程缺环节                     | 最小相邻范围重排 | 显式给出命中范围、前后边界和需保持事件       |
| 固定时长无法容纳原稿                             | 容量冲突报告     | 不擅改原稿；提示调整时长或返回脚本           |
| 缺少必要公共对象                                 | 资产缺口报告     | 不伪造对象；用户明确回资产准备补充后新建任务 |

### 8.2 补丁必须可审计

定义有限、带类型的业务操作，例如 `UPDATE_SHOT_FIELDS`、`REPLACE_RANGE`、`RESEGMENT_CLIPS`、`RETIME_RANGE`、`REASSIGN_CUES`；不接受模型任意 JSON 路径修改整份文档。

结构替换必须携带：基准候选指纹、命中问题 ID、明确旧片段/镜头范围、替换内容、原文事件/声音对应、边界变化和原因。受影响区域之外内容按原值合并；必要扩大范围必须包含在同次修订的明确输出中，不能靠重写全片绕过局部保护。

- 不再强制修订前后镜头数量相同。未改实体 ID 保留；拆分/合并产生明确旧新映射，真正删除的 ID 不能挪给其他镜头。
- 新实体 ID 由服务端按任务、补丁和局部身份稳定分配，模型使用局部引用，经解析映射后保存；重放同一补丁得到同一身份。
- 参考模式可合理改变实际制作时长；固定模式可在明确范围内重分配，但最终全片仍须满足固定要求。不能继续要求每个命中区域总时长原封不动。
- 修订不能修改脚本原句、已确认产品事实、资产公共定义和任务来源；不能删掉难处理的事件或口播后声称容量解决。
- 起止状态、对象引用、完整有序列表、声音落点和时长在合成后一起校验。拆镜后的产品定版明确为另一个镜头，必要时另建场次和片段。

补丁候选在采用前持久化；依次保留原稿、审校、原始补丁、机械错误、合成候选、复核和最终采用稿。恢复只补缺失且有效的步骤，不重复购买已有修订。

### 8.3 有限预算与失败恢复

语义修订总计最多一轮，之后独立复核一次；仍有实质问题则保留候选并停止。结构/引用类机械错误最多一次纠错，预算持久化，跨重启和手动恢复不重置。纠错不能被用于第二轮语义重写。

审校输出不合法的有限纠错、修订机械纠错分别记录原因、次数和额外费用，不算进正常 3/5 次承诺。配置任务级总纠错上限，初始为 2 次；用尽后明确未完成，不追加隐藏循环。

网络、限流及临时供应商故障继续有限请求重试与任务退避，租约有效才写回；语义冲突、来源过期、鉴权失败及已知非法候选不反复付费。HTTP 超时不能证明供应商没执行：记录请求标识与不确定结果，不声称所有异常都能实现供应商侧 exactly-once。

## 9. 让审校结论能被核对

### 9.1 结构化问题与证据

每条 finding 包含稳定 issueId、类别、ERROR/WARNING、影响对象、实际字段引用、来源引用、具体影响、建议修订范围及判断说明。类别至少覆盖事实、原稿兑现、声音容量、动作状态、空间连续、镜头结构、绑定和能力冲突。

模型只选择当前候选真实存在的实体/字段和原文区间，代码从指纹绑定的持久化候选回填准确文本；不让模型自行编造一段「证据引文」。无效引用属于审校未完成，不能直接变成用户内容错误，也不能当作无问题通过。

「内容缺失」无法只引用不存在的字段，因此必须同时定位应兑现的原文，以及实际检查的片段/镜头范围，并说明缺失关系。原句字面覆盖由代码辅助；动作或定版是否已经表达由 AI 对实际内容判断，禁止用关键词匹配直接放行。

只读取已确认来源、实际分镜、能力和时间轴。作者的规划或旧总结不能证明正文已经兑现；没有输入图片像素或实际视频时不输出「画面已经一致」「声音实际来得及」等已验证结论。产品事实优先核对 Brief，故事与旧资产生成文字不能替虚构参数作证。

### 9.2 严重性与误报控制

- ERROR：明确产品事实错误、原句未经授权删改、实质事件遗漏、不可执行状态、确切容量/能力冲突、非法引用等，必须定位依据。
- WARNING：可选景别偏好、审美建议、轻微节奏风险和证据不足的疑虑，不自动阻断。置信度只是说明，不能靠低置信度把实质错误改成建议。
- 总体好评不能冲掉某条 ERROR；笼统疑虑也不能覆盖具体已完成内容。无法给出关键依据时明确待核对，不伪造确定性。
- 正常维度给简短检查结论，不生成长篇同义总结，避免增加阅读成本和输出耗时。

独立复核逐条返回 `RESOLVED / PARTIAL / UNRESOLVED`，关联原 issueId、采用稿指纹及实际修改字段。新问题仍须完整证据；不能仅因作者声称修改了就关闭旧问题，也不能把旧问题原样带入与当前稿矛盾的结论。

实际 before/after、文本是否变化、时长增减由代码计算。第 2 镜口播没变，就不允许展示成「已缩短原句」；至于原句在新时长中能否自然完成，仍交由审校判断。

对「已明确独立定版却被判没交代」建立受控回归样本，同时增加真正未交代的反例。结构字段可减少歧义，但不能凭 `transition=HARD_CUT` 自动认定所有连续性问题都已解决。

## 10. API、持久化、依赖与迁移

### 10.1 接口与单一权威状态

在现有 `projects/:projectId/workflows/customized/production` 下扩展工作区、保存、任务、提示词和失败草稿核对接口，不另建制作任务系统。

创建任务增加版本、时长政策及片段目标；版本由服务端按功能发布配置冻结，客户端不能自行选择旧策略绕过校验。保存携带期望草稿 revision；候选核对携带候选指纹。Worker 写回携带现有租约及 attempt token。

任务输入明确冻结脚本、目录与 Brief 三个真实依赖。当前 SHOTS/PROMPT 会消费 Brief，但来源数组主要记录脚本/目录/镜头，本次补齐显式依赖，并验证有效性，不只依赖间接继承猜测来源。

复用 `CustomizedProductionTask`、JSON 快照/检查点和 `WorkingArtifact`。优先通过版本化 payload 兼容，无需为每个镜头、场次建立一组新的任务表。V2 片段目标存入有类型的输入快照，V1 `shotId` 列保持原义；若实际检索需要新增通用目标列，再做明确的可回滚扩展迁移，不滥用旧列或临时全库回填。

新增 domain 模块负责：版本解析、结构合成、时间轴、覆盖校验、补丁范围、审校证据和规范化指纹；Controller 保留协议职责，Repository 保留持久化职责。

### 10.2 工作副本粒度

| artifactKey                       | V2 内容与用途                                                          |
| --------------------------------- | ---------------------------------------------------------------------- |
| `customized-video-plan`           | 版本化全片目录与确认计划，包含来源、场次、片段顺序和覆盖信息           |
| `customized-shot:<shotId>`        | 单个真实镜头、局部时间及实际对象/原文引用                              |
| `customized-video-clip:<clipId>`  | 片段镜头顺序、实际制作输入、声音安排和必要边界，依赖准确镜头与对象版本 |
| `customized-clip-prompt:<clipId>` | 已通过校验的片段提示词，依赖已确认片段与实际消费的对象/约束            |

以上 key 为本计划新增设计，不表示已经存在。`customized-object:<id>`、目录和旧 `customized-shot-prompt:<shotId>` 保持原义。

全片目录可以保存完整确认快照用于恢复，但单镜/片段内容必须从同一次规范化候选派生，并在一个事务中提交，不允许分别编辑多个副本。片段 Prompt 不依赖整个全片目录的模糊最新版本，避免无关镜头排序导致全片提示词全部待更新。

删除/拆并实体记录替换关系并使其实际已有下游待更新，不能删除旧已确认媒体或自动重渲染。相同来源、相同内容保存不增 revision。仅变显示编号不改身份；相邻边界确实变化时，相关片段属于实际受影响范围。

### 10.3 历史内容处理

1. 无版本的任务/文档继续 V1 规则；打开页面不迁移、不创建新任务、不增长 revision。
2. V1 一条记录只读展示为一个「旧版片段」，内部按原文本保留；不通过解析「硬切」等关键词猜出多个新镜头。
3. 用户明确新生成或转换草稿时才创建 V2；展示旧提示词保留为历史、需要重新核对的范围，禁止假称旧稿已经符合新层级。
4. 转换不自动重新购买模型。只有无法可靠结构化的旧记录才提供独立、明确的 AI 重拆入口，创建新任务；普通打开/编辑不能暗中调用。
5. 历史 FAILED 任务不以新规则恢复。要使用新方法须明确创建 V2 任务，新任务消费当前有效输入，不跨任务复用旧业务结果。
6. ASSETS/IMAGE 写入只改资产区，保留当前版本 videoPlan；SHOTS/PROMPT 不改资产公共定义。补充新旧联合契约回归，防止资产重提把 V2 计划清空。

无法确认镜头边界的旧记录保持旧版阅读/编辑路径，不把原文本机械套入 V2 并宣称它是一个连续镜头。明确转换仅接收可验证的结构化结果；需要 AI 重拆的内容由独立入口说明后执行。

### 10.4 失败候选可用但不冒充通过

复用资产准备已有「人工核对草稿」模式，为 V2 提供只读候选视图：原稿、修订稿、问题及真实差异。任务 FAILED 保持原状态，未完成的 SAVE 不变绿。

候选转入人工草稿前必须通过结构、来源、身份、引用与 revision 校验；非法候选只能查看，不能写进正式编辑状态。结构合法但语义未通过时，用户可明确进入人工核对并修改，沿原「保存修改」入口确认；记录人工确认来源，不伪造 AI 审校通过。未解决容量/事实问题保持醒目定位，不提供一键忽略所有错误并自动提交的捷径。

## 11. 工作台与工作流面板

维持现有火宝式三栏及系统浅色、蓝色、圆角、边框和按钮尺度，不新增另一套页面风格。

- **左栏视频片段目录**：每行显示片段顺序、画面摘要、时长、场景、包含镜头数和制作入口；不恢复已移除的顶部生成/失败统计标签。电影镜头计数不混成视频数量。
- **中栏分镜与提示词**：选中片段后按顺序展示子镜头。普通查看清楚呈现画面及声音；编辑使用现有字段/弹窗，可定位景别、运镜、时长、起止状态及绑定。提示词属于当前片段，明确「生成片段提示词」，首次/再次生成图标沿效果类。
- **素材库**：保留完整目录供选择，清楚区分当前镜头出场、片段实际需求及可用图片；点击绑定沿现有保存保护，不因浏览素材发布版本。
- **右栏制作**：保留现有视频预览、历史位置、参考素材和渲染入口；渲染未接通如实展示，提示词成功不显示为视频完成。子镜头不各自冒出一个没有实际任务的渲染状态。
- **时长提示**：总时长沿用脚本创作及已有制作策略，不新增或恢复“制作设置 / 时长口径”面板。保留任务快照及具体容量问题详情，片段时长在工作台维护。
- **失败记录**：按使用者最新要求，不展示失败/取消终态横条及恢复、候选预览、人工核对入口。失败详情保留在现有工作流面板，不把未采用内容混入正常确认目录。

直接复用 `WorkflowRunProgress`、`WorkflowExecutionGraphDialog`、`WorkflowNodeEditActions`、`WorkflowExtractionActions`、共享字段/信息弹窗、确认与底部导航。进度按服务端真实阶段/批次计算，所有终态后消失；原「查看工作流」入口保留，不增加终态进度横条。

工作流详情按六阶段展示实际输入、容量安排、场次/片段/镜头、对象使用、问题证据、结构变化及复核结果。支持分页/定位，不能只显示数量；不公开原始 JSON、内部标识、系统提示词、存储地址或模型思考。

切换项目、Run、片段、镜头、候选版本和任务时取消旧详情请求并校验响应作用域。409 保留本地编辑；用户主动加载最新内容才替换。保存失败不切走当前片段，提示词未保存切换继续复用现有确认。

## 12. 速度与资源控制

### 12.1 优先减少无效工作

1. 容量与导演规划共用一次调用；固定模式装不下就提前停，避免生成整组不可能通过的分镜。
2. 资产按阶段投影：规划保留实体身份与关键事实，创作保留必要外观/状态，审校保留依据；去掉内部编辑标记、重复制作清单和不相关图片历史。不得截断相关产品事实或以旧总结替代来源。
3. 片段/镜头完整内容只产生一次；审校只输出具体发现，修订只输出实际补丁，代码合成 before/after，避免模型重写全片。
4. 批次请求有界排队、在途最多 2；共享模型并发保持 2，覆盖规划、创作、修订与复核，不通过提高并发转移限流和内存问题。
5. 任务检查点先保存后采用；成功批次、审校、修订、复核按输入/策略/候选指纹恢复。候选变化后旧审校失效，不能为省钱复用不匹配结论。
6. 只缓存经 PostgreSQL 版本校验的只读投影；不缓存大正文、签名 URL 或把跨任务结果当新任务输入。

源稿长度、实体数量、总镜头数和请求 token 预算继续受契约与配置限制，任务冻结这些上限；估时超出安全处理规模时报告具体范围及拆分建议，不截断正文或无界创建批次。每个模型请求同时受输出预算、超时和取消约束，计划出来的长镜数不能绕过资源保护。

### 12.2 统计与验收口径

分别记录排队、每次模型调用、重试退避、API/检查点保存、独立审校、修订、用户等待和端到端墙钟。记录输入/输出 token、首稿通过率、修订率、误报/漏报、修订影响范围和最终可用率；费用有账单才列实际金额。

上轮 358.838 秒为分散执行的五阶段模型耗时之和且最终失败，不能用它证明当前 30 秒任务性能，更不能写成优化后的成功基线。

实施目标：相同原稿及相同通过标准下减少上下文和无效返修；正常单批保留 3 次主要调用、一次语义修订最多 5 次。对具有可比成功质量的新旧样本，争取中位耗时降低至少 25%，P95 不回退；这是待验证目标，未实测前不承诺固定分钟数。若旧链路不能通过，以首稿/最终可用率及实际新耗时单列，不用失败快冒充性能好。

长样本同时报告总视频时长、片段/镜头/请求数，避免通过少拆镜或删词换取速度。模型拥堵、限流与本地处理时间分开记录。质量没达到时优先修方法，不删除独立复核来达标。

## 13. 充电器项目的预期改造验证

下面是结构与验收预期，不是已经生成的新分镜，也不提前规定最终镜头数量和时长。

| 原问题                         | 新链路应该如何处理                                                                    |
| ------------------------------ | ------------------------------------------------------------------------------------- |
| 31 秒容纳整段原话及多步操作    | PLAN 先列实际原句与必要动作，默认参考模式给合理制作时长；固定 31 秒不可行则停止并解释 |
| 一条含掂重、摆放、比较和长口播 | 按观看信息拆成真实镜头，必要时归入同一片段；旁白持续跨镜，不重复播放                  |
| 折脚、扫过、入袋挤在 5 秒      | 允许删去非必要摄影动作、明确省略，或拆镜/延长；不能删确认口播、改产品机械结构         |
| 漏包、线缆或场景               | 当前镜头及片段需求精确引用已有对象，完整素材库仍可浏览；不自动绑定其他人物            |
| 入包后又突然产品特写           | 明确收纳镜结束状态，随后独立定版镜/场次/片段；不能让产品无交代地回桌面                |
| 修订稿已写独立定版却被硬拒绝   | 审校引用实际结构和画面，给出能核对的理由；有疑虑区分其真正影响，不重复不存在的缺口    |
| 声称口播缩短但实际没变         | 真实差异显示原句未变及镜长变化，复核只能对当前安排作判断                              |

实测中保持原上游脚本及目录不变，才能判断本次分镜方法是否改善；若发现源稿本身需要改，单列来源问题，不能悄悄修源稿再宣称同输入通过。

## 15. 验收矩阵

### 15.1 内容与容量

- 充电器原样本：保留全部明确原句/事件；清除无依据比例、卡扣及端口位置；状态和绑定自洽；独立定版正反例均覆盖。
- 默认参考时长、显式固定时长、冲突固定要求、无台词、长对白、数字/型号、双人轮流与重叠说话、画外音跨镜、画面文字、非中文内容。
- 30/60/180 秒规模与超出能力的片段，少量及密集动作；不同场次与独立定版；同场跨请求的边界状态。
- 食品、护肤、电子、家居、软件各至少一份确认原稿；不把软件生成实体三视图，不强制所有产品演示操作流程。

### 15.2 修订与审校

- 单字段修订、一个镜头拆多个、多个镜头合并、跨片段重分组、调时、保留正常镜头和原句、真实缺资产与未渲染图片的区别。
- 真正矛盾/已明确省略/独立定版三组对照；原句没改却被称缩短；无效字段引用、伪造来源、没有具体依据的 ERROR、审美 WARNING、复核出现新问题。
- 补丁非法、合成中断、复核超时、复核失败、重复恢复、纠错预算用尽；候选保留但未提交，不重复购买同一有效阶段。
- 不用模型通过率单独证明效果：人工回看完整脚本与分镜，逐条判断事实、兑现、可执行性及审校误报/漏报，记录仍有争议之处。

### 15.3 API、任务与版本

- 跨项目/Run/脚本访问、重复创建/消息/回调、租约过期、取消、删除项目、旧 attempt、来源变化后回写、固定时长冲突无自动付费重试。
- 同内容保存不增 revision；两轮来源变化；镜头拆并后只有实际相关 Prompt 待更新；兄弟脚本不受影响；打开旧稿不迁移。
- V1/V2 的 SHOTS/PROMPT 以及 ASSETS/IMAGE 联合回归，资产重提不清空新版分镜，旧 Prompt 不被错误映射为新 Clip Prompt。
- 非法候选只读；合法失败候选明确进入人工草稿；409 保留本地内容；未经人工确认不创建正式分镜工作副本。

### 15.4 UI 与性能

- 1920、1440、窄屏，加载/空/运行/失败/候选/完成/待更新；目录、子镜头、素材库、提示词、预览和工作流详情。
- 切项目/Run/片段/镜头/任务、刷新、编辑取消、未保存提示、请求迟到、ESC/焦点恢复；终态进度消失。
- 共享效果类组件的使用关系及效果类回归，不能只凭截图证明复用。
- 先用受控适配器执行规模和故障测试；真实付费先测充电器普通参考模式，再测固定冲突和代表性长稿/其他类型。固定冲突不是全部失败都必须购买后续阶段。
- 相同条件的短/中/长样本收集可重复耗时；每个用于统计的分组尽量至少 5 次，样本不足不报告有代表性的 P95。不为凑样本无限付费，阶段性报告次数、调用与费用后再决定是否扩展。

## 16. 完成标准

同一份确认脚本能生成可读、可编辑、有来源的场次—片段—镜头结构；容量不足能提前解释；结构问题允许真实拆并与调时；审校和复核可对照实际证据，正常内容受到保护。用户在现有工作台完成片段选择、逐镜编辑、对象绑定及片段提示词，不需要来回切业务节点修正摄影表达。

最终交付同时提供实际质量问题、修订与误报记录、正常/异常调用次数、短长样本耗时及未验证范围。文字链路通过只代表制作计划可用，不等于真实视频、配音和画面一致性已经达标。本计划保留设计依据；实施后的界面以用户后续确认收敛：任务内镜头合并阅读，移除主区边界状态、原稿声画和数字范围控件，移除取消/恢复任务入口；底层结构和自动重试保留。实际通过项以验收记录为准。
