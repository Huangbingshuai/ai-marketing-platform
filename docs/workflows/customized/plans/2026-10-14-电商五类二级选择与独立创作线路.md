## 1. 已确认需求与边界

用户先选择“电商带货”，再单选“口播带货 / 促销转化 / 场景种草 / 痛点解决 / 功能演示”。名称与[飞书产品手册](https://ncnejrxxru2v.feishu.cn/wiki/GyzNwFRdBi1ZQXkbL4FcPQjunzg)一致，不让模型替换用户选择。一次任务的多份方案均属于所选类型，分别探索购买切入点、具体创意和讲述推进。另选类型创建新任务，保留已有方案。创意由系统开发，不恢复“创作要求”输入框。

仅改定制类第三节点的电商线路及其直接契约/展示；品牌广告、剧情短片、同城到店维持现状。六业务节点不变。上游为已确认 customized-brief 的固定 artifactId/revision；设置及普通编辑仍是节点草稿。完整脚本独立审校通过后沿原事务提交 customized-script:<scriptId>，资产准备和视频制作继续消费准确脚本 revision。本次不接通图片、视频、交付或发布，不自动提交 Git。

## 3. 选择交互

创作设置中的“视频类型”保留四个大类；只有电商带货下展示五张同系统样式的单选卡，说明分别沿用手册含义：真人推荐建立信任、真实优惠推动下单、生活场景激发需要、解决具体痛点、直观演示产品价值。口播带货排首位，不静默替用户决定。生成前必须明确选择一种。

参考时长、方案数量继续共用，结构要求仍放高级设置。类型不能与结构混为一谈：口播可以有不同推进结构，功能演示也能按用户要求安排顺序，均不机械套固定六段。人物、钩子、场景与创意由系统结合简报设计，不新增必填人设/创意表单。

旧脚本原样可读；有明确历史类型的显示实际类型，未记录的显示“历史带货脚本，未区分类型”，不按正文关键词猜测或回写。新选择改变本次生成设置，不改变正在阅读的旧脚本或其后续路径。

## 4. 五条独立线路

共同入口为信息卡快照、创作依据准备、电商二级类型路由。之后只执行选中线路；未选的没有模型请求或伪造步骤。每条线路拥有自己的策划字段、短创意开发、择优标准、正文指令和商业审校，不能只在同一长提示里换类型标签。

| 类型     | 前期策划要产出什么                                                                 | 独立执行顺序                                                    | 成稿的主体与专项审校                                                                                                               |
| -------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 口播带货 | 受众买前问题、讲述者与自然口吻、推荐理由、语言和演示如何分工、具体开场与中段吸引点 | 推荐策略与口播创意 → 口播方案择优 → 完整口播脚本 → 口播商业审校 | 人物在向观众介绍推荐，完整可说出口的口播，产品演示支撑理由；审查书面腔、重复参数、无依据亲测、只有旁白没有主体讲述。               |
| 促销转化 | 资料中的优惠及条件依据、适用人群、真实购买收益、顾虑回应与行动路径、活动表达创意   | 促销依据与转化创意 → 转化方案择优 → 完整促销脚本 → 转化商业审校 | 产品价值与真实活动利益相连；审查优惠是否讲清、条件是否遗漏、催单是否虚构。无优惠依据时停止本类型并提示补资料，不自动改成其他类型。 |
| 场景种草 | 受众熟悉的时刻、自然使用触点、值得向往的具体体验、产品参与和生活观察               | 生活观察与种草创意 → 场景方案择优 → 完整种草脚本 → 种草商业审校 | 让观众认出自己的需要；审查场景是否只是布景、产品是否硬插、具体价值是否实际发生，不强制矛盾与戏剧反转。                             |
| 痛点解决 | 真实摩擦、受影响的人和代价、解决能力的确认依据、改善链与不可外推边界、问题揭示创意 | 痛点依据与解决创意 → 解决方案择优 → 完整解决脚本 → 解决商业审校 | 看清问题如何被有依据地改善；审查人为用错、伪造故障、虚假竞品、夸张前后效果和跳过关键因果。                                         |
| 功能演示 | 买前疑问、已知能力、演示条件/操作/观察结果、解释与事实边界、观看悬念               | 演示设计与观看创意 → 演示方案择优 → 完整演示脚本 → 演示商业审校 | 过程让观众理解功能对自己有什么用；审查只完成操作或念参数、虚构实测和未知功能、不合理的比较结论。                                   |

创意不限于开场一句话。候选需要说明一个具体吸引点、如何发展、由什么行为/观察兑现、为何帮助理解购买价值。口播也可以提问、互动、实物选择或结果预告；不强制隐喻、反转或荒诞情节。多版本在所选类型内探索不同购买问题、讲述关系与演示，不靠换人物姓名凑差异。

每条商业审校与共用事实/执行审校独立并行。商业侧读取实际正文，策划不能作为已实现证据；事实侧核对完整简报、优惠/功效/认证/能力、动作因果、结构落实与各篇章真实容量。参考总时长保持软约束。任一实质错误进入最多一次定向修订与双路复核，仍错则不提交。审校可按口语、价值、创意、容量给具体结论，不为凑审校角色增加五次模型调用。

## 5. 充电器例子

同一确认资料可分别支持人物讲解双口如何选择、通勤自然使用、两台设备需要补电的合理摩擦、双口连接与实际状态演示，但不同类型的主体和说服过程不同，不能只换标题。

目前确认简报没有活动优惠时，选促销转化应该停在促销依据检查并指出缺口；不得生成“原价、到手价、限时、赠品”。测试真实促销线路需使用明确确认的测试优惠资料，不能偷偷修改现有充电器简报迎合通过，也不能把预期阻断当完整促销稿生成成功。

## 6. 数据、部署与兼容

- Contracts 为唯一来源，新增 commerceType 五值枚举及标签；设置、任务输入、策略、节点详情、脚本 creation 元信息均保存实际选择。其他视频类型不要求该字段。

- 按五个独立策略模块组织业务 Schema 和策划/择优/写作/审校指令；执行器、Provider、租约、检查点、自动重试、补丁及发布事务共享。保留现有 customized-storyboard Worker 和队列，无须五个容器或第二套任务数据库。
- 工作流组件继续与效果类共用；默认展示真实选中线路，展开时显示五个条件出口。节点详情展示推荐策略、真实优惠依据、生活观察、问题改善链或演示过程及具体审校，不只报数量；不展示内部JSON、原始提示或模型思考。
- 一份完成立即发布，其他失败可恢复，旧方案保留。类型设置切换不发布业务版本、不串入其他Run、不覆盖旧脚本。直接下游只消费已提交脚本及其 revision。

## 7. 速度与实施

策划与六份短创意在同一次模型调用内完成并真实保存，第二次调用独立择优。正常N份继续以2+3N主要调用为目标，必要修订增加3次，弱案最多一次替代。不同类型可采用不同输出预算/配置，但首轮保持已有Turbo短开发、Pro择优/正文/双审，先记录质量与速度，不无依据调低审校。总模型并发2，至多两份脚本推进，避免后续正文挤占已到审校的请求。

实施顺序：先契约与设置/历史兼容，再API与五类图，随后五个Worker策略及断点恢复，最后接通二次选择和共享详情。每步保持旧带货可运行。此前自动选型试验不作为默认任务部署；新二级选择实现后显式冻结新版本。
