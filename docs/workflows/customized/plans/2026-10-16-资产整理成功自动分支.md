# 资产整理成功自动分支

用户撤回定义/图片两个子层级方案。固定六节点不变，第四节点只有一层“资产准备”，不按对象数量创建节点。

## 范围和提交

消费当前脚本和简报的准确工作副本 revision。整批 ASSETS 完成全部检查点、审校与服务端来源/结构校验后，在完成事务内创建已发布资产 Run、复制准确上游、写入整批目录及逐对象副本。新 Run 直接挂在对应脚本头下，后续完整重新整理创建兄弟分支；不复制旧视频产物制造下游结果。旧资产版本保持不变。相同结果不创建空分支，重复成功回调只返回已有结果。

单项 ASSETS 成功原位提交；人工修改仍明确保存；IMAGE 只维护当前资产图片草稿，保存修改原位确认，均不创建兄弟分支。原有 `customized-asset-catalog` 与 `customized-object:<id>` 保持稳定，不再写定义/图片双头。失败的人工核对路径仍保留任务 FAILED、由人工明确保存，不伪装自动通过。

## 界面与恢复

保留 AI 整理资产的真实执行面板；只读取 ASSETS，不因最新任务是生图而串用。批量图片不提供查看工作流，也不在运行进度中提供详情入口，保留真实进度、取消与失败恢复。进度完成后消失。成功返回 `publishedWorkflowRunId`，当前页面跟随服务端活动路径刷新；仅原任务来源仍为活动路径时切换到新分支，完成不能抢走用户后来选择的路径。任务冻结输入与归属不搬迁，新资产分支只读关联创建它的执行记录。

版本树整批资产只显示一个节点，实际资产数量来自目录；展示编号按脚本头下的成功分支递增，不使用对象或图片业务 revision。历史目录只读兼容，不因查看新增分支或重跑历史模型。
