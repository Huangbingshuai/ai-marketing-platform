# C08 分镜卖点成立条件与审校校准

仅在本地补充通用分镜生成/审校规则及无付费测试，不执行Git、部署或线上任务，不改已成功计划、咖啡杯联调证据、前端或数据库内容。已有C06/C07修改保留。

作用为视频制作 SHOTS：直接输入当前 Run 已确认脚本、Brief、资产目录的固定来源revision；输出、草稿/确认、下游待更新仍沿既有分镜链路。本轮不重做资产、不重写脚本、不新增调用、阶段或业务节点。

## 冻结与实现

1. 在 ProductionInput 增加可选 `shotBenefitPolicyVersion: 1`，API仅新建V2 SHOTS任务时冻结；幂等返回和历史任务不补写。既有 `.7` 策略及一任务一分镜规则不变，无需扩大旧策略白名单或迁移旧检查点。
2. 独立维护简短的导演、分镜、审校、修订说明，仅任务带该版本且operation=SHOTS时追加。依据简报及原稿明确的本段表达目标，由AI核对必要条件与实际动作；不强制全部卖点逐条演示，不以关键词判断语义。
3. 生成不得为动作自然随意增加削弱表达的外部协助；不得为了展示而编造产品能力。辅助发生在关键动作之前、期间或完成之后须写清，之后的自然持握不追溯否认已经完成的能力展示。
4. 审校比较实际visual、起止状态、动作顺序与原稿，information等观看结论只是待验证主张。明确要求的成立条件与实际画面确定冲突，按原稿兑现/状态问题处理；仅时间关系不清或证据不足先作WARNING，不能自动判定产品事实造假。没有要求展示的卖点不因未演示报遗漏。
5. 有ERROR仍只修一次真实命中范围并独立复核，保留身份、原句、其他正常内容及定级账本；无需问题时不额外调用。历史与PROMPT任务不追加本策略，不自动修改旧结果。

## 验证

受控模型测试覆盖独立完成、关键动作中有辅助、动作后自然换握、未要求展示、时间含混五种情况，以及误导性观看结论不能替画面作证；验证局部修订/复核、WARNING不返修、正常调用数、恢复零额外调用和历史快照兼容。API测试新任务冻结与旧幂等返回不补写，执行相关pytest/mypy、API/Contracts类型和构建。受控结论不作为真实模型的语义识别质量或耗时证明。
