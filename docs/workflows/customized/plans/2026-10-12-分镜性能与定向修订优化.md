# 分镜性能与定向修订优化

## 范围与依据

定制类第三节点，消费已确认 `customized-brief` 的准确 artifactId / revision，完整成功后自动提交 `customized-script:<scriptId>` 独立分支。保留现有输入快照、租约、重试、人工编辑和下游依赖语义，不修改效果类或固定节点。

180 秒充电器基线任务 `07328335-d14b-4259-b4b1-2d4050ba1eea` 共 999 秒；全量修订输出 14935 token、耗时 281 秒；逐镜细化 7 次串行请求。目标是减少重复输出与请求开销，不能通过跳过独立审校、截断上下文或更换弱模型提速。

## 实施

1. Worker 内部增加有类型的稀疏修订格式，模型仍阅读完整稿件、简报和审校问题，只返回变更字段、必要新增/删除镜头及原因。代码机械校验身份、重复编辑、字段、引用和总时长，在完整原稿副本上应用，未改内容保持原样；实际前后差异由代码生成。
2. 保持 API 修订检查点为完整修订稿、差异及独立复核，兼容旧检查点。修订结果先持久化再复核；恢复不重复购买已有修订。复核仍阅读完整修订稿，有 ERROR 不发布。
3. 新长脚本将连续故事段落按最多 60 秒与文本容量合并；故事原段落仍不超过 30 秒，完整保留内容、顺序、总时长、故事、资产目录和前镜上下文。请求仍串行保持连续性，不提高并发。历史检查点沿用已经冻结的分片边界。
4. 所有模型、推理力度、独立审校及一次修订/复核上限不变。机械错误纠正、暂时故障有界重试保持。
5. 跨产品付费测试发现故事分段校验失败时原稿未保存。补齐故事阶段的未采用结果检查点；只对段落 ID、时长和总时长进行一次结构纠正，故事正文保持原样。纠正上限跨重启保存，暂时故障恢复复用已有原稿，不以代码缩放时长或猜测叙事。
6. 跨产品审校出现无效镜头引用，收紧原有审校 Schema：镜头 ID 枚举来自当前完整脚本，同一约束用于审校和复核。请求层拒绝无效引用并按既有预算重试，保持问题文本、严重程度与独立审校职责；不按名称、顺序或相似字符串猜测引用，不降低发布要求。
7. 完整镜头序列的累计时间由代码确定性计算，向审校、修订和复核提供实际时间轴；AI 仍负责判断事件含义和顺序、修改概述与结构。原批次修订一次后仍有 ERROR 则保留失败，不追加业务修订；改进策略用独立同稿付费重放验证，不改历史任务。

## 验收

- 单测覆盖稀疏更新不改正常内容、非法/重复身份、字段/引用、增删镜头、时长校验、旧修订恢复、新修订后复核失败/暂时失败恢复。
- 验证 60 秒分组不丢段落，旧检查点保持原计划；运行 Worker pytest / mypy、相关跨层测试和 diff 检查。
- 获用户授权进行真实付费：以旧 180 秒任务原稿及原审校结果做单独修订重放，比较同输入耗时与输出量（不改旧任务）；再运行全新 180 秒任务，保留完整独立审校、复核、发布与节点详情验证。
- 记录冷启动整批耗时、阶段耗时、token、问题及实际修订；模型结果随调用变化，不将单次结果视为耗时保证。费用仅引用真实账单，未获得账单时报告调用与 token。
- 仅在无活动分镜任务时替换独立 Worker 容器；不自动提交 Git。
