# 定制类提炼：分片整理与原文独立审校

范围为 CUSTOMIZED / INFORMATION_EXTRACTION。输入消费任务冻结的 `customized-source-package` 版本，结果仍是待确认草稿，人工保存才提交 `customized-brief`。不增加业务或内部执行图节点，不修改下游分镜、人工覆盖、revision 或效果类规则。品牌图片不进入模型。

1. 自由文档逐片提取后，由 AI 有界并行、平衡归并同文档分片，判断信息归属、重复和实质冲突，不再直接拼接为业务结果。
2. 在语义精炼阶段，逐文档逐片重新读取解析原文，对照文档提取结果和全局融合结果独立查漏。标准模板也执行审校；空模板只排除示例，不制造调用或事实。
3. 审校输出覆盖的字段及有证据的问题，包含字段、类型、说明、建议值、来源固定版本、位置与原文引文。模型用原文编号定位证据，系统回填固定文档版本、位置及逐字引文，避免模型转述引文；代码校验结构、编号、索引、固定引用和引文存在，不以关键词判断语义。
4. 发现问题后，针对审校建议及已有冲突涉及字段重新逐片读取所有文档，独立收集支持事实与逐字引文，不将首轮结果或审校建议当答案。修正模型结合跨片段依据判断审校是否误报，保留互补事实，不直接采用建议值替换整字段。未涉及字段和未被指出问题的卖点保持原文；再执行冲突复核，要求每个已有差异以原 ID 返回处理决定，遗漏仅允许纠正一次，持续遗漏不能完成。仍成立的冲突再独立交给模型区分共同属性和互斥属性，代码将共同属性格式化进每个完整候选，避免选用某个候选时丢掉共同事实。任何审校、依据收集或修正失败都不能绕过后完成。
5. 每份文档的审校报告持久化到现有步骤，重试复用同任务、同输入的成功报告。旧的未完成任务重试不复用缺少原文审校的语义完成检查点；已确认历史内容不迁移或自动重跑。
6. 独立配置定制类推理强度与输出预算，默认融合、修正与最终复核 medium，逐文档提取/整理和独立原文审校 low；输出预算 16384，有限重试预算 32768。真实标准表单的 medium 审校曾耗时 184 秒、推理约 8800 token，因此按职责分配推理强度，保留所有独立模型校验，不把推理耗时当作质量证明。维持全局模型并发上限，不添加无限循环；共享运行时和效果类配置不变。
7. 共享工作流详情展示实际审校文档/分片量、审校建议及原文证据，并单独展示实际改动的字段；审校建议不等于最终认定的错误。不展示供应商协议或完整模型输入。

无数据库迁移；审校报告契约放 Contracts，Worker 模型以契约测试对齐。验收覆盖遗漏修复、归属错误、跨分片语义整理、例子排除、真实规格冲突、证据伪造、失败恢复、旧检查点升级、并发限制及正常内容保留。运行 pytest / mypy、Contracts 与 API 类型检查、相关 API/Web 测试；在无活动任务时更新独立 Worker，再用隔离样本执行已授权的真实付费验证，记录耗时及质量观察，不以时长证明质量。
