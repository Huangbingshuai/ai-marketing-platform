# C16 分镜整数秒与渲染能力对齐

## 已确认范围

仅本地修改定制类视频制作的 API、Contracts、Worker 和对应测试/指南，不修改前端，不提交、推送、部署、重启或调用真实模型。保留其他会话的任务恢复及共享面板修改。

当前四种渲染模型的系统契约都只接受整数秒；SHOTS 却允许毫秒镜长，导致新确认结果可能没有可用渲染模型。保持真实渲染限制，不能静默取整或让请求时长与确认分镜不一致。

## 实施

1. 新建 V2 SHOTS 在服务端内部输入快照冻结 `shotDurationStepMs: 1000`，幂等返回、历史任务和其他操作不补写此字段。不更换已发布策略标识，不改变计划及对象身份。
2. 标记任务的导演规划、逐镜创作、独立审校和修订指令明确完整分镜镜长为整数秒；正常流程不增加调用或并发。声音、画面文字和动作落点继续毫秒精度。
3. 规划、分批候选、字段/结构修订及最终 Worker 校验均检查该步长；API 完成回调再次检查，不允许跳过 Worker 绕过提交。非法标记明确拒绝。代码只校验数值，不自动修改候选。
4. 无标记历史任务保持原快照及断点恢复。历史半秒结果仍可阅读、编辑和生成对应 Prompt，但真实 RENDER 继续拒绝非整数秒。REFERENCE 人工修改沿现有分镜参数和自动保存；只有改变的片段及实际下游待更新。

## 验证

- 新任务冻结、旧幂等不变、API 拒绝标记任务半秒回调，正常整数和毫秒声音窗口通过。
- Worker 规划、分批候选、字段及结构修订中的半秒拒绝；正常整数无额外调用；持久化标记任务的错误候选不能被恢复成成功；旧无标记任务允许原半秒且不改输入。
- Contracts 对四模型的半秒拒绝保持不变，提示明确“整数秒”；不调整模型范围或参数。
- 使用本地隔离数据库验证正常时长保存、重复保存无 revision 增长，以及未修改片段 Prompt/视频仍有效；无供应商调用或业务项目写入。部署会话另做原项目 UI 实测。
- 相关单元测试、Worker pytest/mypy、工作区类型检查/构建与所属文件格式、链接检查；线上渲染成功不以受控测试替代。
