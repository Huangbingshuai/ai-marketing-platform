# 分镜质量联调与开源调研（2026-10-19）

## 本轮范围

按用户授权，在正式浏览器对现有「充电器」项目的「通勤包减负角度」执行真实火山模型分镜任务，检查生成内容、执行详情、失败恢复、耗时及质量。现有五节点不变；本轮不重新生成上游脚本和资产、不生成图片/视频、不自动提交 Git。阻断联调的问题可以修复；分镜生产方法的结构性调整先形成建议，不以调研直接替换当前流程。

直接输入为脚本工作副本 revision 1、资产目录 revision 10 和冻结的产品信息卡，共 8 项资产。8 项均已有图片引用，当前分镜文字模型不读取图片像素。输出先保存可编辑分镜草稿，明确保存修改才确认镜头工作副本；下游逐镜提示词消费确认镜头及绑定对象。代码路径为 `customized-production` 独立 Worker → 共用制作执行底座的 SHOTS 链路 → 受保护内部 API。

## 取证方法

1. 通过真实浏览器按钮创建任务；记录准确任务、来源和冻结模型。只读数据库查询用于核实持久化状态，不替代浏览器触发或伪造成功。
2. 保存初稿、独立审校、修订及复核；对照完整原稿逐镜检查，区分代码合法、模型通过、人工认为可执行三种结论。
3. 检查正文事件与口播的覆盖、语音与操作容量、镜头语法、产品事实、对象子集绑定和连续性。不对未生成的视频声称实际画质、口型或运动达标。
4. 正常模型阶段耗时与白名单/网络/重启等待分开；报告真实 token 和可确认的调用次数，不编造账单金额。一次辅助诊断重放只写临时本地文件，不提交工作区结果。
5. 浏览器核验实际工作流内容、失败恢复、刷新和最终可见结果。初稿或复核不通过的内容保持未确认，不为了让链路变绿而手工放行。

## 质量观察维度

| 维度       | 需要回答的问题                                                             |
| ---------- | -------------------------------------------------------------------------- |
| 忠实性     | 每个已确认事件、口播及画面文字是否有落点？删改是否明确？                   |
| 时间容量   | 说话、停顿与操作能否在所分配时长中完成？总时长合法不等于每镜可演。         |
| 镜头表达   | 每镜是否有明确观看信息、构图、起幅和落幅？是否混淆一个镜头与多镜视频段落？ |
| 动作连续   | 产品在包内、手中、桌面或接电状态的变化是否有依据？省略是否明确？           |
| 产品事实   | 接口布局、机械结构、相对尺寸及功率承诺是否越过简报？                       |
| 资产       | 出场对象、引用说明和公共定义是否一致？场景、手部等可见对象是否漏绑？       |
| 审校有效性 | 是否发现具体问题？修订是否解决原问题并避免引入新问题？                     |

## 优化候选，待真实结果归纳后排序

- 在现有制作规划中先检查原稿的事件、原文语音、画面文字和可用时长；字数只是机械计量，真实容量由 AI 判断，不能用删词凑秒数冒充忠实拆镜。
- 导演规划输出场次、信息揭示、必要动作和边界状态；将真实电影镜头与后续视频生成任务分开，模型能力决定任务组合，不把 60 秒调用批次当作视频片段。
- 按场或有明确边界的段落有界并行，提供相邻边界状态；不是只给相邻段落概要后让两侧独立猜测。
- 审校增加剧本兑现、镜头表达、语音容量和资产绑定的具体证据；保留独立审校，正常项不重复重写，不追加无界返修。
- 修订按准确镜头与字段修改，保留正常内容和身份。语义不靠关键词或字符串相似度判断；结构、引用和时间计算由代码负责。
- 以阶段投影精简重复的资产制作说明和内部编辑标记，保留全部相关事实及视觉约束；缓存与断点恢复不跨任务复用业务结果。

真实任务结果和最终优先级另写证据文档，本计划不等于已经实施这些方法。

## 联调中确认的检查点缺口及修复范围

真实任务首轮修订模型调用成功返回后，外层机械校验抛出 ValueError；由于候选尚未写检查点，无法还原该次具体返回内容，恢复会重复购买修订。本轮只修复该缺口：模型返回的有类型修订候选在外层校验及采用前持久化，恢复复用同任务候选；失败仍保持未完成，不提交。生成及修订的请求 Schema 限定到本次真实资产 ID，原机械校验仍保留。

不更改正文、目标时长、镜头数量限制或语义审校标准，不增加自动语义返修轮数。测试覆盖非法引用候选留存、恢复不重复模型调用、正常局部修订及独立复核；通过后仅在无活动视频制作任务时更新独立 Worker，并从浏览器恢复原任务。历史已经丢失的候选无法补回，需如实单列一次重新修订调用。
