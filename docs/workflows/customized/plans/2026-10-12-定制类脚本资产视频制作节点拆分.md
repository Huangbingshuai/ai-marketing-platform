## 1. 本次交付

固定六节点改为：**资料导入 → 信息提炼 → 脚本创作 → 资产准备 → 视频制作 → 素材交付**。

本次接通第三至第五节点，到逐镜提示词生成为止。资产图片生成、图片上传替换、视频渲染、成片合成和交付另行接通，不提供假生成、假预览或无效按钮。跨节点版本回溯和历史分支重构暂不处理；仍保留数据隔离、乐观锁、准确来源和迟到回调保护，这些是当前结果可靠保存所必需。

复用火宝的“完整故事 → 共用对象 → 视频工作台”组织方式，使用本系统效果类组件与浅色视觉。脚本选择不是设置主脚本，不因查看另一份脚本而执行生成；从当前脚本进入后续节点即确定当前制作对象。

## 4. 脚本创作

设置继续为目标时长、方案数量；更多设置为叙事结构及补充要求。AI 范围 15–180 秒、1–5 份，历史超范围内容可继续查看与手工修改。品牌、受众、卖点不重复设置。

内部执行：信息卡快照 → 多方案构思 → 完整故事 → 独立审校 → 必要的定向修订及复核 → 保存完整脚本。删除新任务的资产、分镜阶段；保留旧任务恢复兼容。

故事保存正文、开场、发展、收束、对白安排及叙事段落。段落时长用于拆镜节奏，不是镜头。正文为人工编辑的主内容；审校核对产品事实、品牌约束、完整性、时长可行性、方案差异。最多一次针对问题的修订并复核，未通过不发布。

UI 保留方案目录、创作设置、故事概述、完整正文、方案比较、编辑、导入导出。新故事不再显示镜头数量、旧资产目录或逐镜工具。单份成功立即可用；其他方案完成不抢走当前选择。

## 5. 资产准备

### 5.1 对象与制作要求

分类固定为产品、人物、场景、道具。至少一个产品定义；其他类别按故事需要，不强制填满。一个人/产品跨场景仍使用同一个 ID；状态、动作、局部光线在镜头引用里说明，不无故生成重复实体。

每项包含：名称、类别、公共形象与特征、已确认信息、设计与待确认内容、故事/简报依据、图像制作要求、被哪些镜头使用、图片准备状态。

图像制作要求是可编辑文字清单，按实际产品形态提出，不把所有类型都套成实物三视图：

- 产品：外观主视、侧视/背面/俯视、包装、材质、功能或卖点细节；软件可为界面主视、关键界面状态与品牌规范。
- 人物：正面/侧面/背面、关键表情、核心姿态、服装与身份一致性。
- 场景：主机位、侧机位、空间关系、光源方向、时间与色温。
- 道具：整体外观、与人物/产品的比例关系、关键接触面及材质细节。

没有依据的规格/功效/认证不得补造；允许设计的外观写在设计内容里。图像要求不等于生成记录，不出现模拟候选或虚构完成状态。

### 5.2 执行与交互

执行：输入快照 → 实体与依据规划 → 统一定义与制作要求 → 独立审校 → 必要修订/复核 → 保存目录草稿。规划检查故事中的必要对象，审校检查遗漏、重复实体、分类、事实与设计分离和后续可制作性。

分类目录与信息卡；支持新增、改名、改类别、编辑、删除，删除前展示影响。误合实体可新增独立定义再调整相关绑定；重复实体通过明确的合并操作替换草稿绑定，保存才确认。重新整理先确认，旧正式目录保留到采用新草稿；不静默清空已有分镜。

## 6. 视频制作

### 6.1 工作台

宽屏为镜头目录、当前镜头编辑、当前镜头参考资产三栏；窄屏有序折叠。共用系统卡片、表单、动作与弹窗，不复制火宝配色。

镜头字段：名称、景别、运镜、时长、画面描述、台词/旁白、声音、氛围与连续性；支持新增、删除、排序、编辑。目录展示实际时长及 Prompt 状态。候选资产选择器展示完整目录；主工作区仅展示本镜绑定项与本镜呈现要求。

每镜独立生成/重新生成/编辑/保存 Prompt。同一工作台改分镜、绑定与 Prompt，不跳回两个上游节点。Prompt 显示人能读懂的对象名称；稳定 ID 在结构化引用中保存，不把内部 ID 露在正文。当前阶段不伪造图片引用；缺图片不阻断文本创作。

### 6.2 分镜执行

输入快照 → 叙事段落与镜头节奏规划 → 分段创作及实际对象绑定 → 全片审校 → 定向修订及复核 → 保存分镜草稿。

180 秒长故事按不超过 60 秒的连续段落分批，完整正文、全部共用定义、相邻段落上下文一起传入；有界并发并逐片保存检查点。服务器与 Worker 都校验总时长误差不超过 1 秒、正时长、唯一镜头 ID 和合法资产引用。模型负责事实、动作/空间连续性与绑定相关性，不用关键词代替语义判断。

### 6.3 单镜 Prompt 执行

输入快照 → 本镜动作/镜头/引用规划 → 提示词创作 → 独立审校 → 必要修订/复核 → 保存。

只传当前镜头和绑定子集，以及简报约束，不传其他镜头或未绑定对象。每条绑定需在提示词创作中有合理用途；无关项应在镜头编辑里解除。Prompt 的结构化 assetIds 与绑定一致，避免文字与素材引用脱节。后续接视频模型时再按供应商能力编译图片引用，不在本次建立假 @图片 功能。

## 7. 共享进度与真实详情

直接使用 WorkflowRunProgress、WorkflowExecutionGraphDialog、WorkflowNodeEditActions、WorkflowInformationCard/Field/Dialog、WorkflowExtractionActions/Feedback、WorkflowNodeFooter 和现有画布。

任务阶段名按脚本/资产/分镜/Prompt 适配。点击节点显示持久化内容；修订展示具体问题及修订结果，无需修订明确说明。大内容按段落可阅读，不截断成计数。进度服务端计算；完成即移除进度条，查看工作流入口保留。断网只是查询中断；刷新恢复任务。切换项目、Run、脚本、任务时取消或忽略迟到响应；保存冲突保留本地编辑。

## 8. API、Worker 与运行

沿用 storyboard API 管理脚本与方案。制作 API 位于 projects/:projectId/workflows/customized/production，提供工作区、草稿/确认、单镜 Prompt、任务创建/查询/重试/取消。独立 CustomizedProductionTask 表存输入快照、阶段、检查点、attempt、lease；复用 Project、WorkflowRun、WorkingArtifact、Outbox 与权限，不另建项目/资产基础设施。

脚本 Worker 继续独立部署。资产/分镜/Prompt 使用独立 customized-production-worker 服务、队列与 Token，复用同定制流程轻量运行包与 Provider；不安装 Docling/Torch/视频工具。三种操作快照和输出分开校验。当前按脚本串行提交，模型请求内部有界并发，避免互相覆盖草稿；不为并行生成放松来源与租约约束。

固定模型沿用已配置的 creative/detail，不修改效果类配置，不静默降级。临时错误有限退避，最多三次领取；复用同输入已成功阶段/分片。主动重新生成创建新任务。结构/审校失败保留结果，禁止无限付费修订。消息仅携带标识，Worker 经受保护 API 读写；项目删除与迟到回调走现有保护。

## 9. 兼容迁移

技术 nodeId 暂保留 STORYBOARD、SHOT_PROMPT、SHOT_RENDER，以免破坏原导航/历史数据；用户可见名称及职责统一为新三节点，文档说明映射。

旧完整故事缺正文时展示已有概述/叙事结构，不伪称恢复出原故事。旧分镜/人物/产品/场景只读投影到新工作台，首次明确保存再确认新产物。旧 products 不以关键词猜成道具，可由用户改类或重新整理。新任务只消费正文与简报，不把旧分镜当成故事输出约束。打开、切换和刷新不执行迁移写入、不发布新分支、不触发模型。

## 10. 执行顺序与验收

1. 保存修订计划，盘点已有改动；先完成契约与兼容读取，再逐节点接通。
2. 脚本收敛与故事导入导出/比较；旧任务维持恢复能力。
3. 资产字段、制作要求、编辑及合并、独立执行阶段与确认。
4. 分段分镜、单镜绑定、Prompt、审校/恢复、真实详情与共享 UI。
5. 数据库/API/Worker/UI 验证后在无活动任务时部署，更新指南与验收记录。

必须覆盖：食品/电子/软件的不同资产形态；无图片全链路；多脚本作用域；180 秒分段与检查点；单镜绑定子集；事实与设计分离；编辑取消；同内容不增 revision；两轮资产变化仅相关 Prompt 待更新；重复创建/回调、取消后回调、过期租约、跨项目访问、自动重试/恢复；旧项目非破坏读取。

检查命令以仓库配置为准：相关 contracts/Web/API 单测与数据库集成、pnpm typecheck、pnpm build、Worker pytest/mypy、Compose 配置、git diff --check；浏览器检查 1920/1440/窄屏及加载/空/运行/失败/完成/待更新。受控适配器只证明协议与恢复，不冒充真实模型质量。真实付费验收单独记录；本次不执行图片或视频付费任务。不自动提交 Git。
