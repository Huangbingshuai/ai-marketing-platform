## 实际问题与修复

1. **普通参数表第三列丢失。** 原清洗逻辑发现任一填写表后，会把所有表格只保留前两列，导致灯罩“暖白色”、收纳盒“暖灰色”丢失。现在逐张表识别填写项/填写内容，普通表格保留全部列。真实复测恢复颜色、材质及规格，模板示例没有混入事实。
2. **标准模板附录被忽略。** 标准字段快速提取以前忽略表外正文。现在只有完全符合已知表格及模板固定说明的资料走快速路径；额外正文、其他参数表走语义提取。真实复测保留附录的 2400mAh、318g 和苔绿色外观。
3. **多文档卖点来源索引重复。** 三文档融合连续两次因卖点局部索引未重排而失败。现在对与已验证输入原文完全相同的卖点恢复来源并重排最终索引；改写内容不猜测对应关系，仍严格校验。修复后原任务断点恢复成功，保留“含青梅果肉”“瓶盖有防拆封环”，后续完整新任务也成功。
4. **冲突候选替换整字段会漏掉共同事实。** 200g/250g 净含量冲突的第二个候选原来缺少无冲突的“保质期12个月”。单纯调整融合提示和只看融合结果的核对仍未解决。最终让现有语义核对读取各文档提取依据，修订同 ID 的完整候选；没有新增模型调用阶段。最终真实结果两项候选分别为“净含量200g/瓶，保质期12个月”和“净含量250g/瓶，保质期12个月”；未解决时确认返回 400。
5. **无效调用与串行等待。** 长文分片共享有界模型并发（默认 2），有序收集；多文档独立融合对采用平衡轮次，仍为 N−1 次调用。空白标准模板不调用模型；空模板伴随有效文档时不增加融合调用。
6. **短暂内部 API 故障。** 验收期间开发 API 实际重启造成断连，原任务租约到期后自动恢复并复用成功文档检查点。新增内部 HTTP 有限重试：网络错误、429、5xx 最多 4 次，退避 1/2/4 秒，连接超时 5 秒；404/409 不重试。新重试分支用受控 transport 验证，最终真实任务验证正常链路；未再次人为中断共享 API。
