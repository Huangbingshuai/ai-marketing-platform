# C08 分镜卖点成立条件本地验证

日期：2026-10-19。仅本地实现与无付费验证，不执行Git、部署、线上任务或修改已有成功计划；未改咖啡杯联调文档、截图、前端和业务数据。既有C06/C07修改保留。实施范围见[计划](../plans/2026-10-19-分镜卖点成立条件与审校校准.md)。

## 问题与边界

已观察到的质量问题是画面增加另一只手的辅助，却仍以观看信息宣称兑现独立操作能力。问题不等于出现双手就有错，也不能据此反推产品没有单手开启能力。必须结合本段表达要求、实际动作和辅助发生时间判断；关键动作完成后的自然换握不应误报。

此前规则已有原稿兑现、产品事实、持物与空间连续核对，但未明确要求核对“卖点成立所需的条件”，容易将操作可执行当作产品价值已被展示。

## 实现

- Contracts 的内部任务输入增加可选 `shotBenefitPolicyVersion?: 1`。API只在新建V2 SHOTS快照中冻结为1，原 `.7` 策略和一任务一分镜规则不变。无数据库迁移、设置入口或新增工作流阶段。
- 历史快照没有该字段时，不追加新规则；幂等返回不补写版本。新Worker遇到非法或不支持的SHOTS策略版本，在模型请求和过程回调前拒绝。
- `video_benefit_policy.py` 定义导演、分镜、独立审校和局部修订的通用说明；`video_pipeline.py` 仅在SHOTS且版本为1时追加。没有关键词检测、语义分类代码、全量卖点演示配额或新增模型请求。
- AI从简报及原稿已明确的当前表达目标识别必要条件，核对实际动作是否保留。不得擅自加入削弱表达的外部辅助，也不为演示补造产品能力；观看信息、标题或作者自评均不能替画面作证。
- 确定违反已明确条件才按原稿兑现/动作状态报ERROR；先后关系或协助是否必要不清时提示WARNING澄清，不自动判产品事实造假。没有要求展示的卖点不强制演示；操作完成后的自然持握、接手保持合法。
- ERROR仍沿原一次字段/结构修订和独立复核；只修改命中动作、状态及对应信息，保留原话、正常内容及未涉及的身份和时间安排。确需结构/时长修改仍按原有范围和时长政策处理。WARNING不强制返修，未解决不完成；PROMPT及其已有调用规则不受新策略影响。

## 实际验证

- 新增Worker测试11项：独立完成、关键动作中有辅助、动作后自然换握、未要求展示、时间含混，以及误导性观看信息仍交独立审校；有问题按既有一次修订/复核，未解决阻断、恢复不重复调用、无版本历史输入不改写、PROMPT不追加策略、非法版本付费前拒绝。
- 视频Worker全量pytest：86项通过。受控正常样本仍为3次模型请求，只有预设ERROR样本为5次；WARNING、后续自然换握和未要求展示均不触发修订。此处是受控模型计数，不是供应商实测延迟。
- 视频入口、全部视频测试及共用runtime的mypy：27文件通过。资产Worker回归pytest45项通过，其入口/全部测试mypy7文件通过。
- API production与相关契约测试：56项通过，4项数据库测试按原开关跳过。新增2项验证新任务冻结，以及历史幂等返回不补写、不创建新任务。
- API生产构建及Contracts类型检查通过。全工作区 `pnpm typecheck` 曾通过；随后全量 `pnpm build` 被前端并发新增的 `production-shot-states.spec.ts` 第64、71、176行TS2352类型断言错误阻断，不能将当前全量构建记为通过。本轮不修改该前端文件。相关ESLint、Prettier及新增Python文件格式检查通过；本轮8文件尾空白及本地链接检查通过，未执行Git操作。

上述语义结论由受控模型预设，用于验证策略确实传入相应阶段、实际画面与误导性结论都送达独立审校、修订范围及调用保护。它们不能证明真实模型已经稳定识别所有条件，也不作为真实生图、视频、付费质量或耗时验收。本轮未运行数据库集成测试及浏览器，未替线上人工修正结果作结论。

## 待发布与后续

API、Contracts与视频Worker需在空闲窗口配套发布；仅更新API而保留旧Worker，旧实现不会执行新增策略。资产Worker无需因C08单独重启。历史任务继续原策略，不因升级重新提炼、分镜、修订或增加费用。前端不需要新增设置或适配此内部输入字段。

真实模型复测需后续独立授权任务，重点比较动作期间与完成之后的辅助、信息自述与画面矛盾、以及未要求展示的卖点；不为验证规则自动重跑已经成功的咖啡杯分镜。
