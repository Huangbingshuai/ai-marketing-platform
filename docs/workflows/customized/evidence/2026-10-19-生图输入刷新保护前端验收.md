# 生图输入刷新保护前端验收

日期：2026-10-19。范围：C10 Composer 生命周期；仅本地，未部署、真实上传/付费、操作线上项目或执行 Git 写操作。C08/C09/C11 其他任务改动保持原样。

## 问题证据与未定位观察

独立受控组件试验已复现旧行为：同 ID 资产对象替换触发 `() => [projectId, workflowRunId, asset.id]` 的数组 getter watcher；旧上传被取消、参考图清空、生成重新启用。另一个实际 Workspace 刷新对照显示，`load(true)` 更新文档时仍保留弹窗资产引用，进行中的上传没有被清空。因此这是已证明的组件缺陷，**尚不能据此解释首次线上参考图未进入任务的现象**。首次现象继续记录为未定位观察，不宣称线上因果已经确认。

## 修复边界

- 改为比较项目/Run/对象身份与规范化的实际制作依据。资产定义及该对象的历史生成设置相同，仅对象重新物化、属性键顺序或图片/人工标记更新时，不重置本次提示词、模型、画幅、分辨率、参考图及进行中的上传。
- 相同身份的制作依据实际变化时，中止未完成上传，保留本次输入及已选参考图，明确提示并禁止生成。沿用本次输入或载入最新设置均需用户明确点击，后者才替换当前输入。
- 真正切换项目、Run 或对象时中止旧请求，重新载入当前对象并显示可理解的提示。上传冻结原项目/Run，并检查取消标记、身份、依据及请求实例，旧成功/失败响应不能进入新作用域；多文件上传不能继续发送旧批次后续文件。
- 补齐已经打开的模型/参数/品牌选择按钮与文件输入在运行期间的禁用。没有新 API、缓存或模型任务，不复制父图到子对象。
