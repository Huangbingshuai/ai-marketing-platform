# 提炼差异候选范围与未知事实修复

日期：2026-10-19。此次记录本地实现与无付费验证，不修改咖啡杯项目已确认的信息卡，也不将受控模型测试视为真实生成质量验收。

## 原因及修复

线上 SW-C01 信息卡保留了未知事实，但差异候选整理强制每项提示提供至少两个整字段选项。性能未测、配件未知等提示因此借用同字段的容量差异；前端直接采用完整字段又可能撤销之前已处理的其他差异。

候选整理改为按字段共同核对问题，AI 逐 ID 判断真实互斥事实、已经正确保留的未知或互补信息、需要提示的信息缺口。真实冲突返回当前字段中唯一的最小原片段及有依据的替换值；独立语义核对再检查范围和事实依据。代码校验身份、唯一匹配、不重叠与候选合法性，仅拼接原片段之外的文字，不用关键词判断语义。

保留原文审校、跨片段依据收集、定向修正及最终核对。范围核对缺失或拒绝时保持未完成；全部误报被撤销后，差异整理过程仍正确记录为成功。未完成任务只有带 `conflictPolicyVersion: 2` 的语义检查点可复用；已完成任务和历史确认产物不迁移。

## 跨端契约

保留 `issues.alternatives: string[]`，增加可选 `resolution`：

```ts
{ schemaVersion: 1, baseValue: string, before: string, replacements: string[] }
```

`baseValue` 是冻结字段值，替换值与完整候选按索引对应。Contracts 的 `applyCustomizedBriefIssueAlternative(currentValue, issue, index)` 在当前字段应用精确替换，返回成功值或 `LEGACY / INVALID / STALE`。同字段不同位置的候选可以连续采用，保留其他选择和片段外人工修改；原片段变化、多次出现或数据不合法时不改写。历史无范围候选只供完整查看与人工核对。

API 完成回调校验冻结字段、候选对齐和不重叠范围。前端使用同一函数，显示简短候选、原片段及基于当前填写合成的完整预览；来源待更新时不采用。既有编辑草稿、预期 revision、明确保存与取消边界保持不变，不新增分支或数据库迁移。
