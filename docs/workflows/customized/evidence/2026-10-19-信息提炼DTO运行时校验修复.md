# 信息提炼 DTO 运行时校验修复

状态：本地修复及验证完成，尚未部署。未提交、推送或触发付费任务。

## 问题与根因

线上咖啡杯项目在已确认资料包 revision 1 后打开信息提炼节点，带合法 `workflowRunId` 的 GET 返回400：`property workflowRunId should not exist`。错误发生在 Controller 参数校验阶段，尚未进入资料包读取与提炼业务。

`customized-extraction.controller.ts` 使用 `import type` 导入查询及请求 DTO，TypeScript 生产编译后对应的 `design:paramtypes` 是 `Function`，不是带有校验装饰器的实际 DTO 类。Nest 因而无法取得字段白名单；`whitelist: true` 与 `forbidNonWhitelisted: true` 将合法字段视为未知字段。DTO 的继承规则本身正常。

本机 Context7 工具不可用，已核对 [Nest 官方校验文档](https://docs.nestjs.com/techniques/validation#auto-validation)，其中明确要求 DTO 使用运行时导入。

## 修改

- 将信息提炼 Controller 的四个 DTO 改为运行时导入，并说明 ESLint 不应将其改回类型导入。
- 不改前端请求、DTO 字段、UUID 校验、全局 whitelist、鉴权或 Repository 项目/Run 隔离规则。
- 不修改来源 WorkingArtifact、revision、任务队列、模型配置或业务结果。
- 新增编译后元数据与实际 HTTP 校验回归测试；Service 使用受控替身，不创建真实任务、不连接数据库或供应商。

2. 新测试13项：六个查询/写入入口保留正确 DTO；合法 GET 原样转发项目与 Run；缺少 Run、UUID 非法、额外字段、重复参数仍拒绝；创建任务继承 Run 校验正常；未知请求体字段仍拒绝。
3. `pnpm exec vitest run src/workflows/customized/information-extraction/customized-extraction-validation.spec.ts src/workflows/customized/information-extraction/customized-extraction.service.spec.ts src/workflows/customized/production/production-service.spec.ts --maxWorkers=1`：API 目录执行，3文件26测试通过。
