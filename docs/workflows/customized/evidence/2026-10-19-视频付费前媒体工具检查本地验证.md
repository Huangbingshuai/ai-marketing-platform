# C14 视频付费前媒体工具检查本地验证

记录日期：2026-10-19。对应[实施补充](../plans/2026-10-19-Prompt多引文校验与视频运行时诊断.md)。本轮仅本地视频运行时、精确测试及记录；没有新增 Git 操作、部署、服务重启、生产写入或付费调用。

## 范围与行为

定制类第五节点“视频制作”的 RENDER 仍消费任务中冻结的已确认片段及 Prompt revision、配置和图片版本，输出沿既有 API 校验后自动提交 `customized-clip-video:<clipId>`，不改任何来源、产物、分支或提交规则。

构建期只读探针不能证明直接启动或旧镜像中的 Worker 媒体工具齐全。运行时现在在参考图下载、创建围栏及供应商请求之前，逐项执行 `ffmpeg -version` 和 `ffprobe -version`。工具名沿用既有媒体处理的 PATH 路径；每项最多 5 秒，标准输出和错误均丢弃，不将二进制路径或原始异常写入任务。

缺失、权限不足、非零退出或超时导致 SNAPSHOT 明确失败，抛出不可自动重试的安全环境错误。不会设置 createStarted，不会创建传输客户端或调用供应商；失败 checkpoint 不携带 output，因此保留原 providerTaskId、createStarted 及其他检查点。超时及协程取消会终止并回收探针子进程。

已有 providerTaskId 的显式恢复同样先检查工具。补齐工具后使用原身份继续查询和下载；原有“已提交但供应商身份未知”围栏仍优先拒绝，不绕过防重复计费规则。此检查只证明工具可执行，真实视频解码、时长、尺寸和上传校验仍保留。

## 精确测试

新增 `test_video_render_preflight.py` 共 11 项：

- 两个工具分别覆盖缺失、无权限、非零退出、超时；每种同时验证新任务与已有供应商任务失败时输入/output不变、无供应商客户端构造及创建，失败 checkpoint 无 output。
- 正常工具按既有工具名检查，输出不捕获；取消及超时回收子进程。
- 先复现缺工具失败，再恢复工具；使用真正的 SeedanceTransport 搭配 `httpx.MockTransport`，只出现原任务状态 GET 和文件下载 GET，无 POST 创建，也无新提交心跳围栏。封面及上传使用受控替身，不冒充真实媒体验收。
