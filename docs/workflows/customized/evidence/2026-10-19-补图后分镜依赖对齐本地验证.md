# C11 补图后分镜依赖对齐本地验证

日期：2026-10-19。仅本地API实现及无付费验证，不执行Git、部署、线上任务或修改咖啡杯联调证据。C08/C09/C10已有改动保留。计划见[补图后分镜依赖对齐](../plans/2026-10-19-补图后分镜依赖对齐.md)。

## 根因与提交边界

对象工作副本包含 `image`。确认图片使对象及资产目录的真实revision改变，依赖它们的镜头/片段按既有规则待更新；创建PROMPT要求片段CURRENT，而原分镜仍冻结旧目录revision/hash，重新保存分镜也会失败。仅用整体计划的shotsConfirmed不能判断单片段是否可创建任务。

本轮保留通用依赖失效规则。新增 `image-only-plan-rebase.ts`，从当前Run的已确认V2计划、其中保留的资产快照、来源指纹及原依赖构建完整证明：

- 当前目录已确认；去除image后的全部资产内容与冻结快照完全一致，身份、公共定义、事实、设计、制作要求、人工字段等均不能变化。
- 脚本、Brief准确ID/revision/hash仍CURRENT；原目录哈希可由冻结资产及未变来源重建，兼容旧版裸payload哈希，不按时间或名称猜测来源。
- 当前草稿分镜必须与已确认计划一致；逐镜与逐片段payload、原对象依赖、父来源、作用域及身份均核对。未解释的STALE不会因内容没变就被直接清除。
- 当前图片固定版本必须属于本项目定制资产，未失效/归档，文件登记可用、字节数及SHA合法。无效图片不能通过对齐绕过检查。

证明成立后，使用既有工作副本提交器，依次对齐实际镜头、片段及仍精确依赖原片段的提示词，再更新计划中的目录来源和资产图片快照。分镜正文、ID、顺序、时长、声音和绑定保持不变。已有提示词若依赖更早的真实分镜，仍待更新，不盲目采用；旧视频保持待更新且文件内容不变，不自动重渲染。

确有依赖或来源变化的工作副本可以增长revision；重复相同图片和来源不增长。只提交当前project/Run，复用预期revision和项目锁，不新增分支、不额外向兄弟传播对齐操作，不直接写CURRENT。

## 触发入口与兼容

- 用户明确保存资产时，在同一事务内对齐并保存准确草稿revision。
- 用户创建PROMPT/RENDER时，在无活动任务、预期草稿revision匹配后执行相同证明；因此已被旧逻辑阻断的记录不需要假编辑或重跑SHOTS。新任务冻结的是对齐后的真实草稿与来源，领取和回调继续校验。
- 幂等旧任务先按原规则返回，不触发对齐；workspace等GET不写。历史任务输出、原审校及成功计划记录不改写。
- 证明不成立时继续原有拒绝，不能将真实产品定义、脚本、Brief或分镜变化当作补图吞掉。

本轮只改API：新增证明/提交模块、数据库测试，在 `ProductionRepository.save/start` 接入；另有本计划与验证记录。Contracts、Worker、前端、数据库结构无需为C11改变。

## 实际本地数据库验证

运行前解析本机.env，确认DATABASE_URL主机为localhost，再执行只允许本地地址的测试。使用两个随机UUID隔离项目及独立兄弟Run，未读取或改动业务项目。只创建受控图片版本/文件登记，不访问对象存储或调用模型；队列入口使用替身，实际Outbox始终0。

新增集成测试 `image-only-plan-rebase.database.spec.ts` 已在真实PostgreSQL通过，包含以下断言：

1. 建立已确认六片段/六分镜，复现旧逻辑：图片只写草稿和资产工作副本，实际片段STALE；GET不修复或推进草稿revision。
2. 直接创建PROMPT，合法对齐旧来源并成功领取任务；原六片段正文、镜头身份、顺序、时长、声音和绑定一致，SHOTS任务数为0。
3. 第二轮图片变化沿正常资产保存对齐，已有提示词仍有效；同内容重复保存，草稿及全部工作副本revision/hash不变；无新增分支，独立兄弟记录逐字段不变。
4. 第三轮受控补图用于拒绝边界：未保存分镜、旧Brief哈希、错误依赖哈希、不同项目/Run、真实旧提示词不被错误对齐；无效图片登记不会发生对齐提交；不存在的图片版本和旧草稿revision明确拒绝。
5. 真正文字定义变化仍使实际提示词/片段待更新，再创建PROMPT被拒绝，无新增Task。已有视频依赖用受控占位记录验证：保持STALE、payload及revision不变，没有视频渲染任务。
6. 测试最后清理自身记录，并断言两个测试项目范围内项目、工作副本、Run、制作任务、资产、资产版本、文件和Outbox八项计数全部为0。没有迁移、真实消息或付费供应商请求。

API production及相关契约默认回归56项通过；5项数据库测试在默认运行按开关跳过，其中本轮C11集成测试已另行显式执行通过，其余4项没有本轮重跑。全工作区 `pnpm typecheck`、`pnpm build`、相关ESLint/Prettier及5个本轮文件的尾空白/本地链接检查通过；构建保留既有前端大包体提示。本轮遵循不操作Git要求，不执行Git检查或暂存。

## 未验证与发布

没有浏览器、线上恢复、真实图片/视频质量或供应商速度验收；这些由主会话在空闲窗口发布后验证。数据库测试验证真实事务及依赖行为，受控文件登记不等于真实图片像素验收。

C11本身只需发布API，无迁移、Worker重启或前端新按钮。发布后可在原阻断片段直接创建PROMPT；若证明不足，继续保留待更新并给出既有冲突，不自动重付费分镜。
