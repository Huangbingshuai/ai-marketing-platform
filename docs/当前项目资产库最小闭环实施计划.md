# 项目与素材资产中心 V4 纠错实施计划

## 基准、边界与协作

- 唯一视觉与交互基准为 `references/prototypes/integrated/system-integrated-demo.html` 中从第 616 行开始、从第 3183 行开始挂载的“资产中心 V4”。文件前部的 `gaw`、`gpi`、`gai` 历史版本不作为验收基准。
- 正式功能使用 Vue、NestJS、Prisma、PostgreSQL 与 StoragePort 重新实现，不复制原型 HTML、内联 CSS、脚本或 Mock Store。
- 后端先冻结 `packages/contracts`、Prisma 和 HTTP API，前端只消费共享契约和 HTTP API，不维护第二套字段。
- 保留所有现有未提交修改，不提交 Git，完成后等待验收。
- 正式数据环境额外保留加载、空、失败、重试和请求竞态保护；这是相对原型 Mock 的必要补充。

## V4 信息架构

顶部系统入口只保留一个描边“项目与资产”按钮。点击后打开标题为“项目与素材资产管理”的右侧大抽屉：桌面宽度 `min(96vw, 1760px)`，内容高度 `calc(100vh - 116px)`，左侧导航最终宽 184px。

左侧只有两个一级入口：

1. 项目资产库
2. 当前项目资产

左侧同时展示当前业务和当前项目卡。项目资产库按效果类、定制类、裂变类浏览；定制类包含“定制项目 / 音色库”，裂变类包含“爆款视频项目 / 数字人库 / 局部属性变更项目”。

项目资产库先展示可搜索的双列项目卡，进入项目后再浏览对应工作流空间资产；当前项目资产展示当前项目源资产和跨上下文调用后形成的锁定版本快照。

## 共享业务契约

工作流：`EFFECT` 效果类、`CUSTOMIZED` 定制类、`FISSION` 裂变类。

工作流空间：

- `EFFECT`
- `CUSTOMIZED_PROJECT`
- `CUSTOMIZED_VOICE_LIBRARY`
- `FISSION_CLONE`
- `FISSION_AVATAR`
- `FISSION_LOCAL_REPLACE`

资产类型与目录以 `packages/contracts/src/asset.ts` 的最终导出为唯一事实源，覆盖原始资料、视频配置、提炼结果、Prompt、脚本/分镜、人物/产品/场景、音色/音频、字幕、视频素材、模板/时间轴/工程、映射/替换配置/替换引用、成片、报告与交付清单。

项目对外字段至少包括 `id`、`name`、`description`、`status`、`client`、`productName`、`iconKey`、`workflowSpaces` 和各工作流空间 `assetCounts`。

资产在兼容原单文件字段的基础上增加：

- `storageWorkflow`、`workflowSpace`
- `status`、`qualityStatus`、`currentVersion`
- `assetClass`、`businessType`、`contentKind`
- `content`、`businessData`、`views`
- `sourceArtifactId`、`sourceRunId`、`sourceNode`、`sourceShot`
- `sourceProjectId`、`sourceAssetId`、`sourceVersion`、`importedAt`
- `dependencies`
- `isSnapshot`、`readOnly`、`sourceCurrentVersion`、`outdated`

## Prisma 与持久化

- `Project` 增加客户、产品、图标和工作流空间信息。
- `Asset` 继续强制包含 `projectId`，并增加工作流、空间、状态、业务内容、来源、幂等和当前版本字段。
- 新增 `AssetVersion`，保存版本号、修改说明、状态、业务内容和该版本文件元数据；文件字节仍只存 Storage。
- 跨项目或跨工作流调用创建目标项目独立资产 ID和锁定快照，保存来源项目、来源资产和来源版本，修改目标快照不影响源资产。
- 同一上传幂等键再次提交时创建新版本，不创建重复资产。
- 归档作为正式系统中的“删除/移除”实现，不物理删除 Storage 对象。
- 所有查询、版本、批量、快照与内容操作均显式校验 `projectId`；项目 B 使用项目 A 的资产 ID必须返回统一 `404 ASSET_NOT_FOUND`。

## 冻结 HTTP API

除文件内容接口外统一返回 `ApiResponse<T>`。

### 项目

| 方法   | 路径                                   | 行为                           |
| ------ | -------------------------------------- | ------------------------------ |
| `GET`  | `/api/projects?keyword&workflow&space` | 全局或工作流项目搜索与空间计数 |
| `POST` | `/api/projects`                        | 创建当前工作流草稿项目         |
| `GET`  | `/api/projects/:projectId`             | 项目详情与空间计数             |

### 资产浏览与文件

| 方法   | 路径                                                                               | 行为                                         |
| ------ | ---------------------------------------------------------------------------------- | -------------------------------------------- |
| `GET`  | `/api/projects/:projectId/assets?workflow&space&keyword&type&status&page&pageSize` | 项目空间资产、类型计数与分页                 |
| `GET`  | `/api/projects/:projectId/assets/:assetId`                                         | 详情、来源、依赖与快照状态                   |
| `GET`  | `/api/projects/:projectId/assets/:assetId/content`                                 | 原文件预览、下载与 Range                     |
| `POST` | `/api/projects/:projectId/assets/imports`                                          | 按工作流/空间/类型多文件上传，返回 `Asset[]` |

兼容保留原单文件导入、元数据更新与归档路由，但 V4 页面不展示旧元数据弹窗、编辑和归档按钮。

### 版本、跨项目快照与批量

| 方法   | 路径                                                            | 行为                       |
| ------ | --------------------------------------------------------------- | -------------------------- |
| `GET`  | `/api/projects/:projectId/assets/:assetId/versions`             | 版本时间线                 |
| `POST` | `/api/projects/:projectId/assets/:assetId/versions`             | 按修改说明创建新版本       |
| `POST` | `/api/projects/:targetProjectId/assets/import-snapshot`         | 从来源项目复制锁定版本快照 |
| `POST` | `/api/projects/:targetProjectId/assets/:assetId/upgrade-source` | 快照显式升级到来源最新版   |
| `POST` | `/api/projects/:projectId/assets/batch-tags`                    | 批量追加标签               |
| `POST` | `/api/projects/:projectId/assets/batch-archive`                 | 批量软归档/移除            |
| `POST` | `/api/projects/:projectId/assets/store-artifacts`               | 工作流正式产物幂等入库     |

多文件上传固定使用重复 `files` 字段和 `workflow`、`space`、`type` 文本字段。服务端生成幂等键；数据库写入失败必须补偿删除刚写入的 Storage 对象并清理所有 Multipart 临时文件。

## V4 前端验收面

项目资产库必须实现：

- 全局项目搜索及按工作流/裂变空间分组。
- 三张工作流卡及对应计数。
- 定制类和裂变类二级空间。
- 工作流内项目搜索、双列项目卡、新建草稿项目。
- 项目面包屑、返回项目列表、设为当前项目。

资产工作台必须实现：

- 搜索名称、资产 ID、来源产物/任务/节点/镜头、Prompt/正文和标签。
- 按原型生产顺序排列的类型胶囊及计数。
- 选中具体类型后出现相应多文件上传入口。
- 全选本页、全选筛选结果、批量标签、批量删除。
- 24 / 48 / 96 分页、当前区间、上一页和下一页。
- 卡片的 144px 类型化预览、质量状态、版本、业务包数量、来源、锁定语义和最多四个标签。
- 资产区 `1.28fr / minmax(480px, .72fr)` 的桌面布局。
- 详情优先展示业务正文或素材预览，并提供来源、工作流、空间、版本、上游依赖和版本时间线。
- 源资产“生成新版本”；快照“升级到来源最新版 / 移除”；主操作“调用到当前模块”。
- 从项目资产库跨项目、跨工作流调用时创建目标项目锁定快照。

不再展示旧实现中的目录/标签下拉、始终可见的导入按钮、元数据编辑按钮、归档按钮和单文件元数据弹窗。

## 正式工程对原型 Mock 的必要修正

- 原型 `localStorage` 数据改为 PostgreSQL。
- 原型 `URL.createObjectURL` 持久化改为 StoragePort 与本地 Adapter。
- 原型 `projectId: null` 的全局资源不直接落正式业务资产；全局空间可以展示空态，系统资源必须先导入当前项目。
- 原型只读引用按工程规则落为目标项目独立快照，但 UI保持“锁定版本、来源升级不自动影响、可显式升级”的体验。
- 原型 `postMessage` 仅作为工作流 UI桥接；正式入库和调用最终必须请求 NestJS API。
