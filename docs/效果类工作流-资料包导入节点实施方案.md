# 效果类工作流 Step 01「资料包导入」实施方案

## 1. 范围与边界

本次只实现效果类工作流第 01 步“资料包导入”，包括单产品导入、多品类批量导入、全局视频配置、单品配置覆盖、草稿恢复、项目隔离、资料校验、正式资产入库和进入下一节点的门禁。

本次明确不实现：AI 信息提炼业务、Prompt 生成、Seedance 调用、渲染、混剪、时间轴精修、成片导出、TOS Adapter、通用 WorkflowRun 历史版本和用户权限体系。校验通过后只进入“AI 信息提炼暂未开发”占位，不创建 AI 或异步任务。

## 3. 已确认产品规则

- 单产品与批量分别持久化产品数据、全局配置、校验状态和 revision，切换不删除、不覆盖另一模式数据。
- SKU 由后端自动生成并保证当前模式草稿内唯一，前端表单和 CSV/XLSX 清单均不要求用户输入。
- 最低通过条件：每个产品名称、品类完整，至少一张 READY 商品图片，全局配置及覆盖配置合法；电商链接如填写必须合法。
- 产品文档、品牌规范、电商链接、参考视频为可选资料。
- CSV/XLSX 必须先由后端预览；用户确认后所有行写入草稿，错误行同样创建并可在页面修复。
- 服务端已保留文件内容时可直接失败重试；网络中断或内容未保存时必须重新选择文件。
- 当前模式的 READY 文件、产品元数据和每个产品的有效配置均可“保存到项目资产库”；重复入库创建新版本。

页面状态至少区分：无项目、加载、空、成功、失败；保存状态区分 clean、dirty、saving、saved、saveError、conflict；文件状态区分 queued、uploading、ready、failed、deleting；校验状态区分 stale、validating、invalid、valid。

文本和配置使用 600ms 防抖保存，失焦立即 flush。产品字段和全局配置分别使用带递增版本号的 dirty snapshot；旧请求响应只能确认其发送时的版本，不得覆盖飞行期间产生的新编辑。所有写请求进入按项目隔离的单飞队列；模式或项目切换前必须先用旧项目上下文 flush，失败时阻止切换并保留可重试快照；成功后才 abort 请求、增加 generation、清空旧数据并加载新项目草稿，禁止迟到响应污染当前项目。批量列表和完整草稿中的同一产品必须按 productId 同步回写。

全局配置保存最终语义值，不保存下拉控件的 UI 状态：

- 画幅：9:16、16:9、1:1、4:3、3:4、2:3、21:9、自定义。
- 时长：5、10、15、20、30、45、60 秒；自定义整数 1–300。
- 分辨率：720P、1080P、2K、4K、自定义。
- 帧率：23.976、24、25、30、50、60；自定义 1–120。
- 字幕：跟随口播、全程字幕、重点词高亮、仅 CTA、无字幕、自定义。
- 口播：无口播、AI 男声、AI 女声、真人口播、仅文字与音效、自定义。
- BGM：自动匹配、品牌 BGM、轻快、高级质感、无 BGM、自定义。
- 保留风格基调、投放渠道及自定义选项。
- 禁用元素为标签数组，最多 50 项。

产品配置覆盖使用 `Partial<EffectVideoConfig>`；缺失字段继承全局值，返回时同时提供 override 和服务端计算的 effectiveConfig。

## 5. 共享契约与 Prisma 模型

新增 `packages/contracts/src/effect-import.ts`，统一导出模式、状态、视频配置、产品、资料、校验 issue、清单预览/提交、批量操作、正式入库和推进契约。所有 JSON API 继续使用 `ApiResponse<T>`。

Prisma 新增：

- `EffectImportWorkspace`：`projectId` 唯一，保存当前模式和 workspace revision。
- `EffectImportDraft`：`@@unique([projectId, mode])`，保存全局配置、revision、validatedRevision、校验结果、状态、完成时间和最近入库摘要。
- `EffectImportProduct`：包含 projectId、draftId、名称、品类、SKU、normalizedSku、链接、configOverride、排序和清单来源。
- `EffectImportMaterial`：包含 projectId、productId、资料类型、MISSING/UPLOADING/READY/FAILED、期望文件名、实际文件信息、storageKey、安全错误和重试次数。
- `EffectManifestImport`：保存 PREVIEW/COMMITTED/CANCELLED/EXPIRED、规范化预览行、issues、幂等键和过期时间。
- `EffectManifestStagedFile`：保存预览阶段上传的配套文件与匹配结果；提交后转为草稿资料，取消/过期后清理。
- `EffectImportPublishOperation`：以 projectId、客户端 idempotencyKey 唯一记录一次主动入库操作、草稿 revision、完整快照、持有令牌、执行结果和失败状态；部分成功后可按同一操作安全续跑。
- `EffectImportPublishFileHold`：发布运行或恢复期间持有快照引用的 READY 存储对象，避免实时草稿删除/重传破坏尚未完成的入库。
- `StorageCleanupTask`：持久记录工作流删除、重传和清单清理后待删除的存储键；立即执行失败时由后续初始化/请求重试，禁止吞掉异常后永久泄漏。

Draft、Product、Material、Manifest 关系使用包含 `projectId` 的复合外键。所有 Repository 方法必须把 `projectId` 放入查询、更新和删除条件。草稿允许保存空的用户可编辑字段，以便错误行可恢复；SKU 是系统内部标识，创建产品时自动生成。

每次草稿内容修改都原子增加 revision，并清除 validatedRevision。写请求使用 `If-Match` 或 body expectedRevision；Controller 在校验后统一解析二者，至少存在一项，不一致返回 409。只有 `validatedRevision === revision` 且校验无 error 时允许 advance；已推进草稿再次修改时必须把 Step 01 恢复为 CURRENT、Step 02 重新锁定。

## 6. REST API

基础路径：`/api/projects/:projectId/workflows/effect/source-import`

- `GET /`：workspace、双模式草稿摘要、默认配置和节点状态。
- `PATCH /mode`：无损切换当前模式。
- `GET /drafts/:mode`：加载完整模式草稿。
- `PUT /drafts/:mode`：创建/更新该模式全局配置。
- `GET /drafts/:mode/products`：keyword、category、page、pageSize 查询。
- `POST /drafts/:mode/products`：新增产品。
- `PATCH /drafts/:mode/products/:productId`：更新字段或配置覆盖。
- `DELETE /drafts/:mode/products/:productId`：删除产品和草稿资料。
- `POST /drafts/:mode/products/batch-delete`：原子批量删除。
- `POST /drafts/:mode/products/batch-retry`：对保留 storageKey 的 FAILED/RETRYABLE 资料重新执行真实校验/处理；无服务端内容的资料返回 REQUIRES_NEW_FILE。
- `POST /drafts/:mode/products/:productId/validate-link`：只校验、规范化 HTTP/HTTPS 链接，不抓取外部页面。
- `POST /drafts/:mode/products/:productId/materials`：multipart 新增资料。
- `PUT /drafts/:mode/products/:productId/materials/:materialId/content`：重传、补传或带新文件重试。
- `DELETE /drafts/:mode/products/:productId/materials/:materialId`：删除资料。
- `GET /drafts/:mode/products/:productId/materials/:materialId/content`：原始流，视频支持 Range。
- `POST /drafts/BATCH/manifest-imports/preview`：multipart 清单和可选 files[]，返回逐行和文件匹配问题。
- `POST /drafts/BATCH/manifest-imports/:importId/commit`：幂等确认写入。
- `DELETE /drafts/BATCH/manifest-imports/:importId`：取消并清理暂存文件。
- `GET /manifest-template?format=csv|xlsx`：下载正式模板。
- `POST /drafts/:mode/validate`：权威校验并保存 validatedRevision。
- `POST /drafts/:mode/publish`：携带客户端 idempotencyKey，将当前模式完整资料包正式入库；同 key 为同一次请求恢复，新 key 表示用户再次主动入库。
- `POST /drafts/:mode/advance`：标记 Step 01 完成并返回 `AI_INFO_EXTRACTION`。

所有写接口返回最新 revision 和统一 JSON 响应，不使用 204。实体不存在或不属于当前项目时使用相同 404 行为，禁止跨项目枚举。

## 7. 文件、清单与正式资产

文件持久化复用 `StoragePort`；效果模块不依赖 `LocalStorageAdapter`。上传/重传先保存新对象，再事务更新数据库；数据库失败时删除新对象，旧对象仅在事务成功后删除。服务端内容已保存但后续处理失败时保留 FAILED/RETRYABLE 记录供真实重试；内容未保存时记录 REQUIRES_NEW_FILE。底层路径和存储异常不得返回客户端。

白名单与默认限制：

- 批量草稿最多 100 个产品。
- CSV/XLSX 最大 10 MiB、100 行，只读取第一张非空工作表，不执行公式。
- 图片 50 MiB；文档/品牌规范 100 MiB；参考视频 512 MiB。
- Multer 在落盘前限制清单字段 10 MiB、配套文件数量、配套单文件 512 MiB 和总请求体 522 MiB；不得先接收数十 GiB 再由业务层拒绝，业务层继续按图片 50、文档/品牌规范 100、参考视频 512 MiB 做权威限制。
- 扩展名、MIME 和必要文件签名联合校验；零字节拒绝。
- 清单文件列：产品名称、品类、电商链接、商品图片、产品文档、品牌规范、参考视频；多文件名使用 `|` 或换行分隔。SKU 不在模板中，提交时由系统生成。
- 文件名按安全 basename、Unicode NFKC、大小写不敏感精确匹配；找不到或重复匹配均产生结构化 issue。
- 预览 24 小时过期；PREVIEW 到 COMMITTED/CANCELLED/EXPIRED 使用包含 projectId、draftId、当前状态的条件迁移。取消、过期及提交完成后只清理经二次确认仍未 transferred 的对象，提交时同步清理未匹配或歧义的配套文件。

后端新增唯一生产依赖 `exceljs`，只安装到 `apps/api`。它解决 CSV/XLSX 解析问题；现有依赖无法替代，自写 XLSX ZIP/XML 解析不可维护。前端包体不受影响。

正式入库由效果 Service 调用公共 `AssetService`：新增内部文件型工作流产物入库方法，从 staging storage 复制为正式对象，再创建 Asset/AssetVersion。产品元数据和有效视频配置使用现有无文件工作流产物入库能力。稳定产物幂等键定位同一资产；每次用户主动点击生成新的客户端 idempotencyKey 和 PublishOperation，因此即使草稿 revision 未变化也会创建新的 AssetVersion；同一 key 的网络重试或失败恢复复用 operation receipt，不重复创建版本。claim 在事务内锁定并权威校验 draft revision/validatedRevision 后保存完整入库快照和文件 hold，后续从快照安全恢复；完成后释放 hold 并通过持久清理任务删除不再引用的草稿对象。资产名称和标签在发布前按平台长度约束安全映射。
